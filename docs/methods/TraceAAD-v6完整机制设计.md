# TraceAAD V6：质量门控的轨迹进化

> 状态：V6 已按本文协议实现，尚无正式实验结果。V4、V5 继续由各自的文档和实现独立维护；V6 实现位于 `llm4ad/method/traceaad_v6/`。本文给出第一版可复现协议，所有效果判断均为待验证假设。

## 1. 研究问题与核心主张

LLM 自动算法设计需要在有限评估预算内，针对给定任务产生性能尽可能好的算法。任务提供问题描述、程序模板、待优化组件的说明和 evaluator；LLM 根据本轮上下文生成修改建议或候选代码，evaluator 检查候选是否有效并返回性能结果。

一次 LLM 请求只完成一个明确任务。多步改进、路线选择、失败保留以及探索与利用由外部搜索机制组织。TraceAAD 研究的问题是：**如何利用算法的改进历史，为每次请求选择合适的起点并提供有效证据，从而提高连续产生更好算法的概率？**

[What Makes an LLM a Good Optimizer? A Trajectory Analysis of LLM-Guided Evolutionary Search](../../../papers/traj_evo_search/2604.19440.pdf) 的实验分析表明，优秀的 LLM 搜索算子更能围绕已有方案持续产生小步改进；多样性主要在搜索进入高质量局部区域后带来收益。这里的“小步”是围绕已有高质量方案进行可评价的连续改进，不要求每次只能改动少量代码。

V6 的核心机制是：

> 以单轨迹局部改进为搜索主干；当搜索进入高质量区域后，用差异参考选择启用双轨迹知识交换；每次生成都直接依据真实的算法改进历史。

单轨迹算子从一条路线继续改进，对应语义层面的变异；双轨迹算子把另一条高质量路线中有评价证据的思想迁移或重组到主程序，对应语义层面的交叉。两类操作都只产生一个结构父代，候选的来时路始终明确。

## 2. 设计依据

V4、V5 的正式结果和过程审计提供了以下设计线索。这些现象用于形成 V6 假设，不构成受控因果证据。

| 已观察到的现象 | V6 的选择 |
| --- | --- |
| 正式测试中 V4 领先 TSP 和 OBP capacity=100，过程审计中候选唯一率更高 | 以单轨迹改进承担主要预算 |
| 正式测试中 V5 领先 OP100/200，双轨迹算子也产生过路线最好和全局最好更新 | 保留迁移与重组，但限制启用条件 |
| V5 存在参考路线相似、不同分支收敛到相同程序的现象 | 参考选择同时考虑质量与路线差异 |
| 低质量父代容易取得较大父子增量，高质量区域的小幅推进更接近最终目标 | 信用只奖励高质量区域中的路线推进 |
| 轨迹增长伴随程序膨胀，同分择短只能约束保留结果 | 允许局部修正删除、替换和合并无效机制 |

因此，V6 让单轨迹承担主要预算，只在有前景区域启用跨轨迹知识交换；提示使用程序的形成过程和评价结果，不维护脱离来源的在线总结；质量、路线信用、访问公平和路线差异分别承担成果判断、继续开发、低访问保护和参考筛选，避免用一个分数混合所有目的。

跨任务结果见[实验总汇](../results/实验总汇.md)，局部改进与受控多样性的研究记录见 [RQ-005](../research/RQ-005-LLM局部改进与受控多样性.md)。

## 3. 搜索对象与轨迹证据

候选程序记为 \(p\)，evaluator 返回任务结果 \(f(p)\)。实现统一比较方向，使数值越大表示结果越好。只有通过解析、执行、有效性检查并得到有限评价值的候选才是有效程序。

一条轨迹 \(\tau_i\) 是从初始程序到当前程序的祖先路径，包含两个重要位置：

- **endpoint**：最近生成的程序，表示当前延伸位置；
- **compact best**：轨迹中评价最好、完全同分时非空 LOC 最少的程序。

`global best` 是整次搜索中按同一规则得到的最好程序，独立于 active 种群保存。每个有效程序只有一个结构父代，全部程序和修改边构成派生森林。参考路线只提供知识，不增加父边。由内部 compact best 重新生成时，新轨迹由“到该锚点的前缀 + 新程序”组成，锚点之后的旧分支继续保留在完整派生图中。

active 轨迹最多保留 8 个程序节点，用于在线评分和上下文构造；超过上限时保留最近后缀，完整派生图仍保存全部事实。每条有效修改边记录 Action、随候选代码返回的一句 Implemented Idea、相对父程序/批次前路线最好/批次前全局最好的变化、算子与参考来源，以及 LOC 和代码变化。

锚点的**已测试尝试**包括从该锚点产生的有效修改边，以及没有形成有效程序的候选记录。后者涵盖代码解析失败、执行错误、evaluator 超时和无效结果。LLM 服务中断等系统失败只进入运行日志，不作为算法证据传给后续请求。

## 4. LLM 的职责与上下文

LLM 在 TraceAAD 中只需要发挥三种能力：

1. **理解问题与当前算法**：理解任务、待优化组件的作用、当前代码和约束；
2. **利用给定上下文**：从轨迹中识别已有改进、失败尝试和当前可用信息；
3. **产生高质量的下一步输出**：按照本轮指令提出算法修改或完成代码实现。

每次请求包含任务与待优化组件说明、主锚点完整程序、形成历史、从该锚点出发的已测试尝试和本轮算子指令。形成历史按顺序展示 Action、Implemented Idea、评价变化和结果，不重复中间程序的完整代码。

已测试尝试最多展示 6 条，优先级为：产生路线最好或全局最好更新的尝试，最近的无效、失败或退步尝试，其他最近尝试。同一条边不在形成历史和已测试尝试中重复。选择内部 compact best 时，形成历史在该节点结束，节点之后的旧分支作为已测试尝试展示，避免把旧分支中的机制误认为锚点已有代码。

双轨迹算子额外展示参考路线的 compact-best 完整程序及其形成历史。参考历史明确标出曾产生有意义路线最好或全局最好更新的修改，作为可迁移知识；失败和退步只作为已测试边界。主轨迹决定修改起点和新程序归属，参考轨迹只提供第二种算法知识。内部评分、概率和门控阈值不进入提示。

每个实验根据模型上下文窗口显式设置输入上限，并预留输出空间。裁剪时始终保留任务、待优化组件说明、主锚点代码、本轮指令和 Code 阶段的指定 Action；双轨迹操作还必须保留参考程序及其有评价支持的修改。其余证据优先保留最近步骤、最好更新和失败边界，先删除较早且评价中性的步骤。若双轨迹关键证据无法完整放入上下文，本轮改用单轨迹算子。

## 5. 轨迹语义算子与调度

| 算子 | 本轮任务 | 进化作用 |
| --- | --- | --- |
| `trace_refine` | 修正一个已有价值或已暴露弱点的机制 | 证据驱动的局部变异 |
| `trace_ideate` | 根据任务结构提出一个历史之外的新方向 | 扩大邻域的定向变异 |
| `trace_transfer` | 保持主程序主体，迁移参考路线中一个有支持的思想 | 保守的语义交叉 |
| `trace_synthesize` | 各取两条路线中一个有支持的原则，使二者形成明确交互 | 组合式语义交叉 |

这些算子是提示词约束的语义操作。记录参考来源只说明模型看到了该路线；Action、实际代码变化和 evaluator 结果共同说明预期操作是否落实，V6 不增加独立的 LLM judge。`trace_refine` 可以增加、替换、合并或删除代码；若锚点附近连续出现“LOC 增加但没有路线推进”的尝试，其指令优先删改缺少评价支持的机制。

选定主轨迹后，在 endpoint 和 compact best 之间选择锚点：两者相同则直接使用，不同则等概率选择。路线同时满足以下条件时记为成熟：\(Q_i\) 位于 active 前 30%（边界并列全部保留），保留路径至少有 2 条有效边，并且至少 1 条边以超过任务阈值的幅度更新路线最好。

算子按当前状态选择：

1. 主路线未成熟或没有合格参考时，只使用单轨迹算子；
2. 主路线成熟且存在合格参考时，以 0.25 概率选择双轨迹，以 0.75 概率选择单轨迹；
3. 选择 endpoint 且到该锚点的最近 3 条形成边中存在路线推进时，`refine : ideate = 2 : 1`；
4. 选择内部 compact best，或最近 3 条形成边没有路线推进时，`refine : ideate = 1 : 2`；
5. `transfer` 与 `synthesize` 等概率选择。

## 6. 路线价值与父代选择

路线质量同时考虑当前延伸位置和路线已有最好结果：

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i},
\]

前者在 active 路线的 endpoint 集合中计算并列感知百分位，后者在 compact-best 程序集合中计算。程序首先按 evaluator 原始结果比较，只有结果完全相同才用非空 LOC 择短；global best 和 compact best 也遵循这一规则。

V6 不用父子增量直接评价路线，因为它会偏爱从较差起点得到的一般改进。一次批次开始前冻结 active、路线最好和全局最好。设 \(\mathcal B_t\) 为批次前各 active 路线的 compact-best 程序集合，\(\mathcal C_t\) 为本批有效子程序集合；\(q_t(v)\) 是子程序 \(v\) 在 \(\mathcal B_t\cup\mathcal C_t\) 中按相同程序比较规则得到的百分位。若 \(v\) 相比批次前路线最好取得大于 \(\epsilon_{\mathcal T}\) 的提升，令 \(I_{\mathrm{route}}(v)=1\)，否则为 0：

\[
c(e)=q_t(v)I_{\mathrm{route}}(v).
\]

边信用在创建时确定，不随后续种群变化重算。路线信用是保留路径上边信用的近期折扣平均：

\[
C_i=
\frac{\sum_{k=1}^{m}\gamma^{m-k}c(e_k)}
     {\sum_{k=1}^{m}\gamma^{m-k}},
\qquad \gamma=0.8,
\]

单节点轨迹的 \(C_i=0\)。\(\epsilon_{\mathcal T}\) 只用于划分有意义的 improve、plateau、regress 和计算信用，不改变 evaluator 原始结果的严格排序。边的 outcome 按子程序相对结构父代的变化分类，只用于轨迹证据和路线差异。确定性固定种子的 evaluator 默认取 0，其他任务必须根据评价精度显式设置。

继续开发价值和父代分布为：

\[
V_i=0.8Q_i+0.2C_i,
\]

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

\(N\) 是整次运行已经发起的主轨迹批次数，种群收缩后不重置；\(n_i\) 是当前轨迹被选为主轨迹的次数。新分支继承祖先证据，访问次数从 0 开始。主轨迹一旦被选中并发起批次，其访问次数增加 1；本批没有得到可评价代码时也计数。

## 7. 质量门控的差异参考

参考候选必须是另一条成熟 active 轨迹，其 compact-best 程序哈希同时不同于主路线 compact best 和本轮主锚点。V6 使用轻量路线差异代理：

\[
D(i,j)=1-\operatorname{Sim}(i,j),
\]

\[
\operatorname{Sim}(i,j)=0.5S_{\mathrm{code}}(i,j)+0.3S_{\mathrm{idea}}(i,j)+0.2S_{\mathrm{path}}(i,j).
\]

\(S_{\mathrm{code}}\) 是两条 compact-best 代码标识符集合的 Jaccard 相似度；\(S_{\mathrm{idea}}\) 是保留路径中 Action 与 Implemented Idea 词项集合的 Jaccard 相似度；\(S_{\mathrm{path}}\) 是 `(operator, outcome)` 集合的 Jaccard 相似度。

参考还需满足 \(D(i,j)>0\)，且差异不低于本轮候选的中位数。合格参考按下式采样：

\[
R(j\mid i)=Q_jD(i,j),
\qquad
\Pr(\rho_j\mid\tau_i)=\operatorname{softmax}(R(j\mid i)/0.2).
\]

这个差异只用于排除明显重复的路线，不等同于程序功能差异，也不能在交叉前证明两条路线互补。在线搜索把“交叉子程序更新路线最好或全局最好”记为有效知识交换的后验成功；Action、Implemented Idea 和代码变化保留给后续分析。这是可计算的操作性证据，不是互补性的因果证明。V6 第一版不依赖 embedding 或任务专用行为向量；若任务以后能提供稳定的功能行为距离，可在独立验证后替换当前代理。

## 8. Action、Code 与同批评价

Action 请求生成恰好两条编号、单行、自包含的修改建议。每条建议只描述一个主要变化，说明其轨迹依据，与已失败或停滞的尝试保持实质差异，并且不假设待优化组件无法获得的输入；双轨迹 Action 还需说明使用哪个参考思想。

每条可用 Action 分别触发一次 Code 请求。Code 请求接收同一轨迹证据和指定 Action，从主锚点实现该变化。候选至少包含目标函数的完整实现并保持其函数名、输入、输出和基本作用；可以包含程序模板与 evaluator 允许的 imports 和少量顶层辅助函数。

两条 Action 构成一个批次。先生成并评价预算允许的全部候选，再统一建立节点和边：所有子程序从同一锚点和轨迹前缀分支；相对同一个批次前路线最好和全局最好计算变化；质量百分位在“批次前各 active 路线的 compact best + 本批全部有效子程序”中共同计算；最后统一更新路线、信用、全局最好和 active。evaluator 可以逐个执行，但统计语义不得受 Action 顺序影响。

代码解析失败不进入 evaluator，也不消耗评估预算。只要调用 evaluator，无论成功、超时、执行错误或结果无效，都消耗一次预算。只有得到有效评价值的候选形成程序节点，候选造成的其他结果进入锚点的已测试尝试。

## 9. 扩张—收缩种群

active frontier 的目标规模为 \(M=30\)。有效子程序产生新 active 轨迹；规模达到 \(2M\) 时收缩回 \(M\)：

1. **精确去重**：按规范化完整程序哈希合并 endpoint 相同的路线。全局最优锚定路线（best-anchor）指当前登记为 global best 所属的 active 路线；重复组包含它时保留它，否则保留 \(V\) 更高者，再按稳定路线编号决胜；
2. **质量精英**：按 \(Q\) 保留 \(E=\max(2,\lceil0.1M\rceil)\) 条路线；best-anchor 必须进入精英集合，必要时替换其中最弱路线；
3. **差异保留**：从其余成熟路线中，以相对“精英 + 已选差异路线”的 max-min 路线差异保留 \(R=\max(2,\lceil0.1M\rceil)\) 条；
4. **继续开发**：其余席位按 \(V\)-softmax 无放回抽样。

精确去重后不超过 \(M\) 条时直接保留全部路线，不再执行后续选择。成熟路线不足时释放差异保留名额。退出 active 的路线转为 archived，完整派生事实和独立保存的 global best 不删除。

## 10. 完整搜索流程

初始化在预算内连续生成候选，直到建立 \(M\) 条有效单节点轨迹。第一个请求强调简单、完整和有效；后续请求展示最近至多 6 个初始思想的简述，鼓励形成不同起点。初始化和正式搜索遵循同一评估预算。

```text
1. 在预算内建立最多 M 条有效初始轨迹。
2. 重复直到终止：
   a. 计算 active 轨迹的 Q、C、V 和 UCB，选择主轨迹与锚点；
   b. 构造主轨迹证据，判断成熟度并筛选差异参考；
   c. 按当前状态选择单轨迹或双轨迹算子；
   d. 生成两条 Actions，并分别生成候选代码；
   e. evaluator 评价候选，以批次前快照统一建立节点、边和信用；
   f. 更新路线、global best、active 和过程记录；
   g. active 达到 2M 时收缩回 M，并按周期保存 checkpoint。
3. 返回 global best。
```

预算耗尽、外部终止、active 为空、连续 20 次生成/解析失败或连续 20 个批次没有候选进入 evaluator 时停止。初始化后没有有效程序则返回空结果；否则返回 evaluator 结果最好、完全同分时非空 LOC 最少的 global best。

程序复杂度只使用非空 LOC：评价完全相同时择短，并把无收益的 LOC 增长作为 `trace_refine` 的删改依据。LOC 不形成连续 fitness 惩罚，也不设置统一长度上限；代码变化比例只用于过程分析。

## 11. 可复现记录与后续学习

checkpoint 保存完整派生图、active/archived 轨迹、锚点尝试、global best、访问次数、预算、随机数状态和全部机制配置。过程记录必须能够精确重建每次 LLM 请求实际看到的上下文及其输出，并把每个候选关联到起点、算子、参考、Action、Code、评价结果和种群决策。

这些事实形成：

\[
(\text{context},\text{instruction})
\longrightarrow
(\text{action},\text{code},\text{evaluation}).
\]

V6 在线搜索只记录事实，不把每次退步直接定义为负样本。后续研究可以结合即时改进、路线推进和后代长期贡献构造监督、偏好或强化学习信号，把搜索过程中发现的改进能力内化到模型；学习算法不属于 V6 在线搜索机制。

| 默认 \(\epsilon_{\mathcal T}\) | 确定性固定种子 evaluator 取 0；其他任务显式设置 |
| Action / Code 输出上限 | 1024 / 8192 token |
| checkpoint 周期；连续停滞上限 | 10 个完成批次；20 |

上下文输入上限由模型和实验配置显式给出；随机种子必须记录。表中比例和阈值是 V6 第一版协议选择，不是指定论文给出的通用常数。

## 13. 实现边界与待验证假设

实现必须保持以下行为：

- 每个有效候选只有一个结构父代，参考路线不增加父边；
- 双轨迹只在成熟主路线与合格参考之间启用；
- 同批候选使用同一批次前快照；
- 全局访问数在运行中单调增加，新分支访问数从 0 开始；
- 原始 evaluator 结果决定程序排序，无效候选不进入派生图；
- 双轨迹关键上下文放不下时退回单轨迹；
- 种群收缩不删除 global best 和完整派生事实；
- 在线不维护全局文本总结，也不调用额外的反思或评判 LLM；
- 每次 LLM 请求均可由记录精确重建。

V6 需要检验五项假设：

- **轨迹证据**：真实有序历史优于只给当前代码或打乱历史；
- **局部改进优先**：单轨迹为主、双轨迹受门控优于四算子始终等概率；
- **差异参考**：质量与路线差异共同选参考优于只按质量选择；
- **路线推进信用**：高质量区域的新路线最好信用优于父子变化符号；
- **失败与复杂度证据**：锚点级尝试和可删减 refine 能减少重复失败与无收益膨胀。

实验应分别报告训练结果、独立测试结果和搜索过程。过程指标至少包括有效生成率、路线最好与全局最好更新率、单/双轨迹预算占比、交叉后验成功率、活跃程序唯一率、LOC 变化和达到目标质量所需的 evaluator 调用数。
