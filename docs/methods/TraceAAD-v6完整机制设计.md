# TraceAAD V6：质量门控的轨迹进化

> 状态：V6 完整设计规范，尚未实现，也没有正式实验结果。
>
> V4 与 V5 继续由各自的权威文档和实现独立维护。V6 的预期实现目录为
> `llm4ad/method/traceaad_v6/`。本文中的默认值用于给出完整、可复现的第一版
> 协议；凡涉及 V6 效果的判断均标记为待验证。

## 1. 科学问题与核心主张

一次 LLM 请求只需要完成一个边界明确的任务：理解给定上下文，并产生本轮的
算法修改建议或代码。多步改进、失败保留、路线选择、探索与利用由外部搜索
机制组织。因此，TraceAAD 的关键问题是：如何选择当前程序、组织其改进历史，
并在合适的时候引入另一条路线的知识，使每次 LLM 请求更可能产生有效改进。

LLM 在这里需要发挥三种能力：理解任务与当前算法，从轨迹中利用已有改进和失败
信息，并按照本轮指令产生高质量的下一步 Action 或 Code。V6 的其他机制都服务于
这三种能力，尤其是提高模型在多次独立请求中逐步改进算法的成功率。

[What Makes an LLM a Good Optimizer? A Trajectory Analysis of LLM-Guided
Evolutionary Search](../../../papers/traj_evo_search/2604.19440.pdf) 的轨迹分析表明，
表现较好的 LLM 搜索算子能够持续产生小步改进，并逐渐聚集到高质量区域；多样性
主要在搜索已经定位到高质量局部区域后发挥作用。它还指出，局部改进能力属于
“模型、提示与生成配置”构成的完整生成系统，不能只归因于基础模型。
这里的“小步”指围绕已有高质量方案持续产生可验证的局部改进，不等同于强制每次
只改少量代码。

V6 据此提出：

> 以可靠的单轨迹局部改进作为进化主干，以质量与互补性门控的双轨迹知识交换
> 作为交叉机制，并用真实的算法改进历史构造每一次 LLM 请求。

单轨迹算子从一个当前程序出发，依据自己的历史产生变化，对应语义层面的变异。
双轨迹算子将参考路线中已有证据支持的思想迁移或重组到主程序，对应语义层面的
交叉。两类操作生成的新程序都只有一个结构父代，派生关系始终清楚。

## 2. 设计原则

V6 遵循五条原则：

1. **局部改进优先**：大部分预算用于沿一条高质量路线持续修正算法。
2. **多样性受质量门控**：双轨迹操作只发生在已经显示质量和改进能力的路线之间。
3. **上下文使用直接证据**：提示展示程序如何形成、哪些修改有效、哪些尝试失败，
   不维护脱离来源的在线全局总结。
4. **质量、继续开发价值和访问公平分工**：当前质量决定成果，轨迹信用描述近期
   推进能力，UCB 为尝试较少的路线保留机会。
5. **机制保持最小**：相似度、复杂度和日志只承担各自必要职责，不再增加独立的
   novelty judge、反思 LLM 或代码复杂度优化目标。

### 2.1 从 V4 与 V5 得到的设计依据

现有正式结果和过程审计给出的是设计线索，还不能单独证明因果关系：

| 已观察到的现象 | V6 的选择 |
| --- | --- |
| V4 的单轨迹搜索在 TSP 和部分 OBP 设置上更强，并保持了更高的候选程序唯一率 | 让单轨迹变异成为默认搜索主干 |
| V5 的双轨迹算子能够产生路线最好和全局最好更新，并在 OP100/200 上表现更好 | 保留 transfer 与 synthesize 两类知识交叉 |
| V5 出现参考路线高度相似和不同分支收敛到相同程序的现象 | 交叉同时使用成熟度、质量和互补性门控，并对繁衍状态去重 |
| 低质量父代更容易获得父子提升，高质量父代产生全局前沿更新的价值更高 | 用“新路线最好所处的质量区域”记录信用 |
| V4 容易累积代码，V5 的同分择短主要改善保留端，尚未约束生成端 | 保留同分择短，并允许 refine 删除、替换和合并机制 |

跨任务正式结果见[实验总汇](../results/实验总汇.md)。局部改进与多样性的阶段认识
见 [RQ-005](../research/RQ-005-LLM局部改进与受控多样性.md)。

## 3. 搜索状态与派生拓扑

一次生成决策的状态写为：

\[
s_t=(x,p_t,\tau_t,\mathcal L_t,\rho_t,b_t),
\]

其中：

- \(x\)：任务描述、程序模板以及待优化组件的输入、输出和基本作用；
- \(p_t\)：本轮唯一的主锚点程序；
- \(\tau_t\)：从初始程序到 \(p_t\) 的主轨迹；
- \(\mathcal L_t\)：从 \(p_t\) 出发已经执行过的局部修改尝试；
- \(\rho_t\)：双轨迹算子使用的参考轨迹，单轨迹算子下为空；
- \(b_t\)：剩余评估预算和搜索统计。

每个有效候选只有一个结构父代。全部程序节点和修改边组成森林；参考轨迹只提供
知识，不增加第二条父边。每条 active 轨迹最多保留 8 个程序节点。超过上限时
保留最近后缀，完整派生图继续保存所有程序、修改和评价事实。

一条修改边记录：

- 本轮 Planned Action；
- 实际代码的一句 Implemented Idea；
- 父程序和子程序的评价结果；
- 相对父程序、路线历史最好和全局最好三种变化；
- 代码变化比例与非空 LOC 变化；
- 生成算子以及可选参考轨迹的来源。

只有评价有效的候选形成程序节点和修改边。已经得到具体 Action 或 Code、但解析
失败或被 evaluator 判为无效的生成，作为局部尝试记录挂在主锚点上；它们不进入
active，也不参与路线评分。

## 4. 轨迹如何进入 LLM 上下文

### 4.1 形成历史

`[How This Program Was Reached]` 按时间顺序展示从轨迹起点到主锚点的修改边。
每一步只展示 Action、Implemented Idea、评价变化和结果，不重复完整代码。主锚点
代码始终完整展示。

形成历史回答三个与下一步直接相关的问题：当前算法包含了哪些思想，这些思想从
哪里引入，以及它们产生了什么结果。

### 4.2 已测试的局部尝试

`[Tested Continuations From This Program]` 展示从当前锚点出发已经执行过的直接
修改。它既包含所选轨迹中以该锚点为父节点的下一条边，也包含从同一程序产生但
进入其他分支的边，以及没有形成有效节点的实现尝试。每项继续使用原始 Action、
Implemented Idea、评价结果或失败原因，不把多次尝试压缩成一段自由文本总结。

局部尝试最多展示 6 条。优先顺序依次为：产生路线最好或全局最好更新的尝试、
最近的无效、失败或退步尝试、其他最近尝试。同一条有效边不会在形成历史和局部
尝试中重复出现。这个局部记录使失败信息在分支之后仍能被后续请求看到，减少
模型再次提出已经验证无效的相同修改。

### 4.3 参考轨迹

双轨迹算子额外展示：

- 参考轨迹的形成历史；
- 参考轨迹的 compact-best 完整程序；
- 参考路线中得到评价支持的修改及其结果。

主轨迹决定修改起点和新节点的归属，参考轨迹只提供可迁移的知识。提示中不展示
内部质量分数、UCB、种群保留概率或门控阈值。

Action 和 Code 阶段接收相同的形成历史、局部尝试和可选参考证据。这样，Action
阶段依据的事实能够继续约束代码实现。

## 5. 四个轨迹语义算子

| 算子 | 本轮任务 | 进化作用 |
| --- | --- | --- |
| `trace_refine` | 聚焦修正一个已有价值或已暴露弱点的机制 | 小步、证据驱动的变异 |
| `trace_ideate` | 在现有历史之外提出一个有任务依据的新方向 | 扩大邻域的定向变异 |
| `trace_transfer` | 保持主程序结构，迁移参考路线中一个已有支持的思想 | 保守的语义交叉 |
| `trace_synthesize` | 各取主路线与参考路线中一个有支持的原则，使二者产生明确交互 | 组合式语义交叉 |

`trace_refine` 允许增加、替换、合并或删除代码。修改方向由轨迹证据决定，因此
V6 不再设置独立的 simplify 算子。

双轨迹操作交换的是算法思想及其证据。它不拼接两段代码，也不要求 LLM 同时管理
两条后代路线。新候选始终从主锚点生成，并写回主轨迹所在的派生树。

## 6. 路线质量与继续开发信用

### 6.1 路线质量

先由 evaluator 将任务结果统一为“越大越好”的比较值。路线质量为：

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{compact\mbox{-}best},i}.
\]

两项均为当前 active 候选中的并列感知百分位。`compact best` 是轨迹上达到路线
最好评价的最短程序。程序比较首先看 evaluator 结果；评价相同时再选择非空 LOC
更少的程序。

### 6.2 边信用

父子之间的直接提升容易奖励“从较差父代反弹到一般水平”的候选。V6 改为记录
一次修改是否把本路线推进到了新的高点，以及新高点处于怎样的质量区域。

设边 \(e:u\rightarrow v\) 产生时，\(q_t(v)\in[0,1]\) 是子程序在
`active + 当前子程序` 中的质量百分位，\(I_{\mathrm{route}}(e)\) 表示它是否超过
修改前的路线最好结果：

\[
c(e)=q_t(v)\,I_{\mathrm{route}}(e).
\]

超过全局最好时，\(q_t(v)=1\)。评价是否提升由 evaluator 的数值分辨率
\(\epsilon_{\mathcal T}\) 判断；确定性离散指标可以令其为 0。V6 不使用统一的
\(10^{-12}\) 阈值。

路线信用 \(C_i\) 是保留路径上边信用的近期折扣平均：

\[
C_i=
\frac{\sum_{k=1}^{m}\gamma^{m-k}c(e_k)}
     {\sum_{k=1}^{m}\gamma^{m-k}},
\qquad \gamma=0.8.
\]

单节点轨迹的 \(C_i=0\)。父子 improve / plateau / regress 仍进入轨迹上下文和
过程日志，但不再直接形成长期搜索信用。

### 6.3 父代调度

路线的搜索值为：

\[
V_i=0.8Q_i+0.2C_i.
\]

设路线 \(i\) 被选作主轨迹的次数为 \(n_i\)，全部主轨迹访问次数为 \(N\)：

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

\(Q\) 说明当前已经取得的结果，\(C\) 说明近期在高质量区域继续推进的记录，
UCB 只维持访问公平。三者不进入 LLM 提示。

一次主轨迹选择并发起生成批次后，`visit_count` 增加 1。生成或解析失败也计入
访问，因为这次路线机会已经消耗。

## 7. 主锚点选择

主轨迹选定后，在 endpoint 与 compact best 之间选择主锚点：

- 两者相同时直接使用；
- 两者不同时等概率选择。

选择 endpoint 可以延续最新变化，选择 compact best 可以从已知最好程序重新
尝试。选择内部 compact best 时，形成历史截至该节点，节点之后已评价的修改通过
`[Tested Continuations From This Program]` 展示。

## 8. 双轨迹门控与参考选择

双轨迹操作需要同时满足“主路线已经成熟”和“存在高质量互补参考”两个条件。

### 8.1 成熟路线

路线 \(i\) 满足以下条件时记为成熟：

1. 按 \(Q_i\) 排序位于当前 active 路线的前 30%，边界并列路线全部保留；
2. 保留路径上至少有 2 条有效评价边；
3. 至少有 1 条边更新了路线最好结果。

这一定义用高质量和持续改进证据近似论文所说的“搜索已经局部化到有前景区域”。
初始阈值属于 V6 的协议选择，不代表论文给出的通用常数。

### 8.2 互补性

参考候选必须是另一条成熟 active 路线，并且其 compact-best 程序哈希同时不同于
主轨迹的 compact best 和本轮主锚点。路线差异使用已有的轻量代理：

\[
D(i,j)=1-\operatorname{Sim}(i,j),
\]

具体计算为：

\[
\operatorname{Sim}(i,j)
=0.5S_{\mathrm{code}}(i,j)
+0.3S_{\mathrm{idea}}(i,j)
+0.2S_{\mathrm{behavior}}(i,j).
\]

\(S_{\mathrm{code}}\) 是 compact-best 代码标识符 token 集合的 Jaccard 相似度；
\(S_{\mathrm{idea}}\) 是保留轨迹中 Action 和 Implemented Idea 词项集合的 Jaccard
相似度；\(S_{\mathrm{behavior}}\) 是 `(operator, outcome)` 集合的 Jaccard 相似度。
候选还需满足 \(D(i,j)>0\)，且差异度不低于当前参考候选集合的中位数。若不存在
这样的路线，本轮关闭双轨迹操作。

在合格参考中按下式采样：

\[
R(j\mid i)=Q_jD(i,j),
\qquad
\Pr(\rho_j\mid\tau_i)=\operatorname{softmax}(R(j\mid i)/0.2).
\]

质量保证参考思想来自有前景的区域，差异保证第二条轨迹提供主轨迹尚未拥有的
信息。相似度只用于参考门控和种群 reserve，不进入父代质量或候选接受规则。

## 9. 状态相关的算子调度

V6 不再让四个算子始终等概率竞争预算。调度规则如下：

1. 主路线尚未成熟或没有合格参考时，只使用单轨迹算子。
2. 主路线成熟且存在合格参考时，以 0.25 概率选择双轨迹算子，以 0.75 概率
   选择单轨迹算子。
3. 单轨迹家族中，若最近 3 条边至少有 1 次路线最好更新，`trace_refine` 与
   `trace_ideate` 的概率为 2:1；否则为 1:2。
4. 双轨迹家族中，`trace_transfer` 与 `trace_synthesize` 等概率选择。

这套调度先保证局部改进的主要预算，再在高质量、互补路线之间提供有限交叉。
0.25、最近 3 步和 2:1 是第一版可复现默认值，其有效性需要后续实验验证。

## 10. Action 与 Code 两阶段生成

### 10.1 Action

Action 阶段接收任务描述、待优化组件说明、主锚点代码、主轨迹证据、局部尝试、
算子指令和可选参考证据。它输出恰好两条编号、单行、自包含的修改建议。每条建议：

1. 只包含一个主要算法变化；
2. 指明它依据了哪些已有结果；
3. 与已经失败或停滞的尝试保持实质差异；
4. 只使用待优化函数可获得的输入和局部计算；
5. 双轨迹时明确说明迁移或重组的参考思想。

### 10.2 Code

每条可用 Action 分别触发一次 Code 请求。Code 阶段接收与 Action 相同的轨迹
证据，并实现其中一条 Action。输出只包含一个满足待优化组件输入输出要求的完整
函数。evaluator 随后独立检查语法、可执行性、有效性和任务性能。

LLM 在每次请求中只负责根据当前上下文完成指定输出。路线切换、参考选择、失败
保留、候选淘汰和预算管理均由搜索机制完成。

## 11. 扩张—收缩种群管理

active frontier 的目标规模为 \(M=30\)。新有效候选立即进入 active；当规模达到
\(2M\) 时统一收缩回 \(M\)。

收缩流程为：

1. 对 endpoint 程序完全相同的 active 路线去重，保留 \(V\) 更高者作为可
   繁衍代表，其余路线保留在派生图中；
2. 建立 \(E=\max(2,\lceil0.1M\rceil)\) 条质量精英；包含 global best 的
   best-anchor 路线必须进入该集合，必要时替换其中最弱的一条，使精英总数仍为
   \(E\)；
3. 从成熟路线中按相对“精英 + 已选 reserve”的 max-min 差异保留
   \(R=\max(2,\lceil0.1M\rceil)\) 条互补路线；成熟路线不足时释放空余席位；
4. 其余席位按 \(V\)-softmax 无放回抽样；去重后不足 \(M\) 条时保留全部路线。

差异 reserve 只从高质量且有改进证据的路线产生。这样，多样性资源用于保留
高质量区域中的不同解法，低质量路线的基本试验机会继续由 UCB 提供。退出 active
的路线标记为 archived，仍保留全部事实和日志。

## 12. 程序复杂度

V6 使用非空 LOC 记录程序复杂度，并遵循三条规则：

1. evaluator 结果优先；
2. 评价相同时选择更短程序；
3. `trace_refine` 可以主动删除、替换或合并没有贡献的机制。

LOC 不形成连续 fitness 惩罚，也不设置程序长度硬上限。每次生成记录 LOC、LOC
变化和代码变化比例，用于分析程序膨胀以及修改是否真正落实。

## 13. 完整搜索流程

```text
输入：任务描述、程序模板、待优化组件说明、LLM、evaluator、评估预算 B

1. 生成并评价初始候选，建立最多 M=30 条有效的单节点轨迹。
2. 重复直到评估预算耗尽：
   a. 在 active frontier 上计算 Q、C、V 和 UCB 调度分数 A；
   b. 按 softmax(A/0.2) 选择主轨迹，并记录一次访问；
   c. 从 endpoint / compact best 选择唯一主锚点；
   d. 构造形成历史和该锚点的已测试局部尝试；
   e. 判断主路线成熟度，筛选高质量、互补的参考轨迹；
   f. 按状态相关规则选择单轨迹或双轨迹算子；
   g. 双轨迹算子按 Q×D 选择参考轨迹；
   h. 生成两条自然语言 Actions；
   i. 对每条可用 Action 生成候选函数，并由 evaluator 评价；
   j. 为每个有效候选写入一条单父代修改边和一条新 active 轨迹；
   k. 更新路线最好、global best、边信用和过程日志；
   l. active 达到 60 时收缩回 30；
   m. 按周期保存 checkpoint。
3. 返回 evaluator 结果最好、评价相同时 LOC 最少的 global best。
```

代码解析失败不消耗评估预算；进入 evaluator 后的失败消耗一次预算，但不作为
有效节点进入 active。两者在已有具体 Action 或 Code 时写入锚点的局部尝试记录，
并保留失败原因。

## 14. 状态、日志与可学习信号

checkpoint 保存：

- 完整派生图及边事实；
- active / archived 轨迹及其形成历史；
- 每个程序的局部尝试记录；
- global best 与 active best-anchor；
- 访问次数、预算、随机数状态和搜索配置。

过程日志至少记录：主轨迹、锚点、算子、参考轨迹与选择依据、Action、Code 请求
上下文、解析和评价结果、父代/路线最好/全局最好变化、生成时质量百分位、LOC、
相似度和种群管理决策。

这些记录自然形成可学习样本：

\[
(\text{context},\text{instruction})
\longrightarrow
(\text{action},\text{code},\text{evaluation}).
\]

有效且推进高质量路线或全局前沿的输出可以形成正样本；相同或相近上下文中的
无效、退步和重复输出可以形成对比样本。后续可据此进行监督学习、偏好学习或
强化学习，把搜索过程中发现的改进能力内化到模型。具体训练算法属于独立研究
阶段，V6 在线搜索不依赖它。

## 16. 研究边界与待验证假设

V6 是根据现有论文结论、V4/V5 机制审计和当前实验现象提出的完整设计，目前没有
V6 实现或消融结果。指定论文支持“可靠局部改进优先”和“高质量局部区域中的
多样性更有效”这两个一般原则，并未直接验证 V6 的门控阈值、评分公式或算子比例。

后续实验需要检验：

- **H1：轨迹证据有效性。** 真实有序轨迹比仅给当前代码或打乱历史更能提高下一步
  有效改进率。
- **H2：局部改进优先。** 单轨迹为主、双轨迹受门控的调度优于四算子始终等概率。
- **H3：参考互补性。** 按质量与差异共同选择参考优于只按质量选择参考。
- **H4：前沿信用。** 高质量路线推进信用比父子变化符号更能识别值得继续开发的
  路线。
- **H5：局部失败保留。** 锚点级已测试尝试能够减少重复修改，并提高有效预算利用率。
- **H6：复杂度控制。** 同分择短与可删减 refine 能抑制保留程序的膨胀，同时保持
  evaluator 性能。

这些假设需要在多任务、重复运行、训练过程和独立测试结果上分别检验。机制过程
指标至少包括：有效生成率、路线最好与全局最好更新率、单/双轨迹预算占比、参考
相似度、活跃程序唯一率、LOC 变化以及达到目标质量所需的评估次数。
