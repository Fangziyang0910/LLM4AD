# TraceAAD V6 质量门控版：以成熟路线和信用代理约束轨迹进化

> 本文定义历史质量门控 V6 的独立机制。代码快照为 `d4cf664`，训练批次为
> `v6_20260801_183249`，原始工件位于 `archive/traceaad-v6-development/`。
> 四任务三重复训练与 held-out 均已完成，但该版本不是正式 V6，不进入当前正式
> 主结果表。正式 V6 删除了本文的大部分质量代理，见
> [TraceAAD V6](TraceAAD-v6完整机制设计.md)。

## 1. 研究问题与设计假设

V5 的轨迹种群能够保存程序的来时路，但双轨迹交换和路线生存可能在搜索早期就把预算
投向尚未成熟的路线。质量门控 V6 研究一个更具体的问题：**能否先确认一条路线已经在
局部产生可靠推进，再让它承担跨路线知识交换和更强的生存权重？**

该版本的假设是：路线质量、近期推进、成熟度和轻量差异信息可以共同作为搜索控制信号，
使单轨迹局部改进成为主要供给，并在高质量、已有改进证据且相互不同的路线之间启用双轨迹
操作。它同时假设精确 endpoint 去重可以防止相同可执行程序占用多个 active 席位。

这些控制信号都是代理变量。它们约束搜索预算，不改变 evaluator 的真实评价。正式实验的
结果显示，这组代理没有稳定实现“围绕优质区域可靠局部改进”，因此本文记录的是完整的
历史设计和证据边界，不把其过程现象转写为机制成功。

## 2. 状态、轨迹与上下文

候选程序只有在解析、执行并获得有限 fitness 后才进入事实图。每个有效程序节点具有唯一
结构父代；修改边记录 Action、Implemented Idea、算子、参考路线、父子结果变化、路线最好
变化、批前 global-best 变化、LOC、代码哈希和结果标签。

一条 active 轨迹包含：

- 当前 `endpoint`，作为继续修改的当前位置；
- 路径上的 `compact best`，即 fitness 最好且同分最短的程序；
- 最多 8 个在线程序节点和相应修改边；
- 访问数、成熟度、路线质量、路线信用、差异参考和 active/archive 状态。

完整派生图保存所有有效程序和边。路线从内部 compact-best 重新开始时，新的 active 路线
继承到该锚点的结构前缀，并用有限 `evidence_edge_ids` 携带锚点之后的旧尝试；这些证据边
供 prompt 识别已测试方向，但不成为第二个结构父代。

主轨迹上下文包含任务契约、完整锚点程序、形成历史和本轮算子要求。双轨迹时额外包含另一
条路线的 compact-best 程序和形成历史。历史按真实时间和结果展示，不把 Action 或 Idea
当作已证实解释。若双轨迹关键上下文超出模型上限，本批退回单轨迹算子。

## 3. 路线成熟度与算子门控

选定主路线后，endpoint 与 compact best 在两者不同的时候等概率作为唯一结构锚点。路线
被视为成熟，必须同时满足：

1. 路线 $Q$ 位于 active 路线前 30%（并列边界全部保留）；
2. 保留路径至少包含 2 条有效修改边；
3. 至少一条边以超过任务阈值的幅度刷新路线最好值。

四个语义算子分别是：`trace_ideate`、`trace_refine`、`trace_synthesize` 和
`trace_transfer`。当主路线成熟、且存在合格的不同参考路线时，以 0.25 的概率启用
双轨迹；其余 0.75 概率选择单轨迹。若主路线或参考不合格，只从单轨迹算子中选择。

单轨迹算子从当前历史提出新方向或局部修复。`trace_synthesize` 在主程序中组合两条
路线的原则；`trace_transfer` 把参考路线中的一个原则迁移到主程序。参考路线只提供
知识，不形成第二结构边。

## 4. 路线质量、信用与选择

程序比较先看 evaluator fitness，完全相同时按非空 LOC 择短。active endpoint 和路线
compact best 分别在 active 集合中计算并列感知的 fitness 百分位：

$$
Q_i=0.7Q_{endpoint,i}+0.3Q_{best,i}.
$$

质量门控版进一步把路线的局部推进与路径信用合并为搜索值。设批次前 active 路线的
compact best 集合为 $\mathcal B_t$、本批有效子程序集合为 $\mathcal C_t$，$q_t(v)$ 是
子程序 $v$ 在 $\mathcal B_t\cup\mathcal C_t$ 中的质量百分位。只有 $v$ 以超过任务阈值
$\epsilon_{\mathcal T}$ 的幅度刷新批前路线最好时，边信用才为非零：

$$
c(e)=q_t(v)I_{route}(v).
$$

保留路径上最近边的折扣信用为：

$$
C_i=\frac{\sum_{k=1}^{m}0.8^{m-k}c(e_k)}
{\sum_{k=1}^{m}0.8^{m-k}},
\qquad
V_i=0.8Q_i+0.2C_i.
$$

单节点轨迹的 $C_i=0$。边信用在创建时冻结，不随后续 active 集合变化重算；它用于衡量
“从这条路线继续生成是否曾产生高质量路线推进”，不改变候选的原始 fitness。

主路线使用带 UCB 的选择值：

$$
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
P(\tau_i)=\operatorname{softmax}(A_i/0.2).
$$

其中 $N$ 是已发起主轨迹批次数，$n_i$ 是路线被选为主轨迹的次数。$V_i$ 综合路线质量
和路线推进信用，低访问路线仍因 UCB 保留机会。一次批次开始前冻结 active 路线、路线
最好和 global-best 状态；同批候选在同一个批前快照上计算结果变化。

双轨迹参考必须来自另一条成熟 active 路线，且其 compact-best 哈希不同于主路线和主锚点。
质量门控版使用代码、Idea/Action 词项和 `(operator, outcome)` 路径指纹构成轻量相似度：

$$
D(i,j)=1-\operatorname{Sim}(i,j),
$$

$$
\operatorname{Sim}(i,j)=0.5S_{code}(i,j)+0.3S_{idea}(i,j)+0.2S_{path}(i,j).
$$

参考路线按主路线质量与差异联合得分抽样：

$$
R(j\mid i)=Q_jD(i,j),
\qquad
P(\rho_j\mid\tau_i)=\operatorname{softmax}(R(j\mid i)/0.2).
$$

这些相似度是提示和参考选择的代理，不是功能等价性判断。

## 5. 生成与评价

每个批次先冻结主路线和锚点，再生成恰好两条编号、单行、自包含的自然语言 Action。每条
Action 单独进入 Code 阶段，生成完整可执行程序。两条 sibling 共享主锚点、轨迹上下文、
参考路线和批前 global-best 快照，从而避免 Action 生成顺序改变批次语义。

- transport、Action/Code 解析失败不消耗 evaluator 预算；
- evaluator 已启动即消耗一次预算，无论返回成功、timeout、runtime error 或无效数值；
- 只有有限 fitness 的候选进入派生图和 active frontier；
- `positive_threshold` 只把父子变化标记为 improve、plateau 或 regress，不参与接纳、
  路线选择或生存；
- 完全同分时择短，不对更优长程序施加连续复杂度惩罚。

## 6. active 生存、去重与延迟管理

active frontier 目标规模为 $M=30$。新路线先加入 active；规模达到 $2M=60$ 时执行管理。
管理顺序为：

1. 按规范化完整程序哈希执行精确 endpoint 去重。相同 endpoint 只保留一条 active 路线；
   若重复组包含 global-best 路线，优先保留它，否则比较路线 $V$，最后用稳定 route id 决胜。
2. 强制保留包含 global best 的路线。
3. 按 $Q$ 保留质量精英，默认约为 active 的 10%，至少 2 条。
4. 在其余路线中保留成熟路线的差异席位，默认约为 active 的 10%，至少 2 条。
5. 剩余席位按路线值 softmax 无放回抽样。
6. 退出 active 的路线标记为 archived，但完整事实图不删除。

精确去重只回答“两个当前程序是否完全相同”，不判断语义相似、行为等价或历史是否有
知识价值。差异席位使用轻量指纹，也不等同于功能多样性证明。

## 7. 完整流程与可恢复性

```text
1. 生成并评价最多 30 个有效初始程序，建立 active 轨迹。
2. 重复直到预算耗尽或安全停止：
   a. 计算 Q、路线信用和 UCB，选择主轨迹及 endpoint/compact-best 锚点；
   b. 判断成熟度和参考资格，选择单轨迹或双轨迹算子；
   c. 构造主/参考历史，生成两条 Action 及其 Code；
   d. 评价候选，在批前快照上统一更新路线、信用和 global best；
   e. active 达到 60 时去重、保留 global best/精英/差异路线并收缩到 30；
   f. 保存日志、原始候选、边、决策和 checkpoint。
3. 返回 evaluator fitness 最优且同分最短的 global best。
```

checkpoint 保存完整派生图、active/archive 路线、锚点尝试、路线质量与信用、global best、
预算、停滞状态、随机数状态和全部配置。恢复时校验协议、任务、模型非密钥身份、代码哈希、
有限 fitness、唯一父代和 active endpoint 唯一性。质量门控 checkpoint 不得静默续跑到正式
V6 协议。

## 8. 默认配置和证据边界

| 配置 | 质量门控 V6 默认值 |
| --- | ---: |
| evaluator 预算 | 1000 |
| active 目标 / 管理阈值 | 30 / 60 |
| 在线轨迹长度 | 8 个程序节点 |
| 路线质量 endpoint / best | 0.7 / 0.3 |
| UCB 系数 / softmax 温度 | 0.25 / 0.2 |
| 成熟路线分位 / 最少边数 | 前 30% / 2 |
| 双轨迹概率 | 0.25（主路线和参考均合格时） |
| 质量精英 / 差异席位 | 约 10% / 约 10%，各至少 2 |
| sibling Action | 2 |
| Action / Code 上限 | 1024 / 8192 token |
| endpoint 处理 | 精确 `code_hash` 去重 |

该表是历史质量门控批次的描述性 held-out 结果，不是当前正式结果。过程审计显示，成熟度、
