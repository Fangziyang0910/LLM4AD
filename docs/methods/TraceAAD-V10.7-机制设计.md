# TraceAAD V10.7 机制设计

日期：2026-09-07。状态：已实现，尚未启动实验。

**V10.7 仅取消 V10.6 的第二次独立校准调用，生成流程为单次「简短 Idea → 完整 Code」。其余机制沿用 [V10.6 完整机制设计](TraceAAD-V10.6/机制设计.md)。**

## 1. 调整依据

[V10.6 配对核查](../analysis/诊断性分析/2026-09-07-V10.6二次Idea配对核查/结论.md)的 30 组样本中，12 组存在局部纠错，但尚未统计出明确的整体净改善。第二次调用仍会漏判行为等价、无效改动、偏好方向和算法退化，也会新增错误的父代变化描述。

第二次调用不修改当前代码，其收益只能通过更准确的历史描述间接影响后续生成。目前尚无证据证明这条收益链能以合理成本改善搜索，而额外调用已增加成本与等待时间。因此，面向有限预算下达到 SOTA 的目标，取消这层尚未证明净价值的复杂度。该决定取代核查文档中当时“保留两阶段流程”的工作建议，不代表证明独立校准完全无效。

## 2. 唯一机制变更

Init、Refine、Pivot、Fuse 统一在一次生成调用中输出：

1. **Idea**：简短说明算法思路和预期产生的决策变化，指导代码生成。
2. **完整 Code**：输出完整实现，作为正式评价对象。

第一次调用的 Idea 直接写入节点 `idea` 字段，后续历史以 `Idea` 展示。取消第二阶段及其专用 Prompt、响应、重试、恢复、状态和耗时字段；生成、检查与正式评价流程继续沿用原规则。

Idea 仍是生成前提出的设计说明，不能视为经过最终代码校准的实现事实；历史同时保留完整代码作为当前个体的主要依据。

## 3. 保持不变

搜索树与入档规则、8 个有效根初始化、正式评价预算、父代分配、算子比例与指令、Fuse donor 选择及回退、公共任务描述与模板、评价器和实验配置均沿用 V10.6。

历史仍使用最近最多 8 条形成边，历史区上限 8192 tokens。上下文窗口、输出额度、裁剪顺序与代码完整性要求不变。

实现入口见[运行说明](../../experiments/traceaad_v10_7/README.md)。本轮未启动实验；后续用实际调用成本与完整搜索结果检验该调整，不以局部纠错作为保留额外调用的充分依据。
