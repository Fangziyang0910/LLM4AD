# TraceAAD V10.8：可核验形成轨迹条件化的单步搜索

状态：已实现并通过本地工程验收（2026-09-09）；本次按用户提供的设计稿及研究重心讨论落地。已启动 15 路正式搜索，尚无终局结论，不代表性能已优于 V10.7R。实现与验收入口见第 15 节。

来源：用户提供的 `TraceAAD_V10_8_design.md` 与研究重心讨论稿（2026-09-09）。来源稿审查基点为 `52fd74fd4ea4c2fdb7bfb41ce46c19f1452349af`（2026-09-08）；下文历史证据沿用该稿的范围与局限，本次未重新审计历史原始日志。V10.8 使用独立实现与结果目录，不替换 V10.7R 冻结身份。

## 1. 研究定位

主问题不是先估计哪个算法方向最有潜力，而是：已经发生的算法设计实验，能否提供当前程序和评分之外的信息，从而改善后续设计，并在有限预算内得到更好的最终算法？

首发贡献集中在可核验的形成轨迹如何条件化生成。预算分配提供可回访、逐步重决策的搜索载体，不声称学得长期价值，不为凑齐两个创新点添加新的潜力评分器。

本版保留当前阶段的冻结生成模型、公共任务定义、真实评价器和评价预算。不训练模型，不以产生人类未知算法结构为必要目标。

## 2. 证据约束与未解决问题

仓库的生成上下文经验支持：parent-path 在固定锚点实验中具有改善生成分布的证据；但它不是跨任务稳定提高完整搜索结果的定论。直接子代尝试没有显示稳定增益，二次摘要有局部纠错但不是可靠语义校准，固定多步 rollout、max-backup 和未经验证的潜力代理均有历史风险。

2026-08-21 父代来时路完整搜索结果页存在汇总内部不一致。按该页逐 seed 数据重算：CVRP 的 PP=8.9703、CO=8.8801，越低越好，应为 CO 均值更好且 CO 2:1；OP 的 PP=14.773333、CO=14.772667，而不是汇总中的 CO=14.4393。这是页面内部校验，不是对本地原始日志的重新审计。

E2-B' 的 9 个 experienced 锚点中，只有一个 PR 相对 RR 的正例，且该收益发生在第一步；没有 Pivot continuation 增加 Q1。因此不加入 Pivot 保活、固定接力或以从低谷回升为奖励的规则。

V10.7R 已修复证据角色、编号污染及调用协议。其默认生成路径至多提供一份参考，且不读取多步 history_tokens/traj_gens。它是有价值的直接转移证据基线，但不是完整形成轨迹利用的最终答案。

仍未解决：多步轨迹是否比单条边有增量；代码差分是否比短语义描述更利于当前模型；历史是否导致保守锚定；相同输入预算下终局收益是否成立；低分但可开发程序能否获得足够开发预算。不得用新叙事将这些未知项写成已解决。

## 3. 唯一推荐的首发闭环

选择程序底座和设计意图 → 提取该底座真实、近期、连续的形成轨迹 → 一次生成 Idea + 完整 Code → 一次真实评价 → 记录客观转移 → 重新选择。

所有变化围绕同一对象：下一次算法设计实验。保存完整历史不等于暴露完整历史；保存一条程序谱系不等于它是完整因果轨迹或 RL rollout。

不加入独立反思模型、语义 critic、机制簇、行为相似度、停滞触发、动态算子成功率、祖先信用回传、固定开发块或额外自动修复回合。

## 4. 档案与身份

保持完整单父程序树作为派生关系索引，Fuse 的 donor 和实际上下文来源另记引用。结构父节点不等于唯一信息来源。

每次尝试保存真实 parent、requested/executed operator、donor、实际上下文事件、完整 prompt/hash、响应、代码、原始 Idea、评价结果和成本。失败请求保留在事件档案中；只有有限有效 fitness 的程序参加选父及最终输出。所有退步、持平、重复代码均保留，不按思想新颖性或超父率删档。

同一代码可对应不同真实形成历史，不应把这些历史混成一条不存在的路径。为避免副本数量凭空增加预算，调度层按完全相同的代码分组，组内再选择一条真实记录。分组只用于机会计量，不合并事实，也不等于算法语义去重。

## 5. 预算分配：透明载体，而非新增价值模型

### 5.1 同代码机会守恒

候选组 g 由相同 evaluator 协议下完全一致的归档代码定义。N 是有合法完整底座提示的组数。组内拥有多条真实记录时，均匀选择其中一条作为本次节点，使用其自身谱系和原始评价事实，不拼接不同记录。

固定随机评价面板下以该实现的固定 fitness 为组质量。若出现同代码的不同分数，调度质量使用首次有效评价，不取副本最高分；所有原始结果保留，并单独审计评价稳定性。这个固定评价口径也用于按实现选择最终候选，避免依靠重复评价中奖。

c(g) 是该代码组已发起的设计尝试数。选定一次新请求增加一次；失败输出也占据一次生成机会；传输重试、token 计数和同一 pending 请求恢复不重复增加。

### 5.2 分布

沿用现有质量 ESS 校准和次数衰减函数：

    E = min(N, max(0.1*N, 2))
    w(g) = exp(beta * (q(g) - max_q))
    p0(g) ∝ w(g) / sqrt(1 + c(g))

beta 按已有校准函数求取；质量全相同时使用均匀质量权重，并记录可达 ESS。不把质量 ESS 当成次数修正后的最终 ESS。

请求算子比例保持 Refine/Pivot/Fuse = 0.50/0.15/0.35：

    P(g | Refine) = p0(g)
    P(g | Fuse)   = p0(g)
    P(g | Pivot)  = 0.5*p0(g) + 0.5/N

允许按等价联合分布先选父再选算子，禁止借换抽样次序改变目标概率。

这与 V10.7R 的 node-ID 分布并不完全相同：代码组机会守恒是单列的防副本膨胀修正，不得把它的收益归因于轨迹上下文。机制消融各臂使用完全相同的组级调度器；原始 V10.7R 保留作独立部署基线。

低分程序仍可被回访，但不保证获得足够 Refine 机会跨越低谷。次数是机会分散规则，不是能力、信息增益或潜力的估计。

## 6. 核心：可核验的近期形成轨迹

### 6.1 事实单元

一条形成边为：

    source program → actual executed operator → target program
    source fitness, target fitness, full code change
    whether an additional donor participated

代码变更使用确定性差分获得，不调用 LLM 生成“这次为什么变好”的解释。源程序、目标程序、评价必须来自同一真实转移。Idea 继续随原始响应存档，但首发默认不把历史 Idea/长摘要当作轨迹事实输入。

“可核验”仅表示程序、变更和测得结果可核对，不表示模型理解了算法语义，也不表示整次转移的收益归因到了某个模块。

### 6.2 展示表示

当前底座完整代码只展示一次；此前的代码变化以完整 unified diff 展示，包含全部修改块及其必要邻近行，而不是只取名字、AST 标签、增删行数或关键词。

沿用并统一现有必要的提示视图清理，例如移除依赖临时提示编号的注释。所有版本使用同一视图规则，差分也基于同一代码视图计算。不得把清理后的当前代码与未清理的祖先差分混用。原始归档和被评价模块不改写。视图清理与原始源代码的区别须可追溯。

若完整差分比完整前驱代码更长，使用完整前驱代码作为该转移的表示。两种表示表达同一实际转移，选择只按 token 成本，不按得分正负、改动大小的“价值”或模型解释选择。

生成器始终输出完整程序，不要求它执行补丁或遵循编辑 DSL。差分只是输入表示。

### 6.3 取哪段历史

从当前底座向祖先回溯，取最近的连续后缀，按真实发生顺序展示。首发上限沿用最多 8 条形成边、历史区最多 8192 tokens；这只是上限，不承诺每轮都能显示 8 条。

优先保留离当前底座最近的完整转移。容量不足时删除最老整条转移；不能截断一个 diff 的部分 hunk，不能跨过放不下的中间转移而冒充连续链，不能按 fitness 把无关程序重新排列成轨迹。

只有当前底座是根，或连最近一条完整转移都放不下时，退化为 code-only。历史缺失不剥夺合法底座资格，日志记录有效边数与退化原因。

完全相同代码的真实转移可简写为“代码未变化”，同时保留真实前后测得结果，不能写成机制创新。

### 6.4 多输入转移

历史 Fuse 边应明确说明另有 donor 参与。如果该 donor 未在本次提示中展示，不提供它的长谱系，不声称某个增量只由父代改动导致，不把未展示 donor 的分数当作可操作设计证据。完整 donor 身份仍在事实档案中。

### 6.5 不默认加入的记忆

不加入所有直接子代、不做失败目录、不自动提炼长期“知识表”。这不是否定失败经验的可能价值，而是遵守现有负面/未决证据。首发研究的是形成经验，不声称已经解决完整试错记忆的利用。

## 7. 三类设计意图

Refine：利用当前实现的形成过程，围绕一个主要改进目标进行连贯修改。默认保留无关计算，但不强制单行修改或禁止必要重构。

Pivot：利用当前实现及形成过程理解已有主要假设，尝试另一种有竞争力的主要决策方法。历史是比较依据，不是禁止复用的黑名单。首发不额外加入全档案随机/分层 alternative reference，不以语义距离或改动比例验收。

Fuse：当前底座及其形成轨迹，加一份 donor 完整代码与真实评价。目标是形成一个连贯、具有任务收益的候选；不要求双方贡献固定比例，也不把超过较弱父代当作已经实现互补融合。

donor 沿用 V10.7R 的质量水平抽样：排除相同代码，按 distinct fitness 水平从低到高赋秩；水平总质量正比于秩，水平内均匀选实现。组内取真实记录，不拼接 Idea、代码和分数。无需跨血缘，不声称该分布识别语义互补。

无可容纳不同代码 donor 时，执行 Refine；父代不变，不额外生成，不重复扣费或增加选择次数。requested 和 executed 均记录。

## 8. Prompt 与容量

固定顺序：公共任务与接口；当前底座完整代码及评价；近期真实形成转移；本次 donor（仅 Fuse）；设计意图与输出契约。

实际容量分配先保证任务、底座、输出契约以及 Fuse 的必要 donor，再用剩余空间容纳最近完整形成转移。展示顺序与容量优先级不必相同。

沿用 32768 上下文、16384 输出预留、256 安全余量时，最大完整输入为 16128 tokens。配置变化时按真实模型窗口重新计算，不能把这些数值视为所有模型通用常数。

不在全档案逐候选调用 tokenizer。缓存单程序/单转移表示，保持有界 donor 容量尝试，最后对实际完整 chat prompt 精确计数。首发沿用最多 32 次 donor 容量尝试，次数耗尽就回退，不假称已穷尽所有可容纳 donor。

输出保持单次、两段协议：不超过约 100 words 的自包含 Idea，随后完整 Python 代码。Idea 长度是生成指导，不增加语义验收器或第二次摘要调用；解析器和提示协议必须一致。

## 9. 评价、停止与故障语义

8 个有效根记录，初始化正式评价计入总预算，不强求语义互异，也不为凑足根数突破预算。每路首发沿用 1000 次真实 evaluator 调用。

正式 evaluator 启动即扣预算；超时、崩溃、无效返回都占本次评价。解析失败不冒充一次评价，但计入 LLM 调用、token 和尝试记录。重复代码仍按既定评价协议执行并如实计费，不偷偷跳过后宣称同评价预算。

保留已验证的预算收据、pending 请求持久化、源码与配置指纹、恢复语义和停止保护。评价状态未知时不得盲目重评。基础设施故障不以额外无上限模型调用填满预算。

本版不增加失败后的专用修复回合；正常下一轮可由模型提出任意符合接口的有效修改。

最终选择按预先固定的设计评价口径，不在线访问最终测试集。输出程序可以是当前已因上下文长度而不再参与繁衍的归档程序。

## 10. 最小算法

    initialize the event archive and 8 valid roots within budget
    while evaluation budget remains and operational stopping rules permit:
        sample operator and exact-code group under the fixed controller
        select one real node record from that group
        choose a donor only for Fuse
        take the recent contiguous formation suffix ending at the node
        render full base + complete transition evidence + optional donor
        generate one self-contained Idea and one full program
        parse and, when admissible, evaluate exactly the archived program
        record the actual request, code, outcome, references, and costs
        update code-group attempt count and archive facts
        re-decide from the updated archive
    return the best implementation under the predeclared design score

## 11. 必须分开的实验问题

第一组回答系统收益：原始 V10.7R、共同调度下的 code-only、共同调度下的单边代码证据、V10.8 多步代码证据。公共任务、评价器、模型、生成参数、根生成协议及输出解析一致。

第二组回答历史表示：在相同选定父代与同一真实历史快照上，对照旧的短 Idea/Result/Fitness 链与代码转移链。给相同最大输入预算，但同时记录实际 token；不能因为历史较长就自动归因于过程信息。

如果要主张“明确形成关系本身有增量”，另做诊断：相同真实程序快照与评分，一臂明确其真实先后关系，一臂只提供未声明关系的参考集合；两臂均不伪造关系或错配分数。这一诊断与主方法差分压缩实验分开，以免把代码表示变化混成关系作用。

代码组机会守恒在所有机制消融臂共同开启；另行比较开启/关闭它。否则不能把轨迹表示和预算测度的收益合并解释。

固定状态样本覆盖不同任务、质量与搜索阶段，并且只用当时可见的历史；每个锚点多次采样。无效输出不能从分母中剔除。Pivot 不以即时超父率或一步 frontier gain 作为唯一否决门槛。

完整搜索报告各任务 best-so-far 曲线、预定终局得分、最终独立测试、LLM 调用、输入/输出 tokens、评价与总耗时。多个节点不是独立搜索重复；少量 seed 仅能支持相应不确定性强度的结论。

若多步不优于单边，就保留单边结论，而不是继续扩大历史窗；若旧摘要优于代码转移，就承认新表示未获支持，不恢复昂贵摘要器掩盖结果；若固定状态改善而终局不改善，就研究这种差距，不继续把单步增益写成系统成功。

## 12. 实现验收，不替代机制验证

必须覆盖：

- 真实边源/目标/fitness/operator 与档案一致；所有证据在请求前已完成。
- 同一视图下完整差分可重建前后程序；不丢任何必要修改块。
- 容量删减只删除最老整条转移，根或零历史正确退化，完整代码不截断。
- 增加同代码副本不增加其组级总抽样质量；组内仍返回一条完整真实记录。
- 原始 Idea、归档代码、评价收据不被提示视图清理覆盖。
- donor 不可用时只回退一次，不重选父代、不生成第二个候选。
- 解析失败、评价失败、网络重试、恢复各自计费一次且类别准确。
- 原始 V10.7R 的冻结配置不能被 V10.8 静默恢复或混入结果。

无需增加大型通用实验平台。建议只增加一个确定性轨迹构建模块，在现有调度里加入组级计量，并复用已核查的单候选执行循环。消融通过独立实验构造器进行，不把所有历史模式重新放回生产 CLI。

## 13. 与后续训练的衔接

当前不设计新奖励算法。保存真实请求状态、动作、上下文来源、评价和成本，即可为后续研究提供素材。程序祖先链不等于可直接用于 on-policy RL 的 rollout；不能事后任取获胜路径再把后代分数当成祖先动作价值。

未来可分别训练历史条件化的程序修改策略和实验选择策略。两者能力不同，训练生成器不等于学会了预算分配。现在最重要的是先证实哪个状态表示确实值得学习。
