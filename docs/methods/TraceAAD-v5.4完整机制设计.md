# TraceAAD V5.4：提高趋势权重以恢复局部搜索优势

## 1. 设计动机

V5.4 建立在正式 V5（V5.3）之上。V5.3 关闭了在线全局经验，保留 $0.8Q+0.2P$。V5.2 的过程观察已经指出：趋势权重提高后局部改进比例上升，但回弹路线也被放大，全局最优刷新与父代平均质量下降。V5.4 检验这条权衡曲线的另一端：把趋势权重从 $0.2$ 提到 $0.4$，并配套调整趋势阈值、算子引导与代码生成引导，考察更高的走势权重能否恢复一种以局部改进为主导的搜索。

V5.4 的想法是：$0.8Q+0.2P$ 对当前成果依赖过重，对一条正在持续改进的路线给予的额外推动不足。把权重调到 $0.6Q+0.4P$（与 V4 的质量/趋势比重一致），并放宽趋势的正阈值，使量级较小但真实的改进也能计入路线走势。同时在算子与代码引导上强调保留有效结构、替换过时逻辑，引导搜索在已验证机制上做局部精炼，而非不断重起炉灶或叠加并行规则。

V5.4 保留 V5.3 的全部结构：四个语义算子、双轨迹直接参考、有界 8 节点轨迹、自然语言修改决策、关闭在线全局经验。变更集中在调度权重、趋势阈值、算子引导、代码引导与差异选择五处。

## 2. 搜索状态与轨迹

状态与 V5.3 相同：

\[
s_t=(x,p_t,\tau_t,\eta_t,\rho_t,b_t).
\]

V5.4 不维护全局经验。轨迹结构、派生图、8 节点上限、`[How This Program Was Reached]` / `[Later Attempts From This Program]` 分段、短轨迹完整展示的规则均与 V5.3 相同。主锚点程序始终完整展示，双轨迹算子另完整展示参考程序。

## 3. 轨迹评分与父代调度

路线质量与 V5.3 相同：

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i}.
\]

V5.4 把趋势权重从 $0.2$ 提到 $0.4$：

\[
V_i=0.6Q_i+0.4P_i.
\]

这一比例与 V4 的质量/趋势比重一致。相对 V5.3，它降低当前成果的权重、提高路线走势的权重，意在让正在前进的路线获得更明显的繁衍优势。

趋势 $P_i$ 为保留路径上父子变化符号的折扣聚合。V5.4 把区分正/零/负变化的阈值从 $10^{-12}$ 提到 $10^{-6}$：变化绝对值不超过 $10^{-6}$ 视为平台，只有超出该量级的变化才计入走势。其意图是避免无意义的微小波动被趋势放大；代价是某些真实但量级小的改进会被归零。UCB 与 softmax 不变：

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

## 4. 算子引导的局部搜索倾向

四个算子仍独立保留、可用时等概率选取。V5.4 调整了 `trace_ideate` 与 `trace_refine` 的引导措辞，使其偏向单一主思想与已有机制的精炼：

| 算子 | V5.4 引导侧重 |
| --- | --- |
| `trace_ideate` | 围绕一个主要新思想，退步与平台视为已测试边界 |
| `trace_refine` | 保留历史中一个有效思想，做一次聚焦的机制或参数精炼，并说明该精炼意图改变的单一可观察行为 |
| `trace_synthesize` | 与 V5.3 相同 |
| `trace_transfer` | 与 V5.3 相同 |

`trace_refine` 的改动最直接体现"恢复局部搜索优势"的意图：先保留一个已有有效思想，再做一次精炼，并声明精炼要改变的单一行为，使局部修改可审计。

## 5. 代码生成引导

代码生成沿用 V5.3 的输入与两阶段流程。V5.4 在代码引导中加入一段关于保留与替换的要求：保留已被历史支持的有效结构；替换过时逻辑，而非叠加并行规则；仅当请求的算法行为需要时才新增代码；不以牺牲任务行为为代价进行简化。

这段引导同时针对两个方向：抑制程序在"不断新增分支"中膨胀，也抑制模型为追求简短而删除对任务行为必要的逻辑。它与同分择简的简约规则互补：择简只在 fitness 完全相同时起作用，而这段引导作用于生成端，影响候选被写出时的形态。

## 6. 差异选择的播种

种群收缩时保留少量差异代表。V5.3 的差异选择从空集开始，逐个按"相对已选集合最不相似"选取。V5.4 改为先放入当前调度标量最高的路线，再在其上做差异选择。这使差异代表总包含当前最强路线作为参照，避免其退化为第二批远离前沿的同质代表。精英席位与全局最优路线仍按 V5.3 规则独立处理。

## 7. 锚点、简约与生存管理

锚点选择与简约规则与 V5.3 一致：endpoint 与 compact best 去重后等概率选锚点；复杂度仅用非空 LOC，仅在 fitness 完全相同时择简；程序文本相同性与相似度不进入在线接受规则。active 目标 $M=30$，阈值 $2M=60$，收缩规则为质量精英、全局最优路线、以最优路线播种的差异代表，其余席位按 $0.6Q+0.4P$ 的 softmax 无放回抽样。

## 8. 搜索流程

```text
1. 建立至多 30 条评价有效的初始单节点轨迹。
2. 重复至预算耗尽：
   a. 依 0.6Q+0.4P 与 UCB 选主轨迹；
   b. 从 endpoint / compact best 选主锚点；
   c. 依参考是否可用，等概率选四个算子之一；
   d. 双轨迹算子按质量 softmax 选参考轨迹；
   e. 用主历史与可选参考历史生成两条自然语言修改；
   f. 对每条可用修改从主程序生成完整候选（遵循保留与替换引导）；
   g. 评价候选，接受只看 fitness；
   h. 每个有效候选只从主锚点写入一条边；
   i. 更新 compact best、全局最优、访问统计；
   j. active 达 60 时收缩至 30（差异代表以最优路线播种）；
   k. 周期保存断点。
3. 返回 fitness 最优、同分时 LOC 最少的程序。
```

V5.4 没有全局反思与共享经验，与 V5.3 一致。

## 10. 在版本谱系中的位置

V5.4 把趋势权重取到 0.4（$0.6Q+0.4P$），放宽趋势阈值到 $10^{-6}$，并在算子与代码引导中强调保留有效结构、替换过时逻辑。它与 [V5.2](TraceAAD-v5.2完整机制设计.md) 构成趋势权重的两个受控取点。[正式 V5](TraceAAD-v5完整机制设计.md) 采用 0.2 权重与 $10^{-12}$ 阈值。

实验事实与机制诊断见 [版本实验事实与机制诊断](../analysis/TraceAAD-版本实验事实与机制诊断.md)。
