# TraceAAD V9.2 完整机制设计

> 状态：历史版本记录。正式批次（四任务三重复 + held-out）已完成，结局与后续版本对比见 [V9.3 / V9.4 机制与实验分析](../analysis/TraceAAD-V9.3-V9.4机制与实验分析.md)，设计取舍见 [RQ-007](../research/RQ-007-V9.2锚点与局部轨迹窗口.md)。本文是 V9.2 的机制规范；该版不含多窗口竞赛、树信用或路线推进评分。

## 1. 科学问题

自动算法设计中的有限预算，应当投给哪些已经形成的算法改进过程？单个程序只有当前代码和 fitness；轨迹还保存该程序如何形成、附近尝试过什么以及这些尝试得到什么结果。V9.2 检验：

> 以当前可执行程序为锚点，用它的有限局部改进历史指导下一次生成，并用该锚点在这种历史条件下实际产生的新代码质量更新预算价值，能否比只看当前个体或路线局部推进更有效地分配搜索预算？

树只是保存事实的数据结构。锚点是选择和信用单位，锚点的局部轨迹是下一次生成的决策上下文。

## 2. 三种对象

### 2.1 程序锚点

每个有效程序节点 `a` 都是一个锚点。它的完整代码是下一次修改的唯一执行起点，原始 fitness 经方向转换后记为 `q(a)`，始终满足越大越好：最大化任务取原值，最小化任务取负值。

同一份代码若由不同历史形成，仍是两个不同锚点，因为模型看到的历史条件不同。

### 2.2 事实图

事实图保存程序、父子关系、Idea、有效性、fitness、生成次序和评价事件。它只负责恢复真实历史、构造局部窗口、checkpoint 与审计，不定义价值，也不根据访问次数控制扩展。

### 2.3 锚点化轨迹上下文

第 `t` 次生成的决策上下文是：

```text
C_t(a) = 当前锚点完整代码 + 当时的规范局部证据窗口 W_t(a)
```

`W_t(a)` 是事实图在时刻 `t` 对锚点的唯一确定性视图，不是另一类个体，也不是需要单独分配预算的 arm。它会随新事实更新，所以 V9.2 不把它声称为可重复抽样的精确 Markov 状态。

## 3. 为什么每个锚点只有一个规范窗口

为同一锚点枚举大量 8 节点窗口，再分别学习 `Q(a,W)`，表面上更精细，实际上几乎每条精确窗口只会使用一次；新节点加入后窗口又发生变化，信用样本被持续切碎。DGA²D 的同设置消融显示 first-order credit 优于 second-order 和 full-path，后两者因上下文过细而产生稀疏、噪声评分。现有 V9/V9.1 日志也没有同锚点多窗口随机对照，无法支持任意窗口竞赛。

因此 V9.2 不选择“最好窗口”。选择锚点时，当时的规范窗口随之唯一确定。历史负责提供生成信息，评分则在可重复的锚点层面聚合这个局部改进过程实际产生的代码质量。两者共同影响下一步，但不形成两个调度器。

## 4. 规范局部证据窗口

### 4.1 窗口由事件组成

`W(a)` 最多包含 8 个按时间有序的 `Idea—结果` 事件，分为两部分：

1. **形成历史**：优先给锚点唯一父链上、离锚点最近的形成边分配 4 个位置；
2. **局部下游证据**：优先给锚点深度 3 邻域内、最近发生的生成评价事件分配 4 个位置。

若一侧不足 4 条，空余位置由另一侧按近期性补足，窗口总量仍不超过 8；因此 4/4 是优先配额，不是两侧硬上限。形成历史保持祖先到锚点的因果顺序；下游事件按真实发生顺序展示，并明确其相对锚点的深度和所属分支。它们可以来自不同分支，因此文档称其为“局部证据窗口”，不伪造成一条实际不存在的线性派生链。

深度 3 对应现有过程分析观察延迟挽救的时域；8 个事件是首版固定上下文预算，不是理论常数。

### 4.2 每个事件展示什么

窗口只展示生成决策需要的事实：

- 当时的 Idea；
- 有效、无效、改善、持平或退步；
- 父代与结果的原始 fitness；
- 相对锚点的位置、分支区分和真实发生次序。

模型只读取当前锚点的完整代码，历史节点不重复代码全文。无效尝试和退步必须保留；MEMOIR 的受控消融表明，移除局部历史或失败节点都会显著伤害后续生成。窗口不按 fitness 挑“最好事件”，避免幸存者偏差。

窗口明示它是最多 8 个事件的有限局部视图，较早历史可能已省略，下游证据也可能来自不同分支。每条 `Idea—结果` 只是对当次具体实现的条件证据，不直接判定更广泛的 Idea 必然有效或无效。事件 ID、预算编号、节点 ID、LOC 和粗糙的逐行变化比例只留在本地审计工件中，不进入模型上下文。

### 4.3 窗口怎样更新

窗口不保存独立评分，只由事实图确定性派生。新事件发生后：

- 新子代形成自己的锚点窗口；
- 被选父锚点的下游证据更新；
- 沿父链向上、距离新事件不超过 3 的祖先锚点可能更新下游证据；
- 其他锚点不变。

窗口改变只改变下一次生成上下文，不追溯改写任何锚点价值。新的下游事实说明“之后发生了什么”，并不是在新窗口下重新扩展祖先的反事实样本；祖先只有被真正选中后才产生新信用。由此不需要窗口身份、窗口淘汰和窗口信用迁移规则。

## 5. 唯一预算价值

### 5.1 评分目标

评分估计的是：从锚点 `a` 出发，随局部历史逐步积累而持续经营这个改进过程时，真实获得的代码绝对质量。它不是当前精确窗口的 Markov action value，也不估计锚点改善率、路线推进率、趋势好坏或访问不确定性。这是为了在有限预算下保留可积累的信用粒度。

第 `i` 次选择锚点 `a` 时，事件结果定义为：

```text
z_i(a) = q(c_i)    若生成有效子代 c_i
z_i(a) = q(a)      若生成、解析或评价无效，表示没有产生新质量
```

锚点的统一预算价值为：

```text
Q(a) = [q(a) + Σ_i z_i(a)] / [1 + n(a)]
```

其中 `n(a)` 是该锚点已经获得的完整预算事件数。`q(a)` 只是评分初始化，不是概率先验；所有量保持原始 task fitness 尺度，不做全局 min–max、百分位或跨节点归一化。

### 5.2 这个平均值表达什么

- 新锚点从自身代码质量开始：`Q(a)=q(a)`；
- 差锚点的小幅回弹仍保持较低的绝对价值；
- 高质量锚点连续产生差代码时，价值会下降；
- 差锚点若产生一个真正高质量子代会获得有限信用，但不会永久继承该子代最高分；
- 多次结果会稀释一次幸运值；
- 其他锚点出现极端结果不会改变 `Q(a)`。

现有观察数据中，该经验平均尚未稳定超过纯 `q(a)`，所以它是 V9.2 要检验的核心机制，不是已证事实。纯锚点 fitness 是正式消融基线。

### 5.3 信用边界

一次事件只更新被选锚点的 `n(a)`、结果和 `Q(a)`。新子代以自己的 `q(c)` 初始化为新锚点，不继承父代的生成统计。后代成功不会向祖先 max-backup，也不会给未被选择的祖先增加成功次数。

“差节点后来生出好节点”的价值通过两处保存：好节点本身成为高质量新锚点；完整形成过程进入它及附近祖先的局部证据窗口。谱系价值不等于重新扩展祖先的预算价值。

## 6. 固定预算选择

每轮只执行一套固定规则：

1. 对全部有效锚点计算 `Q(a)`；
2. 取 `Q` 最高的至多 10 个锚点作为质量候选区；
3. 候选区内若存在从未获得预算事件的锚点，选择其中 `Q` 最高者完成一次基本验证；
4. 否则选择候选区内 `Q` 最高者。

完全同分时依次比较 `q(a)`、程序有效非空行数和创建次序，仅保证确定性。

前 10 是首版质量区域常数。现有过程数据中，排名 10 以外锚点的全局推进率显著更低；新 V9.1 又把约 70% 预算集中到第一名，因此“优质区域内先完成基本验证，再按同一价值利用”是两者之间的最小折衷。

V9.2 不使用 UCB、Wilson、概率后验、访问奖励、温度采样或动态探索控制器。探索是在优质区域内给尚无后继证据的锚点一次机会；利用是在同一绝对质量尺度上继续选择经验生产力最高的锚点。

## 7. 初始化：先形成短轨迹，再开始竞争

初始化的目标是在有限成本内形成一组有区分、经过一次真实反馈、并能提供高质量可执行起点的短轨迹。V9.2 固定采用 `8 → 6` 的两阶段初始化：

1. 模型只读取任务和函数契约，一次提出 8 条互补、任务相关的策略假设；此时不写代码、不看评价结果，也不对策略排序；
2. 每条策略独立生成一份有效根程序。某条根的提示只含该策略，不读取其他根的代码、Idea 或 fitness，避免后生成路线被前面偶然结果串行污染；
3. 每个根用与正式搜索相同的规范窗口和单生成机制完成一次 trajectory bootstrap，形成 8 条“根程序 → 一次 Idea—结果”的两节点微轨迹；
4. 每条路线以根和有效 bootstrap 子代中 fitness 更好的程序作为代表锚点；若子代无效则仍以根为代表；
5. 用代表锚点已有的 `Q` 排序，选出 6 个正式初始锚点。若根在 bootstrap 后退，它的 `Q` 已包含这次退步；若子代形成突破，则高质量子代以自身 `q` 参选。完全同分仍按 fitness、简洁性和创建次序决定；
6. 未入选路线及非代表端点仍保留在事实图和实验工件中，但不进入正式预算候选集。此后只有正式搜索产生的有效子代会加入候选集。

策略规划调用不生成程序、也不调用 evaluator，因此不占 evaluator 候选预算，但单独记录调用次数、原始提示和策略清单。根程序和 bootstrap 都是科学搜索样本：理想无失败路径固定消耗 16 次评价，占 1000 预算的 1.6%；解析或评价无效照常消耗预算，并在同一策略上继续获得有效根。初始化完成后不再空白生成新根。

这里增加根数只是扩大策略候选池，真正防止差初代的是“先规划不同机制、独立实现、用一次真实轨迹反馈校正、再缩减到 6 个可执行锚点”的完整闭环。8 和 6 是首版固定常数，不是理论最优值。

## 8. 单一生成事件

每次预算事件只选择一个锚点、使用一个规范窗口并生成一个候选：

```text
任务 + 锚点完整代码 + W(a)
    → 一个自包含的 Idea + 一份完整可执行 Code
    → evaluator
    → 事实与 Q(a) 更新
```

提示不再指定 ideate、refine、synthesize 或 transfer。模型依据当前可执行锚点和轨迹事实，直接生成唯一的下一个 `Idea + Code`。历史结果只约束对当次具体实现的理解；重新尝试相关 Idea 时，新实现必须有实质差异并在 Idea 中说明。Idea 必须准确概括 Code 中实际实现的算法机制，但不直接兑换数值信用。

V9.2 的程序表示只保留可执行实现，不允许注释、docstring、被注释掉的候选方案或代码块内说明文字。提示词明确要求无注释代码；解析成功后，系统再通过 Python AST 删除全部注释与 module/function/class docstring，并规范化源码。只有净化后的程序会进入 evaluator、哈希、LOC、事实图、checkpoint、实验工件和后续提示上下文。该步骤不评价算法长短，也不改变 fitness 或选择公式，只删除不参与目标算法执行的文本表示。

单候选使一份预算、一次上下文、一个 Idea、一个代码结果一一对应。多 offspring、自适应批量和算子调度都留在后续独立研究中。

预算计数在 LLM 返回一份响应后立即发生；因此 Code 解析失败和 evaluator 无效都消耗一份搜索预算。未实际返回生成结果的运输层错误不记为科学搜索样本，由统一失败上限终止持续不可用的模型服务。

## 9. 完整搜索闭环

```text
任务与函数契约生成 8 条策略假设
    → 独立实现 8 个有效根
    → 每个根完成一次轨迹 bootstrap
    → 每条路线选较好端点并按 Q 筛出 6 个正式锚点
    → 计算所有合格锚点 Q
    → 取 Q 前 10，未验证优先，否则最高 Q
    → 构造该锚点唯一 W(a)
    → 生成一个 Idea + Code
    → evaluator
    → 更新父锚点 Q、事实图和受影响窗口
    → 有效子代成为新锚点
    → 直到 evaluator 预算耗尽
```

最终输出始终按原始有向 fitness 选择全局最好有效程序，完全同分时择简。搜索价值 `Q` 只服务预算分配，不改变最终答案定义。

## 10. V9.2-Core 明确不包含

- 多个候选窗口及窗口级 bandit；
- 趋势、波动、历史最好或路线推进的人工加权；
- 全局 min–max、祖先 max-backup 和节点访问信用；
- 多语义算子、双轨迹参考和全局自由文本经验；
- embedding、代码相似度或行为距离硬门槛；
- 学习型策略、贝叶斯后验、RL 或高阶 MAB；
- 初始化后的空白根扩展；
- 行级代码因果归因。

趋势、波动、延迟后代和代码变化继续作为离线诊断事实记录；首版上下文只展示可直接解释的 Idea、有效性、fitness 结果、时序与分支位置。在没有独立证据前，其他诊断量不进入数值评分或模型上下文。

## 11. 必须保持的机制不变量

1. 锚点完整代码是唯一修改基础，历史代码不替代锚点。
2. 每个锚点只有一个确定性的局部证据窗口。
3. 窗口最多 8 个真实事件，不按结果优劣抽取。
4. 一个预算事件只生成并评价一个候选。
5. `Q` 只由锚点分数和该锚点真实获得的事件结果组成。
6. 新后代只改变事实视图，不追溯修改祖先信用。
7. 选择只使用固定质量区、基本验证和 `Q` 排序。
8. 最终最好程序只按原始 fitness 与同分简洁性确定。
9. 无效生成保留为失败事实并消耗预算。
10. 初始化 bootstrap 与正式搜索使用同一个生成机制。
11. 正式搜索只从筛选后的 6 个锚点及其有效后代中选择；未入选路线只保留事实。
12. 8 条根路线彼此独立生成，不把先前根代码或结果加入后续根提示。
13. evaluator、轨迹和后续上下文只接收无注释、无 docstring 的规范化可执行源码。

## 12. 核心消融

V9.2 的联合结果不能证明每个组件。最小识别顺序是：

1. **上下文作用**：`current_only`、仅形成历史、完整规范窗口；
2. **预算信用**：纯 `q(a)`、V9.2 `Q(a)`、V9.1 路线推进 Wilson；
3. **初始化**：四个原始根、8 个原始根、8 条 bootstrap 微轨迹筛选 6 个锚点；
4. **整法比较**：V9、V9.1、V9.2 在相同 evaluator 与总预算下比较最终质量、后半程全局推进、预算集中度和 held-out 结果。

这四组实验分别识别轨迹作为生成上下文、轨迹作为预算证据和轨迹化初始化的贡献。

## 13. 相关工作依据与边界

- [DGA²D](../references/LLM自动算法设计方法阅读笔记/51-DGA2D.md)：first-order credit 的受控结果优于 zero-order、second-order 与 full-path，支持避免精确长窗口信用稀疏化；其对象是 pipeline transition，不能直接证明 V9.2 窗口最优。
- [MEMOIR](../references/LLM自动算法设计方法阅读笔记/47-MEMOIR.md)：移除 branch-local memory 和失败节点均明显退化，支持保留局部失败事实；它不能证明 V9.2 的评分公式。
- [PathWise](../references/LLM自动算法设计方法阅读笔记/24-PathWise.md)：支持把派生历史作为状态化生成信息，但整法结果没有单独证明路径评分。
- [BaSE](../references/LLM自动算法设计方法阅读笔记/28-Compute-Allocation-BaSE.md)：说明跨轨迹预算与轨迹内生成应分开；其 bandit 和趋势预测不移植到 V9.2。
- [MCTS-AHD](../references/LLM自动算法设计方法阅读笔记/22-MCTS-AHD.md)：提供绝对代码质量与有限质量区域的强基线；V9.2 不继承 min–max、渐进扩展和祖先回传。
- [PhyloEvolve](../references/LLM自动算法设计方法阅读笔记/21-PhyloEvolve.md)：支持保存谱系作为事实组织的动机，但缺少树结构独立消融，不用于证明预算规则。

这些相关工作提供设计约束，没有任何一篇已经验证 V9.2 的联合闭环。V9.2 的科学贡献仍需由上述分解实验建立。
