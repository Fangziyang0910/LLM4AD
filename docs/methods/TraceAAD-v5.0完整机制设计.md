# TraceAAD V5.0：结构化修改决策与全局经验的初次轨迹种群

## 1. 问题与设计目标

版本标识：V5.0（2026-07-24）。

V5.0 是 TraceAAD V5 的起点。它把 V4 的单条轨迹搜索扩展为轨迹种群，并引入两个新的知识来源：两条路线之间的思想重组，以及一份跨路线共享、由周期性反思维护的高层经验。

V5.0 的核心假设是：算法改进历史不仅服务单条路线的下一步，还能在路线之间流动。一类流动是显式的，即双轨迹算子从另一条路线提取可重组的思想；另一类流动是隐式的，即一份凝练的全局经验周期性地进入所有路线的决策。该假设只规定知识如何进入生成，不预先断言其有效。

V5.0 同时试验了一种结构化的修改决策表示。它要求模型在提出修改时同时给出关系类型、所依据的历史证据、修改内容及其与已有尝试的差异。设计意图是把"决定改什么"和"这次决定凭什么"绑在同一次输出里，使决策可追溯。

实验归档于 `archive/traceaad-v5-development/<task>/version5_0/`（批次 `20260724_220827`，代码状态 `7da32dc`；`d2ed669` 为其失效诊断后改回自然语言的收口提交）。

## 2. 搜索状态与轨迹

一次决策的状态为：

\[
s_t=(x,p_t,\tau_t,\eta_t,\rho_t,g_t,b_t),
\]

其中 $x$ 为任务与目标函数接口，$p_t$ 为本轮主锚点程序，$\tau_t$ 为包含它的主轨迹，$\eta_t$ 为选择内部锚点时其后已测试的旧尝试，$\rho_t$ 为双轨迹算子使用的参考轨迹，$g_t$ 为当前共享的全局经验，$b_t$ 为预算与阶段状态。

一条轨迹是从某初始程序到当前程序的严格祖先路径。每个新程序只有一个结构父代；参考轨迹只提供知识，不成为第二个父代。全部节点与修改边构成森林，完整记录事实来源；active 轨迹只保留最近 8 个节点，超出则从最早端截断，endpoint、compact best、趋势和内部锚点都只依当前保留段计算。

每条历史边向模型展示修改说明、子程序的一句话思想归纳、父子 fitness 与改进/停滞/退步、以及非空代码行数的变化。历史不重复展示完整代码；主锚点程序始终完整展示，双轨迹算子另完整展示参考程序。

## 3. 主轨迹、参考轨迹与全局经验

主轨迹说明当前程序怎样形成、哪些机制已验证、哪些后续尝试已失败。选内部锚点时，提示分两段展示：锚点之前的形成历史，以及其后的已测试尝试。这样模型能用失败边界约束下一步，又不会把后来的机制误认为已存在于锚点代码。

`trace_synthesize` 与 `trace_transfer` 额外读取一条参考轨迹及其 compact best。参考候选排除主轨迹及 compact best 与锚点相同的路线后，按质量 softmax 选取。参考保留具体实现与完整试错关系，相当于种群中跨个体的知识交换，但交换对象是经轨迹语义解释后的算法思想。参考被使用不增加其父代访问次数。

全局经验 $g_t$ 是第三类知识。它由周期性反思维护，以一段标注为"可错的任务级证据"的文本进入 Action 提示，不进入代码生成，也不改变父代关系。全局经验与参考轨迹的分工在于作用域：参考轨迹是本轮选定的具体路线，全局经验是跨路线凝练的抽象判断。

## 4. 四个轨迹语义算子

四个算子独立保留，可用时等概率选取：

| 算子 | 语义 | 对应的搜索操作 |
| --- | --- | --- |
| `trace_ideate` | 依据完整历史提出新方向，退步与平台视为已测试边界 | 较大步幅的定向变异 |
| `trace_refine` | 对已显价值或已暴露弱点做一次聚焦修正 | 局部、证据驱动的变异 |
| `trace_synthesize` | 从主/参考轨迹各取一原则，使二者在主程序中功能耦合 | 经轨迹适配的重组 |
| `trace_transfer` | 保持主程序核心，迁移参考轨迹中一个有支撑的思想 | 经轨迹适配的定向迁移 |

双轨迹算子仅在参考上下文可用时参与选取。这一对应关系说明算子如何落入种群搜索的变异与交叉，但不把提示改写成抽象的"变异/交叉"；模型看到的是算法思想、试错历史和本轮应如何改动主程序。

## 5. 结构化的修改决策表示

V5.0 要求 Action 阶段输出一个包含恰好两条修改的数组，每条修改由五个部分共同描述：

| 部分 | 含义 | 限制 |
| --- | --- | --- |
| 关系类型 | 本次修改与历史的关系 | 属于 {continue, repair, rollback, redirect, consolidate, synthesize, transfer} |
| 证据 | 支持本次修改的历史边 | 已展示的边标识，可为空 |
| 参考证据 | 双轨迹时引用的参考边 | 同上 |
| 修改内容 | 具体改什么 | 自包含，不超过 400 字符 |
| 差异说明 | 相对已展示尝试的不同 | 不超过 200 字符 |

关系类型标明修改性质，证据把决策锚定到历史，修改内容与差异说明强制模型讲清做什么、为何不同。这是 V5.0 区别于后续版本的主要特征：决策与追溯同在一次输出中完成。代码生成阶段接收相同的主历史、主程序与可选参考，从主程序实现选定修改。

## 6. 全局经验反思

全局经验是一个有序条目序列，每条含类别（effective / pitfall / explore）、一句陈述、适用条件和支撑边。反思按边计数触发：每当新派生边累积到 60 条，取这批边为一个反思批次。反思接收任务、当前全局经验、既有条目的支撑边和这批新边，被要求重写全部经验：保留、收窄、修正或删除，至多 5 条。

重写要求 effective 与 pitfall 必须引用至少两条来自不同谱系、不同子代的边；单一事件或冲突证据只能记为 explore；分数与结果是观察，陈述与修改说明是模型主张，不是已验证因果。返回后按允许的边集合校验证据合法性，丢弃引用未观测边的条目。

## 7. 轨迹评分与父代调度

路线质量为

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i},
\]

两项均为 active 集合中的并列感知百分位。程序比较先看任务 fitness，仅当 fitness 完全相同时较短者优先。

V5.0 的调度标量只取质量：

\[
V_i=Q_i.
\]

路线趋势 $P_i$（保留路径上父子变化符号的折扣聚合，折扣 0.8）只作分析字段，不进入调度。这是 V5.0 相对 V4（$0.6Q+0.4P$）的有意改变：让父代选择完全由当前成果驱动，把走势降为离线诊断量。再加 UCB 与 softmax：

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

UCB 给低访问路线保留试验机会。趋势以 $10^{-12}$ 为正负阈值。

## 8. 锚点、简约与生存管理

父代选定后，从去重的 endpoint 与 compact best 等概率选锚点；compact best 是当前保留段上达到路线最优 fitness 的最短程序。复杂度仅用非空 LOC，只在 fitness 完全相同时用于择简，不形成连续惩罚。

active frontier 目标规模 $M=30$，达到 $2M=60$ 时收缩回 $M$：保留质量精英、含全局最优的路线、少量差异代表，其余席位按调度标量的 softmax 无放回抽样。退出 active 的路线仍留在派生图与日志中，只是不再繁衍。

## 9. 搜索流程

```text
1. 建立至多 30 条评价有效的初始单节点轨迹。
2. 重复至预算耗尽：
   a. 依 Q 与 UCB 选主轨迹；
   b. 从 endpoint / compact best 选主锚点；
   c. 依参考是否可用，等概率选四个算子之一；
   d. 双轨迹算子按质量 softmax 选参考轨迹；
   e. 用主历史、可选参考历史与当前全局经验生成两条结构化修改；
   f. 校验格式，对每条可用修改从主程序生成完整候选；
   g. 评价候选，记录父代、路线最优与全局最优三种变化；
   h. 每个有效候选只从主锚点写入一条边；
   i. 更新 compact best、全局最优、访问统计；
   j. 每累积 60 条新边触发一次全局经验反思并重写 g_t；
   k. active 达 60 时收缩至 30；
   l. 周期保存断点。
3. 返回 fitness 最优、同分时 LOC 最少的程序。
```

## 11. 实验事实与失效诊断

V5.0 在四个任务各重复运行，过程工件揭示两处失效。

**结构化决策供给不足。** 四任务合计的修改决策调用中约 39.6% 因格式不合规而被丢弃（OP-ACO 为 398/1021）。把决策与证据追溯合并为一次输出后，模型常无法同时满足关系、证据和字符限制，整条修改因此作废；能通过校验的调用中也只有一部分得到完整的两条。结果是候选供给被压缩，等量预算下产出的有效候选少于后续版本。

**全局反思从未生效。** OP-ACO 的 16 次反思调用全部失败。V5.0 设有上下文长度检查，但其预算估计与模型服务的真实边界不一致，未能拦住过大的提示；提示到达服务端后被拒绝。因此 $g_t$ 始终为空，全局经验未参与任何一次决策。

两点事实各含一条判断：解析通过不等于执行了目标代码，机制未运行不能视为已检验；把决策与追溯强行合并、把共享经验置于超出模型容量的反思中，都会让设计意图落空。V5.0 结果不进入正式结果页。

## 12. 研究边界与后续

V5.0 确立了 V5 的轨迹种群骨架：四个语义算子、双轨迹参考、有界轨迹与 UCB 调度，这些在后续版本中保留。它暴露的两个问题分别得到修正：结构化决策改回自然语言，进入 [V5.1](TraceAAD-v5.1完整机制设计.md)；全局经验的容量问题在 V5.1 简化为纯文本反思，最终在 V5.3 关闭在线全局经验。
