# TraceAAD V10.10：轨迹搜索与一次有界错误修复

2026-09-10 首版，2026-09-11 修订。状态：从 [V10.9（1091）](TraceAAD-V10.9-机制设计.md)复制后移除新结构试用和直接子代试错上下文，简化算子提示与上下文，并加入最小错误处理；2026-09-11 将初始化收缩为 sequential informed initialization，删除 Init 阶段的 AST 去重与提示中的防御性约束。正式批次 `20260910_v1010_formal` 于 2026-09-10 启动，运行冻结副本中的首版机制；本次修订改变机制与检查点指纹，收缩后机制须另起新批次，旧检查点不兼容。计划保持五任务 × 三重复、每路 1000 次真实评价。验证和运行入口见[运行说明](../../experiments/traceaad_v10_10/README.md)。

## 相对 V10.9 的修改

donor 分配沿用 V10.9，初始化收缩为下文的 sequential informed initialization；四个算子各占 25%，不预设哪种设计动作对所有任务更重要。提示明确操作目标，放宽对具体修改手段的限制。移除两项机制：新结构不再因近期出生或开发不足获得额外选择概率；普通生成上下文不再注入当前节点的直接子代试错记录，Refine 使用宿主形成历史，Fuse 可补充宿主与 donor 的形成历史，Tune/Pivot 不附带历史。形成历史仍可包含改善、持平或退步的真实形成边。一次错误修复临时读取本次失败输出和报错，不构成历史试错记忆。

错误处理包括：

1. **宽容解析。** 先调用原解析器；失败时接受大小写不同的 `Idea:` / `Design Idea:`、`python` / `py` 代码围栏、Idea 前与代码后附加文字，以及正常结束时缺失的闭合围栏。只有单个无歧义代码块可恢复；继续使用原 AST、编译和函数签名校验。未标明 Idea 的前置文字不自动当作算法思想，多代码块不猜选最后一个；这些情况进入一次修复。服务报告 `length` 且没有闭合围栏时不恢复，以免把语法恰好完整的截断程序当作完整生成。
2. **保存具体报错。** 评价收据和失败事件保存 `error_type`、`error`、`traceback`，解析失败记录可行动的原因。复用现有评价器返回的错误字段，不添加静态分析依赖或额外任务预检。
3. **最多一次错误条件修复。** 普通候选解析失败，或因候选代码产生 `exec_error`、`runtime_error`、超时、非法结果和非有限 fitness 时，在下一候选位置优先请求修复。输入为任务接口、去掉思考段的完整失败输出，以及清除路径后最多 2000 字符的核心异常类型和消息；有父代时只展示其成绩作为比较基准。完整错误和调用栈仍存入日志。要求最小改动并保留原 Idea。超时反馈明确为整次评价的总时限，要求减少计算并确保终止。修复输出同时给出 Idea 和完整代码，仍接受正常解析、去重和评价检查；再次失败或重复立即结束修复链。评价准备故障和框架异常记录后终止运行，不调用 LLM 猜测修复。

修复用新的 `candidate_id` 和 `repair_of` 关联原始候选，保留原 operator、parent 和 donor 来源。`llm_calls.jsonl` 通过 `stage=repair` 区分额外调用，并保留 token usage 与耗时。修复没有独立抽取算子或重选父代，不再次增加父节点设计机会计数；成功节点接在原有效父代下，失败候选保留在事件中，不冒充有效树节点。统计每个算子时应同时按 `repair_of` 区分原始生成与修复。

**每一次真实评价都计入 1000 次预算，包含初始失败和修复后的评价。** 解析失败不计评价，但 LLM 调用照常记录。预算已耗尽时不发起修复；不再按本地提示长度跳过修复。已知失败和修复候选均复用现有持久化、收据与恢复流程；未知评价结果继续阻断，不能据此启动修复或重复评价。

普通输出提示保留 `Idea:` 与 Python 代码块，只补齐必要 import/helper、变量先定义、输入形状和返回契约要求。第一版没有新输出标记、JSON Schema、错误记忆库、自动补 import 或额外 smoke evaluator。

依据：[V10.9 错误快照](../analysis/诊断性分析/2026-09-10-V10.9生成与评估错误统计/统计.md)中有 144 次解析失败和 203 次评价失败；[V9.16](../analysis/版本综合分析/TraceAAD-V9.16机制诊断.md)的历史修复恢复过 810/929 个初始失败，但含额外评价成本，不能直接视为同预算搜索提升。V10.10 复用成熟的限次报错回喂机制，并以统一真实评价预算检验其净效果。

## 研究出发点

自动算法设计的目标，是在有限评价预算内发现并开发真正改善求解行为的算法。程序当前的分数只说明其当前实现的效果；一个整体较差的程序可能含有可迁移的好部件，一个尚未调好的结构可能提供后续开发空间。形成思想、借鉴部件与数值精炼因此需要交织进行。

[历史强结果](../analysis/探索性分析/2026-09-09-五任务历史强结果搜索模式/分析.md)呈现出互补的路径：TSP V9.14 通过内部求解结构的变化打开空间；CVRP V9.7 长时间开发几何、容量和参数关系；MCTS-AHD 的 OP/CVRP 用跨程序组合产生突破；CALM 的 OBP 强调保结构数值搜索；VRPTW V9.19 中先退步的迁移分支经后续修正获得收益。这些是过程证据，不能把其成绩单独归因给某个算子、某种树搜索或某段提示。

尤其是 MCTS-AHD CVRP 样本 566：两个输入 9.1767、9.9765，组合后为 8.8431；样本 857：8.8106、8.9159 组合后为 8.7302。较差整体中可有好部件，较好部件之间也能进一步形成协同。不能仅以 donor 的整体质量判断迁移价值。

V10.10 将这些经验落实到同一条决策链：**评价机会给谁 → 需要解决哪个设计问题 → 提供哪些真实试验 → 生成什么改动 → 是否改变求解行为 → 是否值得继续开发**。不安排固定的“探索结束时刻”，也不把 fitness 停滞自动解释为 idea 停滞。

## V10.8 的机制缺口

详细证据与统计边界见[V10.8 机制分析](../analysis/诊断性分析/2026-09-09-V10.8思想形成与精炼/分析.md)。该分析对应 1080 正式批的 9584 次评价快照，1081 个体调度及其 A/B/C/D 实验须分别解读。

| 现象 | 底层问题 | V10.10 对应改动 |
| --- | --- | --- |
| 后期质量分布随档案规模扩散，反复开发还会降低选择权重 | 节点数量、被选次数不能直接代表值得开发的思想数量 | 固定质量 ESS 目标 8，取消次数惩罚 |
| 353/3400 个有效 Fuse 与 donor AST 相同，其中 254 个复制更差 donor | 输入两个程序不等于有针对性的部件迁移 | 以宿主为基础借鉴有用计算，允许替换与重组，拒绝输入 AST 复制 |
| 严格仅数值修改为 119/4436 个有效 Refine | 宽泛 Refine 不保证充分数值开发 | 单列 Tune，专门执行参数设置改进 |
| 历史 Fuse 边缺少当时 donor 的完整代码 | 只能看到变更，难以追踪部件来源 | 展示被选历史转移的 donor 实码与评价关系 |

分析用 AST 去掉了文档字符串；V10.10 在线去重保留文档字符串，避免错误抹去可被程序读取的内容。两个重复率口径不可混用。

## 预算分配：按当前质量集中开发

初始化 8 个有效根节点。其后独立抽取设计任务：Refine、Tune、Fuse、Pivot 各 25%，比例在全程不变。当前证据不足以支持一套跨任务通用的偏置，因此采用中性均分，把差异交给父代选择、算子提示和实际生成结果。

质量分布为 `q_i ∝ exp(β(f_i − max f))`，调节 β 使有效样本数 ESS 尽量接近 8。所有内部 fitness 均为越大越好。数量不足或最高分大量并列时，使用可达到的目标；固定目标不代表实际只选择 8 个程序。运行入口不再传递 `ess_fraction/ess_minimum`；继承接口所需的默认值和未使用的 `history_tokens` 归入 `inherited_unused`，不作为当前控制参数。

- Refine / Tune / Fuse：使用质量分布 q，不施加父代被选次数惩罚。
- Pivot：`p_i = 0.5 q_i + 0.5/N`，保留全局探索机会。

删除 recent 候选池及其 20% 混合概率、64 次评价窗口、2 次请求门槛。新节点与其他节点按同一规则竞争，不因新出生、结构变化或尚未开发而获得额外优待。AST 仅用于识别输入复制，不在线计算修改类别。父代资格不再要求同时通过各算子的提示容量检查，所有有效归档节点均可按质量参与选择。

## 初始化：Sequential informed initialization

保持 8 个有效根目标。第一个根只看任务接口独立生成；从第二个根起，生成上下文按生成顺序依次包含已评价的全部已有根的完整代码与实测 fitness，模型据此再提出一个有竞争力的候选。这是初始化的完整机制：existing programs + fitness → next program。

fitness 只作为已有候选的实测表现进入生成上下文，不承担其他初始化控制功能。已有根按生成顺序完整展示，一次组装后检查完整输入容量，已选提示随候选持久化；超容时明确报错，不筛选或截断候选。

初始化不做任何重复规避：不比较已有根的 AST，不按 fitness 判断重复，不筛选展示的候选；生成结果按正常有效性解析与评价流程处理。生成完成后直接进入正常搜索，不设 bootstrap 或额外开发阶段，后续开发由原有 Refine、Tune、Fuse、Pivot 完成。此机制对所有任务一致，不注入任务专属种子或历史优胜代码。相关历史证据见[初始化比较](../analysis/探索性分析/2026-09-09-初始化机制比较/分析与方案.md)。

## donor：整体质量与部件价值分开处理

候选为档案中除当前节点及其 AST 相同程序之外的所有程序，包括祖先、后代和低分程序。以 `0.5 q_donor + 0.5 Uniform` 直接抽样一个 donor，不按长度预筛选或尝试多个 donor。没有不同代码的 donor 时回退 Refine。

保留低分 donor 的机会是为了获得可迁移部件；相关性判断交给看到两个完整程序的模型。Fuse 以宿主为基础借鉴 donor 中有用的计算，允许必要的适配、替换与重组，目标是超过两个输入；若 donor 没有可用计算，可直接改善宿主，不强制拼接。当前没有额外 LLM 排序调用或相似度打分。

## 上下文：按操作提供必要材料

输入不再扣除固定 16K 输出预留。每次请求的输出上限取 `min(16384, 32768 - 256 - 实际输入tokens)`，普通生成与错误修复一致；只在完整输入已没有输出空间时阻断。历史材料仍按下述规则组装。

所有普通请求包含完整任务接口、输出契约与操作提示；一次调用生成 Idea 和完整代码。

| 操作 | 算法上下文 |
| --- | --- |
| Tune | 当前完整代码和成绩，不附带形成历史 |
| Refine | 当前完整代码和成绩，补充向前最多三条形成边，先近后远 |
| Fuse | 完整宿主与 donor 及成绩优先；再尝试 donor 最近一条形成边、宿主向前最多三条形成边 |
| Pivot | 当前完整代码和成绩作为参考，不附带形成历史；允许替换核心设计 |

取消独立的历史 token 配额及相应在线统计。普通请求按规定材料一次组装，只检查最终聊天输入的总容量；超过实际容量时明确报错，不自动丢材料或改变 donor。每条边独立标明真实 source、target、算子和评价号，不把不相连的边拼成一条链。Tune/Pivot 的 `history_ids`、`evidence_relations` 为空。初始化按上节规则展示全部已有根。

当前节点生成后的直接子代尝试仍保存在搜索档案中，但不作为试错记录装入普通生成上下文，也不按其成败筛选上下文。Fuse 独立选定的 donor 仍按原规则展示，不改变 donor 候选范围。

每条形成边固定携带完整源代码与完整 diff，保证独立可重建；不再比较多种表示的 token 长度。历史 Fuse 边也提供其 donor 的完整实码。`context_best_fitness` 只计算真正展示的节点。

这些证据支持模型辨认有效关系、比较参数设置和重新提出假设。整体成绩不被描述成某一个改动的因果收益，也不使用未经核验的长经验摘要。OP 任务提供补充设计说明，注明已核对的执行事实：仓库列始终被候选掩码屏蔽，修改 `heuristic[:, 0]` 本身不改变采样；静态先验在 ACO 前计算。V10.10 通用读取任务提供的说明，搜索器不按任务名称追加专用提示；旧版本的任务协议保持不变。

## 算子各司其职，又允许形成与精炼交织

| 算子 | 要回答的设计问题 | 修改边界 |
| --- | --- | --- |
| Init | 在已有方法及其实测表现之后，还能提出什么有竞争力的决策方法？ | 首根独立生成，后续根参考全部已有根的实码与成绩 |
| Pivot | 当前假设之外，什么决策方法值得试？ | 当前算法仅作参考，允许替换核心设计或重组有用计算 |
| Fuse | donor 的哪些计算有助于改善宿主？ | 以宿主为基础，允许适配、替换与重组 |
| Refine | 当前设计可以怎样继续改善？ | 参考形成历史，在现有设计内做一次聚焦修改 |
| Tune | 主要算法参数可以怎样设置得更好？ | 调整参数设置，保留核心决策方法 |

Tune 是专门的参数改进任务。删除在线 `edit_kind` 分类和数值 AST 归一化；原始输出及有效节点代码继续保存，需要时离线分析修改类型。解析结果、解析方式与错误原因在本次候选内复用，不为写日志重新解析。

搜索请求在线拒绝与父代或 donor AST 完全相同的输出，不花评价预算；注释和格式变化不能绕过该检查，初始化请求不做该检查。保留原有连续 50 次不可评价输出熔断，LLM 成本单独记录。没有全档案语义去重，也不会声称已杜绝所有无效计算。

## 评价与可复核性

每路 1000 次真实评价包含初始化、评价失败和修复后的评价。LLM 失败、解析失败与输入复制不占评价次数，但记录其调用和时间。沿用已有持久化候选、评价收据、未知评价阻断与恢复规则；版本 10100 的机制、源码与采样参数必须一致才能恢复；后端等价，地址及服务模型名称可随空槽分配同步更新。V10.10 使用独立目录与检查点，不能拼接 V10.9 的实验进度。

本次 15 路检验的是完整 V10.10 系统，不足以独立识别各因素收益。与 V10.8、历史强结果比较时，应按相同真实评价预算对齐 best-so-far 曲线、最终质量和三次重复；历史额外修复评价、固定初始程序与算法运行耗时须注明；当前后端按等价服务处理。跨任务 SOTA 目标需要进一步同条件比较和未知实例/跨规模验证，不能用训练面板单次最好分宣布达成。

重点检查：好结构何时到达、后续获得多少请求及延迟收益；Fuse 是否复制输入、是否真迁移部件以及是否超双亲；Tune 实际动作与增益；每次评价的求解耗时和 LLM 成本。若只增加结构变化而未带来后续收益，或只增加数值修改率而终局变差，应修正机制，不把中间指标当成功。
