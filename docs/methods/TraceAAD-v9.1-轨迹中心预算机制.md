# TraceAAD V9.1：轨迹中心预算机制

V9.1 的当前协议是 `traceaad-v9.1-trajectory-centered`。它把“当前可执行终点 + 其唯一形成历史”作为
预算分配对象；树只保存程序派生关系、形成历史与审计事实，不参与价值定义。

## 运行契约

| 配置 | 默认值 |
| --- | --- |
| 初始轨迹数 | `n_init=4` |
| 每次轨迹验证候选数 | `verification_batch_size=2` |
| 原始质量候选区 | 有向 fitness 前 `quality_pool_size=10` |
| 区域内不确定性 | Wilson 上界，`z=1.0` |
| 最近推进窗口 | `trajectory_recent_window=4` |
| 参考轨迹候选数 | 原始质量前 `reference_pool_size=4` |

当前协议不再包含全局 min–max、节点 UCT、访问回传、continuation-value backup、
渐进式拓宽或初始化后的根扩展。旧协议 checkpoint 版本为 2，当前版本为 3，两者不可恢复混用。

## 初始化

只有第一条初始轨迹从任务本身生成。后续初始轨迹必须读取已有根轨迹的 Idea、完整代码和
真实 fitness，再提出实质不同的算法路线。若完整历史超过上下文限制，按原始有向 fitness
保留可容纳的较好轨迹；不会退回空白生成。初始化完成后，所有新轨迹都由已有轨迹继续产生。

## 预算分配

每个有效程序节点代表“当前可执行终点 + 从初始方案到这里的唯一形成历史”。一次分配分两层：

1. 按锚点原始有向 fitness 排序，只让前 10 条轨迹进入质量候选区。fitness 不做跨节点归一化，
   也不与探索项相加。
2. 候选区内未验证轨迹先获得一次基本验证；全部验证后，以各轨迹自己的路线推进次数与验证次数
   计算 Wilson 上界，并用最近推进率、原始 fitness 和代码简洁性依次打破平局。

因此，一条轨迹的分配证据只会在它自己接受新验证后变化。其他轨迹出现极端好坏结果，不会改写
这条轨迹的推进率或不确定性。

## 轨迹验证事件

一次验证固定选择一条轨迹，并从可用算子中抽取两个不同的语义入口，各生成一个 `Idea + Code`；
仅在总预算只剩一个 evaluator 样本时，末尾批次缩减为一个候选。
双轨迹算子只能引用不在当前祖先—后代链上的轨迹，参考候选同样按原始质量筛选，不做 softmax
归一化。

所有生成、解析和 evaluator 结果都属于该验证事件。有效候选各自形成一条更长的新轨迹；无效批次
也会给被选轨迹记一次失败验证。只有候选超过分配前该轨迹沿途达到的历史最好，事件才记为一次
“路线推进”。普通父子改善若只是从此前退化状态回弹，不算路线推进。

验证结束后只更新被选轨迹自身的：

- 完整验证次数与有效候选数；
- 路线推进次数和最近推进记录；
- global-best 推进次数；
- 最后一次验证批次。

这些信用不复制给祖先。子代从父轨迹继承“沿途历史最好”事实，但不继承父轨迹的验证统计。

## 历史如何指导生成

生成上下文保留当前程序完整代码，并展示最近 8 条形成边和最多 8 个直接子分支。历史边不重复完整代码，
只展示 Idea、直接 fitness 结果、代码变化比例和 LOC；直接分支显示 Idea、结果和是否推进路线最好。四个入口分别用于
新方向、证据修正、两条历史的相容组合和已测试改动的迁移。Idea 本身不兑换数值信用；它与实际代码变化和 evaluator 结果绑定后，
才成为下一次生成的有限证据。

当前协议是轨迹信用的第一阶段基线。它尚未使用轨迹水平、趋势、波动、延迟后代证据或轨迹—算子条件效果；这些是研究问题，不是本版已实现行为。

global best 仍只按原始有向 fitness 判断，同分时选择更短程序。完整研究动机、可证伪假设和验证
门槛见 [RQ-006](../research/RQ-006-轨迹中心预算分配.md)。
