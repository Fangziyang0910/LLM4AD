# TraceAAD 历史机制探索（V2–V9.4）

> 本文压缩 V2–V9.4 各版本的机制设计要点：每一版探索了什么问题、机制骨架怎样定义、为何被下一版取代。实验结局与机制诊断统一见[版本谱系与实验事实](../analysis/TraceAAD-版本实验事实与机制诊断.md)，此处不重复。完整规范只保留仍然有效的四份：[V9-Core](TraceAAD-v9-core完整机制设计.md)、[V9.5](TraceAAD-v9.5完整机制设计.md)、[V9.6](TraceAAD-v9.6完整机制设计.md)、[V9.7](TraceAAD-v9.7完整机制设计.md)；被本文替代的版本规范全文由 git 历史承担。

## 探索主线

三个阶段，每个阶段回答一个搜索组织问题：

1. **种群搜索（V2–V7）**：把"当前程序及其来时路"作为搜索个体，用固定规模的轨迹种群分配繁衍预算。探索的核心张力是：附属机制（岛、课程、多分量价值、算子信用）能否提供独立于轨迹主干的信号——结论是不能，逐版删减。
2. **完整树搜索（V8 系列）**：取消种群硬淘汰，用完整单父树保存全部有效程序，把"保留哪些状态"从生存问题改为预算分配问题。V8.2 树骨架被 V9-Core 沿用至今；V8.3 的复合信用与深度上限失败。
3. **锚点中心预算（V9.1–V9.4）**：在 V9-Core 之后，逐版检验"轨迹作为预算证据"的不同信用定义——路线推进率、直接子代均值、rollout 结算、折扣回传。V9.4 确立"一次选择 = 一个 `Idea + Code` = 一次评价"的决策骨架，沿用至当前版本。

贯穿全程不变的要素：单结构父代（参考只传知识，不成第二父代）；真实 evaluator 决定 fitness；失败与退步保留为历史证据；fitness 优先、完全同分时择短。

## V2：机制叠加的第一版完整实现

把主张落地的第一版：有界轨迹（8 节点）+ 单父派生图，之上同时运行六套附属机制。

- **岛模型**：4 岛 × 40 条轨迹，停滞时环式迁移各岛最强路线。
- **五算子**：`endpoint_refine` / `backtrack_branch`（全池扫描回溯目标）/ `mechanism_crossover`（按互补度选 donor）/ `simplify`（复杂度高于池上四分位才触发）/ `novelty_jump`（fresh start，后期限概率）。
- **六分量价值** \(V=0.42Q+0.18P+0.12D+0.12N+0.08C+0.08S\)（质量、潜力、差异、新颖、紧凑、速度），加衰减 UCB（\(c_0=0.4\)，停滞增强），top-12 + 岛代表 + softmax 采样。
- **算子 portfolio**：折扣 UCB bandit + 上下文 bonus + 贝叶斯先验 + softmax/epsilon；信用逐边结算，不向祖先回传。
- **三层记忆**：精英课程（由全局最优刷新事件构造生成参照）、边级经验（按算子取成功/失败修改示例）、Elo 对比反馈。
- 新颖性门 0.92；去重 + 每岛 Pareto + 全局截断 160。

**去向**：没有任何附属层能被证明提供独立于轨迹主干的信号，且内部归因困难。V3 全部删除。

## V3：删附属层，回到轨迹主干

系统性删减：保留轨迹、派生图、四算子（删 `simplify`）、三分量价值 \(V=0.55Q+0.25P+0.20D\)、固定 UCB（轨迹 0.4 / 算子 0.5）、边级经验与新颖性门；移除岛模型、精英课程、Elo、复杂度度量、上下文 bonus、softmax/epsilon portfolio、Pareto 生存。

两处矫枉过正：轨迹与算子选择全部改为确定性 argmax（随机性只剩模型采样本身）；潜力的质量门控被取消。

**去向**：V4 重构为单父代轨迹搜索，把轨迹长度、价值分量、调度方式在主干内部逐一重定义。

## V4：轨迹作为 MDP 状态历史

把改进历史形式化为 \(s_t=(x,p_t,h_t,b_t)\)，action 是边上的语义修改，轨迹是状态历史与推理上下文。建立"改进历史 → LLM 推理 → 子代评价 → 新历史"的核心回路。

- 算子收到两个：`trace_ideate`（一个未尝试的新思想）/ `trace_refine`（深化已显价值的思想），等概率；双父代与 crossover 全部删除。
- 评分：\(Q=0.7Q_{endpoint}+0.3Q_{best}\)（百分位），趋势 \(P\) 为折扣结果符号（\(\gamma=0.8\)），\(V=0.6Q+0.4P\)；UCB \(c=0.25\) + softmax \(T=0.2\)（恢复随机采样）。
- 锚点在末节点与轨迹内历史最好节点间等概率；选内部锚点时锚点后的失败尝试仍入提示作为已测试边界。
- 种群 \(M=30\)，扩张到 \(2M\) 再收缩：质量精英 + 差异 reserve（max-min 距离）+ softmax 抽样 + global-best 路线强制保留。

**去向**：V5 重新引入跨路线知识流动（双轨迹算子）。

## V5：轨迹种群与四语义算子（正式定稿）

搜索个体是"当前程序及其来时路"；四算子对应变异与交叉的底层亲缘：`trace_ideate` / `trace_refine`（单轨迹定向变异）、`trace_synthesize` / `trace_transfer`（经轨迹语义适配的重组与迁移，读取一条参考轨迹的 compact best 与形成历史）。

- 修改决策与代码生成两阶段共享同一历史，减少意图到实现的信息损失。
- \(V=0.8Q+0.2P\)（趋势阈值 \(10^{-12}\)），UCB 0.25，softmax 0.2；锚点在 endpoint / compact best 间等概率；参考按质量 softmax。
- 不维护在线全局经验——跨路线知识只通过本轮选定的参考轨迹进入决策。
- 复杂度只在 fitness 完全相同时择短，不入评分。

开发子版本的受控取舍：V5.0 的结构化五字段决策与全局反思不可运行，V5.1 撤回为自然语言两条与 5 条纯文本要点；V5.2 把趋势以 0.2 权重放入调度；V5.4 把趋势提高到 0.4 并放宽阈值至 $10^{-6}$，结果偏向噪声，随后回退。

**去向**：V6 追问"哪些代理规则本不该存在"。

## V6：简约的轨迹进化

核心判断：局部改进率、成熟度、路线信用、差异门槛、固定算子比例等手工代理都在预判"哪条路线值得投入"，而这类判断应交给 evaluator。V6 只保留：真实历史、\(Q=0.7/0.3\)（不含趋势）、UCB 0.25 + softmax 0.2、四算子等概率、global-best 路线 + Q-softmax 生存。

历史不按"成功/失败价值"重排；超上下文时按确定规则从较早历史裁剪。`positive_threshold` 只作日志标注，不改变接受与生存。相同 endpoint 代码不在线去重（不同来时路视为不同个体）。

**去向**：V7 处理重复 endpoint 占用繁衍席位的问题。

## V7：可执行状态唯一（种群路线最后一版）

两项设计：active frontier 按精确 `code_hash` 保证 endpoint 唯一（重复路线归档，事实不删除；命中缓存复用 fitness 不重复评价）；探索强度随剩余预算衰减，\(A_i=V_i+0.25\,r_b\sqrt{\log(1+N)/(1+n_i)}\)，\(r_b\) 为剩余预算比例。

其余：\(V=0.8Q+0.2P\)；从内部锚点分支时旧尝试以 `evidence_edge_ids` 携带到新路线（知识证据，非第二父代）；Action 阶段改用 strict JSON Schema。

**去向**：种群生存决策把"当前是否保留"与"未来是否值得发展"绑在一起，archived 路线永久失去繁衍机会。V8 用完整树取消硬淘汰。

## V8 / V8.2：完整树与自适应扩展

> 树骨架被 V9-Core 沿用至当前版本，是本阶段的存活产物。

用完整单父树替代轨迹种群：虚拟根 + 初始根分支，全部有效节点永久保留，任何节点可经递归选择重新获得扩展机会。借鉴 MCTS 的 UCT 与子树回传，不采用 MCTS-AHD 的算子集合、elite population 或额外推理调用。

- **子树信用**：\(G(n)=\max(f(n),\max_c G(c))\)，max-backup 沿祖先路径更新；明确定位为乐观的发展潜力代理，不是思想因果证明。
- **递归 UCT**：子树值经全树中秩百分位归一化 \(Z\)，\(\mathrm{UCT}(c)=Z(c)+\lambda_0 r_t\sqrt{\log(1+N(p))/N(c)}\)，探索随剩余预算衰减。
- **自适应扩展**：每个节点有 `new_child` 选项与已有子节点统一竞争。扩展批回报 \(R_b=\max_{c\in C_b}Z(G(c))\)（失败批为 0），新分支质量 \(Q_{new}=[\beta Z(f(n))+\sum_b R_b]/(\beta+B)\)（\(\beta=1\)，自身质量作先验）。无树深与 child 数上限。
- **上下文**：祖先路径最近 8 条边 + `[Previously Tested From This Program]` 最多 8 个直接子分支摘要；参考从其他根分支的 subtree-best 按 \(Z\)-softmax 选。
- 单次 `Idea + Code` 生成（V8.1 起删除独立 Action 调用）；无在线去重、无算子 reward、无趋势项。

V8 初版与 V8.2 同代码两配置：初始根 30 → 10；平方根渐进拓宽 → 价值驱动 `new_child`；两阶段生成 → 单次 `Idea + Code`；\(\lambda_0\) 0.5 → 0.1；极差归一化 → 中秩百分位。两者终局不可分辨，消融基座取 V8.2 形态。

**去向**：V8.3 试图在树上加更强的信用与意图控制，失败；V9-Core 保留骨架、简化调度后成为里程碑。

## V8.3：局部探索脉络与复合信用（失败版本）

问题：树路径可能过长，调度器未必把当前节点附近最相关的尝试交给 LLM。设计：

- **局部脉络**：最近 3 条形成边 + 最多 3 个代表性直接子分支，统一为"思想—形成的算法—结果"三行格式；退步子分支若后代挽救，额外记录后续最好值。
- **两次调用**：Call 1 生成 `design_idea + code`，Call 2 读实际代码生成事实描述 `description`，意图与事实分离。
- **五算子**：`trace_refine` / `trace_tune` / `trace_simplify` / `trace_innovate` / `trace_crossover`（参考从全树按 fitness-softmax 选，温度 1.0）。
- **复合信用**：`descend` 用 \(B(c)+0.1r_t\sqrt{\cdot}\)；`new_child` 先验含路线前沿推进信号 \(\pi(n)=\min(1,F(n)+0.1\sqrt{P_h C_h})\)，直接回报 \(R=0.75F(c)+0.25[F(c)-F(n)]_+\)；平方根宽度下限 + 固定深度上限 `max_depth=10`。

同版本号下另有一条信用重设计路线（轨迹先验、路线经验信用与概率 UCT）；该机制能够运行，但未形成正式发布结果。

**去向**：正式批次出现根锁定与 sibling 爆炸，四任务全落后；两轮修正无效。V9-Core 保留局部历史上下文的语义，弃用固定深度、复合信用公式与五算子。

## V9.1：轨迹中心预算（路线推进率信用）

V9-Core 之后的第一个信用实验：把"当前可执行终点 + 其唯一形成历史"作为预算分配对象，树只保存事实。

- 分配两层：按原始有向 fitness 取前 10 进质量候选区（不归一化、不加探索项）；区内未验证轨迹先获一次基本验证，之后以各轨迹自身"路线推进次数 / 验证次数"的 Wilson 上界（\(z=1.0\)）排序。
- **路线推进**定义为候选超过该轨迹沿途历史最好；从退化状态回弹不算。信用只属于被选轨迹，不复制给祖先。
- 一次验证事件生成 2 个候选；初始 `n_init=4`，后续初始轨迹读取已有根的代码与结果再提出实质不同路线。
- 不含全局 min–max、节点 UCT、访问回传、渐进拓宽。

**去向**：机制按预期运行并实际改变搜索形态，但质量改善只出现在 TSP；推进率作为信用偏爱能持续小幅刷新自身最好的路线，V9.2 起放弃。设计依据与结局见 [RQ-006](../research/RQ-006-轨迹中心预算分配.md)。

## V9.2：锚点中心与规范局部窗口

确立两个沿用至今的构件：**锚点是选择与信用单位**；**每个锚点只有一个确定性的规范局部窗口**（为同一锚点枚举多窗口分别学 \(Q(a,W)\) 会把信用样本持续切碎）。

- **窗口**：最多 8 个 `Idea—结果`事件，优先 4 个父链形成事件 + 4 个深度 3 内近期下游事件，一侧不足另一侧补足；不按 fitness 挑好事件，失败与退步必须保留；历史不含代码，只有锚点完整代码进提示。
- **信用**：\(Q(a)=[q(a)+\sum_i z_i]/(1+n(a))\)，\(z_i\) 为有效子代的绝对质量 \(q(c_i)\)、无效时记 \(q(a)\)；原始任务尺度，无归一化、无祖先回传。
- **选择**：\(Q\) 前 10 质量区，未验证优先，否则最高 \(Q\)；无 UCB、无温度采样。
- **初始化 8→6**：一次规划 8 条互补策略假设 → 独立实现 8 个根（互不读取）→ 各做一次 bootstrap 形成两节点微轨迹 → 按 \(Q\) 筛 6 个正式锚点。该流程沿用至今。
- 单候选单事件；程序经 AST 净化，去注释与 docstring。

**去向**：\(Q\) 的经验均值未稳定超过纯 \(q(a)\)；V9.3 试图放大轨迹的多步性质。

## V9.3：三步 rollout（决策粒度错误）

假设"连续发展一段短轨迹"比"生成一个子代"更能利用延迟改善：一次全局分配固定执行三步，退步结果也作为下一步锚点；两阶段生成（轨迹窗口只进 Idea 决策，代码阶段只读锚点与已定 Idea）；信用按 best-of-rollout 结算 \(Q(a)=[q(a)+\sum_j r_j]/(1+m)\)，只有整段代表程序加入候选集；初始化 8×(1+3)。

**去向**：后续审查确认这把"轨迹提供多步历史"误实现为"一次全局选择后固定连续做三次决策"，改变了基本预算单元，且把轨迹证据、连续决策与 best-of 选择绑成不可分辨的联合机制。V9.4 删除该抽象。

## V9.4：单步决策骨架与折扣信用

> 决策骨架（一次全局选择 = 一个 `Idea + Code` = 一次评价 = 一次事实更新）沿用至当前版本。

- **生成几步与价值看几步分开**：每次只生成一个子代；信用沿真实形成的轨迹有限回传，\(\mathrm{credit}(a,x)=0.5^{d}\,[q(x)-q(a)]_+\)（\(1\le d\le 3\)，与窗口可见深度一致），\(Q(a)=q(a)+C(a)/N(a)\)。不用 max 复制，退步与无效记零并稀释均值。
- **已验证失败反馈**：任务内汇总解析器 / evaluator 真实返回的失败类别与频次，每次展示最高 5 类；只在实现风险相同时使用。
- **严格全局突破**独立记录（同分择简不计），暂不入 \(Q\)。
- **选择**：\(Q\) 前 10 质量区，4 次利用 + 1 次区内最低访问覆盖。
- 初始化恢复 V9.2 的 8→6 单次 bootstrap。

**去向**：折扣信用运行但几乎不改变分配（附近正增益稀疏）。V9.5 改以"锚点质量 + 子代成功率乐观项"分配，并重写证据窗口，见 [V9.5 完整机制设计](TraceAAD-v9.5完整机制设计.md)。
