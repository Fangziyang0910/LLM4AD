# TraceAAD V5.1：自然语言修改决策与可运行的全局反思

## 1. 设计动机

V5.1 修正 V5.0 的两处失效：结构化决策供给不足，全局反思从未生效。它保留四个语义算子、双轨迹参考、有界轨迹与 UCB 调度，改写修改决策与全局经验的表达形式，使其在模型实际的输出与容量限制下可运行。

V5.1 的判断是：一次修改决策应当只承载"改什么"，而不是同时承担追溯表单。把关系类型、证据编号和字符限制叠在同一次输出上，会让模型在满足表单时偏离提出有效修改的主任务。V5.1 让决策回归自包含的自然语言，把来源追溯交给搜索系统记录。全局经验同步从结构化条目简化为纯文本，去掉证据边校验和会否决整次反思的结构化检查。

V5.1 同时移除两条插入搜索主回路的额外约束：反思后的结构化校验，以及候选与锚点父代文本相同时的拒绝。前者让反思在格式不合规时整体作废，后者在评价前过滤候选，二者都偏离"由 fitness 决定接受"的原则。上下文长度检查予以保留。

## 2. 搜索状态与轨迹

状态与 V5.0 相同，$g_t$ 仍为共享全局经验，但内部表示由结构化条目变为纯文本。轨迹结构、派生图与 8 节点上限不变。V5.1 重命名了历史展示的分段：锚点之前的形成历史记为 `[How This Program Was Reached]`，其后的已测试尝试记为 `[Later Attempts From This Program]`，取代 V5.0 的 `[Formation History]` 与 `[Tested After Anchor]`。两段仍共享 8 步上限、前后各取一半。

## 3. 自然语言修改决策

修改决策阶段接收任务、主程序、主历史、算子方向，以及可选的参考程序与参考历史，输出恰好两条编号、单行、自包含的自然语言修改建议。每条须说明改什么、相对已展示尝试的差异、只依赖目标函数参数与局部计算，并在双轨迹时说明如何利用参考知识。输出为纯编号列表，不含结构化字段、代码或独立理由段。

这是 V5.1 与 V5.0 的核心差别：模型只提出修改，来源（算子、锚点、参考轨迹、父子边）由系统记录，不要求模型在输出中复述。代码生成阶段接收相同的主历史、主程序与可选参考，从主程序实现选定修改；提供完整上下文是为减少从修改意图到代码的信息损失。

## 4. 全局经验反思

V5.1 保留周期性全局反思，但简化其表示并移除结构化校验：

- **表示。** $g_t$ 为一段纯文本，至多 5 条要点，不再要求关系类型与证据编号。
- **提示。** 反思接收任务、上一轮反思文本和近期代码变更摘要（每条含修改、思想归纳、fitness 变化与结果），被要求重写为有助于后续修改的要点。
- **校验。** 移除 V5.0 的结构化校验。V5.0 在反思返回后检查证据合法性，不合规则整次作废、$g_t$ 不更新；V5.1 直接存入反思文本。上下文长度检查保留。
- **触发。** 仍按边计数，每累积 40 条新边触发一次。纯文本提示远小于 V5.0 的结构化版本，因此能通过长度检查并被服务端接受。

全局经验仍以一段标注为"可错的任务级证据"的文本进入修改决策提示，不进入代码生成，不改变父代关系。

## 5. 轨迹评分与父代调度

V5.1 沿用 V5.0 的纯质量调度：

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i},\qquad V_i=Q_i.
\]

趋势 $P_i$ 仍只作分析字段。UCB 与 softmax 不变：

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

因此 V5.1 与 V5.0 在调度层面一致，差别全部来自修改决策与全局经验的可运行性。这一隔离让后续 V5.2 能单独检验"把走势纳入调度"的效果。

## 6. 锚点、简约与生存管理

锚点选择、复杂度规则与种群管理与 V5.0 一致。V5.1 移除了候选与锚点父代文本相同时的拒绝：V5.0 在代码生成后比较二者，相同即丢弃；V5.1 不再如此，候选是否进入树与种群只由评价结果（fitness 有效）决定。程序文本相同性与相似度退回过程诊断用途，不在线过滤。

## 7. 搜索流程

```text
1. 建立至多 30 条评价有效的初始单节点轨迹。
2. 重复至预算耗尽：
   a. 依 Q 与 UCB 选主轨迹；
   b. 从 endpoint / compact best 选主锚点；
   c. 依参考是否可用，等概率选四个算子之一；
   d. 双轨迹算子按质量 softmax 选参考轨迹；
   e. 用主历史、可选参考历史与当前全局经验生成两条自然语言修改；
   f. 对每条可用修改从主程序生成完整候选；
   g. 评价候选，接受只看 fitness；
   h. 每个有效候选只从主锚点写入一条边；
   i. 更新 compact best、全局最优、访问统计；
   j. 每累积 40 条新边触发一次纯文本全局经验反思；
   k. active 达 60 时收缩至 30；
   l. 周期保存断点。
3. 返回 fitness 最优、同分时 LOC 最少的程序。
```

## 9. 在版本谱系中的位置

V5.1 把修改决策收窄为"只承载改什么"的自然语言输出，把来源追溯交给搜索系统记录；全局经验同步简化为纯文本并移除结构化校验。它保留 V5.0 的纯质量调度 $V=Q$。[V5.2](TraceAAD-v5.2完整机制设计.md) 把路线走势纳入调度标量。

实验事实与机制诊断见 [版本实验事实与机制诊断](../analysis/TraceAAD-版本实验事实与机制诊断.md)。
