## 1. 设计目标

TraceAAD V8.3 研究一个核心问题：

> 算法下一步如何利用已经发生的改进历史继续设计和试错？

V8.3 的基本假设是：算法改进不是孤立地生成一组代码，而是由一系列中间方案、修改
思想和评价结果组成的过程。保存这条过程，可以让下一次生成知道当前算法从哪里来、
哪些修改已经尝试过、哪些方向产生过价值，以及哪些路线仍然值得发展。

V8.3 用一棵单父代搜索树保存所有评价有效的算法，用根到当前节点的路径表示改进轨迹，
并从树中提取围绕当前节点的局部探索脉络指导下一次生成。MCTS 将有限 evaluator 预算
分配给不同的算法状态。所有有效节点永久保留，不使用 population 淘汰来决定某条历史
是否还能继续发展。

## 2. 总体流程

```text
任务描述、目标函数契约
        |
        v
初始化 10 个评价有效算法
        |
        v
虚拟根 + 算法改进树
        |
        +--> MCTS 选择一个待扩展节点
        |        |
        |        +--> 记录选择路径访问和本次扩展尝试
        |        +--> 选择一个改进算子
        |        +--> crossover 时再选择一个参考算法节点
        |        +--> 构造当前节点的局部探索脉络
        |        +--> LLM Call 1: design_idea + code
        |        +--> LLM Call 2: description
        |        +--> evaluator: fitness + evaluation_time
        |        +--> 有效：创建一个子节点和一条边
        |        +--> 失败：只记录尝试，不入树
        |
        +--> 将直接回报写入本次选择路线，并更新 global best
        |
        +--> 直到预算耗尽或触发停止条件
```

每次搜索扩展只生成一个候选。一个节点可以被反复选中，因此仍然可以拥有任意多个
子节点。V8.3 没有扩展 batch、sibling 聚合或 batch reward。

## 3. 算法个体

### 3.1 个体表示

一个评价完成的算法个体定义为：

```text
AlgorithmRecord = {
    design_idea,
    code,
    description,
    fitness,
    evaluation_time,
}
```

字段含义：

- `design_idea`：生成代码之前提出的算法设计意图；
- `code`：完整可执行实现，是 evaluator 的唯一执行对象；
- `description`：读取实际代码后，对代码真实行为的简洁描述；
- `fitness`：evaluator 返回的有限数值；
- `evaluation_time`：evaluator 实际执行代码的墙钟时间，单位为秒，不包含 LLM 时间。

`design_idea` 和 `description` 的职责不同：前者记录预先提出的设计，后者记录实际实现。
失败候选可以在最小运行记录中保存 `fitness=None`、失败原因和耗时，但不属于有效算法个体。

### 3.2 生成协议

每个新算法固定经过两次成功的 LLM 调用：

```text
Call 1: 任务上下文 -> design_idea + code
Call 2: 任务、design_idea、code -> description
Evaluation: code -> fitness、evaluation_time
```

第二次调用只描述已有代码，不重写代码，也不提出新的修改计划。

两次调用均使用文本协议，不使用 JSON Schema、函数调用或 API 级 structured output。

Call 1 的有效输出：

````text
Design Idea: <one concise sentence>
Code:
```python
<complete implementation>
```
````

Call 2 的有效输出：

````text
Description: <concise factual description of the implementation>
````

每个调用独立重试。请求异常、空响应或解析失败时，首次请求之外最多再请求三次；
三次重试仍失败，则放弃当前候选。初始化阶段继续下一个初始候选；搜索阶段结束
当前扩展尝试，下一轮从虚拟根重新选择。生成阶段失败不消耗 evaluator 次数，也不创建
树节点。

## 4. 评估协议

### 4.1 评估边界

只有 Call 1 和 Call 2 都成功后，代码才进入 evaluator。evaluator 已接受并开始执行
候选时，立即计为一次 evaluator 评估，无论最终成功还是失败。

以下情况属于评估失败：

- timeout；
- 代码 syntax/runtime error；
- evaluator 进程崩溃或评估器异常；
- 输出缺失、无法解析为数值；
- `NaN`、`inf` 或其他非有限 fitness。

失败候选不重试同一份代码，下一次尝试生成新候选。
评估成功的候选直接成为新节点；V8.3 暂不做代码去重或等价性判断。

### 4.2 扩展顺序与耗时

V8.3 的搜索循环在候选级串行执行：一次扩展完成评估并入树，或已经按失败尝试
记账后，才从虚拟根开始下一轮选择。evaluator 内部可以并行处理一个候选所需的任务实例，
但不同树扩展之间不并发。

`evaluation_time` 从 evaluator 开始执行代码到返回结果或失败为止记录。

### 4.3 失败尝试

上下文无法容纳，LLM 请求或解析最终失败，以及 evaluator 未返回有限 fitness，
都统一视为没有产生新算法的失败尝试。失败尝试不创建节点或边，不参与参考选择或
global best。

在搜索阶段，本轮已经发生的选择路径访问和 $A(n)$ 仍然保留，并向本轮实际经过的
程序节点回传 $0$。随后结束本轮，下一轮重新从虚拟根选择。
只有 evaluator 已启动时才消耗 evaluator 预算。

## 5. 初始化

初始化目标是获得 10 个评价有效算法，而不是执行 10 次生成尝试。失败的 LLM 请求、
解析和评估都不增加有效初始化数量；流程继续生成新候选，直到达到目标或触发停止条件。

设已经获得的有效初始集合为：

$$
\mathcal{A}_k=\{A_1,\ldots,A_k\}.
$$

初始化规则：

1. `A1` 使用 `i1`，根据任务描述和目标函数契约独立生成一个完整算法；
2. `A2` 使用 `e1`，从已有有效集合中提供一个参考；
3. `A3` 至 `A10` 使用 `e1`，每次从已有有效集合中均匀、无放回地选择两个不同参考；
4. 每个参考只展示 `design_idea` 和完整 `code`；不展示 `description`、`fitness`、排名、
   搜索评分或 global best；
5. 每个有效初始算法都直接连接虚拟根；参考关系不改变树的结构父代。

`e1` 将参考算法作为可利用的设计信息，要求生成一个适合当前任务的新完整算法。系统不规定
新算法必须融合、远离或只用于避免重复；模型根据参考内容和任务自行决定如何利用。
初始化参考只来自已经评价有效的初始算法。两个参考的无放回只指同一次抽样内不重复；
新的初始化尝试会重新抽样。

初始化在以下任一条件满足时结束：

- 有效初始算法达到 10 个；
- evaluator 预算耗尽；
- 连续 20 次尝试都未得到有效算法。

未达到 10 个有效初始算法时，记录实际数量和停止原因，结束本次运行；
不用失败候选填充树，也不以不完整初始集进入搜索。

## 6. 树与轨迹

### 6.1 虚拟根

虚拟根不包含算法记录，保存根子节点集合和根访问次数。初始化完成后，它与程序节点
一样遵循 progressive widening；宽度不足时用 `e1` 增加新的独立根方案。

### 6.2 程序节点

每个评价有效算法对应一个 `TreeNode`：

```text
TreeNode = {
    id,
    algorithm: AlgorithmRecord,
    parent_id,
    child_ids,
    visit_count,
    expansion_attempts,
    credit_sum,
    credit_count,
}
```

字段含义：

- `parent_id`：唯一结构父节点；
- `child_ids`：已经从该节点产生的有效子节点，按创建顺序保存；
- `visit_count`：MCTS 选择路径经过该节点的次数；
- `expansion_attempts`：该节点被选中并尝试生成新子代的次数，包括失败尝试；
- `credit_sum / credit_count`：从该路线继续搜索时已经观察到的直接扩展回报总和与次数。

`expansion_attempts` 不是子节点数量。一个节点可能有 3 次扩展尝试、2 个有效子节点和
1 次失败。

节点深度、有向 fitness 和子树价值都从结构和算法记录中计算，不属于核心节点字段。

### 6.3 修改边

每个有效子节点有且只有一条结构入边：

```text
TreeEdge = {
    parent_id,
    child_id,
    operator,
    reference_node_id,
    parent_quality,
    child_quality,
}
```

边由 `(parent_id, child_id)` 唯一确定，不单独分配 edge ID。两个 quality snapshot 只用于
冻结该次 `new_child` 的直接信用；`reference_node_id` 只记录生成时读取的额外参考，不构成
第二个结构父代。初始化动作 `i1/e1` 记录在初始化工件中，初始节点不需要入边。

### 6.4 轨迹

对任意节点 $n$，从所属根子节点到 $n$ 的节点和边序列定义其改进轨迹：

$$
\tau(n)=(n_0,e_1,n_1,\ldots,e_k,n_k=n).
$$

轨迹由以下事实组成：

- 每一步的子节点 `design_idea` 和 `description`；
- 每一步使用的 `operator`；
- 父子 fitness 的变化；
- 可选的跨分支参考节点。

完整轨迹由树的节点和边保存，用于重建节点的结构来时路。LLM 不直接读取完整轨迹
或整棵子树；每次生成时按第 8 节提取一个围绕当前节点的局部探索脉络。

## 7. MCTS 搜索

### 7.1 决策对象

每轮搜索从虚拟根开始。虚拟根和程序节点都遵循 MCTS-AHD 的 progressive widening
顺序。对当前节点 $n$，当直接子代数低于
$\max(1,\lfloor N(n)^\alpha\rfloor)$ 时，本轮直接把 $n$ 作为新子代的父节点；
这一步不与 `descend` 进行价值竞争。宽度达到后，才在已有子节点中按 UCT 选择
`descend(c)` 并继续向下。叶节点没有可下降的子节点，因此必然扩展。

虚拟根的 `new_child` 使用 `e1` 生成新的独立根方案；程序节点的扩展仍从五个
算子中等概率选择。这样路线数量由访问次数渐进增加，避免成功 sibling 使某个
节点永久垄断 `new_child`，也允许搜索预算增加时重新打开新的根路线。

默认保留 MCTS-AHD 的平方根宽化指数 $\alpha=0.5$。达到宽度后的选择使用后文定义的
轨迹先验、路线经验信用与概率 UCB，不使用子树历史最大值或剩余预算衰减。

### 7.2 有向 fitness 与全局秩归一化

先把不同优化方向统一为越大越好：最大化任务取原 fitness，最小化任务取其相反数，记为
$y(n)$。V8.3 使用当前全树有效节点作为参照集合，将 $y(n)$ 转为并列感知的中秩百分位
$F(n)\in[0,1]$。当全树只有一个值或全部同分时取 $F(n)=0.5$。该归一化只服务于搜索，
不会改变原始 fitness 和最终算法排序。

对节点 $n$ 的唯一根到节点路径 $\tau(n)$，定义路径历史最好质量：

$$
H(n)=\max_{v\in\tau(n)}F(v).
$$

### 7.3 轨迹先验

轨迹先验表达在尚无充分后续扩展样本时，从节点本身及其来时路能够直接观察到的事实。
首先合并当前端点与路径历史最好质量：

$$
Q_{history}(n)=0.7F(n)+0.3H(n).
$$

最近 $h=8$ 条形成边按真实父子 fitness 变化记为：改善 $1$、持平 $0.5$、退步 $0$；
越新的边权重越高，折扣为 $0.8$。其加权平均记为 $P(n)$；没有形成边的初始节点取
$P(n)=0.5$。轨迹先验为：

$$
V_{prior}(n)=0.8Q_{history}(n)+0.2P(n).
$$

端点质量占主体，历史最好允许曾经有效的路线从暂时退步中恢复，小权重近期趋势区分
持续改善和持续退步。该先验不判断算法语义类型，也不决定算子。

### 7.4 单次扩展回报

在节点 $n$ 扩展得到直接子节点 $c$ 时，先按新节点入树时的全局参照集合冻结 $F(n)$ 和
$F(c)$，再定义：

$$
R(n,c)=0.75F(c)+0.25[F(c)-F(n)]_+.
$$

绝对质量是主体，直接改善只作较小修正。上下文构造、生成、解析或评估失败时回报为
$0$。以后从 $c$ 产生的后代不会追溯改写本次回报，因此一次扩展始终只代表它直接产生的
结果。

### 7.5 路线经验信用

一次扩展选择了从虚拟根到父节点 $n$ 的唯一路径。扩展结束后，将同一个直接回报写入
该路径上的所有程序节点；虚拟根不记录信用。节点保存累计回报 $C_{sum}(n)$ 和样本数
$C_{count}(n)$。选择时的路线利用值为：

$$
Q(n)=\frac{V_{prior}(n)+C_{sum}(n)}{1+C_{count}(n)}.
$$

其中先验相当于一个伪样本。新路线首先由自身历史估值；后续真实扩展结果逐步替代先验。
一次幸运结果只贡献一个样本，连续低回报或失败会继续降低均值，因而不会永久代表整个
祖先子树。该信用表示“沿这条路线继续搜索实际产生结果的经验”，不声称某个算法思想与
远期后代之间已经建立严格因果关系。

### 7.6 已有子节点的概率 UCB 选择

宽度达到要求后，在父节点 $n$ 的已有子节点 $c$ 中计算：

$$
A(c\mid n)=Q(c)+0.25\sqrt{\frac{\log(1+N(n))}{N(c)}}.
$$

探索强度不随剩余预算额外衰减。随后以温度 $0.2$ 对同层所有 $A$ 做 softmax，并使用
本次运行的 seeded RNG 抽样。高价值路线获得更多预算，其他路线仍保留非零机会；这避免
确定性 argmax 因很小的早期差异锁死单一路线。

### 7.7 递归选择与结果更新

每轮从虚拟根开始：

1. 若当前节点直接子代数低于 $\max(1,\lfloor N(n)^{0.5}\rfloor)$，立即在当前节点扩展；
2. 达到宽度后，按第 7.6 节从已有子节点抽样并继续下降；
3. 叶节点直接子代数为零，因此必然扩展；
4. 记录本轮真实选择路径，并增加路径访问次数和父节点扩展尝试数；
5. 成功时创建一个单父子节点，冻结直接回报并按第 7.5 节回传；失败时不建节点，以
   零回报更新同一路径。

虚拟根触发拓宽时仍使用 `e1` 创建独立根方案；该动作没有既有程序路线，因此不回传程序
节点信用。V8.3 不设固定 `max_depth`。搜索深度由访问、宽化和实际预算自然形成，生成上下文
仍只展示有限的最近来时路，不会随树深线性增长。

每个实际选择步在运行记录中保存轨迹先验、经验均值及样本数、利用值、探索值、最终分数
和抽样概率。global best 仍只由原始 fitness 决定，不受搜索分数影响。

### 7.8 默认配置与解释边界

| 参数 | V8.3 默认值 | 作用 |
| --- | ---: | --- |
| 端点 / 路径历史最好 | 0.7 / 0.3 | 轨迹历史质量 |
| 历史质量 / 近期趋势 | 0.8 / 0.2 | 轨迹先验 |
| 趋势折扣 / 窗口 | 0.8 / 8 | 最近形成边的趋势 |
| 子节点质量 / 直接增益 | 0.75 / 0.25 | 单次扩展回报 |
| 先验伪样本权重 | 1 | 无经验时的初值 |
| UCB 探索系数 | 0.25 | 同层低访问路线探索 |
| softmax 温度 | 0.2 | 同层概率选择集中度 |
| progressive-widening 指数 | 0.5 | 直接子代宽度增长 |

这些权重来自 V5 的尺度经验、V8/V8.2 的树搜索事实和 MCTS-AHD 的宽化结构，但它们在
V8.3 中形成的是新的完整闭环，尚不是由消融证明的最优参数。正式实验首先检验该闭环能否
稳定地产生多路线访问、避免 sibling 爆炸并改善搜索结果；若仍然失败，再一次只调整一个
职责明确的参数组。

## 8. 局部探索脉络与轨迹驱动的改进算子

### 8.1 提示词中的轨迹单元

完整搜索历史是一棵树。某个节点 $n$ 被选中扩展时，提示词只提取：

```text
最近的来时路 -> 当前节点 -> 代表性的已尝试分支
```

这个围绕当前节点的小型局部结构称为「局部探索脉络」。它将「当前算法如何形成」和
「从当前算法出发已经做过什么」组织成一段连续上下文。它只需帮助 LLM 判断：

1. 当前算法是怎样形成的；
2. 最近引入了哪些思想，产生了什么结果；
3. 从当前算法出发已经尝试了哪些方向；
4. 下一步应当延续、修正还是换一个方向。

### 8.2 局部脉络的提取

当前节点始终完整展示 `code`、`description` 和原始 `fitness`，并明确任务的优化方向。
当前代码是下一次生成的直接基础，父代和子代代码不再重复展示。

「最近的来时路」默认取轨迹 $\tau(n)$ 末尾最近的 3 条边。若实际深度小于 3，
则展示全部形成步骤。每步只展示子节点的 `design_idea`、`description`、父子原始
fitness 及系统根据优化方向计算的「改进 / 持平 / 退步」结果。

「代表性的已尝试分支」只从当前节点的评价有效直接子节点中选择，默认最多展示 3 个：

1. 当前子树最好有向 fitness $G(c)$ 最高的子分支，展示当前实际到达过最好结果的方向；
2. 最近创建的直接未改进子节点，展示最近暴露的无效或待修正方向；
3. 最近创建的其余直接子节点，补充当前节点最新的探索状态。

同一子节点同时满足多个条件时只展示一次，后续槽位用下一个符合条件且尚未选中的子节点
补足。第 1 项完全同分时选更晚创建的子节点。第 2 项的「未改进」指 $y(c)\le y(n)$。
当前节点没有有效直接子节点时，省略已尝试分支部分。
生成、解析和评估失败继续保留在最小运行记录中；V8.3 的简约上下文基线不展示这些系统或
无效候选失败。

每个形成步骤和已尝试分支都使用同一个最小表达：

```text
思想：<design_idea>
形成的算法：<description>
结果：<parent fitness> -> <child fitness>，<改进 / 持平 / 退步>
```

对已尝试分支，若 $G(c)>y(c)$，说明该直接子节点的后代实际到达了更好结果，再增加一行：

```text
后续发展：该分支后续最好 fitness 为 <subtree-best fitness>。
```

这一行表示某次直接修改可能暂时退步，但它开辟的方向后来实际发展出了更好算法。它只陈述树中
已经发生的搜索事实，不把后代改进解释为该直接修改的因果证明。

### 8.3 上下文顺序与生成任务

所有算子先共享同一份单节点基础上下文：

1. 任务描述和目标函数契约；
2. 当前节点的完整 `code`、`description` 和原始 `fitness`；
3. 一段局部探索脉络，内含最近形成步骤和代表性已尝试分支；
4. 当前算子的主要改进意图；
5. 通用生成要求和输出协议。

通用生成任务要求 LLM 根据当前算法和局部探索脉络，从当前算子指定的
主要视角提出一个下一步修改，判断应当延续有效思想、修正已暴露的问题还是
避开已尝试且效果不佳的方向，然后输出一条简洁、可执行的
`design_idea` 和与之一致的完整代码。

父代和子代的完整代码、访问次数、扩展次数、UCT 项、轨迹先验、路线信用、
节点排名和 global best 不进入该基础上下文。这些量服务于搜索调度，不是 LLM 完成下一次
算法修改所必需的设计信息。

当上下文超限时，任务契约和当前节点的完整 `code`、`description`、`fitness` 必须保留。随后依次
删除更旧的形成步骤和优先级最低的已尝试分支；只要容量允许，至少保留最近一个形成步骤和
第 1 顺位的最好已尝试分支。对 `trace_crossover`，第 8.6 节的参考算法也属于
必需上下文。删除全部可选脉络后仍无法容纳必需上下文时，不发送超限请求，
本次扩展按零回报失败尝试记账。

最近 3 步和最多 3 个代表子分支是 V8.3 的简约基线，尚未由实验证明为最优上下文。后续应在
固定当前节点、LLM 和评价预算时，与「只给当前算法」以及「展示全部可用历史」进行对照。

### 8.4 算子的定位与边界

算子表示本次生成的「主要改进意图」，它向 LLM 提供不同的思考入口，使搜索能够在
局部发展、细节校准、简化、换新方向和思想组合之间产生不同的候选分布。它不是对
代码修改类型的硬性检查器。

一次生成可以包含配套修改。例如，`trace_tune` 在校准阈值时可以增加状态统计或
归一化机制，`trace_simplify` 可以用更简单的机制替换原有复杂结构，`trace_innovate`
也可以保留当前算法中已经有效的部分。边上记录的算子表示生成前选定的主导意图，
不要求对候选的所有实际改动做互斥的事后归类。

五个算子以各自回答的主要问题区分：

| 算子 | 主要问题 | 额外参考 |
| --- | --- | --- |
| `trace_refine` | 当前机制的哪个薄弱点或未完成方向值得继续发展？ | 无 |
| `trace_tune` | 哪些参数、阈值、尺度、触发条件或控制细节正在限制当前机制？ | 无 |
| `trace_simplify` | 哪些部分可以删除、合并或用更简单的方式表达？ | 无 |
| `trace_innovate` | 什么明显不同的核心思路值得从当前节点开出新路线？ | 无 |
| `trace_crossover` | 另一个算法节点中的哪项互补思想值得选择性地融入当前算法？ | 一个参考算法节点 |

这五类意图在实际修改上允许重叠，但它们对 LLM 提出的首要决策问题不同。它们是
轨迹信息之上的五种决策视角，不是五条相互独立的轨迹。

### 8.5 通用提示词协议

五个算子共享同一个 Call 1 提示词骨架：

```text
[Task]
<任务描述、目标函数契约、优化方向和程序接口>

[Current Algorithm]
Fitness: <current fitness>
Description: <current description>
Code:
<current complete code>

[Local Exploration Context]
<最近的来时路和代表性已尝试分支>

[Operator]
<operator name and operator-specific instruction>

[Reference Algorithm]  # 仅 trace_crossover
Fitness: <reference fitness>
Description: <reference description>
Code:
<reference complete code>

[Generation Requirements]
<通用生成要求与输出协议>
```

通用生成要求是：

1. 以当前算法为直接修改基础，从当前算子的主要视角做出一次有算法意义的改动；
2. 利用局部探索脉络识别已经有效的思想和已经尝试的方向，避免无理由地重复已知尝试；
3. 允许为实现主要意图做必要的参数、条件、数据流或局部结构调整；
4. 输出一个候选，保持任务接口，给出完整可执行代码，不留省略或占位符；
5. `design_idea` 简洁说明这次的主要改动，并与实际代码保持一致；
6. 严格使用第 3.2 节的 `Design Idea + Code` 文本输出格式。

这些是所有算子共享的执行协议。「主要视角」用来引导决策，系统不通过静态规则禁止
配套改动，也不因为候选同时具有另一个算子的特征而判定无效。候选是否真正实现了有意义的
改动，最终由完整代码、描述和 evaluator 结果共同呈现。

算子只作用于生成 `design_idea + code` 的 Call 1。Call 2 仍然只接收任务、已生成的
`design_idea` 和完整 `code`，然后忠实描述代码的实际行为。Call 2 不需要重复局部探索脉络、
算子指令或参考算法，避免它根据生成意图美化或改写代码事实。

### 8.6 算子特定提示词与上下文

`trace_refine` 的提示词是：

> 聚焦于继续发展或修复当前机制。根据来时路中已经形成的有效思路、当前算法的薄弱点以及
> 已尝试分支暴露的问题，选择一个最值得继续开发的方向，提出聚焦且完整的下一步改进。

`trace_tune` 的提示词是：

> 聚焦于校准当前机制的参数、阈值、尺度、触发条件或控制细节。判断哪些细节限制了当前算法，
> 并为校准它们做出必要的配套修改；配套修改可以包含状态统计、归一化、自适应控制或局部结构调整。

`trace_simplify` 的提示词是：

> 聚焦于降低当前算法不必要的机制和实现复杂度。判断哪些部分可以删除、合并、重组，
> 或用更简单的机制取代，同时保留当前算法的关键功能。简化应当减少真实概念或代码复杂度，
> 不是只改名、压缩排版或隐藏相同逻辑。

`trace_innovate` 的提示词是：

> 聚焦于从当前节点探索一个明显不同的核心思路。利用局部探索脉络识别已经停滞或反复失败的方向，
> 提出具有实质机制差异的新路线。可以保留当前算法中仍然有价值的组件，
> 但不应将普通的局部调整当作换新方向。

`trace_crossover` 的提示词是：

> 以当前算法为主体，从参考算法中识别一项与当前机制互补的思想，将它选择性地适配并融入当前代码。
> 判断两者的功能关系和冲突，完成必要的配套调整。不要机械拼接两份完整代码，
> 也不要无选择地复制整个参考算法。

前四个算子只使用第 8.3 节的当前节点基础上下文。`trace_crossover` 在同一份
基础上下文中再加入一个参考算法节点的完整 `code`、`description` 和原始 `fitness`。
只提供这一个参考节点，不提供它的父代轨迹、子代分支或其他参考节点。

参考节点只是生成信息和边的追溯信息，不是结构父节点。新候选仍然只连到当前节点，
因此整棵搜索树继续保持单父代结构。算子调度和参考节点选择按第 8.7 节执行。

### 8.7 算子调度与参考节点选择

MCTS 先按第 7 节选定本轮待扩展节点，再独立选择生成算子。V8.3 不为算子
维护 UCB、历史奖励或基于轨迹状态的手工调度规则。在当前可用算子集合
$\mathcal O_{\mathrm{valid}}$ 中，每个算子等概率被选中：

$$
P(o)=\frac{1}{|\mathcal O_{\mathrm{valid}}|}.
$$

当至少存在一个合法参考节点时，五个算子均可用，各以 $1/5$ 概率被选中。
没有合法参考节点时，`trace_crossover` 从可用集合中移除，其余四个算子各以
$1/4$ 概率被选中。算子的历史结果可用于事后分析，但不反过来改变 V8.3 的算子概率。

对待扩展节点 $n$，参考候选集 $\mathcal C(n)$ 由当前全树中满足以下条件的节点组成：

1. 该节点是评价有效的算法节点；
2. 该节点不是 $n$ 自身。

候选集不按初始根、分支、亲缘关系、树距离或历史引用次数再做过滤或分组。
因此祖先、后代、兄弟分支和其他初始根下的节点都可成为参考。

只有当 `trace_crossover` 被选中后，系统才从 $\mathcal C(n)$ 中抽取一个参考节点。
先将优化方向按第 7.2 节统一为越大越好的有向 fitness $y(i)$。设候选数为 $K$，
候选集的均值和总体标准差分别为：

$$
\mu_{\mathcal C}=\frac{1}{K}\sum_{i\in\mathcal C(n)}y(i),
\qquad
\sigma_{\mathcal C}=\sqrt{\frac{1}{K}\sum_{i\in\mathcal C(n)}(y(i)-\mu_{\mathcal C})^2}.
$$

然后定义：

$$
\hat y(i)=\frac{y(i)-\mu_{\mathcal C}}{\sigma_{\mathcal C}+\epsilon},
$$

$$
P(i\mid n,\operatorname{trace\_crossover})=
\frac{\exp(\hat y(i)/\tau_{\mathrm{ref}})}
{\sum_{j\in\mathcal C(n)}\exp(\hat y(j)/\tau_{\mathrm{ref}})}.
$$

V8.3 默认 $\tau_{\mathrm{ref}}=1.0$、$\epsilon=10^{-12}$。$\epsilon$ 只用于避免数值除零。实现 softmax 时先减去
最大 logit，以避免指数溢出。当 $K=1$ 时唯一候选概率为 $1$；当候选有向 fitness
全部相同时退化为均匀抽样。该分布使较高 fitness 节点获得更大参考概率，
同时保留其他有效节点被抽中的非零机会。这是 V8.3 的简约基线，尚未实验证明优于
均匀参考、只选 global best 或基于分支多样性的选择。

## 9. 单次搜索扩展

```text
select node
record the selection-path visit and one expansion attempt
build the valid operator set and sample one operator uniformly
if operator is trace_crossover:
    build the all-tree valid reference set
    select exactly one reference by standardized-fitness softmax
build local exploration context
build shared prompt and append operator-specific context

if mandatory context cannot fit:
    record failed attempt with zero reward
    do not call LLM, evaluate, or add tree state
    continue with the next search iteration

Call 1 with retry:
    parse design_idea and code
Call 2 with retry:
    parse description

if generation or parsing fails:
    record generation_failed
    do not evaluate and do not add tree state
    continue with the next search iteration

evaluate code
record evaluator count and evaluation_time

if evaluation fails:
    record eval_failed
    do not add tree state
else:
    create one AlgorithmRecord
    create one TreeNode
    create one TreeEdge
    update ancestor subtree values and global best
```

一次扩展最多增加一个有效子节点。失败尝试仍增加选择路径访问和
`expansion_attempts`；evaluator 已启动时还增加评估计数。失败事实写入最小运行记录，不增加
`child_ids`。

## 10. 预算、停止与最小记录

### 10.1 预算

- evaluator 总预算包含初始化和搜索；
- LLM 请求失败和解析失败不消耗 evaluator 预算；
- evaluator 已启动即消耗一次 evaluator 预算。

### 10.2 停止条件

初始化或搜索在以下任一条件满足时停止：

- evaluator 预算耗尽；
- 连续 20 次尝试都没有产生新的评价有效算法。

上下文无法容纳、LLM 请求或解析失败、评估失败都计为一次未产生有效算法的尝试；
任意有效算法产生后，连续失败计数清零。停止时保留已经建立的有效树，
不把失败候选转换为节点。

### 10.3 最小运行记录

树保存算法、拓扑和 MCTS 状态。每次扩展另外记录足以还原本次科研过程的最小信息：

- 待扩展节点和完整选择路径；
- 实际算子和参考节点；
- 实际局部探索脉络和 Call 1 prompt；
- 两次 LLM 调用结果；
- 评估结果或失败原因；
- 入树结果和 global-best fitness 刷新事件。

更详细的日志、缓存、容错恢复和 evaluator 内部并行实现不属于 V8.3 的核心科研机制。

## 11. 实现不变量

实现必须满足：

1. 有效算法个体恰好包含 `design_idea`、`code`、`description`、`fitness` 和
   `evaluation_time`；
2. 每个算法生成流程包含两次成功的 LLM 调用；
3. LLM 或解析失败不进入 evaluator，evaluator 启动后无论成功失败都计一次评估；
4. 只有评估成功并返回有限 fitness 的候选才能成为树节点，且不做代码去重；
5. 初始化必须得到 10 个评价有效算法后才进入搜索；
6. 候选级扩展串行执行，每次搜索扩展最多生成一个候选；
7. 一个节点可以被多次扩展并拥有多个子节点，每个有效非根节点只有一个结构父节点；
8. progressive-widening 触发即增加选择路径访问和 $A(n)$，上下文、生成、解析或评估失败均作为零回报；
9. 任意节点都满足 $|\operatorname{Children}(n)|\le A(n)$，每个有效子节点恰好对应一次成功扩展；
10. 虚拟根同样参与 progressive widening；其扩展使用 `e1`，不使用五算子搜索抽样；
11. global best 只由任务优化方向下的原始 fitness 决定，不使用轨迹评分；
12. 局部探索脉络最多展示最近 3 个形成步骤和 3 个代表性直接子分支，只展示当前节点的完整代码；
13. 代表性已尝试分支只来自评价有效的直接子节点；
14. 搜索评分、访问统计、节点排名和 global best 不进入单节点基础上下文；
15. 搜索阶段只使用 `trace_refine`、`trace_tune`、`trace_simplify`、
    `trace_innovate` 和 `trace_crossover` 五个算子；
16. 算子表示生成前的主导意图，候选不因包含其他类型的配套改动而失效；
17. 前四个算子不使用额外参考；`trace_crossover` 恰好使用一个参考节点，但新节点仍只以当前节点为结构父节点；
18. 可用算子在每次扩展中等概率抽样，没有其他有效节点时 `trace_crossover` 不可用；
19. 参考候选是除当前节点外的全树有效节点，不按出身、关系或历史使用情况进一步过滤；
20. `trace_crossover` 在候选集中按标准化有向 fitness softmax 抽取一个参考节点，
    默认 $\tau_{\mathrm{ref}}=1.0$，全部同分时退化为均匀抽样；
21. 成功新节点以 $N=1$ 入树并以自身有向 fitness 初始化 $G$，祖先 $G$ 按自身与所有子代的最好值执行 max-backup；该后代回传只用于已有子代的 `descend` 价值；
22. 每次成功扩展在边创建时冻结直接子节点的 $F(c)$ 和父节点 $F(n)$，`new_child` 回报只使用这两个快照和 $[F(c)-F(n)]_+$，后续后代或全局秩变化都不 retroactively 改写该回报；
23. 失败尝试不改变 $G$，但保留已增加的访问和 $A$，并以零回报保留在扩展信用记录中；
24. 当 $|\operatorname{Children}(n)|<\max(1,\lfloor N(n)^\alpha\rfloor)$ 时无条件触发该节点扩展，达到宽度后才允许 `descend`；
25. 连续 20 次尝试未产生有效算法时停止，产生任意有效算法后该计数清零。

## 12. 最小实现边界

V8.3 的实现按职责分为五个部分，不要求引入更大的框架：

### 12.1 `AlgorithmRecord`

只保存算法个体的五个协议字段。它不保存树父子关系、访问统计或失败状态。

### 12.2 `SearchTree`

负责虚拟根、节点、边和树操作：

```text
add_initial(algorithm)
add_child(parent_id, algorithm, operator, reference_node_id)
children(node_id)
ancestors(node_id)
subtree_value(node_id)
record_outcome(path, reward)
```

`SearchTree` 是结构与路线信用的唯一来源。轨迹从父子关系重建，路线信用保存在节点；
边上的 `parent_quality` 与 `child_quality` 是创建时冻结的直接回报快照，属于边事实而
不是当前全树秩的动态缓存。

### 12.3 `Selector`

读取 `SearchTree` 和评分参数，按第 7 节重建全部派生价值，返回一个
待扩展节点和完整选择步骤。节点确定后，调用方按第 8.7 节等概率选择一个可用算子；
若选中 `trace_crossover`，则再按标准化有向 fitness softmax 选择一个参考节点。
`Selector` 不调用 LLM，也不执行 evaluator。

### 12.4 `Generator` 与 `Evaluator`

`Generator` 负责按第 8 节提取局部探索脉络，拼接通用协议、算子提示词和可选参考算法，
执行两次 LLM 调用、重试和解析，返回完整的
`design_idea + code + description`。`Evaluator` 只执行 `code`，返回：

```text
EvaluationResult = {
    status: ok | failed,
    fitness: finite number | None,
    evaluation_time: seconds,
}
```

上下文、生成、解析和评估失败都由调用方统一按第 4.3 节处理，不创建节点或边。

### 12.5 `RunRecord`

`RunRecord` 按第 10.3 节保存每次扩展的最小科研过程信息，用于解释节点为何被选中、
模型实际看到了什么以及候选如何评估。

单次搜索循环负责连接这些组件：选择、生成、评估、有效入树或失败记录、状态更新。

## 13. 最小验证集

实现后至少验证：

- 初始化失败重试不会增加有效个体数量；
- 只有得到 10 个有效根节点后才进入搜索；
- 初始化中 `e1` 参考只提供设计信息，不强制新算法与参考之间的固定关系；
- 候选级扩展串行执行，上一次尝试记账后才开始下一轮选择；
- 同一节点多次扩展会产生多个独立子节点；
- 单次扩展永远不会创建两个 sibling；
- 上下文、生成、解析或评估失败都保留选择路径访问和 $A$，但不增加节点或边；
- 轨迹能够由父子关系和节点记录完整重建；
- 深度大于 3 的节点只展示最近 3 个形成步骤，较浅节点展示全部来时路；
- 人工构造多个直接子节点时，代表分支按「子树最好、最近未改进、最近其余」确定选出且不重复；
- 直接子节点本身退步但后代刷新分支最好时，上下文同时展示直接结果与后续最好结果；
- 局部脉络中只有当前节点完整代码，且不包含 UCT、访问计数、节点排名或 global best；
- 生成、解析和评估失败保留在运行记录中，不进入简约局部探索脉络；
- 五个算子共享相同的任务、当前节点、局部脉络和输出协议，只替换算子特定提示；
- `trace_tune` 生成包含必要结构调整的候选时，不会因超出「只改参数」而被判定失效；
- 前四个算子的提示词不包含参考算法区块；
- `trace_crossover` 的提示词恰好包含一个参考节点的完整代码、描述和 fitness，
  且不包含该节点的来时路或子代分支；
- `trace_crossover` 候选入树后只有当前节点一个结构父节点，参考关系只是边的追溯信息；
- 存在合法参考时五个算子的抽样概率均为 $1/5$，不存在时其余四个算子均为 $1/4$；
- 参考候选集包含来自不同初始根、同根其他分支、祖先和后代的有效节点，但不包含当前节点；
- 人工构造有不同 fitness 的参考候选时，较高有向 fitness 对应更高 softmax 概率且总和为 $1$；
- 参考候选只有一个时必然选中该节点，全部同分时抽样概率均匀；
- 上下文裁剪优先删除可选的轨迹单元，不删除当前算法；`trace_crossover` 中也不删除参考算法；
- 最小化任务、并列 fitness 和全树同分时的中秩 $F$ 均符合定义；
- 轨迹先验、经验均值、UCB、抽样概率、单次扩展回报和 global-best fitness 可从记录重建；
- endpoint 和路径历史最好相同时，近期持续改善路线的先验高于持续退步路线；
- 成功子节点的后代变好不会改写产生该子节点时已经冻结的直接扩展回报；
- 一次失败扩展增加父节点扩展尝试和相应访问，并向实际选择路径回传零回报；
- 一次高回报后连续零回报会单调降低路线利用值；
- 失败扩展不创建节点或边；成功新叶节点满足 $N(c)=1$；
- 连续 20 次尝试未产生有效算法时停止，一次有效生成会清零该计数；
- 根节点宽度不足时产生 `e1` 根扩展，叶节点第一次到达时必然扩展；
- 人工构造超过 10 层的小树时，选择仍可到达深层叶节点，不存在深度边界绕过宽化；
- 人工构造的小树上，宽度不足会触发横向扩展，宽度满足后概率 UCB 会继续下降；
- 同层高价值节点的抽样概率更高但小于 1，较弱节点仍能在重复抽样中被选中。

V8.3 在完成这些实现验证和重复实验前，只代表确定的机制设计，不代表已经获得性能
收益。
