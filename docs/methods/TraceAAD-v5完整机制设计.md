## 0. 设计总览

V5 不是重建 TraceAAD 的搜索框架，而是在 V4 已经能够稳定运行的轨迹种群骨架上完成四项实质修正：

| 核心变化 | V4 问题 | V5 处理 |
| --- | --- | --- |
| 轨迹评分与父代调度 | 手工局部趋势 \(P\) 会把退步后的部分回弹误当成路线潜力 | 移除 \(P\)，用成果质量 \(Q\) 与 UCB 分别承担利用和访问公平 |
| 全局经验 | 严格祖先轨迹缺少对整个搜索的高层认识 | 定期把近期已评价修改与结果压缩成简短全局反思 |
| 双轨迹知识算子 | `ideate/refine` 只能沿当前路线思考 | 增加 `synthesize/transfer`，直接组合或迁移另一条轨迹中的具体思想 |
| 程序膨胀控制 | 完整程序反复继承，缺少无收益复杂度的淘汰压力 | refine 允许做减法，引入 compact best，并在 fitness 完全同分时择短 |

这四项变化仍围绕同一个核心：利用算法改进历史指导下一步搜索。全局经验提供低分辨率的任务地图，双轨迹算子提供高分辨率的跨路线借鉴，主轨迹继续提供当前程序的来时路。

V5 继续继承 V4 的主体骨架：

- 单父代程序森林与严格祖先轨迹；
- 固定目标种群、扩张到 \(2M\) 后收缩回 \(M\)；
- 质量精英、global-best route、差异 reserve 与 softmax survivor；
- endpoint / 历史最好类锚点选择、UCB 访问公平和完整评估写回；
- 有效候选进入搜索树，失败候选按既有预算规则处理。

自然语言 action、系统自动 provenance、参考轨迹选择、prompt 接入、状态字段、日志和 checkpoint 是四项核心变化的支撑机制。它们保证设计能够被实现、恢复和实验分析，不构成彼此独立的方法贡献。

第一版不引入学习式轨迹价值模型、自适应算子调度、独立 archive 检索、语义 novelty 模型、长度惩罚或复杂度多目标优化。它们是现有机制被实验否定后才考虑的后续方向。

V5 的架构层仍保持这四项最小变化。首轮实验已经把工作分成两个层次：先修正第 6 节的全局经验输入接口，使完整机制真实运行；再通过重复实验检验 \(Q+\mathrm{UCB}\)、全局经验、双轨迹算子和最小简约机制的实际贡献。上下文修正不需要增加新的学习模型、检索器或 memory bank。

## 1. 科学出发点

算法改进是逐步引入算法思想、持续试错和不断修正的过程。当前程序只是这一过程的一个截面；算法怎样走到这里、哪些思想取得了什么结果、哪些坑已经踩过、后续可以怎样延续或换向，同样属于下一步决策需要的知识。

一条轨迹因此不是单调上升的优秀程序序列，而是一段有序的算法实验史。成功、停滞、退步和波动都可以进入轨迹。它们的价值不由一步涨跌直接裁定，而取决于它们是否帮助搜索理解当前算法、避免重复试错或形成后续改进。

TraceAAD 的核心主张是：

> 把算法改进历史组织成可搜索、可评价、可继续发展的轨迹，并把其中积累的经验用于指导下一步算法生成。

v5 延续 v4 的单父代轨迹搜索，集中修正四个问题：

1. 严格祖先轨迹缺少跨路线的全局视野；
2. 手工局部趋势 \(P\) 不能可靠代表轨迹的继续开发价值；
3. 完整父程序的持续继承缺少简约压力，导致程序膨胀；
4. 两个单轨迹算子只能沿当前路线思考，不能直接迁移或组合另一条路线中已经形成的具体算法思想。

完整方法在公平协议下的训练质量、held-out 泛化、重复稳定性、anytime search 和同类方法比较构成主要结果证据。过程统计和组件消融用于解释机制为什么工作、哪里仍需修正。

## 2. 搜索对象与三类轨迹价值

### 2.1 搜索状态

给定任务与函数契约 \(x\)，v5 的一次决策状态为：

$$
s_t=(x,p_t,\tau_t,\eta_t,\rho_t,G_k,b_t),
$$

其中：

- \(p_t\) 是本次生成所依赖的锚点程序；
- \(\tau_t\) 是从初始程序到 \(p_t\) 的完整严格祖先轨迹；
- \(\eta_t\) 是选择内部锚点时，原路线在锚点之后已经测试的非祖先尝试；
- \(\rho_t\) 是双轨迹算子使用的参考轨迹，单轨迹算子下为空；
- \(G_k\) 是从多条轨迹中凝练出的全局经验；
- \(b_t\) 是预算与搜索阶段信息。

LLM 先生成语义 action，再生成完整候选程序，真实评价形成父子转移。每个新程序只有一个锚点父程序，因此全部程序节点与修改边构成森林。

轨迹保持严格定义：它是从某个起始程序到当前程序的单一祖先路径。锚点之后的旧尝试属于决策证据 \(\eta_t\)，不会成为新子程序的祖先。其它分叉也不混入结构 ancestry；其中的具体思想可以通过参考轨迹直接迁移或组合，跨路线共性则由全局经验承担。

### 2.2 轨迹应保存什么

每个程序节点保存可执行程序、模型生成的算法说明、任务 fitness、复杂度、规范化代码哈希和运行状态。每条修改边保存：

- 决策前的父程序与祖先状态；
- action 的自包含修改意图；
- 系统确定的算子、主轨迹、锚点、可选参考轨迹与参考程序 provenance；
- 子程序代码、模型生成的实现说明及机械代码变化统计；
- 子程序相对父节点、路线历史最好和全局最好的结果；
- 本轮向模型提供的主轨迹、参考轨迹、全局经验和非祖先失败边界；
- 后续对该思想的延续、修复、回退、换向或整合关系。

程序代码、fitness、LOC、父子关系和代码差异是直接观察；action、`Idea` 和“实现了什么机制”是模型生成的说明。“为什么有效”“某项修改是否造成结果”“早期动作是否带来延迟收益”属于基于多步证据的解释。第一版不增加额外 LLM judge 自动裁定 action 与代码的语义一致性，而是在分层抽样的过程审计中检查。日志和全局经验必须保留这些边界。

### 2.3 三类价值及其职责

v5 区分三类不能互相替代的轨迹价值：

1. **成果价值**：这条轨迹是否已经产生优秀算法。它服务于结果输出、高质量锚点和质量精英，主要由真实 fitness 衡量。
2. **继续开发价值**：从当前路线继续投入预算，未来产生优秀后代的可能性。它服务于父代调度和搜索资源分配，目前只能用成果质量与访问不确定性的组合做代理。
3. **知识价值**：轨迹中的成功、失败、条件和思想关系能否改善后续 action。它通过主轨迹、直接参考轨迹与全局经验发挥作用，目前不构造主观的 LLM 知识分数。

继续开发价值不是成果价值与全部知识价值的加权和。一条路线可以停止繁衍，其失败边界仍能进入全局经验；一条高质量路线也可能已经缺少新的发展空间。v5 不把三类价值压成统一的“轨迹总分”。

## 3. v4 中保持不变的搜索骨架

除本文明确修改的部分外，v5 继承 v4：

- 单父代程序树与多初始节点森林；
- active frontier 目标规模 \(M=30\)；
- active 数达到 \(2M\) 后统一收缩回 \(M\)；
- 每轮为所选算子生成 2 个 action；
- 质量精英、global-best route、差异 reserve 与 softmax survivor；
- 代码 token、思想词项和 `(operator, outcome)` 指纹组成的轻量路线差异；
- 所有评价有效的普通候选都写入树并进入 active 扩张池；
- 评估失败消耗预算但不进入树，解析失败不消耗评估预算；
- checkpoint、恢复和过程日志骨架。

树是事实拓扑，active frontier 是有限的搜索资源。路线退出 active frontier 后仍保留在树和日志中，不再直接繁衍；已经形成的可迁移知识可继续存在于全局经验中。v5 不恢复独立的原始 archive 检索、双父代写回或机械式代码拼接。双轨迹算子只把第二条轨迹作为生成上下文，子程序仍只写回主轨迹。

### 3.1 完整路径与有限上下文窗口

V4 的轨迹对象直接截断到最近 8 个节点。该实现不能支撑 V5：`compact_best_id` 可能落在窗口外，旧锚点也无法继续分叉。V5 因此把“轨迹状态”和“prompt 窗口”分开：

- 树和轨迹状态保存完整祖先路径；
- `compact_best_id`、路线最好和分叉操作都基于完整路径；
- \(L=8\) 只限制每条轨迹在 prompt 中显示的边记录，不删除搜索状态。

选择 endpoint 时，显示最近 \(L\) 条形成边。选择内部锚点时，在“锚点形成历史”和“锚点后已测试尝试”之间各预留一半位置；任一侧不足时，空位补给另一侧。两个区块分别标记，不能把锚点后的机制当成锚点代码已经包含的机制。参考轨迹采用同一窗口规则。完整有界历史只进入 action 阶段；代码阶段执行已经形成的自包含 action，不再次读取轨迹。

### 3.2 上下文预算

\(L=8\) 是边记录上限，不保证任意长程序都能放入模型上下文。双轨迹算子的 action prompt 同时包含主程序、参考程序和两条历史，程序膨胀会进一步放大这一约束。prompt builder 因此必须在调用前计算 token；OpenAI-compatible 适配器优先调用模型服务自身的 tokenizer，服务未提供该接口或其它 LLM 没有计数能力时使用 UTF-8 字节数保守回退，并记录实际计数模式。随后按固定优先级处理：

1. action 阶段的任务契约、主锚点程序、算子要求的参考程序和全局经验，以及代码阶段的主程序与已确定 action，都是不可静默删除的机制输入；
2. 非初始主锚点至少保留一条形成边；内部锚点在存在后续尝试时至少再保留一条 tested-after 边；非初始参考程序至少保留一条形成边；
3. 超出输入预算时，只从超过上述最小骨架的历史记录中删除最旧边，并保持 formation / tested-after 区块标记；
4. 若“必要机制输入 + 最小历史骨架”已超过“模型上下文减去输出预留”，该主/参考组合不可执行。参考候选在算子选择前据此过滤；单轨迹核心仍超限时，本次记为 `context_overflow`，不调用评估器，但仍计一次主轨迹访问。

初始程序没有形成边，因此不强造历史。该限制是模型接口的可执行边界，不是 anti-bloat 的质量规则。不能静默截断程序、action 或任务契约，也不能把 context overflow 当成候选 fitness。日志记录各区块 token、删去的 edge id、因超限排除的参考候选和最终输入长度，使双轨迹收益能够与上下文代价共同分析。

## 4. 轨迹评分与父代调度

### 4.1 移除手工局部趋势 \(P\)

v4 的局部趋势 \(P\) 是相邻父子边结果符号的折扣平均。过程审计发现，相邻正边经常只是从退步端点部分回弹。\(P\) 可以描述路线近期形状，却不能代表知识价值，也没有足够证据稳定预测继续开发价值。

v5 将 \(P\) 移出父代调度与种群生存，只保留为分析字段。日志继续记录：

- `delta_parent`；
- `delta_route_best`；
- `delta_global_best`；
- improve / plateau / regress；
- 多步 continuation return。

这些数据用于后续研究真正的轨迹价值模型，不在 v5 第一版中形成新的手工总分。

### 4.2 质量代理 \(Q\)

在继续开发价值尚无直接标签时，v5 使用成果质量作为保守代理：

$$
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i}.
$$

两项均在当前 active 候选集合中按任务方向统一后的 fitness 排序计算百分位。排序采用“质量优先、完全同分时更短优先”的词典序：

$$
p_i \succ p_j
\iff
\widetilde F(p_i)>\widetilde F(p_j)
\ \lor\
\bigl(\widetilde F(p_i)=\widetilde F(p_j)\land C(p_i)<C(p_j)\bigr),
$$

其中 \(\widetilde F\) 统一为越大越好，\(C(p)\) 是非空代码行数。不同 fitness 之间永远不由程序长度改变顺序。

百分位必须采用并列感知的排名：`(fitness, -LOC)` 完全相同的程序获得相同百分位，稳定 id 只在有限席位必须从等价项中选取代表时决定可复现顺序，不能让等价副本获得不同 \(Q\)。

### 4.3 UCB 访问公平

设当前 active 候选路线的父代访问总数为 \(N\)，轨迹 \(i\) 被选次数为 \(n_i\)：

$$
A_i=Q_i+c\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/T).
$$

第一版保持 \(c=0.25\)、\(T=0.2\)。\(Q_i\) 提供成果利用，UCB 为低访问路线保留试验机会。两者共同构成当前的继续开发代理，不被解释为轨迹真实价值。

### 4.4 统一比较器与访问语义

实现中只保留一个“质量优先、完全同分时择短”的程序比较器，并在 endpoint/best 百分位、compact best、质量精英、global best 代表程序和最终输出中复用。若 fitness 与 LOC 都相同，两个程序在机制上等价：best 更新保留原代表，排序场景只用稳定 id 打破显示顺序。这样可以避免等长副本不断伪造 global-best update，也避免父代评分已经择短、global-best 代表却仍保留旧长程序的规则冲突。global-best 代表因完全同分但更短而更新时，`delta_global_best=0`，更新原因单独记为 `tie_shorter`。

`visit_count` 表示一条主轨迹被选中并发起过多少个生成批次，而不是产生了多少个有效子程序。一次 action 解析失败或代码生成失败仍算一次访问，因为该路线已经消耗一次搜索尝试。参考轨迹只记录 `reference_use_count` 供分析，不进入 UCB。算子失败率必须按主轨迹、算子和解析阶段分别记录，避免把格式失败误解为路线缺少潜力。

## 5. 三种搜索视野

### 5.1 局部轨迹

祖先轨迹是当前算法最直接的来时路，具有最强的因果连续性。action 阶段接收：

1. 任务、函数契约与锚点完整代码；
2. 按窗口规则选出的锚点形成历史及真实结果；
3. 锚点之后已经测试的停滞或失败尝试；
4. 每步的关系、action、实际修改与结果。

代码生成阶段只接收任务、主锚点程序、自包含 action 和目标函数契约。历史已经完成“决定改什么”的职责；再次传入会让代码模型重新选题，并增加对 Action 的改写。

### 5.2 直接参考轨迹

双轨迹算子额外接收一条参考轨迹 \(\rho_t\)。它提供另一条具体算法路线的程序、思想演化和真实结果，使模型能够在一次决策中迁移一个已有思想，或让两条路线中的互补机制形成明确的功能交互。

参考轨迹不解释主程序怎样形成，也不成为新程序的第二个结构父代。主轨迹提供待修改程序及其来时路，参考轨迹只提供知识。二者的区别是：

- **结构 ancestry** 决定新节点接到哪里，只能有一条；
- **知识 provenance** 记录本次决策借鉴了哪里，可以包含参考轨迹。

双轨迹算子只在 action 阶段接收有界参考上下文。Action 必须把采用的参考原则和适配方式写完整，代码阶段据此从唯一主锚点实现，不再重复读取参考程序。

### 5.3 全局经验

全局经验 \(G_k\) 是多条真实轨迹共同支持的任务认识。它不拼接原始分叉，也不复述全部程序；它用有界文字回答：

- 哪些算法思想在什么条件下反复有效；
- 哪些做法已经真实踩坑；
- 哪些方向仍值得验证。

局部轨迹回答“当前算法怎样走到这里”，直接参考轨迹回答“另一条具体路线中有什么可以迁移或组合”，全局经验回答“整个搜索到目前学到了什么”。下一步 action 由三者共同指导：

$$
a_t\sim\pi(x,p_t,\tau_t,\eta_t,\rho_t,G_k).
$$

单轨迹算子下 \(\rho_t=\varnothing\)。直接参考是高分辨率、单次决策使用的跨路线知识；全局经验是低分辨率、缓慢更新的共享认识。两者互补，不互相替代。

全局经验不进入 \(Q\)、UCB、fitness 或候选接受规则。

### 5.4 三种知识如何汇入一条新边

三种视野最终都必须凝结到一个自包含 action 中：

1. 主锚点代码定义本次修改的真实起点；
2. 主轨迹和 \(\eta_t\) 提供来时路与已经测试的边界；
3. 双轨迹算子再提供参考程序及其有界历史；
4. 全局经验提供可被局部证据挑战的任务级先验；
5. action 用自然语言写出要实施的具体变化，以及相对相关历史尝试的关键差异；双轨迹算子还要重述采用的参考原则与适配方式；
6. 代码阶段从主锚点实现该 action，评价后只生成一条主父边。

任务契约和实际程序是硬约束，真实 fitness 与修改边是观察事实，全局经验是可修正的摘要。局部或参考轨迹中的直接证据与全局经验冲突时，action 应显式说明采用哪一项证据及原因，不能把全局经验当作不可违背的规则。

全局经验不重复进入代码 prompt，因此 action 文本必须包含实现所需的完整信息，不能只写“采用全局经验”或“参考另一条路线”。当 action 使用锚点后的失败尝试、参考轨迹或全局经验时，也必须把采用的原则自然地重述在修改建议中。系统自动记录本轮算子、主轨迹、锚点、参考轨迹与参考程序，但不要求 action LLM 填写 relation 或 evidence id。系统 provenance 证明“提供了哪些上下文”，action 只说明模型提出了什么方案；二者都不能单独证明模型实际因何作出决定。

### 5.5 实现必须保持的不变量

| 不变量 | 含义 |
| --- | --- |
| 单父代拓扑 | 每个新程序恰有一个主锚点父程序，只建立一条入边 |
| 完整状态、有界呈现 | 完整祖先路径用于评分、锚点和分叉，\(L\) 只约束 prompt |
| 非局部知识可追溯 | action 自包含重述采用的原则；系统记录提供过的主/参考/全局上下文，不要求模型填写 id |
| 价值职责分离 | \(Q+\mathrm{UCB}\) 只调度主轨迹；参考和全局知识不反向修改 fitness |
| 事实与说明分离 | 代码、评价和拓扑是事实；action、Idea 和经验规律是可审计说明 |
| 统一质量比较 | 所有质量决策复用“fitness 优先、完全同分时 LOC 更少”的比较器 |

任一实现若破坏这些不变量，即使接口和日志仍能运行，也已经改变 V5 的机制。

## 6. 全局经验机制

### 6.1 科学角色

全局经验 \(G_k\) 是搜索进行到当前阶段后形成的任务级认识。祖先轨迹回答“当前算法怎样走到这里”，参考轨迹回答“另一条具体路线有什么可以借鉴”，全局经验回答“整个搜索到目前学到了什么”。

它保持短小，可以包含三类内容：

1. 近期看起来有用的方向；
2. 容易造成失败、停滞或重复尝试的问题；
3. 下一阶段值得继续探索的方向。

全局经验不是完整实验总结，也不逐项罗列所有尝试。

### 6.2 每 40 个已评价子程序进行一次全局反思

V5.1 默认每产生 40 个经过评估并写入修改边的子程序，更新一次全局经验。初始化程序不计入；解析失败、代码生成失败和评价失败不计入。触发尺度因此直接对应反思输入中实际存在的代码修改数量，不受每轮 Action 数量影响。

40 是与原来“20 轮、每轮最多 2 个 Action”相近的默认信息量，不表示某个结论已经得到证明。后续可以直接检查 20 / 40 / 80 个代码修改的频率敏感性，不引入自适应触发器。

第 \(k\) 次反思只读取上一版全局经验 \(G_k\) 与最近 40 个已评价修改 \(H_k\)：

$$
G_{k+1}=\mathcal R(G_k,H_k).
$$

\(H_k\) 中每项只包含 Action、子程序的简短实现 Idea，以及父程序到子程序的 fitness 变化和结果分类。它不包含完整代码、哈希、轨迹或程序编号、来源分组、完整历史分叉和运行元数据。

提示只要求模型围绕三个问题形成最多 5 点的简短文本：

1. 哪些近期方向有用；
2. 哪些问题反复出现；
3. 下一阶段可以怎样修改。

模型返回的任意文本都直接去除首尾空白后覆盖旧反思。没有 JSON schema、分类字段、引用编号、独立来源要求、结果一致性检查、重复程序检查或全有全无 validator。反思调用失败或输入超出窗口时保留旧文本与待反思批次，下一次继续尝试；这只是调用恢复，不是内容合法性判断。

### 6.3 怎样指导下一步

更新后的 \(G_{k+1}\) 进入之后所有轨迹的 action 决策：

$$
a_t\sim\pi(x,p_t,\tau_t,\rho_t,G_{k+1}).
$$

它帮助模型判断当前路线是否可以借鉴近期有用思想、是否正在重演已知问题，以及停滞时可以转向哪些方向。全局经验是一份可修正的任务级提示；当前祖先轨迹和参考轨迹中的内容与它冲突时，模型可以调整下一步方案。

具体而言，下一步 action 可以用全局经验做三件事：在适用条件相符时承接跨路线有效思想；在拟议修改重演已知陷阱时调整方案；在局部轨迹长期停滞时选择尚未充分验证的换向方向。

全局经验只影响“下一步改什么”，不直接改变 fitness、轨迹评分、父代选择、种群生存或代码评价。

### 6.4 奥卡姆边界

第一版不增加 ReEvo 式短期反思器、good/bad memory bank、独立历史检索、recommendation agent、知识价值评分模型或内容 validator。机制只有一段短文本、一个固定代码批量触发器和一个使用位置。

## 7. 自然语言 Action 与语义算子

### 7.1 Action 契约

action LLM 返回两条编号、单行、可直接交给代码生成阶段的自然语言修改建议：

```text
1. <一项具体且自包含的算法修改，并说明它相对相关历史尝试的关键差异>
2. <另一项具体且自包含的算法修改，并说明它相对相关历史尝试的关键差异>
```

每条 action 聚焦一项主要修改，必须离开 action prompt 后仍可独立理解。它自然包含“改什么”和“相对已经尝试过的方向有什么新差异”，不再拆成多个字段。修改必须能够在目标函数内部、只使用函数参数和局部计算值完成，不得假设隐藏运行状态或改变函数签名。`trace_synthesize` 与 `trace_transfer` 的 action 还必须说明采用了参考路线中的什么算法原则，以及怎样在主程序中组合或适配。

action LLM 不输出 JSON、relation、evidence id、独立 rationale 或代码，也不承担搜索系统已经知道的 bookkeeping。算子、主轨迹、主锚点、`anchor_role`、参考轨迹和参考程序由搜索过程确定并自动写入 provenance。提示日志保留本轮实际提供的主历史、参考历史和全局经验，供离线审计使用。

解析器只接受从 1 开始连续编号的文本项，不把前言、解释续行、代码块或旧 JSON 字段解释为 action。提示要求返回 2 条，但只要存在可用编号项，就继续执行可用子集；全部没有可用文本时，本轮不调用评估器、不消耗评估预算，但仍记录一次主轨迹访问和 action parse failure。

自然语言 action 是生成计划，不是已执行事实。代码生成输出的 `Idea` 也只是实现说明，限定为不超过 300 字符的一句话；超长输出只在保存说明时确定性截断，不影响代码解析。轨迹历史同时显示 Planned Action、实际 child `Idea`、代码变化比例和 LOC，使后续模型能够区分“想改什么”与“实际改成什么”。第一版仍不增加在线 LLM judge。低频全局反思同样使用自然语言文本，不再要求模型填写结构化表单。

### 7.2 四个语义算子

v5 使用四个语义算子：

| 算子 | 职责 |
| --- | --- |
| `trace_ideate` | 根据局部轨迹和全局经验提出一个尚未测试的主要算法思想 |
| `trace_refine` | 对已有机制做一次有证据的深化、修复、替换、删除、合并或参数规则调整 |
| `trace_synthesize` | 从主轨迹和参考轨迹各提取一个有真实历史支持的原则，在主程序中形成明确的功能交互 |
| `trace_transfer` | 保持主程序的核心结构，只把参考轨迹中一个有证据支持的思想适配到主程序 |

`trace_refine` 明确允许做减法。它不默认在旧逻辑旁追加新分支，而应根据轨迹结果删除已经失效、被替代或没有证据支持的实现。若本次主要目标是压缩已有实现，action 直接说明要删除、合并或替换什么，以及为什么相对旧实现更简洁；不增加独立的 `trace_consolidate` 算子。

`trace_synthesize` 的两条路线在思想来源上地位对等，但最终实现仍以主锚点程序为载体。action 必须说明两项原则怎样在操作层面发生交互，不能只是把两段代码并排追加。

`trace_transfer` 是非对称的思想迁移：主轨迹决定问题状态和程序骨架，参考轨迹只提供一个供体思想。action 必须说明迁移对象、适配位置及与主程序现有机制的关系。

### 7.3 选择参考轨迹

先按 \(Q+\mathrm{UCB}\) 选择主轨迹和主锚点，再构造参考候选。参考候选来自另一条 active trajectory，并且按第 3.2 节的最小上下文骨架可以执行。存在参考候选时四个算子等概率；否则仅在 `trace_ideate` 与 `trace_refine` 中等概率选择。V5.1 不按代码是否重复过滤参考路线。

若选中双轨迹算子，在参考候选中按 \(Q\) 的 softmax 选择路线，温度沿用 \(T\)，并使用其 compact best 作为参考程序。参考选择寻找已有成果支撑的具体思想，因此只使用 \(Q\)；这里不使用 UCB，也不增加参考轨迹的父代访问次数，因为它没有获得子节点和继续开发预算。参考程序之后的尝试可以作为失败边界，但被迁移或组合的正向机制必须真实存在于参考程序中，不能只存在于后续失败代码里。

\(Q\) 仍只是成果代理，不代表参考轨迹的知识价值。第一版不再增加供体评分；日志记录参考使用次数、主/参考代码相似度和供体集中度，检验高质量参考路线是否形成垄断。

### 7.4 单父代写回

无论使用哪个算子，新程序都只评估一次，并只从主锚点建立一条父子边：

$$
\tau'=\tau_{p,\le a}\oplus(p_a\rightarrow p').
$$

参考轨迹不增加第二条父边，不复制子轨迹，也不因本次生成获得 fitness credit。其贡献以 `reference_trajectory_id`、`reference_program_id` 和本轮参考上下文记录为知识 provenance，供过程分析使用。父子结果、路线最好推进、\(Q\)、UCB 与 active 管理全部归属于主轨迹。

## 8. 最小程序膨胀控制

### 8.1 原则

v4 的实验已经观察到跨任务的程序增长，且变长子代的直接改进率没有高于变短子代。v5 的目标是切断无收益复杂度的继承优势，同时允许真正有价值的长程序存在。

核心原则是：

> 质量优先，同质择简；知识留在轨迹中，代码只保留当前需要的实现。

v5 不使用长度惩罚、多目标复杂度权重、硬 LOC 上限、近同分阈值、专门简化算子或复杂触发器。

### 8.2 单一复杂度尺度

第一版只用非空代码行数：

$$
C(p)=\operatorname{nonempty\_LOC}(p).
$$

LOC 在候选完成解析后，对规范化的目标函数源码计算：去掉代码围栏，统一换行，统计所有非空行。函数签名和必要 import 若存在也计入；由于任务契约固定，它们不会系统性偏向某个候选。代码哈希和机械差异只作为离线记录，不作为候选接受或全局反思的门槛。字符数、token、AST 节点、运行时间和圈复杂度可以作为离线诊断指标，但不进入核心机制。每个节点记录 `program_loc` 与代码哈希，每条边记录 `delta_loc` 和机械代码变化比例。

### 8.3 紧凑最好锚点

一条轨迹的历史最好质量为 \(\widetilde F_{\mathrm{best}}(\tau)\)。在完全达到该质量的节点中选择最短程序：

$$
\mathcal B(\tau)=
\{p\in\tau:\widetilde F(p)=\widetilde F_{\mathrm{best}}(\tau)\},
$$

$$
p_{\mathrm{compact}}(\tau)
=\arg\min_{p\in\mathcal B(\tau)}C(p).
$$

若长度仍相同，保留原 compact-best 代表；排序显示只使用稳定 id。`compact_best_id` 作为路线摘要独立保存，不因 prompt 的 8 节点后缀而丢失。

父代轨迹确定后，从去重的两个锚点中等概率选择：

- endpoint：保留最新思想、波动路线和暂时退步后的继续发展；
- compact best：从已经达到路线最好质量的最简实现重新出发。

compact best 取代 v4 的普通“历史最好锚点”。它不改变历史最好质量，只在多个同分实现中避免默认继承更长版本。选择 compact best 时，锚点后的已测试尝试仍作为后续历史进入 prompt。

完整祖先路径必须保留，才能保证窗口外的 `compact_best_id` 仍可分叉。新子轨迹的结构路径只包含“根到 compact best 的前缀 + 新边”；锚点后的旧尝试不成为子轨迹祖先。若 action 使用了这些失败边界，其结论通过自包含 action 文本凝结到新边中，系统 provenance 同时记录该 action 是在什么主轨迹与锚点上下文下产生的。

### 8.4 同分时更短优先

完全相同 fitness 下，以更短程序打破平局。这条规则用于：

- endpoint 与 route-best 的百分位排序；
- 质量精英；
- global best 的代表程序；
- compact best；
- 其它原本只由 fitness 决定且出现完全同分的排序。

只要 fitness 不同，质量顺序保持不变。普通候选无论变长、变短、改善或退步，只要评价有效都按正常父子边进入搜索，不设置代码重复或长度接受门槛，也不立即替换父路线。这样保留非单调试错，同时给同质的简洁实现真实的繁衍优势。

### 8.5 为什么轨迹允许代码做减法

从当前程序删除机制，不会删除它在轨迹中的 action、实现、评价和后续影响。失败思想、条件性有效思想和曾经有用但后来被替代的机制仍可被局部历史与全局经验利用。程序因此只承担当前执行，轨迹承担长期知识。

若完全同分情况过少，第一版机制可能产生很弱的简约压力。这是需要由实验判断的结果，不预先引入主观容差。只有数据证明精确同分不足以控制无收益增长后，才单独研究统计近同分或专门简化动作。

双轨迹算子同样受这一原则约束。`trace_transfer` 默认迁移一个核心思想，`trace_synthesize` 必须替换、合并或重组冲突逻辑；二者都不能把“组合”理解为无条件保留两条路线的全部实现。

## 9. 种群管理

active frontier 达到 \(2M\) 后，重新计算只含 \(Q\) 的质量代理并收缩：

1. 保留 \(E=\max(2,\lceil0.1M\rceil)\) 条质量精英；
2. 保留 \(R=\max(2,\lceil0.1M\rceil)\) 条相对“精英 + 已选 reserve”最不相似的路线；
3. 其余 \(M-E-R\) 个席位按 \(Q\) 的 softmax 无放回抽样；
4. 未入选路线退出 active frontier，但继续保存在树与日志中。

global-best route 继续获得保留。如果包含 global best 的路线未进入质量精英，则替换最弱精英。程序长度只在完全同分的质量排序中打破平局，不进入差异 reserve 或普通 softmax 权重。

全局经验与种群生存分离。路线退出 active frontier 后，其历史仍属于本阶段的搜索经验，并可参与下一次全局反思。种群管理只改变哪些路线继续繁衍，不删除已经形成的研究认识。

V5.1 不设置重复代码接受门槛或语义去重器。候选是否产生新的 fitness 信息由评价结果和后续过程分析判断，anti-bloat 只在完全同分的质量排序中让更短程序优先。

## 10. 完整搜索流程

```text
输入：任务 x、函数契约、LLM、评估器、预算、M

1. 在总评价预算内以 M 个评价有效的初始程序为目标建立单节点轨迹；解析失败或评价失败不占用有效初始名额。
2. 初始化全局经验文本 G="" 和待反思修改计数。
3. 重复直到预算耗尽：
   a. 用统一 (fitness, -LOC) 比较器计算 endpoint 与
      route-best 百分位，得到 Q。
   b. 计算 Q+UCB，并按 softmax 选择父代轨迹。
   c. 从去重后的 endpoint / compact best 中等概率选择锚点。
   d. 排除最小上下文无法执行的参考路线，据此确定可用算子。
   e. 均匀选择可用算子；双轨迹算子再按 Q-softmax 选择参考路线，
      使用其 compact best，不增加参考路线的父代访问次数。
   f. 构建主轨迹、非祖先失败边界、可选参考轨迹和 G 的有界上下文，
      生成并提取编号自然语言 actions。
   g. 在剩余评估预算内，对每个可用 action，只用任务、主锚点代码和函数
      契约生成完整候选；不得因一个 action batch 超出总评估预算。
   h. 对候选逐个评价；评价前冻结 parent/route/global best，评价后计算三种 delta。
   j. 每个有效候选只从主锚点建立一条父子边，写入原始 action 文本、
      provenance、代码哈希、LOC 和机械变化统计，并进入 active。
   k. 按统一比较器更新 route/global best 与 compact best，保留本轮修改与
      结果作为阶段经验。
   l. 本轮全部 action 结束后，主轨迹 visit_count 增加 1。
   m. 每积累 40 个已评价子程序，用旧 G 与这 40 项 Action、实现 Idea 和
      fitness 结果生成新的文本 G；响应直接保存，不做内容校验。
   n. 若 active≥2M，再按质量精英、best route、差异 reserve 和
      Q-softmax 收缩回 M。
   o. 按既有周期保存 checkpoint；全局经验更新或种群管理后强制立即保存。
4. 返回按“fitness 优先、完全同分时 LOC 更少”确定的 global best。
```

全局经验更新放在整个搜索轮次结束之后，使同一轮生成使用同一版 \(G_k\)。达到 40 个已评价子程序后完成反思，下一轮开始使用更新后的全局经验。

## 11. 状态、日志与可复现性

checkpoint 除 v4 状态外新增：

- 每条路线的完整 node/edge path、`compact_best_id` 和 active 状态；
- 每个节点的 `program_loc` 与规范化代码哈希；
- 每条边的原始 action 文本、operator、anchor role、主轨迹、参考轨迹与参考程序 provenance；
- 父子、路线最好、全局最好和 LOC/code-change 结果；
- 当前全局经验文本、尚未反思的修改边编号、反思调用次数与成功更新次数；
- global-best 代表、best-anchor route、评估计数和搜索过程使用的随机数状态。

V5 必须提升 checkpoint 格式版本，不原地按 V4 schema 加载。恢复时校验任务、函数契约、fitness 方向、四算子配置、复杂度规则和全局经验配置。Python、NumPy 或其它实际参与抽样的客户端 RNG 均需保存，才能恢复后续抽样序列；外部 LLM 服务若本身非确定，恢复不承诺逐 token 重演。

父代选择日志记录全部候选的 \(Q\)、访问次数、UCB、softmax 概率和最终选择。双轨迹日志另存参考候选的 \(Q\)、softmax 概率、代码哈希、主/参考相似度和最终选择，但不把它记为父代访问。action 日志保存原始响应、提取出的文本 action、数量告警和失败原因。种群管理日志记录每条路线的 `keep/archive` 决定及 `quality_elite/best_anchor/diversity/softmax` 角色。全局反思保留旧认识、近期阶段范围、新认识和调用状态，使研究者能够复查认识怎样被更新。

程序评估次数仍是搜索预算。action、代码和全局反思的 LLM 调用次数、输入/输出 token、墙钟时间与失败率分别报告；全局反思不消耗程序评估次数，但不能从计算成本报告中消失。

过程记录必须能够区分：

- 观察：程序、模型输出的 action/idea、fitness、LOC、代码差异、父子关系和选择结果；
- 推断：某种思想为何有效、某条路线是否有潜力；
- 设计假设：某个 v5 机制预计解决什么问题；
- 实验结论：在预先固定协议下实际支持或否定了什么。

## 13. 可证伪假设与实验

### 13.1 完整方法

首要问题是 v5 作为完整轨迹搜索机制，能否在公平的训练与测试协议下达到领先表现，并保持重复稳定性和有竞争力的 anytime search。

### 13.2 全局经验

`[待验证]` 有界的自然语言全局反思能否减少跨路线重复试错，增加路线最好或全局最好推进，同时不压缩路线间的思想差异。

需要观察全局经验是否按周期真实更新、是否进入后续 action、是否减少跨路线重复试错，以及经验能否被新结果修正。人工检查抽样认识是否忠实概括多条轨迹、是否把单次现象或相关性误写成普遍因果规律。

### 13.3 \(Q+UCB\)

`[待验证]` 移除 \(P\) 后，\(Q+UCB\) 能否比 v4 的 \(Q+P+UCB\) 更稳定地分配预算。

比较父代访问分布、路线历史最好推进、global-best yield、anytime search、held-out 质量和重复方差；另外用等预算 continuation return 检验 \(Q\)、\(P\) 和完整历史特征的预测能力。

### 13.4 自然语言 Action

`[待验证]` 自包含自然语言 action 能否让模型把主要生成能力用于决定下一步算法修改，同时借助轨迹上下文清楚表达相对已有尝试的差异，并减少格式损耗与失败方向的原样重试。

报告文本 action 提取率、每轮提取 0/1/2 条的分布、原样重复失败率、分算子的结果分布和后续多步影响。对按 task 和算子分层抽取的 action，检查修改是否具体、是否说明与相关历史的差异，以及 action-code 是否一致；第一版不把另一个 LLM judge 的分数当作真实标签。

### 13.5 双轨迹知识算子

`[待验证]` `trace_synthesize` 与 `trace_transfer` 能否把另一条具体路线中的有效思想转化为主路线的新进展，并提供全局经验无法保留的高分辨率跨路线指导。

报告四算子的调用量、有效率、直接结果与多步 continuation，参考候选数、参考使用集中度、主/参考代码相似度，以及双轨迹 action 对 prompt 长度和程序 LOC 的影响。通过分层人工样本检查 action 是否重述参考原则、参考思想是否进入实际代码及 `synthesize/transfer` 是否语义可区分。重点检查两种失败：两个算子退化为相同的“继续加机制”，或参考轨迹虽进入 prompt 却没有进入实际代码。

第一版只比较四算子均匀选择与移除双轨迹算子的版本，不同时引入自适应算子调度或额外供体评分超参数。

### 13.6 最小 anti-bloat

`[待验证]` “refine 可做减法 + compact best + 完全同分择简”能否在不损害任务质量与泛化的前提下，降低无收益程序增长。

至少比较：

1. v4；
2. v5 其它机制，但 LOC 只记录不影响搜索；
3. 完整 v5。

报告全部候选、父代、active survivor 与 global best 的 LOC 曲线，父子
\(\Delta F\)-\(\Delta LOC\) 联合分布，精确同分出现率、compact-best 使用率、
同分短程序的存活与后续贡献、执行时间和 held-out 表现。

如果完整 v5 的程序仍持续膨胀，同时精确同分很少发生，则该结果否定“精确同分择简已经足够”的判断。下一步才考虑统计近同分或专门简化动作，不把它们预埋进第一版。

### 13.7 机制联合检查

单组件指标不能发现机制之间的冲突。V5 还必须检查：

| 机制组合 | 主要风险 | 需要观察 |
| --- | --- | --- |
| compact best × 有界历史 | 锚点落在旧窗口外，或失败边界被误当成锚点已实现机制 | 窗口外锚点使用率、formation/tested-after 完整性、分叉路径正确性 |
| 全局经验 × 局部/参考证据 | 摘要压过直接事实，或三种上下文互相冲突 | 冲突 action 比例、采用的证据来源、后续结果 |
| 双轨迹算子 × anti-bloat | 组合算子系统性追加逻辑并加速程序膨胀 | 分算子的 \(\Delta LOC\)、代码变化比例、质量收益和 held-out |
| \(Q\)-供体选择 × 种群管理 | 少数高质量路线同时垄断父代、供体和 best-anchor 角色 | 父代/供体集中度、active 唯一程序数、参考相似度 |
| 自然语言 action × 两阶段生成 | action 已利用知识，代码阶段却没有落实 | 文本提取成功率、人工 action-code 一致率、失败阶段 |
| 双轨迹/长程序 × 上下文预算 | 参考信息挤掉主历史，或程序增长导致调用不可执行 | 分区 token、裁剪 edge 数、context overflow、分算子有效率 |
| 全局反思 × 计算预算 | 评价次数相同但 LLM token 与墙钟显著增加 | 分阶段调用量、token、时间和性能收益 |

这些联合检查用于定位失败原因，不再增加在线控制器。只有某项冲突在重复实验中稳定出现，才进入后续机制设计。

## 14. 与 v4 的最小差异

| 机制位置 | v4 | v5 |
| --- | --- | --- |
| 搜索视野 | 严格祖先轨迹 | 主轨迹 + 直接参考轨迹 + 有界全局经验 |
| 轨迹存储 | 状态直接截断为最近窗口 | 完整祖先路径；仅 prompt 有界 |
| 父代主评分 | \(0.6Q+0.4P\) | \(Q\) |
| 访问公平 | \(V_{\mathrm{search}}+\mathrm{UCB}\) | \(Q+\mathrm{UCB}\) |
| Action | 单轨迹上下文下的自然语言修改说明 | 主/参考/全局上下文下的自包含自然语言修改说明；系统自动记录 provenance |
| 锚点 | endpoint / 历史最好 | endpoint / compact best |
| Refine | 深化已有思想 | 可深化、修复、替换、删除或合并 |
| 算子集合 | ideate / refine | ideate / refine / synthesize / transfer |
| 双轨迹生成 | 无 | 参考轨迹提供知识；子程序只写回主轨迹 |
| 程序复杂度 | 不记录、不参与选择 | 记录 LOC；完全同分时更短优先 |
| 跨路线知识 | 无 | 直接参考轨迹 + 每 40 个已评价子程序更新的全局经验 |
| Checkpoint | V4 树、窗口轨迹和搜索状态 | 新格式：完整路径、经验、provenance、复杂度与 RNG 状态 |

## 15. 实现顺序与设计验收

综合审查后，V5 不缺少新的核心模块；真正风险在于四项变化同时落地时破坏已有不变量。当前独立实现已按以下依赖顺序完成，该顺序继续作为后续审查和重构的验收边界：

1. **状态底座**：先实现完整路径、LOC / 代码哈希、统一比较器和 V5 checkpoint。验收窗口外 compact best 能正确分叉，恢复前后 active、best、访问次数和抽样状态一致。
2. **可追溯决策**：实现自然语言 action、非祖先失败边界和系统 provenance。验收原始 action 文本完整进入代码阶段与修改边，可用子集可以继续，每个新节点始终只有一条父边。
3. **双轨迹算子**：加入参考候选、两个新算子和上下文预算。验收参考只获得知识引用、不获得父边或 UCB credit，且自包含 action 能把所需供体原则传给代码阶段。
4. **全局经验**：最后加入 40 个已评价代码触发、纯文本递归重写和 Action 接入。验收每批恰好包含 40 项修改及结果，响应直接保存，同一搜索轮次使用同一版本 \(G_k\)。
5. **整体冒烟**：在很小预算下覆盖四算子、内部锚点、反思触发、种群收缩和 checkpoint 恢复，再启动正式比较。

实现完成的判据不是“所有新字段已经出现”，而是第 5.5 节不变量、完整流程时序和第 13.7 节联合检查都能由测试或日志直接验证。V5.1 的公开 `run()` 测试覆盖自然语言 Action、代码阶段职责、40 个已评价代码触发的纯文本反思、反思调用失败重试、真实 tokenizer、有效初始化补足、长高质量程序不受简约规则压制和 checkpoint 恢复。机制接口修正不证明最终性能。
