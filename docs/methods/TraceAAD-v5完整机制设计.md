# TraceAAD v5：以轨迹种群指导算法改进

> 当前版本：V5.3（2026-07-28）。
>
> V5.3 以 V5.2 为基线，只做一项核心消融：完整移除在线全局经验及其反思链路。
> 四个轨迹算子、最长 8 节点轨迹、Action/Code 共享历史、双轨迹直接参考、
> \(0.8Q+0.2P\) 搜索值、compact best 和完全同分择简均保持不变。算子提示词
> 只做轻量语义澄清，不把它们机械改名或压缩成普通“交叉/变异”。
>
> V4 由 [TraceAAD v4](TraceAAD-v4完整机制设计.md) 与
> `llm4ad/method/traceaad/` 独立维护。V5.3 仍使用
> `llm4ad/method/traceaad_v5/`，实验工件默认写入 `version5_3`。

## 1. 科学主张

算法改进是逐步引入思想、观察结果、继续修正或换向的过程。当前程序只是这一
过程的一个截面；程序怎样形成、哪些方向已经成功、停滞或退步，都会影响下一步
应该怎样改。

TraceAAD 的核心主张是：

> 把算法改进历史组织成可搜索、可评价、可继续发展的轨迹，并用这些轨迹中
> 积累的经验指导下一步算法生成。

V5.3 从种群进化的底层逻辑理解搜索：一部分操作沿单条路线产生有方向的变化，
另一部分操作让两条路线的知识发生迁移或重组。这里的搜索个体不是孤立代码，
而是“当前程序及其来时路”。因此四个算子具有变异与交叉的底层亲缘性，同时
必须保留面向轨迹历史的适配语义。

## 2. 搜索状态与轨迹

一次决策的核心状态写为：

\[
s_t=(x,p_t,\tau_t,\eta_t,\rho_t,b_t),
\]

其中：

- \(x\)：任务描述与函数契约；
- \(p_t\)：本轮唯一的主锚点程序；
- \(\tau_t\)：包含 \(p_t\) 的主轨迹；
- \(\eta_t\)：选择内部锚点时，锚点之后已经测试的旧尝试；
- \(\rho_t\)：双轨迹算子使用的参考轨迹，单轨迹算子下为空；
- \(b_t\)：预算和搜索阶段状态。

一条轨迹是从某个初始程序到当前程序的严格祖先路径。每个新程序只有一个结构
父代，全部节点和修改边构成森林。参考轨迹只提供知识，不成为第二个结构父代。

active 轨迹最多保留 8 个程序节点和 7 条修改边。超过上限后，从最早端截断；
endpoint、compact best、趋势和内部锚点都只依据当前保留路径计算。完整派生图
继续保存事实拓扑。

每条历史边向模型展示：

- Planned Action；
- 子程序的一句 Implemented Idea；
- 父子 fitness 与 improve / plateau / regress；
- 代码变化比例与非空 LOC 变化。

历史不重复展示每一步完整代码。主锚点程序始终完整展示，双轨迹算子另外完整
展示参考程序。

## 3. 两种在线搜索视野

### 3.1 主轨迹：当前算法的来时路

主轨迹说明当前程序怎样形成、哪些机制已经验证、哪些后续尝试已经失败或停滞。
它是所有四个算子的共同依据，也是新节点写回的唯一 ancestry。

选择 endpoint 时，展示它的形成历史。选择内部 compact best 时，提示词分开
显示：

- `[How This Program Was Reached]`：锚点的形成历史；
- `[Later Attempts From This Program]`：锚点之后已经测试的尝试。

这样模型可以利用失败边界，又不会把后来的机制误认为已经存在于锚点代码中。

### 3.2 参考轨迹：另一条路线的直接知识

`trace_synthesize` 和 `trace_transfer` 额外读取一条参考轨迹及其 compact-best
程序。参考轨迹保存具体实现和完整试错关系，作用类似种群搜索中的跨个体知识
交换，但交换对象是经过轨迹语义解释的算法思想。

主轨迹与参考轨迹的职责保持清楚：

- 主轨迹决定从哪里修改、子节点写到哪里；
- 参考轨迹说明另一条路线有什么可以重组或迁移；
- 新候选始终只有一个主父代。

V5.3 不维护在线全局经验。跨路线知识只通过本轮明确选择的参考轨迹进入决策，
避免一份共享的高层文本持续覆盖各条路线自身的证据。

## 4. 四个轨迹语义算子

四个算子独立保留，并在可用时等概率选择：

| 算子 | 轨迹语义 | 底层进化逻辑 |
| --- | --- | --- |
| `trace_ideate` | 根据主轨迹提出新的算法方向，并把退步和平台当作已测试边界 | 较大步幅的定向变异 |
| `trace_refine` | 对已显示价值的机制或已暴露弱点做一次聚焦修正 | 局部、证据驱动的变异 |
| `trace_synthesize` | 从主/参考轨迹各提取一个有支持的原则，使两者在主程序中形成功能交互 | 经轨迹适配的重组 |
| `trace_transfer` | 保持主程序核心结构，只迁移参考轨迹中一个有支持的思想 | 经轨迹适配的定向迁移 |

这种对应关系用于解释算子为何构成种群搜索，不把 prompt 改写成抽象的
“mutation/crossover”。模型真正需要看到的是算法思想、试错历史和本轮应如何
改变主程序。

双轨迹算子必须先有可执行的参考上下文。参考轨迹排除主轨迹后按质量
\(Q\)-softmax 选择，并使用其 compact best。参考使用不增加其父代访问次数。

## 5. Action 与 Code 两阶段

Action 阶段接收任务、主程序、主历史、算子方向，以及可选的参考程序和参考
历史。输出恰好两条编号、单行、自包含的自然语言修改建议。每条建议需要：

1. 说明具体改什么；
2. 相对已展示尝试有什么实质差异；
3. 只依赖目标函数参数和局部计算；
4. 双轨迹时按算子语义说明如何利用参考知识。

Action prompt 使用轻量的泛化约束：建议应扎根于任务结构，避免只由训练规模
解释的固定常数。它不强制所有任务使用归一化公式，也不替代真实 OOD 评估。

Code 阶段接收与 Action 相同的主历史和主程序；双轨迹时也接收同一参考历史与
参考程序。它从主程序实现选定 Action，并只按 Action 指定的方式使用参考程序。
提供完整上下文的目的，是减少 Action 到代码之间的信息损失；V5.3 不把代码
相同直接归因于上下文本身，也不增加在线重复拒绝规则。

## 6. 轨迹评分与父代调度

### 6.1 质量

路线质量为：

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i}.
\]

两项都是 active 候选集合中的并列感知百分位。程序比较首先看任务 fitness；
只有 fitness 完全相同时，较短程序优先。

### 6.2 趋势与访问公平

路线趋势 \(P_i\) 是保留路径上父子变化符号的折扣聚合。父代搜索值为：

\[
V_i=0.8Q_i+0.2P_i.
\]

再加入 UCB：

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

\(Q\) 提供当前成果利用，\(P\) 提供小权重的路线走势，UCB 维持低访问路线的
试验机会。它们是继续开发价值的代理，不是真实长期价值。

`visit_count` 以“主轨迹被选择并发起一次生成批次”为单位。解析或生成失败仍
算访问，因为本轮已经消耗了一次路线机会。

## 7. 锚点、简约与种群管理

父代轨迹选定后，从去重的 endpoint 和 compact best 中等概率选锚点。
compact best 是当前保留轨迹上达到路线最好 fitness 的最短程序。

复杂度只使用非空 LOC。它不形成连续惩罚，也不拒绝更长候选；只在 fitness
完全相同的比较中让较短程序优先。代码哈希和相似度用于过程诊断，不进入在线
候选接受规则。

active frontier 的目标规模为 \(M=30\)。当 active 数达到 \(2M\) 时收缩回
\(M\)：

1. 保留质量精英；
2. 保留包含 global best 的路线；
3. 保留少量差异 reserve；
4. 其余席位按 \(0.8Q+0.2P\) softmax 无放回抽样。

退出 active 的路线仍保留在派生图与日志中，只是不再直接繁衍。

## 8. 完整搜索流程

```text
1. 在评估预算内建立 30 条评价有效的初始单节点轨迹。
2. 重复直到预算耗尽：
   a. 计算 active 轨迹的 Q、P、UCB，选择主轨迹；
   b. 从 endpoint / compact best 选择唯一主锚点；
   c. 判断参考候选是否可用，等概率选择四个轨迹算子；
   d. 双轨迹算子按 Q-softmax 选择参考轨迹及 compact-best 程序；
   e. 用主历史和可选参考历史生成两条自然语言 Actions；
   f. 对每条可用 Action，从主程序生成完整候选代码；
   g. 真实评价候选，记录父代、路线最好和全局最好三种变化；
   h. 每个有效候选只从主锚点写入一条边，并形成 active 分支；
   i. 更新 compact best、global best、访问统计与日志；
   j. active 达到 60 时收缩回 30；
   k. 按周期保存 checkpoint。
3. 返回 fitness 最优、完全同分时 LOC 最少的 global best。
```

V5.3 流程中没有全局反思阶段、共享经验状态或反思 LLM 调用。

## 9. 上下文、状态与可复现性

方法默认完整构造当前最多 8 节点的轨迹上下文，不设置人为本地 prompt 上限。
如果模型服务有已知硬边界，可通过 `LLM_CONTEXT_TOKENS` 显式配置；此时方法在
调用前检查输入与输出预留是否可执行。

checkpoint 保存派生图、active 轨迹、global best、预算进度、随机数状态和
profiler 累计信息。V5.3 不再保存：

- `global_experience`；
- 待反思边；
- 反思尝试次数或更新次数。

每个实验保留 `run_config.json`、samples、`method_events.jsonl`、
`llm_calls.jsonl`、`errors.jsonl`、`run_summary.json` 和 checkpoint。
Action 与 Code 的 token、耗时、解析状态分别记录。

## 11. V5.3 的实验主问题

V5.3 是针对全局经验的受控消融。与 V5.2 保持同一任务、模型、预算、重复数和
测试协议，主要回答：

1. 移除共享全局经验后，训练质量和三重复下限是否恢复；
2. 不同路线的代码与算法思想是否更分散；
3. plateau、父子相同代码、active 唯一程序比例和后半程 global-best 更新是否
   改善；
4. `synthesize/transfer` 是否仍能提供有效的跨轨迹知识交换；
5. OOD 泛化变化来自搜索到的算法机制，还是训练 fitness 的偶然优势。

当前证据只支持“V5.2 的全局经验文本存在不可靠断言，并可能形成共享偏置”这一
风险判断，尚未证明它是 V5 系列低于 V4 的唯一原因。V5.3 的价值正是把这条
因果链单独拿出来验证。
