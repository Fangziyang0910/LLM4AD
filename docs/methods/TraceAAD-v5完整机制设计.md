# TraceAAD V5：以轨迹种群指导算法改进

## 1. 科学主张与设计目标

版本标识：V5（2026-07-29）。

算法改进是逐步引入思想、观察结果、继续修正或换向的过程。当前程序只是这一过程的一个截面；程序怎样形成、哪些方向已经成功、停滞或退步，都会影响下一步应该怎样改。

V5 的科学主张是：把算法改进历史组织成可搜索、可评价、可继续发展的轨迹，并用轨迹中积累的经验指导下一步算法生成。该主张规定历史如何参与决策，不构成对任一组件或整体效果的预先结论。

V5 以种群搜索描述两类知识流动：部分操作沿单条路线产生有方向的变化，另一部分操作使两条路线的知识发生迁移或重组。搜索个体是"当前程序及其来时路"。四个算子因此具有变异与交叉的底层亲缘性，同时保留面向轨迹历史的适配语义。

设计目标是定义一个包含四个轨迹语义算子、最长 8 节点轨迹、修改决策与代码生成共享历史、双轨迹直接参考的搜索方法。V5 不维护在线全局经验，路线搜索值采用 $0.8Q+0.2P$，程序复杂度只在 fitness 完全相同时用于择简。

## 2. 搜索状态、轨迹与派生图

一次决策的核心状态写为：

\[
s_t=(x,p_t,\tau_t,\eta_t,\rho_t,b_t),
\]

其中：

- $x$：任务描述与目标函数接口；
- $p_t$：本轮唯一的主锚点程序；
- $\tau_t$：包含 $p_t$ 的主轨迹；
- $\eta_t$：选择内部锚点时，锚点之后已经测试的旧尝试；
- $\rho_t$：双轨迹算子使用的参考轨迹，单轨迹算子下为空；
- $b_t$：预算和搜索阶段状态。

一条轨迹是从某个初始程序到当前程序的严格祖先路径。每个新程序只有一个结构父代，全部节点与修改边构成森林。参考轨迹只提供知识，不成为第二个结构父代。

active 轨迹最多保留 8 个程序节点和 7 条修改边，超过上限从最早端截断；endpoint、compact best、趋势和内部锚点都只依据当前保留路径计算。完整派生图继续保存事实来源。

每条历史边向模型展示修改说明、子程序的一句话思想归纳、父子 fitness 与改进/停滞/退步、以及非空代码行数的变化。历史不重复展示每一步完整代码；主锚点程序始终完整展示，双轨迹算子另完整展示参考程序。

## 3. 主轨迹与参考轨迹

### 3.1 主轨迹

主轨迹说明当前程序怎样形成、哪些机制已经验证、哪些后续尝试已经失败或停滞。它是四个算子的共同依据，也是新节点写回的唯一来源。

选 endpoint 时展示它的形成历史。选内部 compact best 时，提示分两段展示：

- `[How This Program Was Reached]`：锚点的形成历史；
- `[Later Attempts From This Program]`：锚点之后已经测试的尝试。

这样模型可以利用失败边界约束下一步，又不会把后来的机制误认为已存在于锚点代码。

### 3.2 参考轨迹

`trace_synthesize` 和 `trace_transfer` 额外读取一条参考轨迹及其 compact best。参考轨迹保留具体实现与完整试错关系，相当于种群搜索中的跨个体知识交换，但交换对象是经轨迹语义解释后的算法思想。

主轨迹与参考轨迹的职责为：主轨迹决定从哪里修改、子节点写到哪里；参考轨迹说明另一条路线有什么可重组或迁移；新候选始终只有一个主父代。

V5 不维护在线全局经验。跨路线知识只通过本轮明确选择的参考轨迹进入决策，避免一份共享的高层文本持续覆盖各条路线自身的证据。

## 4. 四个轨迹语义算子

四个算子独立保留，可用时等概率选取：

| 算子 | 轨迹语义 | 对应的搜索操作 |
| --- | --- | --- |
| `trace_ideate` | 依据主轨迹提出新的算法方向，退步与平台视为已测试边界 | 较大步幅的定向变异 |
| `trace_refine` | 对已显价值或已暴露弱点做一次聚焦修正 | 局部、证据驱动的变异 |
| `trace_synthesize` | 从主/参考轨迹各取一原则，使二者在主程序中功能耦合 | 经轨迹适配的重组 |
| `trace_transfer` | 保持主程序核心，迁移参考轨迹中一个有支撑的思想 | 经轨迹适配的定向迁移 |

这一对应关系说明算子如何落入种群搜索的变异与交叉，但不把提示改写成抽象的"变异/交叉"；模型看到的是算法思想、试错历史和本轮应如何改动主程序。

双轨迹算子仅在参考上下文可用时参与选取。参考轨迹排除主轨迹后按质量 softmax 选取，并使用其 compact best。参考被使用不增加其父代访问次数。

## 5. 修改的两阶段生成

修改决策阶段接收任务、主程序、主历史、算子方向，以及可选的参考程序与参考历史，输出恰好两条编号、单行、自包含的自然语言修改建议。每条须：

1. 说明具体改什么；
2. 说明相对已展示尝试的实质差异；
3. 只依赖目标函数参数与局部计算；
4. 双轨迹时按算子语义说明如何利用参考知识。

修改决策提示含一条轻量泛化引导：建议应扎根于任务结构，避免只由训练规模解释的固定常数。它不强制所有任务使用归一化公式，也不替代真实的分布外评估。

代码生成阶段接收与修改决策相同的主历史、主程序，双轨迹时也接收同一参考历史与参考程序，从主程序实现选定修改，并只按修改指定的方式使用参考程序。提供完整上下文是为减少从修改意图到代码的信息损失；V5 不把代码相同直接归因于上下文本身，也不增加在线重复过滤。

## 6. 轨迹评分与父代调度

### 6.1 质量与简约规则

路线质量为：

\[
Q_i=0.7Q_{\mathrm{endpoint},i}+0.3Q_{\mathrm{best},i}.
\]

两项均为 active 候选集合中的并列感知百分位。程序比较先看任务 fitness，仅当 fitness 完全相同时较短程序优先。

### 6.2 趋势与访问公平

路线趋势 $P_i$ 为保留路径上父子变化符号的折扣聚合。父代搜索值为：

\[
V_i=0.8Q_i+0.2P_i.
\]

再加入 UCB：

\[
A_i=V_i+0.25\sqrt{\frac{\log(1+N)}{1+n_i}},
\qquad
\Pr(\tau_i)=\operatorname{softmax}(A_i/0.2).
\]

$Q$ 提供当前成果利用，$P$ 提供小权重的路线走势，UCB 维持低访问路线的试验机会。趋势以 $10^{-12}$ 为正负阈值。它们是继续开发价值的代理，不是真实长期价值。

访问计数以"主轨迹被选择并发起一次生成批次"为单位。格式不合规或生成失败仍算一次访问，因为本轮已消耗一次路线机会。

## 7. 锚点、简约与生存管理

父代选定后，从去重的 endpoint 与 compact best 等概率选锚点；compact best 是当前保留段上达到路线最优 fitness 的最短程序。

复杂度仅用非空 LOC，不形成连续惩罚，也不拒绝更长候选；只在 fitness 完全相同的比较中让较短程序优先。程序文本相同性与相似度用于过程诊断，不进入在线接受规则。

active frontier 目标规模 $M=30$，达到 $2M=60$ 时收缩回 $M$：

1. 保留质量精英；
2. 保留含全局最优的路线；
3. 保留少量差异代表；
4. 其余席位按 $0.8Q+0.2P$ 的 softmax 无放回抽样。

退出 active 的路线仍留在派生图与日志中，只是不再繁衍。

## 8. 搜索流程

```text
1. 建立至多 30 条评价有效的初始单节点轨迹。
2. 重复至预算耗尽：
   a. 依 Q、P 与 UCB 选主轨迹；
   b. 从 endpoint / compact best 选主锚点；
   c. 依参考是否可用，等概率选四个算子之一；
   d. 双轨迹算子按质量 softmax 选参考轨迹及其 compact best；
   e. 用主历史与可选参考历史生成两条自然语言修改；
   f. 对每条可用修改从主程序生成完整候选；
   g. 评价候选，记录父代、路线最优与全局最优三种变化；
   h. 每个有效候选只从主锚点写入一条边，并形成 active 分支；
   i. 更新 compact best、全局最优、访问统计；
   j. active 达 60 时收缩至 30；
   k. 周期保存断点。
3. 返回 fitness 最优、同分时 LOC 最少的程序。
```

V5 没有全局反思、共享经验状态或反思调用。

## 9. 可复现协议与机制不变量

### 9.1 运行与产物

实现位于 `llm4ad/method/traceaad_v5/`，由 `python -m experiments.runners.traceaad.run --version v5` 启动，工件写入 `traceaad_v5/version5/`；正式批次为 `20260728_151736`，held-out 位于 `traceaad_v5/eval_best_20260728_151736/`。

方法完整构造当前最多 8 节点的轨迹上下文，不设人为的上下文长度上限；模型服务的能力边界由实验后端负责，方法不预先裁掉候选路线，也不增加在线过滤。产物按监控、分析、断点三类分离，只保存原始事实，不在落盘时计算过程指标：

```text
<run>/
  run_config.json
  logs/      progress.log, errors.jsonl, summary.json
  artifacts/ candidates.jsonl, edges.jsonl, llm_calls.jsonl, decisions.jsonl
  checkpoints/latest.json
```

`candidates.jsonl` 记录每次评价的程序、分数、算子与失败信息；`edges.jsonl` 记录入图边的父子、算子、修改、锚点与参考轨迹；`llm_calls.jsonl` 记录阶段、token、耗时与成败（成功调用不存提示与响应，失败可存截断响应）；`decisions.jsonl` 记录轨迹与算子选择、最优更新、种群收缩与停机等原始决策。

断点保存派生图、轨迹记忆、全局最优、预算进度与随机数状态，不保存事件计数，也不保存全局经验、待反思边或反思次数。

### 9.2 机制不变量

- 每个新候选只有一个主结构父代；参考轨迹只提供本轮知识，不写入第二条结构边。
- 修改决策与代码生成使用相同的主历史、主程序和可选参考历史、参考程序。
- 双轨迹算子仅在参考上下文可用时使用；参考轨迹排除主轨迹，并使用其 compact best。
- 参考被使用时不增加其父代访问次数；主轨迹每次被选择并发起一次生成批次都增加访问计数，格式不合规或生成失败也计入。
- 复杂度仅用非空 LOC，仅在 fitness 完全相同时用于择简；程序文本相同性与相似度不进入在线接受规则。
- 代码相同不直接归因于上下文本身；不增加在线重复过滤。
- 退出 active 的路线保留在派生图与产物中，但不再繁衍。
- 断点只保障恢复，不改变搜索机制。

### 开发阶段得到的机制教训

- 五字段结构化 Action 把算法决策与审计表单合并。12,949 次调用中 39.9% 没有合法 Action，只有 30.1% 得到完整两条；两条自然语言 Action 恢复了候选供给。搜索系统应记录 provenance，模型只负责提出修改。
- Prompt、parser、代码提取、validator 和 evaluator 共同定义有效搜索空间。解析成功不等于执行了目标代码；静默选错 Action、固定取第一个代码块和模糊失败语义都会污染机制实验。
- Action 是修改决策，Implemented Idea 只是模型声明，程序差异与评价结果才是事实。两阶段应共享本轮必要证据，同时保持"决定修改"和"执行修改"的职责清楚。
- 首轮全局反思因上下文与输出预算错误一次也未运行；修复后又因缺少证据边界传播错误。机制未执行、执行无效和执行有害必须分别判断。
- 提高父子趋势权重增加了局部 improve，却降低父代质量和 global-best 更新；普通回弹不等于前沿推进。
- 双轨迹算子能够形成高质量路线，但固定等概率会在弱路线或高相似路线之间浪费预算；轨迹身份数量不能替代可执行状态覆盖。
- 同分择简缩短了保留程序，却没有阻止生成端继续增加无收益复杂度；其繁殖影响仍需消融。
- 代码审查和冒烟只能证明机制可运行。均匀算子、路线评分、参考选择和简约规则的收益仍需受控实验。

V5 的主要问题位于"历史怎样转化为预算和修改"，而不是轨迹没有信息。开发子版本的原始工件位于 `archive/traceaad-v5-development/`。
