# RQ-006 轨迹如何成为预算分配的核心单位

## 问题

TraceAAD 的核心不是搜索树，而是算法改进历史：从什么程序出发，引入了什么
Idea，代码实际如何改变，得到什么结果，后续又如何延续、修正或回退。树只是保存
这些真实关系的数据结构。

本问题是：

> 给定多条已经发生的算法改进轨迹，如何根据它们的当前质量、真实推进记录、
> Idea—结果证据和不确定性，把下一份有限评价预算分配给最值得继续验证的轨迹？

## 旧协议诊断与当前状态

正在运行的旧协议 V9.1 保留轨迹作为生成上下文，却仍以程序节点的 continuation fitness
分配预算。它实际上是“带轨迹提示的单样本 MCTS”，还不是轨迹搜索。旧实验继续作为完整
对照，不用当前代码恢复。2026-08-08 起，V9.1 当前实现已直接替换为本文定义的轨迹中心协议；
以下表格描述的是促成这次替换的旧协议缺陷，而不是当前代码行为。

| V9.1 机制 | 问题 |
| --- | --- |
| 节点价值是后代 continuation fitness | 表达当前后代成果，不表达轨迹继续产生有价值 Idea 的能力 |
| 全树 `q_min/q_max` 归一化 | 一个离群结果会改变所有轨迹的选择值，未发生新事件的轨迹也会漂移 |
| 一次选择只随机执行一个算子、生成一个子代 | 一次高方差生成就会重估整条祖先链，没有形成可靠的轨迹证据 |
| 渐进式拓宽触发后立即结束本轮 | 把数据结构增长变成独立预算目标，并与继续验证已有轨迹互斥 |
| 根级拓宽重新调用空白初始化 | 新路线不来自已有历史，只是持续零样本抽样 |
| 访问次数与节点 UCT 决定预算 | 计数单位是树节点，不是完成了多少次可比的轨迹验证 |

这些问题不应通过调整 `lambda`、`alpha`、初始根数量或更换归一化方法修补。
需要重新定义预算分配的对象、证据和更新单位。

## 核心对象：轨迹

一条轨迹由一个可执行终点及其唯一形成历史定义。形成历史中的每条边保存：

- 决策前程序和评价结果；
- 本轮 Idea 及实际代码变化；
- 子代的有效性与 fitness；
- 是否推进该轨迹此前的历史最好；
- 是否推进生成当时的全局最好。

程序、父子关系和 evaluator 结果是事实；Idea 是对实际改动的声明，只有与代码变化和
评价结果绑定后才能作为后续证据。同一程序即使代码相同，来时路不同时仍是不同轨迹。

每个新子代使父轨迹得到一次已测试的后续尝试，并形成一条更长的新轨迹。
旧轨迹仍作为可回退和重新尝试其他 Idea 的真实起点保留。

## 决策时看到的轨迹

完整派生图保存全部事实，单次生成只能使用有限的锚点化轨迹窗口：

- 当前锚点的完整代码与 fitness；
- 上溯的有序 Idea—结果历史，说明当前程序如何形成；
- 从锚点出发已测试的分支或短程后续，说明附近已尝试方向。

历史代码全文通常无法容纳，因此 Idea 必须与有效性、fitness、代码变化摘要和 evaluator 结果绑定。这些信息能提供比孤立个体更多的条件证据，但无法识别 Idea 本身、具体实现、参数与评价噪声各自造成了多少结果。

当前 V9.1 给模型展示最近 8 条祖先边和最多 8 个直接子分支，尚未实现上溯—下游短程混合窗口。“最优窗口”的研究目标应是在固定上下文预算下提高下一步决策信息量，不能按已知最高后代事后挑选，以免隐去失败样本和尝试次数。

## 轨迹证据不压成一个总分

轨迹至少保留六类不同证据：

1. **锚点质量**：锚点程序的原始有向 fitness，表示下一步的真实执行起点。
2. **历史成果**：形成路径曾到达的最好 fitness，只表示这条路线做到过什么。
3. **路线推进**：每次预算分配是否产生了超过分配前路线最好的程序。
4. **Idea—结果记录**：已尝试方向、实际代码变化和直接结果，用于决定下一步做什么。
5. **局部形态**：锚点窗口的水平或时序加权水平、趋势和波动。
6. **延迟后续**：暂时较差状态是否经过多步产生高价值后代，以及该结果消耗了多少后续尝试。

锚点质量和历史成果不等于未来产出能力；一次父子回弹也不等于路线推进。
只有新结果超过该轨迹在本次分配前的历史最好，才记为一次路线推进。
这些证据不通过加权和、全树排名或全局 min–max 压缩为单一价值。

局部水平、趋势和波动只是轨迹形态，不能单独解释为好坏。正趋势可能是差起点回弹，低波动可能是稳定精炼或行为停滞，高波动可能是局部地形崎岖或生成变化失控。它们应影响后续生成约束与预算不确定性，具体映射需由“轨迹形态 × 生成方式”的条件结果验证。

一个较差祖先最终产生很好后代，使它获得事后谱系价值和可供后续推理的历史价值。这不能直接转化为重新扩展该祖先的预算信用；否则会重现“一次幸运后代永久抬高整条祖先链”。延迟贡献应作为单独证据保留，并显式计入尝试次数、后代距离和未验证方向。

## 一次预算分配事件

预算的最小可解释单位不是一次节点访问，也不是一次随机生成，而是一次完整的
**轨迹验证事件**：

1. 选择一条轨迹；
2. 读取该轨迹的形成历史和已测试直接分支；
3. 在相同历史条件下生成一小批语义上不同的 `Idea + Code`；
4. 完成真实 evaluator，无效、失败和重复同样属于该次事件的结果；
5. 把每个 Idea—Code—结果写入事实记录；
6. 只更新被选轨迹的验证次数和路线推进证据，不向祖先递归复制同一份信用。

小批候选用于降低单次 LLM 生成的方差，不得把某个算子的一次幸运结果当成轨迹的稳定能力。
当前最小实现固定生成两个候选，并要求来自两个不同的轨迹语义算子。

## 轨迹预算协议

预算分配采用分层决策，不再使用一个 `fitness + exploration` 总分：

1. **基本验证**：新轨迹只有在质量排序或未验证配额中被选入活跃候选时，才获得一次最小的
   轨迹验证事件；未被选中的轨迹保留事实，但不自动获得后续预算。
2. **质量优先**：完成基本验证后，先用锚点原始有向 fitness 确定值得继续开发的质量区域；
   fitness 只做顺序比较，不与不确定性数值相加。
3. **区域内分配**：在质量可比的轨迹之间，根据路线推进次数、完整验证次数、最近推进记录
   和证据不确定性决定下一份预算。
4. **Idea 指导生成**：轨迹选定后，将该轨迹已尝试的 Idea—结果记录作为证据，生成新的
   `Idea + Code`。语义上可以体现延续、修正、重新组织或引入参考，但这些不是额外的模型层动作变量。Idea 不直接兑换数值信用。

当前最小稳定计算已经确定：质量区域取锚点原始有向 fitness 前 10 条轨迹；区域内先验证尚无
证据的轨迹，随后以路线推进次数 `s`、完整验证次数 `n` 的 Wilson 上界分配预算，`z=1.0`。
最近 4 次推进率、原始 fitness 与代码简洁性只依次用于打破选择次序，不与 Wilson 值加权求和。
该实现满足以下约束：

- 其他轨迹加入一个极端结果时，本轨迹的证据不变；
- 一次普通父子回弹不能伪装成路线推进；
- 一次幸运突破不能永久垄断预算；
- 证据不足的新轨迹可获得基本验证，但不保证均匀访问；
- 选择值只在本轨迹获得新证据时更新。

这套计算是当前实验的第一阶段基线，它估计的仍是“从当前终点生成后立即推进路线最好”的不确定上界。两个不同算子的结果被合并记给同一轨迹，因此它无法学习哪种生成方式与该轨迹匹配。终点前 10 的硬候选区也会使退步较大的中间状态难以获得多步发展预算。这两点是当前 V9.1 对延迟价值和轨迹—算子适配的明确能力边界。

## 新轨迹如何产生

初始化只负责建立一个小型、有效、具有基本竞争力且思想有区分的起始锚点集合。初始数量不是本问题的核心变量；首批质量分布、有效率与可达行为区域才是局部精炼能否发生的边界条件。
初始化完成后不再使用空白 prompt 持续增加根。

新轨迹只能来自已有轨迹证据：

- 对当前轨迹引入一个尚未测试的新 Idea；
- 对已有失败 Idea 进行有证据的修正；
- 从历史中的较好状态回退后走另一条路；
- 引入另一条轨迹中已经有真实结果支持的参考 Idea。

这些是生成下一步 `Idea + Code` 的语义选择，不是树的宽化动作。

## 树的从属职责

树只负责：

- 保存程序的真实派生关系；
- 还原任一终点的唯一形成历史；
- 保留已测试分支，支持回看、回退和跨轨迹引用；
- 为 checkpoint、可观测性和结果审计提供事实拓扑。

树不定义轨迹价值、探索、利用或预算。节点访问次数、子节点数量和树深不再是预算分配的
直接依据。

## 当前 V9.1 改写边界

当前 V9.1 已保留旧实现的可用事实层并整体替换预算机制，不保留旧 checkpoint 兼容路径。

**保留：**

- 完整单父派生关系与真实 evaluator；
- 当前程序、唯一形成历史和已测试直接分支；
- `Idea + Code` 与结果的一一对应；
- 单轨迹与双轨迹两种生成视角；
- global best 只由原始 fitness 和同分简洁性决定。

**删除：**

- 全树 min–max 价值归一化；
- 节点 continuation-value max-backup；
- 祖先递归访问与信用回传；
- `visits ** alpha` 渐进式拓宽作为预算规则；
- 初始化后的空白根生成；
- 单个随机子代立即改写整条路线价值。

**新增：**

- 显式的轨迹验证事件；
- 路线历史最好推进记录；
- 每条轨迹自有的完整验证次数、有效率和推进证据；
- 质量优先、证据不确定性参与的分层预算协议；
- 基于已测试 Idea—结果历史的下一步生成。

## 可证伪假设

- **H1：**轨迹验证事件比单候选立即回传更能稳定表达一条轨迹的后续产出能力。
- **H2：**以“超过分配前路线最好”定义推进，比普通父子 improve 更能预测后续 global-best 更新。
- **H3：**分层预算协议在不使用全局归一化的情况下，能在优质轨迹集合中集中预算，同时不被一次
  幸运突破或极端失败锁定。
- **H4：**从已有轨迹证据生成新路线，比初始化后持续零样本新增根产生更多有效的路线推进。
- **H5：**在当前代码和上下文 token 预算相同时，锚点化上溯—下游窗口比只给最近祖先或只给直接分支产生更好的下一步候选。
- **H6：**估计轨迹形态与生成方式的条件效果，比轨迹无关的算子等概率或全局算子均值调度提供更高的单位预算收益。

## 验证门槛

新机制必须先回答轨迹信用是否真正运行，再比较最终质量。

1. **无 LLM 机制测试**：构造好起点连续失败、差起点普通回弹、路线最好推进、单次幸运突破和离群失败，
   确认只有对应轨迹的证据发生预期变化。
2. **小预算真实模型**：检查每次轨迹验证的历史输入、Idea 差异、直接结果、路线推进和后续选择
   是否逐条可审计。
3. **固定代码的上下文对照**：在当前代码、模型、解码参数和 token 预算不变时，比较 `current_only`、
   最近祖先、乱序历史和锚点化上溯—下游窗口，单独识别历史与窗口的生成作用。
4. **随机化生成方式对照**：先在不同轨迹形态中随机分配生成方式，估计条件效果；在此前不实装自适应算子调度。
5. **同预算对照**：与 V9 和旧协议 V9.1 在相同 evaluator 预算下比较路线最好推进率、后半程推进、global-best
   更新、有效率和搜索 best。
6. **正式四任务三重复**：全部搜索和 held-out 测试完成后，再判断该预算协议是否改善质量与稳定性。

轨迹覆盖、树深和子节点数量只作为运行形态记录，不是机制成功标准。

## 当前决定

1. 正在运行的旧协议 V9.1 作为“MCTS 形式对齐但轨迹信用缺失”的完整对照保留；其 checkpoint
   不能恢复到当前 V9.1。
2. 当前 V9.1 使用双候选轨迹验证、原始质量前 10 门槛和 `z=1.0` 的 Wilson 上界，信用只属于
   被验证轨迹。这是正在运行的第一阶段基线，不代表轨迹价值已完整定义。
3. 这三个数值是明确、可替换的实现选择，不是科学主张；真实实验先检验轨迹信用是否按预期运行，
   再决定是否单独消融。
