# RQ-003 改进历史如何进入生成与预算分配

## 问题

真实的算法改进历史应怎样进入下一步生成，又应怎样决定下一次搜索预算投向哪里？

这是 TraceAAD 核心主张的直接承载问题，也是 V9-Core 的中心假设：当搜索位置和生成预算保持稳定时，把与当前程序严格匹配的真实改进历史交给模型，能否帮助它做出更有效的下一步修改。

## 观察与证据

### 历史进入生成

V9-Core 只提供 `matched_history`：与当前程序严格对应的形成路径，加上从它出发已测试的直接分支。历史边包含 Action、Implemented Idea、父子 fitness、结果分类和 LOC 变化，不重复历史程序全文。完整单父树保证形成历史始终与当前代码严格对应，不会出现 V5 中 Action 与 Code 历史不一致的断层。

已知的边界：历史可见不等于模型真实利用，重复失败仍会发生。这一点需要历史消融（`current_only`、`shuffled_history`）才能识别，本版代码不提供历史模式开关。

### 预算分配

V5 曾用路线质量 $Q=0.7Q_{\text{endpoint}}+0.3Q_{\text{best}}$ 加父子趋势 $P$，父代搜索值为 $0.8Q+0.2P$ 后 softmax 选择。观察到提高趋势权重会增加局部 improve，但降低被选父代质量和 global-best 更新——普通回弹不推进优质前沿（详见[研究认识 §5](../knowledge/研究认识.md)）。

V9-Core 放弃了这套公式，改为：subtree-best max-backup 提供利用值，经 midrank 百分位归一化以避免离群值敏感；递归 UCT 在每个节点比较"开新分支"（`new_child`）与"下降到已有子节点"（`descend`）；探索项随剩余预算比例衰减。V8.3 的教训是固定深度和高回报 `new_child` 会造成根锁定或 sibling 堆积，V9-Core 因此不采用趋势项、路线信用和概率控制器（[研究认识 §4](../knowledge/研究认识.md)）。

## 当前解释

上下文传递与预算分配是两个问题，不应由同一个粗糙标量替代。历史负责传递可追溯证据，选择负责在有限资源下分配评价预算。V9-Core 的立场是简约：只保留解释核心假设所必需、且已有过程证据支持的机制（[研究认识 §5](../knowledge/研究认识.md)）。

## 可证伪假设

- **H1**（历史主张）：真实匹配的形成路径和已测试分支能提高下一步修改质量。需同骨架历史消融识别。
- **H2**（结构主张）：完整单父树让来时路始终与当前代码严格对应，并保存每次 Idea + Code 生成及其结果。
- **H3**（调度主张）：subtree max-backup 与自适应 `new_child`/`descend` 竞争能在有限预算内有效分配搜索机会。
- **H4**：历史记录的事实与搜索调度使用的评分需要分开，不应把生成上下文等同于单一价值标量。

## 决定与下一步

V9-Core 正式批次（`20260807_123753`）已完成：四任务 × 三重复测试全部收口，十三方法同场平均名次 4.167 首次超过 MCTS-AHD（4.200）居第 1（差异微小：名次差 0.033、P(优于 MCTS)=0.38、CI 高度重叠），单版本口径 1.867 居首；对 MCTS-AHD 整体效应量 +0.05，是首个整体效应量为正的版本。名次细节与机制检验见[版本实验事实与机制诊断](../analysis/TraceAAD-版本实验事实与机制诊断.md) 的 V9 节。

按预期，V9-Core 的联合结果只能检验 H1–H3 的合并效果，且与 V8.2 的对照非单变量（P=0.59 不可分辨），不能识别历史协议本身的因果贡献。

随后的关键实验是**同骨架历史消融**：固定树结构、选择机制、算子和预算，只改变提供给模型的历史内容（`matched_history` / `current_only` / `shuffled_history`），这是唯一能单独识别历史主张的设计。

除最终测试外，统一报告被选父代质量、global-best 更新、后半程推进、扩展点深度分布和访问覆盖。
