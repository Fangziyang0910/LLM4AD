# RQ-003 轨迹上下文与搜索评分

状态：当前机制已固定，长期信用仍待研究  
当前判断：上下文传递可追溯证据，评分分配计算预算；两者不能由同一粗糙标量替代。  
下一步：以优质前沿推进和后续贡献定义路线信用。

## 问题

轨迹历史应怎样进入生成，又应怎样决定下一次搜索预算？

## 当前机制

V5 active 轨迹最多保留 8 个程序节点。历史边包含 Action、Implemented Idea、父子 fitness、结果分类和机械代码变化；不重复历史程序全文。Action 与 Code 共享主历史，双轨迹算子同时共享参考历史和参考程序。

路线质量为：

\[
Q=0.7Q_{\mathrm{endpoint}}+0.3Q_{\mathrm{best}}.
\]

保留路径上的父子变化形成趋势 \(P\)，父代搜索值为 \(0.8Q+0.2P\)，再加入 UCB 进行 softmax 选择。

## 已有观察

- 提高父子趋势权重会增加局部 improve，但可能降低被选父代质量和 global-best 更新。
- 较差 endpoint 的回弹容易得到正趋势，却不代表优质路线继续推进。
- Action 与 Code 的历史不一致会造成决策与实现断层。
- 历史可见不等于模型真实利用；重复失败仍会发生。

## 假设

- H1：质量应先确定值得开发的区域，路线推进信用再分配区域内预算。
- H2：路线最好推进、global-best 贡献和后续子代收益，比普通父子符号更接近长期繁殖价值。
- H3：成果价值、继续开发价值和知识价值需要分开记录。

## 待验证

比较 Q-only、当前 \(Q/P\) 和前沿推进信用。统一报告父代质量、route-best/global-best 更新、后半程推进、访问覆盖和 held-out 结果。
