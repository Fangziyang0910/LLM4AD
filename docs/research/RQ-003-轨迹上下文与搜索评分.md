# RQ-003 轨迹上下文与搜索评分

## 问题

轨迹历史应怎样进入生成，又应怎样决定下一次搜索预算？

## 观察与证据

V5 active 轨迹最多保留 8 个程序节点。历史边包含 Action、Implemented Idea、父子 fitness、结果分类和机械代码变化，不重复历史程序全文。Action 与 Code 共享主历史；双轨迹算子同时共享参考历史和参考程序。

路线质量定义为：

\[
Q=0.7Q_{\mathrm{endpoint}}+0.3Q_{\mathrm{best}}.
\]

保留路径上的父子变化形成趋势 \(P\)。父代搜索值为 \(0.8Q+0.2P\)，随后加入 UCB 进行 softmax 选择。

过程观察包括：提高父子趋势权重会增加局部 improve，但可能降低被选父代质量和 global-best 更新；较差 endpoint 的回弹容易获得正趋势，却不代表优质路线继续推进；Action 与 Code 的历史不一致会造成决策与实现断层；历史可见也不等于模型真实利用，重复失败仍会发生。

## 当前解释

当前机制把上下文传递和预算分配视为两个问题。轨迹上下文负责传递可追溯证据，评分负责在有限资源下分配计算预算；两者不应由同一个粗糙标量替代。长期信用仍待研究。

## 竞争解释

父子趋势可能在某些局部区域确实反映继续搜索的机会，因此增加趋势权重带来的局部 improve 不应直接视为错误。问题在于，较差 endpoint 的回弹也能产生正趋势，单凭该信号无法判断路线是否接近优质前沿；观察到的 global-best 更新下降也可能来自父代质量分布变化，而非趋势指标本身失效。

## 可证伪假设

- **H1**：质量应先确定值得开发的区域，路线推进信用再分配区域内预算。
- **H2**：路线最好推进、global-best 贡献和后续子代收益，比普通父子符号更接近长期繁殖价值。
- **H3**：成果价值、继续开发价值和知识价值需要分开记录。

## 决定与下一步

以优质前沿推进和后续贡献定义路线信用，并比较 Q-only、当前 \(Q/P\) 和前沿推进信用。除最终结果外，统一报告父代质量、route-best/global-best 更新、后半程推进、访问覆盖和 held-out 结果。
