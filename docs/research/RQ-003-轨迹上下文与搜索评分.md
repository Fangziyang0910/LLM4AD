# RQ-003 改进历史如何进入生成与预算分配

> 状态：持续研究中。V9-Core 以下内容保留其历史协议；V9.5 后的当前决定见本文末的
> “生成接口识别实验”。该实验用于识别下一版方向，不是正式论文消融。

## 问题

真实的算法改进历史应怎样进入下一步生成，又应怎样决定下一次搜索预算投向哪里？

这是 TraceAAD 核心主张的直接承载问题，也是 V9-Core 的中心假设：当搜索位置和生成预算保持稳定时，把与当前程序严格匹配的真实改进历史交给模型，能否帮助它做出更有效的下一步修改。

## 观察与证据

### 历史进入生成

V9-Core 只提供 `matched_history`：与当前程序严格对应的形成路径，加上从它出发已测试的直接分支。历史边包含 Action、Implemented Idea、父子 fitness、结果分类和 LOC 变化，不重复历史程序全文。完整单父树保证形成历史始终与当前代码严格对应，不会出现 V5 中 Action 与 Code 历史不一致的断层。

已知的边界：历史可见不等于模型真实利用，重复失败仍会发生。这一点需要历史消融（`current_only`、`shuffled_history`）才能识别，本版代码不提供历史模式开关。

### 预算分配

V5 曾用路线质量 $Q=0.7Q_{\text{endpoint}}+0.3Q_{\text{best}}$ 加父子趋势 $P$，父代搜索值为 $0.8Q+0.2P$ 后 softmax 选择。观察到提高趋势权重会增加局部 improve，但降低被选父代质量和 global-best 更新——普通回弹不推进优质前沿（详见[研究认识 §5](../knowledge/研究认识.md)）。

V9-Core 放弃了这套公式，改为：subtree-best max-backup 提供利用值，经 midrank 百分位归一化以避免离群值敏感；递归 UCT 在每个节点比较"开新分支"（`new_child`）与"下降到已有子节点"（`descend`）；探索项随剩余预算比例衰减。V8.3 的教训是固定深度和高回报 `new_child` 会造成根锁定或 sibling 堆积，V9-Core 因此不采用趋势项、路线信用和概率控制器（[研究认识 §4](../knowledge/研究认识.md)）。

## 当前解释

上下文传递与预算分配是两个问题，不应由同一个粗糙标量替代。历史负责传递可追溯证据，选择负责在有限资源下分配评价预算。V9-Core 的立场是简约：只保留解释核心假设所必需、且已有过程证据支持的机制（[研究认识 §5](../knowledge/研究认识.md)）。

## 可证伪假设

- **H1**（历史主张）：真实匹配的形成路径和已测试分支能提高下一步修改质量。需同骨架历史消融识别。
- **H2**（结构主张）：完整单父树让来时路始终与当前代码严格对应，并保存每次 Idea + Code 生成及其结果。
- **H3**（调度主张）：subtree max-backup 与自适应 `new_child`/`descend` 竞争能在有限预算内有效分配搜索机会。
- **H4**：历史记录的事实与搜索调度使用的评分需要分开，不应把生成上下文等同于单一价值标量。

## 决定与下一步

V9-Core 正式批次（`20260807_123753`）已完成：四任务 × 三重复测试全部收口，十三方法同场平均名次 4.167 首次超过 MCTS-AHD（4.200）居第 1（差异微小：名次差 0.033、P(优于 MCTS)=0.38、CI 高度重叠），单版本口径 1.867 居首；对 MCTS-AHD 整体效应量 +0.05，是首个整体效应量为正的版本。名次细节与机制检验见[版本实验事实与机制诊断](../analysis/TraceAAD-版本实验事实与机制诊断.md) 的 V9 节。

按预期，V9-Core 的联合结果只能检验 H1–H3 的合并效果，且与 V8.2 的对照非单变量（P=0.59 不可分辨），不能识别历史协议本身的因果贡献。

V9-Core 后原计划的关键实验是**同骨架历史消融**：固定树结构、选择机制、算子和预算，只改变提供给模型的历史内容（`matched_history` / `current_only` / `shuffled_history`）。这仍是正式检验 V9-Core 历史包净效果的合理形式；V9.5 审计进一步表明，当前应先用更小的固定-anchor 实验识别信息类型、表达粒度和生成意图，再决定下一版的正式消融。

除最终测试外，统一报告被选父代质量、global-best 更新、后半程推进、扩展点深度分布和访问覆盖。

## V9.5 后的问题重述

V9.5 给出了一个结构清楚的最小基座，但现有数据仍无法分离判断：

1. 历史信息本身是否有用；
2. 历史是否因 actual diff 过长、语义重点分散而难以被 27B 模型利用；
3. 完全自由的生成指令是否让模型同时承担了过多的修改决策。

直接从完整搜索中删除 history 只能检验“这一历史表示与其他当前机制的联合效果”。
它同时改变 prompt 长度、注意力分配、修改粒度和生成难度，不能单独证明“历史有用”
或“历史无用”。因此当前的研究顺序是：

\[
\text{诊断性识别}
\rightarrow
\text{机制改进}
\rightarrow
\text{形成强版本}
\rightarrow
\text{正式系统消融}
\]

这个顺序不是回避消融，而是先确保正式消融比较的是语义完整、内部自洽的系统变体，
而不是把联合机制中的一段 prompt 直接注释掉。

## 生成接口识别实验

### 目标与基本单位

该实验只研究单次 generation interface，不运行完整的 1000-budget search。对同一个真实
anchor 配对构造不同 prompt，固定 task、current code、evaluator、temperature、后端支持时的
random seed、output contract 和生成数量；若后端不保证 seeded deterministic sampling，则对每个
anchor × condition 做对称重复，不把一次样本当成确定性对照。从每个 task 的高、中、低质量区间分层抽取真实 anchor，不只抽
best lineage。

### 第一轮已冻结条件

| 条件 | 模型输入 | 要回答的问题 |
| --- | --- | --- |
| `Code Only` | task + current code + generic instruction | 没有历史时的基础修改能力 |
| `Concise History` | 同一批事件的 Idea + result，必要时带 parent→child fitness | 简洁试错信息是否有增量价值 |

第一轮只比较 `Code Only` 与 `Concise History`。A/B 使用同一批真实 snapshot，共享 Task、
Current Fitness、Current Code、Instruction、Output Contract、temperature 和 sampling seed；唯一系统
差异是 B 的 History block。对每个 pair 保存 canonical components，并自动验证移除 B 的精确
History block 后与 A 逐字相同。

第一轮不加 actual diff、compact change、generation operator 或第三个 history 条件。它先回答“最基础的
Idea + result 试错信息是否值得提供”。只有出现可复现的正信号后，才进入 `Concise History` 对
`Concise History + Compact Actual Change`；若历史信号与生成行为的关系仍不清楚，再单独识别
generation intent。

完整冻结协议和复现入口见 [V9.5 简洁历史生成识别实验](../experiments/TraceAAD-V9.5简洁历史生成识别实验.md)。

### 第一轮结果与当前解释

432 次生成已全部完成。在 69 个可配对 conditional Δq 的 anchor 中，
`Concise History` 方向更好 44 个，`Code Only` 更好 23 个，2 个持平。
CVRP 的 anchor-level Δq 配对差为 +1.185，95% bootstrap interval [0.452, 1.941]；
OP 和 TSP 为正方向但 interval 跨 0，OBP 为负方向且 interval 跨 0。

更稳定的跨任务行为是历史让修改更贴近 current code：CVRP、OP、TSP 的
conditional line-change ratio 均下降，配对 interval 不跨 0；OBP 基本不变。
这说明历史不只是 prompt 中的装饰信息，它改变了实际生成分布；但这种收缩不能直接等同
于更好搜索。TSP valid rate 从 75.9% 降到 59.3%，而 OBP 的 conditional Δq 没有正信号，
因此历史的价值具有 task interaction 和工程代价。
对 TSP 的 28 份原 timeout 候选做空闲顺序复评后，History 有 8/20 恢复有效，
No History 有 3/8 恢复有效，但仍有 12 对 5 份稳定超时。因此并发 CPU 竞争放大了
绝对 invalid 数，但没有消除 History 更容易产生慢候选的相对信号。

当前最窄的结论是：对已累积至少两条局部证据的 anchor，简洁 `Idea + Result +
Fitness transition` 历史有单步生成价值，并倾向把模型导向更保守、更贴近当前代码的修改。
它尚未证明对 fresh anchor、完整搜索或 held-out 表现有益。详细任务结果见实验文档。

第二轮已完成：复用同一批 72 个 anchor，配对比较 `Concise History`
与 `Concise History + Compact Actual Change`，共 432 次生成与评价。Compact change
仅由真实 diff 的行数及少量新增/删除代码例子确定性构成，不使用 raw diff
或 LLM 摘要。

结果表明 actual change 有额外信息价值，但不是通用增益。CVRP 的 anchor-level
conditional \(\Delta q\) 配对差为 +0.237，95% bootstrap interval [0.088, 0.409]，
improvement rate 从 13.9% 升至 33.3%。OP 与 TSP 的总体 \(\Delta q\) 为正方向但区间跨 0，
OBP 的总体方向为负。在 70 个可配对 anchor 中，Compact 更好 39 个、Concise 更好
29 个、2 个持平；因 evaluator 尺度不同，不汇总四任务的原始 \(\Delta q\)。

行为上，Compact 在 CVRP、OP 和 OBP 上都进一步压缩修改比例，TSP 基本不变。
两条件各有 19 个 invalid，无解析失败，因此本轮没有发现总体 valid-rate 代价。
当前将 compact actual change 视为值得继续识别的高信号表示，但不升级为已证明的
四任务默认接口。完整协议和任务结果见
[V9.5 紧凑实际修改识别实验](../experiments/TraceAAD-V9.5紧凑实际修改识别实验.md)。

两轮结果把下一个问题定位在历史上下文本身，而不是 generation intent。对 11,102 次真实生成
时刻的统计显示，锚点周围可用历史通常有 30 到 150 多条、只给 8 条，而 V9.5 现行挑法会让
模型在部分任务上看到远多于真实发生的失败。下一版历史上下文机制已定稿，见
[RQ-009](RQ-009-锚点历史上下文.md)；在它落地验证前不开 generation intent probe。

### 报告指标与解释边界

每个条件至少报告：

- valid rate 与 duplicate rate；
- 相对 parent 的 improvement rate 及定向 \(\Delta q\) 分布；
- 修改尺寸与生成代码多样性；
- prompt token 与 response token。

结果按 task 和 anchor quality stratum 分层，再给整体方向；报告配对差值与分布，不只报平均
improvement rate。修改尺寸是必要诊断：一个条件可能提高单步改善率，同时把生成压缩成
过度保守的局部小修，这对长期发现能力仍是风险。

该 probe 的独立单位是 anchor snapshot，每条件的 3 次采样只是 anchor 内重复。\(\Delta q\) 统一为
\(q_{child}-q_{parent}\)；只在 valid candidate 上报告 conditional \(\Delta q\)。三次全 invalid 时保留缺失，
不填人工 penalty，同时完整报告 valid rate。结论的外推范围只是“已累积至少两条局部证据的
anchor”，不代表 fresh anchor。

该识别实验提供机制方向证据，不直接支持完整搜索质量或泛化性结论。即使 `Concise
History` 提高一步改善，也仍需要将其放回完整搜索，考察 global-best 推进、后半程发现和
held-out 结果。

## 识别后的决策规则

- `Concise History > Code Only`：优先保留 history hypothesis，改进历史表示；
- `Concise History` 有正信号：第二轮比较是否增加 deterministic compact actual change；
- `Concise History` 影响修改行为但没有清晰质量优势：再单独检查极简 generation intent，不因此引入调度器；
- 各 task 异质：先报告 effect structure 与不确定性，不把“未在四任务所有层同时提高”直接定义为 History 无效。

识别完成后才形成下一版机制。下一版应优先收缩为“Current Code + compact high-signal
history + 必要时的 simple generation intent + 最小搜索器”，不根据单个 task 的阶段性表现加
rescue、adaptive `s`、critic、credit 或复杂 operator portfolio。当该版本达到或接近 V9 的整体性能后，
再以内部自洽的 code-only interface、有无 generation intent 和统一生成接口下的 allocation 作为正式消融。
