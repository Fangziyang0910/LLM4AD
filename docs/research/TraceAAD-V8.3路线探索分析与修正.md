# TraceAAD V8.3 路线探索分析与修正

## 1. 事实

正式批次 `v83_20260805_final` 完成了 4 个任务、每个任务 3 个 repeat、每个
repeat 1000 次 evaluator。15 个 held-out 规模的平均名次为：V8 `4.067`、
V8.2 `4.133`、V4 `4.600`、V5 `5.100`、V8.3 `7.667`。V8.3 在 TSP、CVRP 和
OP 上整体落后于已有 TraceAAD 版本，OBP 是相对有竞争力的任务。因此本次问题
不是运行失败，而是搜索正常运行后的路线利用失衡。

过程工件显示，多个 run 几乎锁定一个根分支；例如 CVRP repeat 3、OP repeat 1
和 TSP repeat 2 中，单一根分支分别被选中约 `990/990`、`989/989` 和 `990/990`
次。被锁定的中间节点又反复产生直接 sibling，出现 243、558、629、681 个
直接子节点的节点。搜索形态因此接近“锁定一个根分支后反复横向采样”，而不是
多条路线随访问逐步发展。

## 2. 机制定位

V8.3 的轨迹、单父树、局部上下文和五算子等概率调度仍然按设计运行。本次只
针对 MCTS 的路线探索层。原实现有两个相互作用的问题：

1. `new_child` 被作为一个持续参与价值竞争的动作。它的质量由全树秩、轨迹
   先验和已有直接子代回报组成，成功的 sibling 会使该动作继续获得较高分，因而
   同一个中间节点可以长期垄断扩展。
2. 虚拟根只负责在固定的初始化根节点之间选择，初始化以后不再 progressive
   widening。根分支一旦因早期秩值领先，后续路线很难重新打开。

这不是要求根据轨迹写固定的算子规则，也不改变 crossover 是否互补的假设。它
只是把“路线何时获得新的直接分支”恢复为 MCTS-AHD 的宽度约束，并把同一约束
应用到虚拟根。

## 3. 修正假设

对任意当前节点 `n`，令访问次数为 `N(n)`、直接子代数为 `C(n)`。当

`C(n) < floor(N(n)^alpha)`

时，本轮无条件把 `n` 作为新子代的父节点；宽度达到后才使用 UCT 在已有子代
中继续下降。这样新路线的数量由访问次数渐进增加，而不是由 `new_child` 的
全局秩竞争决定。虚拟根使用同样的平方根宽化，因此搜索预算增加时可以重新
打开新的根路线。参数沿用 MCTS-AHD 的默认平衡：`alpha=0.5`、
`lambda_0=0.1`，其中 V8.3 的 `exploration_constant` 对应 `lambda_0`。

五个算子仍在真正的程序节点扩展时等概率抽取；根宽化沿用初始化语义使用
`e1` 生成新的独立根方案。轨迹上下文、评分中的直接父子改进信用以及双调用
生成协议均保持不变。

## 4. 可证伪的过程预期

修正后的工件应满足：

- 根子节点数量随预算按平方根级别增长，而不是固定为初始化数量；
- 单个中间节点的直接子代数量受 `floor(N^0.5)` 约束，不再出现与访问次数
  同量级的 sibling 爆炸；
- 根分支访问不再长期为单一路线垄断；
- 除路线选择/拓展机制外，算子比例、轨迹上下文和生成协议不发生变化。

这些是搜索过程预测，不预先承诺 fitness 必然提升。新一轮 12 路实验将同时
检查最终 held-out 指标和上述树过程指标。

## 6. 修正后实验

批次 `v83_20260806_pw` 曾启动 12 个独立 run，预算为每个 run 1000 次 evaluator、
初始化根数为 10。2026-08-06 在全部 run 未完成时主动停止。停止原因是过程工件确认
根分支仍然垄断，并发现深度边界会绕过 progressive widening；此外部分任务的模型
端点与旧 V8.3 不一致。该批次只作为失败诊断，不进入正式结果页。后续机制决定见
[TraceAAD V8.3 信用、评分与选择重设计](TraceAAD-V8.3信用评分与选择重设计.md)。
