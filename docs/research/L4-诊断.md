# L4 诊断

> 层次：诊断。状态：持续。入口见 [README](README.md)。程序膨胀的详细记录见 [RQ-001](RQ-001-程序膨胀.md)。

## 当前判断

诊断量用来描述搜索过程、任务差异和成本，不进入任务分数、在线信用或硬拒绝规则。任务差异优先用好簇稀有度、族内可改进性和簇间质量方差来读，而不是用谱系深浅。评价次数、生成成本和 held-out 质量回答不同问题。

## 程序膨胀

程序增长占用当前代码和历史上下文的 token 预算，也增加后续修改难度。代码长度不是算法质量的可靠代理。

跨方法过程分析里，按方法去中心化后，run 级 LOC 与泛化 gap 的相关为 0.05（p=0.60）。现有数据不支持“程序越长越过拟合”。V9-Core 至 V9.7 不使用长度惩罚。完全同分时择简只是确定性 tie-break，不能表述为已验证的抗过拟合机制。

可证伪假设和所需证据留在 RQ-001。任何长度干预只有在最终质量上显示可重复净收益时，才有理由进入在线方法。

## 任务几何

不要把四任务反差写成“TSP/CVRP 适合长轨迹，OP 不适合”。更值得测量的是三个量：[待验证]

- **好簇稀有度**：高质量算法簇是否难以被 LLM 一次提议命中；
- **族内可改进性**：进入某簇后，继续 refine 能否稳定抬高质量；
- **簇间质量方差**：不同簇的上限差距有多大。

正统 V9.7 上目前只观察到过程表象：TSP/CVRP 的成功谱系长；OP 的严格 improve 约 4.8%，搜索增益平均在第 82 次评价达到 90%；OBP 多数差异约 1%。谱系深度与路线塌缩缠在一起，不能直接当成“任务需要深积累”。

工作假设：好簇常见且族内可提升时，深度和 Refine 更有杠杆；好簇稀有但找到后容易提升时，需要先广度再 refine；簇间差距大时自适应路线分配才有对象；所有簇都差时分配救不了；当前簇局部饱和时才需要跨族 Explore；路线高度同质时复杂分配器无意义。这些对照来自 BaSE 的任务依赖性，尚未在本仓库四任务上验证。过程拆解见[机制有效性分析](../analysis/TraceAAD-V9.7机制有效性与任务异质性.md)。

## 评价预算与生成成本

正式比较统一 1000 次真实评价。解析失败、重复、缓存命中和模型调用方式会使 LLM 调用数、token 数和墙钟成本不同。正式性能比较、生成成本和搜索过程不能相互替代。
