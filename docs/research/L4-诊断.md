# L4 诊断

> 层次：诊断。状态：持续。入口见 [README](README.md)。程序膨胀的详细记录见 [RQ-001](RQ-001-程序膨胀.md)。

## 当前判断

诊断量用来描述搜索过程、任务差异和成本，不进入任务分数、在线信用或硬拒绝规则。任务差异优先用好簇稀有度、族内可改进性和簇间质量方差来读，而不是用谱系深浅。评价次数、生成成本和同规模独立测试质量回答不同问题。

## 程序膨胀

程序增长占用当前代码和历史上下文的 token 预算，也增加后续修改难度。代码长度不是算法质量的可靠代理。

跨方法过程分析里，按方法去中心化后，run 级 LOC 与泛化 gap 的相关为 0.05（p=0.60）。现有数据不支持“程序越长越过拟合”。V9-Core 至 V9.7 不使用长度惩罚。完全同分时择简只是确定性 tie-break，不能表述为已验证的抗过拟合机制。

可证伪假设和所需证据留在 RQ-001。任何长度干预只有在最终质量上显示可重复净收益时，才有理由进入在线方法。

## 任务几何

不要把四任务反差写成“TSP/CVRP 适合长轨迹，OP 不适合”。更值得测量的是三个量：[待验证]

- **好簇稀有度**：高质量算法簇是否难以被 LLM 一次提议命中；
- **族内可改进性**：进入某簇后，继续 refine 能否稳定抬高质量；
- **簇间质量方差**：不同簇的上限差距有多大。

V9.7 上已经能读出更具体的过程几何。TSP/CVRP/OP 的路线层很早进入单路线吸收态，但最终最好程序分别有 2/3、3/3、1/3 改变了根的静态机制宏簇，说明算法结构变化主要在线路内部发生。Explore 在 OP 上宏簇切换最多，却有 85.7% 的 child 出生即被锚点分数淘汰，且完整搜索仍落后；这与“提议能移动，但 proposal mass 或存活条件没有进入更好盆地”相容。OBP 的多路线访问首先来自 6–7 个初始最高分并列，不足以证明更强簇异质性。完整数字见[V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md)。

V9.8 需要新增 hypothesis 与逐步分配诊断。在线分数直接读取的量包括当前前沿、operator 响应数、跨边界宽限与历史平均 Refine 发展收益；诊断必须分别报告这些 $Q/U/C/M$ 分量改变选择的次数、边界宽限激活与衰减、Explore child 被后续选中的等待时间和次数，以及 operator 的 response/evaluator 双口径份额。离线另报 Explore validity、代码新颖率与 hypothesis 创建率、Refine/Explore 的真实宏簇切换混淆矩阵、hypothesis-level 与 child-chain 的 0/1/3/5 步 parent recovery、静态/行为 proxy-region revisit，以及 hypothesis 内与 hypothesis 间的质量方差。静态/行为重访只是机制代理，不直接等于 semantic duplication 或无效预算。详见[V9.8 设计稿](../methods/TraceAAD-v9.8完整机制设计.md)。

V9.9 的首轮诊断不进入在线分数。每次选择记录几何秩集中度（选择熵、top-5/10/20 份额、所选秩）、$P(E\mid a)$ 与 $C_R$，以及同代码锚点副本数 $m(x)$、该程序合计 $\mu$、top-10 唯一程序数。这些量用来判断 multiplicity bias 与 $h_A=5$ 是否过激进，本身不构成修正规则。详见[V9.9 设计](../methods/TraceAAD-v9.9完整机制设计.md)第 14 节。

工作假设：好簇常见且族内可提升时，深度和 Refine 更有杠杆；好簇稀有但找到后容易提升时，需要先广度再 refine；簇间差距大时自适应路线分配才有对象；所有簇都差时分配救不了；当前簇局部饱和时才需要跨族 Explore；路线高度同质时复杂分配器无意义。这些对照来自 BaSE 的任务依赖性，尚未在本仓库四任务上验证。过程拆解见[V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md)。

V9.15 的三次重复表明，运行稳定性需要独立记录“观察到入口响应”和“观察后继续发展”。V9.16 固定三步 landing，记录有效步、parent recovery、over-parent、严格改进和最终 gain；这些量只用于过程诊断，不作为在线质量信用。入口是 provenance 单位，不是高质量算法簇标签。运行诊断还包括 landing 激活率、landing 预算占比、可靠性失败后的继续投入比例，以及 best-at-budget 和 held-out 的运行间离散度。

## 评价预算与生成成本

正式比较统一 1000 次真实评价。解析失败、重复、缓存命中和模型调用方式会使 LLM 调用数、token 数和墙钟成本不同。正式性能比较、生成成本和搜索过程不能相互替代。
