# RQ-007 V9.2 如何用锚点化轨迹完成搜索闭环

> 状态：设计问题已收口并完成 V9.2 实现，正式效果尚待实验。完整规范见 [TraceAAD V9.2 完整机制设计](../methods/TraceAAD-v9.2完整机制设计.md)，过程证据见 [V9.2 评分机制数据诊断](../analysis/TraceAAD-V9.2评分机制数据诊断.md)。V9.2 实现后的底层反思与下一版开放问题见 [RQ-008](RQ-008-V9.2底层反思与下一版轨迹闭环.md)。

## 核心问题

V9.1 已把树降为事实结构，却仍用“是否立即超过路线历史最好”分配预算。过程数据表明，这个目标会把低质量锚点的局部回弹当成成功。V9.2 需要回答：

> 能否将当前可执行代码、它的形成历史和附近已测试结果组成一个确定的锚点化上下文，再在可积累的锚点层面用真实生成代码的绝对质量分配预算？

## 关键取舍：取消任意窗口竞赛

早期设计允许同一锚点枚举许多连续 8 节点窗口，并为每个精确 `(a,W)` 独立评分。进一步调查后，这个方案被否定。

原因不是工程复杂，而是统计对象错误：树每增加一个节点，就会产生新的精确窗口；多数窗口只使用一次，几乎没有机会积累可比较结果。窗口越精确，状态表面上越充分，信用样本却越稀疏。DGA²D 的 10 次重复消融中，first-order credit 在四个任务上一致优于 second-order 和 full-path，论文也将长历史退化解释为稀疏、噪声评分。它与现有日志中“轨迹形态权重跨协议变号”的结果共同说明，不能把每条完整历史当成独立价值单元。

因此 V9.2 每个锚点只有一个确定性的规范局部窗口。系统只选择锚点，不再先选锚点、再运行第二个窗口 bandit。锚点是选择与信用单位，轨迹窗口是生成上下文；它会随事实更新，因此不被伪称为可重复抽样的精确 Markov 状态。

## 规范窗口怎样形成

窗口最多包含 8 个真实 `Idea—结果` 事件：

- 形成历史和深度 3 内的近期下游事件各有 4 个优先位置；
- 一侧不足时由另一侧按近期性补足，总数不超过 8。

形成边按因果顺序排列；下游证据按真实发生顺序排列并标明深度和分支，不拼成虚假的线性链。窗口不按 fitness 选最好事件，保留无效与退步。MEMOIR 的同预算消融显示，移除 branch-local memory 的损失最大，删除失败节点也明显退化，这为保留局部失败事实提供了直接依据。

窗口是事实图的派生视图，没有独立价值。新事件只使父锚点、新子代和三代范围内相关祖先的窗口内容重算；窗口变化不追溯改写任何数值信用。新事实不是祖先在新上下文下被再次扩展的样本；祖先只有真正被选中后才更新信用。

## 评分对象与公式

V9.2 评分的是锚点附近改进过程的**经验生产力**：从当前代码出发，在局部历史逐步更新的过程中，已经真实产生了多高质量的代码。这不是当前精确窗口的 Markov action value，而是为了让有限结果能在锚点层面积累。

所有任务使用越大越好的有向原始 fitness `q`，不做全局 min–max。选择锚点 `a` 的第 `i` 次预算结果为：

```text
z_i(a) = q(c_i)    有效子代
z_i(a) = q(a)      无效结果，表示没有产生新质量
```

统一价值为：

```text
Q(a) = [q(a) + Σ_i z_i(a)] / [1 + n(a)]
```

这条公式保留锚点质量为地基，又允许实际生成结果逐步修正它。它使用绝对代码质量，因此差锚点的小幅回弹不会获得虚高信用；一个差锚点若真的生成优秀子代可以得到有限提升，但不会永久继承子代最高值。

信用只更新被选锚点。子代以自身 `q` 形成新锚点，祖先不做 max-backup。精确窗口不单独计分，避免 full-path 信用碎片化。

## 固定预算规则

每轮对全部有效锚点计算 `Q`，取最高的至多 10 个作为质量候选区。区域内尚未获得过一次预算事件的锚点先按 `Q` 从高到低完成基本验证；全部已有证据后，直接选择 `Q` 最高者。

这套规则只有一个价值尺度。它既不使用 UCB/Wilson，也不把趋势、波动、访问数和 fitness 加权。前 10 防止低质量回弹路线吞掉预算；基本验证防止搜索只重复选择第一名。现有过程数据支持这个方向，但 `10` 仍是首版常数而非理论结论。

## 初始化怎样避免差初代

初始化不再以“生成若干根”结束，而以“形成若干短轨迹”结束：

1. 模型根据任务与函数契约一次规划 8 条互补策略，不生成代码、不查看评价结果；
2. 每条策略独立实现一个有效根，根提示不读取其他路线的代码、Idea 或 fitness；
3. 每个根用正式搜索的同一窗口和生成机制获得一次预算事件，形成 8 条两节点微轨迹；
4. 每条路线以根与有效子代中 fitness 更好的程序为代表锚点；
5. 代表锚点按已有 `Q` 排序，选 6 个进入正式搜索。未入选路线仍保存为事实，但不再参与预算选择。

这使初始选择不只依赖未经验证的第一代代码：策略规划保障机制方向覆盖，独立实现避免串行模仿，每条路线至少经历一次 evaluator 反馈后的历史条件化生成，`Q` 又会降低“高根节点却立即生成差代码”的路线价值，同时允许“差根产生强子代”的新锚点直接入选。理想路径使用 16 次 evaluator 预算；策略规划调用不产生候选，单独审计。

## 单一生成机制

每次只生成一个候选：

```text
任务 + 锚点完整代码 + 规范局部窗口
    → 一个 Idea + 一份完整 Code
```

模型从当前可执行锚点和局部证据直接生成唯一的下一个 `Idea + Code`，外部不调度多个语义算子。窗口明示它是有限局部视图，不把某次实现的结果表述为对更广泛 Idea 的因果结论。Idea 必须准确概括实际 Code；它与 evaluator 结果绑定后进入历史，本身不获得数值信用。

Code 只表示实际执行的算法，不承担解释职责。提示词禁止注释、docstring 和被注释掉的替代实现；系统在评价前再用 AST 强制删除这些文本并规范化源码。这样不会把长度当作质量代理，也不会拒绝必要的算法复杂度，只是防止无执行作用的文本消耗输出 token、污染 LOC 和重复进入轨迹上下文。

## 延迟价值怎样表达

V9/V9.1 中深度 3 内存在可观察的延迟挽救，但它只说明失败历史和短程后续值得保留。V9.2 将三代下游事实放入局部窗口；真正出现的优秀后代以自身高 `q` 参加选择。祖先不会因后代成功自动获得同等预算价值。

这一区分同时保留“老鼠生出龙”的历史意义和当前预算的前瞻性：老鼠解释龙如何形成，龙决定下一步从哪份代码出发。

## 为什么不采用其他候选方案

| 候选 | 不采用原因 |
| --- | --- |
| 任意 8 节点窗口分别评分 | exact state 几乎不重复，信用稀疏；长路径信用已有反向消融证据 |
| 按窗口最高后代选代表轨迹 | 后见之明与幸存者偏差；好后代本身已是新锚点 |
| 趋势、波动、改进率线性加权 | 现有三个协议中的方向不稳定，会再次构造代理目标 |
| 路线推进 Wilson | 旧 V9.1 产生大量局部回弹成功，不能代表全局竞争力 |
| UCB、Thompson 或贝叶斯价值 | 引入另一套不确定性模型，掩盖轨迹本身的贡献 |
| 祖先 max-backup | 一次幸运永久抬高整条路径，无法回答重新扩展祖先是否值得 |
| 只增加更多初始化根 | 数量本身没有解决方向重复和初代缺乏评价后历史的问题 |

## 相关工作综合

- **DGA²D**：支持局部上下文信用优于 full-path 信用，决定了“不为精确窗口建分数”。
- **MEMOIR**：支持 branch-local 历史与失败事实，决定了窗口保留无效和退步事件。
- **PathWise**：支持将派生历史作为状态信息，但其多智能体 critic 不进入 V9.2-Core。
- **BaSE**：支持将跨轨迹预算和轨迹内生成分开，但其非平稳 bandit 不移植。
- **MCTS-AHD**：说明绝对代码质量与局部精炼是强基线，同时也提供 V9.2 要避免的 min–max、访问和祖先回传对照。
- **PhyloEvolve / Clade-AHD**：提醒保留谱系与多个方向，但缺少足够独立消融，不据此增加家族层控制器。

## 已确定的最终决定

1. 锚点是唯一选择与信用单位，规范局部轨迹是其生成上下文，树只是事实图。
2. 每个锚点只有一个最多 8 事件的规范局部窗口。
3. 窗口以 4 条形成边和深度 3 内 4 条近期下游事件为优先配额，一侧不足时由另一侧补足。
4. 窗口不按 fitness 挑选，也不独立评分。
5. 锚点价值是锚点分数与该锚点真实生成结果的运行均值。
6. 每次只更新被选锚点，不向祖先回传。
7. 全局按 `Q` 前 10 形成质量区，区域内未验证优先，其后最高 `Q`。
8. 初始化为 8 条独立策略路线，每根一次正式生成，再按代表锚点 `Q` 筛出 6 条进入搜索。
9. 只有一个生成算子、一个候选和一份 evaluator 结果。
10. 趋势、波动、延迟后代只进入事实与诊断，不进入首版数值评分。
11. 所有候选在评价和入图前转换为无注释、无 docstring 的规范可执行源码。

## 可证伪假设

- **H1：**完整规范窗口比 `current_only` 和仅形成历史产生更高质量的下一步代码。
- **H2：**`Q(a)` 比纯 `q(a)` 和 V9.1 路线 Wilson 更好地分配后续预算。
- **H3：**8 条策略微轨迹筛选 6 个锚点，比四个原始根或 8 个未经反馈的根直接竞争改善初始质量下限及后半程推进。
- **H4：**联合 V9.2 在相同 evaluator 预算下减少低质量回弹和第一名过度集中，并提高最终与 held-out 质量。

设计与实现现在已经闭合；尚待实验回答的是这些决定是否有效，而不是机制还缺少定义。
