# RQ-007 V9.2 如何用锚点化轨迹完成搜索闭环

> 状态：历史记录（2026-08-13），记录 V9.2 的设计取舍。V9.2 已完成四任务三重复与 held-out，结局与后续版本对比见[版本谱系与实验事实](../analysis/TraceAAD-版本实验事实与机制诊断.md)的 V9.2–V9.4 节；机制要点见[历史机制探索](../methods/TraceAAD-历史机制探索.md)的 V9.2 节；实现后的底层反思见 [RQ-008](RQ-008-V9.2底层反思与下一版轨迹闭环.md)。

## 问题

能否将当前可执行代码、它的形成历史和附近已测试结果组成一个确定的锚点化上下文，再在可积累的锚点层面用真实生成代码的绝对质量分配预算？

## 保留的核心判断

- **取消任意窗口竞赛**：树每增加一个节点就产生新的精确窗口，多数窗口只使用一次，信用样本随精确度增加而稀疏（DGA²D 的 10 次重复消融中 first-order credit 一致优于 second-order 与 full-path）。锚点是选择与信用单位，轨迹窗口是生成上下文，且随事实更新，不伪称可重复抽样的精确 Markov 状态。
- **窗口保留失败**：事件不按 fitness 挑选，无效与退步保留（MEMOIR 同预算消融显示移除 branch-local memory 损失最大，删除失败节点也明显退化）。
- **经验生产力评分** `Q(a) = [q(a) + Σ z_i] / (1 + n)`：使用绝对代码质量，差锚点的小幅回弹不获得虚高信用；子代以自身 `q` 形成新锚点参选，祖先不做 max-backup。
- **延迟价值区分两种信用**：较差祖先对已发生突破的事后谱系价值，不等于现在重新从它出发的预算价值。前者进入历史与解释，后者由当前证据决定。
- **初始化形成微轨迹而非孤立根**：8 条独立策略路线各完成一次评价反馈后的历史条件化生成，再按代表锚点筛出 6 条；根数只负责候选覆盖，真实反馈负责质量。

## 评分目标的数据依据（2026-08-09 过程快照）

V9、旧 V9.1 与新 V9.1 的 19,191 次预算事件重建（脚本 `experiments/analysis/analyze_v92_scoring.py`，观察性分析，用于排除错误目标而非估计策略收益）给出四个事实：

1. **路线推进制造错误的"成功"。** 旧 V9.1 路线推进率 18.5% 但全局推进率仅 0.5%（推进转化率 2.6%；V9 为 4.4%/3.0%，转化 69.6%）：88.9% 的预算落在当时排名 10 名以外的锚点，差起点只需回到该路线旧水平就得到成功信用。新 V9.1 修正后又出现反向集中——70.3% 预算压在排名第 1 的锚点。因此评分标签不能是"是否超过锚点/路线历史最好/路线推进成功率"。
2. **稳定信号是绝对锚点质量与绝对下游质量。** 以"本次最佳有效子代相对当时全局最优差距"为目标，锚点相对全局差距的逐 run Spearman 中位数在三个协议中为 0.460/0.374/0.152，已测试直接子代最好值为 0.404/0.366/0.153，符号一致；直接用锚点 fitness 预测下一次有效子代质量为 0.527/0.384/0.622。加入固定趋势或简单子代均值未稳定提高。
3. **趋势和波动只能作为上下文事实。** 窗口形态与后续结果的方向跨协议不稳定（波动对路线推进的相关在三协议中约 -0.03/-0.22/+0.17，改进比例对子代质量会变号）：同一形态可能对应优质精炼也可能是差路线回弹，人工权重相加只得到跨任务漂移的代理目标。故形态量在 prompt 中忠实展示、在日志中记录，不进入在线评分。
4. **延迟价值存在，但不支持祖先最高分回传。** 得到后续扩展的事件中，直接未推进但深度 3 内后来超过原路线最好者约占 7%–13%——支持保留完整失败历史，但存在严重选择性随访，不能证明差节点应得高预算；后代本身已成为更好的新锚点，祖先的价值在于形成证据。

## 结局

设计如期运行。后续反思（RQ-008）确认三个结构性缺口：规范窗口是拓扑截断而非决策相关轨迹；一步平均质量与预算终局目标不一致；新锚点以无历史负担的分数重新参选，预算仍沿单一谱系推进。这三个缺口分别推动了 V9.6 的历史重构（[RQ-009](RQ-009-锚点历史上下文.md)）、V9.4 的有限多步信用尝试与 V9.7 的路线级分配（[RQ-003](RQ-003-轨迹上下文与搜索评分.md)）。
