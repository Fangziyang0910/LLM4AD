# RQ-005 LLM 局部改进与受控多样性

状态：已有阶段结论  
当前判断：可靠局部改进应先于多样性扩张；多样性应发生在优质且互补的路线之间。  
下一步：量化局部改进可靠性和路线互补性。

## 问题

LLM 作为进化算子时，怎样同时获得可靠改进和有效多样性？

优秀算子应围绕高质量父代持续产生可归因的小步改进。“小步”指保留已验证结构、围绕明确弱点或新思想修改，不等于限制代码长度。

多样性的价值取决于所在区域。弱路线之间扩大差异容易造成语义漂移；多条优质路线分别积累成功和失败证据后，迁移与重组更可能产生突破。

V5 首轮同时保留了多个轨迹身份，却出现 active endpoint 重复和可执行状态覆盖下降。形式上的多轨迹不等于有效多样性；需要同时观察知识覆盖、当前程序状态覆盖和每单位评价预算形成的新信息。

## 假设

- H1：连续 route-best 推进率能够衡量局部改进可靠性。
- H2：参考路线的质量与互补性共同决定双轨迹操作收益。
- H3：先形成优质局部区域、再增加跨轨迹预算，能改善重复下限和后半程突破。

该问题与 [RQ-004 算子调度](RQ-004-算子调度.md) 共用实验，但关注的是生成行为和搜索区域，而不是预算策略本身。
