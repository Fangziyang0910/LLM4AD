# RQ-005 LLM 局部改进与受控多样性

## 问题

LLM 作为进化算子时，怎样同时获得可靠改进和有效多样性？理想算子应围绕高质量父代频繁产生小步改进，同时保留必要的换向和重组能力。

## 观察与证据

“小步”是希望观察到的搜索行为，不是要求每次生成都满足的硬规则。算法设计中的突破稀疏，退步、平台和较大变化都可能是正常尝试。

多样性的价值取决于任务和搜索状态。现有代码差异、成熟度和短期推进指标不足以可靠证明一条路线是否值得参考。V6 只用参考路线质量形成软采样偏好，不建立差异或成熟资格门槛。

V5 首轮同时保留了多个轨迹身份，却出现 active endpoint 重复和可执行状态覆盖下降。形式上的多轨迹不等于有效多样性；评价时还应观察知识覆盖、当前程序状态覆盖，以及每单位评价预算形成的新信息。

## 当前解释

LLM 应保有利用、探索和使用跨路线参考的自由。搜索机制负责提供历史和软选择偏好，不应依据未经验证的过程代理指标预先封闭搜索空间。V6 的简约轨迹进化协议已实现，正式实验将检验这种自由度是否转化为更好的搜索结果。

## 竞争解释

局部改进和多样性可能需要条件化控制。参考路线质量可能只在特定路线状态或调用条件下提高双轨迹操作收益，代码差异也可能在某些任务中比质量更能反映互补性。另一方面，短期 route-best 推进或许能够诊断局部搜索行为，但这些代理关系目前没有得到最终算法质量的验证。

## 可证伪假设

- **H1**：连续 route-best 推进率可以诊断局部改进行为，但不能替代最终算法质量。
- **H2**：参考路线质量可能影响双轨迹操作收益；当前互补性代理是否有效仍待验证。
- **H3**：状态驱动地改变跨轨迹预算是否优于等概率基线，需要独立消融。

## 决定与下一步

量化严格父子改进、全局 best-so-far 突破、语义步长和双轨迹条件收益，并以最终算法质量判断协议。该问题与 [RQ-004 算子调度](RQ-004-算子调度.md) 共用实验，但关注生成行为和搜索区域，RQ-004 关注预算策略本身。
