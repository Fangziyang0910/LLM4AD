# RQ-005 LLM 局部改进与受控多样性

状态：V6 简约轨迹进化协议已实现，待正式实验
当前判断：LLM 应拥有利用、探索和跨路线参考的自由；搜索机制提供历史与软选择偏好，不用过程代理指标预先封闭搜索空间。
下一步：量化严格父子改进、全局 best-so-far 突破、语义步长和双轨迹条件收益，并以最终算法质量判断协议。

## 问题

LLM 作为进化算子时，怎样同时获得可靠改进和有效多样性？

理想算子能够围绕高质量父代频繁产生小步改进，也保留必要的换向和重组能力。“小步”是希望观察到的搜索行为，不是要求每次生成都满足的硬规则；算法设计突破稀疏，退步、平台和较大变化都可能是正常尝试。

多样性的价值取决于任务和搜索状态，但现有代码差异、成熟度和短期推进指标不能可靠证明一条路线是否值得参考。V6 因此只用参考路线质量形成软采样偏好，不建立差异或成熟资格门槛。

V5 首轮同时保留了多个轨迹身份，却出现 active endpoint 重复和可执行状态覆盖下降。形式上的多轨迹不等于有效多样性；需要同时观察知识覆盖、当前程序状态覆盖和每单位评价预算形成的新信息。

## 假设

- H1：连续 route-best 推进率可以诊断局部改进行为，但不能替代最终算法质量。
- H2：参考路线质量可能影响双轨迹操作收益；当前互补性代理是否有效仍待验证。
- H3：状态驱动地改变跨轨迹预算是否优于等概率基线，需要独立消融。

该问题与 [RQ-004 算子调度](RQ-004-算子调度.md) 共用实验，但关注的是生成行为和搜索区域，而不是预算策略本身。
