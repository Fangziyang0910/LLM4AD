# 跨方法轨迹过程分析（TraceAAD v4–v6 与五个基线）

## 一、研究问题

本报告比较 TraceAAD v4–v6 与 `mcts_ahd`、`eoh`、`reevo`、`shinka_evo`、`pathwise` 的搜索过程。问题有三项：

1. 哪些过程指标与全局 best-so-far 的推进和最终任务内表现相联系？
2. TraceAAD 的局部精炼、代码变化和轨迹过程是否与外部方法呈现不同模式？
3. 这些过程信号能否支持关于路线利用、探索和停滞的机制解释？

本报告是与 [TraceAAD v4–v6 轨迹过程分析](TraceAAD-v4-v6-轨迹过程分析.md) 同口径的跨方法扩展。结果是描述性和关联性证据，不构成过程指标的因果验证。

## 二、证据与协议

### 2.1 数据来源

分析脚本为 [experiments/analysis/analyze_cross_method_process.py](../../experiments/analysis/analyze_cross_method_process.py)。数据日期为 2026-08-02，包含 96 个已完成 run（8 方法 × 4 任务 × 3 重复），原始文件为 `docs/research/cross_method_analysis/run_metrics.csv`。纳入的方法是 `version4`、`version5`、`version6`（TraceAAD v4/v5/v6）、`mcts_ahd`、`eoh`、`reevo`、`shinka_evo`、`pathwise`；任务是 `tsp_construct`、`cvrp_aco`、`op_aco`、`online_bin_packing`。

排除了 smoke run、PathWise 旧 500 样本协议（只用 `fair1000` 批次）和 `_eval_proxy`。EoH 的 OBP run 为 2040 次评估，保留全部样本并在结果中注明。模型统一为 Qwen3.6-27B（NVFP4），temperature 1.0；同任务内评估配置一致。部分 run 目录带 `retry2/retry4/retry7`，表示初始批次失败后重跑，过程指标含有重试影响。

### 2.2 指标与重建

| 指标 | 本分析定义 | 可用方法 |
| --- | --- | --- |
| 突破率 | 样本级全局 best-so-far 严格更新；10 样本窗口为单位（所有方法统一） | 全部 |
| LRR | 父子边中 `child.score > parent.score` 的比例 | TraceAAD、MCTS-AHD、ShinkaEvo、PathWise |
| PCD | 父子程序代码的 token Jaccard 距离 | 同上 |
| 新颖性 | 相对全部先前候选的最近代码距离，逐 run min-max 归一化 | 全部 |
| H_spatial / H_fitness | 10 样本窗口内高斯核熵 | 全部 |
| 窗口回归 | 窗口级 OLS + 任务/方法固定效应 + run 聚类稳健标准误（并发与滞后） | 全部 |

父子关系来自以下事件或文件：TraceAAD 使用 `child_accepted`（code_hash / profiler 顺序）；MCTS-AHD 使用 `expand` 事件（父样本按 `parent_score` 匹配）；ShinkaEvo 使用 `archive_update`（program_id→样本）和 `patch_attempt`；PathWise 使用 `population/pop_*.json`（node_id→function）与 `pathwise/entailment_steps.jsonl`。EoH/ReEvo 日志没有父子记录，因此 LRR/PCD 不可用。

本报告和 [TraceAAD 专项报告](TraceAAD-v4-v6-轨迹过程分析.md) 都按样本顺序统一重建全局 best-so-far 严格更新。旧口径下 v5 的 0.241 来自 `best_updated` 事件，其中混入了大量“适应度持平但代码更短”的更新；这些事件仅作日志审计，不计为突破。

### 4.6 run 级回归（有父子日志的 72 个 run）

因变量：任务内 z-score 的最终分数；自变量：LRR、PCD、突破率、平均新颖性 + 任务/方法固定效应，run 聚类。R²=0.723。

| 变量 | coef | p |
| --- | --- | --- |
| 突破率 | **+0.425** | <0.001 |
| PCD | +0.254 | 0.333 |
| LRR | -0.083 | 0.517 |
| 平均新颖性 | -0.073 | 0.787 |
| shinka_evo（相对 mcts_ahd） | **-1.905** | <0.001 |

**观察。** 突破率是唯一稳健正相关的过程预测因子，这一方向与论文一致；LRR、PCD 和平均新颖性均不显著。回归先在任务内对最终分数与过程描述子做 z-score，避免原始分数尺度主导结果。该结果仍是 run 级关联，不能识别产生突破的具体机制。

## 五、机制解释

### 5.1 由结果直接支持的判断

1. 历史过程批次中，TraceAAD V4 的全局突破率最高；正式 held-out 排名则由 MCTS-AHD 总体领先，V5 是最强 TraceAAD。突破率是过程预测信号，不能替代方法综合排名。
2. 三个基线的 LRR 是 TraceAAD 的 2–3 倍，但其突破率与性能更低。高父子精炼率不等同于高全局进展，ShinkaEvo 是局部改进频繁而全局推进停滞的案例。
3. 统一口径后，v5 的突破率低于 v4（0.151 vs 0.166）。此前“v5 突破更多”的印象来自把 `best_updated` 中的等分简化计为突破。
4. 在 TraceAAD 内，v6 呈现“大步长 + 低精炼可靠性”：PCD 0.151、LRR 0.104、regress 占比最高。其 PCD 在跨方法比较中并不极端，因此该关系目前只支持版本内部的步长与可靠性权衡。
5. OBP 在多种方法上出现零突破重复。TraceAAD 也在该任务上明显减速，但没有归零。

### 5.2 待验证的机制推断

全局 best-so-far 更新频率值得继续作为过程目标，因为它在 run 级回归中与最终分数稳定正相关。V5 的正式优势同时表明，突破在任务间的收益分布和局部可靠性也会影响 held-out 结果。MCTS-AHD 的结果与另一种解释相容：更集中的路线预算可能在不提高突破率的情况下改善最终泛化。现有数据没有直接测量这一因果链，后续实验需要共同报告突破、LRR、路线覆盖和 held-out。

## 六、局限与替代解释

- 语义距离使用代码 token Jaccard 代理；窗口=10 样本是“代”的代理；窗口熵接近上界。
- LRR/PCD 只覆盖被接受节点，而且各方法对“接受”的定义并不完全一致。PathWise 的边数较少，均值为 83 条。
- EoH/ReEvo 没有父子日志，因而缺失 LRR/PCD。
- 每种方法只有 3 重复。方法机制与 LLM 调用预算相互混杂，MCTS 约为 2.06 calls/sample，TraceAAD 约为 1.49。
- v4 的 `llm_calls` 在 cvrp/tsp 中计数不可靠。
- Shinka/ReEvo 的部分 run 经过失败重试，过程指标包含重试影响。重试造成的差异是停滞结果的一种替代解释。
- 回归的 R² 和指标构造限制了预测范围。严格突破率的正相关不能证明某一控制机制造成最终改进。

## 七、决定与下一步实验

后续比较继续同时报告 held-out 结果和过程指标，不用 LRR、新颖性或单一熵指标替代最终性能。实验按以下优先级进行：

1. 统一按 LLM 调用窗口（如每 100 calls）重算突破率与窗口回归，消除 calls/sample 差异；
2. 给 EoH/ReEvo 的后续 run 补父子记录（prompt 中的 parents 已存在，可事后解析），补 LRR/PCD；
3. 对程序类任务实现行为距离（固定探针执行），替换代码距离代理；
4. 针对 OBP 停滞单独做轨迹分析（比较零突破 run 的种群与成功 run）；
5. 补零样本基线，把“基础能力 vs 过程能力”维度加入跨方法比较。
