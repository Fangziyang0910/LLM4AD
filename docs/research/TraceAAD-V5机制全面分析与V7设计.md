# TraceAAD V5 机制全面分析与 V7 设计

## 一、研究问题

V5 是当前综合表现最好的 TraceAAD 版本，但 MCTS-AHD 在当前八方法比较中总体领先。本分析回答三个问题：

1. V5 的跨任务竞争力由哪些已观察到的机制行为支撑？
2. 哪些状态管理和预算分配问题限制了 V5？
3. V7 应以哪些最小改动检验这些问题，同时避免引入缺少证据的控制层？

分析区分三类对象。轨迹历史是需要完整保存的知识事实；endpoint 程序是占用繁衍预算的当前可执行状态；路线价值是决定下一次 evaluator 预算投向的暂时估计。V5 保留了有价值的历史，但没有在 active frontier 中充分区分这三类对象。

## 二、证据与协议

### 2.1 证据范围

V5 审计、V7 设计与实现，以及正式 V7 性能实验均已完成。本文关于 V7 机制设计的
论述仍按可检验假设组织；held-out 结果以[实验总汇](../results/实验总汇.md)为准。
分析使用四类材料：

- 正式结果：[跨任务实验总汇](../results/实验总汇.md)，8 方法、4 个任务、
  14 个 held-out 规模，每种方法 3 次运行；
- TraceAAD 过程结果：[V4–V6 轨迹过程分析](TraceAAD-v4-v6-轨迹过程分析.md)，
  36 个完成 run；
- 跨方法过程结果：[跨方法轨迹过程分析](跨方法轨迹过程分析.md)，96 个完成
  run；
- 机制与开发事实：[TraceAAD 版本机制诊断](TraceAAD版本机制诊断.md)和 V5/V6
  开发复盘。

判断采用以下口径：

| 层次 | 本文怎样使用 |
| --- | --- |
| 实验事实 | 已完成 run 的 held-out、日志和工件可直接复核 |
| 机制事实 | 当前方法实际保存、选择、生成和更新什么 |
| 机制解释 | 用因果链解释事实，需要与替代解释同时保留 |
| 设计假设 | V7 预期改善什么，必须由新实验验证 |

过程指标不替代最终 held-out 结果。跨方法 run 级回归中，严格突破率是唯一稳定正相关信号
（系数 +0.425，`p<0.001`）；LRR、PCD 和平均新颖性都不显著。MCTS-AHD 的
LRR 为 0.249，V5 为 0.136，但 MCTS-AHD 的严格突破率 0.113 低于 V5 的
0.151。这些结果与 MCTS-AHD 更强的路线复用和预算集中相容，但不能由高 LRR
单独推出机制优越性。

### 2.2 成本与比较边界

MCTS-AHD 平均约 2.06 次 LLM 调用/评估，
V5/V6 约 1.49 次。正式 evaluator 预算相同，但模型调用预算不同；MCTS-AHD
的领先包含搜索控制与额外模型调用的共同影响。

## 三、观察结果

正式 14 个 held-out 规模中，MCTS-AHD 的八方法平均名次为 2.536，排名第一。只保留一个 TraceAAD 版本与五个外部基线比较时，V5 的平均名次为 2.143，是最强 TraceAAD，也是最接近 MCTS-AHD 的 TraceAAD 版本。由于两种排名对应的方法集合不同，这两个数值不能直接互相比较。

### 3.1 正式 held-out

| 任务 | V5 结果 | 相对 MCTS-AHD |
| --- | --- | --- |
| TSP50/100/200 ↓ | 6.187 / 8.569 / 12.047 | 三个尺度均优于 MCTS-AHD |
| CVRP50/100 ↓ | 9.039 / 15.428 | 两个尺度均弱于 MCTS-AHD |
| OP50/100/200 ↑ | 15.112 / 30.711 / 55.793 | OP100/200 更优，OP50 略弱 |
| OBP 1k/5k/10k, C=100 ↓ | 415.467 / 2050.133 / 4093.400 | 三个尺度均弱 |
| OBP 1k/5k/10k, C=500 ↓ | 81.200 / 403.600 / 805.533 | 三个尺度均弱 |

V5 在 14 个规模中直接胜过 MCTS-AHD 5 个：TSP 三个尺度和 OP100/200；
MCTS-AHD 胜 9 个，差距集中在 CVRP 和 OBP。V7 若要总体超过 MCTS-AHD，首要
目标是减少 CVRP 的稳定构造差距和 OBP 的重复状态/停滞，同时保持 TSP 与 OP
的已有优势。继续改善已经领先的 OP 大尺度，对总体差距的贡献较小。

### 3.2 过程表现

| 指标 | V4 | V5 | 历史质量门控 V6 | 对 V5 的含义 |
| --- | ---: | ---: | ---: | --- |
| 严格突破窗口率 | **0.166** | 0.151 | 0.145 | V5 不是靠更多严格突破胜出 |
| LRR | 0.116 | **0.136** | 0.104 | TraceAAD 内局部 proposal 最可靠 |
| PCD | 0.086 | 0.085 | **0.151** | V5 保持了较小变化步长 |
| regress | 68.4% | **61.6%** | 74.0% | V5 的失败比例最低，但仍很高 |
| 首次严格突破窗口 | **2.9** | 10.5 | 9.6 | V5 启动较慢 |

**观察。** V5 的优势表现为跨任务折中。它的父子改进比 V4 更可靠，但严格突破率
更低；相对质量门控 V6，其过程更稳定。现有指标没有直接测量是否形成了
MCTS-AHD 式的路线预算集中。

## 四、机制解释

本分析把一次昂贵 evaluator 调用的研究价值定义为至少产生一种新信息：得到更好的
可执行程序、排除一个与当前状态匹配的方向、确认一个机制可稳定延续，或建立
一个此前不存在的可执行状态。轨迹的作用是让这些信息保留适用条件，使下一步
生成知道“从什么程序、经过什么尝试、得到什么结果”。

V5 的完整因果链是：

```text
30 个初始程序
  -> 选择一条主轨迹
  -> 在 endpoint / compact best 中选唯一结构父代
  -> 选择 ideate/refine/synthesize/transfer
  -> 可选地读取另一条轨迹作为知识参考
  -> Action 根据历史决定改什么
  -> Code 在同一历史条件下实现修改
  -> evaluator 给出唯一真实质量信号
  -> 新节点和单父边写入事实图
  -> Q/P/UCB 决定路线继续机会
  -> 60 条 active 路线收缩为 30 条
```

在这条机制链中，LLM 提出算法变化，evaluator 提供质量信号，控制器维护事实、
状态不变量和预算。V5 的多数控制规则职责明确，但 active 生存同时受到轨迹身份、
可执行状态和弱多样性代理影响。后者是本分析提出的主要机制风险。

## 五、分机制结果与解释

### 5.1 搜索状态、轨迹与历史

| 机制 | 做得好的地方 | 做得不好的地方 | V7 决定 |
| --- | --- | --- | --- |
| 严格单父派生森林 | 子程序只连接实际被修改的主锚点，因果路径清楚；参考轨迹不会被伪装成第二结构父代 | 同一程序可沿不同历史重复形成多条 active 路线 | 保留单父事实图；分离事实身份与 active 状态身份 |
| 最长 8 节点轨迹 | 控制 prompt 长度，保留近期来时路；完整图仍可审计 | 长期失败知识在截断或归档后不再参与生成；长度 8 未消融 | 保留 8，暂不增加长期记忆层 |
| endpoint + compact best | endpoint 支持连续发展，compact best 允许从路线最好位置回退再试 | 固定 50/50 未证明最优；同一程序可能同时是多条路线锚点 | 保留，先修复状态重复再调锚点比例 |
| 时间顺序的 Requested change/结果历史 | 历史与当前程序严格匹配，失败和平台可作为具体实现的测试记录 | fitness 结果标签不能说明失败原因；模型自述 Idea 可能与代码漂移 | 只向 Prompt 提供请求修改、结果、路线推进和 breakthrough |
| 归档路线保留事实 | 不丢失实验审计和来时路 | 归档事实不再检索，失败经验不能跨路线复用 | 保留；现有全局摘要证据不足，不恢复 |

**观察。** V5 把历史作为条件化生成上下文。V5.1/V5.2 的全局摘要出现过 fitness
方向错误、局部常数泛化和过早饱和判断；所有路线共同读取同一摘要，因而共享这些
错误。V5.3 删除在线全局经验后成为正式 V5。

**解释。** 上述现象支持优先使用局部、可追溯的参考，但尚未单独证明删除摘要造成
了性能改善。V5 仍把不同历史直接映射为不同繁衍状态。历史差异需要保存；当两个
endpoint 完全相同时，当前可执行父代状态相同，重复 active 席位会重复计算访问、
UCB、参考和生存预算。

### 5.2 四个语义算子

| 算子 | 价值 | 已知风险 | 判断 |
| --- | --- | --- | --- |
| `trace_ideate` | 根据已测试边界换一个算法方向，提供结构性变化 | “新方向”仍可能只是表面重写；没有单算子消融 | 保留强历史约束 |
| `trace_refine` | 对已显示价值的机制做聚焦修改，支持 V5 较高 LRR | 局部 improve 不等于全局或 held-out 进展 | 保留，不能单独优化 LRR |
| `trace_synthesize` | 让两条路线的受支持原则在主程序内发生功能交互 | 组合是否互补由 LLM 判断，Q 高不保证可组合 | 保留，参考只提供知识 |
| `trace_transfer` | 保持主结构，仅迁移一个参考思想 | 父子同代码率 16.8%–24.9%，后半程最高 35.3% | 保留语义；参考选择排除与主锚点相同的 executable state |

**观察。** V5.0 最强 TSP 路径包含 13 次 synthesize、5 次 transfer，CVRP 恢复
路径也大量使用；正式 V5 在 OP100/200 领先。这些路径证据说明双轨迹操作能够
产生最终保留的候选，但不能证明其独立贡献。

**设计解释。** 重复风险不足以支持删除全部跨轨迹操作。更小且可检验的修复是阻止
重复程序继续占用繁衍席位，同时不使用代码/Idea/path Jaccard 硬门槛预判思想互补。

四算子等概率提供可解释的基础覆盖，但不保证 evaluator 预算公平。格式通过率、
参考质量和父子同代码率不同，会让每种算子的有效信息产出不同。当前数据不足以
稳定估计算子长期信用；V3 的算子 UCB 同时受到算子能力和被分配状态难度影响。
V7 因此保持等概率，把算子自适应留给后续单变量实验。

### 5.3 Action、Code 与候选供给

| 机制 | 优点 | 缺点 | V7 决定 |
| --- | --- | --- | --- |
| 自然语言 Action | V5.1 删除五字段 schema 后恢复候选供给；避免模型同时做算法设计和审计填表 | 仍可能生成模糊或同义 Action | 保留两条编号 Action |
| Action/Code 两阶段 | 分离“改什么”和“怎样实现” | 多一次模型调用；阶段间可能信息丢失 | 保留 |
| Action/Code 职责分离 | Action 用轨迹决定改什么，Code 用当前程序执行已选修改 | Action 与 Code 之间需要自包含的具体修改 | 保留两阶段；Code 不重复完整历史 |
| 每父代两个 sibling | 用同一事实条件获得低成本 proposal 多样性 | sibling 数 2 未消融；V5 批内状态更新可能带来顺序语义 | 保留 2；采用 V6 批次冻结 |
| 模板执行契约 | 修复 imports/helper/OBP dtype 等假性搜索空间收缩 | 属于实现正确性，不是性能机制 | 保留 |

**观察。** V5.0 的结构化 Action 在 12,949 次调用中有 39.9% 无合法 Action，
只有 30.1% 得到两条。proposal 供给因此构成机制比较的前提。V7 保留自然语言
Action，并通过日志中的 prompt、response、解析、评价和边事实支持审计。

### 5.4 路线评分与预算分配

V5 的质量和趋势为：

\[
Q_i=0.7Q_{endpoint,i}+0.3Q_{best,i},\qquad
V_i=0.8Q_i+0.2P_i.
\]

| 机制 | 优点 | 缺点 | V7 决定 |
| --- | --- | --- | --- |
| endpoint/best 百分位 Q | 与任务尺度无关；同时表示当前状态和历史成果 | active 内相对排名随重复状态改变；Q 不等于未来潜力 | 保留，先精确去重 |
| 小权重趋势 P | 给近期仍推进路线少量机会；比多维信用低耦合 | 回弹也可记正趋势；LRR 不是最终价值；没有 Q-only 消融 | 保留 0.2，不扩大权重 |
| 静态 UCB | 保护低访问路线，职责只在父代选择 | 搜索末期仍持续探索；重复 endpoint 各自得到探索奖励 | 改为剩余预算衰减 UCB |
| Q-softmax 参考 | 偏向已有成果且不设硬门槛 | 高 Q 参考可能相似、饱和或不可迁移 | 保留，重复结果由状态去重处理 |

V5.4 把趋势恢复到 V4 的 `0.6Q+0.4P` 并强化局部提示后，TSP/CVRP/OBP 均
退化。由于评分与提示同时改变，该结果支持系统交互解释，不能识别公式的独立效应。
V7 保留正式 V5 使用的 `0.8Q+0.2P`，只改变探索系数的时间结构。

### 5.5 种群与生存

| 机制 | 优点 | 缺点 | V7 决定 |
| --- | --- | --- | --- |
| 30 个初始路线 | 提供多个可执行起点，降低早期偶然性 | 初始 30 未单独消融；重复程序会降低真实覆盖 | 建立 30 个唯一 active endpoint；重复事实归档 |
| 30→60→30 | 新路线先获得机会，避免即时淘汰 | 很多路线在收缩前仍未被选择；60 不是试用保证 | 保留 |
| global-best route | 最好程序保持可继续开发 | 若 route identity 重复，best 归属可能不稳定 | 保留等价可执行 best 路线 |
| 质量精英 | 防止随机生存丢掉成果 | 精英之间可能是重复状态 | 保留 3 个，先做精确去重 |
| 语义差异 reserve | 试图保护不同路线 | token/Idea/path 差异不等于行为互补，构造效度不足 | 删除 |
| Q/P softmax 生存 | 为非精英路线保留概率性机会 | 代理仍可能偏向饱和路线 | 保留 |
| 无 endpoint 去重 | 保留同程序的不同历史身份 | 唯一 endpoint 仅 52%–80%，明确浪费 active 席位 | 修复为 active 不变量 |

**观察。** 正式 V6 删除精确 endpoint 去重后，OBP 两个零突破 run 最终只有 35/56、
29/57 个唯一 endpoint；held-out 的 C=100 三个尺度全面退化。质量门控 V6
虽然整体没有超过 V5，但其 OBP active 唯一率达到 45/45、49/53、54/54。
这些结果不能证明去重会提高最终分数，但直接说明精确去重能够维持 executable
state 唯一性。该确定性不变量与基于相似度的多样性质量判断属于不同机制。

### 5.6 复杂度、可靠性与可复现性

V5 只在 fitness 完全相同时选择非空 LOC 更少的程序。该规则保留了 fitness
主导权，也显著减轻 V4 的程序膨胀；V4 TSP 晚/早 LOC 平均增长 3.52 倍，
CVRP 为 3.64 倍。它只能决定保留哪个等分程序，不能阻止生成端持续加入无收益
逻辑。V7 保留同分择简，不引入连续复杂度惩罚或 simplify 算子。

V5 的运行协议仍弱于 V6，缺少明确 context hard limit、双轨迹溢出回退、批次
冻结、完整 transport/parse/eval 失败分类、NaN/Inf 拒绝和严格 runtime identity
恢复校验。这些机制不直接产生更好算法，但能保证搜索状态和实验事实可信。V7
完整继承这些护栏。

## 六、V7 设计决定

V7 采用最小充分机制原则：保留职责明确且中介可观察的机制；状态唯一性等可直接
判定的问题使用确定性不变量；缺少构造效度的代理暂不控制搜索预算。

### 6.1 V7 保留

- 严格轨迹历史和单结构父代；
- 四个有分工的语义算子及其 V5 强约束；
- Action/Code 两阶段和职责分离的主/参考上下文；
- 双轨迹直接参考，参考只提供知识；
- `Q=0.7 endpoint+0.3 best`、`V=0.8Q+0.2P`；
- endpoint/compact-best 锚点；
- 30 个起点、60 触发、收缩到 30；
- global-best route、质量精英和 Q/P softmax 生存；
- fitness 优先、完全同分择简。

### 6.2 V7 新增或替换

1. **精确 executable-state 去重。** `code_hash` 相同的程序可以保留多条事实
   历史，但 active frontier 只能保留一条代表路线。
2. **预算衰减 UCB。** 探索系数乘以剩余评估预算比例；早期覆盖，后期集中。
3. **删除语义差异 reserve。** 不再用表面代码/路径差异代理功能互补。
4. **V6 协议护栏。** 批次冻结、context 上限与回退、有限值校验、失败分类、
   checkpoint 配置和 runtime identity 校验。

### 6.4 正式 V7 前的修复复盘

对照“轨迹保存来时路并指导下一步”的初衷，早期 V7 草案仍有三处机制断裂：从内部
compact-best 分支会丢掉锚点之后的失败尝试；路线趋势使用未截断路径计算；fitness
相同但更短的程序只在全局比较器中生效，未进入 parent、route 和 context 反馈。

正式 V7 采用三个最小修复：

- 轨迹增加有界 `evidence_edge_ids`。它携带内部锚点之后的旧尝试，供后续 Action
  context 读取，但不伪造结构父代，也不改变 active endpoint 去重。
- route-best 的 before 状态与 child 生成后实际保留的 bounded prefix 使用同一集合，
  避免路径截断制造虚假的退步或进步。
- 统一 comparator-aware outcome：严格 fitness 改善、同分择短、平台和退步在
  parent outcome、route-best reason、global-best reason 与趋势中保持一致。LOC 仍只
  是同分 tie-break，不成为连续复杂度奖励。

协议因此定为 `traceaad-v7` / checkpoint schema 11。该修复只恢复轨迹事实的连续
可见性和反馈语义，不引入全局经验总结、语义记忆或额外控制器；archive 知识检索
和独立轨迹知识价值仍需后续消融验证。

### 6.3 暂不加入的机制

| 候选机制 | 不加入的原因 |
| --- | --- |
| 全局自然语言经验/反思 | V5.1/V5.2 已出现共享错误偏置；适用边界不可追溯 |
| Elo、多维信用、成熟度 | 同一代理跨父代、参考、算子和生存层控制预算，耦合过高 |
| 语义相似度硬门槛 | 代码/Idea/path Jaccard 不能证明功能重复或互补 |
| MCTS max-backprop | 把后代最好值归给全部祖先，无法分离父代和具体修改贡献 |
| 完整 MCTS 树/渐进扩展 | 可能有效，但与 endpoint 去重和动态 UCB 同时加入会失去因果可辨识性 |
| 代码后额外 LLM 总结 | MCTS-AHD 的记录更对齐代码，但会把调用成本从约 1.49 推向 2+ |
| 连续复杂度惩罚 | LOC 与不同任务 fitness 没有统一交换尺度 |

## 七、相关方法提供的设计依据

| 来源 | 有效认识 | V7 的采纳方式 |
| --- | --- | --- |
| V4 | 主轨迹简单、严格突破率高、早期启动快 | 保留单轨迹 ideate/refine 和直接历史；不恢复无复杂度控制 |
| V5 | 当前最强 TraceAAD，OP 大尺度与跨任务折中最好 | 作为 V7 主体，不重写完整搜索范式 |
| 质量门控 V6 | 精确 endpoint 去重有效维护状态唯一 | 只采纳确定性去重，不采纳成熟度和差异代理 |
| 正式 V6 | 简单控制器和完整运行协议 | 采纳协议护栏；不采纳 Q-only、弱算子提示和无去重 |
| MCTS-AHD | 总体第一；预算集中、剩余预算衰减探索、局部开发可靠 | 采纳预算衰减 UCB；暂不复制完整树和 max-backprop |
| PathWise | LRR 0.334，说明可靠小步有价值 | 保留 evidence-grounded refine；不把高 LRR 当最终目标 |
| ShinkaEvolve | 多策略和大步长仍可能零突破 | 不增加策略层，只记录算子真实产出 |
| EoH | 简单多类生成操作仍有竞争力 | 保持四算子可解释、等概率基线 |
| ReEvo | 交叉和反思本身没有形成总体领先 | 保留直接参考，拒绝无条件反思摘要 |

MCTS-AHD 提供的直接设计依据是预算原则。渐进扩展和 max-backprop 也可能带来
收益，但会与当前修改共同影响结果。V7 因此先检验“唯一 executable state +
动态探索压力”这一较小组合。

## 八、局限与替代解释

1. V5、质量门控 V6、正式 V6 和 V7 改变了多个机制。联合版本结果只能约束解释范围，不能识别单项机制的因果效应。
2. 精确去重直接改善 active 状态唯一性，但尚无证据表明它必然提高 held-out。相同 endpoint 的不同历史也可能提供不同生成条件，这是去重收益不成立时的主要替代解释。
3. `code_hash` 只识别完全相同的程序。代码不同的候选可能行为相同，代码相同的 endpoint 也可能在不同历史下诱导不同后续修改。
4. 删除语义 reserve 可能使代码状态保持唯一而行为多样性下降。若出现这种结果，应检验行为级 reserve，而不能由表面相似度直接推断功能互补。
5. MCTS-AHD 的优势同时包含搜索机制和额外 LLM 调用。渐进扩展、局部算子分层、max-backprop 或额外对齐调用都可能解释 V7 仍未缩小的差距。
6. 当前过程指标只提供代理证据。严格突破、LRR、PCD 和新颖性都不能替代完整 held-out 结果。

## 九、V7 的可证伪假设

### H1：active 去重提高真实路线覆盖

- 预测：active unique endpoint 始终为 100%；同样 evaluator 预算下，父代唯一
  code 数和新 executable state 数高于 V5。
- 反证：唯一率提高，但严格突破、held-out 和状态覆盖均不改善，说明 V5 的重复
  历史可能提供了有价值的不同生成条件。

### H2：预算衰减 UCB 改善后半程预算集中

- 预测：后半程父代概率熵下降，高 Q/V 路线访问占比上升，后半程严格突破不低于
  V5，CVRP 和 OBP 稳定性改善。
- 反证：早期路线偶然优势被过度放大，重复间方差上升或错过后发路线。

### H3：删除语义 reserve 不损害功能多样性

- 预测：精确状态覆盖保持或上升，行为多样性与 held-out 不下降。
- 反证：代码唯一但行为快速收缩，说明需要行为级 reserve，而非恢复表面相似度。

### H4：V7 能缩小并反转对 MCTS-AHD 的差距

- 预测：保持 TSP/OP 优势，并在 CVRP 或 OBP 至少形成足以反转总体平均名次的
  改善。
- 反证：只改善 active 唯一率而不改善 held-out，说明主要差距来自渐进扩展、
  局部算子分层或额外 LLM 对齐调用。

## 十、实验计划与停止条件

### 10.1 实现前验证（已完成）

- 重复初始化/重复子代不占多个 active 席位；
- 重复子代的节点和边仍保留在事实图；
- UCB 探索差随剩余预算下降；
- P 进入调度，但不改变 evaluator fitness 比较；
- sibling 的 global-best 标记与生成顺序无关；
- transport、parse、eval 失败不进入图；
- checkpoint 恢复趋势、scalar value 和 active 唯一性。

实现审计后补充并修正了四个状态约束：UCB 的 $N$ 固定为全局批次选择计数，
不随 active 路线归档回退；初始化停滞同时覆盖评估失败和重复 executable state；
初始化阶段退出后 checkpoint 明确标记为完成，恢复不会重复初始化；双轨迹上下文
超限由调用方显式选择单轨迹回退，避免同一 fallback 被隐式构造两次。图层现在
只接受有限 fitness 节点，四个语义算子用不可变数据值表达，删除了不改变行为的
空壳类和薄包装。

checkpoint 原子写入与身份校验、context hard limit、transport/parse/eval 失败
分类、批次冻结和有限值校验继续保留。它们不参与路线智能调度，却决定中断恢复
是否等价、失败是否污染搜索状态以及实验能否复现，因此属于科研协议本身，不是
可删除的通用工程层。正式 V7 批次 `v7_20260804_001931`（协议 `traceaad-v7` /
checkpoint schema 11）已完成四任务 × 三重复训练与 held-out，并写入结果总汇。

### 10.2 最小冒烟

每个任务先运行足以跨过初始化和一次 population management 的小预算冒烟，检查：

- 模型调用、Action/Code 解析和 evaluator 方向正确；
- 分数有区分度且出现路线更新；
- `active_unique_endpoint == active_count`；
- context fallback、失败分类、checkpoint/resume 可用；
- UCB 系数和剩余预算比例按预期变化。

任一任务未满足这些条件时停止，不启动正式长跑。

### 10.3 因果消融

按最小增量比较：

1. 正式 V5；
2. V5 + exact endpoint dedupe；
3. 上一步 + budget-decay UCB；
4. 上一步 - semantic diversity reserve，即 V7 生存协议。

固定模型、evaluator、1000 评估预算、初始规模、轨迹长度、算子和 prompt。每项
至少 3 重复，报告 evaluator 和 LLM 调用双成本。若去重单独导致两个以上任务
held-out 明显退化，先解释重复历史的生成价值，不继续叠加控制器。

### 10.4 正式比较

四任务各 3 次 1000 评估搜索，并完成全部 14 个 held-out 规模。共同报告：

- 均值、标准差、任务内胜负和跨规模平均名次；
- 相对 V5、V4、正式 V6 和 MCTS-AHD 的直接差值；
- 严格突破率、首次/后半程突破、LRR、PCD、regress；
- active 唯一 endpoint、唯一父代 code、重复候选率；
- 父代概率熵、路线访问集中度和算子有效候选率；
- LOC、evaluator 数、LLM calls/sample 和总 token。

“超过 MCTS-AHD”的成功条件是：在同一正式比较表中，V7 的 14 规模平均名次
严格优于 MCTS-AHD，并且优势不是来自一个任务的极端值；同时至少保持 V5 已有
的 TSP 和 OP 大尺度竞争力。若 evaluator 排名超过但 LLM 调用明显更多，必须
另列等 LLM 调用比较，不能宣称搜索机制本身已经胜出。

## 十一、当前决定

正式 TraceAAD V7 已按上述最小设计完成独立实现、实验入口，以及四任务正式搜索与
held-out。权威批次为 `v7_20260804_001931`，协议为 `traceaad-v7`。机制测试只验证
实现约束；性能结论以[实验总汇](../results/实验总汇.md)为准。后续工作按去重、动态
UCB、生存规则的顺序做消融，并继续对照 MCTS-AHD 的渐进扩展。
