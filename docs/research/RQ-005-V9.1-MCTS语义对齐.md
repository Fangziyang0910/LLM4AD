# RQ-005 V9.1：TraceAAD 是否正确使用了 MCTS 的搜索语义

> **冻结说明（2026-08-08）：**本文记录已投入实验的旧协议 V9.1。该版本完成了节点 continuation value、有效访问和
> progressive widening 的形式对齐，但运行分析表明这仍是节点价值主导的搜索：
> 轨迹只进入生成上下文，没有成为预算分配单位；单候选立即回传、根级空白初始化和
> 宽化后立即结束本轮也与 MCTS-AHD 的完整预算语义不同。当前实验作为这一设计的对照保留，
> 当前 V9.1 代码已直接替换为轨迹中心预算协议，旧 checkpoint 不兼容。当前设计见
> [RQ-006](RQ-006-轨迹中心预算分配.md)，本文以下内容不再描述当前运行行为。

## 问题

V9-Core 借鉴了 MCTS-AHD 的树、UCT 和价值回传，但正式结果显示根分支访问极端集中：CVRP 三次均为 `100%`，TSP 和 OP 接近 `100%`，OBP 为 `90.3%–97.4%`。

最初的解释是探索预算不足，因此提出给每个根增加最低生成机会。进一步对照 MCTS-AHD 原始实现后发现，问题可能更基础：V9 保留了 UCT 公式的外形，却改变了 MCTS 中节点价值、访问次数、渐进式拓展和回传之间的关系。

本研究问题是：

> 在保留 TraceAAD 的历史上下文和 `Idea + Code` 生成方式时，恢复 MCTS-AHD 的核心搜索语义，能否消除 V9 的根级锁定并改善持续生成过程？

## MCTS-AHD 的真实机制

### 1. `lambda_0` 和 `alpha` 负责不同事情

MCTS-AHD 默认使用：

- `lambda_0=0.1`：控制 UCT 探索项的强弱；
- `alpha=0.5`：控制渐进式拓展，不是 UCT 探索系数。

渐进式拓展规则是：

```text
当 int(visits ** alpha) > 当前子节点数量时，允许增加一个新子节点
```

这个规则作用于虚拟根和普通程序节点。随着访问次数增加，树的宽度逐步增加。

### 2. 初始根数量和种群规模不是同一个参数

正式 MCTS-AHD 配置使用 `init_size=4`、`pop_size=10`：

- `init_size=4` 是初始树根数量；
- `pop_size=10` 是种群参考规模和生存管理规模。

V9 使用 `n_init=10` 个固定根，并取消了根级渐进式拓展，实际上把两个不同职责合并了。

### 3. 节点价值表示“继续走下去的结果”

MCTS-AHD 的回传逻辑是：新节点完成评价后，沿父链回传；父节点的 `Q` 更新为其子节点 `Q` 的最大值。一个节点还没有子节点时，可以保留自己的分数；一旦它拥有后代，父节点的价值由后代继续结果决定。

因此，MCTS-AHD 的价值更接近：

> 从这个节点继续生成，当前搜索能得到的最好结果。

V9 的 `subtree_value` 则是：

```text
max(节点自身分数, 所有后代分数)
```

节点自身的早期高分会永久保留，即使之后从它生成的程序连续变差。这更像“这条路线历史上曾经达到过的最高分”，不是同一个 MCTS continuation value。

### 4. 访问次数应和有效回传对应

MCTS-AHD 主要在有效子节点生成并完成回传时增加父链访问次数。V9 在生成 batch 之前就增加路径访问，失败的生成也会改变 `visit_count`，而 `backup_from` 只更新价值，不再同步更新访问次数。

这使访问次数同时混合了：

- 选择尝试次数；
- 生成失败次数；
- 有效子节点完成次数。

UCT 使用的访问次数因而不再具有单一含义。

## V9 与 MCTS-AHD 的关键差异

| 机制 | MCTS-AHD | V9-Core | 影响 |
| --- | --- | --- | --- |
| 根拓展 | 根按 `visits ** alpha` 渐进增加子节点 | 初始化后固定 10 根，不再拓展 | 根级探索机会被冻结 |
| `alpha` | `0.5`，控制树宽增长 | 删除 | 缺少 MCTS 的宽度控制 |
| UCT 系数 | `lambda_0=0.1`，随剩余预算变化 | 同为 `0.1` | 不能先把问题归结为系数错误 |
| 价值回传 | 有后代后由子节点最大值决定 | 永久保留节点自身和后代最大值 | 早期高分不会失效 |
| 访问次数 | 有效回传时沿父链增加 | batch 发送前增加，失败也计入 | 访问统计与有效证据混合 |
| 新分支控制 | 渐进式拓展 | `S_new` 与已有子节点竞争 | V9 增加了未经对齐的价值层 |
| 新分支回报 | 没有独立 batch subtree-best 回报 | 使用会随后代变化的 batch 回报 | 可能重复放大幸运后代 |

## 当前判断

### 高可信判断

V9 不是简单地把 MCTS-AHD 的参数配置错了。`lambda_0=0.1` 与参考实现一致；更明显的偏差在于 V9 删除了根级渐进式拓展，并把 `alpha` 的职责删除了。

### 高可信机制推断

V9 的 `max(self, descendants)` 回传和预先增加访问次数，使一个早期高分节点长期保持很高的选择价值。它与固定根集合共同造成了根分支锁定。

### 待验证判断

恢复原始 MCTS 的价值语义和渐进式拓展后，根访问集中是否自然下降，最终质量是否提高，仍需要实验确认。

## V9.1 设计决定

V9.1 先做 MCTS 语义对齐，不做外部覆盖补丁。

### 保留

- TraceAAD 的真实匹配历史；
- 当前程序和来时路进入 prompt；
- 四个 TraceAAD 生成入口；
- 一次 LLM 调用生成新的 `Idea + Code`；
- 完整单父树和真实 evaluator。

### 移除或重构

1. **移除 `new_child` 作为价值竞争选项。** 新子节点何时产生，由渐进式拓展决定。
2. **恢复渐进式拓展。** 根节点和普通节点统一使用 `int(visits ** alpha) > len(children)`，初始 `alpha=0.5`。
3. **重构节点价值。** 先采用 MCTS-AHD 的父节点回传语义，明确区分叶节点自身分数和已有后代的继续结果。
4. **重构访问统计。** `visit_count` 只表示 MCTS 选择/有效回传的访问；生成尝试和失败次数单独记录，不混进 UCT 访问数。
5. **暂不调大 `lambda_0`。** 保持 `lambda_0=0.1`，先确认语义对齐后的搜索形态。

V9 的 `expansion_quality`、`expansion_batch_rewards` 和 `S_new` 不应继续作为默认搜索价值，除非后续研究证明它们与 MCTS 的节点价值职责相容。

## V9.1 实施边界

以下边界已经确认，作为 V9.1 的实现契约：

| 项目 | V9.1 决定 |
| --- | --- |
| 初始根数量 | `init_size=4`，对应 MCTS-AHD 的初始树根数量 |
| 种群规模参数 | 不把 `pop_size=10` 解释为初始根数量；TraceAAD 不额外引入 active population |
| 渐进式拓展 | 根节点和普通节点均使用 `int(visits ** alpha) > len(children)` |
| `alpha` | `0.5` |
| UCT 探索系数 | `lambda_0=0.1`，先保持不变 |
| 新子节点控制 | 删除 `new_child` 价值臂，由渐进式拓展决定是否增加子节点 |
| 单次扩展候选数 | `offspring_per_iteration=1`，与 MCTS-AHD 的单候选扩展对齐 |
| 节点价值 | 采用 MCTS-AHD 的 continuation value 语义，不永久保留已扩展节点自身的历史最高分 |
| 访问次数 | 只由有效搜索回传更新；生成尝试、解析失败和 evaluator 失败单独记录 |
| 保留的 TraceAAD 部分 | 真实匹配历史、四个生成入口、`Idea + Code` 协议、完整单父树和 evaluator |

`init_size=4` 和 `offspring_per_iteration=1` 是本次语义对齐的一部分，不是待调超参数。
如果后续希望恢复 10 个初始根或两个 sibling，必须作为独立实验变量记录，不能在 V9.1
实现中隐式改变。

## 不在 V9.1 中处理的事项

- 不调整历史窗口和上下文裁剪；
- 不新增或删除 TraceAAD 生成入口；
- 不重新引入趋势、路线信用、算子信用或全局记忆；
- 不先调大 `lambda_0`；
- 不加入根级最低生成机会；
- 不把最终结果直接归因于历史上下文。

## 预期表现

过程上预期：

- 根节点随着访问增长逐步出现新的子节点；
- 根访问不再初始化后立即冻结；
- 一个节点后续连续产生较差程序时，其 continuation value 会下降或不再保持早期高值；
- 访问次数主要反映有效搜索经历，而不是失败请求数量；
- 根分支集中程度下降，但不要求所有根均匀访问。

质量上希望看到：

- 后半程仍有来自不同根和不同深度的有效候选；
- global-best 更新不再完全由早期单根决定；
- TSP、CVRP 和 OBP capacity=500 等 V9 较弱设置的运行间差异减少；
- held-out 表现和 best-so-far 质量至少不低于 V9。

如果语义对齐后根仍然集中，但最终质量提高，应把集中视为正常的质量利用结果；如果根集中消失但质量没有提高，说明还需要研究单步上下文，而不是继续增加搜索控制器。

## 验证顺序

V9.1 首先做最小搜索机制冒烟，检查：

1. 根渐进式拓展是否按 `alpha=0.5` 发生；
2. 节点有后代后，价值是否按照新的回传定义更新；
3. 失败生成是否不会改变 MCTS 的有效访问次数；
4. `new_child` 不再参与选择分数；
5. 选择路径、拓展数量、访问数量和回传结果能在日志中逐步核对。

随后再做小预算真实模型实验，最后才进行正式四任务三重复。正式实验同时报告根覆盖、节点深度、后半程突破、有效率、搜索 best 和 held-out 测试，不能只看最终最好分数。
