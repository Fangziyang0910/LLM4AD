# TraceAAD 版本迭代诊断：结果协议分辨率、真实差距位置与消融基座选择

## 一、研究问题

TraceAAD 从 V4 演化到 V8.3，引入并删除了大量机制，但没有任何版本在正式结果上确立相对 MCTS-AHD 的优势。本笔记回答三个问题：

1. 当前 held-out 结果协议能分辨多大的机制效应？版本之间的差异是否落在可分辨范围内？
2. TraceAAD 与 MCTS-AHD 的差距真实存在于哪些任务？
3. 后续单变量消融应当以哪个版本为基座？

## 二、证据与方法

分辨率分析脚本为 [`experiments/analysis/analyze_result_resolution.py`](../../experiments/analysis/analyze_result_resolution.py)，直接解析 [`docs/results/实验总汇.md`](../results/实验总汇.md) 中 11 方法 × 15 held-out 规模的"均值 ± 样本标准差"（n=3），输出写入 [`version_diagnosis/resolution.json`](version_diagnosis/resolution.json)。

方法为参数化 bootstrap：以报告均值为真值、报告标准差为运行间标准差，重抽 3 个 run 取均值，重算 15 规模平均名次，重复 20000 次。该过程只量化"运行间变异经 3 次重复平均后的残余不确定性"，不涵盖实例选择、模型端点和实现差异带来的不确定性，因此是对真实不确定性的**下界**估计。

轨迹深度分析脚本为 [`experiments/analysis/analyze_tree_depth.py`](../../experiments/analysis/analyze_tree_depth.py)，从 V8 与 V8.2 正式批次共 24 个 run 的 `artifacts/edges.jsonl` 重建单父代树，统计每次扩展所选父节点的深度，输出写入 [`version_diagnosis/tree_depth.json`](version_diagnosis/tree_depth.json)。扩展点深度等于该次生成可获得的祖先历史边数上界。

尺度泛化分析使用 `eval_best_*/results.json` 中的 `instance_costs` 与 `instance_prizes`，在三个粒度上比较，各自的推断对象不同：

- **instance 级**：把一个方法 3 个 run 的实例向量按元素平均，与对照方法的池化结果逐实例配对。推断对象是"这几个具体程序在实例分布上的表现"，用于描述尺度趋势和诊断程序性质。
- **run × run 级**：两个方法的 run 两两配对比较 objective，报告胜出对数。
- **run 级**：3 个 run 的均值差与 Welch 检验，推断对象是方法。

**instance 级的 p 值不能用于方法比较。** 64 个实例不是方法的 64 次重复；实例数只降低"评估某个程序有多准"的不确定性，方法比较的样本量仍为 3。把实例当作重复会构成伪重复，系统性高估证据强度。3.3 给出了具体量级：同一组数据在 instance 级得到 p = 3.0e-25，在 run 级为 p = 0.266。任何 3 次重复的实验都不可能支持 1e-25 量级的 p 值，出现该量级即应先检查推断单位。

机制清单与过程指标沿用 [版本机制诊断](TraceAAD版本机制诊断.md)、[V5 机制全面分析与 V7 设计](TraceAAD-V5机制全面分析与V7设计.md)、[V8 与 V8.2 同期对比](TraceAAD-V8-V8.2同期对比.md) 和 [跨方法轨迹过程分析](跨方法轨迹过程分析.md)。

## 三、观察结果

### 3.1 结果协议的分辨率低于典型版本效应

15 规模平均名次的抽样区间大幅重叠：

| 方法 | 平均名次 | 95% 区间 | P(优于 MCTS-AHD) |
| --- | ---: | --- | ---: |
| MCTS-AHD | 3.333 | [3.067, 5.000] | — |
| TraceAAD V8 | 4.067 | [3.667, 5.267] | 0.236 |
| TraceAAD V8.2 | 4.133 | [3.533, 5.467] | 0.263 |
| TraceAAD V4 | 4.600 | [3.600, 5.733] | 0.199 |
| TraceAAD V5 | 5.100 | [4.067, 6.067] | 0.071 |
| TraceAAD V6 | 6.533 | [5.533, 7.400] | 0.000 |
| TraceAAD V7 | 7.533 | [6.267, 8.400] | 0.000 |
| TraceAAD V8.3 | 7.667 | [6.667, 8.400] | 0.000 |

**观察。** V8、V8.2 和 V4 与 MCTS-AHD 的名次高低在当前重复数下有 20%–26% 的概率反向。名次第一的位置由运行间变异决定，不由机制差异决定。

### 3.2 七个版本中只有三个可被分辨，且都是可分辨地更差

TraceAAD 版本两两比较 P(行优于列)：

| | V4 | V5 | V6 | V7 | V8 | V8.2 | V8.3 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| V4 | — | 0.70 | 0.99 | 1.00 | 0.38 | 0.39 | 1.00 |
| V5 | 0.27 | — | 0.97 | 1.00 | 0.16 | 0.18 | 1.00 |
| V8 | 0.59 | 0.82 | 1.00 | 1.00 | — | 0.47 | 1.00 |
| V8.2 | 0.58 | 0.79 | 1.00 | 1.00 | 0.49 | — | 1.00 |

**观察。** V4、V5、V8、V8.2 两两不可分辨，V8 与 V8.2 之间为 0.47。V6、V7、V8.3 相对这四者可分辨地更差。因此六次版本迭代产出的可靠信息全部是负面结论：过度删减（V6）、去重与衰减 UCB 的联合引入（V7）、信用失衡导致根垄断（V8.3）会造成损害。没有一项正面机制得到确认。

版本效应的量级可以直接对照：3 次重复的标准误约为 0.58 个运行标准差，而七个版本在单个规模上铺开的范围通常只有 1–3 个运行标准差。典型版本差因此只有 1–2 个标准误。

### 3.3 尺度趋势可描述，但没有任何方法可分辨地优于基线

单版本对 MCTS-AHD 的标准化差（正值表示 TraceAAD 更好）：

| 任务 | V4 | V5 | V6 | V7 | V8 | V8.2 | V8.3 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| TSP | +1.54 | +0.90 | +1.23 | −0.50 | +1.95 | +1.76 | −1.49 |
| CVRP | −1.14 | −1.22 | −1.78 | −3.21 | −0.53 | −1.52 | −3.42 |
| OP | −0.57 | +0.36 | −1.95 | −0.70 | −1.23 | −0.19 | −1.36 |
| OBP | −0.07 | −0.84 | −1.05 | −0.62 | −0.39 | −0.27 | −0.03 |
| 全部 15 规模 | **−0.06** | **−0.33** | −0.92 | −1.13 | **−0.12** | **−0.10** | −1.27 |

**观察。** 七个版本在 CVRP 上全部落后，效应量从 −0.53 到 −3.42。TSP 上五个版本领先，V7 与 V8.3 落后。跨版本方向的一致性说明 CVRP 上的差异来自骨架与任务结构的交互，不来自各版本引入或删除的控制机制。

该表同时区分出两类失败。V4、V5、V6、V8、V8.2 在 TSP 上领先、在 CVRP 上落后，整体效应量在 −0.06 到 −0.92 之间，属于任务分化。V7 与 V8.3 在四个任务上全部落后，整体效应量为 −1.13 与 −1.27，与 3.2 中它们可分辨地更差一致。两类问题的成因不同，不能用同一套修改处理。

降到 instance 级后，差异呈现为**随测试规模单调变化的趋势**。脚本为 [`experiments/analysis/analyze_scale_generalization.py`](../../experiments/analysis/analyze_scale_generalization.py)，输出写入 [`version_diagnosis/scale_generalization.json`](version_diagnosis/scale_generalization.json)。CVRP 与 OP 的 `results.json` 保存逐实例向量，TSP 与 OBP 只保存聚合 objective，因此只有前两个任务能做该分析。

CVRP 上各方法对 MCTS-AHD 的 instance 胜率（50 / 100 / 200）：

| 方法 | CVRP50 | CVRP100 | CVRP200 | 趋势 |
| --- | ---: | ---: | ---: | --- |
| V8 | 53% | 17% | 0% | 崩塌 |
| V5 | 34% | 6% | 0% | 崩塌 |
| EoH | 30% | 12% | 0% | 崩塌 |
| V4 | 27% | 14% | 2% | 崩塌 |
| V8.2 | 19% | 0% | 0% | 崩塌 |
| V6 | 12% | 2% | 0% | 崩塌 |
| V7 | 9% | 0% | 0% | 崩塌 |
| V8.3 / Pathwise / ReEvo | ≤3% | 0% | 0% | 全尺度地板 |

**观察一：CVRP 上的崩塌是全方法共性，不是 TraceAAD 的机制缺陷。** 十个非基线方法无一例外，包含 EoH、ReEvo、Pathwise。这否定了"TraceAAD 产出的程序有独有的尺度泛化偏差"这一解释——若为 TraceAAD 骨架所致，基线方法不应同向崩塌。可支持的表述只是：MCTS-AHD 在 CVRP 上找到了比其余全部方法更可迁移的程序，而 TraceAAD 各版本在其中处于中上位置（V8 的 CVRP50 胜率 53%、d=+0.06 是全部方法中最高）。

OP 上的胜率序列则区分出方法：

| 方法 | OP50 | OP100 | OP200 | 趋势 |
| --- | ---: | ---: | ---: | --- |
| V5 | 53% | 61% | 86% | 增强 |
| ReEvo | 23% | 36% | 55% | 增强 |
| EoH | 47% | 45% | 45% | 无趋势 |
| V8.2 | 42% | 44% | 39% | 无趋势 |
| V8 | 27% | 30% | 19% | 无趋势 |
| V4 | 39% | 27% | 16% | 崩塌 |
| V8.3 | 12% | 6% | 3% | 崩塌 |
| V6 | 22% | 6% | 0% | 崩塌 |

**观察二：V5 在 OP 上随规模单调增强，是全部方法中唯一在大规模明显反超 MCTS-AHD 的组合（OP200 胜率 86%、d=+0.74）。** 该趋势跨 split 单调且逐 run 同向（三个 run 的 OP200 胜率为 67%/64%/94%），方向是稳定的描述。

**这些趋势的方向可靠，强度不足以确立显著性。** run 级检验全部未达 p<0.05：V5 在 OP200 为 p=0.444，在 CVRP200 为 p=0.076。逐 run 胜率同时暴露了池化掩盖的变异：V8 在 CVRP200 池化后 0/64 全输、instance 级 p = 3.0e-25，而单个 run 的胜率是 17%/0%/38%，run 级 p = 0.266。

**观察三：没有任何方法在任何尺度上可分辨地优于 MCTS-AHD。** 11 方法 × 15 尺度的 Welch 检验中，p<0.05 的组合共 11 个，全部方向为更差：Pathwise 4 个、V7 与 V8.3 各 2 个、EoH 与 V6 各 1 个。V4、V5、V8、V8.2、ReEvo 均为 0 个可分辨差异，平均 Cohen's d 分别为 −0.06、−0.33、−0.12、−0.10、−0.95。这与 3.1 的名次分析相互印证：现有协议既无法确认 TraceAAD 更好，也无法确认它更差。

**机制解释。** CVRP 上的差距具有泛化特征而非搜索特征：过程批次中四个方法的训练 best 几乎相同（MCTS-AHD −8.664、V4 −8.665、V6 −8.673、V5 −8.717），held-out 差距却随测试规模扩大。但结合观察一，该现象的归因应指向任务本身——CVRP 的 n=50 训练域对全部方法都构成过拟合压力，MCTS-AHD 的程序恰好更简单因而更可迁移。

伴随证据：CVRP 单次评估约 40 秒（TSP 约 0.04 秒）；TraceAAD 的 best 程序非空 LOC 为 141（V5）与 379（V4），MCTS-AHD 为 87；CVRP 后半程窗口突破率 V4 为 0.049、V6 为 0.029，MCTS-AHD 为 0.137。这些量是伴随观察，"程序更简单因而更可迁移"是尚未确立的推断，3.7 给出了它的证据边界。

### 3.4 核心科学主张仍未被直接检验

"算法改进历史为下一步提供信息"是 TraceAAD 的立命主张。从 V4 起，各版本文档一致记载"历史相对于 current-code-only 的独立收益仍待检验"。八个大版本和二十余个子版本全部在优化历史的使用方式，没有一次实验比较过"提供历史"与"不提供历史"。当前无法回答增益是否来自轨迹上下文，还是来自多起点初始化、两阶段生成或执行契约修复。

### 3.5 轨迹深度相差十倍的两个协议表现不可分辨

V8 与 V8.2 的上下文协议都允许最多 8 条祖先边。实测的扩展点深度分布如下：

| 协议 | 任务 | 扩展点深度中位数 | 深度 ≥ 4 的扩展占比 | 最大深度 |
| --- | --- | ---: | ---: | ---: |
| V8 | TSP | 3.0 | 33.0% | 9.7 |
| V8 | CVRP | 3.3 | 49.4% | 12.0 |
| V8 | OP | 4.0 | 54.1% | 15.0 |
| V8 | OBP | 3.0 | 37.8% | 8.0 |
| V8.2 | TSP | 34.0 | 98.0% | 88.0 |
| V8.2 | CVRP | 40.7 | 98.8% | 121.3 |
| V8.2 | OP | 35.0 | 97.6% | 78.7 |
| V8.2 | OBP | 28.3 | 87.7% | 78.3 |

**观察。** V8 跨全部任务的扩展点深度中位数为 3.33，只有 43.6% 的扩展发生在深度 ≥ 4 的节点上。8 条祖先边的上下文容量在多数样本上填不满，实际进入生成的"算法改进历史"是 1–3 步。V8.2 的中位数为 34.50，95.5% 的扩展深度 ≥ 4，上下文容量总能填满。

两个协议的 held-out 表现不可分辨（3.2 中 P(V8 优于 V8.2) = 0.47），15 规模整体效应量分别为 −0.12 与 −0.10。

**机制解释。** 这是目前最接近"操纵历史长度"的对照，方向为无差异：可用历史从约 3 步增加到约 35 步，没有产生可测量的性能变化。

该对照距离单变量很远。核对两个批次的 `run_config.json` 后，V8 与 V8.2 至少相差五项：

| 参数 | V8（`traceaad-v8`） | V8.2（`traceaad-v8.2-adaptive-expand`） |
| --- | --- | --- |
| 初始根数 `n_init` | 30 | 10 |
| 探索系数 | 0.5 | 0.1 |
| 扩展策略 | 标准递归 UCT + `widening_alpha=0.5` | `adaptive_new_child_uct` |
| 生成协议 | 两阶段 Action→Code（`actions_per_iteration=2`） | 单阶段 `direct_code` |
| checkpoint schema | 1 | 3 |

探索系数 0.5 与 30 个根共同解释 V8 的浅树，0.1 与自适应 `new_child` 共同解释 V8.2 的深树。因此至少四种解释都成立：轨迹深度没有独立贡献；深度收益被初始起点减少抵消；深度收益被生成协议变化抵消；深度收益小于当前分辨率。区分需要固定其余参数、只操纵探索系数与扩展策略的单变量实验。

`llm4ad/method/traceaad_v8/` 当前的实现对应 V8.2 形态：构造参数含 `offspring_per_iteration` 与 `expansion_prior_weight`，不再含 Action 阶段参数。复现 V8 的两阶段生成需要回退代码，扫描探索系数与 `n_init` 则只需改参数。

该观察还给出对 V8 搜索行为的重新描述：30 个起点、970 次扩展、深度中位数 3，说明预算主要用于在浅层节点上横向产生兄弟候选。TraceAAD 当前最好的版本，其成绩与"多起点加浅层局部改进"相容，与"长轨迹历史指导"的因果关系尚未建立。

### 3.6 跨方法比较存在未对齐的生成预算

各方法在 evaluator 预算上对齐为 1000，在 LLM 调用上未对齐。MCTS-AHD 约 2.10 次调用/评估，TraceAAD 约 1.49 次，相差约 41%。MCTS-AHD 的额外调用用于 thought alignment。因此当前跨方法结论混有生成预算差异。

### 3.7 两个关于过拟合的因果论断未通过核实

分析过程中曾出现两个论断，被用于支持"轨迹机制提高了训练效率但没转化为泛化""程序越臃肿越过拟合"。逐条复核后，两者的点估计可复现，推断强度不成立。

**论断一：训练排名与测试排名系统性倒挂。** 所引四个方法的 z 值与名次可精确复现（V4 训练第 1 测试第 4，MCTS-AHD 训练第 3 测试第 1）。但 11 个方法整体的 Spearman(训练名次, 测试名次) = **+0.873，p = 4.5e-4**，训练与测试排序高度一致。真实现象是局部重排，不是全场反转。该论断另有一处口径混用：V6 的训练分取自过程批次，改用与 held-out 对应的正式批次后，V6 训练 z 为 −0.003（第 6），位移从 −3 缩小到 −1。

**论断二：泛化 gap 由程序 LOC 驱动，与搜索时长无关。** LOC 均值可复现（V4 275.9、V8.2 130.2、V5 121.1、V8 93.7、MCTS-AHD 74.1，口径为保留注释的非空行）。相关强度不成立：

| 分析 | n | r(LOC, gap) | p |
| --- | ---: | ---: | ---: |
| 方法级，全部 11 方法 | 11 | 0.48 | 0.14 |
| 方法级，论断点名的 5 方法 | 5 | 0.98 | 0.004 |
| run 级，原始 | 119 | 0.20 | 0.03 |
| **run 级，按方法去中心化** | 119 | **0.05** | **0.60** |

**组内相关消失是关键。** run 级的原始相关来自方法之间的差异（V4 既程序长、gap 又大），不来自"同一方法内程序越长越过拟合"。论断报告的 r = 0.642 介于全场不显著与 5 点极强之间，5 点相关的置信区间极不稳定，不足以支撑因果表述。

论断中站得住的部分：r(best_sample_order, gap) ≈ 0（11 方法为 0.07，p = 0.84；组内为 −0.05），即"搜索越久越过拟合"没有证据；V4 的 LOC 显著高于 MCTS-AHD。

**对机制取舍的影响。** 同分择简此前被称为"因果链最清楚的机制"，该称谓依赖论断二。它仍可作为低成本的确定性不变量保留，但不能作为已确认的抗过拟合机制看待，也不能把 V4→V5 的 LOC 与 gap 变化单独归因于它——V5 同时改动了多项。

## 四、诊断

### 4.1 版本迭代不收敛的机制

版本迭代等价于在设计空间中做贪心搜索，其反馈信号是 15 规模平均名次。该信号的噪声大于典型步长效应（3.1、3.2），并且每次迭代同时改变 3–8 个机制（V5→V6 删除六项，V6→V7 增五删二，V7→V8 更换整个搜索骨架，未提交的 V8.3 重构改动六项）。联合改动使效应无法归属，低分辨率使方向无法判断。两者叠加的结果是每个版本都从头猜测，改进无法累积。

TraceAAD 主张搜索应利用已积累的过程经验指导下一步。研究过程本身缺少这一条件：版本历史中没有可归因的信用记录，因此不能为下一版提供方向。

对研究问题 2 的回答需要收窄。差距在 CVRP 上最大，但十个非基线方法在该任务上全部随规模崩塌（3.3 观察一），因此它不是 TraceAAD 的机制缺陷，改动 TraceAAD 的搜索控制层不可能消除它。在可分辨性层面，没有任何方法在任何尺度上优于 MCTS-AHD，也没有任何 TraceAAD 主力版本可分辨地更差（3.3 观察三）。综合起来：当前证据既不支持"机制组合出了问题"，也不支持"某个版本已经接近成功"，它只支持"这套协议尚未产生可用于判断的信号"。

## 五、决定：消融基座为 V8

### 5.1 候选比较

| 判据 | V4 | V5 | V8 / V8.2 骨架 |
| --- | --- | --- | --- |
| 运行间变异系数（15 规模均值） | 1.477% | 1.195% | **0.809%** / 1.164% |
| 15 规模平均名次 | 4.600 | 5.100 | **4.067** / 4.133 |
| 对 MCTS-AHD 胜出规模数 | 6/15 | 5/15 | **7/15** / 4/15 |
| 对 MCTS-AHD 整体效应量 | **−0.06** | −0.33 | −0.12 / −0.10 |
| 状态管理与"保存来时路"的一致性 | archive 硬淘汰 | archive 硬淘汰 | **完整树保留全部有效节点** |
| 历史条件是否为正交干预点 | 与 compact best 锚点、生存排序耦合 | 同左，并与参考选择耦合 | **纯上下文变量，由 `ancestor_history_limit` 单独控制** |
| 消融所需开关的现成程度 | 需要改造 | 需要改造 | **`n_init`、`ancestor_history_limit`、`direct_child_limit`、`exploration_constant`、`expansion_prior_weight`、`operators`、`random_seed` 均已是构造参数** |

### 5.2 判断

**以 V8 系列的树骨架为消融基座**，即 `llm4ad/method/traceaad_v8/` 当前实现。四条理由按重要性排列：

1. **测量分辨率最高。** V8 的运行间变异系数 0.809% 是全部 11 个方法中最低的，TSP200 上标准差为 0.0154（V6 为 0.6407）。消融能分辨的最小效应由基座方差决定，这项优势直接转化为实验效率。
2. **骨架与科学主张一致。** 完整树保留全部有效节点，与"完整保存来时路"相符。V4/V5 的 archive 硬淘汰会取消路线的繁衍资格，在检验历史价值时构成基座层面的内在冲突。
3. **干预点正交且开关现成。** 树骨架下"提供多少历史"由 `ancestor_history_limit` 单独控制，不牵动其它逻辑；深度、起点数、算子集合和随机种子同样已是构造参数。V5 的种群骨架中改动历史会同时影响 compact best 锚点、参考轨迹选择和生存排序。
4. **性能上是最好的 TraceAAD。** V8 平均名次 4.067、对 MCTS-AHD 胜出 7/15 个规模，均为各版本最好；V8.2 紧随且与之不可分辨。

这里选定的是骨架，具体参数配置按 5.3 处理。

### 5.3 基座配置必须先解决轨迹深度

3.5 显示 V8 默认配置的扩展点深度中位数为 3.33，仅 43.6% 的扩展深度 ≥ 4。以该配置直接做历史条件消融存在设计缺陷：三个臂设定为"0 条 / 3 条 / 8 条祖先边"时，第二臂与第三臂在半数以上的样本上取到相同的上下文，操纵强度不足，实验容易读出"无差异"而该结论来自基座配置。V8.2 配置的深度中位数为 34.50，满足操纵强度要求，但运行间变异系数从 0.809% 升到 1.164%。

因此基座定义为 **V8 系列树骨架 + 一个待确定的参数配置**，配置由 6.1 的第一个实验在探索系数与扩展策略上确定。在该实验完成前不冻结基座。由于 V8 与 V8.2 使用同一份代码，该实验只需扫参数，实现成本很低。

其余风险：

- **V8 在 OP 上偏弱**（任务平均 −1.23，OP50 达 −2.40），V8.2 为 −0.19。消融结论按任务分层报告，避免总体均值掩盖任务异质性。
- **V5 在单版本上场口径下平均名次 2.000 优于 V8 的 2.167**，并且在 OP 上是唯一整体效应为正的版本，OP200 的 instance 胜率达 55/64。该差异不可分辨（P(V8 优于 V5) = 0.82）。V5 的四算子与跨轨迹参考保留为后续加法项。
- 当前代码对应 V8.2 形态，不再支持 V8 的两阶段 Action→Code 生成。若后续需要比较生成协议，须先恢复该代码路径。
- 基座选择依据当前证据。若深度实验显示浅树配置的低方差与深树配置的可操纵性无法兼得，需要按实验目的分别选择配置。

## 六、消融路线

各臂固定模型、任务、evaluator 预算、LLM 调用上限、初始种群与随机种子，每次只改一项机制，报告逐规模配对效应量、严格突破率、LLM 调用与 token 成本。先在 TSP、OP、OBP 上做，CVRP 因单次评估约 40 秒单独排期。

1. **轨迹深度（第一优先，同时确定基座）。** 固定 `n_init` 与生成协议，只操纵 `exploration_constant` 与扩展策略，使扩展点深度中位数分别落在浅、中、深三档。该实验有双重作用：确定基座配置，并把 3.5 中混杂五项改动的 V8/V8.2 对照转为单变量证据，直接检验"轨迹深度是否有独立贡献"。若深度无独立贡献，选择能填满 8 条祖先边的最浅配置即可，同时说明核心主张需要限定在内容维度上。
2. **历史条件。** 三臂：只提供当前程序 / 提供随机他人历史 / 提供真实匹配历史。这是核心主张的直接检验，结论决定后续全部工作的方向。必须在 1 确定的深度配置上进行。实现上第一臂需要放开 `ancestor_history_limit` 的正数校验以允许 0，第二臂需要新增打乱历史的上下文构造路径。
3. **预算缩放。** 在 250/500/1000/2000 evaluator 预算下比较 TraceAAD 与基线。主张蕴含可证伪预测：可用历史随预算增长，相对优势应随之扩大。该预测为轨迹方法所特有，与种群式方法形成区分。
4. **上下文构成。** 祖先历史边数与已尝试子分支数分别扫描。
5. **算子集合。** 两算子、四算子、五算子，其余固定。
6. **状态卫生。** 单独恢复精确 endpoint 去重。
7. **选择与信用。** Q-only、`0.8Q+0.2P`、有无预算衰减、max-backup 与均值回传。

尺度泛化（P10）已确认为全方法共性而非 TraceAAD 机制缺陷，因此不占用上述消融的机制预算。仅保留一项零成本检验：

- **离线判定选择规则与搜索的责任划分。** 扫描已有 artifacts 的候选池，检验搜索历史中是否存在测试表现优于当前返回程序的候选。若存在，问题在选择规则，可用 validation 子集选择返回程序解决，且不增加 evaluator 预算；若不存在，问题在搜索产出本身。该检验在 TSP 与 OBP 上成本很低，CVRP 上单个程序在 64 个 test_200 实例上评估约 93 秒，需要抽样。

训练目标改多规模聚合会改变任务定义并破坏与已有基线的可比性，若要推进需作为独立课题重建全部基线，不在本消融序列内。

## 七、局限

- 3.1 至 3.3 的不确定性估计以报告的运行间标准差为唯一噪声源，是真实不确定性的下界。实例选择、模型端点漂移和实现差异未纳入。
- 参数化 bootstrap 假设各方法在各规模上的运行间分布为正态且相互独立。OBP 在 capacity=500 上箱数为整数且三次运行常完全相同，该处的标准差为 0，对应方法在该规模的抽样变异被低估。
- 3.3 中"差异来自泛化"基于训练 best 与 held-out 的对比，未直接检验 best 程序对训练实例的依赖，为机制推断。
- 3.3 的 instance 级胜率为描述性结果。尺度趋势的方向由跨 split 单调性与逐 run 同向性支持，强度受限于 3 次重复：全部 run 级检验均未达 p<0.05。
- 3.3 的尺度分析只覆盖 CVRP 与 OP。TSP 与 OBP 的评估工件只保存聚合 objective，无法做 instance 级比较；这两个任务上仅有的序列是 n=3 算出的 Cohen's d，其标准误与跨尺度差同量级，不足以判定趋势方向，脚本对这两个任务标注"证据不足"而不给标签。
- 3.5 的深度对照非单变量，V8 与 V8.2 之间同时改变了初始根数与扩展策略。"深度无独立贡献"是三种候选解释之一，需要 6.1 的实验区分。
- 3.7 的两个相关分析推断单位为方法（n=11），检出中等效应的功效很低。"未通过核实"指现有证据不支持该强度的因果表述，不等于反向结论成立。run 级去中心化相关只排除了组内的线性关联。
- 扩展点深度是可用历史的上界。模型是否真正利用了进入上下文的历史，需要单独的利用度量。
