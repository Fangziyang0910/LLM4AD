# TraceAAD 版本机制诊断：为什么 V5 最强，MCTS-AHD 仍然领先

日期：2026-08-03
状态：历史机制审计；Occam V6 已定义为正式 V6（批次 `v6_20260802_170400_occamv1`）；质量门控 V6 已归档

## 一、核心判断

正式结果需要把结论改成两层：**MCTS-AHD 是总体第一，V5 是最强的 TraceAAD 版本；V4 是可靠的历史对照，但不是整体最优。** 14 个 held-out 规模的单版本比较中，V5 平均名次为 2.143，优于 V4 的 2.500 和正式 Occam V6 的 3.143；八方法同场时 MCTS-AHD 为第 1，V4/V5 并列第 2。不同方法集合的平均名次不能直接相减，但两种口径都指向同一结论：V5 最接近 MCTS-AHD。

V5 的优势不是某个单独公式，而是一套较平衡的搜索系统：严格匹配的主轨迹保留来时路，四个语义算子同时提供局部修正和有限的跨轨迹知识交换，Action/Code 共享历史避免实现断层，`0.8Q+0.2P` 让成果质量主导而不过早放大短期趋势，完全同分时择简则降低了表示膨胀。历史过程批次中，V5 的 LRR 为 0.136、regress 为 61.6%、PCD 为 0.085，说明它在 TraceAAD 内形成了最可靠的局部变化；正式 held-out 结果则表明这种平衡在 CVRP50 和 OP100/200 上尤其有效，并带来最好的跨任务折中。

V4 仍然有两个重要优点：严格突破率较高、TSP 与 OBP C=100 表现强。但它的代码膨胀和 OP 大尺度弱点会降低跨任务平均排名。正式 Occam V6 进一步说明“更简单”不是充分条件：它在 TSP 获益，却在 CVRP、OP 和 OBP C=100 明显退化，删除精确状态去重后还出现重复 endpoint 和零突破 run。

MCTS-AHD 的领先来自另一种平衡：用树结构、渐进扩展和预算递减的 UCT 把更多计算集中到高价值分支，同时用 m1/m2 的单路线修改和 e2/s1 的重组维持路线级探索。它的严格突破率低于 TraceAAD，但局部精炼率更高，且每个 evaluator 样本使用更多 LLM 调用。因此它提供了值得学习的预算分配和算子调度思路，但其结果优势不能简单归因于树结构，LLM 调用预算和原始方法实现也同时不同。

## 二、证据口径与结论强度

本文按以下等级表述结论：

| 等级 | 含义 | 可以得出的结论 |
| --- | --- | --- |
| A：已确认 | 代码、配置、日志或工件可直接重放 | 实现是否执行、接口是否丢候选、状态是否重复 |
| B：重复观察 | 同协议三重复或跨任务方向一致 | 某种系统现象与性能共同出现 |
| C：机制推断 | 有第一性原理和关联证据，但没有单变量消融 | 最可能的原因、下一步可证伪假设 |

全文不把以下关系写成已证明因果：某个算子出现在最终路径，所以它造成最终收益；某个过程指标提高，所以机制更好；一个联合版本更好，所以其中每项修改都有效。

主要证据包括：

- 36 个同模型、同预算、同任务配置的 V4/V5/V6 正式 run：[轨迹过程分析](TraceAAD-v4-v6-轨迹过程分析.md)；
- 96 个跨方法 run：[跨方法轨迹过程分析](跨方法轨迹过程分析.md)；

## 三、版本谱系与结果

### 3.1 V4 前身：复杂机制做减法后出现回升

下表使用同一 held-out 口径中的 OOD 指标。越低越好。

| 版本 | 主要机制状态 | TSP200 | CVRP100 | 诊断 |
| --- | --- | ---: | ---: | --- |
| V1 | 模式记忆、六算子（Scale-Transfer 默认关闭）、自适应 portfolio、Elo/成对比较、island、novelty gate、Pareto 生存 | 12.306 | 15.955 | 已有竞争力，但控制层很多，结果波动较大 |
| V2 | 加入经验记忆、精英课程、复杂度/运行时价值和 simplify | 12.939 | 15.811 | CVRP 改善，TSP 明显退化；新增知识层没有跨任务稳定收益 |

### 3.4 历史过程批次：V5 的局部可靠性最高

| 指标 | V4 | V5 | 质量门控 V6 | 解释 |
| --- | ---: | ---: | ---: | --- |

| LRR：被接受子代严格优于父代 | 0.116 | **0.136** | 0.104 | V5 在 TraceAAD 内局部变化最可靠 |

## 四、第一性原理：轨迹搜索真正需要优化什么

一次 evaluator 调用的价值不在于生成了一个新轨迹 ID，而在于它是否带来以下至少一种新信息：

1. 得到更好的可执行程序；
2. 排除一个与当前程序和历史匹配的具体方向；
3. 发现一个可继续发展的新状态；
4. 提供能够改变后续决策的可靠证据。

因此，任何机制都应按“每单位评价预算产生多少有效新信息”判断，而不是按模块是否复杂、日志是否丰富或过程代理是否漂亮判断。TraceAAD 的控制链应保持四层分工：

- **事实层**记录全部程序、修改和评价；
- **上下文层**向 LLM 展示与当前锚点匹配的必要历史；
- **繁衍层**维护有限且有差异的当前可执行状态；
- **选择层**用尽量少的可靠信号分配预算。

V5 的主要优势是四层边界仍然清楚，同时允许有限的跨轨迹知识交换。其它版本的主要失败都可以追溯到跨层混合：把审计字段交给 LLM、把轨迹身份当作状态多样性、把局部回弹当作长期信用、把代码差异当作参考互补性，或把共享摘要当作所有路线都适用的事实。

## 五、逐机制诊断

### 5.1 上下文管理

| 更改 | 版本 | 诊断 | 证据等级 |
| --- | --- | --- | --- |
| 当前程序 + 严格祖先历史 | V1-V6 | **保留。** 这是与 TraceAAD 思想最一致的信息：历史和当前代码严格匹配。V4 的 6,299 次 Action 与 12,582 次 Code 调用未发现错轨迹/错锚点。历史是否优于 current-code-only 仍缺直接消融。 | A/B |
| 最多 8 节点历史 | V1-V6 | **合理工程边界，贡献未证明。** 它限制上下文增长并保留近期来时路；没有 4/8/全历史对照。 | A/C |
| endpoint / 内部最好锚点后的旧尝试 | V4-V6 | **设计正确，早期实现不完整。** V4 能内部回退，但失败后缀不会持续传给新分支；V5/V6 用 formation/tested-after 分区修复了语义。收益依 task 变化。 | A/B |

| Action 与 Code 共享同一历史 | V5.2+ | **语义上必要，但不是性能充分条件。** 它修复“决定时看历史、实现时只看一句 Action”的断层；V5.2 结果仍差，说明信息一致性只消除一种实现噪声。 | A/B |
| 显式 context hard limit 与确定性裁剪 | V6 | **保留。** 这是物理接口护栏，不应成为质量门控。质量门控 V6 的 Action/Code fallback 已修复并测试；不能解释其正式性能下降。 | A |

## 六、为什么 V5 成为最强 TraceAAD

V5 的优势可以由一条更完整但仍然克制的因果链解释：

```text
30 个不同起点提供初始覆盖
        ↓
自然语言 Action 和执行契约保证候选供给
        ↓
四个算子在同一主轨迹上提供局部变化与有限跨轨迹变化
        ↓
主/参考历史共享，Action 与 Code 保持同一事实条件
        ↓
Q 主导、P 小权重、UCB 保持访问公平
        ↓
真实 evaluator 决定结果，延迟收缩与同分择简保留有效状态
```

这条链有六个关键性质：

1. **先修复有效搜索空间。** V5.0 的结构化 Action 和执行链会丢候选；V5.1 之后的自然语言 Action、模板契约和失败分类把评价预算重新转成可执行程序。候选供给是机制比较的前提。
2. **历史是条件化上下文。** 主轨迹保存当前程序的真实来时路，双轨迹算子只在本轮引入可追溯参考；删除在线全局经验后，局部事实不再被共享摘要覆盖。
3. **四算子形成互补而非单一风格。** `ideate/refine` 提供沿路线的变化，`synthesize/transfer` 提供受参考约束的迁移和重组。V5 的算子约各占四分之一，使搜索既不完全局部化，也不把一半预算固定给未经验证的跨路线判断。
4. **评分把质量放在趋势之前。** (0.8Q+0.2P) 让已经得到好程序的路线保持机会，P 只提供轻量的继续开发提示，UCB 再补偿低访问路线。它比把成熟度、差异、复杂度和运行时一起塞进资格判断更低耦合。
5. **优势体现为任务组合的折中。** V5 在 CVRP50 和 OP100/200 形成明确优势，虽然不在 TSP 或 OBP C=100 每个单元格领先；正是这种跨任务覆盖使它在单版本平均名次上超过 V4。
6. **复杂度控制不夺取 fitness 主导权。** 完全同分时择短降低 V5 的表示膨胀，同时允许严格更优的长程序保留。它是温和的状态卫生，不是跨任务连续惩罚。

这条链仍有三个未解决问题：V5 的 active endpoint 仍可能因不同历史重复，跨轨迹参考的收益依赖任务，(0.8Q+0.2P) 和四算子配额没有单变量消融。因此正确结论是“V5 当前最强 TraceAAD 组合”，不是“V5 每个细节都已证明最优”。

## 七、其他 TraceAAD 版本为什么不如 V5

### 7.1 V1/V2：历史层和控制层增长快于证据质量

程序图、轨迹、模式、课程、island、Elo、portfolio、novelty 和 Pareto 同时存在时，系统必须用许多代理决定什么值得保存和展示。每个代理都只近似真正目标，组合后却直接决定 evaluator 预算。V2 在 CVRP 改善、TSP 退化，说明复杂系统可以产生局部收益，却没有形成稳定归纳偏置。

### 7.2 V3：删减有效，但算子 UCB 和相似门控仍在替轨迹做过多决定

V3 相对 V2 明显恢复，结果与减法方向一致，但不能归因于某一个删改。剩余问题是算子 reward 混入调用状态，后期强烈集中 endpoint；novelty gate 保护了大量表面不同但几乎全 regress 的 fresh start。它仍没有把“轨迹选择负责去哪、算子只负责怎么改”的职责完全分开。

### 7.3 V5.0：实现缺陷先缩小了候选供给，机制又缩小了状态覆盖

结构化 Action 先丢掉约四成 batch，全局经验一次也未形成，执行链又丢合法程序。即使产生候选，双轨迹 transfer 的重复代码和不同历史同 endpoint 会占 active 席位。这个版本首先是实现失败和资源卫生失败，不能作为双轨迹原理的干净反证。

### 7.4 V5.1/V5.2：修复候选供给后，共享经验与多机制交互仍不稳定

自然语言 Action、执行契约和上下文一致性都得到修复，性能没有在四任务上统一恢复。全局反思从“没运行”变成“运行后把局部误判广播到全部路线”；V5.2 进一步加强历史一致性和趋势评分仍未改善 TSP/CVRP/OBP。问题已经从接口正确性转为机制组合。

### 7.5 V5.3：删除全局经验后成为正式 V5 的关键收口

V5.3 的提升与共享摘要存在风险相符；它在 OP100/200 取得全方法最好，并在正式综合排名中保持最强 TraceAAD 位置。这个结果支持“局部、可追溯的参考交换”比“所有路线共享一份摘要”更适合轨迹搜索，但不能证明收益只来自双轨迹算子。TSP/OBP C=100 仍弱于 V4，说明参考迁移的收益依赖任务结构。

### 7.6 V5.4：迁入 V4 局部机制，没有改善 V5.3 系统

把 `0.6Q+0.4P`、单思想 ideate/refine 和质量优先 reserve 加入 V5 四算子系统后，TSP/CVRP/OBP 退化。它表明机制不是可独立拼装的积木：同一 P 在双轨迹、compact best、同分择简和四算子环境中面对的路线分布已经不同。

### 7.7 质量门控 V6：为了实现“先局部、后多样”加入的代理，反而没有得到局部可靠性

成熟度、路线信用、差异参考和状态调度本意正确，但都依赖手工代理。历史质量门控运行中双轨迹占比很低，ideate/refine 仍产生更大代码步长，LRR 最低、regress 最高。机制没有实现其关键中介目标“围绕优质区域可靠局部改进”，因此没有形成超过 V5 的证据。

### 7.8 正式 Occam V6：方向上回到简单，但把确定性状态卫生也删掉了

删除未经验证的成熟度和差异门槛符合举证责任；删除精确 endpoint 去重则不同。相同代码是否重复是可直接判断的事实，不是主观质量代理。正式 Occam V6 的 OBP 训练出现两次零突破和 active clone 回升，held-out 上 C=100 三个尺度退化，说明“减少控制”必须区分删除弱代理与删除基本不变量。

## 八、MCTS-AHD 与其他方法的机制洞见

### 8.1 MCTS-AHD 为什么值得学习

MCTS-AHD 的关键不是“用了树”三个字，而是把搜索预算分解成了明确的选择、扩展和回传过程：

1. **渐进扩展。** 节点只有在访问次数达到 `N^alpha` 时才增加子节点，避免一开始把预算平均撒到大量路线；这与 V5 的固定 active 池形成鲜明对照。
2. **UCT 的探索压力随剩余预算下降。** 代码用 `lambda_0(1-n/B)` 缩小探索项，早期扩大覆盖，后期集中高价值分支。这个阶段性预算规则比静态等概率算子更直接地回答“什么时候探索、什么时候利用”。
3. **算子职责分层。** `m1` 做单路线结构变化，`m2` 做参数和方程层面的局部变化，`e2` 在两个候选之间提取共同思想，`s1` 汇总一条路径上的多个思想。实际主循环权重为 `e1=0,e2=1,m1=2,m2=2,s1=1`，过程接受样本约为 19%/31%/31%/14%；它把“新结构、参数修正、双候选重组、路径综合”分开，比让一个统一算子同时承担所有变化更容易分析。
4. **路径级信用。** 子代结果沿父链回传，祖先的 Q 由子树最好值更新，UCT 再依据 Q 和访问数选下一条路线。即使这种 max-backprop 不完全符合稳定的 MCTS 价值假设，它仍为 LLM 搜索提供了清晰的路线预算集中机制。
5. **代码后再做思想对齐。** 每个有效生成先得到代码，再用第二次 LLM 调用根据代码重述设计思想。这样记录的描述更接近实际程序，而不是只保存生成前的声明；代价是 MCTS-AHD 平均约 2.06 次 LLM 调用/样本，高于 TraceAAD 约 1.49 次，优势不能与架构完全分离。

过程数据支持“高可靠局部开发”这一解释：MCTS-AHD 的 LRR 为 0.249，明显高于 V5 的 0.136；但严格突破率只有 0.113，低于 TraceAAD。它可能依靠更强的路线复用和高质量分支保留，而不是频繁刷新全局 best。正式结果中它在 CVRP 和 OBP C=500 领先，说明该策略对需要稳定构造和参数调整的任务特别适配。

需要保留的限制有三点：max-backprop 会把后代最好值直接归给祖先，无法区分父代质量和具体算子贡献；人口生存按唯一 objective 和 top fitness 保留，可能丢掉同分但有不同知识的路线；更高的 LLM 调用预算是重要混杂因素。因此应学习“渐进扩展 + 动态探索压力 + 分层算子”，不应直接复制完整 MCTS 价值回传。

### 8.2 其他方法的可借鉴点

| 方法 | 过程/结果事实 | 对 TraceAAD 的启示 |
| --- | --- | --- |
| PathWise | LRR 0.334 最高，但平均新颖性仅 0.020、有效边均值约 83，最终排名低于 MCTS/V5 | 可靠小步改进值得学习；但必须同时保护新的可执行状态和足够预算，不能把局部 improve 当成长期价值 |
| ShinkaEvolve | LRR 0.288、PCD 0.196，但严格突破 0.092，OBP 三重复全部零突破 | 多策略和大变化如果没有路线信用，会产生局部修补而不是前沿推进 |
| EoH | 在 CVRP/OP 部分尺度接近前列，生成操作简单；缺少完整父子日志 | 简单的多类生成操作仍有竞争力，先做可解释、可记录的算子组合，再增加反思层 |
| ReEvo | 使用交叉、mutation 和反思，但最终平均排名较低，过程父子日志不足 | 反思文本和交叉本身不是收益证明；必须记录条件、父代、结果和后续贡献 |
| MCTS-AHD | 总体第一，LRR 高于 TraceAAD，严格突破率反而较低 | 重点学习预算集中和路线级信用，而非追求更高新颖性或更复杂历史 |

这些方法共同说明：**局部可靠性、变化幅度、全局突破和最终泛化是四个不同变量。** V5 的位置是用适中的 PCD 和较低 regress 换取跨任务平衡；MCTS-AHD 则用更高 LRR 和更强路线预算集中换取总体领先。

### 8.3 对基于轨迹搜索的洞见

1. **轨迹最可靠的价值是条件化上下文，不是一个更复杂的总分。** 历史首先帮助 LLM 理解当前程序如何形成；它是否值得继续繁衍，应主要由真实成果和少量访问公平决定。
2. **轨迹身份、知识多样性和可执行状态多样性是三个不同对象。** 同一代码可以有不同历史，这些历史值得记录，但不应自动占多个父代席位。
3. **更多历史不等于更多有效信息。** 跨轨迹 action、课程和全局摘要只有在适用条件可靠时才有价值；否则会扩大 prompt，同时缩小实际候选空间。
4. **局部改进率不是最终目标。** V5 的 LRR 高于 V4，Shinka/PathWise 的 LRR 又高于全部 TraceAAD，最终性能却更差。真正值得优化的是严格全局突破及其 held-out 转化。
5. **多样性必须问“在哪里、以什么状态、付出多少预算”。** 大代码距离、fresh start 或不同轨迹 ID 都不能单独证明有效探索。V5 的四算子、两条 sibling Action、30 个起点和延迟收缩提供了比 V4 更完整的变化组合，但跨轨迹参考仍会产生重复。
6. **LLM 是强 proposal model，控制器应保持克制。** 人工门控越多，越容易把模型本可利用的开放历史变成狭窄资格规则。控制器应负责事实、预算和不变量，把算法判断尽量留给 LLM 与 evaluator。
7. **复杂度适合做完全同分时的状态卫生，不适合作为跨任务连续价值。** V4 证明长程序可以很强，V5 又证明短程序也能很强；长度本身不是质量。
8. **简单机制的优势来自低耦合。** V5 的主轨迹、参考轨迹、算子、评分和生存规则仍然各自承担局部职责；它比 V4 多了跨轨迹变化，但没有重新引入在线全局摘要。后续版本的失败多发生在同一代理跨层控制多个环节时。

## 九、当前最值得做的最小消融

以下顺序用于区分 V5 的真实贡献，并检验 MCTS-AHD 可借鉴机制，不要求立即启动实验：

1. **V5 历史消融：** 原历史、打乱历史、只给当前程序。它直接检验 TraceAAD 核心主张。
2. **V5 评分消融：** `Q-only`、`0.8Q+0.2P`、`0.6Q+0.4P`、去掉 UCB。固定四算子、上下文和种群。
3. **V5 算子组合消融：** `ideate/refine` 与四算子比较，保持其它机制不变，报告任务分层结果而不是只看总平均。
4. **V5 参考消融：** 无参考、Q 参考、Q×差异参考，检验 synthesize/transfer 的条件收益与重复代价。
5. **V5 状态卫生消融：** 只恢复精确 endpoint 去重，不恢复成熟度、路线信用或语义差异门槛；优先在 OBP 和 OP 做三重复。
6. **MCTS 预算消融：** 在 V5 上加入渐进扩展与剩余预算衰减的 UCT，保持总 evaluator 数和 LLM 调用上限一致，比较路线覆盖、后半程突破与 held-out。
7. **MCTS 信用消融：** max-backprop、均值回传和只回传父子增量三种方式，区分树结构收益与价值回传偏差。

每项至少报告：三重复 held-out、严格突破率、首次/后半程突破、active 唯一 endpoint、父代质量、算子有效候选、LOC 与 evaluator/LLM 调用成本。没有单变量对照前，不再用新版本联合修改替代因果判断。

## 十、最终诊断

当前证据最支持的结论是：

> MCTS-AHD 是当前总体第一，V5 是最强 TraceAAD。V5 的净优势来自一套低耦合的组合：严格匹配的轨迹上下文、四个分工明确的语义算子、可追溯的局部跨轨迹参考、Action/Code 共享历史、质量主导的路线选择，以及温和的同分择简。它把轨迹作为条件化证据，而没有让共享摘要、成熟度或差异代理同时接管所有搜索决策。

V5 首版确有严重实现问题；这些问题修复后，V5.3 的直接参考和无全局摘要成为最有解释力的收口方向。V4 的高突破率仍是重要过程事实，但它不能覆盖 V5 在任务组合上的优势。正式 Occam V6 证明简单化也需要保留确定性状态卫生；MCTS-AHD 则表明，预算集中、渐进扩展和分层算子可能比单纯增加新颖性更有价值，但其额外 LLM 调用和 max-backprop 必须在受控实验中拆开。

基于轨迹的搜索下一步不需要更多层。它需要更严格地区分：**记录全部历史、展示匹配历史、繁衍不同状态、把预算集中到可继续发展的路线、用真实 held-out 结果检验价值。**
