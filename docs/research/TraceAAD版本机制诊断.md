# TraceAAD 版本机制分析：V5 相对优势的来源与 MCTS-AHD 领先的条件

## 一、研究问题

TraceAAD 将算法改进建模为由中间方案构成的连续过程。每个中间方案包含当前程序、形成路径、已尝试修改及其结果。本分析围绕三个问题展开：

1. TraceAAD 的版本演化是否形成了稳定的性能和过程差异？
2. V5 相对于 V4 和 Occam V6 的优势，最可能由哪些机制组合解释？
3. MCTS-AHD 的领先中，哪些部分可能迁移到 TraceAAD，哪些部分仍受到预算和实现差异的混杂？

## 二、证据与协议

### 2.1 证据强度

本文采用三级证据标记。A 级表示代码、配置、日志或实验工件可以直接核对，用于判断机制是否执行、候选是否被丢弃以及状态是否重复。B 级表示同协议三重复或跨任务分析出现方向一致的现象，用于描述经验关联。C 级表示由机制原理和关联证据提出的解释，尚无单变量消融支持。

这些等级约束因果表述。算子出现在最终路径中，只能证明它参与了该路径；较高的过程指标只描述过程；联合版本差异也不能分离各项修改的独立作用。缺少单变量对照的解释均标为机制推断或可证伪假设。

### 2.2 分析材料

分析材料包括当前实验结果汇总；36 个同模型、同预算、同任务配置的 V4/V5/V6 运行；96 个跨方法运行；V4、V5、V6 的方法规范；MCTS-AHD 的实现文件和参数配置；V4 机制审计、V5 开发复盘和 V6 开发复盘；以及 V2/V3、V5 和 V6 的历史实验工件。历史代码与文档快照包括 V3 前的 `d79c4a5e^`、V5.1 的 `634f474`、V5.2 的 `8fd1d0e`、V5.3 的 `bb40ff0`、V5.4 的 `3035b01`、质量门控 V6 的 `d4cf664` 和 V6 的 `fde9129`。

## 三、观察结果

### 3.1 从 V1 到 V4：控制复杂度与结果稳定性

下表报告同一 held-out 口径中的 OOD 指标，数值越低越好。V1/V2 的 OP 使用 `orienteering_construct`，V4 以后使用 `op_aco`，因此两组数值不能直接串联。V1/V2/V3 也没有当前四任务的完整同协议覆盖，以下结果用于解释机制演化，而不用于宣称四任务总排名。

| 版本 | 主要机制 | TSP200 | CVRP100 | 结果解释 |
| --- | --- | ---: | ---: | --- |
| V1 | 模式记忆、六算子、自适应 portfolio、Elo/成对比较、island、novelty gate、Pareto 生存 | 12.306 | 15.955 | 已具备竞争力，但控制层较多，结果波动较大 |
| V2 | 加入经验记忆、精英课程、复杂度/运行时价值和 simplify | 12.939 | 15.811 | CVRP 改善而 TSP 退化，新增知识层未产生跨任务稳定收益 |
| V3 | 收缩为 `Q/P/D + UCB`、四算子 UCB、跨轨迹 Action、相似门控和 160 条 active | 12.128 | **15.399** | 相比 V2 回升，与控制层收缩的方向一致，但不能归因于单个删改 |
| V4 | 30 个起点、两算子、单轨迹上下文、`0.6Q+0.4P`、30→60→30 | **11.886** | 15.414 | TSP 进一步改善，CVRP 与 V3 基本持平，在两个可比指标上较稳定 |

**观察。** 控制层增加没有对应单调收益。V2 在 CVRP 上改善而在 TSP 上退化，V3 收缩控制层后回升。由于各版本同时改变多个组件，这组结果只能支持“额外控制可能引入失配”的解释，不能识别具体组件的独立作用。

下表为 held-out 三重复均值。TSP、CVRP 和 OBP 越低越好，OP 越高越好。V5 对应移除在线全局经验后的 V5.3；V6 指 Occam V6，质量门控 V6 仅用于机制对照。

| 任务 | V4 | V5 | Occam V6 | 观察 |
| --- | --- | --- | --- | --- |
| TSP50/100/200 | 6.040 / 8.504 / 11.886 | 6.187 / 8.569 / 12.047 | **5.957 / 8.285 / 11.881** | V6 均值最好，但标准差高于 V4 |
| CVRP50/100 | 9.129 / 15.414 | **9.039 / 15.428** | 9.189 / 15.632 | V5 略优，V6 回退 |
| OP50/100/200 | 15.069 / 30.217 / 53.509 | **15.112 / 30.711 / 55.793** | 14.958 / 29.706 / 52.016 | V5 在总体任务组合中更有利，V6 低于 V4/V5 |
| OBP 1k/5k/10k, C=100 | **413.6 / 2023.6 / 4037.3** | 415.5 / 2050.1 / 4093.4 | 422.1 / 2071.5 / 4131.1 | V4 全面领先，V6 明显退化 |
| OBP 1k/5k/10k, C=500 | 81.33 / 403.13 / 805.13 | 81.20 / 403.60 / 805.53 | **80.80 / 402.87 / 805.20** | V6 接近前列，但 C=100 的代价明显 |

**观察。** Occam V6 在 TSP 上获益，在 CVRP、OP 和 OBP C=100 上退化，因而跨任务结果不支持“越简越好”的一般结论。若每次只选择一个 TraceAAD 版本与五个外部基线比较，14 个规模的平均名次为 V5（2.143）> V4（2.500）> V6（3.143）；相对于五个外部基线的平均名次优势分别为 V5 的 +1.629、V4 的 +1.200 和 V6 的 +0.429。在八方法同场比较中，MCTS-AHD 的平均名次为 2.536，排名第一，V4 与 V5 并列第二。两种比较包含的方法集合不同，因此 2.143 与 2.536 不是同一量纲。现有排名支持 MCTS-AHD 总体第一、V5 最接近这一描述。

### 3.4 过程指标

历史过程批次中的指标如下。它们用于描述搜索过程，不替代当前版本的 held-out 结果。

| 指标 | V4 | V5 | 质量门控 V6 | 解释 |
| --- | ---: | ---: | ---: | --- |
| 严格突破窗口率 | **0.166** | 0.151 | 0.145 | V4 更常刷新全局 best，但这不等价于更高的跨任务平均排名 |
| LRR：被接受子代严格优于父代 | 0.116 | **0.136** | 0.104 | V5 的局部 proposal 更可靠 |
| 父子代码距离 PCD | 0.086 | 0.085 | **0.151** | V6 的修改步长约为 V4/V5 的 1.8 倍 |
| regress 占比 | 68.4% | 61.6% | **74.0%** | V6 的较大步长伴随较低的局部可靠性 |
| 平均新颖性 | 0.081 | 0.058 | **0.107** | 新颖性本身没有带来更好的结果 |
| 首次严格突破窗口 | **2.9** | 10.5 | 9.6 | V4 更早进入可继续推进的区域 |

跨八方法分析中，严格突破率是唯一具有稳健正相关的过程信号；LRR、PCD 和平均新颖性不能单独预测最终性能。因此，V5 较高的 LRR 表示其局部变化较可靠，但不能单独解释总体排名。最终结果还取决于这些变化在不同任务上的收益分布。

### 3.5 Occam V6 与状态重复

Occam V6 删除了成熟度、路线信用、差异门槛、固定双轨迹比例、精确 endpoint 去重和多层 survivor，仅保留 `Q+UCB`、四算子等概率、global-best route 与 Q-softmax 生存。OBP 过程对照如下：

| 协议 | 三次训练 best | 严格突破次数 | 最终 active 唯一 endpoint |
| --- | --- | --- | --- |
| 质量门控 V6 | -724.25 / -738.50 / -726.00 | 6 / 1 / 14 | 45/45、49/53、54/54 |
| Occam V6 | -725.75 / **-744.50 / -744.50** | 9 / **0 / 0** | 50/58、**35/56、29/57** |

**观察。** Occam V6 的两个 OBP 运行中，best 保持在初始化 seed，active 中则保留了大量轨迹身份不同但 endpoint 相同的状态。V5.0 最终 active 中的唯一 endpoint 也仅占 52%–80%，所以该重复并非 V6 独有。Occam V6 的 held-out 结果在 capacity=100 的三个尺度上均差于 V4/质量门控 V6，同时 TSP 均值最好。

**机制解释。** 简化协议可以在部分任务获益，但删除精确去重会让不同轨迹身份占用原本可分配给不同可执行状态的繁衍位置。精确状态去重是可直接判定的不变量，其构造效度不同于未经验证的语义门控。去重是否提高 held-out 仍需单变量实验。

## 四、机制解释

### 4.1 分析框架

本分析以单位评价预算产生的有效信息为机制评价对象。有效信息包括更好的可执行程序、对具体方向的可靠排除、可继续发展的新状态，或能够改变后续选择的证据。新增轨迹 ID 本身不代表获得了新信息。

TraceAAD 的功能分为四层。事实记录保存程序、修改和评价；上下文构造呈现与当前锚点匹配的历史；状态管理维护有限且彼此有差异的可执行程序；路线选择分配后续预算。V5 在保持这些边界的同时允许有限的跨轨迹知识交换。版本间的机制风险主要来自层次混合：轨迹身份被当作状态多样性，局部回弹被当作长期信用，表面代码差异被当作功能互补，共享摘要被当作普遍适用的事实。

以下各表采用四列结构。“与轨迹假设一致”表示机制与 TraceAAD 的核心信息结构相符；“效应与其他修改耦合”表示已有结果无法分离该机制的独立作用；“构造效度不足”表示代理指标与目标概念之间缺少充分对应；“已确认的实现问题”表示代码或运行记录已直接显示接口或执行失败；“删减越界”表示简化操作删除了确定性状态不变量。

### 4.2 上下文与轨迹信息

TraceAAD 以历史作为当前程序的条件化证据。严格匹配的当前程序、祖先和修改结果记录当前状态如何形成；脱离当前锚点的摘要可能把局部经验推广到不适用的路线。现有证据支持这种信息结构的语义合理性，但尚未直接证明历史优于 current-code-only。

### 4.3 算子、状态管理与轨迹利用

算子机制需要同时回答两个问题：它改变了什么，以及它是否把预算分配到有意义的状态。早期版本将算子能力、状态难度和新颖性混合估计，导致控制器难以解释。V4 以后，单轨迹局部修改成为较稳定的基线；V5 在此基础上加入跨轨迹参考，但也引入了参考适用性和状态重复问题。

| 机制 | 版本 | 分析 | 证据等级 |
| --- | --- | --- | --- |
| OperatorPortfolio、preview 与 EMA reward | V1/V2 | 构造效度不足。估计量混合了算子能力与被分配状态的难度；backtrack 天然处理困难状态，novelty 又没有明确父代，平均 reward 难以直接比较。 | A/C |
| 四算子 UCB | V3 | 改变了选择分布，但尚未证明改善结果。4,975 次选择后期集中为 endpoint 73.6%、novelty 1.3%，四算子 best 命中率仅 3.1%–3.9%，且跨任务排序不稳定。 | A/B |
| `ideate/refine` 等概率 | V4 | 与轨迹假设一致。两种算子都围绕同一来时路修改，减少了参考选择和算子信用误差；其独立贡献尚无单变量消融。 | B/C |
| `synthesize/transfer` 双轨迹算子 | V5+ | 能够产生跨路线变化，但稳定性受限。V5.0 最强 TSP 路径含 13 次 synthesize 和 5 次 transfer；transfer 父子同代码率为 16.8%–24.9%，后半程最高 35.3%。 | A/B |
| 四算子等概率 | V5/V6 | 名义上的算子公平不等于有效预算公平。不同算子的 Action 通过率不同，弱参考或相似参考会浪费 evaluator 机会；V6 的两个 OBP 零突破 run 中四算子仍各约占四分之一。 | A/B |
| V5.4 的局部 refine 提示 | V5.4 | 效应与其他修改耦合。恢复 V4 的趋势权重和局部提示后，TSP/CVRP/OBP 均退化，说明局部语义不能脱离完整 V5 环境评价。 | B |
| 成熟度门控与路线信用 | 质量门控 V6 | 未实现其预期中介机制。双轨迹占比约 14%，但总体 PCD 仍为 0.151，LRR 最低、regress 最高，说明代理没有将搜索稳定在可靠的局部区域。 | A/B |
| 极简四算子指令 | V6 | 与其它删改产生交互。TSP 获益而 CVRP、OP 和 OBP C=100 回退，提示放开动作空间的收益依赖状态卫生和选择机制。 | A/B/C |
| 初始种群从 4 增至 30 | V4+ | 可能扩大初始可执行状态覆盖并降低早期偶然性，但 V4/V5/V6 之间相同，不能解释三版本差异。 | A/C |
| 30→60→30 延迟管理 | V4+ | 与延迟评价的逻辑一致。新路线先进入父代池可避免即时淘汰，但不能保证每条新路线获得最低试用机会。 | A/B |
| 精确 endpoint 去重 | 质量门控 V6 | 状态卫生有效，独立价值尚未确定。OBP 中 active 唯一率为 45/45、49/53、54/54；应与成熟度和语义差异门槛分开评价。 | A/B |

### 4.4 评分、复杂度与实现有效性

路线评分的作用是分配有限的后续评价预算，而不是替代真实 evaluator 判断程序质量。V2 的多代理评分和 V3 的多指标混合都扩大了控制器的解释负担；V4–V6 将结果质量作为核心，V5 再以较小权重引入趋势信息，这一结构与其跨任务表现相容，但尚未得到单变量验证。

### 4.5 V5 相对优势的解释

V5 的相对优势与一个低耦合机制组合相容。30 个不同起点提供初始状态覆盖；自然语言 Action 和执行契约减少格式与执行链路造成的候选损失；四个算子围绕同一主轨迹产生局部修改和有限的跨轨迹变化；Action 与 Code 共享主轨迹和参考轨迹历史；`0.8Q+0.2P` 以结果质量为主；UCB 只补偿父代访问；延迟收缩和同分择简分别保护状态机会与表示简洁性。

该解释包含六个相互关联的性质：

1. 候选供给是机制比较的前提。V5.0 的结构化 Action 和执行链路问题缩小了有效搜索空间，V5.1 之后的修复使评价预算重新对应可执行程序。
2. 轨迹历史作为条件化上下文保留当前程序的形成过程。V5.3 删除在线全局摘要后，局部事实不再被一份共享摘要覆盖。
3. `ideate/refine` 与 `synthesize/transfer` 分别提供局部变化和有限迁移。
4. 质量主导的评分减少了成熟度、差异、复杂度和运行时等弱代理对路线资格的共同控制。
5. V5 的优势来自任务组合上的折中，并非每个任务的单点领先。
6. 同分择简限制保留表示的膨胀，同时维持真实 fitness 的主导地位。

这一解释有三个边界：V5 的 active endpoint 可能因不同历史而重复；跨轨迹参考的收益依赖任务结构；`0.8Q+0.2P` 与四算子配额缺少单变量消融。现有证据支持“V5 是当前最强的 TraceAAD 组合”，但不支持其每个组成部分均为最优。

### 4.6 其他版本与外部方法

V1/V2 同时引入程序图、轨迹、模式、课程、island、Elo、portfolio、novelty 和 Pareto 生存，多种代理共同决定保存与展示。V2 的 CVRP 改善与 TSP 退化说明该组合可以产生局部收益，但没有形成稳定的跨任务结果。V3 的控制收缩与结果回升方向一致；其算子 UCB 仍受状态难度影响，novelty gate 保护的大量 fresh start 表面不同但几乎全部 regress。

V5.0 受到结构化 Action、未运行的全局经验和执行链路问题影响，无法单独检验双轨迹机制。V5.1/V5.2 修复候选供给后，共享经验广播了局部误判，多机制组合仍未在四任务上统一恢复。V5.3 删除全局经验后成为当前 V5；这一结果与局部、可追溯参考优于无条件共享摘要的解释相容。V5.4 同时迁入 V4 的评分和局部提示后退化，表明机制效果依赖状态分布。质量门控 V6 的成熟度、路线信用和差异参考没有形成预期的可靠局部改进。Occam V6 进一步删除精确去重，显示状态卫生与语义门控具有不同的构造效度。

MCTS-AHD 有三项可能迁移的搜索结构。其一，节点达到 `N^alpha` 的访问阈值后才渐进扩展，限制预算的早期分散。其二，UCT 探索项按照 `lambda_0(1-n/B)` 随剩余预算下降，使搜索从早期覆盖转向后期利用。其三，`m1`、`m2`、`e2` 和 `s1` 分别承担单路线结构变化、参数层变化、双候选共同思想提取和路径综合；过程接受样本约为 19%/31%/31%/14%，主循环权重为 `e1=0,e2=1,m1=2,m2=2,s1=1`。MCTS-AHD 还沿父链回传子代结果，使路线预算向高价值分支集中。其过程 PCD 为 0.193、平均新颖性为 0.135，均高于 V5，但这些指标不能识别最终收益来源。

过程数据与“高可靠局部开发”的解释一致：MCTS-AHD 的 LRR 为 0.249，高于 V5 的 0.136；严格突破率为 0.113，低于 TraceAAD。路线复用和高质量分支保留可能解释其总体优势。替代解释包括 max-backprop 将后代最好值归给祖先、人口生存丢弃具有不同知识的同分路线，以及平均 LLM 调用成本更高。现阶段优先检验渐进扩展、动态探索压力和分层算子，不直接采用完整价值回传机制。

其他方法也显示局部可靠性、变化幅度、全局突破和最终泛化彼此不同。PathWise 的 LRR 为 0.334，平均新颖性仅 0.020，有效边均值约 83，最终排名低于 MCTS-AHD 和 V5。ShinkaEvolve 的 LRR 为 0.288、PCD 为 0.196，严格突破率为 0.092，OBP 三次重复均无突破。EoH 在 CVRP/OP 的部分尺度接近前列，但缺少完整父子日志。ReEvo 的交叉、mutation 和反思也没有提供独立收益证据。这些观察说明局部改进率不能替代全局突破及其 held-out 转化。

## 五、局限与替代解释

- 当前版本比较主要基于联合修改。V5.3 和 Occam V6 揭示系统层面行为，但不能识别 `0.8Q+0.2P`、四算子配额、历史长度、50/50 锚点或 UCB 系数的独立作用。V5.4 的退化也可能来自机制与状态分布的交互。
- held-out 结果采用三重复。该规模可描述方向性差异，但不足以稳定归因所有任务、规模和机制交互。现有分析没有用统计检验完全分离相邻版本差异与运行方差，平均名次应视为描述性证据。
- MCTS-AHD 与 TraceAAD 的计算成本不同。MCTS-AHD 每个样本约使用 2.06 次 LLM 调用，TraceAAD 约使用 1.49 次。搜索控制、思想对齐调用和原始实现差异共同影响结果；在 evaluator 数和 LLM 调用上限同时统一前，不能把总体领先归因于树结构。
- LRR、PCD、新颖性和路线信用均为搜索质量的间接代理。跨八方法分析中，只有严格突破率显示稳健正相关。较高的局部可靠性或更大的代码距离不保证更好的 held-out 泛化。
- 过程批次来源不完全一致。V4、V5 和质量门控 V6 的过程指标不能替代 Occam V6 的 held-out 结果，历史质量门控批次与当前 Occam V6 的状态管理也不同。过程指标只作为机制解释的辅助证据。
- 任务覆盖限于 TSP、CVRP、OP 和 OBP 的若干规模。V5 在 CVRP50 和 OP100/200 上表现突出，在 TSP 和 OBP C=100 上不领先。“V5 是最强 TraceAAD”只表示当前任务集合上的综合名次最优。
- active endpoint 重复可能浪费繁衍预算，也可能保留对后续生成有用的不同历史条件。现有观察确认状态重复，但没有直接比较这两种效应。

## 六、决定与下一步实验

后续实验采用单变量设计，并保持其它机制、模型、任务、预算和评价口径不变：

1. **历史条件消融。** 比较原始匹配历史、打乱历史和仅提供当前程序，直接检验轨迹上下文是否产生增益。
2. **路线评分消融。** 比较 Q-only、`0.8Q+0.2P`、`0.6Q+0.4P` 和去掉 UCB 的结果，固定四算子、上下文和种群。
3. **算子组合消融。** 比较 `ideate/refine` 与四算子，保持其余设置不变，并报告任务分层结果。
4. **参考机制消融。** 比较无参考、Q 参考和 Q×差异参考，检验跨轨迹参考的条件收益及其重复代价。
5. **状态卫生消融。** 仅恢复精确 endpoint 去重，不恢复成熟度、路线信用或语义差异门槛，优先在 OBP 和 OP 上进行三重复。
6. **MCTS 预算消融。** 在 V5 上加入渐进扩展和剩余预算衰减的 UCT，并同时约束 evaluator 数和 LLM 调用上限，以区分预算分配与模型调用成本。
7. **MCTS 信用消融。** 比较 max-backprop、均值回传和仅回传父子增量，区分树结构收益与价值回传偏差。

每项实验至少报告三重复 held-out 结果、严格突破率、首次突破与后半程突破、active 唯一 endpoint、父代质量、算子有效候选率、LOC，以及 evaluator 和 LLM 调用成本。单变量对照完成前，联合版本结果仍作为系统表现证据，不用于单项机制归因。

## 七、当前决定

当前结果页继续采用以下判断：MCTS-AHD 是当前比较中的总体第一，V5 是最强的 TraceAAD 版本。V5 的结果与一个低耦合机制组合相容：严格匹配的轨迹上下文把历史作为条件化证据，四类算子提供局部修改与有限迁移，Action 与 Code 共享事实条件，评分以结果质量为主，同分择简改善保留状态的表示。

该判断保留三项限制：V5 的组成机制尚未逐项完成单变量验证；Occam V6 的结果支持保留确定性状态卫生；MCTS-AHD 的领先仍混有更高 LLM 调用成本和 max-backprop 的影响。下一阶段区分四项职责：完整记录历史，展示与当前状态匹配的历史，维持彼此不同的可执行繁衍状态，将有限预算分配给具有继续发展潜力的路线。最终判断以统一成本下的 held-out 结果为准。
