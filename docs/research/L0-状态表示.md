# L0 状态表示

> 层次：表示。状态：持续。入口见 [README](README.md)。历史索引见 [RQ-008](RQ-008-V9.2底层反思与下一版轨迹闭环.md)。

## 当前判断

TraceAAD 控制的是下一次算法生成的条件，以及这些条件所在的搜索过程如何获得预算。V9.7 在线状态保存程序、锚点和 root route；算法簇只作诊断。V9.8 新增由生成意图定义的 hypothesis 标记，用来把 Explore 开启的新方向与 root provenance 分开。其严格含义是 Explore-initiated trajectory segment，仍不等于真实算法簇，也不自动拥有预算权利。[V9.9](../methods/TraceAAD-v9.9完整机制设计.md) 取消在线 hypothesis 与 route 信用，只保留带匹配来时路的锚点。同一代码、不同来时路仍是不同生成状态；程序副本数只记录、不在线摊还概率。

## 对象

给定语言模型、评价器和有限预算，系统操作四类在线对象：

- **程序**：评价器执行过的一份代码，带真实适应度。搜索内部使用越大越好的有向质量 $q$。
- **锚点**：程序在一条具体形成路径中的位置。它绑定当前程序、结构父节点、到达该节点的那次生成，以及已从该位置发起的生成次数。同一代码、不同来时路是不同锚点。
- **路线**：同一初始根衍生的全部锚点。它是生成拓扑上的来源单位，不必对应不同算法思想。
- **生成事件**：一次选择后的意图、Idea、实际代码变化、有效性和质量变化。只有完成后的事实进入后续上下文。

**算法簇**目前不是在线对象。它是诊断用的语义单位：一组共享核心机制、因而可能共享性能上限和局部可改进性的程序。[待验证] 轨迹作为程序序列 $x_0\to x_1\to\cdots$ 仍然必要；更有信息的运动是族内停留与跨族切换。路线身份是拓扑，簇身份是语义。代码不同不等于簇不同。静态代理尚不足以支持在线 family classifier，root route 也不能直接视为 bandit arm。

**Hypothesis 标记**是 [V9.8 规范](../methods/TraceAAD-v9.8完整机制设计.md)中的在线轨迹分段：root 创建初始化特例，Refine child 继承标记，有效新 Explore child 启动子分段。它让分配层能够按 Explore boundary 聚合当前前沿、operator 投入和历史发展观测，又避免在证据不足时引入在线 family classifier。Hypothesis 没有 probe、ticket 或生命周期状态；是否继续投资由每一步的 allocation 分数重新决定。Stage P 已确认 Explore 更常改变静态机制代理，因而该操作边界有行为依据；它是否与真实算法区域一致、是否比 route 更适合聚合分配状态仍待验证。

当前方法规范见 [V9.7 §2](../methods/TraceAAD-v9.7完整机制设计.md)。

## 事实层与决策视图

轨迹有两层，不可互换：

- **事实层**：程序、父子关系、声明的 Idea、实际修改、有效性、评价结果和发生顺序。应完整、可追溯。
- **决策视图**：从事实中抽出的有限上下文，用于说明当前程序怎样形成、哪些结果与下一步有关。允许有损压缩，但规则必须明确。

Idea 是语义标签；实际修改由父子 evaluator input 决定。两者不一致时，以代码事实为准。“代码相同”不意味着下一步生成条件相同。

## 决策粒度

历史可以很长，不意味着一次选择后应连续生成多步。V9.3 把历史长度与决策粒度绑成三步 rollout，同时改变了预算事件。V9.4 起恢复为：一次选择、一次 `Idea + Code`、一次评价、一次更新。该粒度沿用至 V9.7。

历史长度、生成步数和预算结算方式应分别研究。联合改变三者会使结果无法归因。V9.8 继续保持原子粒度：一次选择只决定当前一个 operator 与锚点，每次模型响应后立即更新和重选，不预先锁定后续预算。版本事实见[V1–V9.4 机制诊断](../analysis/TraceAAD-V1-V9.4机制诊断.md)。

## 仍约束后续层次的原则

1. 终局目标是 best-at-budget 与 held-out，不是一步平均质量。
2. 锚点保持可执行：当前代码和真实 fitness 是生成与比较的基础。
3. 进入上下文的事实必须来自当前锚点的真实形成过程。
4. 一份预算对应一次可审计事件。
5. 非单调形成过程应保留为事实，但不能自动获得正信用。
6. 根、深度和访问集中只描述生成来源；路线覆盖若要成为科学变量，需要行为或语义证据。

## 开放缺口

- 静态机制代理已显示每次 8 roots 只有 2–3 个宏簇，且 9/12 个最终程序改变根宏簇；该代理仍不是行为簇或双盲语义标签。
- 代码哈希和谱系身份不能证明路线之间存在算法语义差异。
- Explore-defined hypothesis 可能发生两类构念误差：Explore 没有真实换簇，或 Refine 实际完成换簇。V9.8 必须离线报告二者。
- V9.8 的边界宽限只是随 Refine 投入衰减的评分 prior，不保证新 hypothesis 获得固定续段；强制 child-chain 或 hypothesis-level continuation 只属于离线测量协议。
- 行为级归因仍开放：紧凑实际修改提高了可审计性，但不提供行级因果。
- 跨路线复用哪些对象、怎样保留来源，见 [L3](L3-单步生成.md)。
