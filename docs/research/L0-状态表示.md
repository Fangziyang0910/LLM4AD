# L0 状态表示

> 层次：表示。状态：持续。入口见 [README](README.md)。历史索引见 [RQ-008](RQ-008-V9.2底层反思与下一版轨迹闭环.md)。

## 当前判断

TraceAAD 控制的不是固定动作集合上的最高分节点，而是下一次算法生成的条件，以及这些条件所在的搜索过程如何获得预算。在线状态保存可执行程序和它的形成过程。算法簇是诊断用的语义单位，目前不进入搜索状态。

## 对象

给定语言模型、评价器和有限预算，系统操作四类在线对象：

- **程序**：评价器执行过的一份代码，带真实适应度。搜索内部使用越大越好的有向质量 $q$。
- **锚点**：程序在一条具体形成路径中的位置。它绑定当前程序、结构父节点、到达该节点的那次生成，以及已从该位置发起的生成次数。同一代码、不同来时路是不同锚点。
- **路线**：同一初始根衍生的全部锚点。它是生成拓扑上的来源单位，不必对应不同算法思想。
- **生成事件**：一次选择后的意图、Idea、实际代码变化、有效性和质量变化。只有完成后的事实进入后续上下文。

**算法簇**目前不是在线对象。它是诊断用的语义单位：一组共享核心机制、因而可能共享性能上限和局部可改进性的程序。[待验证] 轨迹作为程序序列 $x_0\to x_1\to\cdots$ 仍然必要；更有信息的运动是族内停留与跨族切换。路线身份是拓扑，簇身份是语义。代码不同不等于簇不同。在簇结构被读出之前，不要把路线直接当成 bandit 的臂。

当前方法规范见 [V9.7 §2](../methods/TraceAAD-v9.7完整机制设计.md)。

## 事实层与决策视图

轨迹有两层，不可互换：

- **事实层**：程序、父子关系、声明的 Idea、实际修改、有效性、评价结果和发生顺序。应完整、可追溯。
- **决策视图**：从事实中抽出的有限上下文，用于说明当前程序怎样形成、哪些结果与下一步有关。允许有损压缩，但规则必须明确。

Idea 是语义标签；实际修改由父子 evaluator input 决定。两者不一致时，以代码事实为准。“代码相同”不意味着下一步生成条件相同。

## 决策粒度

历史可以很长，不意味着一次选择后应连续生成多步。V9.3 把历史长度与决策粒度绑成三步 rollout，同时改变了预算事件。V9.4 起恢复为：一次选择、一次 `Idea + Code`、一次评价、一次更新。该粒度沿用至 V9.7。

历史长度、生成步数和预算结算方式应分别研究。联合改变三者会使结果无法归因。版本事实见[版本谱系](../analysis/TraceAAD-版本实验事实与机制诊断.md)。

## 仍约束后续层次的原则

1. 终局目标是 best-at-budget 与 held-out，不是一步平均质量。
2. 锚点保持可执行：当前代码和真实 fitness 是生成与比较的基础。
3. 进入上下文的事实必须来自当前锚点的真实形成过程。
4. 一份预算对应一次可审计事件。
5. 非单调形成过程应保留为事实，但不能自动获得正信用。
6. 根、深度和访问集中只描述生成来源；路线覆盖若要成为科学变量，需要行为或语义证据。

## 开放缺口

- 四个任务上尚未标注根程序与后续程序属于哪些算法簇；没有簇标签，就无法判断路线是不是投资单位。
- 代码哈希和谱系身份不能证明路线之间存在算法语义差异。
- 行为级归因仍开放：紧凑实际修改提高了可审计性，但不提供行级因果。
- 跨路线复用哪些对象、怎样保留来源，见 [L3](L3-单步生成.md)。
