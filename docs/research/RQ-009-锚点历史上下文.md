# RQ-009 锚点历史上下文

> 状态：机制已定稿并实现为 V9.6（规范见
> [V9.6 完整机制设计](../methods/TraceAAD-v9.6完整机制设计.md)），待冒烟与正式运行，
> 结果回写本文。锚点本身怎么选属于预算分配问题，见
> [RQ-003](RQ-003-轨迹上下文与搜索评分.md)。

## 核心想法

选定一个锚点后，从它的父代轨迹和已有子代尝试里，挑最多 8 条有代表性的历史，用清晰、
结构化的方式告诉模型三件事：

> 我现在有什么算法 → 它之前怎么改过来的 → 从这里已经试过什么。

这就是轨迹引导的上下文。当前阶段的重点是把轨迹信息真正以模型容易理解的形式提供进去，
不预先理论化挑选机制；跑出来如果有明显问题，再针对问题改。

## 挑法

三步：

1. **父代轨迹**：取靠近当前锚点的若干步修改，让模型知道这个算法最近是怎么一步步改到
   现在的。
2. **子代尝试**：如果从当前锚点已经试过修改，就选少量有代表性的成功和失败——改进的取
   最近至多 2 条，改差的取最近至多 2 条，完全相同的代码只算一次；持平和无效不入选。
   没有子代就不给。
3. **合计最多 8 条**：父代为主体，子代为补充。各占几条由实际数据决定，不足 8 条就全给，
   不凑数。8 条按发生时间排列。

这个挑法同时修正了一个实测缺陷：V9.5 现行做法是子代优先、能装多少装多少，在同一算法被
反复尝试的任务上会让模型看到的失败远多于真实发生（OP 真实历史中改进占 22.9%，模型看到的
只有 8.2%）。子代封顶并保证成功失败都露面后，这个偏差自然消除。

## 写法

每条历史统一写成容易读的格式：

```text
[History 3] Attempt from current algorithm
Idea: Use adaptive candidate ordering
Change: +8/-5 lines; removed: `score = dist * w`; added: `score = dist * w * decay`
Result: regress
Fitness: 12.84 -> 13.20
```

- **Idea**：当时声明的想法；
- **Change**：实际做了什么的简洁描述——加删了几行，抄一两行真实改动的代码做例子
  （第二轮实验验证过的形式）；不再把整段 diff 压成一行塞进去；
- **Result / Fitness**：改进、退步还是持平，分数从多少到多少；
- 父代的一步标 `Formation step`，子代标 `Attempt from current algorithm`；
- 无效尝试不会入选（挑法只放行改进/退步的子代与形成步）。

整个 prompt 的结构：

```text
Task

Current Algorithm
Fitness
Code

Recent Algorithm Improvement History
（最多 8 条）

Instruction
基于当前算法和这些历史，提出下一步改进。
```

## 依据

- 两轮固定锚点的配对实验（共 864 次生成）：给历史确实改变生成行为；简短实际改动有额外
  信息，CVRP 上有明确单步质量收益；历史给得越多、模型改得越小。见
  [简洁历史识别实验](../experiments/TraceAAD-V9.5简洁历史生成识别实验.md)、
  [紧凑实际修改识别实验](../experiments/TraceAAD-V9.5紧凑实际修改识别实验.md)。
- 正式批次 11,102 次真实生成时刻的统计（脚本
  `experiments/analysis/analyze_v95_local_history_pool.py`）：锚点周围可用历史通常有 30 到
  150 多条，只给 8 条；V9.5 现行挑法在 OP/OBP 上让模型看到的失败比例远高于真实发生。

## 落地

已实现为 V9.6（`llm4ad/method/traceaad_v9_6/`）：只把历史上下文（挑法 + 写法）换掉，
初始化、锚点选择、输出要求与 V9.5 一字不动，两版差异即可归因于这一个改动。预算按真实
评价次数计，固定 1000 次评价。入口 `experiments.runners.traceaad.run --version v9_6`。
先冒烟确认模型调用、评价方向和历史内容正确，再上正式三重复；过程中继续报告有效率与
修改幅度。

## 边界

单步实验的结论只适用于已积累局部历史的锚点，历史的最终价值以完整搜索和测试集为准。
已知历史越多、模型改得越小，这种收缩在局部已经改不动的状态上可能有害，正式运行需观察。
