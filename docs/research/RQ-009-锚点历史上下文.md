## 主次定位（2026-08-13 定稿）

父代来时路是主信息，子代尝试是特殊情况下的补充信息。这不是主观偏爱：新锚点天然
只有来时路，只有旧锚点被再次选中时才存在子代信息，而后者在 V9.6 的搜索动力学下
本来就不是主体。来时路回答"这个算法为什么变成了现在这样"，是当前代码本身没有
显式表达的信息；子代尝试只回答"从这里已经试过什么"这个更局部的问题。上下文构建
本身不应成为核心算法问题——它首先是一个简单、确定性的历史表示，真正要研究的是
改进来时路作为上下文能不能提高下一步算法设计。

三臂单步实验（`code_only` vs `+来时路` vs `+来时路+子代尝试`，其余全部固定）
已完成并支持这一定位：来时路在全部四个任务上单步价值明确（配对 conditional
\(\Delta q\) 区间全部不跨 0，72 锚点 58 好 14 差）；在来时路之外追加子代尝试
没有稳定额外价值（四任务区间全部跨 0，方向 35 好 34 差 3 平），TSP/CVRP 上
还偏负。见
[固定锚点单步生成识别实验](../experiments/TraceAAD-固定锚点单步生成识别实验.md)（第三轮）。
边界：锚点限于子代多为 1 条的 V9.6 真实暴露水平，单步收益不等于完整搜索收益。

该实验带来三个收口性判断（详细论证与数字见
[研究认识](../knowledge/研究认识.md)一.1）：

1. **来时路的作用方式是让修改贴合当前设计状态、减少灾难性偏离**，不只是提高
   improve rate：OP/OBP 的 improve 几乎未变但中位 Δq 一致右移，最差十分位修改
   占比大幅下降（TSP 16%→6%、CVRP 23%→4%、OP 16%→8%）。
2. **TSP 归因修正**：单步层面收缩与质量改善同向发生，"历史 → 收缩 → TSP 搜索变差"
   的直接因果不再被证据支持；TSP 在完整搜索中受损的疑点转向预算分配与修改意图。
3. **本问题停止迭代**：父代取几条、improve/regress 子代各取几条、direct 怎么排序
   都不再是主矛盾。机制定型为"当前算法 + 清晰紧凑的父代改进来时路"，剩余的开放
   问题（收缩对多步探索分布的影响、子代丰富场景）留待有完整搜索证据时再开。

## 核心想法

选定一个锚点后，从它的父代轨迹和已有子代尝试里，挑最多 8 条有代表性的历史，用清晰、
结构化的方式告诉模型三件事：

> 我现在有什么算法 → 它之前怎么改过来的 → 从这里已经试过什么。

这就是轨迹引导的上下文。当前阶段的重点是把轨迹信息真正以模型容易理解的形式提供进去，
不预先理论化挑选机制；跑出来如果有明显问题，再针对问题改。

## 挑法

三步：

1. **父代轨迹**：取靠近当前锚点的若干步修改，让模型知道这个算法最近是怎么一步步改到
   现在的。
2. **子代尝试**：如果从当前锚点已经试过修改，就选少量有代表性的成功和失败——改进的取
   最近至多 2 条，改差的取最近至多 2 条，完全相同的代码只算一次；持平和无效不入选。
   没有子代就不给。
3. **合计最多 8 条**：父代为主体，子代为补充。各占几条由实际数据决定，不足 8 条就全给，
   不凑数。8 条按发生时间排列。

这个挑法同时修正了一个实测缺陷：V9.5 现行做法是子代优先、能装多少装多少，在同一算法被
反复尝试的任务上会让模型看到的失败远多于真实发生（OP 真实历史中改进占 22.9%，模型看到的
只有 8.2%）。子代封顶并保证成功失败都露面后，这个偏差自然消除。

## 写法

每条历史统一写成容易读的格式：

```text
[History 3] Attempt from current algorithm
Idea: Use adaptive candidate ordering
Change: +8/-5 lines; removed: `score = dist * w`; added: `score = dist * w * decay`
Result: regress
Fitness: 12.84 -> 13.20
```

- **Idea**：当时声明的想法；
- **Change**：实际做了什么的简洁描述——加删了几行，抄一两行真实改动的代码做例子
  （第二轮实验验证过的形式）；不再把整段 diff 压成一行塞进去；
- **Result / Fitness**：改进、退步还是持平，分数从多少到多少；
- 父代的一步标 `Formation step`，子代标 `Attempt from current algorithm`；
- 无效尝试不会入选（挑法只放行改进/退步的子代与形成步）。

整个 prompt 的结构：

```text
Task

Current Algorithm
Fitness
Code

Recent Algorithm Improvement History
（最多 8 条）

Instruction
基于当前算法和这些历史，提出下一步改进。
```

## 依据

- 两轮固定锚点的配对实验（共 864 次生成）：给历史确实改变生成行为；简短实际改动有额外
  信息，CVRP 上有明确单步质量收益；历史给得越多、模型改得越小。见
  [固定锚点单步生成识别实验](../experiments/TraceAAD-固定锚点单步生成识别实验.md)（第一、二轮）。
- 正式批次 11,102 次真实生成时刻的统计（脚本
  `experiments/analysis/analyze_v95_local_history_pool.py`）：锚点周围可用历史通常有 30 到
  150 多条，只给 8 条；V9.5 现行挑法在 OP/OBP 上让模型看到的失败比例远高于真实发生。

## 落地

初始化、锚点选择、输出要求与 V9.5 一字不动，两版差异即可归因于这一个改动。正式批次
`20260812_191011` 已完成，结局见头部状态。V9.7 原样沿用该历史机制，在其上研究分配与
生成意图（[RQ-003](RQ-003-轨迹上下文与搜索评分.md)）。

## 边界

单步实验的结论只适用于已积累局部历史的锚点，历史的最终价值以完整搜索和测试集为准。
"历史越多、模型改得越小"的收缩在局部已经改不动的状态上有害，该预警已在 V9.5→V9.6
对比中兑现（TSP 受损）；V9.7 以固定保留的 Explore 意图保留结构性探索机会作为应对。
