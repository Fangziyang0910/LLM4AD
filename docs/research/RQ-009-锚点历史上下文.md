# RQ-009 锚点历史上下文

> 状态：已收口。当前默认上下文为“当前算法 + 父代改进来时路”。V9.6 检验了历史表示的修正，V9.7 根据三臂实验移除了默认子代尝试。后续问题转向预算分配和生成意图，见 [RQ-003](RQ-003-轨迹上下文与搜索评分.md)。

## 研究问题

在固定当前程序时，哪些历史信息能够改善下一次算法生成？

候选信息包括两类：

- **父代改进来时路**：当前程序经过哪些修改和评价形成；
- **已有子代尝试**：此前从当前程序出发尝试过哪些方向。

两类信息的作用范围不同。来时路对每个非根锚点都存在，解释当前设计怎样形成；子代尝试只在锚点被重访后存在，用于描述局部已试边界。

## 实验证据

前两轮固定锚点实验共包含 864 次生成。结果表明，简洁历史能够改变生成分布；紧凑实际修改摘要在 CVRP 上提供额外单步收益，配对差为 +0.237，95% bootstrap 区间为 [0.088, 0.409]。历史增加后，四个任务的修改幅度总体收缩。

第三轮实验固定当前代码、任务、输出契约和采样条件，比较 `code_only`、`+来时路` 和 `+来时路+子代尝试`，共完成 648 次生成：

- 加入来时路后，四个任务的配对 conditional $\Delta q$ 区间均不跨 0；72 个锚点中 58 个方向更好、14 个更差。
- 在来时路之外加入子代尝试后，四个任务的区间均跨 0，方向为 35 好、34 差、3 平；TSP 和 CVRP 的方向偏负。
- 来时路使中位修改幅度下降，同时减少最差十分位修改，TSP、CVRP、OP 分别从 16% 降至 6%、23% 降至 4%、16% 降至 8%。

完整设计和结果见[固定锚点单步生成识别实验](../experiments/TraceAAD-固定锚点单步生成识别实验.md)。

## 结论

父代改进来时路是目前得到直接支持的主要历史成分。它提供当前代码未显式包含的形成信息，并在固定锚点上提高单步质量、减少极端偏离。

已有子代尝试没有显示稳定的平均增益，因此不再作为默认上下文。它仍作为完整搜索事实保留；在多次重访且子代丰富的状态下是否有条件价值，现有实验没有回答。

历史上下文据此定义为：

```text
Task

Current Algorithm
Fitness
Code

Recent Parent-Path Improvements
  Idea
  Compact actual change
  Result
  Parent fitness -> child fitness

Instruction
```

父代路径最多保留靠近当前锚点的 8 个形成事件，并按真实发生顺序呈现。每个事件包含当时声明的 Idea、由父子代码确定的紧凑实际修改、评价结局和真实分数。完整 diff、内部标识和统计字段不进入默认生成上下文。

## 解释边界

1. 这些实验识别的是单步生成作用，不能替代完整搜索或 held-out 评价。
2. 实验中的锚点通常只有 1 条已有子代；对子代丰富状态的结论仍不确定。
3. 修改收缩在固定锚点实验中与质量改善同向发生，因此不能把收缩本身写成已证实的损害。
4. V9.6 在 TSP 完整搜索中的退化不能由“历史导致收缩”单独解释；预算分配、生成意图及其交互仍可能构成替代解释。
5. 来时路中的 Idea 与实际修改仍可能不完全一致。紧凑实际修改提高了可审计性，但不提供行级因果归因。
