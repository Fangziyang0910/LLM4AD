# RQ-008 从轨迹记录走向轨迹驱动的算法搜索

> 状态：持续研究中。本文的底层任务定义与机制原则是 V9.4–V9.7 迭代的共同依据。V9.2–V9.4 的实验结局见[版本谱系与实验事实](../analysis/TraceAAD-版本实验事实与机制诊断.md)的 V9.2–V9.4 节，V9.5 起的当前判断见 [RQ-003](RQ-003-轨迹上下文与搜索评分.md)。

## 1. 底层任务

自动算法设计不是在固定、可枚举的动作集合里寻找最高分节点。给定 LLM、evaluator 和有限预算，系统每一步真正能控制的是：从哪份可执行程序继续；把哪些已发生的改进历史交给模型；是否引入另一条路线的知识；如何根据新结果更新后续生成条件；剩余预算分给哪些改进过程。LLM 随后生成新的 `Idea + Code`——搜索机制不直接移动到代码空间的某个邻居，而是在持续塑造下一次生成的条件分布。

终点是预算结束时质量最高、能够泛化的程序；平均子代质量、改进率、趋势、访问数和树深都只是可能有用的代理，不是任务本身。TraceAAD 的核心问题因此是：

> 如何把有限预算分配给最值得继续的"可执行程序 + 已积累的局部搜索知识"，并把这份知识组织成真正有助于下一次算法生成的上下文？

只做好其中一层，系统仍可能退化为带历史提示的普通个体进化，或退化为会选路线但不会利用路线知识的调度器。

## 2. 轨迹的本质是锚点化的局部搜索状态

轨迹不只是根到叶的路径或最近若干条日志。它围绕当前可执行锚点，保存来时路、已尝试的改变、真实结果和尚未解决的改进边界，分两层：

- **事实层**：锚点代码、父子关系、Idea、有效性、fitness 和真实发生顺序，由事实图完整保存；
- **决策层**：从事实中为当前锚点构造的有限局部视图，让模型理解当前算法怎样形成、哪些方向已被尝试、下一步还有什么可继续的空间。

更完整的搜索状态因此不是裸程序，而是"锚点 + 与它严格对应的形成过程 + 附近已测试的方向 + 仍可推进的知识边界"。同一代码配上不同来时路，会让模型知道不同的已试边界并产生不同的下一步分布——轨迹的独特价值正来自这种状态性。

## 4. V9.3 的决策粒度教训

轨迹包含多步历史，只说明当前决策可以利用一段来时路；它不意味着一次锚点选择后必须连续做多步决策。V9.3 的固定三步 rollout 混淆了历史时间长度与决策粒度，还改变了"一份预算产生一个候选"的基本事件；V9.4 恢复为每次"选一个锚点—联合生成一个 `Idea + Code`—评价一次—更新一次—重新选择"。这一骨架沿用至今（详见[研究认识 §6](../knowledge/研究认识.md)）。

## 5. 机制原则

1. **终局优先**：预算价值面向预算结束时的最好程序，不把一步平均质量当成最终目标。
2. **锚点不可丢**：完整可执行代码和当前 fitness 始终是搜索地基，轨迹不能脱离锚点独立漂移。
3. **状态是代码加知识**：选择比较的是锚点及其局部轨迹状态，不是裸节点。
4. **轨迹按决策价值构造**：固定 token 预算下优先保留定义当前机制、约束已试边界和支持下一步判断的事实。
5. **上下文与信用闭合**：什么历史实际参与了生成，结果就应更新相应的轨迹状态。
6. **承认多步发展**：短期退步、普通尝试和延迟突破属于同一过程；信用时间尺度不能只剩一步，也不能把最好后代无条件复制给祖先。
7. **保持多个知识盆地**：多样性的目标是保留互补的算法行为和搜索知识，不是维持若干节点 ID 或平均分配预算。
8. **允许可追溯迁移**：局部轨迹可以引用另一条路线的已验证思想，但必须保留来源、适用程序和真实结果。
9. **让评价结果更有信息**：在 evaluator 能力允许时，优先提供可解释的行为差异或失败特征。
10. **初始化属于同一过程**：根策略生成、早期发展和路线筛选服从同一个轨迹搜索逻辑。
11. **机制保持简洁**：每一版只实现能够闭合核心信息流的最少机制，设计变更的预期效应量应能穿透测量噪声底。

## 6. 力争 SOTA 时必须形成的真实优势

TraceAAD 若要稳定超过现有方法，需要利用一类其他方法没有充分利用的信息：算法是怎样一步步形成的，以及这些已发生的尝试怎样改变下一次生成。至少应形成三种真实能力：

1. **比孤立精英更会继续**：模型能从连续的成功、失败和修正中做出更有根据的下一步修改；
2. **比静态种群更会分配预算**：系统能识别哪些局部知识状态仍值得发展，而不只是追逐当前最高 fitness；
3. **比独立路线更会复用知识**：互补轨迹能够迁移已验证思想，同时保留来源和局部适用边界。

相关方法提供可借用的搜索结构（MCTS-AHD 的预算集中与局部精炼、BaSE 的两层循环、PathWise / MEMOIR / ReEvo 的历史条件化生成、DGA²D 的信用粒度、FunSearch / EoH 的强基线），但不替 TraceAAD 证明任何设计；必须证明轨迹带来了这些基线没有充分利用的信息优势，而不能把通用进化能力重新命名为轨迹贡献。

## 当前决定

1. V9.2、V9.3、V9.4 的实现与工件是既成事实记录；V9.4 的一锚点、一次联合生成、一次评价、一次更新继续作为决策骨架。
2. V9.5 建立质量加乐观项的最小分配基座，V9.6 完成历史重构，V9.7 增加路线级分配与生成意图；三者合计覆盖第 3 节表中的三个已处理缺口。
3. 后续判读遵循"大而一致"纪律（三重复同向且幅度超过同方法批次抖动），无信号时不按任务构造叙事；开放缺口按预期效应量排序，优先做能穿透噪声底的设计。
