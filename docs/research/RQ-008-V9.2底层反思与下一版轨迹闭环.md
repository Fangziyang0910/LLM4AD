# RQ-008 从轨迹记录走向轨迹驱动的算法搜索

> 状态：持续研究中。V9.2 与 V9.3 保留各自冻结实验协议；V9.3 后续被确认混淆了轨迹历史长度与单次决策粒度。当前修正版 V9.4 见[完整设计](../methods/TraceAAD-v9.4完整机制设计.md)，其余缺口仍是后续版本问题。

## 核心判断

V9.2 已经把树降为事实结构，也把当前可执行代码、形成历史和附近测试结果放进同一个生成上下文。这是方向上的进步。但它目前更接近：

> 用轨迹增强提示词，再用节点的一步子代均值选择下一份预算。

这还不等于轨迹驱动搜索。轨迹在生成时出现了，却没有成为系统理解当前搜索状态和组织后续预算的核心。评分、窗口、初始化和路线竞争分别做了局部合理化，但尚未围绕“怎样利用已经发生的算法改进过程提高未来搜索效率”形成同一个底层闭环。

## 1. 先重新定义底层任务

自动算法设计不是在一个固定、可枚举的动作集合里寻找最高分节点。给定 LLM、evaluator 和有限预算，系统每一步真正能控制的是：

1. 从哪份可执行程序继续；
2. 把哪些已经发生的改进历史交给模型；
3. 是否引入另一条路线的知识；
4. 如何根据新程序及其结果更新后续生成条件；
5. 将剩余预算分配给哪些算法改进过程。

LLM 随后根据这些条件生成新的 `Idea + Code`。所以搜索机制并不直接移动到代码空间中的某个确定邻居，而是在持续塑造下一次代码生成的条件分布。终点是在预算结束时得到质量最高、能够泛化的程序；中间的平均子代质量、改进率、趋势、访问数和树深都只是可能有用的代理，不是任务本身。

由此，TraceAAD 的核心问题应表述为：

> 如何把有限预算分配给最值得继续的“可执行程序 + 已积累的局部搜索知识”，并把这份知识组织成真正有助于下一次算法生成的上下文？

这个任务同时包含局部生成和全局资源分配。只做好其中一层，系统仍可能退化为带历史提示的普通个体进化，或者退化为会选路线但不会利用路线知识的调度器。

## 2. 轨迹的本质是锚点化的局部搜索状态

轨迹不应只被理解为根到叶的路径，也不应只被理解为最近若干条日志。它围绕当前可执行锚点，保存这份程序在局部搜索中的来时路、已经尝试的改变、真实结果以及尚未解决的改进边界。

其中有两层内容：

- **事实层**：锚点代码、父子关系、Idea、有效性、fitness 和真实发生顺序。事实图负责完整保存，不替搜索做判断。
- **决策层**：从事实中为当前锚点构造的有限局部视图。它要让模型理解当前算法怎样形成、哪些方向已被尝试、结果之间是否相互支持或矛盾，以及下一步还有什么可继续利用的空间。

因此，更完整的搜索状态不是裸程序 `a`，也不是脱离程序的一条历史 `W`，而是锚点及其局部知识状态：

```text
当前可执行程序
    + 与它严格对应的形成过程
    + 附近已测试的方向和结果
    + 从这些事实中仍可继续推进的知识边界
```

最后一项不是新的客观真理，而是对现有事实的暂时组织。它可以被后续结果修正。轨迹的独特价值正来自这种状态性：同一代码配上不同来时路，会让模型知道不同的已试边界并产生不同的下一步分布。

## 3. V9.2 已经做对了什么

V9.2 至少完成了四个重要转向：

1. 锚点完整代码是唯一执行起点，树只保存事实关系；
2. 历史与锚点严格匹配，不再用全局 min–max 或祖先最高分替代轨迹事实；
3. 形成历史、失败和短程下游尝试都会进入上下文；
4. 初始化不只生成孤立根，而是先形成一批两步微轨迹。

这些决定使 V9.2 有资格成为下一步研究的起点。下面的不足并不是否定这些方向，而是指出它们还没有充分完成轨迹闭环。

## 4. V9.2 与轨迹思想仍然不一致的地方

### 4.1 规范窗口是拓扑截断，不是决策相关的轨迹

当前窗口固定取近期形成事件和深度三以内的近期下游事件，采用 `4 + 4` 优先配额。它能稳定复现，也避免事后只挑最好结果，但“最近、相邻”不等于“对下一步最有信息”。

较早事件可能定义了当前算法的核心机制，近期事件可能只是参数微调；多个下游分支的最近结果也可能在语义上彼此无关。把它们并排放入窗口，得到的是局部事件集合，不一定是一段连贯的算法改进脉络。V9.2 解决了窗口可执行性，却尚未解决轨迹选择的知识相关性。

下一版真正需要的不是把许多窗口变成 bandit arm，而是在锚点选定后，构造一份与当前决策最相关、语义连贯且不隐去反例的局部轨迹视图。

### 4.2 Idea—结果仍是弱描述，尚未形成可靠的算法知识

V9.2 给历史节点保留一句 Idea 和一个 fitness 结果。它告诉模型“当时声称做了什么”和“随后得了多少分”，却没有确认 Idea 是否准确对应代码变化，也没有说明结果改善了哪些行为、损害了哪些情况。

如果 Idea 与代码不一致，轨迹会传播错误解释；如果不同程序在平均 fitness 上同分，轨迹也无法告诉模型它们的行为差异。代码空间难以做行级因果归因，但这不意味着只能保留一个标量。只要 evaluator 能提供稳定、廉价的结果结构，轨迹应优先保存对下一步修改有用的行为反馈或失败特征，而不是继续增加抽象评分项。

### 4.3 轨迹进入了 prompt，却没有真正进入预算价值

当前 `Q(a)` 聚合锚点 fitness 与从该锚点直接生成的子代质量。窗口内容变化时，旧结果仍留在同一个 `Q(a)` 中；不同历史条件产生的结果被合并。另一方面，新子代立即成为新锚点，并以自身 fitness 重新开始评分。

这使上下文和信用在概念上分离：模型根据当前轨迹生成，选择器却主要评价程序节点过去产生了多少高分子代。系统没有回答“这份局部知识是否让该锚点变得更值得继续”，也没有保存哪些历史事实促成了有效生成。

实现上仍可以把选择值挂在锚点上，但它表达的应是“锚点及其当前局部知识状态的继续价值”，而不是裸节点的一步生产均值。

### 4.4 一步平均质量与预算终局目标不一致

V9.2 偏好能够稳定产生较高绝对质量子代的锚点。这适合局部精炼，却未必适合寻找预算结束时的最好程序。一条路线可能平均稳定但很快饱和，另一条路线可能需要经历普通甚至退步节点，几步后才形成新的算法机制。

因此轨迹价值至少带有时间尺度：当前代码质量决定地基，直接结果说明局部可操作性，多步后续说明这段知识能否继续展开。下一版不应简单把三者线性相加，但必须承认只看一步均值会系统性忽略延迟发展和突破上限。

### 4.5 新锚点重置使搜索仍像个体沿谱系推进

每个高质量子代都以未经历史结果修正的新分数进入候选区；成熟锚点则承受既往普通或失败子代带来的均值下降。即使精确锚点看起来分散，预算也可能沿同一初始谱系不断追逐新节点。

这会把“轨迹继续产生知识”重新变成“当前最好个体不断繁殖”。V9.2 保留了来时路，但没有清楚区分节点更新、谱系推进和独立搜索方向。真正的全局分配应关注多个仍有发展可能的局部知识状态，而不仅是前十个高分节点。

### 4.6 初始化仍用一次反馈判断一个算法方向

`8 → 6` 微轨迹初始化比孤立根更合理，但一次 bootstrap 仍默认一个方向能够在一步内显现价值。需要结构重写、参数校准或先退后进的路线可能被过早排除；八条自然语言策略也不保证八种真实算法行为。

初始化不是正式搜索之前的特殊工程阶段，而是轨迹搜索的最早一段。初始方向应怎样获得足够发展深度、何时参与竞争、何时被保留为备用路线，应与正式搜索使用同一套底层逻辑。

### 4.7 局部路线之间缺少知识流动

V9.2 为了保持机制简洁，取消了双轨迹参考和全局经验。这避免了错误摘要污染所有路线，也使各路线几乎只能重复依靠自己的局部历史。不同路线可能独立发现互补结构，却没有机制让一个锚点读取另一条路线已经验证的算法思想；多个谱系也可能反复尝试相同方向。

轨迹的局部性需要保留，但局部不等于隔离。下一版应考虑受控的跨轨迹比较或知识迁移：来源轨迹及其结果必须可见，参考只改变生成上下文，不伪造成第二结构父代，也不形成无来源的全局结论。

### 4.8 标量 fitness 对下一步修改提供的信息过少

当前搜索知道程序总分，却通常不知道它为什么得到这个分数。对于多实例 evaluator，两个均值相同的程序可能分别擅长不同实例；一个整体改善也可能由少数实例投机造成。轨迹若只记录单一 fitness，模型仍需从代码中猜测改动后果。

TraceAAD 要利用历史超过普通进化方法，就应尽可能保存“变化带来了什么行为结果”。这不要求对每个任务建立复杂 critic，也不要求伪造代码因果解释；它要求重新审视 evaluator 是否能提供比一个标量更有决策价值、又能控制上下文成本的反馈。

## 5. 为什么说 V9.2 仍接近传统个体进化

V9.2 的实际循环是：按节点 `Q` 选择锚点，附上固定局部历史，生成一个子代，再让子代作为新节点参加竞争。轨迹主要改变 LLM 看见什么，节点质量仍主要决定预算流向，信用也随新节点重新开始。

所以它已经是“历史条件化的个体进化”，但还不是完整的“轨迹驱动搜索”。后者要求：

- 搜索状态由代码与已积累的局部知识共同定义；
- 轨迹不仅帮助生成，还影响对继续价值的理解；
- 新节点出现后，系统更新的是整段局部搜索状态，而不只是增加一个新个体；
- 全局预算在多个局部知识状态之间分配，并允许受控的知识迁移。

## 6. 下一版应形成的轨迹闭环

一个更一致的闭环可以分成两个相互连接的循环。

```text
局部知识循环
锚点 + 决策相关轨迹
    -> LLM 生成 Idea + Code
    -> evaluator 给出结果
    -> 更新锚点附近的事实、已试边界和可继续方向

全局资源循环
比较多个“锚点 + 局部知识状态”
    -> 分配下一份预算
    -> 必要时引入另一条轨迹的可追溯知识
    -> 回到局部知识循环
```

树或图只负责让这两个循环能够还原事实。真正的方法特色应落在三件事上：如何构造决策相关轨迹，如何理解一段轨迹还剩多少可继续价值，以及如何在多个轨迹状态之间分配与迁移知识。

## 7. 面向下一版的机制原则

当前先确定原则，不锁死实现公式。

1. **终局优先**：预算价值面向预算结束时的最好程序，不把一步平均质量当成最终目标。
2. **锚点不可丢**：完整可执行代码和当前 fitness 始终是搜索地基，轨迹不能脱离锚点独立漂移。
3. **状态是代码加知识**：选择仍可以统一到锚点，但所比较的是锚点及其局部轨迹状态，不是裸节点。
4. **轨迹按决策价值构造**：固定 token 预算下优先保留定义当前机制、约束已试边界和支持下一步判断的事实，而不是机械取最近事件。
5. **上下文与信用闭合**：什么历史实际参与了生成，结果就应更新相应的轨迹状态；不能长期把不同上下文下的结果当作同一个静态节点价值。
6. **承认多步发展**：短期退步、普通尝试和延迟突破属于同一算法发展过程，信用时间尺度不能只剩一步，也不能把最好后代无条件复制给祖先。
7. **保持多个知识盆地**：多样性的目标是保留互补的算法行为和搜索知识，不是维持若干节点 ID 或平均分配预算。
8. **允许可追溯迁移**：局部轨迹可以引用另一条路线的已验证思想，但必须保留来源、适用程序和真实结果。
9. **让评价结果更有信息**：在 evaluator 能力允许时，优先提供可解释的行为差异或失败特征，而不是继续堆叠对标量 fitness 的派生统计。
10. **初始化属于同一过程**：根策略生成、早期发展和路线筛选都服从同一个轨迹搜索逻辑，不用一次特殊 bootstrap 代替方向成熟。
11. **机制保持简洁**：不因为发现上述缺口就同时加入趋势权重、UCB、摘要器、聚类器和多算子调度。下一版只应实现能够闭合核心信息流的最少机制。

## 8. 从 V9.3 错误到 V9.4 修正

V9.3 曾尝试闭合 V9.2 只观察一步结果的问题：一次全局选择后从同一方向固定连续生成三步，两阶段调用分别决定 Idea 和实现 Code，再按整段最好程序给起始锚点结算。它确实允许真实退步之后继续发展，也产生了可分析的多步过程数据。

后续审查发现，这一实现错误地把两个维度绑在了一起：轨迹包含多步历史，只说明当前决策可以利用一段来时路；它不意味着选择一次锚点后必须替全局分配器连续做三次决策。固定三步还额外获得三次 evaluator 机会并执行 best-of 筛选，使它与“一份预算产生一个候选”的方法不再具有相同基本事件。两阶段生成也让一次本可联合形成的 `Idea + Code` 变成另一项耦合机制。

V9.4 因此不把 rollout 长度简单改成 1，而是删除 rollout 抽象：每次按现有信用选择一个锚点，为它构造局部轨迹窗口，一次调用联合生成唯一 `Idea + Code`，评价一次并更新一次，然后重新进行全局选择。所有有效子代包括退步节点都进入候选；失败事件则以失败类别、异常类型、精简 evaluator 反馈和 Idea 进入锚点局部证据，不生成伪节点。

V9.4 最初实现的单步保留价值仍然过浅：`max(锚点, 子代)` 没有表达真实搜索中跨多次全局重选形成的延迟价值。修正版保持“一次只生成一个候选”，但每个新结果会对规范窗口可见的至多三层祖先回传正向增益，距离每增加一层乘 `0.5`；退步和无效增加证据数但信用为零。这样中间退步节点在后来真正产生优秀后代时能够获得价值，更早祖先的影响逐层减弱，也不会把一个最好分数复制给整条谱系。严格全局突破仍单独记录，不额外塞入评分。

仅更新祖先数值还不构成预算闭环：在所有有效后代都保持合格、选择器又永久取第一名时，成功后代会持续压过得到回传的祖先。修正版因此把纯确定性利用改为质量区内的固定 `4:1` 利用—覆盖：候选仍由 `Q` 前 10 限定，四次按未验证优先或最高 `Q` 选择，第五次选择直接尝试最少且等待更久者。它不向全局低质量区域平均分配预算，只让轨迹信用有机会转化为局部重访。

失败信息也从锚点局部证据扩展为两层：局部窗口保留该锚点附近的真实失败；任务内有界记忆聚合跨分支重复的解析器/evaluator 错误并在后续根生成与正式生成中展示。失败代码不进入提示，无效候选也不成为程序节点。初始化仍为 8 条路线各一个根和一次 bootstrap，再按最好可执行端点保留 6 条。

这次修正解决的是基本决策单位、失败信息闭环和信用效用语义。它仍没有解决语义相关窗口、可靠 Idea—Code 对齐、行为级 evaluator 反馈、跨路线知识迁移和浅初始化等问题。

## 9. 尚未确定的问题

以下问题现在保持开放：

- 决策相关轨迹由确定性规则构造，还是由模型在受约束的事实集合中选择；
- 如何在不建立稀疏“窗口 arm”的情况下，让窗口变化进入锚点继续价值；
- 继续价值应怎样同时尊重锚点质量、局部可操作性和多步发展空间；
- 如何防止新锚点重置造成单谱系吞噬，又不为每条路线预留僵硬配额；
- 初始化方向至少发展几步才有资格被淘汰；
- 何时应继续局部精炼，何时应读取另一条轨迹进行知识迁移；
- 四类任务能够提供哪些通用而廉价的 evaluator 反馈；
- Idea—Code 对齐应通过系统差异摘要、模型复核还是更直接的程序行为描述改善。

V9.2 的最终结果将帮助判断这些问题在不同任务上的严重程度，但不会自动替我们给出下一版机制。即使 V9.2 最终表现很好，也可能主要受初始化、提示词或高质量锚点选择驱动；即使表现不佳，也不能直接推出轨迹没有价值。结果用于定位闭环中的薄弱环节，底层任务定义仍是下一版设计的起点。

## 10. 相关方法提供的结构性启发

相关方法没有严格证明某个树、bandit、反思或记忆机制就是正确答案，但它们揭示了若干可借用的搜索结构：

- [MCTS-AHD](../references/LLM自动算法设计方法阅读笔记/22-MCTS-AHD.md) 表明高质量代码附近的持续局部开发和强预算集中可以很有效；需要学习的是资源集中与局部精炼，不是复制树公式。
- [BaSE](../references/LLM自动算法设计方法阅读笔记/28-Compute-Allocation-BaSE.md) 把轨迹内生成和轨迹间预算分开，说明局部知识循环与全局资源循环可以是两个层次。
- [PathWise](../references/LLM自动算法设计方法阅读笔记/24-PathWise.md)、[MEMOIR](../references/LLM自动算法设计方法阅读笔记/47-MEMOIR.md) 和 [ReEvo](../references/LLM自动算法设计方法阅读笔记/15-ReEvo.md) 都以不同方式让历史改变下一次生成，提示轨迹的首要作用是塑造生成分布，而不仅是提供统计特征。
- [DGA²D](../references/LLM自动算法设计方法阅读笔记/51-DGA2D.md) 提醒信用需要合适的上下文粒度；这支持避免无限细分状态，但不推出 V9.2 的固定近期窗口就是最佳轨迹。
- [FunSearch](../references/LLM自动算法设计方法阅读笔记/04-FunSearch.md) 和 [EoH](../references/LLM自动算法设计方法阅读笔记/05-EoH.md) 说明强 evaluator、优质父代和生成多样性本身已经构成强基线。TraceAAD 必须证明轨迹带来了这些基线没有充分利用的信息优势，而不能把通用进化能力重新命名为轨迹贡献。

这些模式用于帮助我们构造闭环和避免重复犯错。下一版仍应从 TraceAAD 的底层任务出发，只吸收其中真正填补信息或决策缺口的部分。

## 11. 力争 SOTA 时必须形成的真实优势

TraceAAD 若要稳定超过现有方法，不能只拥有不同名称的树策略或更复杂的评分。它需要利用一类其他方法没有充分利用的信息：算法是怎样一步步形成的，以及这些已发生的尝试怎样改变下一次生成。

下一版至少应形成三种真实能力：

1. **比孤立精英更会继续**：模型能从连续的成功、失败和修正中做出更有根据的下一步修改；
2. **比静态种群更会分配预算**：系统能识别哪些局部知识状态仍值得发展，而不只是追逐当前最高 fitness；
3. **比独立路线更会复用知识**：互补轨迹能够迁移已验证思想，同时保留来源和局部适用边界。

如果下一版没有在这三点上形成机制闭环，它即使短期分数提高，也很可能只是另一个更强的工程组合；如果能够做到，轨迹才真正构成 TraceAAD 冲击 SOTA 的方法优势。
