# RQ-008 轨迹驱动算法搜索的科学问题

> 状态：持续研究中。本文定义跨版本的研究对象与机制边界；当前实证判断见 [RQ-003](RQ-003-轨迹上下文与搜索评分.md)。

## 1. 研究对象

在给定语言模型、评价器和有限预算时，搜索系统可以控制三类条件：从哪个可执行程序继续，向模型提供哪些已发生的改进历史，以及怎样根据新结果分配后续预算。语言模型随后生成新的 `Idea + Code`。

因此，TraceAAD 的目标不是在固定动作集合中寻找最高分节点，而是持续构造下一次算法生成的条件。终局指标是预算结束时质量最高且能够在独立测试集上泛化的程序。一步平均质量、改进率、访问数和树深都只是候选代理。

核心问题可以写为：

> 如何把有限预算分配给仍值得发展的“可执行程序 + 局部改进知识”，并把这份知识表示成有助于下一次生成的上下文？

## 2. 轨迹的两层含义

轨迹包含两个不可互换的层次：

- **事实层**：程序、父子关系、生成意图、实际修改、有效性、fitness 和发生顺序；
- **决策视图**：从事实中选出的有限上下文，用于说明当前程序怎样形成以及哪些约束与结果和下一步有关。

同一程序可以沿不同形成路径到达，因此当前代码不能完全替代来时路。固定锚点实验已经为这一点提供单步证据。决策视图仍是有损表示，其信息价值需要在固定 token 预算下检验。

## 4. 决策粒度

轨迹包含多步历史，不意味着一次选择后应固定连续生成多步。V9.3 将历史长度与决策粒度绑定为三步 rollout，同时改变了基本预算事件。V9.4 恢复为“一次选择、一次 `Idea + Code`、一次评价、一次更新”，该粒度沿用至 V9.7。

这一经验说明，历史长度、生成步数和预算结算方式应分别研究。联合改变三者会使结果无法归因。

## 5. 机制原则

1. **终局目标优先**：预算分配服务于 best-at-budget，而非一步平均质量。
2. **锚点保持可执行**：当前代码和真实 fitness 是生成与比较的基础。
3. **历史与代码匹配**：进入上下文的事实必须来自当前锚点的真实形成过程。
4. **一份预算对应一次可审计事件**：生成、评价和状态更新应形成明确闭环。
5. **保留非单调形成过程**：短期退步可以作为历史事实，但不能自动获得正信用。
6. **区分拓扑与语义多样性**：不同根或谱系不必代表不同算法行为。
7. **代理变量需要独立证据**：趋势、成熟度、路线信用和复杂度不能因叙事合理而进入在线规则。
8. **机制变更应可识别**：预期效应需要大于当前实验的噪声底，且每次尽量只改变一个科学变量。

## 6. TraceAAD 需要形成的独特能力

TraceAAD 的科学贡献只有在以下能力得到实证支持时才成立：

- 利用来时路提高相同当前程序上的下一步生成质量；
- 利用轨迹证据把预算分配给仍可能产生终局突破的状态；
- 在保留来源和适用边界的前提下复用跨路线知识。

第一项已有单步证据。第二项和第三项仍是主要开放问题。MCTS-AHD、BaSE、PathWise、MEMOIR、ReEvo、DGA²D、FunSearch 和 EoH 提供了可比较的搜索结构与经验，但不能替 TraceAAD 证明轨迹机制的独立贡献。
