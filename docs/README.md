# 研究记录

当前保留四类研究记录，外加若干备忘：

- `研究认识.md`：记录研究交流中形成的灵感、观点、经验和机制认识。新内容先逐条生长，不预设分类；积累充分后再归类整理。
- `ideas/`：机制思想、方法设计和完整方法设计。文件名使用简短中文主题名。
- `worklog/`：唯一的过程记录入口，按周使用 `YYYY-Www.md` 命名。`Www` 使用 ISO 8601 周编号，每周从周一到周日；例如 2026-07-14 使用 `2026-W29.md`。实验、复现、代码改动、问题发现和阶段性判断都写在对应周文件中，每项一两句话即可。
- `results/`：完成后的权威结果汇总，按 task 子目录组织，例如 `results/tsp_construct/结果汇总.md`；搜索曲线放在同一 task 目录。只有重复实验和测试评估完成后才更新。
- `待办.md`：项目级可勾选待办清单（进行中 / 待排期 / 已完成）；完成打勾，避免与覆盖表重复维护细节状态。
- `实验覆盖.md`：method × task 实验覆盖清单（做过哪些组合、完成/进行中），不含权威分数。
- `实验配置.md`：各 task 训练 / 测试数据与搜索配置。
- `LLM服务源.md`：OpenAI-compatible endpoint / model 备忘（zhong-server、server1、Fang_lab）。

记录规则：对话中形成的简短研究认识先写入 `研究认识.md`；发展成熟的机制想法和完整设计写入 `ideas/`；开展实验或完成其他工作时，在当周 `worklog/` 增加一项，写清日期、做了什么以及简短结果；最终结果再整理到 `results/`；method × task 覆盖变更同步更新 `实验覆盖.md`；可执行待办写入 `待办.md` 并在完成时打勾。不单独创建 `docs/experiments/`。
