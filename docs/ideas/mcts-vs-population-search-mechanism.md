# MCTS-AHD 与基于种群的 AHD 搜索机制对比

2026-07-08

核心区别:MCTS-AHD 不仅仅是"EoH 的树版本"。它改变了搜索状态记忆的内容,以及评估信用(credit)路由的方式。

像 EoH 这类基于种群的方法维护一个有界的(bounded)活跃种群。新的启发式从当前被选中的个体中生成,经过评估,然后由生存选择保留最优的 `N` 个候选。这使得活跃搜索前沿是分数驱动的,可能在那些较弱的中间启发式还未来得及经过多次精炼变得有用之前,就先把它们丢弃掉。

MCTS-AHD 将生成的启发式作为派生树(derivation tree)中的节点保留下来。一个节点存储一个启发式,以及它的评估值和访问次数;选择遵循 UCT,扩展应用 LLM 的 mutation/crossover/path 等动作,模拟评估新的子节点,而回溯(backpropagation)把后代的质量回传给祖先。这使得该方法能够重新访问并进一步开发当前并非精英(elite)的分支,同时仍然偏向高质量区域。

对于 TraceAAD 的设计,重要的启示是把三个决策分离开来:

- 记忆结构:活跃种群、完整派生树,或轨迹库。
- 信用分配(credit assignment):仅终点分数、最优后代、路径回报(path return),或逐步改进信号。
- 生成上下文:被选中的个体、父子谱系(lineage)、从根到叶的完整路径,或轨迹级历史。

这说明 TraceAAD 不应当机械地照搬 MCTS-AHD。如果"轨迹即个体(trajectory as individual)"是核心理念,那么该机制应当让轨迹历史本身承载搜索价值,而不是仅仅把树当作存放启发式节点的容器。

## TraceAAD 定位

TraceAAD 最好被定位为一种介于种群搜索与树搜索之间的、由轨迹引导的搜索方法。

从第一性原理出发,种群方法与树方法的区别在于它们如何压缩搜索经验:

- 种群搜索把经验压缩成一个被管理的候选启发式集合。其优势在于灵活的种群管理、重组(recombination)与精英保留。其风险在于,生存压力可能会丢掉那些包含有用算法思路的、较弱的中间启发式。
- MCTS 式的树搜索把经验压缩成一棵派生树。其优势在于显式的谱系、访问次数、UCT 预算分配,以及分支级的信用分配。其风险在于,搜索可能会被树本身那种以节点为局部范围的扩展与回溯语义所约束。

TraceAAD 增加了一个路径级的记忆对象。一条轨迹既不只是一个节点,也不是一棵完整的树,也不只是一个种群成员。它是一段有界的改进尝试历史,包括基础程序、动作、适应度变化、回退(regressions)、平台期(plateaus)以及终点。这为该方法提供了搜索经验的第三个轴线:改进随时间变化所呈现的形态。

预期优势在于:

- 与种群方法类似,TraceAAD 可以维护一个灵活的、由搜索单元组成的活跃集合,并可以在后续复用种群式机制,例如 top-k 过滤、多样性保持、供体(donor)选择、交叉(crossover)与归档(archiving)。
- 与 MCTS 类似,TraceAAD 使用结构化的祖先关系与一个探索项(exploration term),在纯精英主义之外分配预算。
- 与两者都不同,TraceAAD 能够在决定下一步从哪里分叉之前,先评估某个方向是在改进、饱和(saturating),还是在回退。

核心假设应当被尖锐地表述出来:有用的算法思路往往并不仅仅存在于当前最优程序之中,也不仅仅存在于某个单独的树节点之中。它们可能存在于一条部分的(partial)改进路径之上。因此,路径级的打分与前缀分叉(prefix branching)能够保留并复用那些会被种群生存选择丢弃的思路,同时又避免了把全部预算分配都绑定到一棵完整 MCTS 树上的僵化性。

这也暗示了下一层机制:保留当前"轨迹即个体"的设计,然后在轨迹层级而非程序层级去借用种群式管理。活跃池应当依据终点质量、路径质量、机制多样性以及近期的改进模式来管理轨迹。
