# TraceAAD v4：以算法改进轨迹为 MDP 状态历史的单父代搜索

> 状态：当前实现规范。v3 的多来源写回、DAG、独立完整档案和旧算子不再属于 v4。

## 1. 科学主张

算法改进是连续的思想试错过程。当前程序只说明“现在是什么”，轨迹还说明“为什么到这里、哪些思想有效、哪些方向失败、哪里仍可修复”。TraceAAD v4 研究：把这段来时路作为下一步 LLM 推理的主要上下文，是否能在有限评估预算下产生更有效的算法修改。

轨迹是搜索个体，但轨迹的三种价值分工明确：终点与历史最好节点提供搜索质量，边上的结果提供路线走势，完整有序历史提供推理信息。它们不被强行压成一个代表全部价值的标量。

## 2. MDP 与搜索拓扑

给定任务和函数契约 $x$，以当前程序 $p_t$、根到当前节点的历史 $h_t$ 和预算状态 $b_t$ 构成状态：

$$s_t=(x,p_t,h_t,b_t).$$

一次语义修改 action $a_t$ 由 LLM 提出，代码生成和评估形成转移：

$$s_{t+1}=T(s_t,a_t),\quad r_t=F_x(p_{t+1})-F_x(p_t).$$

action 是边上的修改，不是整条轨迹；轨迹是状态历史和推理上下文。

每个新程序只有一个锚点父程序。程序节点及修改边因此构成树；多个初始节点构成森林，可视为共享虚拟根。`DerivationGraph` 只允许一个入边，保存父子关系、action、算子、定向 delta 和 improve/plateau/regress 结果。轨迹对象保存一条有界根到 frontier 的节点/边路径。

树结构只表达来源关系，不自动引入完整 MCTS。v4 借鉴 MCTS 的访问次数思想，但保留种群式并行路线管理。

## 3. 当前 frontier 种群

当前种群 $\mathcal P$ 保存可继续扩展的轨迹 frontier，目标规模为 $M$，默认 $M=30$，实验可比较 20/30/40。初始阶段生成并评估 $M$ 个有效程序，每个建立一个单节点轨迹；预算不足时按实际有效数运行。

独立完整 archive 不属于 v4。被淘汰轨迹仍保存在本次运行的树和轨迹记录中，用于日志与过程分析，但不再被重新检索、评分或繁衍。这样搜索资源管理和事实记录分离，同时不引入跨轨迹经验层。

轨迹最大保存 8 个节点。超过上限时保留最近后缀；后缀中的边仍保留 action、delta 和 outcome，足以说明当前路线的近期来时路。

## 4. 两层选择：搜索价值与访问公平

### 4.1 搜索价值

当前终点质量和轨迹内历史最好节点均在当前候选集合内做百分位排名：

$$Q=0.7Q_{endpoint}+0.3Q_{best}.$$

近期路径趋势只使用定向结果符号，最近步骤权重更高：

$$P=\frac{1+\operatorname{discounted\_sign}(improve=1,plateau=0,regress=-1)}2,$$

默认折扣 $\gamma=0.8$。搜索价值为：

$$V_{search}=0.6Q+0.4P.$$

`Q_best` 保留曾到达高分节点后继续尝试的路线；它不是“潜力”的证明。退步和失败边界仍作为 LLM 上下文，不能仅凭趋势把它们解释为无信息。

### 4.2 UCB-inspired 父代调度

种群管理和父代调度职责分离。设本轮所有路线的父代访问总数为 $N$，轨迹 $i$ 被选次数为 $n_i$：

$$A_i=V_{search,i}+c\sqrt{\frac{\log(1+N)}{1+n_i}}.$$

默认 $c=0.25$。从 $A_i$ 计算稳定 softmax：

$$\Pr(\tau_i)=\operatorname{softmax}(A_i/T),\qquad T=0.2.$$

访问项让未充分尝试的路线保留机会，高质量路线仍因 $V_{search}$ 获得利用优势。UCB 不参与生存淘汰，不改变轨迹质量或 LLM 看到的历史。

每次选中父代后递增该轨迹的 `visit_count`。子代继承的是路径历史，不继承父代访问次数；访问次数只记录当前 frontier 作为扩展入口被尝试了多少次。

## 5. 单父代生成流程

```text
输入：任务 x、函数契约、LLM、评估器、预算 B、目标种群 M
1. 生成并评估有效初始程序，建立最多 M 条单节点轨迹。
2. 重复直到预算耗尽或搜索停止：
   a. 在 active frontier 上计算 Q、P、V_search 与 UCB 调度分数 A。
   b. 按 softmax(A/T) 选择一条父代轨迹，并记录一次访问。
   c. 在该轨迹中选择末节点或历史最好节点作为锚点。
   d. 均匀选择一个单轨迹语义算子：trace_ideate 或 trace_refine。
   e. 将任务、锚点程序、完整形成历史、锚点后的后续尝试和算子约束交给 LLM，提出 action。
   f. 每个 action 单独生成一个完整候选程序并评估一次。
   g. 每个有效候选只建立一条新轨迹：父轨迹截至锚点的前缀 + 一条新修改边 + 子程序。
   h. 子轨迹进入 active frontier；更新 global best 与 best-anchor。
   i. 当 active 数达到 2M 时执行一次统一种群管理，收缩回 M。
 3. 返回全局最好程序；运行结束时若未到 2M，不提前强制淘汰。
```

代码解析失败不消耗评估预算；程序评估失败消耗预算但不进入树、轨迹或种群。一个 action 只对应一次候选评估和一条新轨迹。

## 6. 锚点与轨迹上下文

父代轨迹先被选中，再在该轨迹内等概率选择：

- 末节点：保留最新思想积累；
- 轨迹内历史最好节点：从已知高质量程序继续尝试。

两者相同时直接使用。选择历史最好节点后，锚点之后的退步、停滞和失败尝试仍写入提示，作为已测试边界。

LLM action 提示包含：任务描述和函数契约、锚点完整代码、从根到锚点的有序修改、锚点后的后续尝试、每步适应度变化与结果、当前单轨迹算子约束。提示不包含内部轨迹评分、UCB 概率、种群状态或 checkpoint 字段。

代码生成阶段再次传入同一形成历史和后续尝试，避免 action 阶段看到历史而实现阶段只看到一句 action。v4 不把第二条轨迹、跨轨迹档案或全局 action 检索注入上下文。

## 7. 语义算子

v4 第一版只保留两个职责清晰的单轨迹算子，均匀选择：

| 算子 | 目的 | 约束 |
| --- | --- | --- |
| `trace_ideate` | 从完整历史中提出一个未尝试的新算法思想 | 每个 action 只有一个主要新思想，并说明其与历史证据的关系 |
| `trace_refine` | 深化一个已经显示价值的思想 | 每个 action 只改一个机制或参数规则，保留函数契约 |

双父代、`trace_synthesize`、`trace_transfer`、代码 crossover、供体轨迹和双轨迹写回均删除。若未来需要研究思想互补，应先定义可证伪的 action 关系，再单独设计机制，不通过隐式第二父代恢复。

## 8. 扩张—收缩种群管理

新轨迹产生后立即进入 active frontier，但管理延迟到：

$$|\mathcal P|\ge 2M.$$

扩张期间新轨迹有机会被父代 softmax 选中；该机会不等于最低一次试用保证。达到阈值后，在整个扩张池上重新计算 $Q/P/V$，执行：

1. 保留 $E=\max(2,\lceil0.1M\rceil)$ 条质量精英；
2. 保留 $R=\max(2,\lceil0.1M\rceil)$ 条相对于 `精英 + 已选 reserve` 最不相似的路线代表；
3. 剩余 $M-E-R$ 个席位按 $V_{search}$ 的 softmax 无放回抽样；
4. 未入选轨迹标记为 archived，只退出 active frontier，不从树记录中删除。

路线相似度使用代码 token、算法思想/动作词项和 `(operator, outcome)` 行为指纹的轻量代理。精英集合必须作为 max-min 距离参考，避免 reserve 只是第二批同质精英。相似度不进入父代 UCB 分数，不设置硬过滤，不引入 embedding、island 或额外 LLM novelty judge。

### Global-best reserve

全局最好程序由所有有效评估更新，独立于普通生存抽样。系统同时记录一条包含该节点的 active best-anchor 路线。管理时若该路线未进入质量精英，则将其强制加入精英席位并从其余精英中移除最弱者；因此 global best 始终可作为下一步锚点继续繁衍。输出最好程序和 active best-anchor 是两个不同概念，前者是结果，后者是搜索资源。

## 9. 运行状态与检查点

检查点保存树节点、单父代修改边、轨迹路径和 active/archived 状态、访问次数、global-best 节点与 best-anchor 路线、评估计数和随机搜索配置。检查点只保障恢复，不改变搜索机制。v4 检查点版本独立于旧 v3，旧版本不自动兼容。

过程日志至少记录：父代轨迹及其 `V_search/UCB/visit_count`、锚点原因、算子、action、子代结果、种群管理前后规模、精英/reserve/best-anchor 保留、全局最好更新。

## 11. 机制检查与可证伪假设

需要通过受控实验检查：完整轨迹上下文是否优于只给当前程序；单父代树是否比无历史搜索产生更高的样本效率；`Q/P` 与 UCB 分工是否比单一综合分数稳定；`2M` 延迟和 best-anchor 是否减少早期误杀；路线 reserve 是否降低思想同质化；退步/失败历史是否改变并改善下一步 action。

核心过程指标包括父代访问分布、UCB bonus 与搜索价值分布、锚点类型、改进/停滞/退步比例、轨迹管理周期、global-best route 是否持续 active、路线行为指纹覆盖和达到目标质量所需评估次数。最终分数不能单独证明轨迹机制有效。

## 12. 机制实验观察：程序膨胀

### 12.1 版本状态

程序膨胀是 TraceAAD v4 正式实验中已经确认的问题，也是计划在 v5 解决的主要机制缺陷。这里的“膨胀”指程序规模随搜索持续增加，而新增代码没有带来相称的适应度、泛化或执行效率收益。该观察不改变本文件前 11 节对 v4 的实现定义；v4 结果和工件继续作为无复杂度控制条件下的实验基线。

v4 总体搜索仍能产生高质量算法代码，程序变长本身也可能对应有价值的新机制。问题在于当前搜索没有区分“为有效思想付出的必要复杂度”和“没有明确收益的累积复杂度”，因此长度增长缺少制动。研究目标不是让程序越短越好，而是要求新增复杂度与可验证收益相匹配。

### 12.2 实验发现

2026-07-24 的运行快照使用待设计函数的非空代码行数比较每个 run 最早和最晚 20% 候选。TSP Construct 和 CVRP-ACO 的 v4 后期/早期长度比分别达到 3.52× 和 3.66×，高于同任务的 MCTS-AHD、PathWise 以及 TraceAAD v2/v3。Knapsack Construct、Online Bin Packing 和 OP-ACO 的 v4 比值分别为 5.14×、2.17× 和 2.33×，说明该现象跨 task、跨重复存在。

单父代修改边提供了更直接的证据。在 TSP、CVRP、KP、OBP 和 OP-ACO 中，59.5%–74.8% 的子程序比锚点程序更长；五个 task 中，变长子代的直接改进率均未超过变短子代。KP 的三次 v4 run 分别在 sample 33、41、51 以 55、71、46 行程序达到相同训练最好分数，继续搜索后，后 20% 候选的平均中位长度增长到约 382 行。

因此，程序长度与 sample order 的正相关不能解释成“更长程序更优秀”。后期候选同时更长、分数也可能更高，包含明显的时间和谱系混杂；父子配对结果表明，增加长度本身没有提高下一步直接改进概率。完整统计和跨方法文献核对见[程序长度膨胀相关研究](程序长度膨胀相关研究.md)。

### 12.3 v4 中的形成机制

v4 的长度正反馈由四个环节共同形成：

1. `trace_ideate` 要求提出新思想，`trace_refine` 要求保留已有价值思想后继续细化；两者均没有要求删除被替代或无效的逻辑。
2. 代码生成阶段传入锚点完整程序，再要求返回新的完整实现。继承旧实现并局部增加代码，是同时保持可执行性、已有分数和 prompt 表面要求的低风险策略。
3. 最大轨迹长度 8 只限制历史窗口，不限制当前程序。旧逻辑进入程序后仍会被完整传给下一代，形成“长父代—长上下文—长子代”的路径依赖。
4. `ProgramNode`、`ValueVec`、父代调度和生存管理均不记录或比较复杂度；同分或近同分时，更简洁的程序没有选择优势。16384-token 输出上限远高于当前候选规模，只是安全边界，不是简约压力。

代码 token 差异 reserve 理论上可能把新增标识符视为路线差异，但当前 TSP 快照中，长度与相对精英的代码 novelty 相关方向并不一致，因此它不是主要原因。v2 曾包含 `simplify` 算子和 compactness 信号，后续核心收缩将其删除；版本间还有模型、种群和其它配置变化，这一历史关联只能作为辅助证据，不能单独证明因果。

### 12.4 相关方法提供的启示

LLM4AD 领域已经出现直接或隐含的复杂度控制：

- FunSearch 在同一分数簇内提高短程序的采样概率，核心是先保证质量等价，再偏向简洁表示。
- EoH 用 M3 算子识别并删除冗余组件；MEoH 保留简化算子，并允许把效率、复杂度和可读性作为独立目标。
- CALM 明确指出 injection、crossover 和 replacement 会使 heuristic 越来越复杂，使用 simplification operator 与 collapse mechanism 抵消冗余；其消融中移除 simplification 带来最大的性能下降之一。
- PathWise 没有直接的程序长度目标，但 world-model critic 会从优劣代码对比中形成减少冗余、降低算法复杂度和执行成本的反馈；其状态剪枝控制的是搜索状态规模，不能直接等同于代码 anti-bloat。
- ReEvo、HSEvo 和 MCTS-AHD 没有发现明确的程序长度控制。反思、语义多样性、树路径和短自然语言描述都不会自动产生简约压力。
- ShinkaEvolve 的作者实现记录 LOC、圈复杂度、Halstead、可维护性和嵌套深度，并允许将其配置为 archive 准则；默认仍只按 `combined_score`，说明“记录复杂度”和“让复杂度影响搜索”是两件事。

这些方法共同说明，生成侧的简化机会和选择侧的简约偏好承担不同职责。只有简化 prompt，短候选仍可能因轻微分数波动被淘汰；只有长度惩罚，又可能压制真正需要的复杂机制。v5 需要让二者围绕轨迹证据协同工作。

### 12.5 面向 v5 的推荐方向：轨迹感知的扩张—整合

TraceAAD 的独特优势是：算法知识保存在轨迹中，不必全部永久保存在当前代码中。一个机制被删除、替换或合并后，它的 action、分数变化和失败边界仍留在修改边上。因此 v5 可以把“保留来时路”和“保留所有旧代码”分开，让路线在引入思想后周期性整合实现，而不丢失研究经验。

推荐的最小方案包含三个相互配合的部分。

第一，给每个程序节点记录轻量复杂度 $C(p)$，以 AST 节点数作为主要结构尺度，同时记录非空 LOC、字符数和运行时间用于诊断；每条边同时记录适应度变化 $\Delta F$ 与复杂度变化 $\Delta C$。复杂度先作为事实和修改结果，不直接加入 $V_{search}$。这样可以区分“改进且变长”“同质变长”“近同质变短”和“简化失败”，避免把所有增长或所有缩短视为同一种行为。

第二，在每条轨迹内维护一个质量等价集合与紧凑锚点。统一优化方向后的轨迹最好值记为 $\tilde F_{\mathrm{best}}(\tau)$，则

$$
\mathcal E_\epsilon(\tau)=
\left\{p_i\in\tau:
\tilde F(p_i)\geq \tilde F_{\mathrm{best}}(\tau)-\epsilon_{\mathrm{task}}
\right\},
\qquad
p_{\mathrm{compact}}(\tau)=
\arg\min_{p_i\in\mathcal E_\epsilon(\tau)} C(p_i).
$$

$p_{\mathrm{compact}}$ 表示这条路线中已经达到近似同等质量的最简洁实现。它不替代精确 global best，也不把短程序定义为更高质量；它作为新的可选锚点，使后续思想能够从干净基线继续发展。其节点标识应作为路线级摘要独立保留，不因 8 节点 prompt 后缀截断而丢失，也不需要恢复全局 archive 检索。$\epsilon_{\mathrm{task}}$ 不应使用跨任务固定绝对值，优先根据训练实例上的成对结果、重复评估方差或 bootstrap 等价区间确定；缺少这些信息时，先从完全同分择简开始，再通过消融扩展到近同分。

第三，增加一个轨迹整合动作 `trace_consolidate`。当当前端点比 $p_{\mathrm{compact}}$ 更复杂却没有取得可区分的质量提升，或者最近多条边持续增加复杂度而没有形成有意义的累计收益时触发。它读取完整历史中的有效修改、无收益增加和失败边界，要求 LLM 保留有证据支持的核心机制，删除、合并或替换冗余实现，再生成一个正常评估的完整子程序。`trace_refine` 也应明确优先替换已经失效的实现，而不是在旧组件旁继续叠加。整合候选不因“更短”自动接受；只有实测质量仍处于等价区间时，才在父代与生存选择中优先于更复杂的等质候选。

该方案形成“扩张—整合”节奏：`trace_ideate` 允许为新思想增加必要复杂度，`trace_refine` 改善已有机制，`trace_consolidate` 利用轨迹证据偿还无收益复杂度。global best 继续只由任务适应度定义，$V_{search}$ 的质量、趋势与访问公平职责保持不变；复杂度只决定何时整合、从哪个近同质节点继续，以及近同质候选之间的选择顺序。

### 12.6 不推荐作为 v5 核心的做法

- 不把固定的 `fitness - λ × length` 作为主价值。不同 task 的分数和合理程序规模不同，固定权重会混淆算法质量与表示成本。
- 不用硬 LOC/token 上限承担主要控制。硬上限适合作为上下文和执行安全边界，不能判断复杂度是否有收益。
- 不把 novelty 或 embedding 多样性当作简洁性。新颖、可读、快速和短是不同属性。
- 不在每轮无条件调用简化算子。简单程序和刚获得显著提升的复杂程序没有整合必要，固定频率会浪费评估预算。
- 不从代码中删除机制后同时删除轨迹证据。实现可以压缩，来时路仍应完整记录，这正是后续避免重复试错的依据。

### 12.7 v5 的可证伪实验

最小消融应固定模型、task、预算和随机设置，比较：

1. v4 baseline；
2. 只增加复杂度记录，不影响搜索；
3. 增加 `trace_consolidate`，但不做近同质择简；
4. 完整的“整合动作 + 紧凑锚点 + 近同质择简”。

除训练与 held-out 最终指标外，应报告候选、父代、active survivor 和 global best 的 LOC/AST 曲线，$\Delta F$–$\Delta C$ 联合分布，三类算子的长度增量与改进率，整合候选的质量保持率，以及达到同等质量所需的平均程序规模。核心假设为：

> `[待验证]` 在不改变任务质量主目标的前提下，利用轨迹保存被删除机制的历史证据，并在质量等价区域内周期性整合代码，可以降低无收益程序增长，同时保留 TraceAAD 的搜索质量与历史指导能力。
