## 1. 核心概念辨析：预算决策的三维结构

在有限预算的序贯算法设计中，必须严格区分三个维度的概念，避免将物理资源事实与在线控制策略混淆：

| 概念维度 | 回答的核心问题 | 典型范畴 | 关键辨析要点 |
| :--- | :--- | :--- | :--- |
| **决策对象** | 机会给谁、做什么？ | 节点 $n$、算子 $o$、联合动作 $(n, o, r)$、代码候选 | 决定搜索重心的投向；单纯给单节点赋予“未来价值标量”隐含了脱离后续算子的静态假设 |
| **资源单位** | 消耗了什么物理成本？ | evaluator 真实调用次数、API 调用次数、Token 量、运行时间 | 系统主预算严格受限于真实 evaluator 调用次数（如 1,000 次评测）；其余为辅助开销 |
| **重决策频率** | 何时重新评估并分配新机会？ | 单候选单评价单步重选、同父代固定批次重选、多步 rollout 结束后重选 | 决定控制器的在线响应灵敏度与选项价值（Option Value）的保留程度 |

**基本认识**：
- “一次候选消耗一次真实评测”是客观的资源单位事实，**并不能直接推导出“系统必须在任何情况下严格逐步重选”的绝对教条**；
- 采用多步尝试或同父批次，属于在重决策频率上所做的工程与机理权衡（例如用重选的灵活性换取同父代不同算子的配对对照数据），不应将特定阶段的权衡选择上升为不可逾越的唯一原则。

## 2. 价值对象与分配方式的演进脉络

过去版本在分配机制上的探索与反思，展现了价值对象从“复杂标量代理”逐步收敛至“清晰可归因基准”的历程：

| 阶段 | 当时分配的对象与方式 | 核心做法 | 暴露的问题与反思 |
| :--- | :--- | :--- | :--- |
| **V2–V3** | 轨迹 / 种群整体 | 多维轨迹打分、岛模型、迁移、Pareto 筛选 | 控制变量严重混杂；整条轨迹的静态历史无法预测下一次局部修改的边际增益 |
| **V4–V7** | Active Trajectory | 当前表现 + 历史趋势坡度 + UCB | 将短期抖动强行拟合为趋势标量；淘汰机制容易误将暂时退步的探索判定为全无潜力 |
| **V8–V8.3** | 树节点 / 子树 | 子树最好成绩回传 $G(n) = \max(f(n), \max_c G(c))$ | 偶发突破使祖先节点长期垄断信用，引发严重的根锁定（Root Locking）与兄弟节点爆炸 |
| **V9.1–V9.4** | 路线推进率 / 多步链路 | 局部多步 credit、固定 3 步 rollout | 多步绑定锁死了即时止损的灵活性（丧失选项价值）；推进率打分将 88.9% 预算偏向低分节点 |
| **V9.5–V9.7** | 锚点 / 单节点 | $q + s/\sqrt{n+1}$，历史信息转入上下文 | 形式简洁，但固定加权项跨任务尺度敏感；无条件单节点估值无法表达不同算子的需求 |
| **V9.19–V9.22** | 行为区域 / 假说 + 动作 | P/U/T、Action Utility、假说 UCB | 行为指标改变了搜索树形，却未稳定改善终局；完整在线 BehaveSim 还缺乏跨任务的低成本保证 |
| **V10–V10.1** | 联合动作 / 同父批次 | 质量偏置抽样，同父串行生成 Refine/Pivot/Fuse | 用放弃单步重决策的灵活性，换取同一父节点上三种算子行为的完整配对对照数据 |
| **V10.5** | 单步联合决策基线 | 逐步重决策（单候选单评价）；透明基线配比 | 回归逐步重决策以保留选项价值，保持分配基线简洁透明，优先服务生成端机理辨识 |

## 3. 已经确立的实证经验与边界认知

### 3.1 事实档案、繁衍资格与 Prompt 组织的三层解耦
必须严格分离数据管理的三个层次，不可因搜索控制需要而篡改历史事实：
1. **完整事实档案（Full Archive）**：记录搜索树上发生的所有代码、评分、报错与父子关系。**低质量与崩溃节点同样作为不可篡改的事实永久保留，绝不物理丢弃**；
2. **在线繁衍资格（Active Candidate Set）**：决定当前步骤允许哪些节点参与父代或参照抽取。**保留事实不等于所有节点享有均等被选概率**；通过活跃集、质量偏置抽样限制繁衍范围，是控制搜索重心的合理且必要的手段；
3. **Prompt 上下文子集（Context Subset）**：仅从历史档案中提取与当前设计行为高度相关的局部证据输入模型。

### 3.2 祖先信用回传的实证反思
V8 尝试的子树最好成绩回传导致了根锁定与资源浪费：
- **机理反思**：后代的突破高度依赖于特定动作序列与上下文的触发。脱离具体动作直接对祖先进行无条件信用回传，容易把偶然的后代突破转化为对整条分支盲目追加预算；
- **经验边界**：这证明了简单的 max-backup 信用分配在开放代码搜索中存在严重负面效应，并不代表具有因果归因能力的层次化表示全无价值。

### 3.3 已兑现 Fitness 是代码骨架，而非未来潜力
- 真实得分 $f(n)$ 仅反映该算法在当前训练实例上的已知客观表现；
- 在父代选择中给予高分程序更高的抽样概率（如 Boltzmann 偏置抽样），其根本合理性在于：**高质量程序为下一步算法设计提供了更可靠的代码骨架与逻辑基底（Scaffold）**；
- 严禁将已兑现质量简单误读为对节点“未来增量潜力”的无条件保证。

### 3.4 质量证据与探索不确定性的正交性
- 质量证据来自已知评估结果；探索项（如访问频次、覆盖稀疏度）反映当前认知的不完备（Epistemic Uncertainty）；
- 两者具有不同的逻辑尺度，简单的固定线性加权（如跨任务使用统一超参的 UCB）在面对不同任务的适应度景观时极易失真（例如在 TSP 上探索项主导，在 OBP 上探索项失效）；
- 探索资源的分配应围绕“当前何处最缺乏关键信息”展开，不宜强行将不确定性折算为伪装的质量加分。

### 3.5 决策频率的科学取舍：选项价值 vs 配对数据
- **单步重选（Step-by-step Re-allocation）**：每次评估后立即根据最新历史状态更新选择，最大化保留了根据即时反馈及时止损、调整方向的**选项价值（Option Value）**；
- **批次/多步尝试（Batching / Rollout）**：在固定父代上连续执行预设步骤。其代价是暂时让渡了即时重决策灵活性，但其价值在于能够受控收集同一基底下的多算子对照数据，或给予需要多步渐进微调的假说一定的容错区间；
- 系统应根据当前科研阶段的重心灵活选用决策频率，而非将某一种模式教条化。

### 3.6 辅助观测的信息价值与在线成本必须同时成立

- 群体统计成立，只说明观测含有描述信息，不说明维护这项观测值得占用在线资源；
- V9.19 已经先后实现独立行为 panel，以及正式评价内同步记录五任务轨迹；后一版也缓存轨迹并只增量计算新旧节点距离。因此“合并评价”和“缓存”不是尚未尝试的简单补丁；
- 评价内采集解决额外求解，没有消除随 archive 增长的成对距离。OBP 的 scale-matched 长前缀造成高精确编辑距离成本；ACO 的稳定行为证据可能要求额外随机流；
- V9.21 已将 BehaveSim 从在线控制撤下。当前把它用于离线机制解释；任何轻量在线替代都要把画像、距离、峰值内存和延迟计入等总资源对照。

## 4. 稳健分配策略的基本准则

结合历代探索经验，当前阶段在预算分配上遵循以下准则：

1. **基线透明优先**：在生成机理辨识阶段，优先保持分配规则清晰、稳定、少超参，避免由于分配逻辑频繁变动导致生成端效果难以归因；
2. **动作条件化思考**：在考虑“给哪个节点预算”时，必须联动考虑“准备对其执行什么算子”；
3. **警惕过程指标激活**：任何新颖的分配代理（如多样性距离、行为新颖度、假说 UCB）能够改变搜索选择，不等于其具备真实的性能预测力，必须以同预算下的端到端表现作为最终检验标准。
