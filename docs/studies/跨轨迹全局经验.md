# 跨轨迹全局经验

> 研究问题：怎样把多条轨迹的真实试错压缩成可持续更新、可指导下一步生成的全局认识？
>
> 状态：已形成阶段判断，并被 TraceAAD v5 采用。
>
> 当前判断：祖先轨迹承担局部经验；跨轨迹事实定期重写成一份有界、带证据的全局经验，只进入 action 决策。
>
> 影响设计：[TraceAAD v5：全局经验机制](../methods/TraceAAD-v5完整机制设计.md#6-全局经验机制)。

本文只回答一个问题：已有 LLM 自动算法设计方法怎样把跨个体、跨代的搜索结果变成后续生成可用的经验，以及这些机制对 TraceAAD v5 的“全局搜索认识”有什么启发。材料以本地论文源码和作者参考代码为准。

文中严格区分三层证据：

- **论文主张**：作者在论文中明确提出或通过实验报告的机制；
- **代码行为**：当前本地作者仓库实际执行的更新和使用方式；
- **TraceAAD 推断**：根据前两者与 TraceAAD 核心认识提出的设计判断，不冒充原作者结论。

## 1. 核心结论

相关工作提供了三种不同的跨代知识：

1. **显式文字经验**：ReEvo 把当代比较反思递归压缩成长期反思；HSEvo 进一步区分产生和未产生新 elite 的反思；ShinkaEvolve 周期性总结近期全部程序，维护全局洞见并产生后续建议。
2. **短期策略反馈**：PathWise 分别反思高层搜索 action 和底层代码生成，把最新反馈路由给下一步 policy 与 world model。
3. **隐式搜索记忆**：FunSearch、EoH、MEoH、MCTS-AHD 和 ShinkaEvolve 的 archive、population、island、tree path 与 inspiration programs 保存可再次利用的程序，却不等于已经形成任务层面的语义认识；CALM 则把搜索反馈进一步写入模型参数。

对 TraceAAD 最重要的判断是：

> v5 不需要照搬 ReEvo 的“短期反思—长期反思”双层结构。祖先轨迹已经承担了局部、短期且高分辨率的经验，因此只需在轨迹之上增加一个缓慢更新、证据约束、篇幅有界的全局经验状态。

这个状态不是原始分叉的集合，也不是搜索日志摘要。它是多条真实轨迹共同支持的任务认识，用较低分辨率回答：目前哪些思想在什么条件下有效，哪些做法踩过什么坑，还有哪些方向值得继续验证。

这个判断只限定“全局经验状态”怎样构建，不排斥生成时按需读取一条具体参考轨迹。后者属于高分辨率的跨路线迁移或组合，不承担全局总结。

## 2. ReEvo：递归压缩的长期反思

### 2.1 论文明确机制

ReEvo 的每轮搜索依次执行 selection、short-term reflection、crossover、long-term reflection 和 elitist mutation。短期反思针对一对表现不同的父代，比较它们的代码并给出改进提示；crossover 同时看到较差代码、较好代码和这条短期反思。长期反思再读取“旧长期反思 + 当轮新短期反思”，把它们重新总结成改善 heuristic design 的提示；精英变异使用当前 elite 与长期反思生成候选（`../papers/ReEvo/sections/04_evolution.tex:34-48`）。

论文 prompt 进一步确定了反思内容：

- 短期反思看到完整的 better/worse code，但只被要求在 20 词内给出设计建议；黑盒任务可在 50 词内推断节点、边属性与 objective 的关系（`../papers/ReEvo/appendix/01_prompts.tex:64-94`）。
- 长期反思看到旧长期反思和当轮全部短期 insights，并在 50 词内输出 constructive hints（`../papers/ReEvo/appendix/01_prompts.tex:117-125`）。
- 精英变异看到 task、长期反思与 elite code（`../papers/ReEvo/appendix/01_prompts.tex:127-138`）。

因此 ReEvo 的长期反思主要总结的是“较好程序相对较差程序体现了什么设计规律，以及这些规律怎样指导 elite 的下一次变化”。它没有预定义“成功经验、失败经验、注意事项”等字段，而是让一个很短的自由文本承担这些内容。

论文也给出两个证据边界。其组件消融报告去掉长期反思或短期反思都会退化，但这是完整组件级结果，没有单独证明长期反思中哪类认识有效（`../papers/ReEvo/sections/06_ablation.tex:68-89`）。另外，部分任务的初始长期反思并非搜索产生，而是作者预置的“组合多种因素、尝试稀疏化、尝试 look-ahead”等外部知识（`../papers/ReEvo/appendix/01_prompts.tex:333-340`）。

### 2.2 作者代码真实行为

当前本地代码把长期反思维护为单个字符串。若任务目录存在 `external_knowledge.txt`，它会被用作初始长期反思（`../reference_code/ReEvo/reevo.py:66-77`）。每轮中：

1. 随机选择目标值不同的父代对；
2. 根据 objective 明确标出 better/worse code，批量生成短期反思（`../reference_code/ReEvo/reevo.py:325-378`）；
3. 用旧字符串与当轮全部短期反思生成新字符串，并**覆盖**旧长期反思（`../reference_code/ReEvo/reevo.py:380-405`）；
4. 新长期反思只直接指导 elite mutation（`../reference_code/ReEvo/reevo.py:441-458`）；
5. 这套更新在每个 evolution iteration 都发生（`../reference_code/ReEvo/reevo.py:461-486`）。

这里有一个容易被“长期经验”名称遮蔽的事实：ReEvo 的新短期反思来自**既有父代之间的静态比较**，长期反思在 crossover 结果产生之后更新，但输入中没有这些新 offspring 的实际结果。因此它并不知道“刚才这条反思是否真的带来了改进”。它积累的是基于相对优劣的归纳，不是对反思建议本身的结果归因。

### 2.3 可借鉴原则与边界

**可借鉴：**

- 旧经验与新证据每次重新归纳，而不是无限追加；
- 严格限制经验篇幅，避免跨代记忆膨胀；
- 经验直接进入后续生成，使其成为搜索状态的一部分；
- 通过 better/worse 对比形成比单个优秀代码更清晰的语义差异。

**不宜直接照搬：**

- 每一步都更新会让全局认识追逐局部噪声；
- 只依据“两个程序谁更好”容易把相关性写成因果规律；
- 不核对建议应用后的结果，无法保证总结出的“坑”真的踩过；
- 单个 50 词自由文本虽然简洁，但容易在递归重写中遗忘旧的有效条件、放大最新观察；
- 只用长期反思指导 elite mutation，会把全局经验收缩为“怎样继续改最好程序”，没有覆盖多条轨迹的路线选择视野。

## 3. HSEvo：用后续搜索结果区分有效与无效反思

### 3.1 论文明确机制

HSEvo 认为 ReEvo 对每一父代对分别反思既不够 general，又浪费资源。它的 flash reflection 先把当轮被选父代去重并整体排序，让 LLM 分析 mixed、good 和 bad ranking pairs；随后把当轮分析与历史分析比较，形成后续 crossover 和 elite mutation 使用的指导（`../papers/HSEvo/aaai25.tex:503-512`）。

其 prompt 先要求从按表现排序的多段代码中提炼少于 60 词的 `Experience`（`../papers/HSEvo/appendix.tex:237-265`），再把当前经验与历史上的 good reflection、bad reflection 合并，输出 `Keywords / Advice / Avoid / Explanation` 四项、总计少于 100 词。论文明确把“产生新 heuristic 的过去反思”归入 good，把“没有产生新 heuristic 的过去反思”归入 bad（`../papers/HSEvo/appendix.tex:268-287`）。

论文同时报告一个重要负面边界：仅把 ReEvo 的 reflection 替换成 flash reflection，在更长 token budget 下不足以继续改善 objective 与 diversity；作者据此认为没有 diversity-promoting mechanism 时，flash reflection 本身不够（`../papers/HSEvo/aaai25.tex:554-559`）。

### 3.2 作者代码真实行为

代码会把被选程序按 objective 从好到坏排序并去重，然后生成 `Analysis` 与 `Experience`（`../reference_code/HSEvo/hsevo.py:372-420`）。综合反思读取当前 experience、历史 good 列表和历史 bad 列表，生成当前 generation 使用的 memory（`../reference_code/HSEvo/hsevo.py:431-461`）。

当 crossover 和 mutation 都评估完成后，代码比较 elite 的 `code_path` 是否变化：变化就把**本轮 flash experience**加入 good list，否则加入 bad list（`../reference_code/HSEvo/hsevo.py:690-718`）。这比 ReEvo 多了一层结果检验，但归因仍然很粗：

- elite 变化只表示这一轮出现了新的 elite，不证明是哪一条经验导致；
- 一轮中同时发生 crossover 和 mutation，无法区分贡献来源；
- “没有新 elite”不等于经验错误，也可能是候选生成或评估噪声；
- good/bad 列表在当前代码中持续累积，没有启用已注释的长度限制。

### 3.3 对 TraceAAD 的启发

HSEvo 最值得借鉴的不是四字段格式，而是一个原则：

> 全局经验不能只总结代码差异，还应接受后续真实结果的反证和修正。

但 TraceAAD 不应复制“按整轮是否刷新 elite 给反思贴好坏标签”的粗粒度归因。轨迹边已经记录具体 action、父节点、子节点与结果，能够用更直接的局部证据判断某个思想在某个上下文中产生了什么变化。

## 4. ShinkaEvolve：周期性 meta-scratchpad

### 4.1 论文明确机制

ShinkaEvolve 与用户设想最接近。论文明确提出 meta-scratchpad：每隔 \(T\) 代总结近期程序评估，识别共同的优化策略和设计原则；meta-agent 把它们合成为 actionable recommendations，再附加到 mutation prompt，以便从累积的进化经验中提供高层指导（`../papers/ShinkaEvolve/sections/03_method.tex:74-76`）。

它还同时保留两种未经抽象的全局视野：固定大小 archive 中的 top-performing programs 与随机 archive samples 被作为 inspiration programs 加入 mutation context（`../papers/ShinkaEvolve/sections/03_method.tex:9-10`）；程序的 scalar fitness、public metrics 和 textual feedback 也会存入 archive 供后代使用（`../papers/ShinkaEvolve/sections/03_method.tex:51-74`）。因此 ShinkaEvolve 同时拥有“原始案例视野”和“抽象全局经验”，两者职责不同。

### 4.2 作者代码真实行为

代码实现比论文概述更具体：

- 全部新评估程序都会进入待总结集合，包括正确和错误程序（`../reference_code/ShinkaEvolve/shinka/core/summarizer.py:45-64`）。
- 论文说“每 \(T\) 代”，当前同步实现实际按**尚未处理的程序数**达到 `meta_rec_interval` 触发，这更贴近“产生一定数量个体后更新”的设想（`../reference_code/ShinkaEvolve/shinka/core/summarizer.py:76-92`）。
- 更新包含三步：逐程序摘要、生成 global insights scratchpad、再生成 recommendations（`../reference_code/ShinkaEvolve/shinka/core/summarizer.py:94-155`）。
- 全局洞见会读取新程序摘要、previous global insights 和 current best，要求分别总结 successful patterns、ineffective approaches、implementation insights 和 performance analysis，并引用具体程序及结果（`../reference_code/ShinkaEvolve/shinka/prompts/prompts_meta.py:29-90`）。
- recommendations 与洞见分开生成，要求具体、可执行且有证据（`../reference_code/ShinkaEvolve/shinka/prompts/prompts_meta.py:93-127`）。
- global scratchpad 会进入后续 prompt evolution 的上下文（`../reference_code/ShinkaEvolve/shinka/prompts/prompts_prompt_evo.py:129-148`）。

### 4.3 可借鉴原则与边界

**可借鉴：**

- 按新增评估样本数周期更新，而非每一步更新；
- 同时观察成功、失败、invalid 和当前最好程序；
- 新认识读取旧认识并进行修订；
- 把“对搜索现状的认识”和“下一步建议”区分开；
- 要求认识引用实际程序、指标和反馈，压低自由想象空间。

**需要收缩：**

- 三次 meta LLM 流程、逐程序 LLM 摘要和长期累积 individual summaries 对 TraceAAD v5 过重；
- `Successful / Ineffective / Implementation / Performance` 四大区块容易变成完整实验报告，而不是可直接影响下一步搜索的紧凑状态；
- 过度强调 current best 可能再次把全局视野缩成精英优化；
- 把全局 scratchpad 放入“prompt evolution”在 ShinkaEvolve 中有其框架语义，TraceAAD 应让它直接服务于算法轨迹的下一步判断。

## 5. PathWise：即时、分工明确的 routed reflection

PathWise 没有维护类似 ReEvo 的累计长期总结。它的 policy critic 比较多种 parent-selection / derivation actions 及其多次 rollout 的平均表现，反思高层演化策略；world model critic 比较当步最好与最差的代码 rollout，反思底层代码生成质量。二者的结果分别指导下一步 policy 与 world model（`../papers/PathWise/example_paper.tex:318-376`）。

论文消融显示移除任一 critic 都会退化，policy critic 的影响更大；作者将其解释为高层 parent selection 和 operator choice 的反馈比单纯代码级修改更重要（`../papers/PathWise/example_paper.tex:834-856`）。这对 TraceAAD 的启发是：全局经验不应只有“怎样写代码”，还应包含“哪些思想路线与修改方式值得选择”的搜索层认识。

代码行为表明它主要是最新一步的状态反馈：当前 reflection 在下一步被覆盖，world-model reflection history 只保留最新一条；新的 outer iteration 也只继承上一轮最新反思（`../reference_code/PathWise/pathwise.py:1509-1526`、`../reference_code/PathWise/pathwise.py:1604-1617`）。因此 PathWise 更像短期自适应 policy，不是跨全部轨迹慢慢形成的全局任务认识。

它还提供了一个信息量边界：论文实验显示同时增大 action 数与 rollout 数会因 critic 上下文过大而退化，多样的 action 对 policy critic 比同一 action 的更多 rollout 更有价值（`../papers/PathWise/example_paper.tex:2400-2405`）。这支持 v5 采用少量、有对比度的证据更新全局经验，而不是把所有分叉全部交给 LLM。

## 6. 其他方法：保存历史不等于形成全局经验

### 6.1 MCTS-AHD

MCTS-AHD 的树路径保存从根到叶的 heuristic evolution history，s1 action 会分析待扩展叶节点到根节点的全部 unique heuristics，提取 advantageous designs 后生成新程序（`../papers/MCTS-AHD/icml2025.tex:249-251`）。这是祖先路径知识，与 TraceAAD 的局部轨迹视野接近；论文和代码中未发现周期性跨分支语义总结，因此不能把 tree 本身称为全局经验。

### 6.2 EoH 与 MEoH

EoH 让 LLM 同时读取多个已有 thought/code，并通过 E1/E2 寻找差异或共同思想，作者将其称为从 previous experiences 学习的 fine-grained in-context learning（`../papers/EoH/3-method.tex:4-13`、`../papers/EoH/3-method.tex:69-90`）。MEoH 延续多父代 prompt，同时以 dominance-dissimilarity 管理性能与代码差异（`../papers/MEoH/MEoH.tex:229-233`、`../papers/MEoH/MEoH.tex:290-299`）。两者提供的是当次选中个体的案例学习，没有单独、持续更新的全局语义状态。

### 6.3 FunSearch 与 ShinkaEvolve 的 inspiration programs

FunSearch 的 islands 和按表现选择的多个程序让历史优秀实现重新进入 prompt；ShinkaEvolve 的作者代码进一步从 archive 采样 best、elite、random 和 top-k programs（`../reference_code/ShinkaEvolve/shinka/database/inspirations.py:36-140`、`../reference_code/ShinkaEvolve/shinka/database/inspirations.py:143-242`）。这类机制能扩大视野，但仍把“判断哪些规律成立”的工作留给每次生成。它们与全局经验互补，不等价。

### 6.4 CALM

CALM 把搜索产生的 prompt-response-performance triples 作为训练数据，用 heuristic quality 进行 GRPO fine-tuning，让模型内化成功 heuristic 的特征（`../papers/CALM/main.tex:93-104`、`../papers/CALM/main.tex:129-131`）。这是把全局经验写入模型参数的数值路径，可能比文字状态更深，但需要训练、成本更高、认识不可直接审计，也不符合当前 v5 追求的简洁机制。它适合未来研究，不应成为这一步设计的起点。

## 7. 面向 TraceAAD v5 的最小方案

以下是基于相关工作的 **TraceAAD 设计推断**，不是任何一篇论文的原始机制。

### 7.1 科学角色

TraceAAD 的生成上下文包含两个分辨率尺度、三个知识来源：

- **祖先轨迹**是当前算法的局部来时路，保存高分辨率 action–result 序列，回答“怎样承接当前算法”；
- **直接参考轨迹**按需提供另一条路线的高分辨率实现与试错历史，回答“有什么具体思想可以迁移或组合”；
- **全局经验**是多条轨迹共同形成的任务认识，保存低分辨率跨路线规律，回答“整个搜索目前学到了什么”。

全局经验的作用不是替代 trajectory selection，也不是成为另一个 parent。直接参考轨迹同样只是知识来源，不成为第二个结构父代。全局经验提供缓慢变化的任务级先验，使被选中的任何轨迹都能知道其他路线已经验证过的规律和踩过的坑。

### 7.2 最小内容

全局经验只保留三个可选部分；没有可靠内容时允许为空：

1. **有效经验**：哪些算法思想或修改方式，在什么条件下带来了什么改善；
2. **已知陷阱**：哪些具体做法在什么条件下导致退步、失效、过拟合、冗余或重复试错；
3. **待验证方向**：已有局部迹象但证据尚不足，值得由后续轨迹继续验证的假设。

“针对当前代码应改哪一行”属于局部轨迹推理；“某个任务中 look-ahead 在高负载阶段反复有效”才属于全局经验。全局经验不需要逐个罗列尝试，也不需要填满三个部分。

每条认识至少保留“条件—做法—结果”三者。只有结果真实来自已评估程序时才能写入。单次现象可以进入“待验证方向”，不能直接升级为普遍有效经验或永久禁区。

### 7.3 形成与更新

设第 \(k\) 次反思前的全局经验为 \(G_{k-1}\)，新产生的一批真实轨迹边证据为 \(E_k\)，则：

\[
G_k=\operatorname{Reflect}\!\left(G_{k-1},E_k\right).
\]

这里的关键不是公式，而是四个约束：

1. **批量更新**：生成固定数量的新个体后再反思，不跟随每一步波动；
2. **完整对比**：新证据同时包含已成功评价边中的改善、停滞和退步，不只看 global best；invalid 与生成失败留在运行日志中，不混成算法结果；
3. **重写而非追加**：每次输出新的有界状态，合并重复认识、修正旧结论、删除已经被反证或失去作用的内容；
4. **证据约束**：输入提供旧经验当前引用的原始事实、新批次的 action、相对父代/路线/全局的结果和必要任务条件，输出必须区分观察事实与归纳判断。

ReEvo 支持“旧经验 + 新经验递归压缩”，HSEvo 支持“用后续结果反证反思”，ShinkaEvolve 支持“按新增个体批量更新并结合当前最好”，PathWise 支持“比较不同搜索 action 而非只比较代码”。TraceAAD 可以把这四个原则压缩进一次周期性全局反思，无需引入四套机制。

### 7.4 怎样进入下一步轨迹搜索

下一步算法生成仍以“当前程序 + 当前祖先轨迹”为主体，双轨迹算子可再读取一条直接参考轨迹，最后提供同一份简短全局经验作为额外高层视野：

\[
a_t\sim\pi(x,p_t,\tau_t,\rho_t,G_k).
\]

它应帮助 LLM完成三类判断：

- 延续当前轨迹时，是否有跨路线反复有效的思想可以借鉴；
- 当前拟议修改是否重演了其它路线已经证实的坑；
- 当前轨迹陷入停滞时，哪些尚未充分验证的方向值得换向尝试。

全局经验只提供指导，不直接否决生成，也不改变真实 fitness。这样错误或过时认识仍能被新的搜索结果推翻。

### 7.5 奥卡姆边界

v5 第一版不需要：

- 再建立 ReEvo 式短期反思层，因为祖先轨迹已经保存局部经验；
- 直接检索和拼接大量历史分叉，因为全局经验的目的正是压缩这些分叉；
- 分别维护 good/bad memory bank、policy critic、world-model critic 和 recommendation agent；
- 把全局经验细分成复杂数据库、置信度模型或永久规则库；
- 每一步更新，或让全局经验无限增长；
- 用模型自由发挥补齐没有搜索证据的“领域知识”。

最小可行结构就是：

> 一份有界全局经验状态；每积累一批新个体，用旧状态与新轨迹证据重写一次；随后作为额外高层视野进入所有轨迹的下一步生成。

## 8. 应保留的研究边界

现有论文能支持“长期反思、meta-scratchpad 和 routed critic 能够帮助 LLM-AAD 搜索”，但不能直接证明上述 TraceAAD 组合一定有效。尤其需要警惕：

- 搜索相关性被总结成因果规律；
- 单个偶然失败被固化为“不要再试”；
- 全局经验只围绕当前最好程序，反而缩小视野；
- 递归摘要逐步遗忘适用条件；
- 太多文字挤压祖先轨迹，使次要全局先验盖过主要局部来时路；
- 全局经验越来越保守，只重复已知有效思想，削弱探索。

因此，全局经验首先是一项**可修正的搜索状态**，不是方法自动获得的真理。它的科学价值在于让跨轨迹试错得到积累和再利用，同时仍由后续真实评估持续检验。
