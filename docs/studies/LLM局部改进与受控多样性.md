# LLM 局部改进与受控多样性

> 研究问题：LLM 作为算法进化算子时，持续、可归因的局部改进是否比少数大跨度跃迁更有效；多样性是否只有在优秀局部解附近才更容易转化为搜索进展？
>
> 状态：相关工作已提供跨模型、跨任务的轨迹证据；V5.4 已采用轻量局部改进语义，等待正式实验。
>
> 当前判断：TraceAAD 应优先把 LLM 组织成以优秀主轨迹为锚点的局部改进者，并把多样性理解为高质量区域内部的有效变化。V5.4 先恢复 V4 的单轨迹局部改进语义；基于优质路线成熟度的动态算子调度继续单独验证。
>
> 影响设计或关联证据：[What Makes an LLM a Good Optimizer?](../../../papers/traj_evo_search/README.md)；`docs/研究认识.md` 中“渐进搜索”和“延迟管理与多样性”两节。

## 1. 论文提供的证据

Zhang 等人在固定进化协议下分析了 15 个 LLM、8 个任务和 7.2 万余个候选解。研究发现，优秀 LLM 算子的典型轨迹是频繁产生相对父代的小幅改善，并逐渐集中到高表现的语义区域；较弱算子更容易发生大范围语义漂移，偶尔突破后长期停滞。

在算子层面，父代到子代的局部改进率能够显著解释最终性能。较大的父子语义距离单独看与性能负相关，但在同时考虑局部改进率后，其影响基本消失。这说明问题的核心不是“大改动绝对错误”，而是大改动通常降低了产生可靠改善的概率。

论文还发现，平均 novelty 不能预测最终性能。只有当种群保持较低空间分散度、搜索集中在高质量区域时，新的变化才更容易形成突破；高 novelty 与高分散同时出现时，多数探索没有转化为进展。

## 2. 对 TraceAAD 的机制解释

这组结果与 TraceAAD 的科学主张形成了清晰联系：

```text
优秀程序与其改进历史
        ↓
识别已经有效的结构和当前弱点
        ↓
进行一次有锚点、可归因的修改
        ↓
评价结果决定延续、修复、回退或换方向
        ↓
多次可靠的小改善累积为长期进展
```

因此，“小步改进”应定义为算法行为上的连续性：保留已经验证有效的主体结构，集中处理一个明确机制、参数关系或失败原因。它不等于限制代码行数，也不意味着禁止引入新思想。一次代码变化可以较大，只要它仍围绕清楚的问题、保持与父代的因果联系，并能由父子评价解释。

四个轨迹算子不需要改写成普通交叉和变异。`ideate` 与 `refine` 可以沿主轨迹提出不同程度的定向变化；`synthesize` 与 `transfer` 继续承担跨轨迹重组和迁移，但应把参考知识适配到优秀主程序，而不是借助参考轨迹进行无约束的整体重写。

多样性也需要与一般探索机会分开。差异 reserve 的目标应是在值得发展的高质量区域内避免过早同质化；潜力未知路线的有限机会继续由 UCB 和延迟管理提供。不能因为一条路线与精英差异很大，就自动认为它具有更高的继续开发价值。

## 3. 后续验证顺序

V5.4 已把局部改进语义与 V4 风格的评分选择一起作为联合修正。后续按以下顺序验证：

1. **V5.4 整体检查**：检验单轨迹算子的父子改善率、路线推进、修改幅度、无效候选和 held-out 是否同时改善。
2. **跨轨迹适配检查**：观察 `synthesize` 和 `transfer` 是否把参考原则适配到主程序，还是频繁造成整体重写和语义漂移。
3. **贡献回退消融**：若 V5.4 有效，分别回退评分或单轨迹提示，区分两者贡献。
4. **多样性位置与调度**：统计新变化发生时父代质量、参考质量、父子变化幅度、种群分散程度与后续收益，再验证是否只在优质路线成熟后提高双轨迹概率。

至少同时报告以下指标：

- 父代到子代的局部改进率；
- 路线最好与全局最好更新频率；
- 父子代码变化和功能行为变化；
- plateau、无效候选与后期搜索停滞；
- 不同父代质量区间中的变化幅度与后续收益；
- 三重复均值、最差运行和 held-out 表现。

## 4. 可证伪条件与证据边界

如果局部改进提示提高父子改善率，却降低全局最好更新、后期突破或 held-out 表现，说明搜索被约束得过于局部；如果高质量父代附近的变化并不比其它区域更容易产生可延续收益，就不能把“优质局部区域内的多样性”写成 TraceAAD 的一般机制。

论文采用固定的进化协议，novelty 主要由最近邻距离刻画，模型混合实验也无法完全隔离局部改进能力。其任务同时包含直接解、提示词、方程和启发式程序，与 TraceAAD 的完整算法代码搜索并不相同。因此，这篇论文为上述方向提供了重要外部证据，但不能替代 TraceAAD 自身的受控实验。
