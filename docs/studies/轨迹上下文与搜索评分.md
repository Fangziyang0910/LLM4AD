# 轨迹上下文与搜索评分

> 研究问题：轨迹历史怎样进入生成，又怎样决定下一次搜索预算？
>
> 状态：正式 V5 机制已固定；长期价值学习仍待研究。
>
> 当前判断：上下文负责传递可追溯证据，评分负责分配预算。两者应相互配合，
> 但不能用同一个粗糙标量替代所有决策。

## 上下文

active 轨迹最多保存 8 个程序节点。每条历史边展示 Planned Action、简短的
Implemented Idea、父子 fitness、结果分类和机械代码变化，不重复历史程序全文。
主锚点程序始终完整提供；双轨迹算子额外提供参考程序和参考历史。

Action 与 Code 读取同一段主历史，双轨迹时也读取同一参考信息。这样可以减少
“完整决策证据被压缩成一句 Action，再由无历史 Code 阶段猜测实现”的信息断层。
完整上下文并不天然导致重复代码；重复更可能来自评价平台、父代分布、算子行为
和有效状态覆盖的共同作用。

## 评分与选择

正式 V5 的路线质量为 endpoint 与 compact best 质量分位的加权和：

\[
Q=0.7Q_{\mathrm{endpoint}}+0.3Q_{\mathrm{best}}.
\]

保留路径上的父子改善方向形成趋势 \(P\)，父代搜索值为
\(0.8Q+0.2P\)，再加入 UCB 后进行 softmax 选择。这个分数是当前的轻量调度
代理，不是真实长期价值。

实验表明，单纯提高父子趋势权重会增加局部改善，却可能降低被选父代质量和
global-best 更新。较差 endpoint 的回弹不等于优质前沿的推进。因此，下一步
应把成果质量、继续开发价值和知识价值分开：质量先确定值得发展的区域，路线
最好推进与后续贡献再决定区域内预算，参考选择同时考虑质量与互补性。
