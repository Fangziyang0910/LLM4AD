# 轨迹上下文与搜索评分

> 研究问题：为什么 TraceAAD V5.1 在不同任务上的强弱与重复稳定性不一致，主要问题是否来自两阶段上下文和提示词，其次是否来自轨迹评分与选择？
>
> 状态：已完成 V4/V5.1 过程核对并形成 V5.2；四任务三重复实验已于 2026-07-27 启动。
>
> 当前判断：V5.2 的轨迹直接最长 8 个节点，Action 与 Code 共享同一段无逐步代码的历史；refine 使用聚焦的证据驱动提示，父代搜索值采用 \(0.8Q+0.2P\)。V5.1 没有整体失去探索能力，但 V5.2 能否提高跨任务稳定性仍需本轮实验验证。

## 1. 结果现象

V4 比 V5.1 “更稳定地强”这一判断在 TSP 和 CVRP 上成立，在 OP 上不成立，因此不能归因为 V5.1 整体机制全面退化。

| task | V4 | V5.1 | 当前观察 |
| --- | --- | --- | --- |
| TSP train | −5.976 ± 0.061 | −5.950 ± 0.181 | 均值接近，V4 明显更稳 |
| TSP50/100/200 | 6.040/8.504/11.886 | 6.030/8.436/12.202 | V5.1 在 50/100 略好，V4 在 200 更好且方差更小 |
| CVRP train | −8.665 ± 0.064 | −8.896 ± 0.434 | V4 的均值与稳定性都更强 |
| CVRP50/100 | 9.129/15.414 | 9.273/15.656 | V4 两项都更好且方差更小 |
| OP train | 14.882 ± 0.066 | 14.822 ± 0.059 | 两者接近 |
| OP50/100/200 | 15.069/30.217/53.509 | 15.077/30.492/54.956 | V5.1 在 100/200 更强，且大规模方差更小 |

这组结果支持两个阶段判断：

1. V5.1 已经能在 OP 上搜索到更可扩展的机制，不能删除双轨迹、全局经验等全部新增设计；
2. TSP/CVRP 的重复波动和大规模退化说明，新增知识进入 Action 后未必被稳定、忠实地实现，搜索预算的分配也可能过度依赖当前训练质量。

## 2. 轨迹长度与历史内容

当前定义直接收紧为：一条 active 轨迹最多包含 8 个程序节点以及最多 7 条修改边。超过后删除最早节点与对应边，compact best、趋势、评分和内部分叉都只基于当前这条轨迹，不再区分“完整轨迹状态”和“prompt 窗口”。

轨迹历史不包含每一步程序代码。每条边只提供 Planned Action、child 的一句实现 `Idea`、父子 fitness、结果分类、代码变化比例和 LOC 变化。当前主程序单独完整提供；双轨迹算子再单独完整提供参考程序。因此给 Code 增加轨迹历史不会把 8 份历史代码重复塞入 prompt。

## 3. 两阶段上下文的信息断层

V4 的 Code prompt 同时包含当前程序、Action、轨迹历史和算子约束。修订前 V5.1 的 Action prompt 能看到主轨迹、主程序、可选参考轨迹与参考程序、全局经验和算子方向；Code prompt 却只看到任务、当前程序、单条 Action 和函数契约。

单轨迹局部修改有时可以由一条自包含 Action 完整传递。双轨迹算子的风险更明显：Action 可能只说“采用参考程序的角度奖励”或“替换成参考路线的隔离惩罚”，Code 阶段却看不到参考程序怎样计算该量，也看不到哪些近似实现已经失败。于是两阶段之间形成一个高损耗的语言瓶颈：

```text
完整决策证据 -> 一条压缩 Action -> 无历史的代码实现
```

“自包含 Action”仍是有价值的 provenance 要求，但候选稳定生成只证明接口可达，不证明这条压缩通道对算法机制是信息充分的。当前实现因此让 Code 重读本轮同一段主历史，双轨迹 Code 再读取参考程序与参考历史。

### 已采用的最小改动

1. Action 阶段读取当前最长 8 节点轨迹；
2. Code 阶段读取与该 Action 相同的主轨迹历史；
3. `synthesize` / `transfer` 额外读取本轮选中的参考程序和参考轨迹历史；
4. Code 阶段不重复注入长篇全局经验，也不再注入算子口号；
5. 不在提示词中写“历史只用于忠实实现”“不得重新选题”等角色说明，以免额外语言约束带偏模型。

历史实验的 TSP/OP Action 最大输入达到 24573/24385 tokens，接近当时人为设置的 24576 token 输入预算，但原因不是逐步历史代码。TSP 最大样本中，主程序约 6.8K 字符、参考程序约 5.8K，两条历史约 7.6K、全局经验约 2.4K；OP 最大样本的单个当前程序已约 17.4K 字符、290 行。程序膨胀后的当前/参考程序是首要来源，两条历史中的 Action 与 Idea 是第二来源。当前默认已删除这一本地 32K 预检，只完整构造并记录 token；若模型服务确有硬边界，再由实验显式配置。

## 4. 提示词与泛化性

当前训练只在各 task 预先规定的训练分布上给 fitness。TSP、CVRP、OP 的搜索不会直接看到最终 100/200 规模测试反馈，因此评分本身无法区分“只在训练规模上碰巧平衡的公式”和“随规模仍成立的算法原则”。完整历史进入 Code 可以提高实现忠实度，却不能单独创造不存在的泛化信号。

Action 是施加归纳偏置的合适位置。目标不是让模型写泛化承诺，而是用一句轻量约束引导它从任务结构出发：

> 优先提出由问题结构和尺度不变量支持的机制；使用归一化或无量纲关系，避免依赖训练实例规模的固定常数。

当前实现已把这句话作为轻量 Action 偏好加入。它仍不是已证实机制，需要结合输出代码审计，检查模型是否真实使用候选集比例、距离分布统计或其它随规模可比的量，不能只看 Action 是否出现 “generalize”。

更强的泛化信号必须来自协议内验证而不是最终测试泄漏。可选方案包括：

- 在同一训练规模内使用多个实例或 seed，并保留独立验证 seed；
- 选择时同时关注均值和跨实例下分位数，避免少数实例上的偶然高分主导搜索；
- 如果要引入中间规模验证，必须在实验前定义并与最终 OOD 规模分开，这会改变现有零样本跨规模问题，不能事后加入。

## 5. `refine` 与完全同分择简是两件事

修订前 V5.1 的 `refine` 提示明确列出 deepen、repair、replace、delete、merge、simplify，并要求不要默认增加分支。这是生成阶段的语言干预。V4 的提示更集中：保留历史中一个有价值思想，做一次聚焦的机制或参数修正。

四任务过程结果不能单独把 `refine` 的弱化归因给这句话，但现象与“提示过宽、把模型注意力从证据驱动的具体改进分散到操作清单”一致。TSP/CVRP/OP 中，V5.1 `refine` 的父代改善率分别约为 6.5%/7.8%/6.0%，低于 V4 的 18.0%/13.5%/11.6%。当前版本已回到中性目标：根据历史证据修正一个已验证机制或一个已暴露弱点，至于通过增加、替换、删除还是合并实现，由模型根据问题决定。`[待验证]`

“完全同分时优先短程序”不是算子提示词。V5.1 在程序比较时使用 `(fitness, -LOC)`：只要 fitness 有任何严格差异，仍由 fitness 决定；只有数值完全相等时，较短程序成为路线 compact-best 或 global-best，并在质量排名中占优。

这条规则虽然很弱，却不是无影响的记录项。V5.1 的 TSP/CVRP/OP/OBP 正式运行中，global-best 因严格 fitness 更新分别发生 38/48/28/15 次，因完全同分但更短而更新分别发生 43/45/53/25 次。同分择简经常改变后续锚点身份和选择分位，因而也需要单独消融。它的设计作用是降低同质复杂度，现有结果却不能单独证明这一作用的净收益，更不能证明它提高了泛化；它也可能删除一个同分但为后续组合保留了有用结构的较长锚点。

## 6. V4 与 V5.1 的评分差别

两版的路线质量都以当前端点和路线历史最好为核心，默认比例均为 0.7/0.3。关键差别是：

```text
V4:   V_search = 0.6 Q + 0.4 P
首轮 V5.1: V_search = Q
当前修订: V_search = 0.8 Q + 0.2 P
两版父代调度: V_search + 0.25 UCB
两版 softmax temperature = 0.2
```

其中 `Q` 是 active 路线中的质量分位，`P` 是沿最多 7 条修改边的父子变化符号折扣趋势。当前修订让 `P` 以 0.2 权重参与父代和普通 survivor 选择；参考供体仍按纯 `Q` 选择。

V4 的趋势不是严格的长期潜力真值。一个差程序向上回弹但仍低于路线历史最好时也会得到正趋势，因此不能直接恢复后宣称评分已经正确。不过它提供了一个 Q 没有的信息：这条路线最近是否仍能产生方向一致的变化。

## 7. V5.1 的实际选择压力

四任务三重复的 `trajectory_selection` 日志表明，V5.1 没有坍缩为只选一条路线。平均 active 候选约 44 条，softmax 分布的有效候选数约为 TSP 24.5、CVRP 24.7、OP 25.4、OBP 28.5；最高单条概率约 11.6%–14.9%，前五条合计约 38.5%–45.8%。UCB 和延迟种群管理仍在维持必要探索。

但质量偏向很明确：被选轨迹的平均 `Q` 为 TSP 0.740、CVRP 0.738、OP 0.729、OBP 0.677；TSP/CVRP 中约 55% 的选择落在 `Q>=0.75`，`Q<=0.25` 仅约 2%。而且同一个 Q 分数又用于参考轨迹采样和大部分 survivor softmax，质量压力会跨三个决策累积。

过程收益呈现出有意义的分工：

- 被选轨迹处于最低质量四分位时，TSP/CVRP/OP 的下一批父代改善率约为 28.3%/36.5%/20.3%；
- 处于最高质量四分位时，对应父代改善率降为 6.3%/9.9%/6.3%，但全局最好更新率升为 9.0%/10.2%/8.8%。

这并不说明应优先选择低分路线。低分父代有更大局部改善空间，高分父代更难改进但更能推进全局前沿。它说明单一 Q 同时承担“成果质量”和“继续开发潜力”会丢失结构：当前机制擅长利用好路线，对可修复路线的预算主要依赖 UCB 的访问补偿。

趋势与后续收益也存在正向过程信号。按被选路线趋势分成四组，最高趋势组在 V4 的 TSP/CVRP/OP 上刷新全局最好的比例约为 6.0%/6.3%/7.1%，在 V5.1 的 TSP/CVRP 上约为 9.3%/9.1%。这只是相关性，但足以支持把趋势重新列入消融，而不支持直接宣布 V4 的 0.4 权重最优。

## 8. 鲁棒性的可控部分

搜索是随机过程，鲁棒性仍可通过改变结果分布来改善。目标应同时包括：

- 提高上限：高质量路线仍有足够预算推进 global best；
- 提高下限：单个早期幸运路线或低区分度平台不应锁死整次运行；
- 保持探索：未充分访问、思想不同或近期仍有发展信号的路线获得可解释的最小机会；
- 降低评价噪声：候选在多个训练实例/seed 上的分布比单一均值更可靠。

OBP rep1 是下限问题的直接例子：1000 次总评价中 992 次有效，其中 962 个有效派生候选有 846 次 plateau、106 次 regress，只有 10 次父代改善，最终 best 仍是初始化样本 1。这不是基础设施故障，而是低区分度评价面、重复状态和选择反馈共同造成的搜索停滞。

因此“鲁棒性不可控，因为方法有随机性”并不成立。无法保证每次运行相同，但可以控制父代分布、幸存者覆盖、评价方差和停滞后的预算重分配，从而压缩坏 run 的尾部风险。

## 9. 已采用修订与后续验证

当前实现一次完成以下相互配套的修订：

1. 轨迹状态最长 8 个节点；
2. Action/Code 共享无逐步代码的轨迹历史；
3. 双轨迹 Code 读取参考程序与参考历史；
4. refine 改为聚焦的证据驱动修正；
5. Action 加一句尺度不变量偏好；
6. 搜索值改为 `0.8Q+0.2P`，参考供体继续按纯 Q。

下一批正式实验应首先按当前完整修订重跑四任务三重复，报告 global-best 上限、三重复最差 run、选中分布熵、低质量路线访问率、局部改善、路线最好推进、全局推进和 held-out。若整体结果改善，再通过回退式消融分别识别共享上下文、提示词和 0.2 趋势的贡献。完全同分择简单独做 on/off 消融；是否加入中间规模验证属于协议变化，另立实验。

## 10. 当前证据边界

现有结果支持以下事实：

- 首轮 V5.1 Code 阶段确实缺少 V4 曾提供的轨迹历史，双轨迹时还缺少直接参考；
- V5.1 的质量选择没有完全坍缩，但明显偏向高质量路线；
- V4 在 TSP/CVRP 更稳，V5.1 在 OP 大规模泛化更强；
- `refine` 操作清单和完全同分择简分别作用于生成和选择，不能混为一条机制。

尚未由现有实验确认的是：

- 共享历史是否就是 TSP/CVRP 稳定性差异的主因；
- 0.2 趋势是否优于 Q-only，或者只是增加局部回弹；
- 任务不变量提示能否稳定产生更底层、跨规模有效的算法思想；
- 完全同分择简对泛化、速度和后续组合潜力的净效应。

这些问题应通过上述按层消融回答，避免一次同时改 prompt、评分、算子和评价协议后无法归因。
