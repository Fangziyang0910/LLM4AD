# TraceAAD v4 轨迹选择与种群管理审计

> 状态：2026-07-24 冻结过程证据，不承担当前方法设计。

## 1. 审计问题与证据边界

本节检查 TraceAAD v4 是否真的把“算法改进轨迹”作为搜索个体使用，重点回答：

1. 轨迹质量 \(Q\)、趋势 \(P\) 和搜索价值 \(V_{\text{search}}\) 在真实搜索中是否有区分度，是否与后续进展有关；
2. UCB 是否真的为低访问路线增加机会，以及这种机会是否带来有效搜索；
3. endpoint、轨迹内历史最好节点和内部回退锚点分别怎样工作；
4. \(2M\rightarrow M\) 管理、精英保留、差异 reserve、softmax survivor 和 global-best route 在真实运行中是否发挥了预期作用；
5. 当前实现中的“轨迹个体”究竟保存并利用了多少历史。

审计数据冻结于 **2026-07-24 15:29:39（Asia/Shanghai）**。数据来自 5 个任务、每个任务 3 次重复，共 15 个 v4 run 的：

- `logs/method_events.jsonl`
- `logs/method_state.jsonl`
- `logs/checkpoints/latest.json`

冻结时 online bin packing 和 OP-ACO 的 6 个 run 已达到 1000 次评估，其余 9 个 run 仍在运行。为避免运行日志领先定期 checkpoint，所有事件和状态均按各 run 的 `latest.json.total_samples` 截断；因此下述数字是冻结快照，不是最终实验结果。

本文严格区分三类结论：

- **【观测事实】**：能够从真实事件、状态或 checkpoint 直接计算；
- **【机制解释】**：对观测现象的因果候选解释，尚未由受控消融确认；
- **【证据不足】**：当前日志缺字段，或现有实验没有合适反事实，不能作出判断。

局部改进、路线进展和全局进展使用三个不同口径：

- **local improve**：子程序优于本轮实际锚点，等同事件中的 `outcome=improve`；
- **route-best improve**：子程序优于所选轨迹保留窗口内的历史最好程序；
- **global best**：子程序触发 `best_updated`。

这个区分非常重要。一个程序可以从退步端点回弹，但仍没有恢复到该路线以前达到过的最好水平。

## 3. 轨迹评分是否在真实选择中工作

### 3.1 评分分量有区分度，选择也确实偏向高价值路线

v4 的运行实现按 endpoint 百分位和轨迹内历史最好百分位计算 \(Q\)，按最近边的 improve/plateau/regress 符号计算 \(P\)，再用

\[
V_{\text{search}}=0.6Q+0.4P
\]

进行 softmax 选择；UCB 只加在父代调度分数上。实现位置为 `llm4ad/method/traceaad_v4/value.py:191-248` 和 `value.py:318-340`。

| task | 选择轮数 | 被选 \(V\) 均值±标准差 | \(Q\) 标准差 | \(P\) 标准差 | 被选轨迹平均节点数 | 已达 8 节点上限 | \(V\) AUC：local / route-best / global | global-best 子代数 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| CVRP-ACO | 997 | 0.716±0.172 | 0.233 | 0.162 | 7.10 | 71.4% | 0.430 / 0.542 / 0.739 | 51 |
| Knapsack | 1158 | 0.570±0.112 | 0.140 | 0.141 | 6.00 | 45.8% | 0.386 / 0.580 / 0.971 | 3 |
| Online bin packing | 1470 | 0.658±0.163 | 0.218 | 0.139 | 7.03 | 66.5% | 0.375 / 0.568 / 0.708 | 38 |
| OP-ACO | 1457 | 0.672±0.166 | 0.214 | 0.169 | 7.16 | 73.1% | 0.395 / 0.587 / 0.747 | 41 |
| TSP construct | 1206 | 0.710±0.177 | 0.241 | 0.180 | 6.86 | 65.6% | 0.412 / 0.529 / 0.655 | 69 |

AUC 只在已经被选择的父代中计算；0.5 表示没有排序能力，越大表示该值越倾向把产生相应事件的父代排在前面。Knapsack 只有 3 个搜索期 global-best 事件，其 0.971 不稳定，不能与其它任务等量解释。

**【观测事实】**

1. \(Q\)、\(P\) 和 \(V\) 在所有任务上都有非零方差，不是常数或日志摆设。
2. 在没有历史 archive 不确定性的首个扩张周期中，可以精确重建完整 active pool。255 次选择的父代 \(V\) 平均处于池内约第 76.9 百分位，说明 softmax 的实际抽样明显偏向高价值轨迹。
3. 高 \(V\) 不倾向产生更多 local improve（AUC 0.375–0.430），但对 route-best improve 有轻度正排序能力（0.529–0.587），对稀少的 global-best 事件有更明显的正排序能力（除样本过少的 Knapsack 外为 0.655–0.747）。
4. 被选轨迹平均已有 6.00–7.16 个节点，45.8%–73.1% 已达到 8 节点窗口上限。真实搜索并非大部分时间只选择单节点程序；轨迹历史确实进入评分和提示。

**【机制解释】** 高质量路线更接近当前性能上界，继续产生“比锚点更好”的局部变化反而更难，因此 local improve 与 \(V\) 负相关并不等于选择失效。更关键的口径是能否超过路线历史最好或刷新全局最好；在这两个口径上，\(V\) 的方向总体正确。

**【证据不足】** 上表只观察被选中的父代，没有未选择父代的反事实生成结果。它能说明 \(V\) 与被选后的产出相关，不能证明当前 \(0.6/0.4\) 权重优于只用 endpoint、只用 \(Q\) 或其它权重。

**【观测事实】** 从已退步 endpoint 继续时，27.4%–49.3% 的子代优于 endpoint，但只有 1.4%–9.0% 超过该轨迹历史最好。也就是说，大部分正边只是恢复部分损失。当前 `_path_trend` 只读取相邻边 delta 的正负号（`value.py:80-93`），这些回弹边会完整计为 `+1`。

**【机制解释】** \(P\) 当前衡量的是“局部斜率”，不完全是“路线净进展”。当一条路线在最好点、退步点和回弹点之间振荡时，它可能获得正趋势，但仍没有创造新知识或新质量。这是 \(P\) 值得优先检查的设计边界：后续应同时记录相对父节点、相对 route best 和相对全局最好三种进展，比较哪一种更能预测未来突破。

**【证据不足】** 现有数据没有运行“局部趋势”与“route-best 趋势”的配对选择实验，因此目前只能确认两种定义大量不一致，不能直接断言替换趋势定义一定提升最终结果。

## 4. UCB：调度压力真实存在，质量收益尚未被因果确认

首个扩张周期没有历史 survivor 身份缺失，可以精确重算每轮有无 UCB 时的 softmax 分布：

| task | 首周期选择数 | 所选父代此前零访问 | 所选 \(V\) 池内百分位 | 未访问路线概率质量：无 UCB → 有 UCB |
|---|---:|---:|---:|---:|
| CVRP-ACO | 52 | 80.8% | 76.7% | 71.7% → 81.8% |
| Knapsack | 49 | 81.6% | 81.5% | 74.4% → 83.4% |
| Online bin packing | 50 | 86.0% | 68.5% | 77.1% → 85.7% |
| OP-ACO | 55 | 80.0% | 77.9% | 73.6% → 82.9% |
| TSP construct | 49 | 83.7% | 79.8% | 75.2% → 84.0% |

**【观测事实】**

- 在这 255 次完全可重建选择中，UCB 将分配给未访问路线的总概率质量从平均 74.4% 提高到 83.5%，增加约 9.1 个百分点。UCB 不是数值太小而不起作用。
- 全搜索快照中，59.1%–72.2% 的父代选择发生在该轨迹第一次被访问时。
- 首次访问父代产生 route-best improve 的比例并未系统性低于重复访问父代：CVRP 为 12.9% 对 10.4%，Knapsack 为 2.2% 对 2.4%，online bin packing 为 5.6% 对 4.1%，OP-ACO 为 5.3% 对 5.6%，TSP 为 10.4% 对 11.2%。探索低访问路线至少没有显示出普遍无效。

**【机制解释】** UCB 的主要可见作用是把访问从少数重复父代转向新 frontier，且这些首次访问仍能贡献路线进展和 global-best 事件。因此“访问公平”作为调度职责是有实际基础的。

**【证据不足】** 所有正式 run 都启用了相同的 `ucb_c=0.25`，没有 `ucb_c=0` 反事实。现有数据只能证明 UCB 改变了概率分布，不能证明它改善了样本效率或最终质量。首周期实际被选父代的 \(V\) 百分位由 UCB 调整前到调整后只平均上升约 0.5 个百分点，说明它主要重分配相近价值路线，而不是彻底覆盖质量信号。

## 5. 锚点机制：回退真实发生，但收益依任务而异

锚点先在 endpoint 与轨迹内历史最好节点之间等概率抽取（`traceaad.py:451-463`）。如果 endpoint 本身就是历史最好，两种抽取结果相同；只有 endpoint 已经退步时，才能观察真正的 endpoint/internal-best 分叉。

**【观测事实】**

- 内部历史最好锚点真实发生 986 轮，不是死代码。
- 相比从已退步 endpoint 继续，内部历史最好锚点显著减少“看似改进但未恢复路线最好”的回弹：其 local improve 与 route-best improve 必然相等。
- 内部最好锚点的普通 route-best improve 率在 4/5 个任务上低于“endpoint 已是最好”情形；但它在 CVRP 和 TSP 上产生 global-best 的密度更高，分别为 4.1% 对 2.8%、4.2% 对 3.0%。在 Knapsack 上没有观察到收益。

**【机制解释】** 内部回退更像高门槛的“从已验证强基点再次分叉”，不是提高一般 local-improve 率的工具。CVRP/TSP 的结果支持它可能集中产生少量高价值突破；跨任务结果不支持把它当成普遍更优的默认锚点。

**【证据不足】** 锚点由随机抽取，不是对同一 action 的配对实验；不同锚点收到的 action 和代码都不同。需要固定所选轨迹后，对 endpoint 与 internal best 做配对或随机化 A/B，才能判断因果收益及适用条件。

## 6. 内部回退暴露了一个核心历史传承缺口

action prompt 和 code prompt 会把所选轨迹的完整保留窗口传给 LLM，包括锚点之后的失败尝试（`context.py:12-41`、`traceaad.py:324-353`）。但是生成子轨迹时，`branch_from` 只保留“锚点以前的前缀 + 新子节点”，锚点之后的边全部从子轨迹中删除（`trajectory_memory.py:50-57`）。

| task | 内部回退轮数 | 被截掉边数 | 每轮平均 | 单轮最大 | regress | plateau | improve |
|---|---:|---:|---:|---:|---:|---:|---:|
| CVRP-ACO | 171 | 279 | 1.63 | 6 | 187 | 73 | 19 |
| Knapsack | 32 | 129 | 4.03 | 7 | 32 | 94 | 3 |
| Online bin packing | 260 | 494 | 1.90 | 7 | 285 | 161 | 48 |
| OP-ACO | 243 | 482 | 1.98 | 7 | 275 | 142 | 65 |
| TSP construct | 280 | 412 | 1.47 | 5 | 303 | 70 | 39 |
| **合计** | **986** | **1796** | **1.82** | **7** | **1082** | **540** | **174** |

**【观测事实】**

1. 986 次内部回退共从新子轨迹中截掉 1796 条锚点后边，其中 60.2% 是 regress、30.1% 是 plateau。
2. 当轮 action/code 生成确实看到了这些失败边；子轨迹建立后，这些边只留在全局 derivation graph 和旧轨迹记录中，不再属于新轨迹的提示历史。
3. 这些内部回退共生成 1837 条有效子轨迹，其中 638 条后来又被选为父代。对这 638 次真实后续使用而言，先前被截掉的失败后缀已经不在输入轨迹中。

**【机制解释】** v4 当前实现的是“一次性利用回退前的失败历史”，还没有实现“让新分支持续继承为何回退的经验”。图中保存事实不等于搜索会再次使用事实。这个差异直接关系核心主张：如果失败边只在回退当轮被看见，后续分支仍可能重复已经验证过的失败方向。

**【证据不足】** 尚未统计这 638 条后续路线是否语义上重复了被截掉的失败 action。应把截掉 action 与后续 action 做语义/机制级重复分析，才能判断该缺口实际造成多少重复试错。

## 7. 扩张—收缩种群管理

### 7.1 \(2M\rightarrow M\) 按预定节奏运行，但经常从 61 收缩

**【观测事实】** 冻结快照包含 378 次 `population_management`：

- 207 次从 60 条 active 轨迹收缩到 30；
- 171 次从 61 条收缩到 30；
- 每次均报告 3 个 elite、3 个 diversity reserve，其余由无放回 softmax survivor 填充。

之所以会出现 61，是因为一次迭代可生成两个有效子轨迹，而管理在整轮生成结束后才检查 `active >= 60`（`traceaad.py:504-506`）。因此运行事实是“达到或越过 \(2M\) 后收缩”，不是严格总在 60 触发。45.2% 的管理从 61 开始，这不是罕见边缘情况。

### 7.2 延迟管理提供了真实扩展窗口，但多数新路线没有在管理前被试用

| task | 进入完整管理周期的新子轨迹 | 管理前至少被选一次 | 有完整下一周期可观测的新子轨迹 | 管理后被确认再次选中 |
|---|---:|---:|---:|---:|
| CVRP-ACO | 1810 | 18.0% | 1720 | 17.3% |
| Knapsack | 2185 | 16.5% | 2093 | 16.8% |
| Online bin packing | 2626 | 18.1% | 2534 | 16.1% |
| OP-ACO | 2696 | 16.7% | 2604 | 15.3% |
| TSP construct | 2229 | 17.4% | 2138 | 16.8% |

“管理后被确认再次选中”是 survivor 的可识别下界：被选说明它一定存活，但存活而未被选的路线无法由当前日志识别。

**【观测事实】** 扩张期新轨迹确实立即具备父代资格，但只有 16.5%–18.1% 在下一次收缩前实际被扩展。因而 v4 实现了“有机会”，没有实现“一次试用保证”。多数新轨迹的第一次去留主要依赖其单次生成后的 \(Q/P/V\) 和管理抽样，而不是它作为父代产生子代后的证据。

**【机制解释】** \(2M\) 延迟避免了逐子代即时淘汰，但对“让新路线先证明自己”的支持仍有限。如果该设计目标只是扩大 survivor 候选池，它已经工作；如果目标包括给每条新路线一次繁衍试验，当前调度没有达到。

### 7.3 elite、diversity reserve 和 softmax survivor 的真实作用目前无法审计

**【观测事实】** `population_management` 事件只记录：

- `before/after`
- `elite_count/diversity_count`
- `archived`
- 总体 `selection_mode`

它没有记录 keep/archive trajectory IDs，也没有记录每个 survivor 属于 elite、best-anchor replacement、diversity reserve 还是 softmax sample。`latest.json` 只保存最终 active/archived 状态，没有 archive 时间和历次 survivor 角色。

因此，不能从最终 checkpoint 无偏倒推出 378 次管理各自的候选池和 survivor 身份，也不能计算：

- diversity reserve 是否比普通 softmax 保留了更不相似的路线；
- reserve 路线之后是否产生更多独特 action 或性能突破；
- softmax survivor 相比被淘汰路线是否更有后续价值；
- best-anchor 强制占位是否挤掉了哪一条质量 elite。

单元测试证明这些代码路径在构造样例上能保留不同 signature 和 global-best route，但测试不能替代正式运行中的机制效果。

**【证据不足】** 当前实验只能确认“管理按数量执行”，不能确认三个 survivor 子机制分别有效。这是本审计最明确的 observability gap。

## 8. Global-best route 的保留与复用

| task | best route 被选占全部选择 | global-best 节点实际作为锚点 | 冻结时 current best route active |
|---|---:|---:|---:|
| CVRP-ACO | 8.5% | 14.7% | 3/3 |
| Knapsack | 3.1% | 5.4% | 3/3 |
| Online bin packing | 6.1% | 15.0% | 3/3 |
| OP-ACO | 5.6% | 12.4% | 3/3 |
| TSP construct | 8.1% | 15.6% | 3/3 |

**【观测事实】**

- 15/15 个 latest checkpoint 中，当前 `best_trajectory_id` 都是 active。
- best route 不只是被动保留：它占 3.1%–8.5% 的父代选择；由于其它 active 轨迹也可能包含当前最好节点，global-best 节点实际被选为锚点的比例更高，为 5.4%–15.6%。
- 多个跨过至少一次管理周期的 best incumbent 此后仍被选择，提供了正式运行中“管理后仍可复用”的直接样例。

**【机制解释】** best-anchor 机制在“保护已知最好程序并继续开发”这一职责上有真实运行证据，尤其在 TSP、CVRP、online bin packing 中使用频率不低。Knapsack 很早达到大量同分平台，global-best 更新少，best route 的特殊身份相应较弱。

**【证据不足】** 事件没有记录每次管理的 best-anchor survivor ID，无法逐次证明 378 次管理都执行了预期替换；当前证据由最终 active 状态和管理后的再次选择共同提供。

## 9. “轨迹作为个体”的当前结论

### 9.1 已经成立的部分

**【观测事实】**

- 父代采样对象是 trajectory ID，不是直接从程序列表抽样；
- \(Q\) 使用 endpoint 与轨迹历史最好，\(P\) 使用有序边结果；
- action 和 code 两阶段都接收所选轨迹的有序历史；
- 被选轨迹平均已有 6–7 个节点，大部分任务中约三分之二的选择使用满 8 节点窗口；
- 内部回退、按锚点分叉和轨迹级 visit count 都在正式运行中真实发生；
- active/archived 状态确实控制一条路线能否继续繁衍。

从工程执行意义上说，v4 已经是轨迹驱动搜索，而不是只在文档中把节点改名为轨迹。

### 9.2 整体机制与当前解释边界

**【观测事实】**

1. 当前 derivation graph 中每个程序只有唯一父节点，因此每个 endpoint 都有清晰的祖先轨迹。
2. 内部回退会删除新分支中的失败后缀，说明当前轨迹个体是严格、有限的祖先路径，不承担全局分叉记忆。
3. 管理日志缺 survivor 身份，暂时无法解释差异 reserve 怎样改变长期谱系覆盖。

因此目前最准确的结论是：

> **TraceAAD v4 已经把轨迹机制真实接入评分、调度、锚点、提示和生存管理；现有运行结果支持高价值路线与全局突破相关、UCB 确实扩大低访问路线机会、best route 确实被保护和复用。完整系统的最终方法价值由 SOTA、held-out 和重复稳定性共同评价；当前过程证据同时指出，严格祖先轨迹之外仍缺少经过凝练的全局搜索认识。**

## 11. 后续审计所需的最小可观测性

下一轮实验不需要先重写搜索机制，先补齐以下事件字段即可把大部分“无法判断”变成可检验问题。

### 11.1 每次父代选择

对全部 active trajectory 记录或单独写一条紧凑 decision snapshot：

- `trajectory_id`
- `endpoint_id`
- `route_best_node_id`
- `quality`
- `trend`
- `search_value`
- `visit_count_before`
- `ucb_bonus`
- `adjusted_value`
- `softmax_probability`
- `selected`

同时记录所选锚点类型：`endpoint_best`、`endpoint_regressed` 或 `internal_best`，以及锚点后的 `dropped_edge_ids`。

### 11.2 每次种群管理

对 60/61 条候选分别记录：

- `trajectory_id`
- 管理前 \(Q/P/V\)
- 与 elite/reserve 的相似度摘要
- `decision=keep/archive`
- `role=quality_elite/best_anchor/diversity/softmax`
- archive 时间或 management sequence

这样才能真实比较各 survivor 角色的后续访问、独特 action、route-best improvement 和 global-best 贡献。

### 11.3 必须配套的最小消融

1. **历史表达比较**：严格祖先轨迹、祖先轨迹加全局搜索认识、不同全局认识更新方式；
2. **评分消融**：只用 endpoint、当前 \(Q\)、\(Q+P\)、\(Q+P+\)UCB；
3. **趋势定义消融**：相对父节点、相对 route best、相对 global best；
4. **锚点随机化实验**：只在 endpoint 已退步的轨迹上，对 endpoint 与 internal best 随机分流；
5. **种群管理消融**：elite+softmax、加入 diversity reserve、加入 best-anchor 强制保留。

每项首先比较达到同一质量阈值所需评估数、route-best improvement 数、谱系覆盖和重复失败 action，而不是只比较最终单个最好分数。
