# TraceAAD V5 结构化 Action 失效诊断与 V5.1 修正方案

> 状态：首轮失效证据已冻结，V5.1 修正已落实到
> `llm4ad/method/traceaad_v5/`。本文记录为什么旧结构偏离方法意图、
> 修正后的权威行为以及重新实验前的验收边界。

## 1. 核心判断

V5 首轮 action 运行损耗的主要原因不是模型服务请求失败，也不是“两阶段
生成”本身无效，而是 action 的输出职责发生了偏移。

方法真正需要 LLM 完成的任务是：

> 在系统已经给定算子、主程序、祖先轨迹、可选参考轨迹和全局经验后，
> 提出下一步算法怎样修改。

旧 V5 却要求模型同时返回 `relation`、主轨迹 evidence、参考轨迹
evidence、`change` 和 `novel_difference` 五个字段，并服从 JSON、枚举、
证据 id、字符长度和对象数量约束。这把算法设计与审计元数据填写合并成
同一个生成任务。大量有内容的响应因此在进入代码生成前被格式或字段校验
拒绝。

V5.1 将 action 恢复为一条自包含自然语言修改建议。`change` 与
`novel_difference` 的有效语义合并到同一段文本；算子、主轨迹、锚点、
主轨迹、参考轨迹和参考程序由系统自动记录。Action LLM 不再输出 JSON、
关系枚举或 evidence id。

## 2. 原始设计与旧实现的偏差

### 2.1 原始 action 语义

Action 是一次算法修改决策，不是搜索系统的状态对象。给定当前决策状态

$$
(x,p_t,\tau_t,\eta_t,\rho_t,G_t),
$$

模型只需形成一项可执行的修改意图：

$$
a_t=\text{“下一步具体怎样改变当前算法”}.
$$

一条合格 action 应在自然文本中说清：

1. 当前程序要改变什么；
2. 新方案怎样利用所选算子和已给上下文；
3. 它与相关的既有尝试有什么实质差异；
4. 对 `synthesize/transfer`，参考思想是什么、怎样适配到主程序。

这些内容共同构成一个 action，不需要拆成独立字段。

### 2.2 V4 的真实行为

V4 同样采用“先 action、后代码”的两阶段生成：

1. 系统选择父代、锚点和 `ideate/refine` 算子；
2. Action prompt 提供任务、锚点程序、历史与算子约束；
3. 模型返回两条编号自然语言修改建议；
4. parser 提取非空 action 行；
5. 每条 action 单独进入代码生成和评价。

Action 在树边上就是一个字符串。V4 没有要求模型复述算子、引用 edge id
或分类 relation。

### 2.3 旧 V5 新增的负担

旧 V5 的每个 action 必须同时满足：

```text
合法 JSON
∧ 顶层为 array
∧ 对象数量正确
∧ 五个字段齐全
∧ relation 属于枚举
∧ relation 与已选算子一致
∧ evidence id 位于当前允许集合
∧ change ≤ 400 字符
∧ novel_difference ≤ 200 字符
```

其中多项信息已由系统确定：

- `synthesize/transfer` 的 relation 与已选算子重复；
- 主轨迹、锚点和参考轨迹已由搜索过程选择；
- 可见 edge id 是 prompt 的临时接口，不是算法修改本身；
- evidence 字段不进入后续代码 prompt；
- `novel_difference` 可以自然写入修改建议。

结构化契约由此没有扩大模型的算法推理能力，却增加了多个一票否决点。

## 3. 首轮运行证据

统计 2026-07-24 启动的 12 个 V5 run：

| Action 调用结果 | 次数 | 比例 |
| --- | ---: | ---: |
| 得到 2 个合法 action | 3,898 | 30.1% |
| 得到 1 个合法 action | 3,881 | 30.0% |
| 得到 0 个合法 action | 5,170 | 39.9% |
| 合计 | 12,949 | 100% |

这批运行的 action 阶段没有记录模型请求异常。解析错误记录中，真正的
JSON 语法错误只有 55 条；schema 或契约错误有 14,074 条。错误条目数
不是失败调用数，因为一个响应可以同时有两个对象错误。

主要错误依次包括：

- 文本超过字符上限；
- 字段或枚举值无效；
- 主轨迹或参考轨迹 evidence id 无效；
- `synthesize/transfer` relation 与算子不一致；
- 单轨迹算子使用跨轨迹 relation；
- 返回对象数量不等于 2。

对照下，所核对 V4 批次的 7,356 次成功 action 响应均被 parser 提取出
两条文本 action，另有 2 次请求级错误。V4 parser 更宽松，不能据此证明
每条文本都具有高算法质量；它足以证明同一模型能够稳定完成“生成两条修改
建议”，而 V5 的主要新增失败来自结构化协议。

## 4. 运行损耗怎样进入搜索

旧 action 契约造成四层损耗：

1. **计算损耗**：已经完成一次 LLM 调用，却没有形成可执行 action；
2. **分支损耗**：每轮预期两个兄弟候选，实际经常只剩一个或零个；
3. **调度噪声**：空 action batch 仍增加主轨迹 `visit_count`；
4. **算子偏置**：不同算子的格式通过率不同，名义均匀尝试变成不均匀的
   有效候选预算。

首轮 V4 每个 iteration 约形成 1.84–1.93 个有效子代，V5 只有
0.74–0.98 个。完整运行仍能最终消耗 1000 次程序评价预算，但需要更多
action 调用，并让 UCB 访问统计混入格式服从性。

因此，结构化 action 不是最终质量下降的单独充分原因，却会与算子分配、
轨迹访问和 active frontier 收缩发生交互。

## 5. V5.1 修正后的 Action 契约

### 5.1 输入保持不变

Action LLM 继续接收：

- 任务描述、fitness 方向和函数契约；
- 主锚点完整程序；
- 主轨迹的 formation history 与 tested-after 边界；
- 当前全局经验；
- 本轮算子及其语义约束；
- 双轨迹算子下的参考程序与参考轨迹。

V5 的三种搜索视野与四算子能力均不删除。

### 5.2 输出恢复为自然语言

默认要求返回两条编号、单行、自包含的修改建议：

```text
1. <具体算法修改；同时说明相对相关旧尝试的实质差异>
2. <另一项独立的具体算法修改；同时说明相对相关旧尝试的实质差异>
```

双轨迹算子下，每条 action 还需自然说明：

```text
借鉴参考路线中的什么原则，以及怎样适配到主程序。
```

不再要求：

- JSON；
- `relation`；
- `evidence_edges`；
- `reference_evidence_edges`；
- 独立 `change`；
- 独立 `novel_difference`；
- 硬字符上限。

Parser 只提取自然语言 action 行并最多保留配置数量。模型只返回一条时，
该条仍可执行；没有可用文本时才记为 `parse_failed`。

### 5.3 系统自动保存 provenance

每条新边保存：

- 原始 action 文本；
- operator；
- 主轨迹和 anchor role；
- 可选参考轨迹与参考程序；
- 父子、路线最好和全局最好变化；
- LOC、代码哈希与机械代码变化。

Prompt/LLM 日志保存当时实际提供的局部历史、参考历史与全局经验。系统记录
“提供过哪些知识上下文”，不要求模型声称自己精确使用了哪个 edge，也不把
这种声称误当成代码事实。

### 5.4 与全局经验的边界

本次只简化在线 action。全局反思仍输出少量结构化经验及 evidence edge，
因为它要更新一个长期共享状态，条数低、输出预算独立，而且证据校验属于
该机制的认识可靠性约束。Action 是高频算法决策，不承担这项职责。

## 6. 实现修正

V5.1 已完成：

1. `StructuredAction` 和 `ActionRelation` 从运行时 schema 删除；
2. `ImprovementEdge` 直接保存 `action: str`；
3. action prompt 改为两条编号自然语言建议；
4. parser 恢复轻量文本行提取；
5. 代码 prompt 直接接收原始 action；
6. 全局反思使用 action 文本和系统 provenance 构造近期经验；
7. checkpoint edge schema 同步简化，格式版本从 7 升为 8；
8. 日志中的 `parsed_actions` 改为文本列表。

Checkpoint 8 不加载旧格式 7，以免把旧五字段 action 静默解释为新语义。
首轮 V5 工件继续作为冻结证据读取，不用于新代码恢复运行。

## 7. 测试与重新实验验收

公开 `TraceAADV5.run()` 行为测试已验证：

- 两条编号文本 action 均进入代码生成；
- 两个候选分别评价并形成两条单父边；
- checkpoint 原样保存 action 文本；
- prompt 不再要求 JSON array；
- 双轨迹 reference 继续只作为知识 provenance；
- 全局经验仍按 20 轮更新并进入后续 action；
- checkpoint 8 可以恢复搜索。

正式重跑前还应在真实模型小预算冒烟中检查：

| 指标 | 首轮旧 V5 | V5.1 目标 |
| --- | ---: | ---: |
| 0 个 action 的调用 | 39.9% | 接近 V4 水平 |
| 每轮解析 action 数 | 0/1/2 大量混合 | 主要为 2 |
| action schema/证据错误 | 大量 | 不再存在 |
| 每 iteration 有效子代 | 0.74–0.98 | 明显恢复 |
| 算子有效候选偏置 | transfer 偏高 | 不再由格式服从性主导 |

这些验收只证明 action 接口恢复了设计语义。自然语言 action 是否减少重复
代码、改善后半程探索和最终质量，仍需与其它 V5.1 修正一起通过同模型、
同协议重复实验验证。
