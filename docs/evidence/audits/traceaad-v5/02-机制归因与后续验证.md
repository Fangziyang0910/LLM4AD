# TraceAAD v5 首轮机制归因与后续验证

> 本文基于[训练结果与运行过程](01-训练结果与运行过程.md)中的冻结观察。
> “导致”“有效”等表述均按本页标注的证据等级理解，不把单次运行关联
> 写成已证明因果。

## 1. 阶段总判断

当前结果支持下面的谨慎判断：

> V5 的核心改进没有被现有训练结果从原理上否定；当前实现和机制组合中
> 已经存在足以造成过早收敛、有效预算浪费和重复方差上升的具体缺陷。
> 因此，先修复这些缺陷并让完整机制真正运行，比现在删除全局经验、
> 双轨迹算子或 anti-bloat 更有证据基础。

这不是为所有新机制预设正确。科学上，当前只说明“实现缺陷是性能下降的
充分竞争解释”，还没有说明“缺陷修复后 v5 必然超过 v4”。若修复后、
在同模型同协议下重复运行仍无改善，就必须进一步否定或收缩相应机制。

## 2. 从观察到解释的整体因果链

当前最符合数据的系统解释是：

```text
全局经验始终为空
        +
四算子按尝试次数固定均匀，实际有效候选向 transfer 倾斜
        +
参考选择偏向高质量程序，但不判断思想是否可迁移或已在主程序中存在
        ↓
跨轨迹算子反复迁移已经收敛的思想
        ↓
大量 plateau、父子完全同代码和行为等价程序
        ↓
相同可执行状态以不同轨迹身份进入 active frontier
        ↓
有限种群席位被重复代码占据，根谱系覆盖降到 3–4
        ↓
Q+UCB 继续利用当前强但已饱和的区域
        ↓
搜索在 300–500 samples 后很少再产生新前沿
        ↓
结果依赖早期是否偶然命中强路线：单次上限提高，均值与稳定性下降
```

链条中的“全局经验为空”“重复代码”“active 收缩”和“后期停滞”是直接
观察；“它们共同造成最终质量下降”是当前最有支持的机制推论，仍需修复
后重跑确认。

## 3. 逐机制判断

### 3.1 全局经验

**观察：** 所有 run 均触发更新，但成功次数为 0，action 始终看到空经验。

**判断：实现未成立，原理无法评价。**

全局经验不是“效果不好”，而是根本没有进入搜索决策。它没有直接降低
训练 score，却使 v5 缺少原本用于跨路线总结有效方向、踩坑和拥挤区域的
任务级状态。当前双轨迹算子只能看一个具体参考，无法得到“这一思想已经
被很多路线重复尝试”的高层提醒。

**待验证：** 修复上下文后，全局经验是否减少跨路线重复、提高后半程唯一
程序比例和 global-best yield。未经成功更新的运行不能进入该问题的正反
证据。

### 3.2 双轨迹 `synthesize/transfer`

**观察：**

- TSP/CVRP 的路线推进率高于单轨迹算子；
- TSP 最强运行和 CVRP 的恢复路径大量使用双轨迹算子；
- transfer 的父子完全重复率达到 16.8%–24.9%，后半程最高 35.3%；
- OP 中 transfer 没有一次直接推进 global best。

**判断：机制具有价值，实现和调度过粗。**

直接删除双轨迹会丢掉已经观察到的高质量路径。问题更具体：

1. 参考程序质量不等于参考思想的可迁移价值；
2. 主/参考代码不同不等于两者的核心思想不同；
3. action 声称迁移不保证生成代码实际发生变化；
4. 固定 25% 尝试概率没有根据搜索阶段和有效产出调整；
5. 同代码候选仍被评价并作为新轨迹加入种群。

当前双轨迹算子扩大了信息输入，却没有稳定扩大有效搜索视野。搜索后期，
它们更像收敛思想的传播器。

**待验证：**

- 在完全相同搜索设置下比较四算子与只保留 `ideate/refine`；
- 分别报告早/晚期、唯一子代、route-best 和 global-best yield；
- 检查去除完全重复评价后，双轨迹的有效预算占比和收益是否恢复；
- 人工分层检查 reference 思想是否真的进入代码，而不只进入 action。

### 3.3 `Q+UCB`

**观察：**

- 高分路线的 global-best yield 高于低分路线；
- 高分路线的普通路线推进率低于低分路线；
- V5 active 根谱系和当前程序覆盖比 v4 更低；
- V4 的高 selected-value 四分位总体同时具有更高路线推进和前沿推进。

**判断：成果利用成立，继续开发代理不足。**

\(Q\) 能识别“目前已经好”的路线。V5 的实际问题与研究认识一致：成果
价值不能完整代替继续开发价值。高质量路线更可能刷新全局前沿，也更容易
已经饱和；当 active 中又包含大量重复状态时，Q-softmax 会反复利用同一
等价区域。

现有证据不能证明旧 \(P\) 是正确答案。V4/V5 同时改变了算子、action、
历史和生存规则，恢复 `0.6Q+0.4P` 仍需受控比较。合理结论是：删除 \(P\)
后没有得到“Q 足以承担继续开发价值”的过程支持。

**待验证：**

- 固定其它 v5 机制，比较 `Q+UCB` 与 `Q+P+UCB`；
- 用等预算 continuation return 检查二者对未来后代的排序；
- 分开评价 route-best progress 和 global-best yield，避免弱父代容易
  局部改善造成误判。

### 3.4 结构化 action

**观察：** evidence、relation 和 action 能够被日志直接审计；同时
35%–49% operator batch 为空，失败大多是字符长度或枚举服从性问题，
失败仍增加路线访问次数。

**判断：可追溯性有价值，契约和访问语义实现粗糙。**

结构化 action 解决了 v4 中“修改意图与历史关系不可直接追踪”的问题，
不应因为解析率低而退回完全自由文本。当前失败主要是接口契约与模型输出
不匹配，不是轨迹思想失败。

真正的机制冲突在于：UCB 的 `visit_count` 本应近似“路线获得了多少搜索
机会”，当前却同时记录“路线被选中但模型格式不合规”。格式失败会给
路线潜力增加无关噪声。

**待验证：**

- 修正 prompt/长度契约后将空 batch 降到可接受水平；
- 分开记录 generation attempt、合法 action 和有效 child；
- 比较三种访问定义对父代分配的影响，至少不再把纯格式错误解释为路线
  已被有效探索。

### 3.5 最小 anti-bloat

**观察：**

- best LOC 和 active endpoint LOC 相对 v4 大幅下降；
- TSP 最强 v5 程序比 v4 程序短，同时训练分数更高；
- 短 plateau 比长 plateau 更常位于后续 global-best 祖先路径；
- 仍有约 22%–26% 全部边属于“fitness 不变但代码变长”。

**判断：survivor/output 层已经有效，proposal/evaluation 层仍未解决。**

完全同分择短不会用低分短程序覆盖高分长程序，因此不存在直接牺牲训练
best 的路径。Compact-best 与 endpoint 的后续推进没有显示稳定劣势，
当前数据也不支持“中性长代码被删掉后失去延迟收益”是主要下降原因。

但 anti-bloat 只改变同质候选的表示和生存优势，无法阻止模型继续生成
无收益复杂度。V5 的输出更短，评价预算中的复杂度浪费反而更多。这是
机制作用层次的边界，不应把“best 变短”等同于“程序膨胀完全解决”。

**待验证：**

- 保留当前最小规则；
- 继续报告 proposal、accepted、active 和 best 四条 LOC 曲线；
- 优先处理完全重复代码和 plateau-long 的预算浪费；
- anti-bloat 关闭实验放在重复/调度问题之后，不作为首要怀疑对象。

### 3.6 种群管理与“轨迹作为个体”

**观察：** 相同当前代码可以因历史不同成为多个 active trajectory；
V5 active 中重复代码和根谱系收缩显著高于 v4。

**判断：知识保存与繁衍资源没有彻底分开。**

不同历史确实可能让同一程序得到不同下一步指导，因此不能简单删除轨迹。
但轨迹中的知识可以继续保存在树、edge facts 和全局经验中，不必让完全
相同的当前可执行程序无限占据 active 席位。

当前实现把“历史值得保存”隐式转换成“该历史必须继续作为独立父代资源”。
这与既有研究认识冲突：路线可以停止繁衍，其知识仍应存在。V5 已在概念
上区分知识价值和继续开发价值，种群实现尚未完整落实这一分工。

**待验证：**

- 完整保留所有轨迹事实；
- 对相同代码的 active 代表实施有界化，而不是删除历史；
- 观察 active 唯一代码、根谱系、后半程突破和重复稳定性；
- 检查不同历史但同代码的轨迹是否确实产生可区分后代，决定代表上限。

## 4. 为什么当前更支持“实现粗糙”，而非“原理无效”

### 4.1 已经发现确定性的机制缺口

以下问题不依赖统计显著性：

- 全局经验调用全部失败；
- 与父程序完全相同的代码仍消耗一次 evaluator budget；
- 完全相同代码可以重复占据有限 active 席位；
- action 格式失败进入 UCB visit；
- 四算子尝试均匀不等于有效候选预算均匀；
- 参考质量没有验证思想可迁移性。

这些行为与 V5 设计希望实现的“扩大有效搜索视野、减少重复试错”不一致，
足以成为结果下降的竞争解释。

### 4.2 新机制已经出现局部正证据

- 双轨迹算子构成了当前最强 TSP 程序的大部分祖先路径；
- CVRP 的部分运行通过双轨迹从很差初始化显著恢复；
- Q 仍把 global-best 突破集中到高质量路线；
- anti-bloat 大幅降低 best 和 active LOC；
- 完整路径、单父代结构和知识 provenance 按设计运行。

如果机制原理完全无效，不容易同时观察到这些结构性正结果。更合理的阶段
解释是：新能力存在，但搜索资源、重复控制和接口可靠性没有把能力稳定
转化为均值。

### 4.3 仍需避免“实现问题”成为不可证伪保护

任何表现不佳都可以被事后归因于实现，这种叙事本身没有科学价值。因此
下一轮必须预先定义修复内容和验收指标。修复后若重复程序、空经验和解析
错误已经消失，而 CVRP/OP 均值与后半程推进仍不改善，就应当降低对双轨迹
均匀调度或 Q-only 调度的信心，而不是继续无限增加补丁。

## 5. 修复与实验的最小顺序

### 阶段 0：正确标记当前运行

当前工件保留为：

> `V5 structure with empty global experience`

它们可以支持四算子、Q、action、种群和 anti-bloat 的过程研究，不能作为
完整 V5 的最终结论。CVRP/OBP rep3 可自然完成，继续作为冻结批次的一部分。

### 阶段 1：先修机制正确性，不增加新理论模块

1. **全局经验可执行**
   - 使用服务真实 context window；
   - reflection prompt 进入同一预算器；
   - 小预算冒烟必须至少出现一次合法 `global_experience_updated`；
   - 下一轮 action prompt 必须观察到非空 \(G\)。

2. **完全重复程序不再浪费评价**
   - 生成后先比较规范化 code hash；
   - 与父程序或已有程序完全相同时复用已知结果或跳过 evaluator；
   - 不把完全相同程序无限写成新的 active 繁衍资源；
   - 历史 action 和失败事实仍保留在日志/轨迹知识中。

3. **结构化 action 与访问语义对齐**
   - 让 prompt 和 validator 对字符上限、relation、evidence 集合使用同一
     明确契约；
   - 保留有效子集；
   - 区分 attempt、valid action、evaluated child 和 productive visit。

4. **种群资源落实价值分工**
   - 相同当前代码的历史可以保留；
   - active executable representative 必须有界；
   - 生存日志继续记录被折叠代表及其 provenance，避免不可审计删除。

这些修改属于机制正确性和资源卫生，不引入学习式价值模型、自适应复杂
调度器或语义 embedding。

### 阶段 2：修复后的最小冒烟验收

先在 OP-ACO 和 CVRP-ACO 做短预算过程验证，因为它们最容易复现停滞。
建议预先检查：

| 指标 | 当前现象 | 修复后首要目标 |
| --- | --- | --- |
| 全局经验成功更新 | 0 | 至少 1 次，且进入后续 action |
| 父子完全相同仍评价 | 7%–25% | 接近 0 |
| 图中唯一代码比例 | 79%–92% | 明显恢复并接近 v4 |
| 空 operator batch | 35%–49% | 降到低水平 |
| active 重复代码 | 20%–48% 席位 | 不再大量占据 |
| 后半 transfer 重复 | 21%–35% | 明显下降 |

这些目标先验证实现是否按机制意图运行，不预设训练 best 必须立即超过 v4。

### 阶段 3：再做最小因果消融

修复完整 V5 后，按单一职责依次比较：

1. 四算子与只保留 `ideate/refine`，判断跨轨迹知识的净贡献；
2. `Q+UCB` 与 `Q+P+UCB`，判断局部发展信号是否仍有条件价值；
3. 有/无全局经验，判断共享高层认识是否减少重复并延长后期改进；
4. 最后再关闭 anti-bloat，确认短表示是否影响质量和 held-out。

优先在 OP/CVRP 用同模型、同 prompt 基础、同预算和显式种子做少量预实验；
确认过程信号后再扩展三重复和 held-out。TSP 必须统一模型服务后才能作为
严格版本消融。

## 6. 可证伪的阶段预测

当前解释提出以下预测：

1. 如果重复代码和 active clone 是主要原因，去重后唯一程序比例、根谱系
   覆盖和 sample 500 之后的路线推进应同时上升；
2. 如果双轨迹原理有价值，去除重复浪费后 `synthesize/transfer` 应仍在
   TSP/CVRP 产生可观测的 route/global-best 贡献；
3. 如果 Q-only 是主要短板，修复其它问题后 `Q+P` 或更可靠 continuation
   代理应降低早期锁定和跨 run 方差；
4. 如果全局经验能够提供全局视野，非空 \(G\) 应降低跨路线重复失败和
   后半程相同 transfer；
5. 如果 anti-bloat 没有损害搜索，保留它时应继续得到更短 best/active，
   同时训练和 held-out 不劣于关闭版本。

任一预测被受控实验稳定否定时，应修正对应机制认识，而不是继续用“实现
还不够好”解释。

## 7. 研究认识的阶段凝练

这批实验带来一个与 TraceAAD 核心思想一致的新认识：

> 扩大上下文中的知识来源，不自动等于扩大有效搜索视野。参考轨迹如果只
> 按程序质量选择、没有识别思想重复和可迁移条件，就可能加速已有思想在
> 种群中的传播，使形式上的多轨迹搜索收敛为少数等价可执行状态。

轨迹搜索因此需要同时维护：

- **知识覆盖**：成功、失败、条件和不同来时路仍可被后续使用；
- **状态覆盖**：有限繁衍资源中保有足够不同的当前程序和根谱系；
- **预算有效性**：完全相同程序和纯格式失败不能伪装成新的算法实验。

V5 的原理目标仍然有价值：局部来时路、直接参考和全局认识分别提供三种
视野，程序复杂度与知识记忆分离。当前首轮实现的问题，是这些职责在具体
资源分配处重新混在了一起。下一步改进应优先把职责落实清楚，而不是继续
增加新的评分项和控制器。
