# TraceAAD v5 首轮训练结果与运行过程

> 冻结时间：2026-07-25 12:02（Asia/Shanghai）。
>
> 证据状态：TSP Construct 与 OP-ACO 的 v5 三重复已经完成；CVRP-ACO
> rep1/rep2 已完成、rep3 运行至 742/1000；Online Bin Packing rep1/rep2
> 已完成、rep3 运行至 789/1000。本文只报告训练过程，不包含 held-out
> 评价。

## 1. 研究问题与统计协议

本轮不是把单个算子的直接改进率当作机制结论，而是检查下面的整体链条：

> v5 新知识进入搜索状态 → 父代和算子把预算分给可发展的路线 →
> 生成形成有效且有差异的程序 → active frontier 保持足够的路线覆盖 →
> 搜索后期仍能推进路线最好和全局最好。

训练目标统一按“越高越好”读取。TSP Construct 和 CVRP-ACO 的 score
是负 objective，因此更接近 0 更好。V4/V5 的程序复杂度均按目标函数的
非空 LOC 离线重算；V5 checkpoint 中的 `program_loc` 用于交叉核验。

程序身份按规范化源码判断：统一换行并去掉行尾空白后计算哈希。下列
“与父程序完全相同”表示源码哈希相同，不是语义相似度判断。路线推进表示
`delta_route_best > 0`；全局推进只统计严格 fitness 更新，不把
`tie_shorter` 计作质量提升。

分析单位包括：

- 训练 best 与 best 出现位置；
- 成功评估并写入树的父子边；
- 每次父代选择及其后代；
- 最终 checkpoint 中的 active frontier；
- global-best 代表程序的完整祖先路径。

## 3. 最终训练质量与稳定性

### 3.1 TSP Construct


| 方法        | 三重复训练 best             |   mean ± sample std |    最好单次 |
| ------------- | ----------------------------- | ---------------------: | ------------: |
| TraceAAD v4 | −5.908 / −5.997 / −6.024 | **−5.976 ± 0.061** |     −5.908 |
| TraceAAD v5 | −5.823 / −6.105 / −6.161 |     −6.030 ± 0.182 | **−5.823** |

**观察：**

- v5 rep1 超过全部既有 TraceAAD 训练单次结果，说明 v5 搜索空间中存在
  更高质量算法；
- v5 三重复均值略低于 v4，标准差约为 v4 的三倍；
- v5 rep2/rep3 最后一次严格 global-best 更新分别发生在 sample 347
  和 319，之后没有再提升；rep1 在 sample 661 产生最终突破；
- v4 三次最终严格提升分别持续到 sample 974、996 和 898。

### 3.2 CVRP-ACO


| 运行    | 冻结时样本数 | 训练 best |
| --------- | -------------: | ----------: |
| v5 rep1 |         1000 |   −8.770 |
| v5 rep2 |         1000 |   −8.869 |
| v5 rep3 |          742 |   −9.290 |

V4 三重复为 −8.736、−8.648、−8.611，均值约 −8.665。V5 rep1/rep2
已经完成但均低于 v4 均值；rep3 尚未完成，冻结时明显落后。

**观察：**

- v5 rep1/rep2 的初始化最好分别只有 −10.243、−11.094，明显弱于 v4
  初始化的约 −9.65 至 −9.78；两次搜索分别提升 1.473 和 2.225，
  说明搜索具有较强恢复能力；
- v5 rep3 初始化 −9.823，与 v4 接近，却只提升到 −9.290，并在 sample
  374 后没有严格最好更新；
- 初始化随机差异解释了 rep1/rep2 的一部分最终落后，不能解释 rep3
  的长期停滞。

### 3.3 OP-ACO


| 方法        | 三重复训练 best          |  mean ± sample std |
| ------------- | -------------------------- | --------------------: |
| TraceAAD v4 | 14.920 / 14.920 / 14.806 | **14.882 ± 0.066** |
| TraceAAD v5 | 14.836 / 14.774 / 14.596 |     14.735 ± 0.125 |

**观察：**

- v5 三次均低于对应 v4 水平，均值下降约 0.147，方差增加；
- v5 最后一次严格 global-best 更新发生在 sample 335、253 和 50；

OP-ACO 是当前最清楚的“初始化并不差，但搜索后期失去推进能力”案例：
v5 rep2/rep3 的初始化 best 14.032/14.022 均不弱于 v4，多出的 970
次左右评估没有将它们推进到 v4 水平。

## 4. 全局经验没有实际运行

### 4.1 直接观察

冻结时 12 个 v5 run 均满足：

```text
global_experience_entries = []
global_experience_updated = 0
```

完成 run 通常触发 15–16 次 `global_experience_error`，所有更新尝试均
失败。错误一致为：

```text
actual model context = 32768
requested output tokens = 16384
prompt input tokens >= 16385
total >= 32769
```

运行配置却把 `max_context_tokens` 记为 131072。反思 builder 因此没有
按真实输入预算裁剪 60 条 edge facts，服务端返回 HTTP 400。失败批次不
消耗程序评价预算，搜索继续执行，旧经验保持为空。

### 4.2 证据边界

当前运行不能回答“全局经验是否改善搜索”。它只证明：

- 更新时序被触发；
- 失败恢复没有让主搜索崩溃；
- 模型上下文配置与实际服务不一致；
- action 从始至终没有得到设计中的全局搜索认识。

因此，这批结果更准确地表示“v5 其它机制 + 空全局经验”，不能作为完整
v5 的最终机制证据。全局经验没有直接降低 fitness，但预期用于识别跨路线
重复试错和拥挤方向的指导完全缺席。

## 5. 有效搜索空间发生收缩

### 5.1 Plateau 显著增加


| Task | V4 plateau / 全部边 | V5 plateau / 全部边 |
| ------ | --------------------: | --------------------: |
| TSP  |               12.0% |           **49.9%** |
| CVRP |               19.2% |           **49.4%** |
| OP   |               23.0% |           **60.7%** |

V5 的 global-best 路径也包含大量 plateau：

- TSP v5 三条最终路径分别有 13/24、23/36、8/24 条 plateau 边；
- CVRP v5 为 15/35、12/41、21/28；
- OP v5 为 13/20、18/24、17/19。

对照下，v4 最终路径中的 plateau 数量通常为 2–7 条。V5 不只是外围
候选出现持平，其最好程序的来时路本身也经历了更长的等价状态链。

### 5.2 重复代码直接消耗预算


| Task | V4 图中唯一代码比例 | V5 图中唯一代码比例 | V5 父子代码完全相同比例 |
| ------ | --------------------: | --------------------: | ------------------------: |
| TSP  |         99.7%–100% |        81.7%–92.0% |             6.7%–11.9% |
| CVRP |        98.8%–99.5% |        84.4%–87.4% |             6.8%–11.4% |
| OP   |        97.4%–99.6% |        78.7%–80.8% |            12.2%–15.4% |

V4 的父子完全相同通常低于 1%，最高约 2.6%。V5 中同一源码被重新评价、
重新写入树并成为新的轨迹个体。对确定性 evaluator，这类边不提供新的
结果信息。

### 5.3 Active frontier 的可执行多样性下降

完成 run 的最终 checkpoint：


| Task | V4 active 根谱系数 | V5 active 根谱系数 | V5 active 唯一 endpoint 代码 |
| ------ | -------------------: | -------------------: | -----------------------------: |
| TSP  |               7–9 |           **3–4** |          27/37、31/40、42/53 |
| CVRP |              9–12 |              **3** |                 28/39、25/40 |
| OP   |              9–21 |           **3–4** |          28/50、28/37、29/56 |

V4 active endpoint 几乎全部代码不同。V5 虽然仍保存多个 trajectory id和不同历史，但有限 active 席位中已有 20%–48% 被完全相同的当前程序占据。

这一现象说明“轨迹历史多样”与“当前可执行状态多样”发生了分离。不同历史可能包含不同知识，不能据此直接称为无用；但它们正在共同消耗父代选择和生存资源。

## 6. 四算子的实际行为

以下统计合并同 task 的三个 v5 run；CVRP rep3 使用冻结前缀。

### 6.1 直接结果


| Task | 算子       | 有效子代 | 路线推进率 | 严格 global-best 次数 | 与父代码完全相同 |
| ------ | ------------ | ---------: | -----------: | ----------------------: | -----------------: |
| TSP  | ideate     |      587 |       2.9% |                     9 |             0.7% |
| TSP  | refine     |      693 |       3.2% |                    13 |             3.2% |
| TSP  | synthesize |      693 |  **11.3%** |                    12 |            10.0% |
| TSP  | transfer   |      859 |       8.1% |                     6 |        **16.8%** |
| CVRP | ideate     |      523 |       5.7% |                **22** |             0.2% |
| CVRP | refine     |      554 |       3.8% |                    10 |             2.5% |
| CVRP | synthesize |      561 |  **13.0%** |                    11 |            12.3% |
| CVRP | transfer   |      934 |      11.0% |                    12 |        **17.8%** |
| OP   | ideate     |      669 |       2.5% |                 **7** |             0.6% |
| OP   | refine     |      653 |       1.4% |                     6 |             4.6% |
| OP   | synthesize |      599 |   **5.8%** |                     2 |            18.0% |
| OP   | transfer   |      970 |       4.0% |                 **0** |        **24.9%** |

观察显示两种同时成立的事实：

1. TSP/CVRP 中，双轨迹算子的路线推进率高于单轨迹算子，不能据此删除
   `synthesize/transfer`；
2. 双轨迹算子特别是 transfer 更容易生成完全相同代码，OP 上大量路线
   回弹没有转化成全局前沿突破。

### 6.2 最强运行确实使用了双轨迹知识

TSP v5 rep1 的最终 best 路径深度为 24，其中：

```text
synthesize = 13
transfer = 5
ideate = 4
refine = 2
```

这条路径取得 −5.823，超过 v4 的所有单次训练 best。双轨迹算子不是
只在外围产生活跃日志，它们真实构成了最强算法的来时路。

CVRP v5 rep1 从较差初始化恢复到 −8.770 的最终路径中包含 21 次
transfer 和 8 次 synthesize。双轨迹知识对部分运行具有明显的结构贡献。

### 6.3 后期双轨迹算子退化

按 `sample_order ≤ 500` 和 `> 500` 分段，transfer 的变化为：


| Task | 前半路线推进率 | 后半路线推进率 | 前半完全重复 | 后半完全重复 |
| ------ | ---------------: | ---------------: | -------------: | -------------: |
| TSP  |          16.9% |       **0.6%** |        11.1% |    **21.6%** |
| CVRP |          16.5% |       **4.2%** |        14.8% |    **21.2%** |
| OP   |           8.3% |       **0.0%** |        14.0% |    **35.3%** |

Synthesize 也出现相同但较弱的趋势。V4 后期同样会变难，但其代码完全
重复通常仍低于 3%，TSP refine 后半仍有 6.3% 路线推进率和 14 次
global-best update。V5 后期停滞不只是一般性的“越接近最优越难改进”。

### 6.4 实际候选分配并非均匀

设计上四个可用算子各 25% 选择。Action 解析失败率却具有算子差异：

- ideate/refine 常为 40%–52%；
- synthesize 常为 35%–50%；
- transfer 常为 28%–32%。

因此 transfer 产生的有效子代最多，占三个 task 已接受子代约
30%–36%。均匀的是“尝试次数”，不是最终消耗评价预算的候选分布。

## 7. 结构化 action 的运行损耗

V4 `operator_batch` 的空批次通常为 0%–1.2%，每轮约形成 1.84–1.93
个有效子代。V5：


| Task | 各 run 空 batch 范围 | 有效子代 / iteration 范围 |
| ------ | ---------------------: | --------------------------: |
| TSP  |         35.4%–46.1% |                0.74–0.98 |
| CVRP |         39.6%–43.4% |                0.84–0.89 |
| OP   |         39.1%–48.5% |                0.75–0.95 |

绝大多数 `parse_failed` 响应本身是合法 JSON。主要失败原因是：

- `change` 或 `novel_difference` 超过字符上限；
- evidence id 不属于当前允许集合；
- relation 写成 `refine/synthesis` 等非枚举值；
- `synthesize/transfer` 的 relation 与算子不一致；
- 只返回一个 action，而契约要求两个。

解析失败不消耗程序评价预算，所有完整 run 最终仍达到 1000 samples。
但一次失败仍增加主轨迹 `visit_count`。因此格式服从性、证据服从性和
路线探索次数被写进同一个 UCB 访问统计。

按选择价值四分位检查，解析失败没有稳定集中于高质量路线。它不是质量
下降的充分解释，但会增加与路线潜力无关的调度噪声，并使每次父代选择
失去两个兄弟候选的预期结构。

## 8. `Q+UCB` 的观测行为

在每个 task 内合并三个 run，并按 `selected_value` 分为最低和最高
四分位：


| Task | 低分路线推进率 | 高分路线推进率 | 低分 global-best yield | 高分 global-best yield |
| ------ | ---------------: | ---------------: | -----------------------: | -----------------------: |
| TSP  |      **12.6%** |           6.4% |                   0.8% |               **4.5%** |
| CVRP |      **11.2%** |           8.5% |                   0.9% |               **7.3%** |
| OP   |       **6.3%** |           3.5% |                   0.2% |               **2.1%** |

这是成果价值与继续开发价值分离的直接过程表现：

- 高 \(Q\) 路线更靠近全局前沿，因此一旦成功更容易产生 global best；
- 高 \(Q\) 路线也更饱和，普通路线推进率低于低分路线；
- \(Q\) 能承担成果利用，不能从当前数据证明它足以预测继续开发价值。

V4 的最高选择价值四分位在三个 task 中总体同时具有更高路线推进和
global-best yield。但 v4/v5 还同时改变了算子、action 和上下文，不能
仅凭该关联断言“移除 \(P\) 导致性能下降”。

## 9. 程序膨胀的两层结果

### 9.1 输出和 active survivor 明显变短

最终 best LOC：


| Task | V4 三重复       | V5 三重复/冻结值    |
| ------ | ----------------- | --------------------- |
| TSP  | 251 / 496 / 210 | **133 / 19 / 75**   |
| CVRP | 261 / 489 / 302 | **132 / 206 / 109** |
| OP   | 115 / 160 / 152 | **19 / 55 / 17**    |

最终 active endpoint LOC 中位数：


| Task |  V4 范围 |      V5 范围 |
| ------ | ---------: | -------------: |
| TSP  | 230–494 |  **20–133** |
| CVRP | 372–526 | **132–207** |
| OP   | 195–283 |   **17–56** |

`tie_shorter`、compact-best 和 `consolidate` 均真实进入运行。TSP 最强
v5 程序只有约 133 LOC，却取得高于 210–496 LOC 的 v4 最好分数，直接
说明长代码不是达到高训练质量的必要条件。

### 9.2 无收益复杂度仍在生成


| Task | V4 plateau 且变长 / 全部边 | V5 plateau 且变长 / 全部边 |
| ------ | ---------------------------: | ---------------------------: |
| TSP  |                       7.4% |                  **24.1%** |
| CVRP |                      13.1% |                  **22.5%** |
| OP   |                      13.3% |                  **25.5%** |

在 v5 的全部 plateau 边中，约 42%–48% 变长，只有约 14% 变短。当前
机制能够让简短的同质程序获得生存和输出优势，却没有阻止 LLM 持续提出
无收益增加。

### 9.3 短 plateau 的后续结构贡献更高

把每条 plateau 边标记为“是否位于后来某个严格 global-best 节点的
祖先路径”：


| Task | 变短 plateau | 变长 plateau |
| ------ | -------------: | -------------: |
| TSP  |     **4.9%** |         0.4% |
| CVRP |    **13.1%** |         0.5% |
| OP   |     **5.0%** |         0.4% |

这是结构关联，不证明“变短造成后续改善”，因为短节点可能本来就获得了
更多繁衍机会。但当前数据没有显示 anti-bloat 系统性删除了有用的长平台
脚手架；相反，短平台节点更常出现在后续突破路径上。

## 10. 观察层总结

现有工件直接支持：

1. v5 具备超过 v4 单次上限的能力，但跨任务训练均值和重复稳定性没有
   全面超过 v4；
2. 完整 v5 并未被执行，全局经验在所有 run 中始终为空；
3. v5 比 v4 更早停滞，后半程产生大量 plateau 和重复程序；
4. 双轨迹算子能够构成高质量最终路径，也更容易在后期退化成重复迁移；
5. active frontier 保存了多个轨迹身份，却丢失了大量当前程序和根谱系
   覆盖；
6. \(Q\) 能识别靠近全局前沿的路线，尚不能承担完整继续开发价值；
7. 最小 anti-bloat 明显降低最终 best 和 active 程序长度；
8. 生成阶段的无收益复杂度增加没有被解决。

这些事实不足以单独证明任一组件的因果收益或危害。综合机制解释与下一步
可证伪实验见[机制归因与后续验证](02-机制归因与后续验证.md)。
