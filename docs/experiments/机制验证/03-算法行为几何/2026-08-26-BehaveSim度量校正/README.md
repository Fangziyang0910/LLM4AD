# BehaveSim 算法行为度量校正

## 1. 实验目标与 PSTraj 度量协议

本实验确立程序解题行为轨迹（Problem-Solving Trajectory, PSTraj）的客观测量标准与基准几何，验证行为近邻结构的稳定性及不同生成算子的行为步幅差异。

- **PSTraj 状态提取与距离定义**：
  - **构造式任务（TSP、VRPTW、OBP）**：按执行流程逐步记录解的构建序列（路径或箱号分配），均匀保留 12 个中间状态；
  - **ACO 任务（OP、CVRP）**：保留迭代过程中的 5 个 incumbent 状态；
  - **距离度量**：单步部分解采用归一化编辑距离，轨迹间采用动态时间规整（DTW）对齐并除以较短轨迹长度，对探针（probe）结果取均值。
- **探针面板与稳定性检验**：
  - 每个任务设置面板 A、B 各 4 个固定 probe（测试集之外的独立实例）；
  - 计算面板间的 Spearman 相关性以评估行为度量的一致性。
- **样本范围**：全量涵盖 132 个 run（V9.16 15 个、TraceAAD 历史版本 42 个、对比方法 75 个），在固定 probe 上重放历史候选。

### 2.2 算子步幅事实（Explore vs Refine）

Explore 的中位父子行为距离在五个任务的所有重复中均显著高于 Refine：

- **中位父子行为距离（Explore / Refine）**：
  - TSP：`0.712 / 0.453`
  - OP：`0.664 / 0.557`
  - OBP：`0.339 / 0.155`
  - CVRP：`0.830 / 0.749`
  - VRPTW：`0.740 / 0.525`
- **正向适应度边占比**：Refine 为 12.5%–43.8%，而 Explore 仅为 0.0%–4.2%。

## 3. 机制分析与决策

1. **算子诱导不同的行为动态**：实验确证 Explore 与 Refine 诱导了截然不同的执行步幅——Explore 具备显著更大的行为跨度，但单步产生适应度正增益的概率极低；Refine 集中在局部行为邻域，是产生持续质量突破的主要来源。
2. **搜索停滞的表型特征**：停滞的核心体现是“低行为距离 + 无适应度突破”的高频精确重访（尤其是 OBP 与 TSP，重访率达 18%–28%）。
3. **职责定位决策**：确立 BehaveSim 作为算法群体的宏观行为表型坐标；仅用于描述搜索空间覆盖与重访状态，不直接作为微观单节点的在线选择打分依据。
