# E2-B' 结果：Pivot 两步 option value

## 结论

本轮预注册正向门槛**未通过**。在真正具有 development experience 的 9 个锚点上，Pivot→Refine 相对 Refine→Refine 的平均相对 \(Q_2\) 差为 \(+0.000201\)，95% anchor bootstrap 区间为 \([0,+0.000602]\)：9 个配对中只有 1 个 Pivot→Refine 更好，其余 8 个全为零收益平局，而且正方向只来自 TSP，未达到至少 2/3 任务为正的门槛。

更关键的机制事实是：

\[
\boxed{0\text{ 个 Pivot continuation 提高了第一步已经达到的 }Q_1}
\]

唯一一个 experienced 锚点上的 Pivot→Refine 正收益，在第一步 Pivot 就已出现；第二步 Refine 没有再增加 best-so-far。因此这批随机干预**没有支持“Pivot 先退化、再由一步 Refine 兑现”的两步 stepping-stone 叙事**。

结果仍是小规模 pilot，不能证明 Pivot 在更长 horizon 或其 V10.6 宽 parent routing 中没有价值。但现有证据不支持把动态 Pivot continuation 写入 controller，也不值得把本轮当成 positive result 扩大复现。

## 执行完整性

冻结的 18 个 anchor 全部完成两臂，共 36 条路径：

| 项目 | 实际数量 |
|---|---:|
| 第一步生成 | 36 |
| 第一步语法/接口通过并调用 Implementation Summary | 31 |
| 第一步评价有效 | 28 |
| 获得无条件第二步 Refine | 28 |
| 第二步评价有效 | 25 |
| 生成调用（第一步 + 第二步） | 64 |
| Implementation Summary 调用 | 31 |
| 模型调用合计 | 95 |
| evaluator 调用 | 57 |

5 个第一步输出没有满足 V10.6 的严格输出契约，3 个通过解析但评价失败；这些路径按协议记为零改善，没有重抽。28 个评价有效的第一步全部获得了一次 Refine，与第一步涨跌无关。第二步中 2 个输出解析失败、1 个评价失败。

| 状态 | 路径 | 第一步有效 | 第二步有效 |
|---|---|---:|---:|
| Experienced | RR | 6/9 | 5/9 |
| Experienced | PR | 7/9 | 7/9 |
| Fresh | RR | 7/9 | 6/9 |
| Fresh | PR | 8/9 | 7/9 |

本样本中PR的有效率没有低于RR，所以主结果缺少两步收益不能归因于Pivot路径更常在解析或评价阶段被截断。

锚点来自 E2-A 的冻结快照。每任务 3 个 experienced 均满足“至少 3 次历史开发、最近最多 5 次无超父/前缘、至少 2 个有效 behavior child、小移动、高重访”；3 个 fresh 从未被扩展，并按原始 fitness 就近匹配。每个任务六个 anchor 的代码哈希互不重复。两臂在同一 anchor 上使用同一 backend 和对应阶段 sampling seed；Prompt hash 不同，差异来自第一步 operator instruction 及其后形成的不同 child。

另用每个anchor独立的新PromptBuilder重建全部Prompt：36/36个第一步和28/28个第二步hash均与实际运行一致，排除了不同source run复用node id导致缓存串扰。运行器同时增加anchor间显式清空Prompt缓存的保护。

## 主结果：两步 best-so-far

跨任务使用 \(\widetilde Q_2=Q_2/|f^*|\)。

| 状态 | RR 均值 | PR 均值 | PR−RR | 95% CI | PR更好 / 平 / RR更好 |
|---|---:|---:|---:|---:|---:|
| Experienced | 0 | 0.000201 | +0.000201 | [0, 0.000602] | 1 / 8 / 0 |
| Fresh | 0.004234 | 0.014098 | +0.009864 | [-0.012702, 0.042295] | 1 / 7 / 1 |

Experienced 的任务分解：

| 任务 | RR | PR | PR−RR | 配对方向 |
|---|---:|---:|---:|---:|
| TSP | 0 | 0.000602 | +0.000602 | 1 / 2 / 0 |
| OBP | 0 | 0 | 0 | 0 / 3 / 0 |
| VRPTW | 0 | 0 | 0 | 0 / 3 / 0 |

Fresh 中，TSP 为 \(+0.042295\)，VRPTW 为 \(-0.012702\)，OBP 为 0。方向不一致，区间跨零，也没有显示“只有开发耗尽时 Pivot 才有两步价值”的状态交互。

Experienced 的一步 \(Q_1\) 与两步 \(Q_2\) 统计完全相同。这说明那一个正例是即时 Pivot 改善，而非 continuation 兑现。Fresh 的 PR 同样没有任何第二步增加 \(Q_1\)；RR 只有一个 fresh VRPTW 路径由第二步将相对收益从 0.0237 提到 0.0381。

## continuation gain 为何看起来很大

只在两臂的两步评价都有效的锚点上，直接比较 \(f(c_2)-f(c_1)\)：

| 状态 | 可配对 anchor | PR−RR 平均相对 continuation gain | 95% CI |
|---|---:|---:|---:|
| Experienced | 5 | +0.7014 | [-0.0706, 1.8860] |
| Fresh | 5 | +1.4229 | [0.0870, 3.7690] |

这个表面上的强信号不能解释为 option value。三个 experienced OBP Pivot 第一步分别跌到 -3000、-2830.5、-2625，第二步回到 -744.5、-745、-744.5；相对 \(c_1\) 是巨大恢复，但仍没有超过各自的 anchor。Fresh 中也存在同类恢复。于是：

\[
f(c_2)-f(c_1)\gg0
\]

可以只说明 Refine 撤销了 Pivot 的灾难性改动，并不意味着：

\[
\max(f(c_1),f(c_2))>f^*.
\]

这也说明 continuation gain 必须与 anchor-relative \(Q_2\) 联合解释，不能单独作为 Pivot credit。

## 行为移动的解释

15 个评价有效的第一步 Pivot 获得了双 panel 行为画像，其中 14 个有有效 continuation。按干预前冻结的历史 Pivot 移动中位数划分：

| Pivot 移动 | n | 平均相对 continuation gain | 平均相对 \(Q_2\) |
|---|---:|---:|---:|
| Large | 10 | +1.2921 | 0.01269 |
| Small | 4 | -0.01735 | 0.000452 |

移动距离与 continuation gain 的 Pearson 相关为 0.664，但与 \(Q_2\) 的相关只有 -0.032。前一个相关主要由“大步跌落后大幅恢复”驱动；它没有转化为超过 anchor 的后续收益。行为距离在这里确实测到了 Pivot 实际移动多远，但“大移动”仍不是“更有 option value”的证据。

## 研究认识

1. E2-A 的主要问题得到修正：development experience 已进入状态，且 \(Q_1\) 不再阻断 \(Q_2\) 实验。
2. 修正后仍没有观察到一步 Refine 对 Pivot stepping stone 的兑现。现阶段应把它视为未经支持的机制假设，而不是从少数成功路线反推的既定事实。
3. \(f(c_2)-f(c_1)\) 会奖励“先制造很深的坑、再爬回起点”。控制器真正需要的是 anchor/frontier-relative option value。
4. BehaveSim 作为 transition sensor 是可解释的，但移动距离对最终两步价值没有呈现正向关系；不能据此奖励大 Pivot。
5. 本实验只识别固定 parent 上的 prompt sequence，不覆盖 Pivot 的宽 parent routing，也没有测试两步以上的修复期。若再研究 Pivot，应提出新的独立理由和明确 horizon 成本，而不是继续在本批 anchor 上改阈值。
