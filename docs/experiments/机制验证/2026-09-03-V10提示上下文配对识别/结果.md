# V10.1/V10.2 提示与上下文配对识别结果

## 工件定位

该工件只比较固定 Fuse 状态上的五个累积文本条件和 Init 端点。它显示这些文本条件会改变 proposal 分布，且方向依赖任务和状态；不用于解释 V10.1/V10.2 完整搜索结果，也不用于按历史最终效果给 Prompt 排名。

在本工件中，`comment_free -> operator_instruction` 的配对方向在任务间不一致；OBP 出现较大的负向均值，但这只是该批固定状态上的局部观察，不能标记为跨任务稳定成分。完整 V10.2 同时改变了多个文本字段，端点差不能拆成单一历史 Prompt 范式的效果。

去掉 Current/Donor 注释在这批状态上没有显示出一致负向变化；区间较宽，不据此认定去注释有益。

初始化分布也发生了变化。20 个 V10.1 Init 全部有效；20 个 V10.2 Init 中 4 个无效，集中在 OP `3/4` 和 VRPTW `1/4`。每任务只有 4 对，这里只记录为后续 replay 的待检查现象。

## 完整性

- Fuse：60 个固定状态，每个状态 5 个条件，共 300 条。
- Init：20 个固定任务与采样种子 block，每个 block 2 个条件，共 40 条。
- 生成 `340/340`，缺失 0，重复 0；解析失败 1。
- 评价 `340/340`，有效 331，invalid 9；解析失败不调用 evaluator。
- 30 个来自 V10.1 的抽中锚点，其基线 Prompt 均与正式运行日志逐字符一致。
- 五任务、V10.1/V10.2 来源状态、父节点 fitness 低中高层均按设计平衡。

OP 与 VRPTW 的有效配对数过少，区间不作稳定效应解释。这里最直接的事实是 V10.2 Init 新增了 4 个运行时无效候选。

## 结论边界

该实验支持的事实是：在固定状态、算子、donor、模型和采样条件下，文本条件可以改变单步 proposal 的有效性、质量和尾部行为。它没有测量这些差异经过父节点选择、后续开发和有限预算累积后的搜索终局，也不能恢复历史版本中已经丢失的逐步 proposal 质量。历史 Prompt 的后续研究转入[历史 Prompt 范式固定状态重放](../2026-09-04-历史Prompt范式固定状态重放/实验设计.md)，以代表性范式为处理臂。
