## 1. 实验问题与目标

**E1：Operator-Conditioned Local Transferability。** 相似的算法状态，在执行同一种搜索行为时，是否具有可迁移的后代响应？第一轮只研究 Refine：

$$
d_B(n_i,n_j)\text{ 小}
\quad\Longrightarrow\quad
\mathcal D(\Delta f\mid n_i,R,H_i)
\approx\mathcal D(\Delta f\mid n_j,R,H_j),
$$

其中 $R=\mathrm{Refine}$，$\Delta f=f(child)-f(parent)$，$H_i,H_j$ 是各锚点自己的真实形成历史。所有任务统一使用越大越好的 fitness。

要验证的是：在父代质量、已选次数、搜索阶段等信息之外，行为邻域是否为下一次 Refine 结果提供**增量预测价值**。相近算法当前 fitness 接近，只说明静态质量结构；它不能替代对未来动作响应的验证。

动机来自稀疏反馈：[V10.6 设计](../../../methods/TraceAAD-V10.6/机制设计.md)引用的覆盖核查实际来自 V10.5 前 750 次评价的 15 路运行，5,847 次 Refine 涉及 2,762 个父节点，其中 72.4% 只获得 1–2 次 Refine。这一历史策略下的样本量不足以稳定独立估计每个节点的后代分布。

本实验希望检验：能否通过相似状态之间共享轨迹反馈，将独立节点估计转为局部条件估计：

$$
P(\Delta f\mid n,R,H_t)
\approx P(\Delta f\mid\mathcal N(n),R,\text{可比形成状态}).
$$

这是轨迹反馈能否跨节点泛化的问题，不要求提出新的相似度度量，也不直接上线 landscape score。

## 2. 为什么以 V10.6 为基线，为什么先只做 Refine

V10.6 保留形成路径生成、逐评价重选及明确的 R/P/F 联合分布，尚未加入个体潜力预测、行为聚类与自适应算子选择，因此适合隔离新增观测的信息价值。其作用是清楚的实验基线，不预设为性能最优版本。

第一轮只研究 Refine，原因是没有 donor 变量、历史动作较多、设计意图对应局部开发。先验证 $Q(n,R\mid H_t)$ 是否可迁移，再决定是否扩展 Pivot 或 Fuse 的状态空间。

E1-A 与 E1-B 均不修改正式 `_schedule()`，不增加行为感知 Prompt，不改变 V10.6 archive 或在线选择。后续在线实验须通过 E1 的证据门槛。

实现依据：

- [V10.6 运行说明](../../../../experiments/traceaad_v10_6/README.md)：生成协议、模型配置、工件与评价计费。
- [V10.6 实现](../../../../llm4ad/method/traceaad_v10_6/traceaad.py)：`_schedule()`、`_advance()`、独立实现摘要调用及事件字段。
- [BehaveSim v3 协议](../2026-08-26-BehaveSim行为度量校正/实验设计.md)：probe、PSTraj 与距离计算。

## 4. E1-A：数据准备与严格时间回放

### 4.1 数据来源与冻结

从 V10.6 的修订协议 `idea_code_then_implementation_idea` 工件读取，冻结 run 清单、源代码/模板指纹、数据截点和 backend。不同生成协议不混入同一主分析。

| 工件 | 用途 |
| --- | --- |
| `run_config.json` | task、seed、backend、生成与评价设置 |
| `tree_state.json` | 节点 code、实现摘要、parent/donor、fitness、evaluation ID |
| `events.jsonl` | 候选尝试顺序、请求/执行算子、选择前状态、评价结果与失败 |
| `llm_calls.jsonl` | 原始 generation Prompt、模板哈希、采样参数和调用成本 |
| `evaluations.jsonl` | 真实评价收据、失败原因、耗时与评价次数 |
| batch manifest / backend snapshot | 运行来源与实际模型服务版本 |

先核查每条 Refine 的输入状态与结果是否能联接。代码事件中可读取 `selection.parent_probability`、`selection.operator_conditional`、`selection.parent_count_before`，有效后代另有 `parent_delta`、`frontier_delta`；Fuse 有 donor 时记录 `both_delta`。无效后代不会有有效节点和这些增益字段，必须从事件恢复失败尝试，不能只遍历成功树边。

主分析使用 **requested=Refine 且 executed=Refine**。requested=Fuse 后回退为 Refine 的尝试单列敏感性分析，避免将 donor 不可用状态混入主样本。若合并，需显式保留回退标记和相应选择概率。

### 4.2 时间单位与可见集合

令 $t$ 为一次候选尝试的序号，$H_{t^-}$ 为本次选择前已完成的历史。定义：

$$
\mathcal A_{t^-}=\{\text{本次选择前已经入档的有限有效节点}\},
$$

$$
\mathcal F_{t^-}=\{(p_i,c_i,\text{outcome}_i):\text{在 }t\text{ 前已经完成的 Refine 尝试}\}.
$$

集合不是“曾被选为 parent 的节点列表”，也不能从最终树直接取全量。选择次数使用选择前值；搜索阶段用当时已消耗真实 evaluator 预算占比，不能用最终子代数替代。

画像可以事后统一计算，但使用固定 probe 与固定表示模型；回放时仅允许访问当时已存在节点的画像。禁止用未来节点、未来子代收益、全程最终排名或全数据调出的阈值来构造当时的预测。

原始代码若无法确定出生时间或当时上下文，标为不可回放，不猜测填补。不要把未完成 pending 请求当作已知结果。

### 4.3 画像覆盖与成本

至少画像所有被研究的 Refine parent；若要计算 archive 邻域，则还需要所用历史档案候选的画像。两者不是同一个工作量。

资源不足时，先用固定的、只依赖当时信息的抽样规则建立“已画像历史子集”，并报告覆盖率；不能把该子集的密度描述为全 archive 密度。相同代码可缓存画像，但其不同形成状态、被选次数与动作尝试仍需分开保留。

BehaveSim 初期沿用 v3 固定面板与任务适配，比较面板 A/B 的距离排序、近邻重合和随机种子敏感性。OP/CVRP 的画像成本特别单列。画像失败标记缺失，不设置为距离零或极远。

### 4.4 只计算四组观测

所有邻居集合先排除 $n$ 本身。若相同代码以不同节点出现，允许它们产生零距离重访，但另做排除同代码的敏感性分析。

**最近邻距离：**

$$
d_1(n,t)=\min_{j\in\mathcal A_{t^-}\setminus\{n\}}d_B(n,j).
$$

它描述当下 parent 与其他已知算法的行为接近程度，不等同于候选出生时的新颖度。

**局部密度：** 令 $k_t=\min(k,|\mathcal A_{t^-}\setminus\{n\}|)$：

$$
\rho_k(n,t)=\left[\epsilon+\frac1{k_t}\sum_{j\in N_{k_t}(n,t)}d_B(n,j)\right]^{-1}.
$$

**局部 fitness 离散：**

$$
R_k(n,t)=\frac1{k_t}\sum_{j\in N_{k_t}(n,t)}|f(n)-f(j)|.
$$

这是粗粒度局部波动量，不直接宣称为真实地形 ruggedness。无邻居时上述量缺失，同时提供覆盖标记。

**局部 Refine 响应：** 对此前已完成尝试，令 $y_i=1$ 当且仅当候选有效且严格超父，否则为 0：

$$
w_i(n)=K(d_B(n,p_i)),\qquad
\widehat P_R(n,t)=
\frac{\alpha\pi_R(t)+\sum_{i\in\mathcal F_{t^-}}w_i(n)y_i}
{\alpha+\sum_{i\in\mathcal F_{t^-}}w_i(n)}.
$$

$\pi_R(t)$ 是此前同 task/backend 的全局 Refine 改善率，冷启动用预先固定的平滑先验；$\alpha$ 是收缩强度。核函数、带宽、$k$ 和概率截断只在训练数据确定。另报告正部增益、有效率和权重有效样本量，不能将加权相关样本直接解释为精确 Beta 后验。

为直接检验**跨节点**迁移，主分析中估计局部响应时排除 $p_i=n$ 的同节点尝试；另报告允许同节点历史的在线实用版本。否则模型可能仅学会重复父节点的自有历史，而没有跨节点泛化。

### 4.5 逐条回放流程

1. 读取当前尝试前的 archive、已完成动作反馈与选择前计数。
2. 用当时可见的画像和历史训练模型，生成并保存预测。
3. 读取当前真实结果，计算标签和误差；不得用它反向调整当前预测。
4. 将当前尝试结果与新增有效节点加入下一时刻历史。
5. 依次处理到冻结截点，输出覆盖、缺失与失败统计。

不同 run 各自保留时间轴。主回放以本 run 已发生的反馈构造在线邻域；其他 run 可用于离线训练/调参，但必须通过外层按 run 留出隔离。若另研究跨 run 在线共享，需明确哪些完整历史 run 在目标 run 开始前可用，不能任意混入别的 run 的未来。

## 5. E1-A：模型、指标与预测检验

### 5.1 四个必要对照

| 模型 | 输入 | 目的 |
| --- | --- | --- |
| M0 | 历史全局 Refine prior | 检查是否只预测总体稀有成功率 |
| M1 | parent fitness、count、search stage | 当前简单控制信息的预测基线 |
| M2 | M1 + code/Implementation Summary embedding 邻域 | 检查便宜表示是否已足够 |
| M3 | M1 + BehaveSim 邻域及局部历史响应 | 检查行为几何的增量价值 |

M2/M3 使用相同容量的预测器、相同调参预算与验证划分；区别主要是邻域定义。固定表示模型与 canonicalization 规则，使用历史已存在的实现摘要，不为获得 M2 输入新增 LLM 摘要。若补摘要，须另设成本和实验条件。

M3 内保留“只加距离/密度/离散”与“进一步加邻域响应”的消融，以判断增量来自静态地形还是轨迹反馈共享。可加 M1 + 同节点历史、M1 + 质量匹配邻域作为诊断对照。实现先用简单模型，不把完整 contextual bandit 引入预测验证。

### 5.2 标签与指标

主标签是每次计划尝试的无条件严格改善 $y_t$。另报告“给定代码可评估”的改善率，区分生成失败与求解质量。

主要指标：

- Brier score、log loss：主比较为 M3 相对 M1 的预测误差变化，越低越好。
- PR-AUC：补充稀有正例排序能力；无正例子集报告不可定义，不填零。
- 校准曲线与各预测组的实际改善率。
- 预先固定的高预测组（例如最高 20%）相对全体的 improvement lift，不能看结果后挑分组阈值。
- 正部增益、灾难性退化及超当前 best 的预测作为辅助，检查“容易超弱父”是否偏离真实目标。

按 task 和 backend 分层报告。使用相同测试尝试上的配对误差，按 run 聚合并报告区间；不把大量相关树边当作独立重复。历史 V10.6 每任务重复有限时，如实说明区间精度，不以候选数量掩盖 run 数量不足。

### 5.3 进入 E1-B 的条件

先确认时序、覆盖和画像稳定性合格，再看 M3 相对 M1 是否有可重复增量；同时比较 M2 是否能以更低成本达到近似效果。只看训练集相关性或全档案后验聚类，不构成进入依据。

出现跨任务方向冲突时，可将 E1-B 缩小到有信号且测量可信的任务，并重算预算；不得仍宣称完成五任务验证。正式分析前冻结主指标、最小有意义效应和筛选规则，现阶段不凭空预定“必然显著”的阈值。

## 6. E1-B：固定锚点与近/远配对

### 6.1 样本单位与匹配

一个 anchor 是 **节点 + 历史时刻 + 当时完整 Refine 上下文**，不仅是代码。所有重复子代都从同一冻结 anchor 独立生成，彼此不串成新轨迹，不更新 parent count 或把先生成的 child 放回后续 Prompt。

从 V10.6 archive 按下列变量匹配：task、backend、fitness percentile、search stage、lineage depth、近期轨迹趋势、Prompt/history 长度。fitness 分位等信息只用锚点时刻可见数据；趋势由锚点自身已有形成路径计算，不读取未来后代。

在可比状态池内选：

- Near pair：fitness 接近、行为距离较小。
- Far pair：fitness 同样接近、行为距离较大。

Near/Far 距离阈值按 task、有效匹配池预先确定，采用同一冻结 probe；同时记录 embedding 距离。两组还须比较匹配变量的整体平衡，而不仅仅保证每一对内部接近。候选不足时报告匹配失败，不为了凑够 180 次而偷偷放宽规则。

主设计不重复使用同一 parent，尽量避免同代码与近亲谱系垄断样本。使用多个来源 run；若跨 backend，必须分层，不能把不同量化或服务实现视为同一生成核。

### 6.2 固定生成协议

沿用 V10.6 原始 Refine Prompt 与 task contract：当前 code、已有 Implementation Summary、真实 parent path、最近最多 8 条 formation events，使用原 builder 的 token 截断与输出契约。优先复用历史实际 Prompt；重建时保存文本与哈希并核对来源。

采样按冻结 V10.6 配置：temperature=1.0、top_p=0.95、top_k=20、thinking 关闭，其他输出和上下文限制同基线。保留实际 backend/model/量化信息。一个匹配比较内使用同一 backend，随机交错锚点与重复的调用顺序，减少时段负载和服务漂移的混杂。

每个 anchor 的多个 child 是独立抽样；不复用导致完全相同输出的同一随机种子。若接口支持生成 seed，预先固定每次调用的映射；不支持时记录事实。评价使用固定且一致的任务随机规则，不根据生成结果调 seed。

### 6.3 为什么单步实验可以省略 child 的摘要调用

V10.6 先生成 Idea+Code，再独立生成该 child 的 Implementation Summary，随后评价。第二次调用不改写已生成代码，主要服务 child 未来作为父代时的上下文。

E1-B 不继续开发 child，因此可在独立实验 runner 中省略第二次摘要调用，保留**输入 anchor 已有摘要**，只测：

$$
x\sim K_\phi(\cdot\mid C_{\mathrm{V10.6}}(H,n,R)).
$$

实现时应核对省略摘要不改变评价 seed、代码或其他执行状态；复用原解析、合法性检查与评价路径。若之后研究负向 child 的第二步开发，必须恢复实现摘要形成流程，因为它将进入后续上下文。

### 6.4 pilot 与扩展预算

| 规模 | 每任务 Near/Far 对数 | 每任务独立 parent | 每 parent 生成次数 | 五任务计划生成 |
| --- | ---: | ---: | ---: | ---: |
| Pilot | 3 + 3 | 12 | 3 | $5\times12\times3=180$ |
| 扩展总规模 | 6 + 6 | 24 | 4 | $5\times24\times4=480$ |

若扩展沿用全部 pilot anchor、Prompt 和协议，则在 pilot 基础上追加 300 次生成：原 60 个 parent 各补 1 次，共 60 次；新增 60 个 parent 各 4 次，共 240 次。若更改匹配、模型或生成协议，不能直接合并称为同一批重复。

预算按三项分开统计：计划候选生成、实际 API 请求（包括传输重试）、真实 evaluator 调用。180/480 是全部成功解析时对应的 evaluator 上限；解析失败不进入评价，超时或执行失败一旦提交真实评价就计费。失败候选不自动补到“每父 3 个成功 child”，否则会隐藏失败率并增加预算。

本实验省略 child 摘要，理想情况下 pilot 为 180 次 generation 调用，而非 360 次双阶段 LLM 调用。画像、embedding、token 与总耗时另列。评价状态未知时先核对收据，避免同一候选重复提交。

## 7. E1-B：响应量与统计比较

### 7.1 锚点响应

对每个 anchor 的计划尝试数 $m_n$，估计：

$$
\widehat p_R(n)=\frac1{m_n}\sum_j\mathbf1[\text{valid}_{nj}\land f(c_{nj})>f(n)],
$$

$$
\widehat\mu_R(n)=\frac1{m_n}\sum_j g_{nj},\qquad
g_{nj}=\begin{cases}(f(c_{nj})-f(n))_+,&\text{valid}_{nj},\\0,&\text{otherwise}.\end{cases}
$$

无效候选的正部收益计零是“每次生成机会的兑现收益”定义，不是将其 fitness 伪造为零。另报告有效子代条件下的 $\Delta f$ 分布、invalid rate、catastrophe rate 和超锚点时刻 best 的比例。

严重退化以有效候选 $\Delta f\le-\tau_{task}$ 定义，$\tau_{task}$ 在生成前依据任务尺度冻结；invalid 单列，也可补充二者合并的坏结果率。

### 7.2 Near/Far 的主比较

材料提出响应距离：

$$
D_R(i,j)=|\mu_R(i)-\mu_R(j)|+\lambda_D|p_R(i)-p_R(j)|.
$$

因增益与概率尺度不同，主报告分别给出两个分量；若使用合成距离，先按 task 的训练期固定尺度归一化增益，预先冻结 $\lambda_D$，不能与后续在线混合权重混用。

关键假说为：

$$
\mathbb E[D_R(i,j)\mid Near]
<\mathbb E[D_R(i,j)\mid Far].
$$

以匹配 pair 或匹配 block 为分析单位，报告 Far−Near 差值、各 task 的方向、区间和原始锚点响应；不能将同一 parent 的 3–4 个 child 当成独立 parent 重复。若锚点重复使用，必须按共享锚点处理相关性。

每锚点 3–4 次只是低成本 pilot，成功率分辨率粗，经验分布距离容易被生成噪声主导。pilot 没有显著差异不等于证明无 locality；结合效应方向、测量稳定性与不确定性决定是否扩展。也不能只因 Near 响应相同便判成功：若全是失败，应结合 E1-A 的校准、区分度与收益大小判断是否有分配价值。

固定锚点与等量采样减少了历史策略决定“谁获得更多后代”的偏差，但 Near/Far 不是随机改变同一算法的行为距离，未观测的代码/路径差异仍可能混杂。结论应表述为受控匹配样本中的响应局部性，不能宣称已经识别距离的独立因果作用。

## 8. 结果分支与下一步选择

| 结果 | 证据 | 下一步 |
| --- | --- | --- |
| A：动作局部性有支持 | M3 超过 M1，固定锚点 Near 响应比质量匹配 Far 更接近，且不只来自同节点或无效样本 | 进入 Refine 局部可演化性选父消融 |
| B：只支持饱和诊断 | 不足以预测收益高低，但低重访距离与历史无改善能预测继续开发无效 | 单独设计 Refine→Pivot/Fuse 的 switching 实验，不包装为节点潜力 |
| C：有效观测仍无预测信号 | 数据覆盖与测量合格，几何对动作响应和停滞均无增量信息 | 停止 geometry-aware parent allocation；保留诊断用途，转 Fuse 配对或形成表示研究 |
| 未决：数据或精度不足 | probe 不稳、缺失多、匹配不足、pilot 区间过宽 | 先修测量或补最必要样本，不将“不确定”判为 C |

同时比较表示的成本收益：BehaveSim 明显更好时，研究低成本行为采集；embedding 近似有效时优先测试便宜视图在线使用，BehaveSim 保留为诊断参照；二者均无增量时不强行进入控制器。

## 9. E1-C：条件成立后，只改 Refine 选父

### 9.1 唯一机制改变

令 $p_0(n)$ 为原质量与次数分布，$p_E(n)$ 为非负、归一化的局部 Refine 可演化性分布。必须预先明确 $\widehat E_R$ 使用改善概率还是正部增益；两者不是相同目标。无历史、有效权重不足或所有值为零时回退 $p_0$，不产生无法归一化的分布。

冻结混合系数 $\lambda_{mix}\in[0,1]$，定义：

$$
J_R(n)=0.50[(1-\lambda_{mix})p_0(n)+\lambda_{mix}p_E(n)],
$$

$$
J_P(n)=0.15[0.5p_0(n)+0.5/N],\qquad J_F(n)=0.35p_0(n).
$$

仍然先选父再选算子：

$$
m(n)=J_R(n)+J_P(n)+J_F(n),\qquad P(o\mid n)=J_o(n)/m(n).
$$

只要 $p_0,p_E$ 在相同合法父代集合上归一化，就有请求边际 $\sum_nJ_R=0.50$、$\sum_nJ_P=0.15$、$\sum_nJ_F=0.35$。$m(n)=0$ 的节点不被选择。

Fuse donor、Prompt、形成上下文和入档规则保持基线。无合法 donor 的 Fuse 仍回退 Refine，因此这里只保证**请求**边际；不能说所有实际执行的 Refine 都来自新的 $J_R$。

### 9.2 必要对照与报告

至少比较原 V10.6（$\lambda_{mix}=0$）与冻结参数的新分布；若 E1-A 显示 embedding 有竞争力，加入同结构 embedding 分布。调参在独立数据进行，不用测试 run 选最优混合权重。

确认新分布归一化、原比例和回退记录正确，再做匹配 task、seed、backend、模型与真实评价预算的在线比较。正式终局比较采用项目默认每路 1,000 次真实评价，初始化、失败与超时照原规则计入；任务和重复规模在启动前单独登记，不把本设计当作已启动完整批次。

主要结果是最终 best、best-so-far、未知实例与跨规模表现，同时报告 Refine 收益、预算落点、有效率及所有画像成本。局部改善率上升可能只是更多开发低分父代，不能替代终局收益。

## 10. E1-D：行为采集的上线可行性验证

若需要在线 BehaveSim，优先研究复用正式 evaluator 中已经执行的固定训练实例：

$$
\mathcal E(x)\longrightarrow(f(x),z_B(x)).
$$

不默认每个候选再执行整套额外 probe，也不将验证/测试实例加入控制器。当前 V10.6 的评价收据不能直接视为已经保存 PSTraj，本阶段需单独实现和验证采集。

对同一批固定候选、同一输入与随机 seed，配对运行原评价器和加观测版本，比较：

1. fitness 是否 bitwise 相同；不能 bitwise 时，预先定义合理数值容差并检查来源。
2. 随机状态、决策顺序与候选行为是否一致。
3. runtime、内存和 timeout rate 是否改变，尤其关注接近时限的候选。
4. 在线 signature 的距离排序及 E1 预测能力，是否保留离线 BehaveSim 的有效信号。

即使没有额外实例执行，插桩也可能改变时限表现，因此不能只以“evaluator 次数相同”认定成本相同。通过上述验证后，才决定在线观测频率、缓存和采样配置。

## 12. 本轮交付与研究判断

本设计初次交付时仅记录方案。后续已按用户要求完成 E1-A 离线画像与历史回放；未新增生成 LLM 调用，未改动 V10.6 搜索实现。实际结果见[E1-A 结果](E1-A-结果.md)：M3 相对 M1 的 run 宏平均 Brier 恶化6.87%，未通过筛选门槛。随后完成的[E1-A.1](E1-A.1-结果.md)也未发现行为在质量近邻之外的可信增量，因此不启动原版 E1-B。

E1 的成功标准不是画出平滑地形，而是建立这条有证据的关系：

$$
\text{形成轨迹反馈}+\text{相似状态邻域}
\longrightarrow\text{未见节点的 Refine 响应预测}
\longrightarrow\text{更有效的 Refine 预算分配}.
$$

先用 E1-A 筛信号，再用 E1-B 固定锚点确认，最后才通过 E1-C 检验预算收益。失败或未决也要保留其对应结论，使下一步研究选择有据可依。
