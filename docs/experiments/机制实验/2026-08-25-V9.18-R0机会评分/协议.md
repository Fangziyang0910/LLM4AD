# V9.18-R0 机会评分

实现前固定的实验顺序。结果写入工件和正式结果页后，只补充实际完成的数字。

机制规范见[TraceAAD V9.18-R0](../../../methods/TraceAAD-V9.18完整机制设计.md)。对照分析见[V9.16 与 V9.17](../../../analysis/TraceAAD-V9.16-V9.17对照分析.md)。

## 问题

| 阶段 | 比较 | 问题 |
| --- | --- | --- |
| P0 | 固定锚点 History-off/on | 父代来时路与 Global-Facts-Lite 是否改变下一步提议 |
| A | `q-atomic` / `q+O-atomic` | 边界机会项是否改变锚点路由和有限预算结果 |
| B | 原 Explore / Global-Facts-Lite | 极短全局事实是否改善 Explore 提议 |
| C | A 与 B 的联合臂 | 两个已经识别的改动共同作用如何 |

P0 是 transition 证据，A/B/C 是完整搜索证据。过程激活不等于质量改善。

## 协议

- 模型：Qwen3.6-27B。
- 每路八个有效根，1000 个 primary evaluator slots。
- `Refine=0.7`、`Explore=0.3`；temperature、max output tokens、repair 与评价器与 V9.16 正式口径一致。
- A 阶段两臂从同一个精确八根 checkpoint 分叉。
- held-out 只在搜索结束后对每个 repeat 的 train best 独立评估。
- 修复调用不占 primary slot，单独报告 evaluator / LLM / repair 次数。

每个 slot 记录选择前的 `q`、`O`、`n_after`、`sigma_q`、`S`，以及锚点、算子、fitness 与失败类型。run summary 含机会项激活率、选择熵、valid/invalid/timeout/repair 率。
