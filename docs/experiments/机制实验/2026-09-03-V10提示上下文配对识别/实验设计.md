# V10.1/V10.2 提示与上下文配对识别实验

## 问题

本实验识别 V10.1 到 V10.2 的提示与代码上下文变化是否改变单步 proposal
质量。预算分配与扩展调度不进入本实验。

主实验固定同一个任务、父节点、父代来时路、Fuse 算子与 donor，对同一个
Qwen3.8-27B 后端使用相同采样种子，依次比较五个累积条件：

1. 正式运行时的 `V10.1`
2. `+ Implementation Principle`
3. `+ Current/Donor 去注释`
4. `+ V10.2 Fuse instruction`
5. 完整 `V10.2`

第五步补入 V10.2 剩余的来时路序号、Idea 标签与输出契约变化。V10.1 端点按
2026-09-02 正式运行日志中的 `Generation -k` 来时路格式重建，不采用运行后改成
`Step k` 的当前展示代码。五个条件使用相同的来时路截断长度。每个固定状态构成
一个完整 block，block 内条件顺序按固定随机种子打乱。

## 锚点与预算

锚点来自 2026-09-02 已完成 1,000 次评价的 V10.1 与 V10.2 搜索。五个任务分别
从两个来源版本各抽 6 个 Fuse 状态；每个 `任务 × 来源版本` 内按父节点 fitness
分成低、中、高三层，每层抽 2 个，并在已有重复间平衡。完全相同的 V10.1
基线 Prompt 只保留一次。

主实验共 60 个状态、300 次生成。另对每个任务运行 4 个 `V10.1 Init` 与
`V10.2 Init` 配对 block，共 40 次生成，用于识别根节点初始化 Prompt 的变化。
总计 340 次生成；解析成功的候选各进行一次训练集评价。

锚点抽样不使用原 Fuse 子代的成败或 fitness。来源版本只描述状态来自哪套搜索
分布；处理效应由同一状态内的配对差识别。

## 运行控制

- 每个 block 的所有条件固定 task、parent、trajectory、operator、donor、采样
  seed、LLM backend 与 evaluator。
- 同一 block 不跨 shard，避免后端差异进入处理差。
- 各 shard 先完成全部生成，之后由一个本地进程顺序评价，避免并行 CPU 负载与
  evaluator timeout 绑定到处理条件。
- 模型与采样参数沿用正式实验：Qwen3.8-27B，temperature 1.0、top_p 0.95、
  top_k 20，最大输出 16,384 tokens。
- 生成与评价逐条落盘，可以从已完成 trial 继续。

## 响应与分析

Fuse 的主要响应为：

1. `delta_fitness = child_fitness - parent_fitness`，只在有效候选上计算；
2. 无条件改善率，有效且严格改善记为 1，其余记为 0；
3. invalid rate，包括解析失败与 evaluator 无效。

对每个任务报告五个相邻/端点配对对比：四个逐步增量与完整
`V10.1 -> V10.2`。均值差的 bootstrap 区间以固定状态 block 为重采样单位。
原始 fitness 标度不跨任务汇总。来源版本分层结果用于检查处理效应是否依赖
V10.1 或 V10.2 形成的状态分布。

Init 单独报告同任务内的有效 fitness 配对差与 invalid rate；它没有父节点，因而
不计算 `delta_fitness`。

本实验只能回答固定状态下单步 proposal kernel 是否变化，不能估计预算分配、
完整搜索终局或测试集泛化效果。
