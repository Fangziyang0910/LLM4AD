# 父代来时路完整搜索消融（V9.7-PP vs V9.7-CO）

## 要证明什么

**主张**：在 V9.7 的完整协议（两级路线—锚点分配、固定 0.7/0.3 意图、即时反馈、同意图日程与种子）下，把生成上下文从 code-only 换成 code + 父代来时路，提高 1000 次真实评价的 search best，方向在四任务三重复中一致；held-out 方向同报。

**机制链**：单步证据（三轮固定锚点实验、V9.8 Stage P）已确立来时路改善 $P(x'\mid x,h,o)$——四任务配对 $\Delta q$ 区间全部不跨 0、压缩灾难性偏离与修改幅度。本实验检验该单步收益是否**累积**为完整搜索的 best-at-budget：更好的 child 更多被选为锚点 → 更好的来时路 → 形成路径质量抬升。

**反假设**（同样可证）：单步收益不兑现——(a) 收益集中于浅层修正，重复选择下耗尽；(b) 修改收缩降低长期多样性，突破变少；(c) 路径自增强把早期噪声放大。若方向分裂或为负，结论为"V9.7 的完整搜索优势来自分配与意图结构，来时路是单步改良但非完整搜索净贡献来源"。两个方向都是 V9.7 证据链的必要一环：V9.6→V9.7 联合升级从未分离过来时路的净贡献。

## 设计

- **两臂**：`CO`（code-only：任务说明 + 当前 Fitness + 完整代码 + 意图指令 + 输出契约，无历史区）与 `PP`（V9.7 原样：至多 8 条父代形成事件）。CO 的提示构造与固定锚点第三轮 `code_only` 臂一致。根生成提示两臂逐字节相同；bootstrap 起 CO 无历史占位区（处理定义的一部分，记录在案）。
- **配对**：同任务、同 seed（意图日程复用 V9.7 的确定性映射、生成种子公式相同），4 任务 × 3 seed × 2 臂 = 24 个 1000-eval 运行。初始化前两臂提示除 bootstrap 历史占位外一致；配对单位是任务 × seed。同 seed 配对在搜索混沌下不保证逐轨迹同步，统计上按独立重复报告。
- **实现**：独立方法包 `traceaad_v9_7_co`（V9.7 逐位复制，仅提示构造去历史区；协议 `traceaad-v9.7-code-only-ablation`），runner 注册 `--version v9_7_co`；PP 臂直接用 V9.7。
- **终点**：主要 = 1000-eval search best 与正式 held-out（统一口径，`evaluate_best.py`）。过程 = 修改幅度分布、improve 率、有效率、树深度/宽度、最好程序形成路径长度、意图结局分布、token 成本。
- **判定**：验证性实验，无门槛终止；按三重复实际均值差与逐重复方向报告（仓库三重复纪律）。预注册解释框架：多数任务配对方向为正且 held-out 同向 → 支持主张；方向分裂或为负 → 反假设证据；均写明任务画像。

## 结果

逐 run 记录：搜索结束即测 held-out（`evaluate_best.py` 统一口径），全齐后给臂均值与逐 seed 配对方向。train best 为 1000 次评价内的 `best_score`；所有 run 均以 `evaluator_budget_exhausted` 在恰好 1000 次评价收尾，最优候选必然在预算内，故不设 `--max-sample-order`（该参数按生成序截断，会把无效响应之后的有效候选误判为超预算）。

## 汇总

train best 均值（3 seed）与 held-out 均值的臂间方向，逐 seed 配对方向以 train best 计：

| 任务 | train best 均值（PP vs CO） | seed 方向 | held-out 均值方向 |
| --- | --- | --- | --- |
| TSP | 5.7840 vs 5.7534（CO 好） | CO 2–1 | CO 三规模全好 |
| CVRP | 8.9703 vs 8.8801（PP 好） | PP 2–1 | CVRP50/100 略偏 CO，CVRP200 PP 好 0.35 |
| OP | 14.7733 vs 14.4393（PP 好） | PP 2–1 | PP 三规模全好，OP200 差 2.70 |
| OBP | −726.58 vs −726.58（相等） | PP 2–1 | CO 六设置中五个更好（由 PP s1 离群拖动） |

判读（按预注册框架）：**方向分裂，不支持"来时路一致提升完整搜索 best"的主张，也不支持一致的负向反假设**。四任务无一 3–0：OP 是最清楚的正向（train 与 held-out 全向 PP）；CVRP 的 train 均值偏 PP 但 held-out 只在最大规模同向；TSP 整体偏 CO（train 均值与 held-out 三规模，唯一例外是 s0）；OBP train 均值两臂相等、held-out 均值偏 CO 但逐 seed 方向偏 PP。臂间差距与 seed 间方差同量级（TSP PP s1 5.928、OP PP s2 14.522 是各自臂的最差 run，单 seed 摆动大于臂效应）。结论按任务画像记录：来时路的完整搜索净贡献不是跨任务常数——在 OP 上为正、TSP 上为负、CVRP/OBP 上在噪声量级内。净贡献方向与任务的区域上限画像对齐：OP 是 V9.7 相对 V9 仍全面退化的任务（锁定区域低于可达上限），也是唯一清楚的臂效应；OBP 评价离散、早饱和，两臂 train best 相等；CVRP 仅最大规模偏 PP；TSP 偏 CO 由 PP s1 单 seed 拖动，处于 seed 方差量级。机制解释与检验入口见 [V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md) §6.4。

事实记录：6 个 PP run（CVRP s0/s1、OP s0、TSP s0/s1/s2）在 8 月 20 日 23:46–23:59 因后端迁移中断约 13 分钟，从断点续跑，每 run 至多损失一个在途生成；生成服务源按仓库口径不区分。held-out 评估对全部 24 个 run 以逐 run 独立口径完成（`eval_best_ppab_20260820_131000/<run_name>/results.json`）。

后续分析入口：24 个 run 的中途预算 best-so-far 曲线（如 200/500/1000 处臂间对照），检验来时路收益转化为可达终点还是收敛速度。工件已按不可复现口径精简（保留 evaluations.csv、best_curve、best_program、held-out results，checkpoints 已删）；ppab 运行无 candidates.jsonl，修改幅度等过程指标不可再分析。
