# v4flash 模型批次对比结果（独立记录）

> 本页记录 **deepseek-v4-flash**（opencode.ai zen/go 网关，`https://opencode.ai/zen/go/v1`）作为搜索 LLM 的独立实验批次。
> 与正式主实验（Qwen3.6-27B，3 次重复）**分开记录**：模型不同，不进入正式结果页与跨任务排名。
> 正式口径见 [实验总汇](实验总汇.md) 与 [实验配置](配置.md)。

## 1. 批次设置

| 项 | 值 |
| --- | --- |
| 模型 | `deepseek-v4-flash`（opencode.ai zen/go，OpenAI 兼容端点） |
| 关闭思考 | `thinking: {"type": "disabled"}`（DeepSeek 官方参数；该网关不识别 vLLM 风格的 `enable_thinking`/`chat_template_kwargs`，详见下方备注） |
| 搜索预算 | 1000 次评估（与正式协议一致） |
| 重复次数 | 2（seed=0、seed=1 各一轮） |
| 方法顺序 | MCTS-AHD → PathWise → EoH → ReEvo → CALM（方法间串行，方法内 4 task 并行） |
| 任务 | `tsp_construct`、`cvrp_aco`、`op_aco`、`online_bin_packing`（与正式主实验相同 4 题） |
| 批次标识 | 第一轮 `v4flash_20260811_185827`（seed=0）、第二轮 `v4flash_20260813_205108`（seed=1） |
| 运行方式 | `run_v4flash_batch.sh` 调度；每实验独立 tmux 会话，`experiments/<task>/<method>/v4flash_<时间戳>_*_rep1/`；测试工件 `v4flash_eval/`（第一轮）与 `v4flash_r2_eval/`（第二轮） |

搜索/测试协议与正式口径相同（TSP50×16 搜索；CVRP/OP 各规模 64 实例；OBP 六尺度），见 [实验配置](配置.md) 的「任务评价协议」节。

**备注（LLM 网关调用）**：opencode.ai zen/go 网关是 DeepSeek 官方 API 风格（响应含 `reasoning_content`）。关闭思考必须发送 `thinking: {"type": "disabled"}`；`enable_thinking=False` 或 `chat_template_kwargs.enable_thinking=False` 不被识别，会导致模型全量思考、`content` 为空。本项目客户端已修改 `llm4ad/tools/llm/llm_api_openai.py` 的 `_merged_extra_body`，三种格式同时发送以兼容本网关与其他 vLLM 后端。

## 2. 完成状态

两轮共 40 个实验（5 方法 × 4 task × 2 轮）搜索与测试集评估均已完成。

| 方法 | 每轮搜索状态 | 测试评估 |
| --- | --- | --- |
| MCTS-AHD | ✅ 4/4（各 1000 eval） | ✅ 两轮 |
| PathWise | ✅ 4/4（各 ~1000 eval） | ✅ 两轮 |
| EoH | ✅ 4/4（各 ~1010 eval） | ✅ 两轮 |
| ReEvo | ✅ 4/4（各 1000 eval） | ✅ 两轮 |
| CALM | ✅ 4/4（120–182 eval，见下方说明） | ✅ 两轮 |

> **CALM 预算说明**：CALM（w/o GRPO）的搜索框架含 archive 去重、performance-profile 去重与 numeric refinement，4 个 task 均在 1000 eval 预算内耗尽有效候选后正常终止（`status=finished, error_count=0`），两轮实际评估次数 113–182。这是方法搜索空间特性，非错误。`max_sample_nums=1000` 上限一致，公平性约束满足。

> **EoH CVRP 说明**（第一轮）：v4flash 关闭思考后不输出花括号格式的思想描述，导致 EoH 初始化阶段 thought 解析全部失败、CVRP 搜索终止。已修复 `llm4ad/method/_sampling.py` 的 `trim_braced_thought`（花括号缺失时 fallback 到 docstring），第一轮 CVRP 与第二轮全部 task 使用修复后代码正常完成。

## 5. 跨任务小结

- **两轮结果可复现**：同一方法两轮 best 与测试值接近，主要设置上方法排名稳定——EoH 在 TSP、ReEvo 在 CVRP 两轮均列五方法最佳；OBP 上 ReEvo 与 CALM 各占数档。
- **五方法排名因模型而异**：TSP 上 EoH 在 v4flash 下最佳（Qwen 下排第 3）；CVRP 上 ReEvo 在 v4flash 下最佳且优于其 Qwen 表现（Qwen 下 MCTS-AHD 最佳）；OP 两轮均值由 MCTS-AHD 在 OP100/200 领先（单轮波动大，CALM 第一轮三档全胜、第二轮 OP200 转弱）。模型选择会改变方法间相对优劣。
- **v4flash 与 Qwen3.6-27B 总体接近**：多数设置两轮均值落在 Qwen 三次运行 ±std 附近。最稳定的例外是 **CVRP**：MCTS-AHD/PathWise/CALM 在 v4flash 下差 Qwen 约 3–5%（超 Qwen 运行间波动）；TSP 上 EoH v4flash 略优于 Qwen；OP 上 MCTS-AHD v4flash 的 OP200 略优。v4flash 在 CVRP 这类 ACO 嵌入任务上相对弱，在构造类任务上与 Qwen 相当。
- **CALM（w/o GRPO）搜索效率高**：以 113–182 eval 达到与其他方法 1000 eval 可比的测试性能，OBP 跨规模多档五方法最佳。但这可能部分源于其 archive/profile 去重使有效探索集中在早期，不等价于在完整 1000 eval 下的表现。
- **限制**：v4flash 为 2 次运行、Qwen 为 3 次；以上排序与差距为描述性统计，不构成显著性检验。
