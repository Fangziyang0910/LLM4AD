# 生成上下文的经验得失

当前整体认识见[研究认识](研究认识.md)，预算分配的经验见[预算分配](预算分配经验.md)，历代 Prompt 的事实索引见[历史 Prompt 素材库](../analysis/TraceAAD历史Prompt素材库.md)。本文只沿「一次生成时，什么信息能帮助当前程序做出更好的算法设计决策」这条线总结。

## 1. 核心判断

TraceAAD 的终局不由预算分配单独决定，而由分配策略 $\mu$ 与生成策略 $K_\phi$ 共同决定。分配策略选择下一次机会给哪个节点和设计行为；上下文、算子指令和输出契约共同决定这次机会能产生什么。

$$
a_t=(n_t,o_t,r_t)\sim\mu(\cdot\mid\mathcal H_t),
$$

$$
(i_{t+1},P_{t+1})
\sim
K_\phi\!\left(\cdot\mid C(\mathcal H_t,n_t,o_t,r_t)\right).
$$

$n_t$ 是父节点，$o_t$ 是设计行为，$r_t$ 是 Fuse 才需要的 donor；$C$ 把完整搜索事实投影成本次决策可用的上下文。LLM 在这一步生成新的 `Idea + Code`，不是在一组显式的 continue / repair / backtrack / abandon 动作中选一个。

现有证据最牢固的结论是：**与当前节点匹配的形成来时路和明确的设计行为，能系统改变单步 proposal distribution。** 这不等于「Prompt 比预算分配更重要」，也不等于某个 Prompt 已被证明能提升完整搜索和 held-out 结果。

## 2. 上下文不是搜索档案

搜索树和事件日志应保存完整事实：代码、父子关系、声明的 Idea、实际修改、有效性、fitness 和发生顺序。生成上下文则是针对当前决策的有损压缩，不应默认暴露全部档案。

$$
完整事实\;\mathcal H_t
\xrightarrow{\;C(\cdot,n,o,r)\;}
与本次设计决策相关的证据。
$$

上下文的目标不是 information completeness，而是 decision relevance。增加信息只有在对决策的边际价值大于 attention dilution、anchoring 和 over-steering 时才值得。

## 3. 已经留下的硬经验

### 3.1 与当前节点匹配的形成来时路有单步价值

三轮固定锚点实验共完成 1,512 次生成；第三轮为 4 任务、72 个锚点、648 次生成。在当前代码之上加入父代形成来时路后，四任务配对质量变化的区间均为正，72 个锚点中 58 个方向更好、14 个更差，极端大幅改写同时减少。再加入该节点已有的直接子代尝试，没有稳定额外收益。

因此，轨迹目前最可靠的作用不是被压成节点未来价值，而是作为当前修改的 generation evidence。但在完整 1,000-eval 搜索中，parent path 相对 code-only 的净贡献随任务和 seed 变化；单步 proposal 改善不会自动变成搜索终局改善。见[V1–V9.6 机制诊断](../analysis/机制分析/TraceAAD-V1-V9.6机制诊断.md)和[父代来时路完整搜索](../experiments/机制实验/2026-08-21-父代来时路完整搜索/结果.md)。

### 3.2 算子是设计行为，不是装饰性标签

V10.1 在同一父节点上分别生成 Refine、Pivot 和 Fuse 子代。五个任务的任务内汇总中，Refine 严格改善率为 4.6%–16.3%，Pivot 为 0.5%–2.4%，Fuse 为 16.2%–40.9%；Pivot 在 TSP、CVRP、OP 和 VRPTW 的中位相对退化为 27%–76%。三种文字协议对应不同的有效性、改写幅度、即时质量和尾部风险。

Pivot 的低平均收益不等于它没有价值。部分胜者路线依靠少数早期 Pivot 或等效大步 Refine 完成结构跳变，再由 Fuse / Refine 兑现。这说明不同算子不应统一优化「下一步 $\Delta q$ 最大」。见[V10.1 预算流向与兑现分析](../experiments/机制实验/2026-09-02-TraceAAD-V10.1正式实验/预算流向与兑现分析.md)。

### 3.3 更多信息不等于更好的生成

已有直接子代尝试没有在父代来时路之上显示稳定增益。V9.13 的全局机制簇和前沿表能降低亚前沿重入，却在 CVRP 诱发过度结构改写，使有效率下降 7.4 个百分点。这类信息有可用信号，但它的提示价值与过度引导风险不可混为一个「信息越多越好」的结论。见[V9.13 机制诊断](../analysis/机制分析/TraceAAD-V9.13机制诊断.md)。

控制器可以读取 behavior distance、novelty、UCB 或区域统计，但 Generator 只应获得对本次修改必要的语义摘要。「控制器可以复杂，Generator context 应简单」是当前的默认原则，不是禁止日后用配对实验证明某个新信息块。

### 3.4 Prompt 成分的效应依赖任务、状态和算子

V10.1/V10.2 配对识别完成了 60 个固定 Fuse 状态的 300 次生成和 20 个 Init block 的 40 次生成。Implementation Principle、去注释、Fuse instruction 和其余标签/输出契约都能改变 proposal，但方向随任务变化，有些均值又主要由少数尾部样本驱动。因此，该实验支持「文本条件会改变 proposal kernel」，不支持某个 V10.2 成分跨任务统一更好。见[V10.1/V10.2 提示与上下文配对结果](../experiments/机制实验/2026-09-03-V10提示上下文配对识别/结果.md)。

## 4. 当前默认的生成上下文

当前默认的最小主干是：

1. **Task Contract**：问题、可编辑接口、合法性约束和优化方向。
2. **Current Code + Current Fitness**：当前实现和它已兑现的质量。
3. **Matched Formation Path**：与当前节点严格匹配的近期来时路，记录 `Idea / Result / Fitness`，默认最多 8 代。
4. **Operator Intent**：明确且相互区分的设计行为。
5. **Output Contract**：一个新的 Idea 和一份完整、可评价的 Code。

上下文应与算子条件化，不是所有行为共享同一份信息：

| 设计行为 | 与当前设计的关系 | 主要质量目标 | 额外上下文 |
| --- | --- | --- | --- |
| Refine | 接受当前核心思想，继续开发或修正实现 | 提高稳定改善率，压低退化尾部 | 无 |
| Pivot | 否定或替换当前核心思想 | 产生真正不同、有效且可继续开发的结构 | 无 |
| Fuse | 保留 target 中有用的核心，迁移 donor 的一个互补机制 | 形成真正的互补合成，而非复制或回归 donor | donor 的 Idea、Fitness 和 Code |

对 Pivot 而言，允许即时退化不等于不考核有效性和尾部风险。V10.1 中大幅退化的 Pivot 几乎没有获得后续机会或延迟兑现；当前更需要改善的是 Pivot proposal 本身，不是预先为所有低质量 Pivot 绑定开发预算。

## 5. 值得检验、但尚未确立的上下文成分

### 5.1 Current Core Design

建议用一句话显式表达当前程序的核心算法假设，使 Refine 知道什么要保留，Pivot 知道什么要替换。它应描述当前机制，而不只是「上一步做了什么」。这是设计假设，尚无独立消融。

### 5.2 Actual Change

`Idea` 是模型声称的设计意图，`Actual Change` 是父子代码间真实发生的修改。用简短且确定的差异摘要补足 `Idea / Result / Fitness`，有望帮助模型区分「思想不行」与「本次实现没有兑现思想」。既有 parent-path 实验没有独立拆出 Actual Change 的贡献，它暂不作为统一默认项。

### 5.3 Selective Modification

V10.2 要求新机制不得默认叠加到旧机制上；重复或冲突时应 replace、simplify 或 remove。它处理的是 mechanism accumulation，不是单纯限制代码长度。V10.1 的 CVRP 曾因适应度奖励和生成许可共同驱动机制堆叠，导致两段 29–31k 字符代码的 Fuse 请求超限。该原则针对了真实生成失败，但 V10.1/V10.2 配对结果尚未显示稳定跨任务收益。

## 6. 默认不进入 Prompt 的信息

在没有新的配对证据前，以下信息作为搜索事实或控制器状态保存，不进入默认生成上下文：

- $P/U/T$、ESS、UCB、选择概率等控制器内部数值；
- 全局机制簇表、完整 frontier table 和无关分支历史；
- 当前节点的所有已有子代尝试和失败代码全文；
- 原始 behavior distance 和大量行为统计；
- Fuse donor 的完整形成历史；
- 只为「让模型多想」而增加的独立 planning / analysis 调用。

这不是认定这些信息永久无用，而是要求每个新信息块独立证明它改善了哪一种算子、哪一类状态上的 proposal。

## 7. 实验路径

上下文研究应先固定 task、parent、formation path、operator、donor、模型、采样参数和 evaluator，只替换一个 Prompt 信息块或表达协议。直接测量：

1. valid / invalid rate；
2. unconditional improvement rate 和 $\Delta q$ 分布；
3. severe degradation tail；
4. 代码改写幅度与输出成本；
5. 是否真正执行 Refine / Pivot / Fuse 的设计语义。

固定锚点首先识别 $K_\phi$ 是否变化。只有某个成分在相关任务和算子上显示稳定 proposal-level 改善后，才值得进入同预算完整搜索；完整搜索再回答这种改善能否与 $\mu$ 形成良性交互，held-out 评价最后回答是否改善泛化。

```text
Prompt 成分改变
    -> 单步 proposal 行为改变
    -> 同预算搜索路径改变
    -> 训练集终局改变
    -> held-out 泛化改变
```

目前的[历史 Prompt 范式固定状态重放](../experiments/机制实验/2026-09-04-历史Prompt范式固定状态重放/实验设计.md)已按这一路径将历史版本收缩为七类可配对范式。它比继续用整版 1,000-eval 结果倒推 Prompt 优劣更直接。

## 8. 一句话

轨迹的首要价值是将「这份程序怎样形成」压缩成与当前节点和设计行为匹配的生成证据；上下文研究要回答的是，**哪些最小而关键的历史事实，以什么设计行为被利用，才能让下一个 `Idea + Code` 更好。**
