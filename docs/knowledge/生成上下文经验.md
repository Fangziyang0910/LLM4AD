# 生成上下文经验：已尝试模式、实证观察与适用代价

> **文档职责**
>
> 本文系统总结 TraceAAD 在生成上下文与算子设计上已尝试的模式、实证观察、适用条件和潜在代价。
> 全局科研定位与系统抽象参见 [研究认识](研究认识.md)；预算分配层面的权衡参见 [预算分配经验](预算分配经验.md)；历代 Prompt 演进细节参见 [提示词索引](../prompts/README.md)。

## 1. 核心定位：决策相关性而非信息完备性

在 TraceAAD 闭环中，生成核由上下文与设计意图联合调控：

$$(i_{t+1}, P_{t+1}) \sim K_\phi\left(\cdot \mid C(H_t, n_t, o_t, r_t)\right)$$

其中 $n_t$ 为父节点，$o_t$ 为设计行为，$r_t$ 为参照/donor 节点；映射 $C$ 将完整的搜索历史档案有损投影为针对当前决策的上下文。

**关键原则**：
- **上下文不是搜索档案**：搜索树日志应完整保留所有历史事实（代码、评分、报错、父子演化链）；而生成上下文是面向当前设计决策的精炼提炼，绝不应默认暴露全部历史；
- **边际收益与认知代价权衡**：向模型增加信息只有在其带来的边际决策价值大于**注意力稀释（Attention Dilution）**、**思维锚定（Anchoring）**与**过度引导（Over-steering）**的代价时才成立。

## 2. 已尝试的上下文成分与实证观察

### 2.1 形成来时路（Parent-Path）
- **尝试做法**：在当前算法代码之上，注入其父代的演化链路（按顺序呈现 `Idea / Result / Fitness`，默认最多 8 代）；
- **实证观察**：三轮固定锚点实验（共 1,512 次生成，第三轮覆盖 4 任务、72 锚点、648 生成）显示，配对增益区间全部为正，72 个锚点中 58 个表现更优。其最主要效果是**显著压低灾难性偏离，减少完全无效的代码崩溃与大幅失真**；
- **适用条件与代价**：适用于局部延续性开发；但在完整 1,000-eval 搜索中，parent-path 相对 code-only 的净收益随任务与随机种子波动，单步提议改善不会无条件转化为搜索终局改善。

### 2.2 直接子代尝试与全局机制表
- **尝试做法**：在父代来时路之上，进一步提供该父节点以往已尝试失败的直接子代代码片段，或在提示中展示全局机制簇表与帕累托前沿表；
- **实证观察**：
  - 增加直接子代尝试并未观察到稳定的额外增益，反而容易诱发无意义的局部细节规避；
  - 在 V9.13 中展示全局机制标签表虽一定程度降低了亚前沿重入，但在 CVRP 上引发了过度结构重构，导致有效率下降 7.4 个百分点（触发安全中止协议）；
- **代价总结**：负经验与全局状态若缺乏精确对齐，极易引发模型在上下文冲突下的防御性过度修补。

### 2.3 提示词成分微调（Principle / Comments / Contracts）
- **尝试做法**：在提示中加入实现原则说明（Implementation Principle）、强制去除历史代码注释、或调整接口输出契约；
- **实证观察**：V10.1/V10.2 配对识别实验（60 个固定 Fuse 状态与 20 个 Init 状态）表明，这些提示成分均能显著改变生成的分布形态，但影响方向强依赖于任务与模型状态，且部分均值由少数极端样本驱动；
- **代价总结**：不存在跨任务无条件普适的“魔法提示词”，文本微调的作用本质上是调整局部先验，不能替代算法逻辑的合理组织。

## 3. 算子模式、意图引导与评价边界

### 3.1 三类核心设计行为的意图定位
算子是指导模型在当前状态下开展具体算法设计的意图定向，当前系统确立的三类主要设计行为如下：

| 设计行为 | 意图定位 | 期望改变的行为特征 | 额外上下文需求 | 主要风险与潜在代价 |
| :--- | :--- | :--- | :--- | :--- |
| **Refine** | 针对当前程序做局部修正、参数调优或渐进扩展 | 提高稳定改进率，压低退化尾部风险 | 无（仅当前父代来时路） | 容易过早陷入局部骨架锁定，缺乏跳出能力 |
| **Pivot** | 尝试跳出既有模式，探索替代性算法机理 | 产生具有差异且可执行、有开发价值的新结构 | 无（要求明确反思来时路的局限） | 即时有效率低，易引发语法崩溃或大幅性能退化 |
| **Fuse** | 尝试借鉴或结合另一算法（donor）的有益机制 | 寻求不同算法机制结合带来的互补增益 | donor 的 Idea、Fitness 与 Code | 易退化为单亲复刻或机制简单拼接，破坏代码紧凑性 |

### 3.2 破除“算子固有优劣排名”的误区
在 V10.1 等实验中曾观察到：Refine 严格改善率为 4.6%–16.3%，Pivot 为 0.5%–2.4%，Fuse 为 16.2%–40.9%，且 Pivot 在多项任务中呈现 27%–76% 的即时相对退化。

**科学边界界定**：
- **命中率不等于算子内在优劣**：算子的超父率与改写幅度高度依赖于**选父分布**、**父代成熟度**与**任务适应度景观**。若给某个算子分配了已被深度开发的成熟节点，其改进难度自然增大；
- **低即时收益不等于无探索价值**：Pivot 的低平均收益符合其“探索性跳变”的职能设定。历史优质演化路线中，多次出现依靠早期 Pivot（或大步 Refine）实现结构跳变、后续再由 Fuse/Refine 兑现收益的模式；
- 严禁脱离状态将算子按命中率做静态高下排序，不同算子承担不同的探索与利用职能。

### 3.3 Fuse 算子的多维辨析：任务收益与机制合成
在分析交叉/融合类算子时，必须严格解耦以下三个评价维度，避免以形式上的“纯洁性”反向惩罚优化进展：
1. **任务收益（Task Gain）**：新代码在验证集上的实际得分改善；
2. **超越最优父代的增益（Gain over Best Parent）**：新候选是否超越了参与融合的 target 与 donor 中的较优者；
3. **实际机制合成（Mechanistic Synthesis）**：新代码是真正融合了两者的互补机制，还是主要复刻了强势 donor，抑或退化为单亲改写。

**原则**：改善父代不等于机制合成成功；但若模型通过合理吸收或重组 donor 的成熟代码为后续搜索打开了空间，同样具有实际价值，不宜单纯因为缺乏教科书式的“机制杂交”就予以否定。

### 3.4 提示模式的历史反思：硬契约与软指引
历史版本（如 V10 早期）曾尝试强硬的算子身份契约（例如强令“Refine 绝不得改变算法核心假设”、“Pivot 必须大幅重写”）：
- **观察到的代价**：当算法本身面临瓶颈时，硬性限制往往迫使模型强行拼接冗余代码或生成怪异结构以应付格式要求，破坏了代码本身的简洁性与可执行性；
- **当前遵循的准则**：**“任务契约为硬约束，设计意图为软指引”**。接口规范、数据流合法性与执行边界必须绝对遵守；而算子意图是帮助模型聚焦视角的语义提示，不应设置死板的惩罚逻辑。

## 4. 默认生成上下文的最小骨架

基于上述实证与代价分析，当前推荐的默认生成上下文保持精炼结构：

1. **Task Contract**：问题描述、可编辑函数接口契约、输入输出类型与优化方向；
2. **Current Code + Current Fitness**：当前基底程序的完整代码与已兑现的客观得分；
3. **Matched Formation Path**：与当前节点严格匹配的近期形成来时路（记录 `Idea / Result / Fitness`，默认最多 8 代）；
4. **Operator Intent Directive**：根据当前动作类型给出的差异化设计意图指引；
5. **Output Contract**：要求输出一份简洁的 Idea 陈述与完整、可独立评测的代码。

**默认不暴露给生成模型的信息**：
- 控制器内部统计值（$P/U/T$、ESS、UCB 标量、历史抽取概率等）；
- 全局机制簇表、全量前沿表及无关分支的演化树；
- 当前节点所有尝试过的失败代码全文；
- 原始行为距离矩阵与大规模特征统计；
- Fuse donor 的完整演化历史链条（仅暴露 donor 本身的代码与核心思路）。

## 5. 实验验证路径与不确定性原则

对生成上下文与提示机制的改进，应坚持**以最低证据成本回答最关键的不确定性**：

```text
Prompt / 上下文成分变动
    ↓  【单步配对实验 (Fixed-anchor)】：检验有效率、Δq 分布、代码改写幅度、退化尾部
生成分布 (Proposal Kernel) 发生预期改变
    ↓  【全预算在线搜索 (Full-budget Search)】：检验与分配策略结合后的长程动态累积表现
训练集终局与搜索效率改善
    ↓  【未见实例盲测 (Held-out Evaluation)】：检验跨规模、跨分布的真实泛化能力
确立为稳健有效机制
```

不盲目将每一处局部提示调整直接推入昂贵的全量消融，也不以单纯的单步方差收窄草率替代全预算搜索验证。机理分析采用单步配对识别，系统评价采用匹配预算搜索，两者分工明确。
