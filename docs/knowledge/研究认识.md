# 自动算法设计

试过的机制见[机制尝试](TraceAAD机制尝试.md)。预算分配沿价值对象这条线的经验见[预算分配](预算分配经验.md)。

## 1. 任务对象

自动算法设计用大语言模型提出并改写算法函数，再与进化机制结合，在有限评价预算下优化该函数，使其能够求解一类问题。

待优化对象是程序模板中的算法函数 $r$。模板将它装入完整程序 $P_r=K[r]$；evaluator 在实例上运行 $P_r$，返回该函数的质量。单个实例上的解只是评价这个函数的观测。

一个可交给 LLM 自动设计的任务包含三部分：

1. **问题描述 $d_{\mathcal T}$**：要解决的问题、输入与输出、有效结果的条件和评价方向。
2. **程序模板与可编辑部分 $K$**：可运行骨架，标明允许修改的函数或代码块。
3. **evaluator $\mathcal E$**：组装并运行完整程序，检查是否有效，返回可比较的分数。

$$
\mathcal T_{\mathrm{AD}}=(d_{\mathcal T},K,\mathcal E),\qquad
P_r=K[r],\qquad
q(r)=\mathcal E(P_r;S_{\mathrm{train}}).
$$

可编辑范围由任务决定。初始实现只需能够运行，随后由 LLM 与进化机制共同改进。

在线装箱是一个例子。模板固定物品到达和放置流程，只开放 `priority(item, bins) -> scores`。evaluator 在物品序列上运行完整装箱程序并按平均箱数评分。设计对象是这个优先级函数：它对一类物品序列都要给出装箱决策。

算法优势来自对目标问题结构的利用。自动算法设计要降低的，是面向特定问题类做这种设计的成本。

优化在训练集 $S_{\mathrm{train}}$ 上进行。测试集 $S_{\mathrm{test}}$ 是不同规模的新实例，不参与生成、评价、选择或停止判断。例如在 TSP50 上优化，再在 TSP100、TSP200 上测试。

## 2. 搜索循环

LLM 可以提出新的函数版本，但单次改写通常不够用。代表性方法把生成放进循环：

```text
选择父代与历史
    -> LLM 生成或修改算法函数
    -> 运行完整程序
    -> evaluator 评价
    -> 更新候选与历史
```

每一次 LLM 输出已经是一个完整的候选函数。进化机制选择父代、保留历史、分配有限评价预算，并用 evaluator 比较候选。这里的进化是广义的程序进化：种群、树或轨迹保存做过什么及其效果。

一次改写需要模型理解问题和当前函数，利用给定上下文，按本轮提示写出思路和完整代码。给哪个节点机会、提供什么上下文和提示，由进化机制确定。

evaluator 把能否运行、是否违反约束、性能如何变成可观察的事实。正式比较统一以真实 evaluator 调用次数计。

## 3. 两个基础问题

不同问题有各自的优势算法思想。LLM 对各思想的生成偏好不同，各思想的可改进程度也不同：有的可以持续改下去，有的不能。要做的是让 LLM 更好地生成对应当前任务的优势思想，并持续开发。目前还没有办法真正区分这些思想所属的算法簇。[待验证]

每一步搜索只做两件事：

1. **给哪一个节点下一个扩展机会**
2. **怎样帮它做出更好的决策**：给到合适、有价值的上下文与提示，用不同设计行为实现深挖、换向和融合

V10.1 按当前真实质量概率性选择父节点，再在同一冻结快照上分别执行 Refine、Pivot 和 Fuse。轨迹是辅助这三次生成的历史证据，不进入父节点分数。轨迹保存当前代码、父子关系、声明的 Idea、实际修改、有效性、评价结果和发生顺序。模型实际看到的只是从这些事实里抽出的有限上下文。同一份代码可以沿不同路径形成，因此代码相同不等于下一次改写条件相同。

V10.1 的方法定位是 trajectory-conditioned generation、quality-biased probabilistic tree search 与 multi-operator expansion。跨任务稳定的轨迹价值函数尚无可靠证据，因此轨迹负责辅助生成，已兑现质量负责父节点分配。

父节点分配与生成辅助在实验上分开看。固定节点识别轨迹与算子提示；固定三算子批次协议识别父节点分配。整体版本的终局只能评价整套系统。

## 4. 怎样帮它做出更好的决策

生成本质是给当前节点合适、有价值的上下文与提示。

**来时路有用，已有子代尝试没有稳定额外价值。** 三轮固定锚点共 1,512 次生成；第三轮 4 任务、72 锚点、648 次生成。加入父代改进来时路后，四任务配对质量变化的区间都不跨 0（58 个锚点更好、14 个更差），大幅改写也更少。在来时路之外再加入已有子代尝试，四任务区间都跨 0。因此默认上下文是：当前完整算法，加上与该节点匹配的父代改进来时路。已有子代尝试作为搜索事实保存，不放进默认提示。见V1–V9.6 机制诊断。完整搜索里来时路的净贡献随任务而变，见[父代来时路完整搜索](../experiments/机制实验/2026-08-21-父代来时路完整搜索/结果.md)。

失败代码进提示，实验上没有稳定增益。模型容易围着有缺陷的实现继续改。来时路提供这条函数已经怎么改过来的事实，帮助本轮聚焦。

**算子与探索、利用结合。** 一些算子应鼓励有效探索，一些算子应鼓励有效利用。历史版本使用过 Refine、Explore、ideate、synthesize 和 transfer 等提示协议。把不同路线的逻辑在提示里硬接在一起，容易把算法写坏。Refine 改得更小、即时质量更高；Explore 改动更大、即时质量更低，离线静态机制标签也切换得更勤。这些是提示诱导出的行为差异。来时路对 Refine 更稳，对 Explore 方向不稳定。见V9.8 机制诊断。V10.1 固定使用 Refine、Pivot 和 Fuse，三者的配对生成结果将提供其行为差异与价值的后续证据。

上下文应与当前节点和本次算子匹配。第一版 Refine 与 Explore 共享父代来时路。在 Explore 提示里展示其他方向的机制标签和前沿分数，单步质量有时上升，但在 CVRP 上有效率明显下降，版本按协议停止。见V9.13 机制诊断。

代码长度目前只作诊断。它与测试差距没有稳定关系（$r=0.05$），不进分数，只在完全同分时用来择简。

## 5. 给哪一个节点下一个扩展机会

分配的本质是选择下一个获得 Refine / Pivot / Fuse 扩展批次的父节点。V10.1 只用节点当前真实质量，通过 ESS 校准的 Boltzmann 分布抽样。高质量节点获得更高概率，其他有效节点保留非零概率。机制见[V10.1](../methods/TraceAAD-V10.1完整机制设计.md)，历史经验见[预算分配](预算分配经验.md)。

选中节点后，当前 Idea、Fitness、Code、父代来时路和 Fuse donor 全部冻结。Refine、Pivot 和 Fuse 在同一快照上独立生成 sibling，每个子代各占一次正式评价。整批结束后才把有效子代加入树并重新选择父节点。三次生成互不依赖，批次内没有前一个子代影响后一个子代的连续决策。完整批次是最小父节点分配单元，以逐评价重新选择的 option value 换取同一父节点上的配对算子覆盖。

完整单父树保留所有有效中间状态。退步状态不被删除，退步本身不加分；后代的已有突破不回传为祖先分数。轨迹保留并进入生成上下文，不进入父节点分数。

三个算子在同一父节点上的配对结果作为研究数据保存。固定 $1{:}1{:}1$ 覆盖的含义，是在尚无可靠条件算子价值估计时采用中性实验协议。当前搜索机制不根据这些结果在线调整算子份额。

## 6. 跨任务结果

正式比较用 Qwen3.6-27B、每次 1000 次真实评价、每任务 3 次独立搜索。主表 TraceAAD 为 V9、V9.16、V9.17。V9.16 对五个外部方法在 15 个测试设置上平均名次 1.900，VRPTW 三规模 1.333。V9.14 在 TSP 上更强，见[历史版本](../experiments/其他实验/历史版本.md)。完整版本同时改多个机制，终局只评价联合系统。数字见[主实验](../experiments/主实验/结果.md)。

1000 次评价只统一真实 evaluator 调用。模型调用数、token、墙钟是另一件事。

## 7. 证据分层

1. 机制规范：系统被设计成怎样运行；
2. 过程激活：机制是否真的改变了选择或提示；
3. 单步生成：固定节点时，历史或提示是否改变下一候选；
4. 完整搜索：统一预算下训练集最好结果是否改善；
5. 测试集：最终函数在不同规模新实例上的质量，以及搜索代价。

前一层不能替代后一层。三重复比较按实际均值差与方向记录。中期快照不能当终局裁决。

## 8. 还要回答什么

1. 怎样的上下文和提示，更能帮当前节点写出该任务的优势思想，并持续改下去。[待验证]
2. 只按当前真实质量概率性选择父节点，再固定覆盖 Refine、Pivot 和 Fuse，能否在不人工估计轨迹潜力的情况下实现有效搜索。[待验证]
3. 轨迹里哪些事实适合进提示，哪些只适合记在档案里。[待验证]
4. 搜索中形成的任务、上下文、修改、代码和评价，能否变成可学习信号，使模型内化算法改进模式。第一阶段固定 V9.19 搜索控制器，只学习给定轨迹状态与动作时的生成政策。见[轨迹条件 RL](轨迹条件RL.md)。[待验证]
5. Refine、Pivot 和 Fuse 是否形成可区分的 proposal distributions；完整三算子批次是否值得其放弃的逐评价重选机会。[待验证]
6. Pivot 产生的低初始质量新方向，能否在纯质量父节点分配下获得足够的后续成熟机会。[待验证]

## 9. 执行行为与停滞诊断

BehaveSim 的 PSTraj 与改进轨迹描述两个不同维度。改进轨迹记录候选怎样形成，用于组织生成上下文和过程分析；PSTraj 记录候选在固定问题探针上怎样逐步求解，用于判断执行行为是否重访或分散。AAD 中需要分开看设计意图、代码实现和实际执行策略：好的算法思想可能因内部参数、比较方向或状态更新写错而退化成另一种策略，不同代码也可能实现相近的求解过程。固定 probe 上的 BehaveSim 可以作为已实现算法思想的经验近似：相似度高支持把候选视为采用相近实际求解策略的工作假设，从而帮助识别实现失真、行为重访和真正的路线变化。它不能确认潜在设计意图或完整语义等价；有限 probe 上的行为邻域也不能直接命名为语义算法簇。

BehaveSim v3 在五个任务的已有搜索工件上完成了离线校正。它使用正式 evaluator 一致的状态更新、两组固定 probe、逐步 PSTraj、单步归一化编辑距离和 DTW。V9.16 的过程信号显示，OBP 的无突破精确行为重访约 27.7%，TSP 约 18.6%；OP 与 CVRP 均约 1.1%，VRPTW 约 5.8%。这些数字说明行为重访可以作为停滞候选信号，但仍需和质量突破联合读取。距离协议与离线校正见[校正结果](../experiments/机制实验/2026-08-26-BehaveSim行为度量校正/结果.md)。

低行为距离且没有质量突破时，可以暂时标记为重复停滞；高行为距离且没有突破时，表示行为改变但没有兑现，可能是无效探索。低距离仍可能是有效利用，高距离也不保证带来更好的候选。

V9.19 旧版把 BehaveSim v3 直接接入节点分数、区域欠开发、算子概率和交叉配对。停止时 15 路中只有 2 路完成 1,000 slots，因此没有正式终局比较；10,965 次普通决策已经提供在线过程证据。综合分数经常改变纯质量排序，但被选节点仍位于高质量、低欠开发区域；局部失败信号把 Explore 推到约 45%–50%；Structural Explore 行为步幅最大，严格改善率只有 1.5%–2.3%。同预算搜索只在 TSP 三次稳定占优，CVRP 相对版本而变，OP、OBP、VRPTW 均值退化。见[V9.19 旧版机制诊断](../analysis/机制分析/TraceAAD-V9.19旧版机制诊断.md)。

Behavior Crossover 在旧版中的整体严格改善率为 17.5%，并直接产生 OP 三次运行的当前 best；其子代到既有档案的最近距离通常接近或低于 Local Refine。现有证据把它识别为任务相关的行为条件迁移与重入。若要建立交叉贡献，需要在同一生成协议和真实预算下比较近行为父对、远行为父对、随机父对与无参考生成，并观察子代有效率、行为变化、质量突破和 held-out 结果。
