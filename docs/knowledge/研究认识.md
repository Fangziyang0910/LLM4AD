# 研究认识

本文记录 TraceAAD 研究中可跨版本复用的科学判断。具体问题见 [`research/`](../research/README.md)，方法见 [`methods/`](../methods/)，结果见 [`results/`](../results/README.md)。

## 算法改进是知识引导的渐进搜索

算法改进通常从一个已有方案出发，逐步引入思想、观察结果，再继续细化、回退、重组或换向。当前程序只是最终截面；它无法单独说明算法怎样形成、哪些机制已经验证、哪些方向失败，以及哪些思想仍值得发展。算法改进历史保存的正是这条“来时路”。

TraceAAD 因此把轨迹作为搜索个体和推理上下文。程序节点保存可执行状态，修改边保存一次算法决策及其真实结果，路径保存思想演化的先后关系。轨迹的核心作用是让下一步建立在已经发生的实验上，而不是每次从孤立代码重新猜测。

[LLM 优化器轨迹分析](../references/LLM优化器轨迹分析.md) 表明，优秀 LLM 进化算子的关键更接近持续、可靠的小步改进，而不是依赖少数大跨度跃迁。这里的“小步”是算法行为层面的受控变化：保留已验证结构，围绕明确弱点或新思想做可归因修改，再由真实评价决定是否继续。它不等于限制代码行数，也不排斥必要的新机制。

基础问题解决能力提供搜索潜力，长期优化能力还取决于变化能否持续转化为 best-so-far 推进。原始新颖性不能独立代表有效探索；搜索保持局部化时，新颖变化才更容易形成突破。局部精炼也不是基座模型单独固定的能力，模型、父代与历史上下文、提示策略、反馈和解码配置共同定义实际进化算子。

算法设计是困难且突破稀疏的任务，LLM 的生成又具有较大不确定性。一次退步、平台或重复不能直接证明某个方向应该被禁止；进化搜索需要在足够多的真实尝试中积累结果。搜索规则的职责是保存事实、分配有限预算和保证评价可靠，不是预先替 LLM 决定哪些变化必然正确。

## 轨迹保存什么

一条有用的算法改进轨迹至少包含：

- 决策前状态：任务、当前程序、祖先历史、搜索阶段和预算；
- 修改意图与实际行为：计划改什么，生成代码实际改了什么；
- 直接结果：有效性、fitness、错误、超时、复杂度和跨配置表现；
- 跨步骤关系：思想怎样被延续、修复、重组、回退或放弃。

程序、父子关系和 evaluator 结果是直接证据；模型写出的 Action、Idea 和失败解释只是声明。单次改善只能说明本次修改在当前条件下有效，不能自动升级为普遍因果规律。研究记录与提示词都应保持“事实—解释—待验证假设”的边界。

轨迹具有三类不同价值：

1. **成果价值**：这条路线当前得到了多好的程序；
2. **继续开发价值**：再投入预算是否可能产生进展；
3. **知识价值**：它是否保存了成功原则、失败边界或可迁移思想。

三类价值不应被一个标量完全替代。fitness 决定最终输出，简单的路线质量和 UCB 可以分配父代预算，直接轨迹内容可以为生成提供知识。路线进展、失败边界或长期贡献若要进入在线评分，必须先证明它们比简约基线更能提高最终算法质量。

## 局部来时路与跨轨迹参考

主轨迹说明当前程序怎样形成，是所有算子的共同依据，也是新节点唯一的结构 ancestry。双轨迹算子额外读取一条参考轨迹和参考程序，用于迁移或重组另一条路线的知识；参考只提供知识，不成为第二个结构父代。

共享全局经验是更高影响力的第三种视野。开发实验表明，缺少证据范围、fitness 方向校验和反证能力的自由文本总结，会把局部误判传播给所有路线并伤害搜索。这证明当时的设置有害，不证明全局经验天然无效。正式 V5 暂停在线共享经验，只保留主轨迹和本轮直接参考。若未来重新引入，全局结论必须可追溯、可降权、可被后续真实结果反证。

## 四个算子与种群进化

`ideate/refine` 沿主轨迹产生有方向的变化，`synthesize/transfer` 在主轨迹与参考轨迹之间重组或迁移知识。它们与变异、交叉具有底层亲缘性，但不能机械改写成普通遗传操作；真正传递的是算法思想、试错边界和当前程序结构。

双轨迹能力不自动产生有效多样性，代码差异也不能证明两条路线互补。当前证据不足以把“成熟”“互补”或短期算子命中率变成在线资格门槛。简约基线让可用算子保持等概率，把参考路线质量作为软采样偏好；阶段调度、差异门控和信用调度必须通过最终质量消融后再引入。

## 评分、选择与计算预算

轨迹评分与轨迹选择是两个层次。评分提供质量、走势和不确定性证据；父代扩展、参考选择、种群生存和最终输出是不同决策，不要求共享同一排序。

现有过程证据表明，父子局部改善的方向不能直接等价为长期繁殖价值。较差 endpoint 的回弹容易得到正趋势，却未必推进路线最好或全局前沿。提高这种趋势的权重可以增加局部 improve，同时降低优质父代比例和 global-best 更新。因此下一步应先用质量确定值得发展的区域，再用路线最好推进、后续贡献和访问不确定性分配区域内预算。

种群是有限的路线资源，派生图是完整的事实拓扑。路线退出 active frontier 只代表暂时不再繁殖，不应删除其历史事实。固定规模、延迟管理、global-best 保留、按质量随机生存和 UCB 已足以形成清楚基线；去重、差异 reserve、成熟层和多重信用只有在最终质量上显示独立增益时才值得加入。

## Action、Code 与有效搜索空间

Action 是算法决策，不是审计表单。复杂的结构化输出会让正常模型响应因格式问题失去评价机会，把接口负担错误地注入搜索。高频决策应使用最小自然语言契约，审计字段由系统根据代码和评价结果记录。

Action 与 Code 应共享本轮相关历史。尤其在双轨迹算子中，如果 Action 看到了参考程序，Code 却只拿到一句压缩建议，跨轨迹知识容易被不完整实现。完整上下文的作用是减少信息断层；现有证据不支持把重复代码简单归因于 Code 看到了相同上下文。

有效搜索空间由真正可执行、可评价的状态覆盖决定。代码文本不同不保证算法行为不同，同一程序也可能带着不同历史知识。代码哈希、相似度和唯一率适合诊断，不能未经验证就变成在线拒绝规则。模板 import、输入 dtype、输出 shape、finite 要求和 parser/validator 一致性属于系统契约，必须先保证，不能把接口故障解释为方法机制失败。

机制实验还必须区分三种状态：机制没有运行、机制运行但没有改善、机制运行后造成损害。接口测试只能确认第一层，最终分数只能评价整个系统；具体机制贡献仍需过程证据和受控对照。

## 程序复杂度

程序复杂度与 fitness 同样需要观察，但长度不是算法质量代理。V4 暴露了无边界增长会增加上下文和修改负担；固定长度惩罚或硬性拒绝长程序又会压制必要复杂化。

当前最小原则是 fitness first、完全同分时择简。任何严格更优程序都优先，只有 fitness 完全相同时才偏向非空 LOC 更少的实现。该规则仍会改变 compact best 和后续锚点，不能只当展示层处理；在离散评价面上的净效应需要单独验证。测试程序的选取也必须与方法内部比较规则一致。

## LLM 进化算子的底层认识

LLM 利用预训练得到的程序、算法和人类修改先验，对已有方案进行语义变化。[Evolution Through Large Models](https://arxiv.org/abs/2206.08896) 将其视为从人类程序修改分布中学到的智能变异；[Evolving Code with a Large Language Model](https://arxiv.org/abs/2401.07102) 指出具体变化行为隐含在模型、提示词和上下文中。因此提示词、父代、历史和反馈共同定义实际进化算子，它们不是外围接口。

[Behaviour Space Analysis of LLM-driven Meta-heuristic Discovery](https://arxiv.org/abs/2507.03605) 说明提示词会显著改变探索、利用、收敛与停滞行为；[Fitness Landscape of Large Language Model-Assisted Automated Algorithm Search](https://arxiv.org/abs/2504.19636) 说明不同算法任务的搜索地形具有不同的多峰和崎岖程度。由此不能期待同一轨迹深度、选择压力和多样性水平在所有 task 上产生相同行为。

[Language Model Crossover](https://arxiv.org/abs/2302.12170) 支持通过上下文进行语义层面的多父代关系归纳；这为双轨迹知识重组提供了依据，但不意味着代码拼接。[DeltaEvolve](https://arxiv.org/abs/2602.02919) 强调保存语义增量及其结果，与“来时路”主张一致。[When Can LLMs Actually Correct Their Own Mistakes?](https://aclanthology.org/2024.tacl-1.78/) 则提醒，自我修正通常需要可验证的外部反馈；模型总结不能未经验证就成为共享事实。

综合来看，可靠改进能力应先于偶发创新，优质局部区域内的互补多样性应先于全局漂移，真实 action–result 对应应先于高层总结。这三点构成后续机制迭代的主要约束。

## 实验结论的边界

训练最好、held-out 泛化和搜索过程是三类证据。最终分数不能解释具体机制，局部 improve 也不能替代 global-best 推进；应同时报告三次重复均值与下限、后半程更新、路线推进、有效候选、复杂度和测试表现。

自定义 task 协议不要求逐项复制某篇论文，但必须预先固定训练域、保持训练与测试独立，并让比较方法共享同一数据、评价器、模型条件和结果选择规则。不同原生预算回答的是各方法按自身设计运行时的整体表现；共同预算截面可以补充样本效率分析，但不应事后改变主协议。

正式 V5 的四任务实验表明，轨迹种群和双轨迹直接参考能够形成有效搜索，但尚未在所有任务上稳定超过 V4 或 MCTS-AHD。当前最重要的问题不是继续增加记忆、资格门槛和控制器，而是在简约、可复现的搜索骨架上确认轨迹历史能否稳定帮助 LLM 得到更好的算法。
