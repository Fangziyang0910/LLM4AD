# 研究认识

本文记录 TraceAAD 研究中可跨版本复用的科学判断，并把当前版本的观察单独列出。具体问题见 `docs/research/`，方法见 `docs/methods/`，结果见 `docs/experiments/`。

## 一、跨版本可复用原则

### 1. 算法改进需要历史

算法改进通常从已有方案出发，逐步生成新的 Idea + Code 并观察结果。最终程序只是过程的一个截面，单独看它无法说明算法怎样形成、之前做过什么以及每次尝试的效果。算法改进历史保存了这条“来时路”。

TraceAAD 将轨迹同时作为下一次生成的证据和有限搜索预算的分配对象。程序节点保存可执行状态，生成边保存一次 Idea + Code 及其真实结果，路径保存生成序列的先后关系。这样，下一次生成可以建立在已经发生的实验上，而不必每次从孤立代码重新猜测。

**来时路作为生成上下文的价值已有直接证据。** 固定锚点三臂单步实验（`code_only` /
`+来时路` / `+来时路+子代`，四任务 72 锚点 648 次生成，
[实验页](../experiments/TraceAAD-固定锚点单步生成识别实验.md)）给出核心命题目前
最干净的支持：加入父代改进来时路后，四个任务的配对 conditional Δq 区间全部不跨 0
（72 锚点 58 好 14 差）。当前代码没有完整包含下一步设计所需的信息，形成过程提供了
额外且有用的决策信息。它的作用方式不能简化为"提高 improve rate"——OP/OBP 的
improve 几乎未变，但四任务中位 Δq 一致右移、最差十分位修改占比大幅下降
（TSP 16%→6%、CVRP 23%→4%、OP 16%→8%），同时修改幅度收缩。即来时路让下一步修改
更贴合当前设计状态、减少灾难性偏离；单步层面收缩与质量改善同向发生，"改得小"本身
不是代价。在来时路之外追加已有子代尝试没有稳定额外价值（四任务区间全部跨 0，方向
35 好 / 34 差 / 3 平，TSP/CVRP 偏负）：来时路回答"为什么当前算法是这样的"，普遍有
用；子代回答"从这里已经试过什么"，只是特殊重访场景下可能有用的补充，未证明值得
常驻上下文。历史上下文机制据此收口为**当前算法 + 父代改进来时路**，不再迭代条数、
配额与子代排序。V9.7 把这一收口写进默认生成上下文：Direct Attempts 仍作为搜索事实
记录，但不进入模型 prompt。[待验证] 两个遗留问题：收缩是否在完整搜索的多步探索分布上仍有代价
（单步均值改善不排除多步多样性损失）；子代丰富（多次重访、≥3 条）场景是否另有结论
（三臂实验的锚点子代多为 1 条）。

### 1.1 单步生成与持续搜索

TraceAAD 有两个相互连接但需要分开分析的部分：

1. **上下文引导的单步生成**：给定当前程序及其来时路，LLM 生成下一次的 `Idea + Code`。这一部分回答的是：当前上下文能否帮助 LLM 产生更好的下一次算法生成。
2. **搜索机制引导的持续过程**：搜索机制从已有程序中选择下一次生成的起点，并分配有限的评价预算。它不替代 LLM 生成 Idea + Code，而是决定后续会访问哪些程序、形成哪些上下文以及生成过程如何持续展开。

完整循环是：

```text
搜索机制选择当前起点
    -> 构造当前程序及其来时路
    -> LLM 生成 Idea + Code
    -> evaluator 评价
    -> 新程序加入搜索空间
    -> 搜索机制选择下一次起点
```

这一区分用于定位机制问题：当前程序到下一次生成的质量主要反映上下文与单步生成能力；起点覆盖、预算集中和多轮推进主要反映搜索机制。最终方法效果由两部分共同形成，不能用其中一部分的结果替代另一部分。

因此 TraceAAD 的核心主张实际上包含两个需要分开识别的假设：在当前代码不变时，与它真实匹配的历史能否改善下一步生成；在生成协议不变时，使用轨迹证据分配预算能否优于只看终点个体。一个联合版本的最终分数不能单独证明任一假设。

搜索机制分配生成机会，LLM 决定机会能否转化成有效修改与最终突破。相同或相近的选择形态仍可能因初始路线、上下文和随机生成而产生不同结果；这种方差属于联合搜索系统，不能在缺少受控证据时全部归因于预算公式，也不能据此直接增加 critic、planner 或 operator。机制诊断应分别检查“是否改变了机会分布”和“机会是否被生成器兑现”。

[What Makes an LLM a Good Optimizer?](../../../papers/What_Makes_an_LLM_a_Good_Optimizer_Trajectory_Analysis/) 的结论：优秀 LLM 进化算子更接近持续、可靠的小步改进而非少数大跨度跃迁（"小步"指算法行为上的受控变化，不等于限制代码行数）；新颖性只有在搜索保持局部化的条件下才提高突破概率；局部精炼能力由模型、父代与历史上下文、提示策略、反馈和解码配置共同定义，不是基座模型单独固定的属性。基础问题解决能力提供搜索潜力，长期优化能力还取决于变化能否持续转化为 best-so-far 推进。

算法设计困难，突破稀疏，LLM 生成也具有较大不确定性。因此，一次退步、平台或重复不足以据此禁止某个方向。进化搜索需要通过足够多的真实尝试积累结果。搜索规则应保存事实、分配有限预算并保证评价可靠，将哪些变化必然正确预先写入规则则缺少依据。

### 2. 轨迹是以可执行程序为锚点的证据视图

一条用于下一步决策的轨迹，应当以一个真实可执行的代码节点为锚点。锚点的完整代码和 fitness 定义了下一步实际从哪里出发；上溯历史说明它经过哪些 Idea 和结果形成；从该锚点出发已测试的子代或短程后续则说明附近哪些方向已经尝试。下游可能分叉，所以决策上下文常常是一个“锚点化的局部证据窗口”，而不是从根到叶的一条完整直线。

受上下文容量限制，当前完整代码应优先保留，历史程序可压缩为有序的 `Idea + 结果`、有效性、fitness 变化和简短代码变化摘要。这样的轨迹能告诉模型“尝试过什么，当时发生了什么”，不能告诉它“哪个 Idea 或哪行代码必然造成该结果”。Idea 可能方向正确但实现不充分，也可能与实际代码不符、参数未调好或只是受评价噪声影响。因此 Idea—结果是有限条件下的弱证据，不是细粒度因果标签。

Idea—Code 一致性是轨迹证据的构念有效性前提。提示要求 Idea 概括实际代码，并不能证明二者真的一致；若 Idea 错误描述了实现，后续模型读取的就是“失真的思想说明 + 真实分数”。因此轨迹机制表现不佳可能来自历史本身无帮助，也可能来自历史表达失真。在否定轨迹价值前，应使用实际父子代码审计 Idea—Code 对齐；即使二者对齐，也只能确认本次声明与改动相符，不能据此获得行级因果归因。

轨迹具有四类相互关联但不可互相替代的用途：

1. **事实记录**：保存程序、生成关系和 evaluator 结果；
2. **生成上下文**：帮助模型避免无信息重复，延续、细化或重新组织已有思想；
3. **预算证据**：判断从这个锚点及其历史出发，再投入一次评价的边际价值；
4. **研究证据**：还原算法怎样通过多步尝试形成。

轨迹窗口的“最优”应表示在固定上下文预算下对当前决策最有信息，不是事后挑出分数最高的子路径。只展示最佳后代会隐去失败次数并制造幸存者偏差。近期窗口、关键事件窗口、上溯与下游混合窗口应作为不同可验证方案，选择规则需预先固定并显式告知模型哪些历史被省略。

历史事实更精细，不等于模型得到的可用信息更多。上下文的有效性同时取决于信息是否与当前
修改相关、表达是否突出语义重点，以及它相对当前代码和核心指令占用多少注意力。完整 actual diff
可以提高事实忠实度，也可能用大量低层代码细节淹没 Idea 与 outcome；反过来，短摘要更易读取，
却可能丢失真实实现。固定 anchor 的配对实验已经证实这一点：简洁 `Idea + outcome` 有单步价值，
紧凑实际改动摘要有额外信息，而 V9.5 的整段压平 diff 反而以 3 倍 token 换来更低的可读性
（[RQ-009](../research/RQ-009-锚点历史上下文.md)）。不能以 token 越多或事实越完整直接推断上下文更好。

### 3. 局部来时路与跨轨迹知识

主轨迹说明当前程序怎样形成，是所有算子的共同依据，也是新节点唯一的结构 ancestry。双轨迹算子额外读取一条参考轨迹和参考程序，与当前上下文共同用于生成新的 Idea + Code；参考轨迹提供生成上下文，不构成第二个结构父代。

轨迹可以理解为全局搜索历史的局部浓缩视图：它在有限上下文内保持与当前代码的一致性，多个锚点则保留不同的局部视角。它无法完全替代全局拓扑，跨路线参考的作用是有限度地引入其他局部视角，而不是把整棵搜索树塞给模型。

共享全局经验提供了比局部轨迹更广的视野，也会影响所有路线。缺少证据范围、fitness 方向校验和反证能力的自由文本总结，可能把局部误判传播为全局偏置并伤害搜索。

V5 开发中出现了两类性质不同的失败：首轮因误判上下文容量（假设 131K，实际 32K）导致机制一次也未执行，只能说明机制没有运行；接口修复后摘要确实进入搜索，却出现 fitness 方向错误、把局部常数写成普遍规律和过早判断方向饱和，关闭摘要后多个任务的路线推进与后半程更新恢复。这三种状态——机制未运行、运行但无效、运行后有害——必须分开判断。

已有证据否定的是当时的实现方式，不是跨轨迹经验本身。V5 正式版起不再维护在线共享经验；V9-Core 只保留双轨迹算子的参考轨迹通道，V9.5 起该通道也被移除，当前版本没有任何跨路线知识流动，V9.7 将跨路线知识重组明确留作单独研究。[待验证] 若重新引入，共享经验单元至少需要标明证据来源与适用范围、由系统提供 fitness 方向、允许被后续结果降权或推翻、让路线直接证据优先于共享摘要，并保证调用与写回状态显式、失败批次不被静默消费。

### 4. 算子、种群与多样性

V4–V9 期间的算子族中，`ideate/refine` 基于主轨迹生成新的 Idea + Code，`synthesize/transfer` 同时参考主轨迹与另一条轨迹。它们与变异、交叉具有底层亲缘性，但不能机械改写成普通遗传操作，因为真正传递的是算法思想、之前的尝试及其结果。

双轨迹能力不会自动产生有效多样性，代码差异也不足以证明两条路线互补。V5 首轮同时保留多个轨迹身份，却出现 active endpoint 重复和可执行状态覆盖下降——形式上的多轨迹不等于有效多样性。

锚点分散、谱系分散和行为分散是三个不同层次。预算分给许多程序锚点时，这些锚点仍可能来自同一初始路线；保留多条初始谱系时，不同谱系也可能实现相同算法行为。精确锚点预算占比、初始路线预算占比和可执行行为差异应分别诊断，不能用其中一个替代另外两个。[待验证] 维持多条独立谱系是否改善最终质量，仍需与允许优质路线自然集中的对照比较，不能从谱系数量直接推出。

调度方面的证据同样不支持复杂控制器。V3 的 4,975 次算子选择表明，平均收益 UCB 会把分布推向 endpoint，但没有形成跨 task 稳定排序；四个算子的 best-update 命中率都在 3.1%–3.9% 之间，而调用上下文明显不同。backtrack 更多用于退步、平台或 endpoint 非最优的困难状态，其低均值不能解释为能力较差。单步 plateau 也不适合作为切换依据：五个 task 中 47%–68% 的 plateau 在后续 5 步内出现改善。这些数据只能证明调度改变了选择分布，未证明它提高了搜索质量。

因此简约基线不依据短期 plateau、LOC 增长、成熟度、路线相似度或历史命中率改变生成方式。V9-Core 沿用四算子等概率并明确不采用趋势、路线信用和概率控制器；V9.5 起生成收敛为单一自由指令；V9.7 改为与搜索状态无关的 Refine 0.7 / Explore 0.3 固定概率意图。这条脉络一以贯之：先提供无状态控制器的对照，状态依赖的调度在"意图 × 结局"证据积累并通过最终质量检验后再决定是否引入。[待验证]

[待验证] 轨迹形态可能与生成方式存在条件关系：稳定向好的局部历史可能适合继续细化，长期平台可能需要引入新原理，高波动可能需要约束修改幅度或增加重复验证。但同一形态可以来自任务地形、算子跳跃、Idea—Code 不符或 evaluator 分辨率，不能硬编码为确定性算子映射。真正需要积累的是“锚点轨迹 × 生成方式”的结果证据，而不是一个脱离上下文的全局算子平均分。

### 5. 评分、选择与预算是不同决策

轨迹事实与预算评分处于不同层次。水平、走势、波动和失败记录可以帮助模型理解局部过程，却不天然等于预算价值；锚点选择、生成上下文和最终输出也不必共享同一排序。

预算价值最终要回答一个前瞻性问题：在当前锚点、局部历史、生成方式和已有证据下，再分配一份 evaluator 预算的预期边际收益是什么。锚点 fitness 是必要依据，因为下一步仍从该代码实施；但它不能单独表达未来生产力。

有限预算优化的终局目标是预算结束时的最好程序，而不是下一代程序的平均质量。平均绝对子代质量只是这个终局目标的代理：一条路线可以稳定地产生较好但从不突破的程序，另一条路线也可能均值较低却具有更高的突破上限。由此不能直接推出应把波动、趋势或突破率加权进评分；首先需要验证候选代理与最终 best 的边际贡献是否一致，再决定是否需要表达上尾或多步价值。

[待验证] 对历史条件化的 LLM 搜索，程序代码本身未必提供充分的决策上下文：同一代码配上不同的 Idea—结果历史，可能诱导不同的下一步生成分布。“可执行代码锚点 + 规范局部证据窗口”因而是更完整的生成上下文。但窗口会随新事实更新，不应伪称为可重复抽样的精确 Markov 状态；上下文表达的精度也不等于信用粒度应无限提高。精确长窗口几乎不重复，会把有限结果切成稀疏单元。DGA²D 的受控消融中，first-order credit 优于 second-order 与 full-path，支持保留有限历史作为生成上下文、在可重复的锚点层聚合生成结果。窗口上游和下游的既有变化负责描述上下文，不能再次作为未来回报。

锚点聚合与精确窗口评分之间存在不可消除的粒度—稳定性矛盾：精确窗口信用更贴近当时上下文，却几乎没有重复样本；锚点信用可以积累，却把不同 `W_t(a)` 下产生的结果合在一起。后者只能解释为“随局部历史积累而持续经营该锚点的过程价值”，不能解释为固定状态下的精确 action value。[待验证] 早期窗口下的结果是否会在下游证据更新后变得陈旧，需要通过同一锚点不同窗口快照的受控生成检验，不能默认累计均值始终同分布。

轨迹形态至少有三个互补的描述角度：

- **水平**：均值或时序加权均值描述锚点附近通常处于什么质量区域；
- **趋势**：描述近期尝试是否持续将局部知识转化为改善；
- **波动**：描述结果是稳定可复现，还是具有高风险、高上限或高噪声。

三者都是证据而不是天然价值：正趋势可能只是差起点回弹，低波动可能是稳定精炼也可能是行为停滞，高波动可能产生突破也可能只是修改失控。证据数量、有效率、修改距离和不同生成方式的条件结果必须一起解释。在这些关系尚未被实验识别前，将它们线性加权为一个总分只会重新制造不稳定的代理目标。

“差节点多代之后产生超级个体”揭示了延迟价值，也要区分两种信用：该节点对已发生突破具有事后谱系价值，但这不等于现在重新从它出发具有最高预算价值。一条后代成功只证明该路线曾经达到突破，不证明这个差节点是因果上必要的，也不能忽略它获得了多少次后续尝试。合理做法是保留它的延迟后代证据、用于历史上下文和备选分支，再根据尚未验证的方向与已有证据数量判断是否重访，而不是将最佳后代分数无条件回传给全部祖先。

最终优秀 lineage 可以包含大量单步退步，因此要求 ancestry 每一步单调改善会排除真实可达的成功路径。最小而稳妥的处理是保留仍可执行的 regression state 及其真实结果，让选择器以后仍可访问；不能从事后位于成功 lineage，推出该节点在当时具有可识别的正信用。允许非单调搜索与奖励退步是两个不同设计。

Allocation 改变纯 fitness argmax 的比例只描述干预强度，不是优化目标。高 changed-rate 可以对应有效探索，也可以只是把预算移离当前最好程序；低 changed-rate 则可能来自合理利用，也可能说明 optimism 没有实际作用。预算机制最终应以共同 evaluator budget 下的 best-at-budget 判断，并通过固定 Evidence/Generation 的 `q(a)` 对 `q(a)+opportunity(a)` 消融识别净价值，不能按 changed-rate 反向调参。

V9.1 将这一认识落实为第一阶段基线：以锚点原始有向 fitness 前 10 划定质量候选区，再用每条轨迹自身的完整验证次数与“超过分配前路线历史最好”的次数估计路线推进成功率，信用只属于被验证轨迹，不沿派生树回传。它解决了全局 min–max 漂移和祖先 max-backup，但实验表明路线推进率会把低质量锚点的局部回弹当成成功，该信用被 V9.2 起放弃。

V9、旧 V9.1 与轨迹中心 V9.1 的过程数据共同确认：锚点绝对 fitness 和已测试直接子代的绝对质量比推进率更稳定地关联下一次生成质量；趋势、波动与改进比例的关系跨协议变号，只适合作为模型上下文与诊断事实，不适合预设通用在线权重。V9.2 据此改用绝对代码质量的经验生产力评分；V9.5 起进一步简化为"质量 + 乐观项"（`q + s/√(n+1)`），经验均值被放弃。

比较新锚点与成熟锚点时还存在证据年龄差异：新锚点从自身 fitness 初始化，成熟锚点则已经吸收普通退步或失败结果。每个高质量子代都可能以一个没有历史负担的新分数重新进入竞争，从而形成隐式的新锚点偏好，使许多锚点选择实际沿同一谱系持续推进——V9.3/V9.4 约 98.5% 的正式预算落在单一初始谱系正是该效应的表现。V9.7 的路线级分配是对它的第一个直接处理，但其正式批次已给出负过程结果：在 12,251 次决策中，route optimism 相对同状态纯质量选择只改变 32 次（0.26%），而同一 $s$ 在锚点层改变 60.6%。锚点的一步 bootstrap 尺度不能直接假定为路线竞争的有效尺度。

路线层的 **coverage** 与 **continuation value** 是两个问题。coverage 只要求为其他欠投入的初始来源保留少量机会；continuation value 要求预测哪条路线未来更可能产生终局突破。`best q + count bonus` 不能因为同时包含质量和次数就被解释为已经估计后者。若要先判断 coverage 是否有价值，显式固定的 route exploitation / coverage mixture 是比事后放大 $s$ 更直接的待验证基线；它不能伪称估计了路线潜力。[待验证]

无效生成的信用必须先说明效用语义。把无效结果记为锚点 fitness，表示事件后仍保留原有 incumbent；但若评分声称估计“产生有效新代码的能力”，同一次结果又代表消耗预算而没有产出。保留质量、有效子代质量和单位预算边际收益不能混为同一目标。评分公式应明确选择其中哪一个，并单独记录有效率；无效结果如何进入价值是待验证的机制选择，不能因缺少全局最差值而被静默定义。

将有效结果按 `max(锚点质量, 子代质量)` 结算只表达单步后的保留质量，无法表达“暂时退步的中间节点后来产生强后代”的有限多步价值。V9.4 曾以有限多步折扣信用（至多三层祖先按 `0.5^d [q(后代)-q(祖先)]+` 更新）表达它；实验结局是该信用运行但几乎不改变最高价值利用的实际选择（[版本谱系与实验事实](../analysis/TraceAAD-版本实验事实与机制诊断.md)的 V9.3/V9.4 节），V9.5 起放弃多步信用回传。延迟价值如何进入预算仍是开放问题。

[待验证] 失败节点不应成为可继续扩展的程序锚点，但其真实错误不能随锚点切换而消失。局部窗口保存与锚点相关的失败，任务内有界失败记忆则保存跨分支重复的解析器/evaluator 错误类型、精简消息和次数。两者都只能提供“哪种实现曾以何种方式失败”的外部事实，不能把失败归因为宽泛 Idea，也不能把无效代码重新放进模型上下文。

祖先信用若只改变数值、选择器却在基本验证后永远取最高分，则成功后代本身通常会压过收到折扣回传的祖先，信用很难真正改变预算流——V9.4 的折扣信用正落入此境。其 `4:1` 利用—覆盖规则只有主谱系内部的局部正信号；V9.5 起两者均被 `q + s/√(n+1)` 单公式取代。

种群是有限的路线资源，派生图则是完整的事实拓扑。路线退出 active frontier 只表示暂时停止繁殖，不应删除其历史事实。固定规模、延迟管理、global-best 保留、按质量随机生存和 UCB 已构成清楚的基线；去重、差异 reserve、成熟层和多重信用只有在最终质量上显示独立增益时才值得加入。[待验证]

派生树的 root、clade、depth 和 lineage 是生成来源与先后关系的事实，不是算法语义空间中的天然
类别。不同 root 可能收敛到相近代码或行为，同一 lineage 的相邻程序也可能发生大幅机制重构。
因此 clade budget share、root switching 和 lineage depth 可以用于还原 provenance，不能直接
解释为语义多样性、不同算法路线或 causal success mechanism。V9.7 的路线级分配沿用这一边界：
H1 只检验不同初始来源是否仍长期锁死，不把路线预算均衡读成算法多样性提高。需要语义结论时，应另行审计代码、
Idea 与行为，而不能让拓扑标签代替构念测量。

### 5.1 初始化决定轨迹搜索的边界条件

初始化的核心不是生成 4 个还是 10 个根，而是能否用可接受的预算建立一组有效、具有基本竞争力且思想方向有区分的锚点。如果 LLM 主要是局部精炼器，过差的起点会直接限制后续可达区域；只有代码多样但全部很差的初代也不构成有效探索。反过来，初始化占用过多 evaluator 预算又会挤压后续历史驱动的多步改进。

[待验证] 初始化应单独报告首批候选的有效率、质量分布、行为或思想区分度及对后续推进的影响。“轨迹上下文有用”与“初始锚点足够好”是相互作用的两个因素，正式实验需要区分，不能用根数调整代替。V9.2 引入的最小闭环是：8 条互补策略各自独立生成根并完成一次历史条件化 bootstrap，再筛出 6 条；V9.5 起简化为 8 个独立根各一次 bootstrap、不再筛减，bootstrap 的有效 |Δq| 同时为乐观项提供尺度。具体根数与 bootstrap 深度仍未消融。V9.7 的路线级分配使“8 个根是否值得分开投入”成为解释 H1 的前提：在线只保证 code unique，过程分析需定性检查初始方案的算法结构差异；若根高度同质，route balancing 缺少可分开投入的对象。不加入 embedding novelty 或 diversity rejection。V9.7 的两级硬门是可检验的设计选择而非天然结构；bootstrap 得到的 $s$ 是 Refine 一步尺度的启发式，不与后续 Refine/Explore 混合严格同分布。

[待验证] 初始化评价的时间尺度还应与算法改进的时间尺度匹配。如果某个方向需要两三步局部精炼才显现价值，只依据根节点或一次 bootstrap 缩减路线会系统性低估延迟方向。初始化除报告最好值外，还应报告质量下限、bootstrap 改善比例、各初始路线实际获得的发展深度，以及浅层未入选路线的后续反事实仍然未知。需要给每条路线多少步不能凭直觉设成固定保护配额，应由不同初始化深度的受控对照确定。

### 6. Action、Code 与有效搜索空间

Action 或 Idea 表达本轮生成意图，不是审计表单。表面格式差异不构成搜索失败的证据；operator、fitness、代码变化和审计字段由系统根据代码和评价结果记录，不转嫁给模型。

Idea 与 Code 在语义上承担不同职责：Idea 说明本轮改什么，Code 给出真实可执行实现；但这不推出必须把一次搜索决策拆成两次模型调用。对于每份 evaluator 预算只生成一个候选的协议，默认应让模型在同一份“锚点 + 相关轨迹”上下文中联合输出一个 `Idea + Code`，使声明与实现共同形成并接受一次真实评价。先定 Idea、再另行生成 Code 是可单独研究的实现变量；如果它又与固定多步 rollout、best-of 选择绑定，就会改变基本预算单位，无法再把效果简单归因于轨迹。

轨迹包含多步历史，不等于一次锚点选择后必须连续做多步决策。历史的时间长度描述模型在当前一步能看到多少来时路；决策粒度描述何时重新比较全局锚点并分配下一份预算。两者必须分开。V9.3 的固定三步 rollout 混淆了这两个维度；V9.4 恢复为每次“选择一个锚点—联合生成一个 Idea + Code—评价一次—更新一次—重新选择”。

自动算法设计的信用粒度存在根本限制。程序行为往往由多处代码、参数和控制流共同产生，一行变化也可能引起非局部效果；它不像某些 GP 表示那样可以将一次符号或子式替换直接解释为精确操作。即使保存完整 diff，也只能说变化与结果共同发生，不能自动确定哪一行 work。因此轨迹应提供思想层的条件证据和多步关系，不应伪造行级因果精度。

有效搜索空间由真正可执行、可评价的状态覆盖决定。代码文本不同不保证算法行为不同，同一程序也可能携带不同历史知识。代码哈希、相似度和唯一率适合诊断，未经验证不应成为在线拒绝规则。模板 import、输入 dtype、输出 shape、finite 要求以及 parser/validator 一致性属于系统契约，必须先满足，接口故障不能解释为方法机制失败。

评价器的分辨率决定预算机制是否拥有可学习信号。大量行为不同的程序若在搜索集上同分，信用和选择无法按目标质量区分它们，后续结果会更多受有效率、同分简洁性和创建顺序影响。此时长期平台既不能证明轨迹无效，也不能证明已经达到算法最优。实验应同时报告 fitness 唯一值比例、最好分数并列规模、平台持续时间和 held-out 分化，把“评价信号不足”与“搜索机制没有利用信号”分开。

机制实验应区分三种状态：机制没有运行、机制运行但没有改善、机制运行后造成损害。接口测试只能确认第一层，最终分数只能评价整个系统；具体机制贡献仍需要过程证据和受控对照。

### 7. 程序复杂度不是质量代理

程序复杂度与 fitness 都需要观察，但长度不是算法质量代理。V4 暴露出无边界增长会增加上下文和修改负担；固定长度惩罚或硬性拒绝长程序又可能压制必要复杂化。

当前的最小原则是 fitness first、完全同分时择简：任何严格更优程序优先，只有 fitness 完全相同时才偏向非空 LOC 更少的实现。这条规则会改变 compact best 和后续锚点，因此不只是展示层选择；它在离散评价面上的净效应需要单独验证。测试程序的选取也必须与方法内部比较规则一致。

注释和 docstring 不属于算法复杂度：它们不参与目标程序的决策，却会消耗生成 token、扩大后续上下文并污染 LOC 诊断。对自动算法设计，可以在评价与入图前确定性删除这些文本，而不引入长度惩罚或搜索偏好。V9.2 起只让规范化后的可执行源码进入 evaluator 和轨迹；真正的控制流、公式、辅助函数和必要中间状态不因该规则被删减。

### 8. LLM 进化算子的底层认识

LLM 利用预训练得到的程序、算法和人类修改先验，对已有方案进行语义变化。[Evolution Through Large Models](https://arxiv.org/abs/2206.08896) 将其视为从人类程序修改分布中学到的智能变异；[Evolving Code with a Large Language Model](https://arxiv.org/abs/2401.07102) 指出，具体变化行为隐含在模型、提示词和上下文中。因此，提示词、父代、历史和反馈共同定义实际进化算子，而不是外围接口。

[Behaviour Space Analysis of LLM-driven Meta-heuristic Discovery](https://arxiv.org/abs/2507.03605) 说明提示词会显著改变探索、利用、收敛与停滞行为；[Fitness Landscape of Large Language Model-Assisted Automated Algorithm Search](https://arxiv.org/abs/2504.19636) 说明不同算法任务的搜索地形具有不同的多峰和崎岖程度。因此，同一轨迹深度、选择压力和多样性水平不应被预期在所有 task 上产生相同行为。[待验证]

[待验证] 不同任务可能具有不同的算法改进几何：有的任务需要在很深的 lineage 中连续积累、反复重构并穿过短期退步，有的任务则更像围绕强 heuristic 重复测试局部变体。前者可能从 formation history 获得更多信息，后者可能更依赖 exact-state direct trials。现有跨任务差异只是联合机制下的相关性观察；在 `Current Code Only` 对 `Current Code + Evidence` 以及 Evidence 组成消融完成前，不能把它写成任务适配规则。

[Language Model Crossover](https://arxiv.org/abs/2302.12170) 支持通过上下文归纳语义层面的多父代关系，为双轨迹知识重组提供依据，但不意味着代码拼接。[DeltaEvolve](https://arxiv.org/abs/2602.02919) 强调保存语义增量及其结果，这与“来时路”主张一致。[When Can LLMs Actually Correct Their Own Mistakes?](https://aclanthology.org/2024.tacl-1.78/) 提醒，自我修正通常需要可验证的外部反馈；模型总结未经验证不能成为共享事实。

综合这些认识，后续机制迭代应优先保证可靠改进，再在优质局部区域寻找互补多样性，并先建立真实的 action–result 对应，再使用高层总结。这三点是机制设计的主要约束。

机制设计首先要从底层任务出发：在给定模型、evaluator、上下文和预算下，系统需要保留什么搜索状态、给模型什么信息，以及怎样把预算交给仍可能产生最终突破的算法改进过程。科学叙事、可证伪假设和消融用于澄清与检查机制，不应倒过来把机制限制为当前方便测量的代理。一个机制能讲出完整故事、能做单变量对照，或在相关工作中出现，都不等于它已经抓住核心问题；相关工作提供可借用的搜索模式和失败经验，不替 TraceAAD 证明任何设计。

因此应先形成最简但完整的信息—决策—生成—评价—更新闭环，再让实验帮助定位其中真正有效的部分。上下文窗口会改变模型的实际算子，算子会改变轨迹分布，评分会改变哪些轨迹继续产生数据，初始化则决定可达局部区域。任一机制单独看似合理，与其他机制组合后都可能形成冲突。不能从当前分数逆向叠加工程补丁；每个新设计都应说明它解决了底层任务中的哪个信息或决策缺口，以及它与系统其余部分怎样闭合。

联合系统中的“删模块”不自动构成语义有效的消融。例如删除 history 会同时改变信息量、prompt
长度、注意力分配和模型的修改任务；其结果最多说明当前表示在当前系统中的净效果。用于支持机制
主张的正式消融应比较语义完整、内部自洽的接口，并先用低成本配对识别实验确定是信息类型、
表达粒度还是生成指令在改变行为。

[待验证] 生成算子的最小价值可能是降低单次 generation 的决策不确定性：一个简短的 `Refine`
或 `Explore` 意图可以约束本次修改，却不需要 operator credit、UCB 或 adaptive portfolio。生成意图与
算子选择机制是两个不同层次；前者是 prompt 中的当次任务，后者才是如何在多个意图之间分配预算。
极简意图是否优于完全自由生成，正由 V9.7 的 Refine 0.7 / Explore 0.3 固定混合在完整搜索中检验，
过程报告按意图分列结局与编辑幅度。

## 二、当前版本观察与待验证判断

搜索集最好分数、测试结果和搜索过程构成三类证据。最终分数无法解释具体机制，局部 improve 也不能替代 global-best 推进；报告应同时包含三次重复均值与下限、后半程更新、路线推进、有效候选、复杂度和测试表现。

自定义 task 协议不要求逐项复制某篇论文，但需要预先固定搜索集、保持搜索与测试独立，并让比较方法共享同一数据、评价器、模型条件和结果选择规则。不同原生预算回答各方法按自身设计运行时的整体表现；共同预算截面可以补充样本效率分析，但不应事后改变主协议。正式比较统一使用 1000 次真实评价的固定预算。

已完成的 V9-Core 正式四任务结果中，十四方法同场平均名次为 4.467 居第 1，V8（5.167）第 2，MCTS-AHD（5.233，以 CVRP 20260812 批次为准）第 3；单版本与四个固定外部基线同场时，V9 为 1.800、MCTS-AHD 为 2.067（2026-08-13 从 `eval_best_*` 工件统一重算的正式口径，见[实验总汇](../experiments/实验总汇.md)）。V9 是当前应优先解释的强 TraceAAD 完整版本参照，但差异小且只有 3 次重复，不能据此证明历史或任一支撑机制的独立贡献。V9.1 的 MCTS-Aligned 与 Trajectory-Centered 两个协议也已完成四任务三重复及 held-out：Trajectory-Centered 相对 V9 的改善主要出现在 TSP，CVRP、OP 与 OBP 没有形成同方向优势，说明轨迹中心预算的联合效果具有明显任务依赖。

V9.2、V9.3 与 V9.4 现均已完成四任务三重复及 held-out。[版本谱系与实验事实](../analysis/TraceAAD-版本实验事实与机制诊断.md)的 V9.3/V9.4 节显示：V9.3 相对 V9.2 在 15 个测试单元中 10 个更好、1 个持平、4 个更差，主要收益在 CVRP、OBP 和 OP，TSP 退化；V9.4 相对 V9.3 只有 5 个更好、10 个更差，并表现出更大重复间方差。V9.3 的固定三步协议仍存在决策粒度错误，其较好分数不能使该定义变正确；过程证据支持的是退步后的有限连续发展与整段代表筛选。V9.4 恢复了正确的一步联合生成并把模型调用约减半，但折扣信用几乎没有改变最高价值利用的实际选择，`4:1` 覆盖只有主谱系内部的局部正信号。两版约 98.5% 正式预算都落在一个初始谱系，说明增加锚点数和质量区覆盖没有形成多路线搜索。

[V9.5 终局复盘](../analysis/TraceAAD-V9.5终局复盘.md)覆盖 10/12 个到达预算终点的 run；TSP/CVRP 各一次 replacement repeat 因基础设施失败未完成，V9.5 因此不进入正式结果页与十四方法排名，其价值以过程证据与后续版本的基座形式保留。已完成结果中，TSP 提供强正信号，OP 3/3 在 search 与 held-out 上均弱于 V9，CVRP 没有形成升级，OBP 则是在 `s=0` 下观察 Evidence + Generation + pure-`q`/tie-break 的自然对照。TSP/CVRP 的 active optimism、OP 的 near-greedy 与 OBP 的 pure-`q` 形态持续到预算终点，但活跃程度与最终质量没有单调关系。V9.5 因而证明了机制能稳定运行并显著改变搜索行为，尚未证明 Evidence 或 Quality + Opportunity allocation 各自改善最终质量。

生成接口审计还显示：TSP/CVRP/OP 的随机真实 prompt 中，V9.5 平均放入约 7.9 条历史事件，少于 V9 的约 8.8--9.0 条，但其 history token 为约 3.1--3.4K，V9 仅约 1.0K；主要增量来自 actual diff，不是核心 instruction。该审计触发的固定 anchor 识别实验已完成两轮（共 864 次生成）：简洁 `Idea + result` 历史有单步价值，紧凑实际改动摘要有额外信息，历史越多、模型改得越小；结果与协议见 [RQ-003](../research/RQ-003-轨迹上下文与搜索评分.md)。

V9.5 的最终 best lineage 在 TSP/CVRP 中包含大量 regress transition，而 OP/OBP 更短且偏 improvement/plateau。这为非单调算法形成过程提供了结构证据，也提出了“历史价值依赖任务改进几何”的待验证假设；它不能证明 regression 具有前瞻信用，也不能把 formation/direct 的任务差异写成在线规则，更不能把 same clade 当成语义路线。

MCTS-AHD 所展示的预算集中与局部精炼能力值得学习，但其树结构和具体公式不是 TraceAAD 需要复制的科学主张。

V9.6 依据识别实验重构历史挑法与写法（[RQ-009](../research/RQ-009-锚点历史上下文.md)）：历史修正全部兑现，单步生成在失真最重的 OP/OBP 大幅改善，但收益集中在 direct 稀疏锚点，编辑收缩加深；搜索与最终质量任务分化（OBP 全面受益、TSP 受损），四层证据链见 [V9.5-V9.6 证据链对比](../analysis/TraceAAD-V9.5-V9.6证据链对比.md)。这再次说明单步生成收益不自动转化为完整搜索收益，兑现方式依赖任务的改进几何。

三臂单步实验（648 次生成，详见一.1）进一步确立：来时路是第一个在全部四任务上单步价值明确的上下文成分，修改收缩首次与质量收益同向；子代尝试在其之上无稳定额外价值。历史价值的主体是来时路。该实验同时修正了 TSP 的归因：固定同一批 TSP 锚点，来时路使单步质量显著改善（improve 0%→12%，valid 81.5%→98.1%）且同时伴随修改收缩，"历史 → 编辑收缩 → TSP 搜索变差"的直接因果不再被证据支持（证据链对比头部已标注）。由此形成的证据分层：**来时路上下文明确有用（四任务一致），子代尝试无稳定额外价值，预算分配与修改意图仍然高度可疑**——单步确实改得更好之后，完整搜索仍不稳定变好的原因大概率在"从哪里继续"与"这一步该精修还是换方向"两处。历史线收口，不再迭代条数、配额与子代排序。

当前 V9.7 的路线问题已完成过程定位：两级结构存在，但共享 bootstrap 尺度几乎没有激活路线层；不能把任何最终差异归因为多路线已获得实质探索。正式 held-out 也已完成：联合版本在 TSP 改善、CVRP 无信号、OP 相对 V9 退化，OBP 差异主要在约 2% 噪声底附近，没有形成跨任务大而一致的统一升级。显式 Refine / Explore 是否改变生成、其独立贡献如何，仍需单独的过程分析或消融。来时路提高局部决策质量已被单步实验支持；修改收缩本身不能写成已证实的损害，Explore 也不是对这一收缩的修复。后续判读仍遵循“大而一致”纪律：三重复同向且幅度明显超过同方法批次间抖动（held-out 约 2%）才承认差距；不根据干预率调大 $s$，不把诊断倍率直接写成下一版参数。
