# TraceAAD 研究认识

> 本文只保留跨版本可复用、且由现有证据支持的当前判断。方法规范见 [TraceAAD V9.7](../methods/TraceAAD-v9.7完整机制设计.md)，正式结果以[实验总汇](../experiments/实验总汇.md)为准，具体研究问题见 [`docs/research/`](../research/)。

## 1. 当前证据

### 1.1 父代改进来时路具有单步生成价值

三轮固定锚点实验共完成 1,512 次生成与评价。第三轮固定当前代码、任务、输出契约和采样条件，覆盖 4 个任务、72 个锚点、3 个上下文臂和每臂 3 次重复，共 648 次生成。

- 加入父代改进来时路后，四个任务的配对 conditional $\Delta q$ 区间均不跨 0；72 个锚点中 58 个方向更好、14 个更差。
- 在来时路之外加入已有子代尝试，没有显示稳定额外价值；四个任务的区间均跨 0，方向为 35 好、34 差、3 平。
- 来时路使修改幅度收缩，并减少最差十分位的大幅改写；这一变化与单步质量改善同时出现，不能写成已证实的损害。

因此，当前默认生成上下文是“当前完整算法 + 与该锚点匹配的父代改进来时路”。已有子代尝试继续作为搜索事实保存，但不常驻默认提示。该结论只识别给定锚点时的单步作用，不能直接推出完整搜索或 held-out 收益。完整证据见[固定锚点单步生成识别实验](../experiments/TraceAAD-固定锚点单步生成识别实验.md)。

### 1.2 完整版本没有形成跨任务统一升级

正式比较使用 Qwen3.6-27B、每次运行 1000 次真实评价、每个方法每任务 3 次独立搜索，并在 4 个任务的 15 个测试设置上进行 held-out 评价。

十五方法同场的描述性平均名次为：TraceAAD V9 为 4.933，TraceAAD V8 为 5.667，MCTS-AHD 为 5.700，TraceAAD V9.7-batch 与 V4 均为 6.267，TraceAAD V9.6 为 7.667。单版本上场为 1 个 TraceAAD 与 5 个外部对照共 6 方法；V9、V5、V8.2、V8、V9.7-batch 的平均名次分别为 2.067、2.133、2.367、2.433、2.767。

这些排名用于压缩跨设置结果，不代表统计显著性。V9.7-batch 在父代来时路实验收口前启动，仍使用 V9.6 的 `formation + direct attempts` 上下文；它不是当前 V9.7 完整协议的正式评价。父代来时路 V9.7 已完成 TSP、OP、OBP 的正式 held-out，与 V9.7-batch 的差距未穿过约 2% 噪声底。用未完成 CVRP 的当前 best 做 15 设置快照时，整体同场平均名次为 4.733（第 1），单独上场为 2.200（6 方法中第 1）；该快照不能替代正式排名。V9.7-batch 也不是对 V9 或 V9.6 的跨任务统一升级。V9.5 只有 10/12 个计划运行完成，不进入正式排名。完整版本同时改变多个机制，其结果只能评价联合系统，不能归因到单一组件。

### 1.3 V9.7-batch 的路线乐观项几乎没有改变路线选择

V9.7-batch 将预算分为路线层和锚点层，并在两层共享初始化一步变化尺度。在 12,251 次决策中：

- 路线层乐观项改变 32 次选择，即 0.26%；
- 锚点层乐观项改变 7,418 次选择，即 60.6%；
- 路线层全部干预发生在各运行的前 1/3；
- 典型路线要反超当前赢家，所需尺度中位数约为当前值的 3–11 倍。

这是“机制运行但在路线层近似未激活”的过程负结果。它不证明路线覆盖无价值，也不否定两级结构；它只说明共享尺度在 V9.7-batch 中不足以实质改变路线预算。由于该批次使用旧历史上下文，结果不能直接外推到当前 V9.7 完整协议。干预率是诊断量，不是应反向调参追求的目标。详见[V9.7 路线级分配诊断](../analysis/TraceAAD-V9.7路线级分配诊断.md)。

### 1.4 评价预算与生成成本必须分开

1000 eval 只统一真实 evaluator 调用。解析失败、重复、缓存命中和模型调用方式会使 LLM 调用数、token 数和墙钟成本不同。正式性能比较、生成成本和搜索过程回答不同问题，不能相互替代。

## 2. 方法认识

### 2.1 搜索控制的是下一步生成条件

给定任务、语言模型和评价器，搜索系统每消耗一份预算，需要决定：

1. **从哪里继续**：哪条路线、哪个锚点获得下一次生成机会；
2. **怎样走到这里**：哪些与当前代码匹配的历史进入上下文；
3. **这次怎样改**：本轮采用何种生成意图。

三者共同定义给定搜索状态下的单步候选分布。树、路线、锚点、信用和记忆是支撑机制，不是独立于生成质量的最终目标。当前判断是：短期瓶颈更可能在生成，长期瓶颈才是预算分配。[待验证]

### 2.2 历史上下文与预算分配是两个独立研究对象

历史上下文改变“给定锚点时会生成什么”；预算分配改变“哪些锚点会获得生成机会”。固定锚点实验可以识别前者，完整搜索消融用于识别后者。联合版本结果、访问统计或谱系图不能替代这种分离。

### 2.3 轨迹事实与决策视图必须分层

轨迹事实至少包括当前代码、父子关系、声明的 Idea、实际修改、有效性、评价结果和发生顺序。模型实际看到的历史只是从这些事实中抽取的有限决策视图。

事实应完整、可追溯；决策视图允许有损压缩，但压缩规则必须明确。同一份代码可以沿不同路径形成，因此“代码相同”不意味着“下一次生成条件相同”。Idea 是语义标签，实际修改由父子 evaluator input 决定；两者不一致时，以代码事实为准。

### 2.4 非单调形成过程应保留，但不能奖励退步

优秀算法可能经过持平、退步、修复和重组后形成。保留 regression state 的理由是避免提前删除尚未完成的路线，不是给退步预设正信用。某个祖先事后位于成功谱系，只说明它属于来时路，不能证明当时重访它具有较高前瞻价值。

### 2.5 树拓扑不等于算法语义

根、分支、深度和访问集中只描述生成来源。不同根可能实现同一种算法思想，同一路线也可能在后续替换核心机制。路线覆盖若要成为科学变量，需要行为或语义证据；代码哈希和谱系身份本身不够。

### 2.6 预算分配需要区分覆盖与延续价值

- **路线覆盖**：为欠投入的初始来源保留有限机会；
- **延续价值**：预测某条路线在剩余预算内产生终局突破的可能性。

当前质量是最可靠的基础信号，但不是未来突破的充分统计量。访问补偿可以改变机会分配，却不自动估计延续价值。路线推进率、局部回弹、趋势、成熟度和事后谱系成功均不能在缺少独立证据时写入在线信用。

### 2.7 生成意图应作为可识别变量研究

当前 V9.7 用固定 0.7/0.3 混合区分 Refine 与 Explore。该设计把局部细化和结构变化显式化。完整协议已有 TSP、OP、OBP 的正式 held-out，但 CVRP 尚未齐，且这些结果是联合协议评价，不能识别两种意图的独立作用。V9.7-batch 同时改变了路线分配和生成意图，且使用旧历史上下文。需要固定锚点和历史，分别比较修改幅度、有效率、严格父代改进率、新 best 率及后续繁殖结果。

### 2.8 程序复杂度目前只是诊断量

现有 run 级分析没有显示 LOC 与 held-out gap 的稳定关系。代码增长可能是必要复杂化、暂时退步或停滞后的无收益改写，单靠长度无法区分。LOC 不应进入任务分数、在线信用或硬拒绝规则；完全同分时择简只是一条确定性 tie-break。详见[RQ-001](../research/RQ-001-程序膨胀.md)。

## 3. 证据与写作纪律

研究结论需要区分五层证据：

1. **机制规范**：系统被设计成怎样运行；
2. **过程激活**：机制是否实际改变了选择、提示或候选分布；
3. **单步生成**：固定锚点时，历史或意图是否改变下一候选；
4. **完整搜索**：统一预算下是否改善 best-at-budget；
5. **held-out 与成本**：最终程序是否稳定泛化，以及代价是多少。

前一层不能替代后一层。完整联合版本只能支持整体系统判断；若没有固定其他条件的消融，不认领单组件贡献。实例级配对样本不能替代运行级独立重复。三重复下，小于或接近约 2% held-out 抖动、方向不一致的差距统一读作无信号。

## 4. 当前开放问题

1. **路线覆盖**：在固定历史与生成协议下，显式保留欠投入路线是否提高 best-at-budget 与 held-out 质量；
2. **生成意图**：Refine 与 Explore 是否形成稳定、任务相关的单步分布，并在完整搜索中产生净收益；
3. **延续价值**：哪些可重复的轨迹证据能够预测剩余预算内的突破，而不是事后解释成功谱系；
4. **跨路线知识**：哪些知识可迁移，怎样保存来源与适用边界，何时会因错误类比产生负迁移；
5. **任务几何**：不同任务的有效修改幅度、偏好算法形态和突破稀疏度如何由轨迹在线读出；
6. **参数学习**：搜索轨迹能否在不引入幸存者偏差和数据泄漏的前提下，改善固定搜索器中的候选生成先验。

## 5. 外部证据的位置

现有文献支持三项背景判断：LLM 变异具有结构化先验；可靠局部改进通常比无条件扩大文本新颖性更重要；代码、行为和路线多样性不能混为一谈。相关证据及边界见[LLM 作为进化算子的机制分析](../references/LLM作为进化算子的机制分析论文.md)、[AAD 方法汇总](../references/LLM自动算法设计方法汇总.md)和[逐篇阅读笔记](../references/LLM自动算法设计方法阅读笔记/README.md)。这些外部结果用于提出可检验假设，不能替代 TraceAAD 自身的受控实验。
