# TraceAAD 研究认识

## 1. 当前证据

### 1.1 父代改进来时路具有单步生成价值

三轮固定锚点实验共完成 1,512 次生成与评价。第三轮固定当前代码、任务、输出契约和采样条件，覆盖 4 个任务、72 个锚点、3 个上下文臂和每臂 3 次重复，共 648 次生成。

- 加入父代改进来时路后，四个任务的配对 conditional $\Delta q$ 区间均不跨 0；72 个锚点中 58 个方向更好、14 个更差。
- 在来时路之外加入已有子代尝试，没有显示稳定额外价值；四个任务的区间均跨 0，方向为 35 好、34 差、3 平。
- 来时路使修改幅度收缩，并减少最差十分位的大幅改写；这一变化与单步质量改善同时出现，不能写成已证实的损害。

因此，当前默认生成上下文是“当前完整算法 + 与该锚点匹配的父代改进来时路”。已有子代尝试继续作为搜索事实保存，但不常驻默认提示。完整证据见[V1–V9.6 机制诊断](../analysis/TraceAAD-V1-V9.6机制诊断.md)。

完整搜索层的净贡献已由 PP/CO 消融识别（V9.7 协议、同 seed 配对、4 任务 × 3 seed × 1000 eval）：净贡献不是跨任务常数。结果分别以搜索 best 和同规模独立测试报告；单步收益不自动累积为完整搜索收益，n=3 的空结果也不证明无贡献。转化机制与检验入口见[V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md)，完整搜索结果见[父代来时路完整搜索消融](../experiments/父代来时路完整搜索消融.md)。

### 1.2 完整版本没有形成跨任务统一升级

正式比较使用 Qwen3.6-27B、每次运行 1000 次真实评价、每个方法每任务 3 次独立搜索；主排名使用 4 个任务的同规模独立测试设置，跨规模设置另报。

代表性同场只放入 V8、V9、V9.7 与 5 个外部对照，共 8 方法；7 个同规模设置上的描述性平均名次为 TraceAAD V9.7 `3.429`、TraceAAD V9 `3.571`、MCTS-AHD `4.786`、TraceAAD V8 `5.000`。单版本上场为 1 个 TraceAAD 与 5 个外部对照共 6 方法；V9 与 V9.7 的平均名次分别为 `1.857` 和 `2.000`，均列六方法第 1。

这些排名用于压缩同规模设置结果，不代表统计显著性。V9.7 是父代来时路完整协议（批次 `20260814_150927`），四任务三重复已齐并进入代表性同场；同规模列中 TSP50 最佳为 V9.9、CVRP50 最佳为 V8、OP50 最佳为 V9，OBP 各设置由多个版本分占。完整版本同时改变多个机制，其结果只能评价联合系统，不能归因到单一组件。过程拆解见[V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md)。

### 1.3 两级分配在 V9.7 协议上仍然几乎不改变路线选择

V9.7 把预算分成路线层和锚点层，并在两层共享初始化一步变化尺度。V9.7 批次 12,152 次决策中，路线乐观项改变 130 次（1.07%），锚点乐观项改变 7,877 次（64.8%）；路线干预仍全部发生在前 1/3。TSP/CVRP/OP 的顶路线份额为 99.4%–100%，OBP 为 85.9%–98.0%。

这是“机制运行但在路线层近似未激活”的过程负结果。进一步重放显示现行分数有不可恢复淘汰：CVRP/OP 在第 1–2 次正式生成、TSP 最迟第 40 次进入单路线吸收态；96 条路线中有 64 条没有 bootstrap 后续段。它仍不证明路线覆盖无价值，也不否定两级结构，因为被放弃路线的 continuation value 没有被观测。干预率是诊断量，不是应反向调参追求的目标。详见[V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md)。

### 1.4 评价预算与生成成本必须分开

1000 eval 只统一真实 evaluator 调用。解析失败、重复、缓存命中和模型调用方式会使 LLM 调用数、token 数和墙钟成本不同。正式性能比较、生成成本和搜索过程回答不同问题，不能相互替代。

### 1.5 Refine / Explore 角色与短续段已获得受控单步证据

V9.8 Stage P 完成了 864 次 History × Intent 固定锚点响应和 690 次 Explore child 强制续段响应。固定锚点下，Explore 在四任务、两种上下文中都更常切换静态机制代理并形成更大修改，但即时有向质量低于 Refine；这支持“替代方向提议”与“当前方向发展”的生成角色，不证明真实 family discovery。

Parent path 对 Refine 的锚点级配对即时质量在四任务均为正向均值，正向锚点多于负向锚点；对 Explore 的方向与有效率更不稳定。五步强制续段能发展一部分 Explore child，OBP 与 OP 的 parent recovery 增加最明显，CVRP 基本不变。Hypothesis-level 局部重选没有稳定优于 child-chain。完整证据见[V9.8 机制诊断](../analysis/TraceAAD-V9.8机制诊断.md)。这些结果识别 proposal 与短期 delayed development，不识别边界宽限、历史发展项或完整搜索收益。

从这组证据可以抽出三条稳定边界。第一，轨迹上下文的价值依赖 operator；当前只支持 parent path 作为 Refine development context，不支持“同一历史对所有生成意图统一有益”。第二，跨边界的即时低质量不能被解释为零有限续段价值，但 development opportunity 不等于 guaranteed budget；续段价值依赖任务、horizon 和局部 policy。第三，内部可改进性不等于相对已有方向的可恢复性；CVRP 中多个 child 能在新段内继续改善，但五步 parent recovery 基本不变。

因此，Stage P 支持“为什么需要研究跨边界延迟容忍”，不支持 V9.8 中 $C$ 的具体形式。$C$ 是否改变选择、是否改善 best-at-budget，以及这种改善是否依赖任务的跨边界提议几何与有限视野可恢复性，仍属于 Stage A 的问题。

### 1.6 V9.10 联合分配没有形成正向净收益

V9.10 四任务三重复搜索与同规模独立测试已完成。相对 V9.7，同规模设置中 TSP50、CVRP50 和 OBP 的 `1k/5k × capacity {100,500}` 整体退化，OP50 改善。跨规模结果只作为迁移补充。四任务结果不支持“折扣 Thompson 联合分配改善有限预算搜索”的完整版本主张。

过程 checkpoint 显示，V9.10 的锚点数接近评价数，约半数锚点从未再次选择；TSP/OP 约 `36%–38%`、OBP 约 `53%` 的动作在终局仍 pending，其中多数年龄超过 100 次响应。终局 top-20 联合臂只占约 `2%` 分配质量，有效锚点熵仍为总锚点的 `92%–94%`，Refine 边际接近先验 `0.7`。当前可支持的机制判断是：联合后验没有获得及时、代表性的局部反馈，分配行为近似扩散；不能据此把负结果归因于 Thompson 抽样、折扣或父链证据中的单一组件。过程诊断见 [V9.10 机制诊断](../analysis/TraceAAD-V9.10机制诊断.md)。

### 1.7 V9.11 止跌但未形成统一升级

V9.11（停滞触发 Explore + 一次 Landing）四任务三重复已完成。头对头 15 设置：对 V9.10 好 12、对 V9.9 好 10、对 V9.8 好 7 差 8、对 V9.7 好 5、对 V9 好 4。单版本上场平均名次 3.100（V9.8 2.667、V9.9 3.400、V9.10 4.033）。任务画像分化：OP 三档同向高于 V9.7（0.6%–1.9%）但输给全部五个外部对照的 OP100/200；OBP 对 V9/V9.6/V9.7/V9.8 全面落后；TSP50 均值 5.918 为全部内部版本与外部对照的独占最佳，TSP200 却比 V9.7 高 2.9%。结论：V9.11 是 V9.9/V9.10 退化后的有效恢复，与 V9.8 平手；V9.8–V9.11 一代均未追回 V9.7 与 V9。完整对照与中期判断修正见[V9.11 机制诊断](../analysis/TraceAAD-V9.11机制诊断.md)。

### 1.8 V9.15 使任务×机制交互成为主要开放问题

V9.15 统一提高了 Explore 份额并缩短了最好谱系，但四任务结果方向不同：OBP 搜索与六个 held-out 设置稳定改善，OP 均值改善，TSP 与 CVRP 的发展深度下降且有限预算收益不足。过程重放显示 `C_traj` 广泛改变父节点排序，而初生保护 `B` 很少改变真实选择；历史 realized gain 不能直接作为未来 continuation value。任务差异应优先用好簇稀有度、族内可改进性与簇间质量方差解释，这些变量仍需独立固定视界实验识别。完整分析与 V9.16 入口见[V9.15 机制诊断](../analysis/TraceAAD-V9.15机制诊断.md)和[V9.16 完整机制设计](../methods/TraceAAD-V9.16完整机制设计.md)。

三次重复还显示运行间存在“命中后发展”差异：TSP 与 OP 中较高局部严格改进率与较好运行相容，但 CVRP 和 OBP 分别出现高改进率不对应最好 held-out、低改进率对应最好 held-out 的情况。局部突破是入口即时响应信号，不是高质量算法簇的身份证明。稳定性应拆成入口发现率、固定视界认证率、持续精炼率和未认证入口预算锁定；V9.16 将这些指标写入入口生命周期和着陆协议。

V9.16 的机制设计收缩为一个可直接检验的 landing 干预：固定 `Refine/Explore=0.7/0.3`，普通父节点只按当前质量 `q` 选择；成功 Explore child 以固定概率获得一次、最多三步的连续 Refine landing，landing 预算上限为初始化后剩余预算的 `10%`。单个 entry 是 provenance 单位，不等同于算法簇；`C_traj`、`B`、动态 `p_E`、分层 prior、LCB、license 和 shadow tree 不进入本版本。完整边界见[V9.16 完整机制设计](../methods/TraceAAD-V9.16完整机制设计.md)。

V9.16 进一步把分配问题写成一个可检验的视界取舍：逐评价重选保留即时纠错，连续 landing 为结构性 proposal 提供短期发展时间。`one-step quality` 与短视界发展价值之间的关系仍需由 `q` 基线与 `q + landing` 的配对过程和结果共同识别。[待验证]

这段描述保留 V9.16 的历史协议事实，但不再作为当前预算分配认识。V9.16 的 landing 是固定的连续发展干预；它没有定义“哪个锚点值得下一次投入”的评分。V9.17 的正 block gain 也只说明一部分任务中存在局部发展机会，不能把短期成功直接解释为下一段预算的 continuation value。当前 R0 将这两个事实分开处理，见[V9.18-R0 完整机制设计](../methods/TraceAAD-V9.18完整机制设计.md)。

### 1.9 V9.16 的全景事实与双范式权衡

V9.16 确立了纯质量评分 $S(a)=q(a)$、目标 10% ESS Boltzmann 宽采样与 10% 硬封顶 3 步 Refine Landing 的联合体制。在 5 大任务 18 个 held-out 规模评测中，与五个主流外部基线同场平均名次达到 `1.750`（列全部 6 方法第 1）。

该结果揭示了搜索动力学的核心结构性权衡：
1. **全局宽采样 vs 超深单链精炼**：V9.16 的 ESS 动态自适应宽采样（后期活跃池达 ~97 个节点，每 run 访问 196~335 个不同父节点）彻底消除了 V9.7 的单路线强吸收，在 OP/TSP/VRPTW 上实现了全局高质量方向的广泛突破；但对于极度依赖 50~100 步深层单链特化的任务（CVRP），宽采样稀释了局部连续投入，导致 CVRP 成绩落后于 V9.7。
2. **硬封顶短着陆有效杜绝算力耗散**：将 Landing 严格限制在初始化后剩余预算的 10%（最多 33 次 Landing），成功避免了 V9.8/V9.10 探索无限侵占主线算力的退化现象，验证了对跨簇新方向提供极低成本短程视界的可行性。

## 2. 方法认识

### 2.1 两个核心研究对象

AAD 不是在平滑、同质的程序空间里做黑盒优化。更合理的抽象是：搜索空间由若干潜在算法簇构成；不同簇有不同的性能上限和局部可改进性，LLM 迁入各簇的概率高度不均匀。[待验证]

TraceAAD 因此只保留两个核心科学问题：

- **轨迹条件生成**：给定当前算法 $x_t$、轨迹上下文 $h_t$ 和生成意图 $o_t$，如何改善下一步提议分布 $P(x_{t+1}\mid x_t,h_t,o_t)$，使搜索既能在族内 refinement，也能跨族 exploration。
- **轨迹感知的计算分配**：面对当前 hypothesis、锚点和搜索历史 $\mathcal H_t$，如何用 $\mu(a_t\mid\mathcal H_t)$ 决定下一次模型响应从哪里出发。V9.8 的操作实现先按 $\pi(o_t)$ 抽取生成意图，再计算条件于该 operator 的锚点分配；每份预算只启动一个 transition，响应后立即更新和重选。

生成机制决定 transition kernel：哪些新算法及算法簇可达、以多大概率可达。预算分配决定这些潜在能力在有限预算下有多大概率被兑现。渐近上限主要由模型、提示、算子和评价反馈决定；有限预算可达前沿由生成与分配共同决定。不要把二者写成简单的上限 / 下限。

BaSE 的真正启发不是“应该上 bandit”，而是迫使我们把搜索空间看成异质算法簇，并把深度—广度权衡读成：花多少预算找正确的族，又花多少预算在已找到的族内部开发。它只解决轨迹投资，不建模轨迹内容。外部证据见 [BaSE 笔记](../references/LLM自动算法设计方法阅读笔记/28-Compute-Allocation-BaSE.md)。

操作上，每次评价仍回答三个问题：从哪里继续，怎样走到这里，这次怎样改。前一个属于分配，后两个属于生成。初始化划定最初可分开投入的起点；V9.8 为保持可比性仍从一次 root bootstrap 估计共享一步尺度 $s_0$，但它只服务于观察不足和锚点回访，Explore 跨边界回撤由单独的衰减宽限处理。树、信用和记忆是支撑机制。

### 2.2 实验上拆开，理论上耦合

识别贡献时，生成与分配必须分开做实验：固定锚点识别 $P(x'\mid x,h,o)$，固定生成协议与 operator seed schedule 识别 $\mu(a\mid\mathcal H)$。联合版本结果、访问统计或谱系图不能替代这种分离。

理论上二者不能当成彼此无关的旋钮。有效的分配建立在提议异质性上：若不同投资单位上的 LLM 生成分布相近，分配器没有可利用的差异。反过来，若 Explore 能制造不同算法区域，而分配分数只读取入口即时质量，提议多样性会被预算调度截断。V9.7 搜索几何已经读出 route 与静态 family 的错位；下一步需要用固定锚点、强制短续段和 Uniform 对照检验新的 hypothesis unit 与跨边界宽限，而不是从选择性日志拟合长期价值。

### 2.3 轨迹事实与决策视图必须分层

轨迹事实至少包括当前代码、父子关系、声明的 Idea、实际修改、有效性、评价结果和发生顺序。模型实际看到的历史只是从这些事实中抽取的有限决策视图。

事实应完整、可追溯；决策视图允许有损压缩，但压缩规则必须明确。同一份代码可以沿不同路径形成，因此“代码相同”不意味着“下一次生成条件相同”。Idea 是语义标签，实际修改由父子 evaluator input 决定；两者不一致时，以代码事实为准。

### 2.4 非单调形成过程应保留，但不能奖励退步

优秀算法可能经过持平、退步、修复和重组后形成。保留 regression state 的理由是避免提前删除尚未完成的路线，不是给退步预设正信用。某个祖先事后位于成功谱系，只说明它属于来时路，不能证明当时重访它具有较高前瞻价值。

### 2.5 路线是投资单位，当且仅当存在可利用的异质性

根、分支、深度和访问集中只描述生成来源。不同根可能实现同一种算法思想，同一路线也可能在后续替换核心机制。代码不同不等于算法簇不同。路线覆盖若要成为科学变量，需要行为或语义证据。

V9.7 的顶路线份额与路线乐观项干预率，只说明当前公式几乎不改写路线选择。它至少对应三种尚未分开的情况：[待验证]

- **路线确实异质**：某一根已进入高潜力簇，把预算集中给它可能正确；强行增加路线探索会变差。
- **路线没有语义差异**：八个根只是同一族的轻微变体，任何跨路线分配器都没有可利用的臂。
- **有潜力差异但分配器看不见**：现行 $q^*+s/\sqrt{N+1}$ 只看已经达到多高和已经投了多少，不估计这条路线还有没有继续突破的可能。

因此当前最重要的分配问题不是把乐观项从 1 调到 2，而是：现有路线到底是不是有意义的投资单位。V9.7 的最终最好程序有 9/12 次改变所在根的静态机制宏簇，说明 route 是 provenance unit，尚不是稳定 family。覆盖与延续价值仍然是两个目标，但它们都以取得各路线可比较续段为前提。路线推进率、局部回弹、趋势、成熟度和事后谱系成功均不能在缺少独立证据时写入在线信用。

V9.8 据此把 hypothesis 降为 Explore 开启的 trajectory segment，并让它只携带边界、当前前沿、operator 投入和历史发展观测。新 Explore child 不再自动获得固定 probe；当它低于来源父代时，Refine 分数用随 $N_R$ 衰减的边界宽限暂时中和一次实现回撤，之后每个响应都重新选择。该 prior 可能减少即时早夭，也可能给无价值的大幅改写额外机会，必须与 $c_R=0$ 做单因素对照。观察不足与历史平均发展收益同样是启发式信号，不是潜力或长期边际价值的估计。完整定义与对照见[V9.8 机制诊断](../analysis/TraceAAD-V9.8机制诊断.md)。

### 2.6 生成意图的理论含义是族内 refinement 与跨族跃迁

当前 V9.7 用固定 0.7/0.3 混合区分 Refine 与 Explore。除 Refine 改得更小、improve 更高外，静态代码机制代理还显示 Explore 的宏簇切换率为 37%–54%，高于 Refine 的 2%–12%，并贡献各任务 20%–36% 的搜索期全局增益。根到终局发生宏簇变化的 9 次运行中，6 次由 Explore 首次进入终局宏簇；12 个最终最好程序本身全部由 Refine 生成。这是“稀疏换簇后继续开发”的描述性证据，不是固定锚点意图消融或行为簇确认。

轨迹不只是程序序列 $x_0\to x_1\to\cdots$，更有价值的运动是算法簇之间的停留与切换。V9.8 固定锚点实验已确认 Explore 提高静态机制代理切换并扩大修改，Refine 保持更高即时质量；真实 family 与进入更好盆地的概率仍未验证。现行 V9.7 锚点分数会让 36%–87% 的 Explore child 出生即淘汰，因此完整搜索里的后代率同时混入 proposal 与 allocation。Refine 也存在延迟改进：在实际选择下，regress child 被后代救回并超过原父代的比例为 TSP 15.8%、CVRP 21.8%、OP 2.4%、OBP 16.5%，但这是选择性分配下的 realized value。V9.8 强制续段进一步确认部分 Explore child 存在短期 delayed development，同时显示 recovery 高度任务相关；这些 horizon 是测量干预，不是在线预算承诺。

Stage P 还提示上下文政策应写成 $h_t=\operatorname{Ctx}(a_t,o_t,\mathcal H_t)$，而不是与 operator 无关的固定轨迹模板。Parent path 可能同时给 Explore 提供问题信息并把它锚定在当前机制，该 trajectory anchoring 解释尚未被中介或专门上下文实验识别。第一版保留共享 parent path 是实现 baseline，不是认定它对两种 operator 均为最优。

V9.8 的 proposal 仍是 local-trajectory-conditioned：Explore 知道当前程序怎样形成，但不知道全局已经出现过哪些 alternative hypotheses。代码不同不能证明语义新颖，因此新 hypothesis 的静态/行为 proxy-region revisit 必须离线报告；在其成本被稳定测量前，不加入全局 Idea Bank、在线 judge 或聚类。V9.8 的 allocation 同样具有明确能力边界：历史平均 Refine gain 只描述 realized development yield，不估计额外计算的长期边际价值。第一版先用强制续段和逐步分数消融取得证据，再讨论学习式长期价值。

### 2.7 程序复杂度目前只是诊断量

现有 run 级分析没有显示 LOC 与同规模独立测试差距的稳定关系。代码增长可能是必要复杂化、暂时退步或停滞后的无收益改写，单靠长度无法区分。LOC 不应进入任务分数、在线信用或硬拒绝规则；完全同分时择简只是一条确定性 tie-break。详见 [V1–V9.6 机制诊断](../analysis/TraceAAD-V1-V9.6机制诊断.md)。

### 2.8 V9.18 修订后的轨迹认识

V9.18-R0 把轨迹的作用分成三个层次：

1. **形成事实**：完整保存当前代码、父子关系、Idea、结果、有效性和顺序，供审计和生成上下文使用。
2. **展示价值**：固定同一代码与 operator，比较展示来时路和不展示来时路的下一步生成质量。这是 operator-conditioned 的反事实量，必须由 History-on/History-off 探针估计。[待验证]
3. **再选择机会**：在完整搜索中，用新 Explore 入口的有限、可衰减状态调节锚点评分，决定下一次是否更可能重新选择该锚点。它是 opportunity prior，不是 `V_show` 或长期 continuation value。[待验证]

R0 在线项只读取新 Explore 入口和实际选择次数，不读取 `F` 历史信用、回撤幅度、累计 gain、后代成功、子树最好值、最终谱系归因、pending 回报或独立锚点后验。每次选择后立即更新，机会随实际选择次数衰减；因此 landing 的思想存在于评分与选择中，但不再表现为连续三次预算。

V9.18-R0 还修订了生成上下文的认识。`Change` 是可复现的代码事实，适合保存在工件中；当前证据不足以把它作为默认生成提示的稳定收益来源。Refine 继续使用父代改进来时路；Global-Facts-Lite 只加入最多三条真实数值事实，不提供完整参考程序、代表锚点 Idea 或人工机制簇标签。Diagnosis 只作为可选审计字段，不构成已激活的反思动作。完整参考程序、强制 Diagnosis 和 `F` 历史项后置为单因素实验。

route、entry、hypothesis 仍然是来源和形成过程的记录单位。它们不能直接被称为算法簇，也不能因为某条最终谱系成功就获得祖先信用。V9.18-R0 将分配对象收回到锚点，把簇结构留作离线行为诊断。[待验证]

### 2.9 早期机制（V1–V9）失效的深层理论解释

结合算法簇几何、离散代码提议核与计算分配理论，早期机制的退化与重构具有以下本质机理：

1. **子代试错历史进 Prompt 的失效（离散空间负反馈与 Attention Bias）**：
   - 连续空间优化依赖负梯度或拒绝方向指引更新；离散程序空间不具备此凸性。失败程序包含大量具象的代码语法、变量命名与有缺陷控制流。
   - 自回归模型将局部失败尝试作为上下文时，会产生强烈的局部注意力偏置（Attention Bias），诱导模型在失败实现的细微变体上试错，破坏了顺畅的族内精炼路径。
   - 相比之下，父代正向来时路提供了一条沿可行流形改进的因果轨迹，与自回归模型的先验分布对齐。

2. **跨路线合成与细分算子的失效（算法不变量耦合与真实生成自由度）**：
   - 算法是强耦合的离散因果系统，其正确性依赖特定的结构不变量（Invariants）。跨路线算子（`synthesize` / `transfer`）假定不同拓扑路线的机制具备“即插即用”的模块化组合性，而在提示词空间直接拼凑异构逻辑必然导致前置/后置条件破坏与功能崩溃。
   - 在程序生成空间，模型有效的提议自由度仅有两类：**维持当前不变量的局部精炼（Refine）** 与 **打破当前不变量的结构跃迁（Explore）**。细分算子在算法簇几何上不存在独立的提议核。

3. **树递归 UCB 分配的失效（血缘拓扑与算法簇错位、历史最好与边际延续价值混淆）**：
   - **拓扑与簇的错位**：单父树的分支只是生成历史的血缘拓扑（Provenance），不是统计平稳的算法簇（Cluster）。同一分支后代可能漂移至不同算法族，也可能迅速陷入局部饱和。
   - **功劳与延续价值的混淆**：子树最大值 $G(n)$ 的向上传播将“历史功劳归因（Ancestral Attribution）”误当成“未来边际延续价值（Marginal Continuation Value）”。祖先曾孕育高分只代表它是来时路上的可行节点，不代表当前重新回访具有高边际产出，从而导致早期偶然高分分支锁定全部预算（Root Lock）。

## 3. 证据与写作纪律

研究结论需要区分五层证据：

1. **机制规范**：系统被设计成怎样运行；
2. **过程激活**：机制是否实际改变了选择、提示或候选分布；
3. **单步生成**：固定锚点时，历史或意图是否改变下一候选；
4. **完整搜索**：统一预算下是否改善 best-at-budget；
5. **同规模独立测试与成本**：最终程序在相同任务规模上的质量，以及搜索代价；跨规模测试补充报告迁移。

前一层不能替代后一层。完整联合版本只能支持整体系统判断；若没有固定其他条件的消融，不认领单组件贡献。实例级配对样本不能替代运行级独立重复。三重复比较按实际均值差与方向记录，包括约 1%–2% 的改进。

同一层内，中期过程快照的跨版本排序不能外推为终局结果。跨版本的主判断须以完整搜索与同规模独立测试为准；跨规模结果只用于迁移分析。

## 4. 当前开放问题

V9.8 的生成角色与短续段机会已完成识别，V9.9 进一步暴露了静态分配形状、算子条件概率未激活和新 child 过早失去机会。V9.10 因此把开放问题收敛为以下可分解检验：

1. **锚点级自适应分配**：折扣 Thompson 是否比 V9.9 固定几何秩更有效地把预算转向近期仍在产生局部改进的锚点（见 [V9.10 机制诊断](../analysis/TraceAAD-V9.10机制诊断.md)）。
2. **折扣是否必要**：近期衰减是否优于普通 Thompson，还是只增加了一个没有收益的时间参数。
3. **局部改进作为奖励**：V9.10 以最多 3 代的有限窗口结算父子及后代改进；需检验这段短延迟是否比只看当前父子关系更有用，不能外推为长期 continuation value。
4. **父链证据是否可迁移**：V9.10 将最近 4 代祖先的同意图结果按距离衰减并入同一联合后验；需检验它是在稀疏改进时提供有效先验，还是把不相关历史带入后代。
5. **Operator-conditioned generation**：Refine 与 Explore 共享完整 parent path，只改变意图指引；需检验联合 Thompson 分配是否改变两种意图在不同锚点上的短程调度效果（见 [V9.8 机制诊断](../analysis/TraceAAD-V9.8机制诊断.md)）。该结果不直接等于算子的纯因果效果。
6. **任务几何**：算法簇稀有度、族内可改进性与簇间质量方差能否解释不同任务的有效分配宽度（见 [V9.7 机制诊断](../analysis/TraceAAD-V9.7机制诊断.md)）。这些仍是离线诊断与待验证泛化主张，未进入 V9.10 的在线簇标签。

以上列表记录 V9.8–V9.10 阶段提出的历史问题，不能被理解为 V9.18-R0 已经采用的机制。V9.18-R0 的当前识别顺序收缩为：

1. 用固定锚点的 History-on/History-off 阻断探针，分别测量 Refine 与 Explore 的展示价值。[待验证]
2. 在关闭 landing 的原子搜索中，比较 `q(a)` 与 `q(a) + lambda_O * sigma_q * O_t(a)`，检验入口机会项是否改变锚点选择和有限预算结果。[待验证]
3. 在固定锚点评分下比较原 Explore 与 Global-Facts-Lite，检查极短全局事实板是否改变可执行提议，而不是只增加上下文文字。[待验证]
4. 只有两个单因素在直接证据层成立后，才评价联合版本；联合结果不重新归因给单一组件。

V9.18-R0 的具体协议见[TraceAAD V9.18-R0 完整机制设计](../methods/TraceAAD-V9.18完整机制设计.md)和[实验协议](../experiments/TraceAAD-V9.18-R0实验协议.md)。

## 5. 外部证据的位置

现有文献支持三项背景判断：LLM 变异具有结构化先验；可靠局部改进通常比无条件扩大文本新颖性更重要；代码、行为和路线多样性不能混为一谈。BaSE 额外表明：有限预算下的可达前沿依赖算法簇的提议质量不对称，自适应分配只在轨迹间存在可利用异质性时有价值；它不证明 bandit 公式应当写入 TraceAAD。这些外部结果用于提出可检验假设，不能替代 TraceAAD 自身的受控实验；证据与边界见[LLM 作为进化算子的机制分析](../references/LLM作为进化算子的机制分析论文.md)与[AAD 方法汇总](../references/LLM自动算法设计方法汇总.md)。
