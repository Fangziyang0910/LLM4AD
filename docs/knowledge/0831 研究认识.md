# 0831 研究认识

本文是 TraceAAD V10 的问题表述与机制动机。可复现定义见[V10 完整机制设计](../methods/TraceAAD-V10完整机制设计.md)。

LLM-based AAD 结合 LLM 与进化计算（Evolutionary Computation, EC）自动设计算法。LLM 根据任务和已有算法生成新的算法候选，评估器返回候选的质量分数（适应度），搜索机制根据评价结果继续演化。

TraceAAD V10 关注这个演化过程中的评价预算分配。在固定的评价次数下，搜索机制需要决定哪些算法获得后续改进机会，并利用已有改进轨迹辅助 LLM 完成改进，以在预算内找到质量尽可能高的算法。

## 1. 固定评价预算下的 LLM-based AAD

自动算法设计搜索的是用于求解一类问题实例的算法 $P$。评估器 $E$ 在训练实例上运行 $P$，返回适应度 $q(P)$。

LLM 根据任务、已有算法和生成上下文提出新候选：

$$
P'\sim p_\theta(P'\mid d_{\mathcal{T}},P,\mathrm{context}).

$$

其中：

- $\mathcal{T}$ 表示需要设计算法的问题类型，$d_{\mathcal{T}}$ 是该问题的任务描述；
- $P$ 是搜索机制选定的已有算法，$P'$ 是 LLM 在此基础上生成的新算法候选；
- $\mathrm{context}$ 是本次生成时提供给 LLM 的其他上下文；
- $p_\theta$ 是参数为 $\theta$ 的 LLM 所定义的条件生成分布，$\mid$ 表示生成以右侧信息为条件；
- $\sim$ 表示从该分布中生成一个候选，而不是等号。

因此，这个公式表示：LLM 根据任务描述、选定的已有算法和生成上下文，生成一个新的算法候选。

搜索机制选定要改进的算法，LLM 生成修改后的候选，评估器返回适应度，搜索历史随之更新。这个过程反复进行，直到用完正式评价预算 $B$。

时刻 $t$ 的搜索历史为 $\mathcal{H}_t$，剩余评价次数为 $b=B-t$。搜索在 $B$ 次正式评价后返回历史中适应度最高的算法：

$$
\hat{P}_B=\arg\max_{P\in\mathcal{H}_B}q(P).

$$

每个新候选的正式评价消耗一次评价预算。预算分配决定后续评价次数如何用于算法改进。

## 2. 评价预算如何用于算法改进

每生成并评价一个新算法候选，就会消耗一次评价预算。在每轮算法改进中，搜索机制先从已有算法个体中选取一个个体，使其参与下一次改进。这一步类似于进化计算中的父代选择。随后，搜索机制为该个体选择一个算子。

算子表示希望以什么方式改进选中的算法个体。上下文是本次改进提供给 LLM 的信息，用于帮助 LLM 按照该算子的思想完成改进。同一个算法个体采用同一个算子时，不同上下文也可能产生不同的新个体。因此，一个改进机会由算法个体、算子和上下文共同决定。

一个改进机会表示为

$$
a=(s,o,\mathrm{context}).

$$

其中，$s$ 是被选中的已评价算法个体，$o$ 是用于改进该个体的算子，$\mathrm{context}$ 是本次改进提供给 LLM 的上下文。上下文从搜索历史中选取，可以包含该个体的形成路径、已有评价结果以及与本次改进相关的其他信息。Restart 是不选取已有个体的特殊情况，此时 $s=\varnothing$。

V10 使用五种算子：


| 算子           | 思想                                                   |
| ---------------- | -------------------------------------------------------- |
| Develop        | 保留当前核心算法思想并继续完善                         |
| SemanticRepair | 保留当前算法思想，修正算法思想与实现之间的不一致       |
| Pivot          | 以当前算法个体为修改起点，更换核心机制                 |
| Transfer       | 将其他已评价算法中的有效思想或机制用于改进当前算法个体 |
| Restart        | 不以已有算法个体为起点，生成新的算法思想               |

改进机会的理想价值衡量当前选择对整个后续搜索的价值：现在选择该机会，并以最理想的方式使用剩余评价次数，搜索结束时预计能找到多好的算法。形式化为

$$
Q_b^*(\mathcal{H}_t,a)
=\sup_\pi\mathbb{E}_\pi\bigl[q(\hat P_B)\bigm|\mathcal{H}_t,a_t=a\bigr].

$$

其中：


| 符号                     | 含义                                                                                                      |
| -------------------------- | ----------------------------------------------------------------------------------------------------------- |
| $B$                      | 总评价次数                                                                                                |
| $t$                      | 当前已经进行的评价次数                                                                                    |
| $b=B-t$                  | 当前剩余的评价次数                                                                                        |
| $\mathcal{H}_t$          | 进行到第$t$ 次评价时的完整搜索历史                                                                        |
| $a$                      | 当前考虑的改进机会，即算法个体、算子和上下文的组合                                                        |
| $a_t=a$                  | 当前这一次确定选择改进机会$a$                                                                             |
| $\pi$                    | 完成当前改进后，后续评价预算的分配方式                                                                    |
| $\hat P_B$               | 用完$B$ 次评价后，搜索历史中适应度最高的算法                                                              |
| $q(\hat P_B)$            | 搜索结束时最好算法的适应度                                                                                |
| $\mathbb{E}_\pi[\cdot]$  | 按照分配方式$\pi$ 继续搜索时，对最终结果取期望；需要取期望是因为 LLM 生成具有随机性                       |
| $\sup_\pi$               | 在所有可能的后续预算分配方式中取最高的期望结果                                                            |
| $Q_b^*(\mathcal{H}_t,a)$ | 在当前搜索历史和剩余预算下，现在选择$a$ 所能带来的理想搜索结果；上标 $*$ 表示后续预算采用最理想的分配方式 |
| $\mid$                   | 表示“在右侧条件成立的情况下”                                                                            |

这个公式可以从右向左理解：当前搜索历史固定为 $\mathcal{H}_t$，当前选择固定为 $a_t=a$；随后按照某种方式 $\pi$ 分配剩余预算，并计算搜索结束时最好算法适应度的期望；最后从所有后续分配方式中取最高值。

例如，总评价次数为 $B=1000$，当前已经进行了 $t=200$ 次评价，则还剩 $b=800$ 次。$Q_{800}^*(\mathcal{H}_{200},a)$ 表示：现在选择改进机会 $a$，之后以最理想的方式使用剩余评价次数，最终能够得到的最好算法的期望适应度。

V10 不直接估计这个数值。它利用当前搜索证据，比较候选改进机会的相对价值。

## 3. 比较改进机会所用的证据

预算分配使用完整搜索历史 $\mathcal{H}_t$。其中，一个已评价算法的局部记录为

$$
s=(P,q,\tau,A,\Gamma).

$$


| 字段     | 记录内容                           |
| ---------- | ------------------------------------ |
| $(P,q)$  | 当前算法代码与适应度               |
| $\tau$   | 当前算法的形成路径                 |
| $A$      | 从当前算法出发已执行的修改尝试     |
| $\Gamma$ | 当前算法所属实验线程的后续改进结果 |

$\tau$ 由近期 Idea、结果与适应度变化组成。$A$ 按算子记录直接尝试，包括有效候选、无效输出、超时与重复。$\Gamma$ 按形成谱系记录一条实验线程消耗的评价次数及其最好适应度。线程是用于记账的形成谱系，不表示语义上的算法簇。

令 $B_h(\Gamma)$ 表示线程 $\Gamma$ 消耗 $h$ 次正式评价后的最好适应度。该线程相对起点的改进记为

$$
G_h(\Gamma)=B_h(\Gamma)-q_{\mathrm{origin}}.

$$

$G_h$ 记录该线程的最好适应度相对起点的变化。只有实际消耗至少 $h$ 次正式评价的线程才记录 $G_h$，缺失观察不补零。

适应度、一步改进、形成路径、尝试记录与线程结果共同用于比较改进机会。形成路径同时用于预算分配和 LLM 生成。尝试记录仅用于预算分配，默认不进入生成提示。

## 4. V10 的预算分配

V10 在每次正式评价前重新执行以下过程：

$$
\text{screening}
\;\longrightarrow\;
\text{valuation}
\;\longrightarrow\;
\mathcal{C}_t
\;\longrightarrow\;
\text{coverage}
\;\longrightarrow\;
\text{realization}.

$$

**Screening** 从已评价算法中选出有限个起点，用于控制估价规模。每个起点与算子及可用上下文组成多个候选改进机会。

**Valuation** 由估价器根据搜索历史比较候选机会，形成竞争集合 $\mathcal{C}_t$。竞争集合保留当前证据下值得使用正式评价的改进机会。

**Coverage** 在 $\mathcal{C}_t$ 内根据暴露次数选择机会。覆盖粒度为 $(s,o)$：

$$
C(a)=\bigl(n(s,o),\;n(\Gamma(s),o),\;n_G(o)\bigr).

$$

暴露较少的算法个体与算子组合优先获得机会，以控制评价预算过度集中在少数组合上。

**Realization** 将选中的算法个体、算子和上下文组织为 LLM 提示。LLM 根据算子的改进思想和给定上下文输出一句 Idea 和一份完整程序，交给评估器。评价结果更新搜索历史，然后开始下一次分配。
