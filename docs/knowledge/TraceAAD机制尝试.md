# TraceAAD 机制尝试：带时间坐标的历史决策与探索档案

本文提炼历史尝试留下的经验，区分实现失败、机制无效、改动混杂与验证不足。下文版本案例用于说明经验来源，具体结构演变见[历史机制探索](../methods/TraceAAD-历史机制探索.md)，版本设计与实现入口见[方法导航](../methods/README.md)。不在本页维护“当前版本”或运行状态。

## 1. 机制审视的四类失败性质界定

在审视历史探索的得失时，必须严格区分四种不同性质的“失败”，避免将工程缺陷或测试受限简单上升为对机制原理的否定：

| 失败性质 | 核心特征 | 典型历史案例 | 归因与反思边界 |
| :--- | :--- | :--- | :--- |
| **类型 1：实现失真或交互未正确运行**<br>(Implementation / Parsing Failure) | 代码或提示词实现存在缺陷，机制并未在环境中按设计合法执行。 | V4 结构化 Action 大量解析失败；早期全局反思多生成空洞模板。 | 属于交互格式与模型能力不匹配，**不能归纳为“结构化设计无用”或“反思机制原则上无效”**。 |
| **类型 2：机制按预期运行但实效不佳**<br>(Ineffective Design) | 机制完全按照设计逻辑正常运转，但在评测中未能达到预期收益或产生副作用。 | V8 子树最好成绩（max-backup）回传引发根锁定；V9.3 固定三步 rollout 失去即时重选机会。 | 机制设计本身与有限预算搜索特性存在冲突，属于真实的负面实证经验。 |
| **类型 3：多项改动混杂无法归因**<br>(Confounded Modification) | 在单次迭代中同时变动了多个控制器与上下文组件，导致因果关系不可分离。 | V1–V2 同时叠加岛模型、课程学习、Elo 评价与算子信用分配。 | 无法剥离各个组件的独立贡献，**不能由此断定其中某个具体策略单独有效或无效**。 |
| **类型 4：方案尚未充分测试或提前终止**<br>(Untested / Aborted Setup) | 因资源限制、有效率下跌触发安全中止协议、或处于原型期而未完成全量验证。 | V9.13 机制标签表因 CVRP 有效率下降 7.4pp 按安全协议中止。 | 属于安全截断或未完成探索，不宜作为终局定论引用。 |

## 2. 历代版本演进纪实（带时间坐标）

### 阶段一：控制器过度工程化（V1–V2，2026年6月）
- **当时假设与目标**：假设引入复杂的演化外壳（岛模型、课程记忆、Elo 竞技场、多目标 Pareto 筛选）能够协同攻克开放程序空间的探索难题；
- **实际实施与可见结果**：系统引入了大量超参数与状态模块，多变量严重混杂（**失败类型 3**）；整体搜索表现弱于后续大幅删减控制器的精简版本；
- **当时留下的客观经验**：在没有摸清基础生成机制前，堆砌外层控制器只会制造混杂噪声。

### 阶段二：回归轨迹与生成协议探索（V3–V5，2026年7月上旬）
- **当时假设与目标**：从复杂种群控制器回归，探索以“代码 + 形成链路”作为演化基底；尝试通过结构化 Action 契约（定义显式修改操作）与全局反思提升生成的规范性；
- **实际实施与可见结果**：V4 跑通了标准测试，但严格的结构化 Action 遇到了大量的格式解析失败，全局反思模块多生成空泛套话（**失败类型 1**）；
- **当时留下的客观经验**：预训练 LLM 对自由形式的“Idea + Code”具有更好的指令跟随鲁棒性；严格的 DSL 约束若频繁导致解析失败，会直接损害搜索有效性。

### 阶段三：代理指标尝试与单父树确立（V5.2–V8.3，2026年7月中旬）
- **当时假设与目标**：试图通过代码行数（LOC）、历史趋势坡度、节点成熟度以及子树历史最好成绩 $G(n) = \max\bigl(f(n), \max_c G(c)\bigr)$ 估计分支的“未来潜力”；
- **实际实施与可见结果**：实测显示 LOC 与最终效果相关性仅约 0.05；趋势指标频繁将局部抖动误判为高潜力；子树最好成绩回传使早期偶然突破的节点长期垄断预算，导致严重的根锁定与兄弟节点盲目爆炸（**失败类型 2**）；
- **当时留下的客观经验**：确立了**完整单父树（Single-parent Tree）**架构（保证历史事实完整留存，低分节点不物理删除）；认识到无条件祖先信用回传具有严重负面效应。

### 阶段四：决策粒度与多步 Rollout 权衡（V9.1–V9.4，2026年7月下旬）
- **当时假设与目标**：假设单步修改不足以跨越机制低谷，尝试通过固定 3 步 rollout 或路线连续推进来支持深挖开发；
- **实际实施与可见结果**：固定步数绑定导致当第一步已发生严重退化或报错时，后续预算仍被强制消耗，丧失了根据即时反馈重新选择的灵活性（**失败类型 2**）；V9.1 的推进率打分导致 88.9% 的预算偏移至低排名节点；
- **当时留下的客观经验**：真实 evaluator 评估是昂贵资源；逐步重决策具有宝贵的选项价值（Option Value）。是否绑定步数属于重决策频率的权衡，在缺乏明确前置验证时，过早预支预算往往得不偿失。

### 阶段五：形成轨迹受控验证与算子行为区分（V9.5–V9.8，2026年8月上旬）
- **当时假设与目标**：将历史信息的作用重心从“预算打分”转向“生成上下文”；探索在提示中加入父代形成来时路对生成的影响，并对比 Refine 与 Explore 算子的行为差异；
- **实际实施与可见结果**：三轮固定锚点实验证实，在相同代码基础上加入父代形成来时路（parent-path），四任务配对增益区间全部为正，72 个锚点中 58 个更好，核心表现为显著降低灾难性偏离；同时证实 Refine 与 Explore 诱导截然不同的改写幅度与即时收益分布；
- **当时留下的客观经验**：形成了轨迹作为生成上下文证据的实证基础；确认算子对应不同的设计意图与候选分布。

### 阶段六：复杂在线信号的再膨胀与收敛（V9.9–V9.22，2026年8月中下旬）
- **当时假设与目标**：再次尝试引入行为空间分析（BehaveSim、PSTraj）、机制标签表、前沿表、行为区域划分与假说 UCB，试图构建高度自适应的在线控制系统；
- **实际实施与可见结果**：V9.19 初版在正式评价后执行 `behavesim_v3_combined_panel`，行为邻域实际参与父代分配、Explore 调节和 Crossover 参考选择；其后改为 `behavesim_v4_train_trajectory`，五个 tracked evaluator 在正式训练执行内同步返回 fitness 和轨迹，并缓存节点轨迹、只增量计算新旧距离。V9.20 继续使用行为覆盖和参考检索，V9.21 明确让 BehaveSim 退出在线控制。在 Explore 中展示全局机制标签表虽降低了亚前沿重入，但在 CVRP 上引发过度重构导致有效率下降 7.4pp（**失败类型 4，按安全协议停止**）；多数复杂在线指标显著改变了树形与排序，但全预算端到端对比并未稳定超越简洁基线；
- **当时留下的客观经验**：“能改变搜索选择”不等于“具有预测价值”，群体几何有信息也不等于在线维护它划算。评价内采集与缓存不能消除 OBP 长前缀成对比较或 ACO 稳定化的成本。控制器可以记录丰富的原生事实；完整 BehaveSim 保留为离线解释工具，输入给生成模型的上下文仍应精炼聚焦。

### 阶段七：联合决策形式化与三算子批次（V10–V10.1，2026年9月上旬）
- **当时假设与目标**：将搜索决策明确抽象为 $(n, o, r)$ 三元组；在 V10.1 中采用同父代三算子批次（Refine、Pivot、Fuse 串行评测），旨在收集无偏的算子配对数据；
- **实际实施与可见结果**：系统清晰揭示了三类算子的有效性特征与退化风险，验证了算子条件化生成机制；但也观察到批次锁定在局部表现欠佳时延缓了转向；
- **当时留下的客观经验**：验证了不同算子语义对生成分布的调控作用；确认批次调度是用部分重选灵活性换取同父代算子横向覆盖的特定权衡。

### 阶段八：单步基线与生成机理深化（V10.5，2026年9月）
- **机制定位**：回归单候选单评价的逐步重决策机制，建立透明稳定的算子首发配比与选父规则，重点深挖上下文组织与提示指引机理。具体规范由方法文档定义。

## 3. 核心机制专题溯源

### 专题一：状态表示与存储结构
- **种群淘汰制（V2–V7）** $\to$ **完整单父树（V8 确立）** $\to$ **三层解耦（当前认识）**：
  从早期丢弃低分个体的有损做法，演进为完整单父树保存全部有效事实；进而明确区分**完整事实档案**、**在线繁衍资格**与 **Prompt 组织子集**，消除了历史留存与搜索偏置之间的冲突。

### 专题二：预算分配与选父准则
- **多维启发式打分（V2–V4）** $\to$ **子树后代回传（V8）** $\to$ **纯质量抽样（V9.16/V10）** $\to$ **结构化基线（V10.5）**：
  从试图构造未经检验的“未来潜力标量”，到确立以已兑现质量作为可靠的代码 scaffold，再到解耦决策对象、资源单位与重决策频率，逐步收敛至透明可归因的控制方案。

### 专题三：生成上下文与提示引导
- **格式强约束（V4）** $\to$ **来时路注入（V9.5–V9.7）** $\to$ **强身份契约（V10 早期）** $\to$ **硬契约+软指引（当前认识）**：
  从依赖严格 DSL 导致解析失真，到实证确立 parent-path 降低灾难性偏离的作用；再反思强制保留或强制新颖对求解逻辑的扭曲，最终收敛为“任务契约为硬约束，设计意图为软指引”的稳健生成准则。
