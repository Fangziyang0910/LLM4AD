当前认识见[研究认识](研究认识.md)。预算分配沿「到底在估计什么」这条线的经验见[预算分配](预算分配经验.md)。本文记试过什么、当时看见了什么。

## 2. 状态怎么存

试过：固定种群、完整单父树、按初始根划分的路线加锚点、Explore 开启的分段标记、只保留算法节点的纯树。

固定种群会把低分个体丢掉，后面无法再改。树把有效节点留下来，父链记录这条函数怎么形成。路线是同一初始根下的形成记录。

## 3. 给哪个节点机会

| 尝试 | 结果 |
| --- | --- |
| 质量、多样性、潜力、Elo 一起打分 | 互相干扰，无法归因 |
| 把后代最好成绩计入当前分数 | 早期高分把预算锁住，兄弟节点铺开 |
| 用路线最好成绩被刷新的频率分配 | 偏向低质量上的小幅自刷新 |
| 用锚点质量与子代分数的均值 | 把节点自己的质量和未成熟子代混在一起 |
| 一次选中后连续走三步 | 失去每步重选 |
| 路线加锚点的乐观项 | 路线层几乎不改选择（1.07%）；锚点层常改 |
| 给 Explore 子代质量宽限 | 有的任务能缓一口气，有的把主线冲散 |
| 按质量名次做概率采样 | 树变大后宽度居高不下，深改写被摊薄 |
| 锚点×算子的跨代后验 | 终局 36%–53% 动作还没有结果，分配近似摊开 |
| 用最近 Refine 成败调 Explore 概率 | 改写了 10%–16% 的算子选择，任务间方向不同 |
| 把历史累计增益加进分数 | 排序被改写，但预测不了下一步 |
| 只按当前质量、放宽采样，并随机给三步续改 | OP/TSP/VRPTW 变好，CVRP 上深改写被摊薄 |
| 用质量、行为邻域、欠开发和轨迹响应联合打分 | 经常改变纯质量排序，但被选节点仍集中在高质量、低欠开发区域；质量与邻域质量高度相关，轨迹项实际变异最小 |

## 4. 怎样帮它决策

| 尝试 | 结果 |
| --- | --- |
| 四五种复杂算子，包括跨路线拼接 | 拼接容易把算法写坏 |
| 要求模型输出固定 JSON/DSL | 大量解析失败 |
| 先让模型做诊断规划再写代码 | token 和墙钟翻倍，规划常事后找理由 |
| Refine / Explore 两种提示 | 改写幅度和即时质量分开；Refine 更小更稳，Explore 更大、即时更差 |
| 当前代码 + 父代来时路 | 四任务单步质量上升，大幅改写减少 |
| 来时路之外再加已有子代尝试 | 没有稳定额外价值 |
| 在 Explore 提示里展示机制标签和前沿分数 | 单步有时变好，CVRP 有效率下降，按协议停止 |
| Local / Mechanism / Structural / Crossover 四算子 | Local 的即时改善率在五任务都不低于 Mechanism；Structural 行为步幅大但质量转化弱；Crossover 在 OP/OBP 有任务相关收益 |
