# EoH-S

- 论文：*EoH-S: Evolution of Heuristic Set using LLMs for Automated Heuristic Design*；本地来源：[`eohs.tex`](../../../../papers/EoH_S_Evolution_of_Heuristic_Set_using_LLMs_for_Automated_Heuristic_Design/eohs.tex)；设计对象：一组协作/组合使用的启发式，而非单一启发式。

## 1. 核心问题与方法

EoH-S 指出单一启发式通常只能覆盖问题的一部分状态或实例分布，因此演化对象扩展为 heuristic set：搜索对象从单个 $h$ 变为集合 $H$（$1<k\ll m$），要求每个实例至少被集合中一个成员优化好。**评价方式与单启发式相同**：每个体在 $m$ 个实例上正常评价，得到实例级性能向量；集合分 CPI = 各实例最优成员分数的均值，是选择期的聚合，不对集合整体做额外评价，也没有组合器——推理期按实例选最优成员即可。选择机制是互补种群管理 CPM：从 $2n$ 候选贪心选 $n$（每步选 $\arg\max\Delta CPI$，超模性给出 $(1-1/e)$ 型贪心保证）；CS 算子按实例级性能向量的 Manhattan 距离选"行为最互补"的父代对。

## 2. 论文宣称的机制贡献（逐项）

- 启发式集合可利用成员间互补性，应对单规则的偏数；CPI 单调且超模，贪心选择有近似保证。
- CS 亲代选择把互补性变成生成信号（Manhattan 距离最远的父代对，prompt 告知两算法"对不同实例分布有效"）。
- CPM（集合级选择信号）是最大贡献项：消融中去掉 CPM 退化为按平均分保留（0.0373 vs 完整 0.0326），落到与 ReEvo Top10 相当；w/o CS 与 w/o LS 各只贡献约 0.001。

## 4. 机制的底层逻辑

阅读分析：集合的价值来自条件分工：不同启发式在不同实例上赢，CPI 把"每个实例被集合覆盖到多好"直接写成目标。信用分配在实例级向量上天然成立（每个成员在每实例有独立分数），不需要组合器；Top10 基线对照（直接检验"演化保留的 10 个是否天然互补"——答案是否）排除了"多候选本身带来收益"。实例分布单一时互补空间小、方法退化为精英选择（作者在 OBP/CVRP 对比中自证）。

## 5. 对 LLM4AD / TraceAAD 可学习之处

- 可学习点：把“多条历史路线”当作可条件选择的库。前提：有可靠的选择条件。风险：库只增加 token 和评估开销。最小验证：固定总生成数，比较单候选、随机集合与条件集合。
- 可学习点：为每个成员记录何时被采用。前提：运行时可观测。风险：只看总分无法信用分配。最小验证：成员 leave-one-out 及实例级胜率。

## 6. 证据边界

集合大小、成员生成成本、组合器、评估实例和种子都会影响结果；没有集合大小匹配的预算对照与成员消融时，不能把主表优势解释为互补性。集合对未见实例是否泛化还须独立测试。
