# LLM 辅助自动算法搜索的适应度景观

核对论文：[Fitness Landscape of Large Language Model-Assisted Automated Algorithm Search](../../../papers/Fitness-Landscape-LLM-Assisted-Automated-Algorithm-Search/manucript.tex)，arXiv:2504.19636v3，2026-08-02。

## 论文的研究对象与核心判断

论文把 LLM 辅助算法搜索产生的候选算法及其父子生成关系表示成图，以观察实际搜索过程经过的适应度景观。论文报告，这类景观通常多峰、连接稀疏、缺少清晰的漏斗结构，而且景观形态会随任务、LLM 和种群规模明显变化。由此，论文将搜索空间视为一个受模型、提示算子和搜索配置共同塑造的可达区域，而不是一个具有固定几何结构、可以由单一搜索策略稳定处理的空间。

这里的“适应度景观”更准确地说是搜索过程诱导出的经验景观图。论文没有枚举完整算法空间，也没有为任意两个算法预先定义邻域；只有被实际生成的算法进入节点，只有真实发生的父代到子代生成关系形成邻接。因此，图中看到的结构同时反映任务本身、LLM 生成先验、EoH 算子以及有限预算下的采样历史。

## 研究问题与实验范围

论文围绕三个问题展开：怎样表示和刻画 LLM 驱动算法搜索的适应度景观；不同任务、LLM 与搜索配置如何改变景观；怎样度量算法相似性，以及相似性与性能变化、算子行为之间有什么关系。

实验统一使用 EoH 搜索框架，采用默认初始化提示和 E1、E2、M1、M2 四类 LLM 搜索算子。默认种群规模为 20，每次运行最多评估 2,000 个候选算法，并记录候选的适应度和父子生成关系。

六类任务包括四类组合优化启发式设计任务，即在线装箱（OBP）、旅行商问题（TSP）、容量车辆路径问题（CVRP）和带时间窗车辆路径问题（VRPTW）；智能体设计任务 Mountain Car（Car）；以及符号回归任务细菌生长曲线拟合（Bact）。六个模型是 GPT-3.5-Turbo、GPT-4o-Mini、DeepSeek-V3、DeepSeek-Chat、Qwen2-Turbo 和 GLM-3-Turbo。全部实验在 LLM4AD 平台上执行。

## 适应度景观的分析方法

### 经验景观图

论文从经典三元组 $(S, NS, f)$ 出发，其中 $S$ 是候选算法空间，$NS$ 是邻域关系，$f$ 是任务适应度。由于代码算法没有天然且可靠的距离和邻域，论文不先定义几何近邻，而是用实际生成关系定义邻域：若 $a_j$ 由以 $a_i$ 为父代的 LLM 搜索操作直接生成，则 $a_j \in NS(a_i)$。

由此构造图 $G=(N,E)$。节点代表搜索中生成的候选算法，节点颜色或三维高度表示适应度；论文中的目标均按越小越好展示，深色表示更优。边代表直接父代—子代关系，景观总览使用无向边，边权是相同转移发生的次数。演化路径分析改用有向边，从父代指向子代，并以到最优算法的路径距离进行层级布局。二维图用于观察连通结构，三维图把适应度作为 z 轴，归一化适应度分布用于比较不同任务。

这种表示绕开了“代码算法之间没有公认距离”的困难，也保留了搜索的真实来时路。但边表示的是生成关系，不表示边长意义上的算法距离。

### 跨任务景观比较

论文对六个任务分别构图，并结合两类证据判断景观形态：一是二维或三维图中的峰、局部区域、连接与整体形状；二是归一化到 $[0,1]$ 后的候选适应度概率分布。这部分用于识别多峰、近似局部最优、漏斗结构、连通性和任务间的分布差异。

论文对“多峰”和“崎岖”的判断主要来自图形与分布观察。论文没有给出自相关长度、fitness-distance correlation、局部最优数量或 ruggedness index 等独立量化指标。

### 跨 LLM 的图结构比较

论文固定 TSP 任务，使用三个网络指标比较不同 LLM 诱导出的景观。Density 是实际边数占全部可能边数的比例，用于衡量整体连接密度；Average Degree 是节点平均连接数，用于衡量候选之间的平均连接广度；Clustering Coefficient 表示节点形成局部团簇的倾向，用于衡量局部社区结构。

作者将高密度、高聚类解释为更多局部搜索与精炼，将稀疏、低聚类解释为更少冗余转移和更偏全局的探索。这是依据图结构作出的行为解释，并非直接测量“全局探索距离”。

### 种群规模比较

论文固定 DeepSeek-V3 与 TSP，将种群规模设为 2、5、10、50，比较二维和三维景观。图中还突出显示权重大于 1 的边，以观察频繁发生的转移。作者据此分析种群规模如何改变候选覆盖、分支和重复连接：小种群集中于局部利用，大种群覆盖更广并暴露更多尚未探索的峰。

### 演化路径分析

论文从最优候选反向追踪其祖先链，绘制带方向的父子网络。该图同时显示算法编号、适应度和层级，用于识别搜索从哪些分支到达最终最好算法、哪些修改带来明显性能提升，以及哪些当时性能较差的中间算法后来成为通往更好算法的踏脚石。

这项分析强调，父代当下的适应度不能完整代表它对后续搜索的价值；改进历史本身包含下一步搜索可以利用的路径信息。这一表述是从路径图得到的作者解释，不能直接等同于已经完成的因果验证。

### 四类代码相似度

由于景观图的边长不代表真实算法距离，论文进一步在 TSP 和 OBP 上比较四种代码相似度。BLEU 使用代码 token 的 1–4 gram 重合与长度惩罚，主要反映词法表面相似；Weighted BLEU 提高 `return`、`for`、`while` 等编程关键词的 unigram 权重；AST Match 忽略叶节点后比较抽象语法树子树，反映程序结构相似；Data-flow Match 比较变量依赖和数值传播的数据流图，更接近语义关系。

分析以父子算法对为单位，同时计算相对性能差（performance delta）。论文使用 KDE 比较不同任务的指标分布，并用散点图、线性拟合和相关系数检查四个相似度之间、相似度与性能差之间的关系；论文还按 E1、E2、M1、M2 比较性能差和 Data-flow Match 的分布。

## 论文报告的重要发现

### 景观通常多峰、稀疏且缺少漏斗结构

作者观察到多个近似局部最优，搜索没有自然汇聚到单一优质区域。景观平均度低、连接稀疏，说明有限搜索过程形成了相对碎片化的分支，有益思想在不同区域之间传播的机会有限。论文将缺少漏斗结构归因于 LLM 生成的随机性，以及缺少明确的几何约束和搜索方向。

任务差异明显。四类组合优化启发式设计中，大量候选聚集在归一化目标值较低的区域；论文报告约 80% 的算法落在最低 20% 的目标值区间。VRPTW 因时间窗约束更难到达精英区域。Car 呈明显双峰，大量较差候选与少量很好候选之间缺少中等水平算法。Bact 中约 98% 的候选离最优值很远；作者认为，符号表达式及参数的微小改变就可能引起巨大性能变化，因此该景观尤其敏感。

### 不同 LLM 诱导出不同搜索结构

在 TSP 上，GLM-3-Turbo 的密度（0.00223）和聚类系数（0.02282）最高，Qwen-Turbo 的平均度（4.76190）最高；作者将二者解释为更密集的局部搜索。DeepSeek-Chat 的密度（0.00069）、平均度（2.15053）和聚类系数（0.00180）均最低，被解释为更稀疏、冗余更少且更偏全局的搜索。GPT-3.5-Turbo 和 GPT-4o-Mini 位于中间，DeepSeek-V3 呈较稀疏、拉长的结构。

论文据此提出，模型选择不只是更换候选生成器，也会改变搜索实际面对的景观和探索—利用行为。密集结构利于局部精炼，但可能更易停在局部区域；稀疏结构利于扩展覆盖，但可能损失精炼能力。作者进一步推测，具有互补行为的多模型组合可能比单一模型更合适。“互补组合更合适”是作者基于图结构与行为解释提出的推测，而不是该实验直接完成的组合消融结果。

### 种群规模改变可见景观，而不只是运行成本

种群规模为 2 和 5 时，搜索更集中于局部利用；规模为 10 和 50 时，分支与覆盖范围增加，并显露更多峰。作者据此认为，大种群提供更广的探索，小种群提供更强的局部集中。种群规模因此被视为塑造经验景观的机制参数，而不只是并行度或预算参数。

### 暂时退化的候选可能是必要踏脚石

最优算法祖先链中存在性能暂时较差、随后通向更优候选的节点。这说明只保留单调改进路径可能丢失具有长期价值的思想；分析搜索机制时应同时看最终性能和实际改进路径，而不能只看每一步是否立即提升。论文展示了这一单次路径现象，但是否稳定提高最终性能仍需对照实验。

### 代码相似度可以描述算子倾向，但难以预测性能

四个相似度在 TSP 和 OBP 中彼此强正相关。TSP 上 AST Match 和 Data-flow Match 与性能差的相关性相对最高；总体上，相似度越高，父子性能差越小。OBP 的关系更弱且不一致，尤其 BLEU 和 AST Match 难以预测性能变化。TSP 的 AST/Data-flow 分数整体更高，OBP 分布更分散，反映任务间的实现多样性不同。

在算子层面，E1 的性能变化方差和中位数最大、Data-flow Match 最低，表现为更激进的探索；M1、M2 的 Data-flow Match 更高且性能差分布更紧，表现为语义保持程度更高的利用。论文认为，多类算子的互补形成了不同搜索步长，有助于平衡探索与利用。

然而，所有代码相似度对性能差的相关性都较小且随任务变化。相同算法可以有多种代码实现，词法或结构相似不等于功能相似。作者因此把 LAS 专用算法距离视为关键研究缺口，并建议进一步使用执行轨迹、复杂度分析或学习得到的功能表示。

## 本笔记的综合解释与 TraceAAD 启示

从论文的经验景观定义出发，本笔记的综合解释是：景观并非独立于搜索器而预先存在的对象。任务、模型、提示算子、种群规模、去重和有限预算共同决定哪些候选会出现、哪些父子关系会被观察到。因此，同一套选择逻辑在不同任务和模型上面对的可达区域与邻接结构可能不同，难以依靠一组固定的种群规模、选择压力和算子比例适配所有任务。

这对自动算法设计的直接启示是，搜索管理需要同时保留局部精炼与跨区探索。论文的图结构和算子分析都指向两者互补；有效机制需要识别何时沿当前分支深化，何时切换生成行为或模型。最优解的祖先链还说明，改进历史具有独立信息：它揭示有效分支、暂时退化和关键跃迁，仅以当前候选适应度压缩历史，会丢失未来路线选择所需的证据。

对 TraceAAD 而言，轨迹可以作为一种保留算法来时路的组织方式：它记录候选从什么方案出发、经历了什么修改以及修改后产生了什么结果。轨迹信用若要支持路线选择，应同时区分当前质量、后续贡献和暂时退化的中间状态。论文留下的总体启示是，功能行为距离比代码表面距离更接近真正的算法空间；因此，若使用相似度进行去重、生态位、信用分配或新颖性调度，应优先验证它是否反映执行行为与性能，不能直接把 BLEU/AST 距离当作算法距离。这些是本笔记基于论文结果对 TraceAAD 的设计推论，不是论文对 TraceAAD 的直接实验结果。

## 证据边界

图只覆盖 EoH 在有限预算内实际访问的候选，因此不能直接等同于完整、搜索器无关的算法空间景观。“多峰”“崎岖”“缺少漏斗”的证据主要是可视化和适应度分布；论文没有给出经典崎岖度或漏斗性的定量检验，也没有严格定义和计数局部最优。

密度和聚类既受 LLM 行为影响，也受重复候选、生成协议、去重规则、预算和图构造方式影响。将其解释为局部或全局搜索倾向具有启发性，但不是因果识别。论文主要使用一套 EoH 框架，不同选择、记忆、反思、树搜索或轨迹搜索机制可能诱导出不同景观。

四种相似度只在 TSP 和 OBP 上重点分析，且与性能变化的相关性较弱，不能据此建立跨任务通用的算法距离。论文展示了单次路径中的踏脚石现象，但没有通过对照实验检验“允许退化候选”是否稳定提高最终性能。
