# AAD 与 AHD 的算子设计调研

本文从**算子**视角纵读论文库中的 59 个方法（44 个直接 AAD/AHD，15 个广义程序与算法发现），回答四个问题：各家设计了什么算子、为什么这样设计、他们把算子理解成什么角色、算子周围有哪些上下文机制。全部条目经论文原文（tex 或 PDF）核对，方法清单与元数据见[LLM 自动算法设计方法汇总](LLM自动算法设计方法汇总.md)；研究"算子本身产生什么搜索偏置"的诊断类论文另见[LLM 作为进化算子的机制分析](LLM作为进化算子的机制分析论文.md)，与本文互补。

**算子的口径**：凡是把"已有算法程序 + 若干信息"变为"新候选程序"的生成机制都算算子——提示式变异/交叉/改写、RL policy 的动作、latent 空间的梯度步、多智能体的生成动作均在内。选择、接受、预算分配机制在算子之外，但它们决定"算子在哪里、以什么条件被调用"，作为上下文机制一并讨论。**上下文的口径**：算子调用时条件到的全部信息，包括 prompt 里的父代与文本、以及决定谁进 prompt 的选择结构。

一条贯穿全文的观察先放在这里：**算子角色经历了四次重定位**——(1) 语义变异/交叉（把人类修改先验装进 EA 算子）；(2) 带上下文的条件生成（反思、记忆、规划进入 prompt，算子本体不变）；(3) 采样管线中的 proposal（proposal—acceptance—resampling—schedule 显式分离，算子成为被调度的采样单位）；(4) 可学习的策略/智能体动作（算子内化进权重或升格为自主决策）。下文十节按此谱系展开。

## 一、奠基：把 LLM 安装进变异与交叉（2022–2023）

| 方法 | 生成算子（原名） | 输入与上下文要点 | 角色定位（论文原话） |
| --- | --- | --- | --- |
| [ELM](../../../papers/Evolution_through_Large_Models/) | Diff mutation（单算子，无交叉） | 1 父代全码 + commit message（如 "Changed parameters…" 按概率抽样）；prompt 不含适应度与历史 | "intelligent perturbation operator"，在代码流形上模仿人类程序员 |
| [LMX](../../../papers/Language_Model_Crossover_Variation_through_Few_Shot_Prompting/) | LMX = ψ(LLM(φ(x₁,…,x_k))) | k 个父代文本按序拼接，无指令、无分数；k=1 退化为变异 | "intelligent evolutionary crossover"；也被证明与选择算子合成一个 EDA |
| [LLM_GP](../../../papers/Evolving_Code_with_A_Large_Language_Model/) | 8 个 LLM 化算子：i/e/φ/s/v_xo/v_mu/r/b | 每算子一个 prompt-function，文法 `<EXAMPLES><QUERY><PRIMITIVES><RESPONSE_FORMAT>`；few-shot 例取自当前种群 | "prompt 驱动的 EA 算子角色"，把选择/替换/排序也 LLM 化 |
| [FunSearch](../../../papers/Mathematical_discoveries_from_program_search_with_large_language_models/) | Best-shot prompting（变异+交叉合一） | 同岛采样 k=2 个程序按分数排序改名 v0/v1，抽掉待演化函数、末尾留 v2 空头让 LLM 补全；分数不进 prompt 文本 | "an instance of genetic programming with the LLM acting as a mutation and crossover operator"；LLM 是 "the creative core" |

设计动机的共同起点是对随机算子的批评：GP 的离散随机扰动"常导致功能剧变"（ELM §2.1）、"designing effective and general code mutation operators remains difficult"（FunSearch Related Work）。LLM 预训练于人类代码与代码修改，天然带有"像人会做的修改"的先验，能一次协调多处相关修改。四篇的贡献分别是：ELM 用在 GitHub diff 上训练的 300M 模型证明该先验存在（4-Parity 上 diff 变异一次修复 5 个耦合 bug，随机变异 10 万次无一成功），并率先演示算子自改进（用被接受 diff 微调 diff 模型）；LMX 把算子写成 few-shot 拼接的闭式公式，证明多父代上下文产生可测的特征继承，且父代按适应度排序本身就是一种软选择压力；LLM_GP 给出形式化词汇表——哪个 EA 环节可以被 LLM 化、每个算子的 prompt 是新超参数，并首次把 token 成本与错误率算作算子设计维度（实测 selection/replacement 的 prompt 最贵最易错）；FunSearch 把这条线工程化：skeleton 固定已知结构只开放关键函数、岛模型 + signature 聚类的 Boltzmann 分数加权采样 + 短程序偏好把评价反馈**只**写进"谁被放进 prompt"，evaluator 负责挡住幻觉。

这一阶段确立的两个默认约定被后来几乎所有方法继承：**分数不进 prompt 文本，选择压力经由父代挑选与排序间接进入**（FunSearch 采纳了 LMX 的排序发现）；**算子只提议，evaluator 只裁决**。

## 二、EoH 模板：prompt 策略谱系与它的后代（2024–2026）

[EoH](../../../papers/Evolution_of_Heuristics_Towards_Efficient_Automatic_Algorithm_Design_Using_Large_Languag/) 把"prompt 措辞"本身做成算子谱系：个体为 (思想描述, 代码) 双表示，五个进化 prompt——探索组 **E1**（5 父代，要求新启发式"as much different as possible"）、**E2**（5 父代，先识别共同 "backbone idea" 再据此生成不同实现）；修改组 **M1**（改结构）、**M2**（只改参数）、**M3**（分析并删除冗余组件），外加初始化 prompt。动机是"模仿人类专家的启发式开发过程"（演化 thoughts 与 codes），对照 FunSearch "evolves codes only and does not use prompt strategies explicitly"。上下文机制极简：父代按 rank 概率 p∝1/(r+N) 采样，prompt 含任务 + 策略指令 + 父代（描述+代码），无分数无反馈；消融显示思想通道贡献显著（仅代码的 EoC 最差）。

| 方法 | 对 EoH 算子谱系的改动 | 创新落点 |
| --- | --- | --- |
| [MEoH](../../../papers/MEoH/) | 五算子原样继承（M3 改写为"识别过拟合组件、简化以增强 OOD 泛化"） | 选择端：dominance-dissimilarity（Pareto 支配掩码 × AST 距离）采样父代与管理种群 |
| [HSEvo](../../../papers/HSEvo/) | 换成 crossover（2 父代显式标注 better/worse + flash reflection 指导）+ elitist mutation + 和声搜索参数优化（LLM 抽参数、经典 HS 调参，M2 被**非 LLM** 数值搜索取代） | 代级 flash reflection 批量压缩（批评 ReEvo 逐对反思浪费资源）；批评 EoH "does not focus enough on exploitation" |
| [QUBE](../../../papers/QUBE_Enhancing_Automatic_Heuristic_Design_via_Quality_Uncertainty_Balanced_Evolution/) | 零改动——FunSearch 的双父代补全 prompt 逐字沿用 | 选择端：UIQ = 簇的子代平均质量 + UCB 访问计数不确定性，用于父代簇选择与岛重置；逐级消融直接支持三层设计 |
| [CDEoH](../../../papers/CDEoH_Category_Driven_Automatic_Algorithm_Design_With_Large_Language_Models/) | 压缩为 innovation/improvement 两个单父代 prompt，删除交叉；新增 reflection 错误修复算子与 category induction（生成评估**之后**打标签，只进选择不进 prompt） | 选择端：类别两阶段精英 + 稀有类加成 λ/|C(i)| |
| [EoH-S](../../../papers/EoH_S_Evolution_of_Heuristic_Set_using_LLMs_for_Automated_Heuristic_Design/) | 收敛为 CS（互补感知搜索：实例级性能向量 Manhattan 距离最大的父对）+ LS（即 M1） | 上下文的语义化：prompt 告诉 LLM 两父代"effective for solving different instance distributions"；集合端 CPM 超模贪心 |
| [Controlling Mutation](../../../papers/Controlling_the_Mutation_in_LLMs_for_Efficient_Evolution_of_Algorithms/) | LLaMEA 的 (1+1) 变异 prompt 加"只能改 x% 代码"指令族（手工 1–5、自动 6–11） | 变异率控制：x 从 fast-mutation 幂律采样；GPT-4o 可执行速率指令，GPT-3.5 基本失败；不指定时两模型都倾向极端变异 |

这组的主演进而用一句话概括：**创新重心从"prompt 里写什么"移到"谁被放进 prompt"**。MEoH、QUBE、CDEoH、EoH-S 的算子文本几乎照抄前人，全部改动在父代选择与种群管理；HSEvo 与 Controlling Mutation 是仅有的两个继续在算子文本上下功夫的（前者换算子族并给反思留槽位，后者把 GA 变异率理论移植到 prompt 层）。EoH-S 值得单独记：它把"上下文选择"变成一个显式优化问题（argmax 互补父对），并用一句自然语言把互补性语义传给 LLM——这是"选择信号进 prompt"的最早干净示例。

## 三、反思与元认知：把评价信息写进生成条件

[ReEvo](../../../papers/ReEvo/) 首次把评价反馈转译为算子上下文：generator 与 reflector 两个 LLM 角色；短期反思对 (worse, better) 父代对做比较分析进 crossover prompt；长期反思递归压缩为 ≤50 词的单一滚动文本，条件化 elitist mutation。角色理解是本文最值得继承的部分——用适应度景观把反思理论化：邻域定义为 N(h_c)={h | LLM(h|h_c,x)>ξ}，反思改变 prompt x 即改变邻域结构，故称 "verbal gradient"；实测带反思的 correlation length 1.28 vs 无反思 0.28（邻域更平滑）。此后四篇沿"反思产物的位置"递进：

| 方法 | 反思产物的位置 | 关键机制 |
| --- | --- | --- |
| [ReEvo](../../../papers/ReEvo/) | prompt 槽位：短期反思进 crossover，长期反思进 elitist mutation | 字数上限即压缩；无检索无打分 |
| [HiFo-Prompt](../../../papers/HiFo_Prompt_Prompting_with_Hindsight_and_Foresight_for_LLM_based_Automatic_Heuristic_Des/) | 被管理的知识资产：Insight Pool（准入 Jaccard<0.7、按 utility 检索 top-3、分段信用 EMA、eviction 淘汰）+ foresight 三态指令（种群停滞计数 + 表型多样性 → Explore/Exploit/Balance 指令池） | 生成算子完全照搬 EoH 五模板，只加两个上下文插槽；关键消融：把相同 seed insights 注入 EoH/ReEvo/HSEvo/MCTS-AHD 增益可忽略——**收益来自管理架构而非知识本身** |
| [EvoPH](../../../papers/Experience-Guided_Reflective_Co-Evolution_of_Prompts_and_Heuristics/) | 被进化的对象：meta-prompt 用父子指标差 + 完整对话史重写演化 prompt 本身；另按经验采样 5 档探索强度的策略（参数修改→…→完全重写） | "elevate the evolutionary search from the program level to the prompt level"；prompt 演化同时提高可执行率 |
| [MeLA](../../../papers/MeLA_Metacognitive_LLM-Driven_Architecture_for_Automatic_Heuristic_Design/) | 唯一搜索对象：放弃种群动力学，metacognition 读全部 thoughts/errors/fitness 输出 ≤80 词反思，条件化唯一的 Metacognitive Generation 算子 | "evolves the problem-solving strategy itself, which is encoded in the LLM's guiding prompt"；批评 ReEvo 交叉要求可执行父代、不可执行则停摆 |
| [MeEvo](../../../papers/MeEvo_Metacognitive_Evolution_for_Automatic_Heuristic_Design/) | 与代码并立的基因型：reasoning trace 是可遗传基因型、代码是表型；自然进化（LLMCrossover/LLMMutate，强制生成 reasoning trace）与元认知进化（结构化 Meta Insight：收敛诊断/局限分析/路径建议）按 N:M=2:1 循环交替 | 交替而非并行的操作性理由：交叉需要稳定父代池、反思需要跨代历史；算子比率 p_c 从 0.7 线性降至 0.5；消融 (2,1) 最优、纯 NE/纯 ME 均差 |

演进逻辑：反思产物的载体从 prompt 槽位 → 被打分检索的知识池 → 被进化的 prompt → 唯一搜索对象 → 与代码并立的遗传实体。算子相应从"变异 + 反思上下文"演化为"表型变异算子 + 基因型反思算子"的双进程体系。

## 四、树与规划：算子作为被调度的扩展动作

[MCTS-AHD](../../../papers/MCTS-AHD/) 把 EC 算子搬进树并发明树原生算子：六个动作 **i1/e1/e2/m1/m2/s1**——e1 在根节点做跨子树交叉，e2 用"父代 + elite set 采样参考"做交叉，m1/m2 是机制/参数变异，**s1 是树路径推理**（把根到叶路径上所有 unique 启发式给 LLM，先列 helpful ideas 再综合）。动机直接批评种群法"directly discards low-performance heuristics… falling into local optima"——树允许 worse-before-better。分工：UCT + 渐进扩展（⌊N^0.5⌋）+ max 回传决定算子在哪里调用；生成后二次调用做 thought-alignment（先码后述，避免先描述后码的幻觉）。s1 的消融正面支持"树结构本身催生新算子"。

| 后续 | 改了哪一侧 | 要点 |
| --- | --- | --- |
| [PoH](../../../papers/Planning_of_Heuristics_Strategic_Planning_on_Large_Language_Models_with_Monte_Carlo_Tree/) | 生成侧 | 唯一算子族 = "建议→执行"两段式：自反思产出 improvement suggestion（动作），optimizer LLM 按建议改码（转移）；state_transit prompt 同时放示例、建议与**祖先链**；受控消融固定算子只换 MC/Greedy/Beam/MCTS，证明规划层本身的贡献 |
| [PathWise](../../../papers/PathWise/) | 两侧 | 动作 = (父集 S, 自由文本 directive κ)——"the policy can dynamically invent new operator types through κ"；policy agent 提议、world model 执行 N_w 个 rollout、双 critic 反思路由；**取消 UCT 与访问数**，预算交给 argmax + leaf-first 种群管理；谱系变为可多父的 entailment graph + 压缩父代元数据 |
| [Clade-AHD](../../../papers/Clade-AHD_Clade-level_Selection_for_MCTS_in_Automatic_Heuristic_Design/) | 只改选择，生成冻结 | prompt 与六动作**逐字沿用** MCTS-AHD；节点点估计换 clade 级 Beta 信念（深度衰减聚合 + Thompson 采样 + 冻结 + 预算退火）；理由是 stepping-stone 节点孤立看差但后代优，稀疏评价下 UCT 点估计失真 |
| [CogMCTS](../../../papers/CogMCTS_Cognitive-Guided_MCTS_for_Iterative_Heuristic_Evolution/) | 生成侧的上下文供给 | 骨架照搬 MCTS-AHD，交叉替换为 em1（CCS 候选集配对组合）与 em2（全局最优引导）；两阶段认知（rapid 两两对比 → complex 整合 K⁺/K⁻ 知识库）注入两个 em 算子；CKV 用前后 global-best 变化验证知识正负归属 |

组内分工演化：生成算子从固定模板（MCTS-AHD）→ 建议-执行两段式（PoH）→ 策略自由发明的 directive（PathWise）→ 认知知识库注入（CogMCTS），越来越依赖上下文而非模板；选择机制分岔出贝叶斯谱系信念（Clade-AHD）与反思路由 + 种群管理（PathWise）。一个反复出现的模式：**每篇都保留"祖先谱系 + 全局精英"两类跨分支上下文**，承载形式分别为 elite set / trajectory / PM+reflection / CCS+K⁺K⁻ / clade 信念。

## 五、调用条件：调度、时机与在线共生

这组方法不改算子内容，改算子**何时、何地、以什么版本**被调用。

| 方法 | 改变的调用条件 | 角色定位 |
| --- | --- | --- |
| [RefineEvo](../../../papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/) | Planner 按种群状态（多样性、收敛率）与算子统计（成功率、无效率）选算子并触发算子改写；算子库 op1–op5 改编自 EoH，其**自然语言描述本身**被在线改写（incremental/radical 两模式）；Reflector 产出经验条目入 E⁺/E⁻ 双银行（utility 信用 + 矛盾消解 + top-3 检索） | "operator selection adapts *which* operators to apply, operator refinement adapts *how* each operator guides generation"；算子是被调度的 prompt 资产；选择性调度把 token 开销从约 965K 压到 511K |
| [BaSE](../../../papers/Compute_Allocation_in_Evolutionary_Search_From_Depth_Breadth_to_Multi_Armed_Bandits/) | 算子与 prompt 全冻结，研究 C=T·N 的深广划分与 K 条轨迹间的 bandit 路由（improving bandits，UCB/EXP3.P/Thompson） | "not a model improvement, nor a prompt improvement, but an allocation improvement"；发现双线性 production law 与平台半宽；机制解释：轨迹在前几代锚定算法族，广度给更多找到可行族的并行机会、深度在族内精炼 |
| [EvoStage](../../../papers/EvoStage_Evolutionary_Stagewise_Algorithm_Design/) | 设计对象按时段拆分：Stagewise-Design 由 coordinator 分解 K 个阶段、coder 逐段生成，输入**该阶段执行后的中间反馈**（如当前 wirelength/overflow 及变化）；Global-Explore/Enhance 保留 one-shot 整体生成作"全局视角"；三算子 1:1:1 固定频率 | 针对 black-box modeling：只有终态分数使 LLM 无法利用中间反馈纠正设计方向；还关闭了 EoH 式 thought-of-code（稀缺数据场景加剧幻觉） |
| [DyACE](../../../papers/DyACE_Dynamic_Algorithm_Coevolution/) | 算子调用主体移入求解过程：每 5 代解进化触发 1 代算法进化；三模式 Combine/Mutate/Explore 全部两阶段 think-then-code，Diagnosis Agent 把 solver 的搜索轨迹特征（landscape kinematics + operator telemetry）翻译成 verbal gradients 再驱动 Coding Agent | grounded meta-controller（receding horizon）；关键反面证据：DyACE-Blind（保留在线循环、去掉特征提取）劣于静态版本——**无感知的频繁算子改写是随机游走** |

## 六、历史结构与知识态：从种群副产品到一等输入

| 方法 | 历史的表示 | 算子与历史的关系 |
| --- | --- | --- |
| [DeltaEvolve](../../../papers/DeltaEvolve_Accelerating_Scientific_Discovery_through_Momentum_Driven_Evolution/) | 三层 delta 金字塔：L1 FROM/TO 策略摘要（20–40 token）、L2 组件级 plan（COMPONENT/OLD_LOGIC/NEW_LOGIC/HYPOTHESIS）、L3 全码（存库不进上下文） | 唯一 mutation 算子在同一次响应中生成新码 + 自文档化 delta；上下文 = 父码 + 3 个 top delta + 2 个 diverse delta（MAP-Elites 嵌入网格取远端）+ 定性 ΔR；动量类比 SGD；EM 形式化把上下文构造定为唯一被优化的潜变量。**最重的受控发现：Blind-Elite（去掉分数）几乎无损，Random-Context（随机选上下文）崩溃——起作用的是上下文选择而非分数条目** |
| [PhyloEvolve](../../../papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/) | 谱系森林，S-表达式边 (mod, delta_reward)；Elite Pool 两形态：完整 elite trajectories + 统计化 elite modifications（带 μ/σ/n 与 value(m) 公式） | 四 agent：NextStepper（in-context policy，warmup/explore/exploit 三模式）、ModifyAgent（最小 diff + 失败调试路径上树作负例）、Designer（跨范式分叉造新树根）、Summarizer（周期压缩）；理论外衣是 ICRL（Algorithm Distillation + prompt-Decision Transformer）："EA learns at population level through selection; ICRL learns at trajectory level through contextual conditioning" |
| [BttB](../../../papers/Back_to_the_Beginning_of_Heuristic_Design_Bridging_Code_and_Knowledge_with_LLMs/) | 知识态 K（design principle/motif/rule 文本）成为一等搜索对象，代码只是 K 的实例化与检验 | CX_K/MT_K 在知识层做交叉/变异；DS/GR 两个算子专职代码↔知识互译；把 ReEvo 与 MCTS-AHD 改造成 knowledge-first 版本做同预算对照；distortion–compression 权衡论证换轨的代价与收益；稀疏评估下未评估候选退化为 structure-only evidence |
| [MEMOIR](../../../papers/Memory_Guided_Tree_Search_with_Cross_Branch_Knowledge_Transfer/) | 双时间尺度记忆：branch-local memory 存修复/改进记录（**代码本身不入记忆**，存独立 artifact 库）；global memory 存分支终止时 REFLECT 压缩的三字段条目（设计、失败原因、负约束，约 272 token） | 五算子 PROPOSE/REPAIR/IMPROVE/CRITIC/REFLECT 各条件于相应记忆；PROPOSE 只见全局记忆并被指令要求 DIFFERS from failed attempts；消融证明**分层本身**（flat memory 变体显著差）与失败记录的价值；只升级 Critic/Reflect 模型即有 +4.17 提升——记忆条目质量本身重要 |
| [AutoSND](../../../papers/AutoSND_Execution_Evidence_to_Structural_Policies/) | 执行证据档案 → LLM-Struct 投影到**固定结构词汇**（degree/two-hop/boundary…）→ 对比证据（正例 Pareto 层 + 负例按差质量/慢/失效分类）+ 结构统计 | Policy induction（B₂=10 次）+ 确定性 Compile 合并为 Π=(A⁺, A⁻, B) 三段结构政策，硬性进入 Stage III 每次生成调用并拒绝违反 forbidden_patterns 的响应；知识从建议变成可执行约束 |
| [GeoEvolve](../../../papers/GeoEvolve_Automating_Geospatial_Model_Discovery/) | 历史主要在**外部**：141 份文献的向量检索库；内部只有 OpenEvolve 默认种群 + 全局精英 | Analyzer 诊断代码知识缺口并提出检索查询 → GeoKnowRAG（多角度查询扩展 + RRF 重排）→ Geo-informed Prompt 四要素注入；消融显示静态知识 prompt 有时比纯 OpenEvolve 更差——**外部知识必须绑定当前失败证据** |

一条成形的设计语法：历史 →（差分/谱系/记忆条目/政策）→ 条件化生成。分歧只在四点：知识态由谁产生（搜索自产 vs 外部检索）、压缩发生在哪（生成时自文档化/分支终止反思/阶段间编译）、对算子是软上下文还是硬约束（AutoSND 的 forbidden patterns、MEMOIR 的负约束措辞）、代码与知识谁是搜索坐标系（BU vs TD，BttB 的核心轴）。

## 七、大规模系统：从单个提示到采样—接受—调度管线

[AlphaEvolve](../../../papers/AlphaEvolve/) 论文正文没有给生成算子命名（"evolve/recombine/SPIRE" 等名称出自开源复现，引用时须注明）；其生成端只有一个 creative generation（SEARCH/REPLACE diff，短程序可整写），交叉隐含在 prompt 含多个先前解中。真正的贡献在环绕机制：prompt sampler 四组件（显式上下文、随机格式化、渲染评估结果、**meta prompt evolution**——指令本身在平行数据库中共同演化）、Flash+Pro 模型 ensemble 的静态吞吐分工、评估级联与并行化、MAP-Elites + islands 程序库。消融中 "No context in the prompt" 单项显著退化，是"上下文是算子有效性的一部分"的大规模证据。

后续工作把隐式机制显式参数化，最终形成四层管线：

| 层 | 代表工作 | 机制 |
| --- | --- | --- |
| proposal | [ShinkaEvolve](../../../papers/ShinkaEvolve/)：变异族 diff/full/cross 概率 0.45/0.45/0.1；[RL-Algorithms](../../../papers/Evolutionary_Discovery_of_RL_Algorithms_via_LLMs/)：macro mutation（重写恰好一个组件、"justified by the failure patterns"）+ diversity-aware crossover（第二父代按 Levenshtein 距离混合采样，α=0.5），生成器写成显式条件分布 q_φ(f₁,f₂,op,R,E)；[SMCEvolve](../../../papers/SMCEvolve_Principled_Scientific_Discovery_via_Sequential_Monte_Carlo_Evolution/)：2×2 kernel mixture（edit/rewrite × 有无 peer inspiration）+ Thompson 选 kernel | 生成分布的参数化与混合 |
| acceptance | ShinkaEvolve 的 novelty rejection sampling（嵌入阈值 0.95 + LLM judge）；SMCEvolve 的 reward-only Metropolis 接受（温度化） | 生成与入库之间的显式过滤 |
| resampling/选择 | ShinkaEvolve 父代 power-law/weighted（多子代惩罚）；SMCEvolve 温度化 softmax + systematic resampling | 父代分布的构造 |
| schedule | [TurboEvolve](../../../papers/TurboEvolve_Fast_and_Robust_LLM_Driven_Program_Evolution/)：VS 多子代采样 + 岛级自适应 K（按 cell replacement 事件调节）；[RelayEvolve](../../../papers/Relay_Dont_Route_Adaptive_Population_Handoff/)：Grow/Deepen bandit + relay gain（超模质量-覆盖集分数）驱动 cheap→strong 的**种群级**交接（变异外包给 ShinkaEvolve 不动） | offspring 数、调度动作、交接种群成为新的算子变量 |

[SMCEvolve](../../../papers/SMCEvolve_Principled_Scientific_Discovery_via_Sequential_Monte_Carlo_Evolution/) 的收束性表述值得单列：AlphaEvolve 与 ShinkaEvolve 是"固定 β、K=1、接受概率恒为 1、预固定 T"的特例——"This explains why existing frameworks work"。其 inspiration 取自**包含被拒绝程序在内的完整历史**（拒绝者的信息不丢弃、转为灵感），ESS 自动停止取代固定迭代数；消融显示 adaptive resampling > uniform/greedy、mixture > 单 kernel、同预算下 (N,K) 配置存在宽度-深度权衡。

另一条正交轴：**父代选择与分区信号本身成为算子设计面**。[BehaveSim](../../../papers/Rethinking_Code_Similarity_for_Automated_Algorithm_Design/) 用执行轨迹（PSTraj + DTW 双重期望）重定义岛归属（新算法放入平均行为最相似的岛）与父对选择，生成 prompt 不动；[PartEvo](../../../papers/PartEvo_Partition_to_Evolve/) 用特征投影 + K-means 在语言空间构造 niche，其上组合 prompt-centric（RE 反思进化、SE 摘要进化）与 EC-inspired（CN 跨 niche 交叉、LGE 个体+niche 最优+全局最优三元组）四算子，K=1 时显式退化回 EoH 式选择。

## 八、设计对象扩展：算子粒度随对象分层

固定单函数模板被从四个方向突破：

| 方法 | 设计对象 | 算子形态 |
| --- | --- | --- |
| [RedAHD](../../../papers/RedAHD_Reduction_Based_End_to_End_Automatic_Heuristic_Design_with_Large_Language_Models/) | 规约 (f,g) + 其下的启发式模板 | 三段串行 prompt（候选问题描述 → 规约函数 → 启发式模板，刻意不合并防幻觉）；启发式层只复用 EoH 的 E2+M1（E1 被弃："often erroneous"）；跨规约共享种群——任一问题的启发式可为另一问题当父代；规约层停滞触发 refinement |
| [Hercules](../../../papers/Efficient_Heuristics_Generation_for_Solving_Combinatorial_Optimization_Problems_Using_La/) | 仍是 GAF 内单函数，但四类槽位 | 算子沿用 ReEvo；创新在上下文前置（CAP：每迭代从 top-5 精英抽象核心组件作方向先验，后期切换为父代自身组件保多样性）与评估代理（PPP 少样本性能预测 + 置信分层接受）；批评 ReEvo 反思产出 "test and iterate" 式空泛方向 |
| [MoH](../../../papers/Generalizable_Heuristic_Generation_Through_LLMs_with_Meta_Optimization/) | heuristic-optimizer 本身（`optimize_algorithm(population, utility, LM, prompt, subtask)` 可调用函数） | **没有固定算子集合——算子是被设计对象**；外层 meta-optimizer 进化 optimizer（跨任务规模加权 utility），内层被设计的 optimizer 生成启发式；seed optimizer 跑出的后代包含 GA/ACO/PSO/SA 及混合 |
| [InstSpecHH](../../../papers/LLM_Driven_Instance_Specific_Heuristic_Generation_and_Selection/) | 按实例子类的启发式组合 + 在线选择 | EoH 算子池全量复用，上下文按子类实例化；Neighbor Search 把邻近子类的既有启发式拿来评估复用；LLM/NN 二选一做在线算法选择 |
| [A2DEPT](../../../papers/A2DEPT_Large_Language_Model_Driven_Automated_Algorithm_Design_via_Evolutionary_Program_T/) | 完整 solver 程序（mutable/immutable 角色划分） | 分层算子 m1 micro（单函数、接口锁死）/ m2 macro（只写主函数骨架、**允许未定义 helper**）/ e1 语义交叉（双亲 THOUGHT+主函数）；维护算子（角色重分析 + 依赖修复闭环）兜底可执行性；谱系只喂选择与调度（LCA 多样性选交叉伴、节点级算子权重 softmax），**不进生成 prompt** |
| [BEAM](../../../papers/BEAM_Bi-level_Memory-adaptive_Algorithmic_Evolution/) | 结构层 α（骨架）+ 函数层 w 双层变量 | 外层 GA 在结构层做交叉/变异（ReEvo 式 better/worse 比较，**仅结构不含函数**）；内层 Education 逐函数构造——每填一个函数就临时补全并评估完整个体（函数级中间信用）；AM 自适应记忆把函数沉淀为可 import 的组件库（LLM 只见函数名+用途，"Do not reimplement"）；CMA-ES 校准超参 |
| [DGA²D](../../../papers/DGA2D_Directed_Graph_Guided_Automated_Algorithm_Design/) | 有向算子图：节点=功能算子带实现池，边=执行顺序，算法=有界有向 walk | 三类正交动作：实现级编辑（ADD/REPLACE，带失败诊断）、边编辑（GraphDelta，至多 2 加 2 删，事务式提交）、沿 walk 的一阶马尔可夫实现选择；**信用粒度是显式设计变量**：一阶转移信用 Q(c_{i−1}→c_i)，消融 first > zero > second > full-path（full 最差："excessive path dependence introduces noisy signals"） |

系统级四篇（A2DEPT/BEAM/DGA²D 与其自述）共享同一组困难：可执行性、空间爆炸、信用分配。三种解法各有消融支持：A2DEPT 用**粒度调度**回避归因（先在易归因的小粒度改）；BEAM 用**双层中间评估**制造归因（每函数一次完整个体评估）；DGA²D 用**一阶马尔可夫近似**显式建模归因的偏差-方差。DGA²D 的 full-path 变差同时为"上下文不是越长越好"提供了组内最直接的证据。

## 九、算子的学习化与外部信号

三条正交轴：

**（一）角色化（不学习）**：[RoCo](../../../papers/RoCo_Role_Based_LLMs_Collaboration_for_Automatic_Heuristic_Design/) 在 EoH 之上保留其算子，把生成拆为 explorer/exploiter 两个角色策略（指令分别强调"creative, future-oriented"与"conservative, efficiency-driven"），新增 critic（比较前后代产出 ≤30 词反思 + ≤40 词可执行建议）与 integrator（按分数融合双方产物），另有带角色记忆的 elite mutation 三算子；产物与 EoH 算子产物合并后 TopN 选择——选择机制仍是 EoH 式精英制。

**（二）外部信号条件化（学习信号源，不学生成器）**：

| 方法 | 外部信号 | 进入算子的方式 | 边界证据 |
| --- | --- | --- | --- |
| [LLaMEA-SAGE](../../../papers/LLaMEA_SAGE_Guiding_Automated_Algorithm_Design_with_Structural_Feedback/) | archive 训练的 XGBoost surrogate + SHAP | 一句结构指令 "try to \<increase/decrease\> the \<feature\>" 扩展 LLaMEA 变异 prompt | Figure 5：random-new prompt 下 LLM **完全忽略**引导，refine prompt 下大多遵循——引导的生效依赖基础算子类型；作者明示相关性非因果 |
| [Teacher-Aware](../../../papers/Teacher_Aware_Evolution_of_Heuristic_Programs/) | 独立训练的神经求解器（L2D/LEHD/ECO-DQN）在候选 on-policy 状态上的动作偏好 | analyzer LLM 把分歧案例转成 revision briefs，驱动三个修改模式（structural rewrite / parameter calibration / mechanism fusion）；种群按 objective–alignment Pareto 管理 | 最终选择只按任务目标（max-align 消融在 TSP OOD 更差）——**教师信号只应引导搜索，不应成为目标** |

**（三）生成器学习化**：[EvoTune](../../../papers/Algorithm_Discovery_With_LLMs_Evolutionary_Search_Meets_Reinforcement_Learning/) 最早把话挑明——"refining the search operator, the LLM, through RL fine-tuning"：FunSearch 式 prompt（2 程序+分数）产 K=8 个输出，off-policy DPO 用同 prompt 输出构造偏好对，程序库类比 replay buffer。[Fine-tuning LLM for AAD](../../../papers/Fine-tuning-LLM-Automated-Algorithm-Design/) 转为离线：用 EoH/FunSearch 历史产物 + DAR 分层采样（跳过相邻质量档保证信号、x 用固定模板而非 few-shot——后者导致 DPO 不稳定）训出可插入任意搜索器的专门模型。[CALM](../../../papers/CALM/) 合并两线并前进一步：细粒度 verbal 算子（injection/replacement/crossover/simplification，比率 1:2:4:1）被**明确设计成便于 GRPO 做 token 级归因**的形态（论文原文：uniform treatment of all parts is unreliable），配层级化负奖励（缺 idea −1.0 … 含随机性 −0.75）与 collapse 重置；消融中 w/o GRPO 是最大退化。[AHD Agent](../../../papers/AHD_Agent_Agentic_Reinforcement_Learning_for_Automatic_Heuristic_Design/) 取消独立算子：生成、评估调用、工具调用（实例结构分析、AST 新颖度检查——免费且只碰设计集）、终止全部是一个 GRPO 策略的动作空间，只有一个 system prompt + 一个 user prompt；预实验发现"在固定工作流里给 LLM 全部工具收益有限甚至有害"——缺的是**状态依赖的信息获取机制**，这正是把上下文获取本身变成学习动作的动机。

共同的经验教训：无论内化进权重、几何还是记忆，**选择与验证机制都不能省**——Hero 的硬可行性门、GAE 的四级验证链、LHS 的执行评分、CORAL 的隐藏 grader 都是各自系统中 load-bearing 的部分；且两个独立来源（Hero 的 anti-lazy-sort、GAE 的父代分数基线）都指向**负向/相对信号比正向引导更算数**。

## 十一、跨谱系综合

### 1. 算子角色的四次重定位

1. **语义变异/交叉**（ELM→LMX→FunSearch→EoH）：算子 = 装了人类修改先验的 EA 算子。核心主张是 LLM 能一次协调多处相关修改并"留在功能流形上"；温度≈变异率、父代排序≈软选择、prompt 措辞≈算子定义。
2. **带上下文的条件生成**（ReEvo→HiFo→EvoPH→MeLA→MeEvo，及树搜索组的生成侧）：算子本体稳定（EoH 模板或 MCTS-AHD 六动作），创新全部发生在"算子条件到什么"。ReEvo 的邻域形式化 N(h|h_c,x) 把这一点说透了：改 x 就是改邻域。
3. **采样管线中的 proposal**（AlphaEvolve→ShinkaEvolve→SMCEvolve→TurboEvolve/RelayEvolve）：proposal、acceptance、resampling、schedule 四层显式分离；offspring 数、调度动作、交接种群也成为算子变量。SMCEvolve 的"现有框架是特例"表述是这一定位的成熟形态。
4. **可学习策略/智能体动作**（EvoTune→CALM/Fine-tuning→AHD-Agent→GAE/Hero；CORAL）：算子内化进权重（mutation policy、solver 合成策略）、连续化为 latent 梯度步、或升格为接管信息获取与评价调度的自主动作。

四个定位不互相淘汰而是叠层共存：2026 年的系统（GAE、DGA²D、AHD Agent）同时使用 prompt 算子族、显式接受规则与学习型调度。

### 2. 上下文机制类型学

**信息类型**（什么进条件）：

| 类型 | 代表 |
| --- | --- |
| 父代与精英（分数间接进入） | rank 概率（EoH 系）、Boltzmann 分数簇（FunSearch/QUBE）、互补父对（EoH-S）、行为 niche（BehaveSim/PartEvo）、LCA 多样性（A2DEPT）、Levenshtein 第二父代（RL-Algorithms）、dominance-dissimilarity（MEoH） |
| 分数直接进 prompt | EvoTune（2 程序+分数）、DeltaEvolve 的定性 ΔR、DyACE 的轨迹特征、EvoStage 的阶段反馈——少数派，且多经语言化转译 |
| 反思与知识条目 | ReEvo 短/长期、HiFo insight pool（带信用与淘汰）、CogMCTS K⁺/K⁻、RefineEvo E⁺/E⁻、MEMOIR 负约束、AutoSND A⁻ |
| 谱系与历史结构 | 祖先链（MCTS-AHD s1、PoH trajectory）、delta 金字塔（DeltaEvolve）、谱系树 S-expr（PhyloEvolve）、entailment graph + PM（PathWise） |
| 规划与状态信号 | HiFo foresight、RefineEvo Planner、PoH/PathWise 规划器、CogMCTS 认知指导 |
| 外部信号 | SHAP 结构归因（SAGE）、teacher 动作对齐（Teacher-Aware）、文献检索（GeoEvolve）、性能预测（Hercules PPP） |
| 组件与知识库 | BEAM 的 AM（import 复用）、PhyloEvolve elite modifications、AlphaEvolve 程序库、CORAL notes/skills、MoH 被设计的 optimizer 接口 |

**管理机制**（怎么进条件）：字数上限（ReEvo 50 词、MeLA 80 词）是最原始的压缩；分层渲染（DeltaEvolve 按 recency 降粒度）、终止点反思压缩（MEMOIR ~272 token 条目）、固定词汇投影（AutoSND）、周期摘要（ShinkaEvolve meta-scratchpad、PhyloEvolve Summarizer、PartEvo SE）是结构化压缩；准入-检索-信用-淘汰（HiFo、RefineEvo、BEAM AM）是完整的知识资产管理；接受规则与调度（SMCEvolve、TurboEvolve、RelayEvolve）决定算子的调用分布。

### 3. 被继承的算子资产

- **EoH 五算子**是被复用最多的资产：MEoH、InstSpecHH 全量继承；RedAHD 裁为 E2+M1（E1 因错误率高被弃）；RefineEvo 改编为可改写的 op1–op5；HiFo 原样继承并加上下文插槽；RoCo 保留 E1/E2/M1/M2；BEAM 把 ReEvo 交叉/变异升维到结构层；PartEvo 沿用 EoH 双表示。
- **FunSearch 双父代排序补全**：QUBE 逐字沿用；AlphaEvolve 保持"多先前解进 prompt + diff 输出"精神；EvoTune 沿用并首次把分数写进 prompt。
- **MCTS-AHD 六动作**：Clade-AHD 逐字冻结（为隔离选择机制贡献）；CogMCTS 沿用选择/回传、替换交叉类动作为认知驱动版本。
- **ReEvo 的 verbal gradient 概念**被 DyACE（在线控制）、Hercules（批评其空泛）、PartEvo（叠加 niche）、HSEvo（批量化为 flash reflection）多向引用，是反思谱系的标准术语。

### 4. 消融支撑最硬的算子层事实

以下各条都有论文内的受控对照，是本调研中证据强度最高的设计事实：

1. 上下文选择支配分数条目（DeltaEvolve Blind-Elite/Random-Context）；
2. 反思使生成邻域更平滑（ReEvo correlation length 1.28 vs 0.28）；
3. 知识的收益来自管理架构而非知识文本本身（HiFo seed-insight 注入基线）；
4. 记忆分层本身、失败记录本身有价值（MEMOIR flat/w/o-failed 消融）；
5. 一阶转移信用优于零阶与全路径（DGA²D 信用粒度消融）；
6. prompt 级变异率控制依赖模型能力（Controlling Mutation：GPT-4o 可、GPT-3.5 不可）；
7. 结构引导只在 refine 型算子生效（SAGE Figure 5）；
8. 教师信号引导搜索有效、作为最终目标有害（Teacher-Aware max-align 消融）；
9. proposal/acceptance/resampling 分离有独立贡献（SMCEvolve 组件消融）；
10. 无感知的在线算子改写有害（DyACE-Blind 劣于静态）；
11. 固定工作流里堆信息无益，缺的是状态依赖获取（AHD Agent 预实验）;
12. 硬可行性门与负向结构罚是跨越能力墙的关键（Hero 消融组）。
