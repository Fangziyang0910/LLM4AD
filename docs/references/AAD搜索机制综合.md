# AAD 搜索机制：种群、树、轨迹与图

## 统一问题

自动算法设计方法的核心差异可以归结为三个相互关联的问题：1. 保存什么搜索历史；2. 怎样分配候选与路线的信用；3. LLM 根据什么上下文生成下一步。种群、树、轨迹和图是组织历史的方式，它们本身不直接保证搜索质量。其有效性取决于是否能在有限预算下改善候选生成、信用分配和路线覆盖。

下文先按搜索历史的组织方式说明各方法，再给出本文对这些方法的综合解释。方法名称、搜索单位、历史与反馈、预算分配和主要边界均保留原有综述口径；其中“主要边界”是当前笔记作者根据论文与代码入口整理出的核对重点，不等同于每篇论文都已通过独立消融证明的缺陷。

## 方法比较

EoH 以程序种群为搜索单位，保留 idea、代码和五类生成操作，并通过精英保留分配预算。当前笔记指出，中间退步思想容易消失。

ReEvo 同样以程序种群为搜索单位，通过短期比较与递归长期反思提供历史与反馈，并使用精英交叉或变异分配预算。当前摘要缺少轨迹条件和证据引用，这是该笔记对现有材料的来源与表述边界判断。

HSEvo 以程序种群为单位，结合质量、多样性和反思，并通过和声搜索分配机会。其主要边界是，多样性指标未必对应算法行为差异。

MEoH 使用 Pareto 种群，以多目标质量与程序差异组织历史，并通过非支配保留分配预算。其有效前沿取决于目标和距离的定义。

MCTS-AHD 以派生树节点为搜索单位，使用路径上下文、访问和回传值，并以 UCT 分配预算。当前笔记关注的边界是，后代结果可能被错误回传给祖先。

ShinkaEvolve 维护程序库与搜索组，使用历史程序、patch 和经验摘要，并通过加权父代与策略分组分配预算。其机制较多，调用口径也较复杂。

PathWise 维护程序关系图，以修改理由、父程序和评价反馈作为历史与反馈，并通过策略模型、世界模型和评价模型分配搜索机会。当前笔记认为，图结构的增益缺少独立消融，而且调用成本较高。

TraceAAD 以算法改进树为搜索单位：完整单父树保存全部评价有效的中间方案，根到当前节点的路径作为生成上下文。V9-Core 的调度为 subtree max-backup 与递归 UCT，不采用趋势、路线信用与概率控制器。当前仍待验证的问题包括历史深度与上下文构成对下一步生成的影响，以及多样性应在何时引入。

## 按历史组织方式理解机制

### 种群

种群方法直接保留高质量程序，并通过多类生成操作维持搜索。它的优势是简单和高吞吐；弱点是程序一旦被淘汰，其形成过程和暂时退步的中间思想通常无法继续利用。这里的判断关注历史保留方式，而不是声称所有种群实现都具有相同结果。

### 树

树保存明确的父子关系，并允许重访非精英分支。MCTS-AHD 用 UCT 分配预算，但启发式程序修改不满足普通树搜索中稳定、可归因的价值回传假设。因而，父代质量、动作质量和后代结果需要分开解释；把后代结果直接作为祖先价值，可能造成错误的信用回传。

### 图

PathWise 和 ShinkaEvolve 保存更丰富的程序关系或生成策略，可以动态规划修改方式。代价是更多模型调用、评价环节和上下文。比较这些方法时，应同时报告程序评估、LLM 调用和 token，而不只比较 fitness evaluation。这里的成本判断是对搜索系统资源的分析要求，具体成本数值仍需由各方法的统一实验测量。

### 轨迹

轨迹保存当前程序的来时路，使生成能够利用连续的成功、停滞和失败。其研究价值取决于三个尚需实验回答的问题：历史是否改变下一步，路线信用是否预测后续推进，以及跨轨迹参考是否在合适时机产生互补变化。因而，轨迹不能仅以“保存更多文本”来评价，而应检查历史是否改变了后续路线选择和候选质量。

## TraceAAD 的定位与待验证问题

TraceAAD 将当前程序及其完整祖先路径作为搜索个体：树节点保存可执行程序，边保存一次修改及其真实结果，生成上下文是根到当前节点的路径加已测试直接分支；参考节点只提供知识，不构成第二个结构父代。这一设计把"算法改进历史指导下一步"作为搜索上下文的核心，而不是把历史仅当作结果存档。

当前优先问题有四个。第一，历史深度与上下文构成对下一步生成的影响（同骨架历史消融）。第二，先形成优质局部解，再扩大跨轨迹预算。第三，区分程序差异、算法行为差异和知识互补性。第四，在相同评估预算下补充 LLM 调用与 token 成本。以上四项是 TraceAAD 的研究计划和作者解释，不是上述相关方法已经支持的共同经验结论。
