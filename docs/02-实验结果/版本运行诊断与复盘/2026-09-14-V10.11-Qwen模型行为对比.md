# V10.11 旧批次 Qwen3.6 与 Qwen3.8 行为对比

更新：2026-09-14

本文只分析已停止的 V10.11 旧批次：`20260914_v1011_q36` 与 `20260914_v1011_q38`。重启后的 `*_restart` 批次使用了新的目标函数锚定解析协议，不与本文混合。

## 结论

在 V10.11 的旧机制下，Qwen3.8 的**有效搜索表现整体更强**，最明显的是 CVRP、OP 和 VRPTW；OBP 在后半段也更强，TSP 两个模型接近且重复间差异较大。这个结论是“当前机制 × 模型”的行为结论，不是仅凭 Idea 文本证明 Qwen3.8 具备更强的算法推理能力。

指令遵循需要拆开看：

- 两个模型几乎都能生成声明的目标函数和正确签名，目标函数存在率约为 97%–100%，没有证据表明 Qwen3.8 在这一核心要求上高出很多。
- Qwen3.6 更常主动写出 `import numpy`。旧解析器把这些响应判为非法，但它们大多是“imports + 一个目标函数”，属于合理的完整程序输出，不应解释成模型不懂指令。
- 在旧的“只能有一个函数”解析口径下，Qwen3.8 的运行有效率更高、修复需求更少，尤其在 CVRP、OP 和 OBP；这部分优势主要反映了输出形态更贴近错误的解析器，而不是纯粹的算法能力。
- Qwen3.8 的 Idea 缺失和超长问题并没有全面更少。它在 TSP、VRPTW 的部分响应也出现了 Idea 格式问题；Qwen3.6 在 Idea 标签遵循上并不明显更差。

## 批次与比较边界

| 批次 | 模型 | 已启动路数 | 旧解析累计事件 | 真实评价数 | 说明 |
|---|---|---:|---:|---:|---|
| `20260914_v1011_q36` | Qwen3.6-27B | 9 | 6,642 | 4,363 | TSP/CVRP/OP/OBP 各两重复，VRPTW 一重复 |
| `20260914_v1011_q38` | Qwen3.8-27B | 15 | 11,901 | 9,630 | 五任务各三重复 |

两批都关闭 thinking，预算设计为每路 1000 次真实 evaluator 调用。Qwen3.6 使用 local/server1，Qwen3.8 使用 server3/server3b；按实验约定把它们视为等价运行槽位，不把 backend 当作方法解释变量。由于 Qwen3.6 少了六路，模型比较主要使用相同任务、相同重复编号和相同 evaluator 前缀；VRPTW 只能做有限比较。

原始工件位于：

- `experiments/traceaad_v10_11/results/<task>/20260914_v1011_q36_*_v1011_rep*`
- `experiments/traceaad_v10_11/results/<task>/20260914_v1011_q38_*_v1011_rep*`

## 指令遵循

### 目标函数要求基本都能满足

对所有原始 LLM 响应重新按 AST 检查目标函数，而不是沿用旧解析器的“模块只能有一个节点”条件：

| 任务 | Qwen3.6：目标函数/响应 | Qwen3.8：目标函数/响应 |
|---|---:|---:|
| TSP | 1088/1094（99.5%） | 2708/2724（99.4%） |
| CVRP | 722/723（99.9%） | 1059/1061（99.8%） |
| OP | 1335/1337（99.9%） | 1675/1685（99.4%） |
| OBP | 2944/2980（98.8%） | 3995/4030（99.1%） |
| VRPTW | 498/512（97.3%） | 2394/2406（99.5%） |

这里的分母包含原始生成和修复响应，目标函数必须是顶层函数且名称匹配。两者的核心接口遵循都很高，不能说 Qwen3.8 在“知道要生成哪个函数”这一点上明显胜出。

### Qwen3.6 更常显式声明依赖

在能够解析出目标函数的响应中，包含模块级 imports 的比例大致为：

| 任务 | Qwen3.6 | Qwen3.8 |
|---|---:|---:|
| TSP | 22% | 18% |
| CVRP | 26% | 6% |
| OP | 27% | 4% |
| OBP | 36% | 23% |
| VRPTW | 24% | 20% |

Qwen3.6 最常生成 `import numpy as np`，Qwen3.8 更常直接使用模板函数签名和上下文中暗示的 NumPy 环境。旧批次的严格解析器要求代码块只能含目标函数，因此把这类响应判为 `code_shape_error`。在旧日志中，Qwen3.6 的大多数 `code_shape_error` 和 Qwen3.8 的大多数 `code_shape_error` 都可以归入“一个目标函数加 imports”，而不是目标函数缺失。

### 旧解析器下 Qwen3.8 的有效率更高

旧运行真正进入 evaluator 并产生有效节点的比例如下：

| 任务 | Qwen3.6 | Qwen3.8 | 解释 |
|---|---:|---:|---|
| TSP | 70.8% | 74.2% | Qwen3.8 略高 |
| CVRP | 68.7% | 88.0% | Qwen3.8 明显高 |
| OP | 70.6% | 89.4% | Qwen3.8 明显高 |
| OBP | 55.5% | 74.0% | Qwen3.8 明显高 |
| VRPTW | 73.2% | 76.0% | Qwen3.8 略高 |

这张表不能直接当作“指令遵循能力”排名，因为旧解析器错误地拒绝了合法 imports。它更准确地表示：在旧协议下，Qwen3.8 的输出形态更容易直接通过系统，并且在修复后更容易留下有效候选。

### 修复依赖

旧批次中，触发修复的响应比例为：

| 任务 | Qwen3.6 | Qwen3.8 |
|---|---:|---:|
| TSP | 17.6% | 17.8% |
| CVRP | 18.2% | 9.3% |
| OP | 17.5% | 8.5% |
| OBP | 30.5% | 20.3% |
| VRPTW | 15.8% | 16.9% |

Qwen3.8 在 CVRP、OP、OBP 的修复需求明显较低；TSP 和 VRPTW 没有优势。修复成功率也大致支持同一方向：Qwen3.8 的 CVRP/OP/OBP 修复成功率约为 72%/75%/72%，Qwen3.6 约为 27%/33%/54%。

## 算法设计行为

### 同预算前缀的训练 best

内部 fitness 统一为越大越好；下表比较相同 evaluator 前缀的前两个重复。VRPTW 的 Qwen3.6 只有一个重复，因此单独标出。

| 任务 | 100 eval | 250 eval | 500 eval | 观察 |
|---|---:|---:|---:|---|
| TSP | Q36 −6.46 / Q38 −6.20 | Q36 −6.43 / Q38 −6.14 | Q36 −6.14 / Q38 −6.12 | Qwen3.8 略好，但差距小、重复方差大 |
| CVRP | Q36 −9.49 / Q38 −9.98 | Q36 −9.23 / Q38 −9.23 | Q36 −9.17 / Q38 −9.14 | Qwen3.8 略好，差距尚不稳定 |
| OP | Q36 14.12 / Q38 14.77 | Q36 14.49 / Q38 14.89 | Q36 14.52 / Q38 14.89 | Qwen3.8 优势最清楚 |
| OBP | Q36 −744.5 / Q38 −744.5 | Q36 −744.5 / Q38 −744.5 | Q36 −744.5 / Q38 −744.5 | 前 500 次基本无差别，之后 Qwen3.8 改善更快 |
| VRPTW | Q36 −20.11 / Q38 −20.92* | Q36 −19.69 / Q38 −19.68* | Q36 −19.69 / Q38 −18.92* | Qwen3.8 后续改善更强；Q36 只有一路 |

`*` VRPTW 的 Qwen3.6 是单重复，Qwen3.8 为两个重复均值。这里仍然是搜索训练分，不是 held-out 泛化。

### 生成的算法思路差异

从 best 节点的 Idea 和实际代码共同看，Qwen3.6 更常使用明确的局部启发式和参数化规则：

- TSP：最近邻完成代价、候选预筛选和 donor 的距离惩罚；
- CVRP：距离指数、容量惩罚、depot proximity；
- OP：剩余预算、回 depot 代价和可达 prize；
- OBP：Best Fit、exact-fit bonus 和残余空间惩罚；
- VRPTW：距离、等待、紧迫性、saving 的动态权重。

Qwen3.8 更常把局部计算放入状态相关的结构中：

- TSP：dynamic regret、lookahead、isolation 和局部 2-Opt refinement；
- CVRP：radial/sector sweep、角度连续性和 pairwise capacity mask；
- OP：slack、剩余预算和 donor 的可达性计算；
- OBP：scale-aware residual、inverse-residual 和自适应 waste penalty；
- VRPTW：动态系数、service-time feasibility 和 route consolidation。

这说明 Qwen3.8 的候选更常围绕“当前状态—后续代价—约束余量”组织计算，Qwen3.6 更常直接调整一个已有启发式的权重、指数或局部 bonus。这个解释与 Qwen3.8 在 OP、CVRP、VRPTW 的训练分优势一致，但 Idea 是模型自述，不能单独证明这些机制确实按描述工作；仍需以代码执行和 held-out 结果确认。

## 当前判断

目前可以支持的结论是：

1. **Qwen3.8 在 V10.11 中的有效算法搜索能力整体更强，尤其是 OP，CVRP 和 VRPTW 也有较稳定的正向信号。**
2. **不能说 Qwen3.8 在基本指令遵循上全面强很多。** 两个模型都能找到目标函数；Qwen3.6 只是更常把依赖显式写出来，而旧解析器错误地惩罚了这种行为。
3. **Qwen3.8 的主要优势是有效候选比例和算法搜索兑现率，而不是简单的格式服从。** 修复更少、有效节点更多、同预算 best 更高，才是目前更可信的差异。
4. **TSP 没有明显模型优势，OBP 的前半段也没有明显优势。** 不能把 Qwen3.8 概括成所有任务都强很多。
5. **旧批次的模型比较仍受解析协议污染。** 新重启批次的目标函数锚定解析允许完整程序，后续应优先用新批次在同预算和 held-out 上复核这里的判断。

## 后续检查

- 用新解析器对旧 `llm_calls.jsonl` 做离线重放，统计 imports/helper 候选中能通过编译的比例；
- 对恢复出的候选只做小规模、可复现的 evaluator replay，不直接把旧无效响应全部重新计入正式预算；
- 等 `*_restart` 两个批次完成后，按同一 evaluator 前缀和 held-out 协议重做 Qwen3.6/Qwen3.8 比较；
- 继续区分模型能力、搜索机制、旧解析器和 serving 配置，不能把有效率差异全部归因于模型本身。
