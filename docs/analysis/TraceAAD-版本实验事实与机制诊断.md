# TraceAAD 版本实验事实与机制诊断（V1–V8.3）

> 本文汇总从 `docs/methods/` 各版本机制设计中剥离的实验事实、失效诊断与阶段结论。
> 机制设计只定义机制本身；每个版本运行后观察到什么、哪些设计预期落空、结论如何影响
> 下一版本，全部记录在这里。
>
> 冻结说明：各条目按其批次和分析时点冻结，不随后续版本改写。正式测试数字以
> [实验总汇](../experiments/实验总汇.md) 为准。V1–V3 条目由已删除的版本机制诊断文档迁移。

## V1：初代控制层过载

V1 在程序图与轨迹之上同时使用模式记忆、六算子、自适应 portfolio、Elo 成对比较、
island、novelty gate 和 Pareto 生存。同跨规模口径（TSP200 12.306、CVRP100 15.955，
数值越低越好）已具备竞争力，但控制层多、结果波动大。V1 的 OP 使用
`orienteering_construct`，与 V4 以后的 `op_aco` 不同，不能直接串联比较；V1/V2/V3
也没有当前四任务的完整同协议覆盖，以下结果用于解释机制演化，不用于宣称四任务总排名。

**结论**：多种弱代理共同决定保存与展示时，机制标签和统计把模型声明当作稳定语义，
但没有任何一层显示出相对于后续减法版本的独立优势。V1 结果不进入正式结果页。

## V2：机制叠加的归因困难

**批次** `20260718_174552` / `20260718_193305`，代码 `1f6c9ca`（原始工件已删除）。TSP Construct 与 CVRP-ACO 各三重复 + 测试。

V2 在轨迹与派生图之上同时运行岛模型、新颖性搜索、五算子 portfolio 信用分配、精英课程、Elo 对比反馈与多分量价值评估。

过程与结果指向同一判断：这些机制是否各自提供独立信息并不清楚。当搜索改进时难以判断哪一层在起作用，停滞时也难以判断哪一层在拖累。V2 搜索结果在两任务上均低于 V3。

**结论**：每一层辅助机制都增加复杂度与归因难度，却不必然改善结果。直接导向 V3 的系统性删减。V2 结果不进入正式结果页。

## V3：删除附属层后搜索反而变好

**批次** `20260720_233339`，代码 `e8e94f6`（原始工件已删除）。TSP Construct 与 CVRP-ACO 各三重复 + 测试。

V3 移除岛模型与迁移、精英课程、对比反馈、复杂度与运行时度量、上下文 bonus、softmax/epsilon portfolio、Pareto 生存。两任务搜索结果均优于 V2：TSP Construct 代表重复最优从约 −6.36 升到 −6.07，CVRP-ACO 从约 −8.96 升到 −8.81。

**结论**：V2 叠加的附属层没有为轨迹主干提供独立有用信号，部分还在拖累搜索。当主张是"用改进历史指导下一步"时，让历史直接、完整地进入决策，优于在历史之上再加一层调度。

**遗留代价**：确定性 argmax 与固定 UCB 使搜索随机性大幅降低，探索更多依赖模型采样本身与新颖性门。V3 结果不进入正式结果页。

## V5.0：两处机制未运行

**批次** `20260724_220827`，代码 `7da32dc`（`d2ed669` 为收口），工件 `experiments/<task>/traceaad_v5/development/version5_0/`。四任务各重复。

**结构化决策供给不足。** 四任务合计的修改决策调用中约 39.6% 因格式不合规被丢弃（OP-ACO 为 398/1021）。把决策与证据追溯合并为一次输出后，模型常无法同时满足关系、证据和字符限制，整条修改作废；通过校验的调用中也只有一部分得到完整两条。等量预算下的有效候选少于后续版本。

**全局反思从未生效。** OP-ACO 的 16 次反思调用全部失败。上下文长度检查的预算估计与模型服务真实边界不一致（假设 131K，实际 32K），提示到达服务端后被拒绝。$g_t$ 始终为空，全局经验未参与任何一次决策。

**结论**：解析通过不等于执行了目标代码，机制未运行不能视为已检验。把决策与追溯强行合并、把共享经验置于超出模型容量的反思中，都会让设计意图落空。V5.0 结果不进入正式结果页。

## V5.1：可运行性恢复

**批次** `20260725_234854`，代码 `634f474`，工件 `experiments/<task>/traceaad_v5/development/version5_1/`。

改回自然语言决策后格式合规率回到正常水平，两条修改恢复了每轮两个候选的预期供给。纯文本反思提示规模显著小于结构化版本，OP-ACO 记录到 24 次反思调用并产出有效文本，$g_t$ 首次真正进入决策。

**结论**：格式不合规一定压缩搜索空间。提示、解析、代码提取、评价共同定义有效搜索空间，其中任一环的静默失效都会污染机制实验。V5.1 结果不进入正式结果页。

## V5.2 与 V5.4：趋势权重的两次受控取点

**V5.2** 批次 `20260727_210010`，代码 `3cc726d`（`8fd1d0e` 收口），趋势权重 $0.2$。
**V5.4** 批次 `20260729_093300`，代码 `3035b01`（`4105f34` 回退），趋势权重 $0.4$、阈值放宽至 $10^{-6}$。

两版观察方向一致且 V5.4 更强：提高趋势权重后路线局部改进比例上升，近期持续改进的路线获得更多繁衍机会；同时对回弹路线（父子符号为正但起点较低）的选择概率也提高，这类路线的局部改进不推进优质前沿，因而全局最优刷新与父代平均质量相对纯 $Q$ 调度下降。

**结论**：普通回弹不等同于前沿推进。趋势权重存在一个高于质量利用收益的噪声拐点——$0.2$ 处于利用与噪声之间，$0.4$ 已偏向噪声一侧。V5.4 的调度变更未被采纳，`4105f34` 回退至 $0.8Q+0.2P$ 与 $10^{-12}$ 阈值。两版结果均不进入正式结果页。

V5.4 的代码引导（"保留有效结构、替换过时逻辑"）思路在后续版本延续；其生成端收益仍需消融，同分择简只能约束保留端，无法单独阻止生成端增加无收益复杂度。

## V5 开发阶段的机制教训

正式 V5 批次 `20260728_151736`，代码快照 `bb40ff0`。子版本原始工件位于各 task 的 `experiments/<task>/traceaad_v5/development/`。

- 五字段结构化 Action 把算法决策与审计表单合并。12,949 次调用中 39.9% 没有合法 Action，只有 30.1% 得到完整两条；两条自然语言 Action 恢复了候选供给。搜索系统应记录 provenance，模型只负责提出修改。
- Prompt、parser、代码提取、validator 和 evaluator 共同定义有效搜索空间。静默选错 Action、固定取第一个代码块和模糊失败语义都会污染机制实验。
- Action 是修改决策，Implemented Idea 只是模型声明，程序差异与评价结果才是事实。
- 机制未执行、执行无效和执行有害必须分别判断。
- 双轨迹算子能形成高质量路线，但固定等概率会在弱路线或高相似路线之间浪费预算；轨迹身份数量不能替代可执行状态覆盖。
- 同分择简缩短了保留程序，却没有阻止生成端继续增加无收益复杂度。
- 代码审查和冒烟只能证明机制可运行。

## 正式 V6：删代理并非处处失败

批次 `v6_20260802_170400`，简约协议重构提交 `fde9129`。

- V6 在 TSP 三尺度测试均值最好，说明删代理并非处处失败。
- OBP 两个重复搜索 best 停在 seed，active 出现大量重复 endpoint，capacity=100 明显退化。
- 八方法同场时 V6 平均名次第 4；单版本对外部方法时平均名次第 3，相对优势弱于 V5/V4。

**关键区分**：删除未经验证的质量门槛符合举证责任；删除精确 endpoint 去重则不同——相同代码是否重复是可直接判断的事实，不是主观质量代理。后续最小消融应单独恢复精确去重，不恢复成熟度/信用/语义差异门槛。

## V7：设计预期未获支持

批次 `v7_20260804_001931`，协议 `traceaad-v7`，checkpoint schema 11。四任务三重复 + 完整测试完成。

V7 引入精确 endpoint 去重、剩余预算衰减 UCB 和生存简化。测试结果弱于 V5/V6/V8（见[实验总汇](../experiments/实验总汇.md)）。

### 设计假设及其检验结果

V7 设计来自 V5 机制边界分析（原文已删除，结论凝练入本文 V5 各节与本节），按可证伪假设组织。正式实验没有单独检验各假设，只完成了联合版本的完整测试：

| 假设 | 内容 | 状态 |
| --- | --- | --- |
| H1 | active 去重提高真实路线覆盖 | 未单独检验 |
| H2 | 预算衰减 UCB 改善后半程预算集中 | 未单独检验 |
| H3 | 删除语义 reserve 不损害功能多样性 | 未单独检验 |
| H4 | V7 能缩小并反转对 MCTS-AHD 的差距 | 不成立；V7 为可分辨地更差（见[版本迭代诊断与消融基座选择](TraceAAD-版本迭代诊断与消融基座选择.md) 3.2 节） |

**结论**：H1–H3 因联合修改无法归因（H4 的反证也不可逆推为前三个假设各自失败）；V7 的教训是确定性去重和动态探索压力这类"状态卫生"不变量应保留，但不应被当作性能机制单独宣称价值。

**未采纳的候选机制**（V5 分析第六节）：全局自然语言经验（V5.1/V5.2 已现共享错误偏置）、Elo/多维信用/成熟度（代理跨层耦合）、语义相似度硬门槛（构造效度不足）、MCTS max-backprop（无法分离贡献）、完整 MCTS 树/渐进扩展（因果不可辨识）、代码后 LLM 总结（调用成本向 2+ 推高）、连续复杂度惩罚（LOC 与任务 fitness 无统一交换尺度）。

V8 在十一方法同场中的 15 个规模平均名次为 4.067。该数字是当前任务、数据、模型、种子和重复数下的描述性结果，不构成树机制普遍有效的证明。

## V8.2：与 V8 并列

批次 `v82_20260804_203128`，协议 `traceaad-v8.2-adaptive-expand`。

十方法同场时 V8 与 V8.2 平均名次并列（3.867）；任务上呈现分化（TSP/OP/OBP-C100 上 V8.2 更好，CVRP/OBP-C500 上 V8 更好），不构成统计显著性结论。

## V8.3：路线锁定与横向采样失衡

批次 `v83_20260805_final`，实现真相源提交 `04aaef9`。

15 个测试设置平均名次 7.667，在 TSP、CVRP 和 OP 上整体弱于 V8/V8.2，OBP 相对更有竞争力。问题不是运行失败，而是搜索正常运行后的路线利用失衡。

完整诊断、两轮修正尝试及其失败原因见 [V8.3 路线探索与信用重设计](TraceAAD-V8.3路线探索与信用重设计.md)。

V8.3 正式版同时引入树结构、局部上下文、五算子、两次 LLM 调用、扩展信用和递归选择，联合结果不能识别单个机制的因果贡献。

## 跨版本的共同判断

1. **联合版本结果无法归因到单个机制。** V2→V3、V8.2、V8.3 都同时改变多个控制层，总体分数不能识别任何单一组件的独立效果。
2. **未经验证的代理变量应当删除。** V2→V3、V8.3→V9-Core 两次删减都没有使搜索变差，其中 V3 明确变好。
3. **可直接判断的事实与主观质量代理不同。** 精确代码去重属于前者，成熟度、路线信用、语义差异属于后者，删除时的举证责任不对称。
4. **趋势类信号存在噪声拐点。** 普通回弹不等于前沿推进。
5. **机制未运行、运行无效、运行有害必须分开判断。** V5.0 的两处失效都属于第一类。

后续单变量消融的基座选择见 [版本迭代诊断与消融基座选择](TraceAAD-版本迭代诊断与消融基座选择.md)。
