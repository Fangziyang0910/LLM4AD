## 二、机制有效性汇总

**已确认有效的机制(有受控或过程证据):**

- 自然语言 Action 决策(替代结构化 Action):格式合规率恢复,候选供给恢复(V5.1,B 级)。
- 概率调度组合 $0.8Q+0.2P$ + $0.7Q_{\mathrm{endpoint}}+0.3Q_{\mathrm{best}}$ + ucb_c=0.25 + 温度 0.2:单次选择最大概率 0.08–0.14、有效候选 19–27,能集中预算而不锁死(V5,B 级)。
- 删减未经验证的代理变量:V2→V3、V8.3→V9-Core 两次删减均未使搜索变差,V3 明确变好(A 级联合)。V6 的删减是例外方向:删代理本身并非处处失败(TSP 最好),但 V6 整体可分辨地更差,删减边界需单独标定。V8.3→V9 的整版删减(去掉趋势、路线信用、概率控制器,回到 V8.2 骨架)后 V9 平均名次 9.433→4.167,是删减方向的最强例证,但属于整版联合修改,不能归因到任一删除项。
- 完整单父代树骨架:V8 与 V8.2 共 24 个 run 重建成功、V8 变异系数全方法最低、成为最强 TraceAAD(V8,B 级);该骨架被 V9-Core 原样沿用,V9 是首个在十三方法同场平均名次超过 MCTS-AHD 的版本。
- 真实匹配历史协议(V9-Core):把与当前程序严格匹配的形成历史、已测试直接分支与双轨迹参考作为唯一可变输入,其余搜索行为有意保持 V8.2 骨架(设计层面首次把"历史"与"搜索骨架"分离)。正式结果只检验了整版组合(V9 vs V8.2 平均名次 4.167 vs 5.000,P=0.59 不可分辨),"历史作为唯一变量"的因果检验仍需单变量消融(B 级,设计确认,因果未确认)。

**已确认有害的机制(有证据):**

- 趋势权重 0.4:偏向噪声,调度被回退(V5.4,B 级)。
- new_child 扩展信用(含已有子代回报)+ descend 子树最大值 + 虚拟根无渐进拓宽:根锁定与 sibling 爆炸(V8.3,B 级)。

**退化责任候选(伴随观察,未单变量消融):**

- 删除精确 endpoint 去重:OBP capacity=100 明显退化(V6,A/B 级)。

**未运行(不等于已检验):**

- 全局反思 $g_t$(V5.0):预算估计超模型真实边界,16 次调用全失败。
- 结构化 Action(V5.0):39.9% 调用无合法 Action。

**未单独检验(联合修改无法归因,占大多数):**

- V1/V2 的叠加层、V4 的 UCB 与内部锚点、V5 的四算子与双轨迹参考、V7 的 H1–H3、V8/V8.2 的深度与生成协议、V8.3 的五算子与两次调用。

## 三、跨版本科学结论

1. **联合版本结果无法归因到单个机制。** V2→V3、V6→V7、V8→V8.2、V8.3→V9 每次同时改变 3–8 项;总体分数不能识别任何单一组件的独立效果。六次版本迭代(V1–V8.3)产出的可靠信息全部是负面结论(V6/V7/V8.3 可分辨地更差),没有一项正面机制得到确认;V9 是首个超过外部最强基线 MCTS-AHD 的版本,但同样是整版联合结果,不构成对"历史输入有效"的直接检验。
2. **未经验证的代理变量应当删除。** 成熟度、路线信用、语义差异是主观代理,删除符合举证责任;精确代码去重是可直接判断的事实,删除的举证责任不对称(V6、V8.3 教训)。V9 以 V8.2 骨架删去全部代理后取得全部版本最好的平均名次,是该判断的最强支持(仍为联合修改)。
3. **趋势类信号存在噪声拐点。** 普通回弹不等于前沿推进(V5.2/V5.4);一次幸运结果不应永久抬高整条祖先分支(V8.3)。
4. **机制未运行、运行无效、运行有害必须分开判断。** V5.0 的两处失效属于第一类;解析通过不等于执行了目标代码。
5. **核心科学主张的直接检验已在单步层面完成(本文时点之后)。** 截至 V9 收口,"算法改进历史为下一步提供信息"从未与 current-code-only 对照;V8/V8.2 深度对照(3 步 vs 35 步)是最接近的操纵,方向为无差异,且非单变量(差五项)。此缺口随后由固定锚点单步实验补上:两轮配对(864 次生成)与三臂实验(648 次生成)确认来时路在四任务上单步价值明确,子代尝试无稳定额外价值(见 [RQ-009](../research/RQ-009-锚点历史上下文.md))。完整搜索层面的历史单变量消融仍未做,单步收益也不自动转化为搜索收益(V9.5→V9.6 证据链)。

## 四、版本失败类型

| 类型 | 版本 | 特征 |
| --- | --- | --- |
| 任务分化型 | V4/V5/V6/V8/V8.2 | TSP 领先、CVRP 落后;整体效应量 −0.06 到 −0.92 |
| 四任务全落后型 | V7、V8.3 | 全部任务落后;效应量 −1.13/−1.27 |
| 机制未运行型 | V5.0 | 搜索空间失效,结果不进正式页 |

V9 不落入任何失败类型:十三方法同场平均名次 4.167 首次超过 MCTS-AHD(4.200),为全部版本最好,但其优势同样小(名次差 0.033、P(优于 MCTS)=0.38,CI 高度重叠),不构成统计显著。

CVRP 上的尺度崩塌是全部非基线方法的共性(含 EoH/ReEvo/PathWise/CALM),不是 TraceAAD 机制缺陷;任务层问题与版本机制问题成因不同,不能用同一套修改处理。

## 五、科学主张与后续走向

TraceAAD 的主张是"保存改进轨迹并用它指导下一步"。V9 收口时的证据状态是:树/轨迹作为**状态组织方式**可行(V8 系列骨架延续至 V9),但成绩与"多起点加浅层局部改进"相容,与"长历史指导"的因果未建立。

实际走向没有采用整版搜索消融,而是先用低成本固定锚点单步实验识别历史的价值(见第三节结论 5),再按识别结果迭代 V9.5(质量加乐观项分配)、V9.6(历史挑法与写法重构)与 V9.7(路线级分配 + Refine/Explore 意图)。当前判断与开放问题见 [RQ-003](../research/RQ-003-轨迹上下文与搜索评分.md) 与[研究认识](../knowledge/研究认识.md)。

## V1：初代控制层过载

V1 在程序图与轨迹之上同时使用模式记忆、六算子、自适应 portfolio、Elo 成对比较、
island、novelty gate 和 Pareto 生存。同跨规模口径（TSP200 12.306、CVRP100 15.955，
数值越低越好）已具备竞争力，但控制层多、结果波动大。V1 的 OP 使用
`orienteering_construct`，与 V4 以后的 `op_aco` 不同，不能直接串联比较；V1/V2/V3
也没有当前四任务的完整同协议覆盖，以下结果用于解释机制演化，不用于宣称四任务总排名。

**结论**：多种弱代理共同决定保存与展示时，机制标签和统计把模型声明当作稳定语义，
但没有任何一层显示出相对于后续减法版本的独立优势。V1 结果不进入正式结果页。

## V2：机制叠加的归因困难

**批次** TSP `20260718_174552` / CVRP `20260718_193305`，代码 `1f6c9ca`（原始工件已删除）。TSP Construct 与 CVRP-ACO 各三重复 + 测试。

V2 是"改进历史指导下一步"主张落地的第一版完整实现：把每次修改的来时路组织成有界轨迹（上限 8 节点）与单父派生图，并在其上同时运行岛模型（4 岛/迁移周期 20）、新颖性搜索、五算子 portfolio 信用分配、精英课程、Elo 式对比反馈与六分量价值评估。

**实验事实**：训练集 best TSP 代表重复约 −6.36，CVRP −8.96 / −8.79 / −8.97；测试 TSP50 均值 6.3683（std 0.112）、TSP100 8.9617、TSP200 12.9386，CVRP test_50 9.2129、test_100 15.8113。两任务搜索结果均低于 V3。rep1 图统计与日志一致（969 节点、822 边、969 轨迹），五算子均实际执行（rep1 次数：endpoint 692、crossover 670、backtrack 594、novelty 375、simplify 140）。

**机制检验**：轨迹主干 + 派生图 + 边级经验得到支持（结构被 V3 完整保留）；五算子执行确认；岛模型、精英课程、Elo 反馈、多分量价值均未单独检验（无消融对照）；附属层叠加整体为运行无改善——搜索改进时无法判断哪层起作用、停滞时无法判断哪层拖累（A 级联合，不可逐层归因）。

**结论**：每一层辅助机制都增加复杂度与归因难度，却不必然改善结果。直接导向 V3 的系统性删减。V2 结果不进入正式结果页。

## V3：删除附属层后搜索反而变好

**批次** `20260720_233339`，代码 `e8e94f6`（原始工件已删除）。TSP Construct 与 CVRP-ACO 各三重复 + 测试。

V3 移除岛模型与迁移、精英课程、对比反馈、复杂度与运行时度量、上下文 bonus、softmax/epsilon portfolio、Pareto 生存，保留轨迹主干、四个语义算子（删除依赖复杂度度量的 simplify）、三分量价值（Q/P/D）、固定 UCB、确定性 argmax 调度、边级经验记忆与新颖性门。

**实验事实**：两任务搜索结果均优于 V2——TSP 代表最优从约 −6.36 升到 −6.07，CVRP 从约 −8.96 升到 −8.81；测试 TSP50 均值 6.0948（std 0.023）、TSP100 8.6217、TSP200 12.1275，CVRP test_50 9.0424、test_100 15.3989。四算子执行确认（rep1 次数：endpoint 1330、backtrack 593、crossover 508、novelty 27）。

**结论**：V2 叠加的附属层没有为轨迹主干提供独立有用信号，部分还在拖累搜索。当主张是"用改进历史指导下一步"时，让历史直接、完整地进入决策，优于在历史之上再加一层调度。

**遗留代价**：确定性 argmax 与固定 UCB 使搜索随机性大幅降低，探索更多依赖模型采样本身与新颖性门，成为后续版本的调参问题。V3 结果不进入正式结果页。

## V4：首个正式四任务版本

V4 首次把算法改进历史编码为单父代派生树上的有界轨迹（上限 8 节点），并作为 MDP 状态历史参与生成与搜索：两条单轨迹算子（`trace_ideate`/`trace_refine`）、UCB 启发父代调度、`2M→M` 种群管理。树只表达来源关系，不引入完整 MCTS。

**实验事实**：首个进入正式四任务协议并完成完整测试的版本（Qwen3.6-27B、1000 次搜索评估、每任务 3 重复）。OBP capacity=100 三档均为 11 方法中最佳均值；跨规模平均名次 4.600（11 方法同场第 4）；单版本上场 2.400（第 2，相对 4 基线优势 +0.750）。过程批次（12 run）：严格突破率 0.166、LRR 0.116、PCD 0.086，82% 突破位于前半程，首次突破平均在窗口 2.9。V4 与 MCTS-AHD 无任何可分辨差异（平均 Cohen's d −0.06，15 尺度中 0 个 p<0.05）。

**机制检验**（过程审计；单一机制收益均无受控消融）：轨迹记录、上下文匹配（6,299 次 Action / 12,582 次 Code 调用未发现错轨迹或错锚点）、`2M→M` 管理按设计运行；历史利用部分支持（存在依据退步边修订后成功的案例，也存在重复失败 Action）；路线价值部分支持（五个 task 中高价值路线均有更高 global-best yield）；UCB 调度缺 `ucb_c=0` 对照；**失败经验传承为运行无改善**——新分支不会持续继承锚点后的失败后缀，设计意图未实现。

**已否定的因果论断**："LOC 驱动泛化 gap"不成立（按方法去中心化相关 0.05，p=0.60）；"搜索测试名次系统性倒挂"不成立（11 方法 Spearman +0.873）；CVRP 崩塌是全方法共性。

**遗留问题**：历史进入 prompt 不等于模型使用历史（重复失败 Action）；程序持续增长（best LOC 275.9 为各方法最高）缺少简约控制；突破集中在早期、后半程停滞是跨版本共性。遗留问题分别进入 [RQ-001](../research/RQ-001-程序膨胀.md) 与 [RQ-003](../research/RQ-003-轨迹上下文与搜索评分.md)。

## V5.0：两处机制未运行

**批次** `20260724_220827`，代码 `7da32dc`（`d2ed669` 为收口），工件 `experiments/<task>/traceaad_v5/development/version5_0/`。四任务各重复。

**结构化决策供给不足。** 四任务合计的修改决策调用中约 39.6% 因格式不合规被丢弃（OP-ACO 为 398/1021）。把决策与证据追溯合并为一次输出后，模型常无法同时满足关系、证据和字符限制，整条修改作废；通过校验的调用中也只有一部分得到完整两条。等量预算下的有效候选少于后续版本。

**全局反思从未生效。** OP-ACO 的 16 次反思调用全部失败。上下文长度检查的预算估计与模型服务真实边界不一致（假设 131K，实际 32K），提示到达服务端后被拒绝。$g_t$ 始终为空，全局经验未参与任何一次决策。

**结论**：解析通过不等于执行了目标代码，机制未运行不能视为已检验。把决策与追溯强行合并、把共享经验置于超出模型容量的反思中，都会让设计意图落空。V5.0 结果不进入正式结果页。

## V5.1：可运行性恢复

**批次** `20260725_234854`，代码 `634f474`，工件 `experiments/<task>/traceaad_v5/development/version5_1/`。

改回自然语言决策后格式合规率回到正常水平，两条修改恢复了每轮两个候选的预期供给。纯文本反思提示规模显著小于结构化版本，OP-ACO 记录到 24 次反思调用并产出有效文本，$g_t$ 首次真正进入决策。

**结论**：格式不合规一定压缩搜索空间。提示、解析、代码提取、评价共同定义有效搜索空间，其中任一环的静默失效都会污染机制实验。V5.1 结果不进入正式结果页。

## V5.2 与 V5.4：趋势权重的两次受控取点

**V5.2** 批次 `20260727_210010`，代码 `3cc726d`（`8fd1d0e` 收口），趋势权重 $0.2$。
**V5.4** 批次 `20260729_093300`，代码 `3035b01`（`4105f34` 回退），趋势权重 $0.4$、阈值放宽至 $10^{-6}$。

两版观察方向一致且 V5.4 更强：提高趋势权重后路线局部改进比例上升，近期持续改进的路线获得更多繁衍机会；同时对回弹路线（父子符号为正但起点较低）的选择概率也提高，这类路线的局部改进不推进优质前沿，因而全局最优刷新与父代平均质量相对纯 $Q$ 调度下降。

**结论**：普通回弹不等同于前沿推进。趋势权重存在一个高于质量利用收益的噪声拐点——$0.2$ 处于利用与噪声之间，$0.4$ 已偏向噪声一侧。V5.4 的调度变更未被采纳，`4105f34` 回退至 $0.8Q+0.2P$ 与 $10^{-12}$ 阈值。两版结果均不进入正式结果页。

V5.4 的代码引导（"保留有效结构、替换过时逻辑"）思路在后续版本延续；其生成端收益仍需消融，同分择简只能约束保留端，无法单独阻止生成端增加无收益复杂度。

| new_child 信用 | 部分支持 | 深树形态与"按子树结果分配信用"一致；V8.3 诊断指出"一次成功 batch 的后代最大值永久抬高祖先"可能无法区分偶然突破与稳定生产力，但 V8.3 为联合修改，不能反向归因 | B |

**轨迹深度对性能的影响：未单独检验，存在四种解释。** V8/V8.2 对照非单变量，至少差五项（n_init、探索系数、扩展策略、生成协议、checkpoint schema）。"轨迹深度无独立贡献"只是候选解释之一；深度收益也可能被初始起点减少抵消、被生成协议变化抵消，或小于当前结果协议分辨率。区分需固定其余参数、只操纵探索系数与扩展策略的单变量实验。

**同期过程**（2026-08-04 中期快照，重复数不足）：前 10%–40% 预算内 V8.2 在 TSP/OP/CVRP 强 repeat 上 best-so-far 均值更高且更早锁定好解（TSP rep1 在 sample 94 达 −6.0732、OP rep1 在 sample 82 达 14.6920，V8 同预算未达）；OBP 前中期持续落后，约 350 sample 才追平；同预算树深明显更深（V8 max/mean 约 3–6 / 2–3 层，V8.2 约 13–30 / 6–18 层）；CVRP 强弱 repeat 分化明显（rep1 在 T=230 赢 3/3，rep2 在 T=110 仅赢 1/3）。中期判断为支持跑完正式预算，不记为已证实优于 V8；终局（2026-08-05）确认两者并列。

**结论**：V8.2 确认自适应扩展协议可运行且与 V8 不可分辨；深树、同期早期更快锁定好解、OBP 前中期落后、CVRP repeat 分化描述的是搜索行为，不构成性能结论；这是目前最接近"操纵历史长度"的对照（可用历史约 3 步增至约 35 步），方向为无差异。V8.2 的骨架与配置被 V9-Core 沿用为搜索基线。

## V8.3：路线锁定与横向采样失衡

批次 `20260805_final`，实现真相源提交 `04aaef9`。

15 个测试设置平均名次 7.667，在 TSP、CVRP 和 OP 上整体弱于 V8/V8.2，OBP 相对更有竞争力。问题不是运行失败，而是搜索正常运行后的路线利用失衡。

V8.3 正式版同时引入树结构、局部上下文、五算子、两次 LLM 调用、扩展信用和递归选择，联合结果不能识别单个机制的因果贡献。

**名次细节**：11 方法同场平均名次 7.667 第 9（V8 4.067、V8.2 4.133、V4 4.600、V5 5.100）；单版本上场平均名次 3.433 第 4，与 V7 并列。TSP、CVRP、OP 三规模报告均值全部落后；OBP 相对有竞争力（capacity=100 三规模接近 V4 但未列最佳，整体效应量 −0.03 是四任务中唯一接近基线的）。7 版本两两比较中相对 V4/V5/V8/V8.2 可分辨地更差（P(优于)≈1.00）。15 规模整体效应量 −1.27；CVRP instance 胜率 ≤3%/0%/0% 全尺度地板，OP 12%/6%/3% 崩塌。四个任务 run 均正常完成 1000 次 evaluator，失败发生在路线利用失衡。

**根锁定与 sibling 爆炸**：多个 run 几乎锁定单一根分支——CVRP rep3、OP rep1、TSP rep2 的单一根分支分别被选中约 990/989/990 次；被锁定的中间节点又反复产生 243、558、629、681 个直接 sibling。机制原因有二：`new_child` 质量含已有直接子代回报，成功 sibling 使该动作持续得高分，同一中间节点长期垄断扩展；`descend` 使用子树历史最大值，一次幸运后代给整条祖先分支长期保持最高利用值，且虚拟根初始化后不再渐进拓宽，根分支一旦早期领先便难以重新打开。

**机制检验**（V8.3 为联合改动，除过程审计可确认的执行事实外，任何单项的因果贡献均未被正式实验单独检验）：

| 机制 | 检验状态 | 证据 | 证据级别 |
| --- | --- | --- | --- |
| 树结构与完整历史保留 | 支持 | 节点、边、信用全部写入 checkpoint，局部轨迹按设计提取；完整单父树语义被 V9-Core 延续 | B |
| new_child 扩展信用（质量含已有直接子代回报） | 运行有害 | 成功 sibling 抬高 `Q_new`，同一中间节点长期垄断扩展 | B |
| descend 子树历史最大值回传 | 运行有害 | 一次幸运后代给整条祖先分支长期保持最高利用值，无法区分偶然突破与稳定生产力 | B |
| 虚拟根无渐进拓宽（根只在 10 个既有根中选择） | 运行有害 | 根分支一旦早期领先便难以重新打开 | B |
| 递归选择（S_new 与 S_down 竞争、选择路径记账） | 部分支持 | 结构按设计执行，但作为信用失衡的载体导致根锁定 | B |
| 失败尝试记账（零回报入 Q_new，不建节点） | 支持 | 失败候选只写运行记录不入树 | B |
| global best 只由原始 fitness 决定 | 支持 | 评估结果与搜索分数分离 | B |
| 五算子等概率 / 两次 LLM 调用 / 局部上下文 | 未单独检验 | 联合引入，因果贡献不可分离；局部上下文语义被 V9-Core 保留 | C |

**两轮修正尝试均失败**：

1. **平方根宽化**（批次 `v83_20260806_pw`）：把 `new_child` 竞争改为平方根宽化后，12 路未完成即主动停止——10/12 run 最高根分支访问占比仍超 90%；`max_depth=10` 边界使选择器返回深度 9 父节点绕过宽度条件，形成 60–61 个深度 10 sibling；修正后 `trajectory_progress` 等量不再参与实际选择，信用、评分与选择没有闭环。该批次部分 repeat 模型端点不一致，不能作为机制比较。
2. **信用重设计（V8.3-credit，未发布）**：轨迹先验 + 路线经验信用 + 概率 UCT——先验 $V_{prior}(n)=0.8[0.7F(n)+0.3H(n)]+0.2P(n)$（$F$ 为有向 fitness 全树中秩百分位，$H$ 为路径历史最好秩，$P$ 为最近形成边折扣趋势）；单次扩展回报 $R(n,c)=0.75F(c)+0.25[F(c)-F(n)]_+$ 取创建时点快照，失败记 0；回报写入本轮选择路径全部程序节点、按运行均值聚合，使一次幸运突破只贡献一个样本；选择 $A(c)=Q(c)+0.25\sqrt{\log(1+N(\text{parent}))/N(c)}$ 同层温度 0.2 softmax；扩展按 $\lfloor N(n)^{0.5}\rfloor$ 宽度条件，取消 `max_depth`。已实现并通过真实模型冒烟（TSP 16 次全部有效，高质量根单次选择概率 0.556、低质量根 0.024，弱后代路线利用值 0.660→0.578），但正式 12 路实验未完成，已完成的三任务未见改善（12 尺度平均 Cohen's d −1.28，与 V8.3 的 −1.27 持平），仅作为机制故障修复记录。否决过的替代方案：全局 trajectory population（退化为种群调度）、恢复 V8.2 自适应 `new_child`（重新引入幸运结果过度信用）、只增大 UCT 系数（不修复信用缺失）。

**可迁移认识**：V5 的概率调度组合能集中预算而不锁死，可迁移的是职责分解与概率选择；V8 宽覆盖（根最高访问占比 4%–36%）与 V8.2 深开发总体接近——根集中本身不等于失败，不可复用的是"一次成功 batch 的后代最大值永久抬高祖先"；MCTS-AHD 的平方根宽化结构约束可保留，但参数尺度不能直接移植。

**结论**：三个选择机制——带已获回报的 `new_child` 持续参与价值竞争、`descend` 用子树历史最大值、虚拟根无渐进拓宽——组合使搜索锁死单一根分支并向中间节点横向爆炸，损害来自选择层信用，不在生成协议。一次幸运结果不应永久抬高整条祖先分支；未经验证的代理变量应当删除。V9-Core 不采用趋势项、路线信用和概率控制器——更复杂的信用可改善过程形态，尚未证明提升最终质量，故选择简约调度；保留局部历史上下文的语义，不采用固定深度、V8.3 信用公式和五算子集合。

## 正式 V9：真实匹配历史作为唯一可变输入

批次 `20260807_123753`，协议 `traceaad-v9-core`，checkpoint schema 1。四任务三重复 1000 evaluator + 完整测试完成，12 个 run 全部 `finished`（`stop_reason=budget_exhausted`）。机制规范见 [V9-Core 完整机制设计](../methods/TraceAAD-v9-core完整机制设计.md)。

V9-Core 以 V8.2 骨架（固定 10 根、递归 UCT、自适应 `new_child`、单次 `Idea + Code`、四算子、subtree max-backup、fitness 优先）为搜索基线，把"真实匹配历史"设计为唯一可变输入：当前节点最近 8 条祖先形成边、已测试直接分支摘要（至多 8 个）、双轨迹算子的其他根分支参考及其真实形成路径。明确不引入趋势、路线信用、算子信用、progressive widening、固定深度与在线去重。算法行为有意接近 V8.2，独立的包、协议和 checkpoint 使历史输入成为可单独操作的设计维度。

**名次细节**（十三方法同场口径，2026-08-08 统一重算）：15 规模平均名次 4.167 第 1，95% bootstrap 区间 [4.067, 6.267]；MCTS-AHD 4.200 第 2（差 0.033，区间高度重叠）；V8 4.867、V8.2 5.000。P(V9 平均名次优于 MCTS-AHD)=0.38，未达统计显著；版本两两比较 P(V9 优于 V6/V7/V8.3)=1.00、P(V9 优于 V5)=0.82、P(V9 优于 V4)=0.66、P(V9 优于 V8)=0.58、P(V9 优于 V8.2)=0.59、P(V9 优于 CALM)=0.99。单版本上场口径 1.867 第 1（同场 MCTS-AHD 1.933，名次差 −0.067），相对四基线平均名次优势 +1.417 为全部版本最高。对 MCTS-AHD 整体效应量 +0.05（TSP −0.51、CVRP −1.14、OP +0.21、OBP +0.85），是首个整体效应量为正的版本；运行间变异系数 1.214%。

**任务观察**：OP50 报告均值为全场最佳（15.162082，首次超过 MCTS-AHD 的 OP50 列），OP100/200 接近 V5 未取得最佳；OBP capacity=100 的 `1k/5k` 两档全场最低、`10k/100` 仅高于 CALM（4033.467 vs 4026.733），capacity=500 三档均弱于 V8；TSP 三规模与 CVRP 三规模均值均弱于 MCTS-AHD，CVRP 崩塌仍是全方法共性。

**机制检验**（V9 为整版组合；正式测试只确认整版表现，单项收益均无受控消融）：

| 机制 | 检验状态 | 证据 | 证据级别 |
| --- | --- | --- | --- |
| 真实匹配历史协议（8 祖先边 + 8 直接分支 + 双轨迹参考） | 部分支持（设计确认，因果未确认） | 历史被设计为唯一可变输入，与 V8.2 骨架的对照仍为整版联合（独立实现、协议与 checkpoint 身份不同）；V9 平均名次 4.167 优于 V8.2 的 5.000 但 P=0.59 不可分辨；提供/不提供历史的单变量消融未运行 | B |
| 删除趋势、路线信用、概率控制器（回 V8.2 骨架） | 部分支持 | V8.3（9.433）→V9（4.167）是删减方向最强例证，但属于整版联合，不能归因到任一删除项 | B |
| V8.2 搜索骨架（递归 UCT、自适应 new_child、单次生成、四算子） | 支持（延续） | 与 V8/V8.2 同构，12 个 run 树重建与完整落盘成功；V9 成为全部版本最好名次 | B |
| subtree max-backup、fitness 优先、LOC 只处理完全同分 | 支持（延续） | 与 V8/V8.2 一致；global best 只由原始 fitness 决定 | B |
| 双轨迹参考 softmax（秩百分位，τ=0.2） | 未单独检验 | 与树、历史协议联合引入 | C |
| 上下文边界（缩短参考历史 → 减少分支摘要 → 退化为单轨迹） | 未单独检验 | 运行无 `context_overflow` 记录，该回退路径未触发，无法检验 | C |

**结论**：V9 是首个在十三方法同场平均名次上超过 MCTS-AHD 的版本（4.167 vs 4.200），但优势微小（名次差 0.033、P=0.38、CI 高度重叠），单版本口径 1.867 居首。搜索行为接近 V8.2 是有意的控制设计，"历史输入作为唯一可变量"是设计层面的分离，不是已完成的受控实验；V9 的正式结果只检验了整版组合，不能归因到 matched_history 协议本身。核心科学主张的后续单步检验见第三节结论 5。

## 附：V4–V6 轨迹过程分析（2026-08-02 过程批次，36 run）

对照 [What Makes an LLM a Good Optimizer?](../../../papers/What_Makes_an_LLM_a_Good_Optimizer_Trajectory_Analysis/) 的指标（突破率、LRR、PCD、新颖性、窗口熵），从 4 任务 × v4/v5/v6 × 3 重复的日志离线重建（脚本 `experiments/analysis/analyze_process.py --scope traceaad`，可重新生成全部指标与图表）。代码 token Jaccard 是语义距离的代理，窗口=10 次评估不等价于论文的"代"。

**主要事实**：

- v4 的严格突破率（0.166）和任务内归一化最终分数（+0.44σ）均为三版最高；v5 此前看似"突破更多"来自等分简化被误计为突破（12.1 次/run），修正后不是适应度突破。
- v6 的 PCD 0.151 约为 v4/v5（0.086/0.085）的 1.8 倍，同时 LRR 0.104 最低、regress 占比 74.0% 最高：更大语义步长未带来收益。双轨迹算子只占 14%，步长增大主要出现在 ideate/refine 行为中。
- 三版突破均集中在搜索早期（v4 82% 位于前半程），后半程停滞是共同模式；v5/v6 首次严格突破明显更晚（窗口 10.5/9.6 vs 2.9）。
- 窗口级回归中稳定的模式只有"突破随窗口指数下降"（p<0.001）；论文的"新颖性×空间熵"交互未复现，新颖性并发弱正相关（p=0.033）、滞后不显著。run 级相关（突破率 +0.37、LRR +0.31）样本量不足，不作因果解释。

**边界**：LRR 只统计被接受子代；每版本 3 重复功效有限；版本间比较同时改变多项机制。"局部化条件下新颖性才有生产力"需要真正的代内种群快照才能检验，当前窗口代理不足。
