# TraceAAD V4 机制分析

状态：2026-07-24 冻结快照；V4 为历史版本，不定义当前方法。

## 范围

分析覆盖 TSP Construct、CVRP-ACO、Knapsack Construct、Online Bin Packing 和 OP-ACO 的 15 个 V4 run。OBP 与 OP-ACO 已完成 1000 次评估，其余为当时的运行中快照。分析单位包括候选程序、父子边、轨迹选择和种群管理周期。

## 结论

V4 确实以轨迹参与生成与搜索：历史进入 Action/Code，路线质量和趋势影响父代选择，内部锚点支持回退，active frontier 按 \(2M\rightarrow M\) 管理。TSP 与 CVRP 出现沿同一路线连续刷新 global best 的案例。

| 环节 | 判断 | 主要证据或缺口 |
| --- | --- | --- |
| 轨迹记录 | 支持 | node、edge、trajectory 与日志一致；历史窗口上限为 8 节点 |
| 上下文匹配 | 支持 | 6,299 次 Action 和 12,582 次 Code 调用未发现错轨迹或错锚点 |
| 历史利用 | 部分支持 | 存在依据退步边修订后成功的案例，也存在重复失败 Action |
| 路线价值 | 初步支持 | 五个 task 中高价值路线均有更高 global-best yield |
| UCB | 调度作用成立 | 未访问路线获得更多选择概率；质量收益缺少 `ucb_c=0` 对照 |
| 内部锚点 | 部分支持 | 986 次内部回退；收益依 task 而异 |
| 失败经验传承 | 不成立 | 新分支不会持续继承锚点后的失败后缀 |
| 延迟管理 | 部分支持 | 新路线可立即被选，但多数在收缩前未获得父代机会 |
| 生存机制 | 无法判断 | 事件未记录 survivor ID、保留角色和相似度 |

## 形成的问题

- 父子回弹会被趋势记为正向，但不一定推进优质前沿。
- 历史进入 prompt 不等于模型使用历史。
- Action、声明的 Idea 和实际代码可能不一致。
- `2M` 候选数量明显大于可分配的繁殖机会。
- 程序持续增长，缺少简约控制。

这些问题分别进入 `docs/research/RQ-001-程序膨胀.md`、`docs/research/RQ-003-轨迹上下文与搜索评分.md` 和 `docs/knowledge/研究认识.md`。V4 机制规范见 `docs/methods/TraceAAD-v4完整机制设计.md`。
