# TraceAAD V4 分析

> 版本规范:[docs/methods/TraceAAD-v4完整机制设计.md](../methods/TraceAAD-v4完整机制设计.md)
> 状态:2026-08-07 冻结;历史版本,不定义当前方法。

## 1. 版本定位

V4 首次把算法改进历史编码为单父代派生树上的有界轨迹(上限 8 节点),并作为 MDP 状态历史参与生成与搜索:两条单轨迹算子(`trace_ideate`/`trace_refine`)、UCB 启发父代调度、`2M→M` 种群管理。设计意图是以有序来时路(哪些思想已产出结果、哪些失败、哪些仍可修复)作为下一步 LLM 推理的主要上下文;树只表达来源关系,不引入完整 MCTS。

## 2. 实验事实

审计范围覆盖 TSP Construct、CVRP-ACO、Knapsack Construct、Online Bin Packing 与 OP-ACO 共 15 个 V4 run;OBP 与 OP-ACO 已完成 1000 次评估,其余为当时运行中快照。V4 是首个进入正式四任务协议并完成完整测试的版本:Qwen3.6-27B、1000 次搜索评估、每任务 3 重复、测试集不参与搜索。测试均值(3 重复;除 OP 外越低越好):

| 任务 | 小规模 | 中规模 | 大规模 |
| --- | ---: | ---: | ---: |
| TSP 50/100/200 | 6.040 ± 0.161 | 8.504 ± 0.224 | 11.886 ± 0.141 |
| CVRP 50/100/200 | 9.129 ± 0.130 | 15.414 ± 0.294 | 27.900 ± 0.595 |
| OP 50/100/200 ↑ | 15.069 ± 0.091 | 30.217 ± 0.673 | 53.509 ± 2.612 |
| OBP `1k/5k/10k × C=100` | 413.600 ± 3.292 | 2023.600 ± 7.203 | 4037.333 ± 16.008 |
| OBP `1k/5k/10k × C=500` | 81.333 ± 0.462 | 403.133 ± 0.902 | 805.133 ± 1.332 |

OBP capacity=100 三档均为 11 方法中最佳均值。跨规模平均名次 4.600(11 方法同场第 4);单版本上场 2.400(5 方法第 2,相对 4 基线的平均名次优势 +0.750)。

过程批次(v4 的 12 个 run):严格突破率 0.166、LRR 0.116、PCD 0.086、新颖性 0.081;82% 的突破位于前半程,首次突破平均在窗口 2.9;该批次内 v4 严格突破率与任务内归一化最终分数均最高(+0.44σ)。跨任务诊断:V4 在 CVRP 胜率 27%/14%/2% 随规模崩塌,但十个非基线方法全部同向崩塌,非 V4 独有缺陷;"搜索名次 1、测试名次 4"是局部重排,11 方法 Spearman(搜索名次,测试名次)=+0.873(p=4.5e-4);V4 best 程序 LOC 275.9 为各方法最高,但 LOC 与泛化 gap 按方法去中心化后相关为 0.05(p=0.60),不能按过拟合驱动因素处理。V4 与 MCTS-AHD 无任何可分辨差异(平均 Cohen's d −0.06,15 尺度中 0 个 p<0.05)。

## 3. 机制检验

| 机制 | 检验状态 | 证据 | 证据级别 |
| --- | --- | --- | --- |
| 轨迹记录 | 支持 | node/edge/trajectory 与日志一致;轨迹窗口上限 8 节点 | B |
| 上下文匹配 | 支持 | 6,299 次 Action / 12,582 次 Code 调用未发现错轨迹或错锚点 | B |
| 历史利用 | 部分支持 | 存在依据退步边修订后成功的案例,也存在重复失败 Action | B |
| 路线价值 | 部分支持 | 五个 task 中高价值路线均有更高 global-best yield | B |
| UCB 调度 | 部分支持 | 未访问路线获得更多选择概率;质量收益缺 `ucb_c=0` 对照 | B |
| 内部锚点 | 部分支持 | 986 次内部回退;收益依 task 而异 | B |
| 失败经验传承 | 运行无改善 | 新分支不会持续继承锚点后的失败后缀,设计意图未实现 | B |
| 延迟管理 | 部分支持 | 新路线可立即被选,但多数在收缩前未获父代机会 | B |
| 生存机制 | 未单独检验 | 事件未记录 survivor ID、保留角色与相似度,无法判断 | B |
| 种群管理 `2M→M` | 支持 | 运行事实成立:按阈值收缩、global best 强制保留可续繁衍;无 M 规模消融 | B |

表内检验均来自过程审计;正式测试只确认整版组合表现,单一机制的收益均无受控消融,联合版本修改不能归因到单一机制。

## 4. 结论

- **确认**:V4 完整跑通正式四任务协议并交出可比结果(跨规模平均名次 4.600,OBP capacity=100 全场最佳);轨迹记录、上下文匹配、`2M→M` 管理按设计运行,历史确实进入 Action/Code 与父代调度。
- **否定或未确立**:失败经验传承未实现;LOC 驱动 gap、搜索测试名次系统性倒挂两个因果论断不成立;CVRP 崩塌是全方法共性,不是 V4 搜索控制层的缺陷。
- **遗留问题**:历史进入 prompt 不等于模型使用历史(重复失败 Action);`2M` 候选数明显大于可分配的繁殖机会;程序持续增长(275.9 LOC)缺少简约控制;突破集中在早期、后半程停滞是跨版本共性。
- **对下一版本**:V5 引入双轨迹算子与轨迹种群,让知识跨路线流动,直接回应 V4 单轨迹信息隔离;V4 遗留问题分别进入 RQ-001(程序膨胀)与 RQ-003(轨迹上下文与搜索评分);后续版本全部为联合修改,需受控消融才能归属。
