# TraceAAD V9.7 路线级分配诊断

> 分析批次：`20260813_184519`；12 个完成 run。
>
> 本分析在每次选择当时记录的 `(q, n, optimism, score)` snapshot 上将 optimism 置零后重放平局规则。它只回答 bonus 当时是否改变选择，不构造另一条完整搜索轨迹，也不是最终质量证据。
>
> 协议边界：该批次 `run_config` 记录的历史选择器是 `v96_recent_formation_fill_capped_improve_regress_direct_v1`；当前工作树已另行修改历史组成。本报告只依赖批次中保持不变的路线/锚点分配公式和决策日志，不声称该批次验证了当前 parent-path 历史协议。

## 核心判断

V9.7 的 route score 确实被计算，但 route optimism 在 12,251 次决策中只改变 32 次（0.26%）。同一尺度在锚点层改变 7,418/12,251 次（60.6%）。因此共享 bootstrap 一步尺度在两层产生了明显不同的干预强度：锚点层活跃，路线层接近未激活。

## Bootstrap 0-delta

9/12 个 run 的 bootstrap 尺度集合包含至少一个零变化。正式实现将所有成功形成新 child state 的有效转换纳入中位数，包括 `delta_q = 0`；文档已与这一实际协议统一。

## 证据边界

- 这是“机制运行但几乎没有改变路线选择”的过程负结果。
- 它不证明两级结构本身错误，也不证明路线 coverage 对最终质量无价值。
- 不能根据 intervention rate 反向调大 $s$ 或把 $\lambda_{\mathrm{crit}}$ 的中位数直接写成下一版乘数。
- V9.7 同时改变了其他机制；任何 search 或 held-out 差异都不能归因为 route optimism 已经提供了实质跨路线探索。
