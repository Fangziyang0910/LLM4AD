# Qwen3.6 / Qwen3.8：Idea–Code 固定位置语义抽查

日期：2026-09-08。证据范围：Qwen3.6 对应 V9.7 的旧实验，Qwen3.8 对应 V10.7 的新实验。本文核查已有产物，不调用模型、不运行任务 evaluator。

## 核心判断

**双方都有可以逐行证实的 Idea–Code 脱节，现有抽查不足以给出模型一致性胜负。** 3.6 样本中能看到“声称新增机制，实际仍保留原机制或只加注释”；3.8 样本通常能找到 Idea 所列的主要公式，但也出现关键公式被改写、数值处理让机制失效、声称打破平局却不改变平局。不能以叙述流畅、代码有效或单次 fitness 提升代替语义核查。

一个特别值得追踪的现象是 **错误实现仍可能拿到正常分数**：3.8 TSP rep2 的所有评分变成 NaN，实际返回首候选；当前调用方按当前距离给出候选，因此退化为最近邻并未表现为运行失败。3.8 CVRP rep3 的 depot boost 被 NaN 清洗抹掉，但子代仍比父代分数高。由此不能推断它理解了自己描述的机制。

## 取样与边界

- 四个共同任务：TSP constructive、CVRP ACO、OP ACO、在线装箱，每任务 3 个重复、每代 12 个，共精读 **24 个候选的留存 Idea 与完整程序**；必要处与父代对照。
- 固定取第 80 次真实评价的有效非根子代，若无则向后取至 90。旧 TSP rep3、旧 OP rep2 顺延至 81，其余均为 80。没有按是否改进、是否复杂、是否容易发现问题挑样本。
- 旧序列用 `evaluator_called=True` 累计真实评价；新序列用 `evaluation_id`。完整来源、JSONL 行号、节点、父节点、程序和判断见 [语义抽查样本.json](语义抽查样本.json)。新节点 Idea/Code 取 `tree_state.json`，事件行确定评价位置。
- **旧 Idea 是系统截断的记录**：[V9.7 prompt.py](../../../../llm4ad/method/traceaad_v9_7/prompt.py) 第 13 行规定 `IDEA_MAX_CHARS=300`，第 149 行直接切片；本组 7/12 条恰好 300 字符。只能判断留存主张，不能声称完整原始 Idea 均被覆盖，也不能把旧 Idea 短归因于模型。
- 样本位置固定、数量少且算子/上下文/搜索状态不同；这是一组问题样本与正例的审计，**不是总体一致率、模型胜率或因果能力排名**。短 Idea 主张少，严格正确数也不能直接比较；这里没有构造这类百分比。
- “公式实现”“在返回值里生效”“影响下游选择”“带来更好搜索结果”是不同问题。下表说明前三项，fitness 留在样本 JSON 供追溯，未把正收益当作一致性标签。

## 六个最小探针 / 静态校验

使用仓库现有 `.venv` 的 NumPy 1.26.4，只调用抽中的单个函数，输入为四个手工构造点或三个箱子；没有执行 ACO、完整 TSP 评价、数据集评价或任何模型请求。结果保存在样本 JSON 的 `probe_results`。

1. **3.8 TSP r2**：候选 `[2,1,3]`，实际最近点为 1，但函数返回 2；返回时捕获到 `scores` 全 NaN。根因是 `fill_diagonal(sub, inf)` 后 `sum`，再做 `inf/inf`。当前 [TSP evaluation.py](../../../../llm4ad/task/optimization/tsp_construct/evaluation.py) 第 90–94、115–123 行按距离排序候选，解释了为何这种错误可以隐藏为正常最近邻。该解释依据当前调用方源码，未重跑历史 evaluator。
2. **3.6 TSP r2**：相同子矩阵对角 inf 问题令 `mean_dists_to_others` 全 inf、`score_central` 全 0；这一项只有共同常数贡献，其余评分仍可生效。不能将两例统称为同样程度的失败。
3. **3.6 OP r2**：父子 `ast.dump(ast.parse(code))` 完全相同。Idea 声称新增 budget-pressure，但差异全部是注释；这是“代码可以运行而新增机制不存在”的直接证据。
4. **3.8 CVRP r3**：捕获 depot 角度项为 NaN；最终 depot 出边与入边（非对角）全部 `1e-9`。代码虽写了 `*=1.15/1.10`，乘在 NaN 上再清洗，不能改变 depot 偏好。
5. **3.8 装箱 r2**：`item=5,bins=[8,8,10]` 返回前两项完全相同（约 `-2.75`）。同残量意味着同容量，`eps*b` 不可能实现宣称的平局消除。且 `-r+1/(1+r)+eps*(r+item)` 的导数为 `-1-1/(1+r)^2+eps<0`，可行区仍严格 Best-Fit。
6. **3.8 OP r3**：四点输入的返回 depot 列最终全 `1e-9`，由于以 depot 自身 `1/eps` 归一化，正常返回权重被压到 floor 以下。另一个更强边界来自 [OP evaluation.py](../../../../llm4ad/task/optimization/op_aco/evaluation.py) 第 111–161 行：从 depot 出发即将它标记已访问，随后禁选；无法继续时走 dummy sink，**显式回 depot 的 heuristic 列本来不控制终止选择**。本条依据当前 evaluator 源码，不将它外推为未核实历史版本事实。

## 对下一步模型评估的含义

这些例子支持优先测量“声明的改动有没有落实”，并将其与编译/接口成功率分开。可在同一 TraceAAD 版本、同一父代与历史上下文上，让两模型完成相同少量 Refine/Pivot/Fuse，再盲审主要主张与执行路径、记录实际选择是否变化；之后才看有限预算搜索收益。

当前材料只能说：**两代模型都需要语义与行为层的核查；3.8 更强的通用能力不能自动保证其 Idea–Code 更一致，3.6 的实际有效改动也不能因其官方基准较弱而忽略。** 本抽查没有把 24 个样本扩展成模型能力百分数，也没有新增付费/模型实验。
