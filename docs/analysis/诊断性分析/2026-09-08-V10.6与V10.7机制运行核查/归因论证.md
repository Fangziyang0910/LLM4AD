# V10.7 不达预期：方法设计、具体实现与干扰因素

2026-09-08。本文接续[运行核查](结论.md)和[同期质量追踪](质量退化追踪.md)，重新核对原始方案、执行代码、实际上下文与生成程序，并增加隔离反事实评价和固定 Prompt 诊断。

## 1. 先区分三层问题

“实现有问题”需要明确指哪一层，否则容易把不同证据混在一起。

| 层次 | 本次要检验的问题 | 当前判断 |
| --- | --- | --- |
| 搜索方法的具体设计 | 全档案分层、三程序排序、统一参考规则，能否帮助下一次生成？ | 存在已被数据暴露的结构性不足；不能因代码符合规范就认可方法有效 |
| TraceAAD 的实现与 Prompt 表达 | 采样、父代、donor、索引、入档是否正确；记录在新上下文中是否仍表达原意？ | 调度与采样主逻辑未发现违背设计；Idea 的历史编号确有错指，原始注释展示也引入了额外信息变化 |
| 模型生成的求解程序 | 算法是否正确实现其声称的决策，修复后是否更强？ | TSP 代表程序存在 NaN 退化；但修复后全部更差，不能解释成“强算法 idea 只是被代码错误拖累” |

宽泛的“从全档案主动组织有用材料”与“当前 V10.7 的具体三程序分层方案”也不是同一个命题。前者尚未被这些实验否定；后者已经在若干任务上明显不达预期。现有证据不支持把失败归结为一个小型运行代码错误，也不足以给设计问题和表达缺陷分配各自的因果占比。

## 2. 搜索主逻辑基本忠实于原方案

本次直接读用户最初附件和[讨论原文](../../../ideas/V10.7采样轨迹/讨论原文.md)，没有只用事后整理的当前规范自证。

- 全档案取材、排除父代同代码、同代码均匀选一条完整记录、质量分层、弱到强排列，均来自原方案。
- 同分不拆层、没有行为去重，均是明确的方案选择；OBP 层塌缩不是分位数函数写错。
- Pivot 不绑定某个底座，要求替代主要决策方法；当前英文基本对应原方案，无法把未强制偏离当前最好方法解释成漏实现了某条硬要求。
- Fuse 从已采到参考中选最好者、取消旧 top5 和血缘限制，也来自原方案；大量 donor 较弱不是指针选错。
- 原方案主动放弃真实祖先形成链，使用按分数排列的程序材料；不能把缺少真实变化顺序判成实现偏离。

已有日志核查逐步复算了两版约 2.6 万次父代/算子分配，概率与次数一致；V10.7 8,668 次搜索的完整程序、fitness、排序、父代/donor 索引和调用协议均对应。没有发现预算错计、采到未来节点、错误替换父代、额外第二调用等能解释退化的主循环错误。

容量检查从全候选预筛改成抽中后有界检查，确实改变了工程实现顺序。但正式快照没有 fit rejection 或参考短缺，未见长代码被容量机制系统性拒绝的证据；不能用这个差异解释当前主要退化。

## 3. 当前具体设计的三个不足

### 3.1 跨质量参考直接担任 Fuse 主输入，带来材料质量风险

固定每路前 250 次评价，三重复汇总：

| 指标 | TSP V10.6 → V10.7 | VRPTW V10.6 → V10.7 |
| --- | --- | --- |
| donor 属于当时 top10% | 79.4% → 38.9% | 79.8% → 20.2% |
| donor 弱于父代 | 47.1% → 66.8% | 44.8% → 88.5% |
| 有效 Fuse 子代超过父代 | 30.5% → 6.2% | 27.3% → 12.8% |
| 有效 Fuse 子代超过最好上下文 | 12.7% → 2.5% | 12.7% → 9.6% |

父代平均分位基本接近（TSP 89.1%→87.3%，VRPTW 88.8%→90.2%），整个上下文包含当时最好分数的比例反而增加。材料质量的主要变化是第二份主材料变弱。

这有清楚的机制解释：若三层各约三分之一、无大量并列，两个参考优先来自不同层，那么抽到 high 的概率约 2/3；high 中属于全档案 top10% 的比例约 30%。最终 donor 属于 top10% 的概率因此约为 20%，与 VRPTW 实测接近。

低分程序可以提供反例或替代结构，但“适合作为对照”不等于“适合作为必须结合的主输入”。当前同一套材料规则同时服务 Refine/Pivot/Fuse，没有根据动作目的区分反例、替代方案和强合作对象。这属于具体方法设计的不足，不能全部交给代码修复。

上述统计仍是观察关联。有效子代经过不同格式筛选，父代与档案状态也不同；不能把 donor 分数与融合收益的同时下降当作完整因果证明。

### 3.2 分数覆盖与完整代码去重，都不保证有新的决策信息

V10.7 OBP rep2/3 的 1000 次评价都未超过最初的 −744.5；分别有 913/946 份不同完整代码，却有 977/995 个节点与最优同分。两路分层边界始终重合，92.3%/98.6% 的上下文三份程序全同分。

不能由同分直接推出行为等价，但已有公式级反例：`-slack+ε*b`、`-slack-ε*b`、`1/(1+slack)` 在本任务可行域内都保持 Best-Fit 排序。当前层与代码去重规则允许这些程序反复充当“不同算法”。它们的节点选择已经很分散，继续分散 node ID 不会自动解决这种信息重复。

TSP 还说明了另一种不足：代码看似有不同 cohesion、regret、退出代价项，实际主分数却全部 NaN，行为仍相同。只用最终 fitness 和原始设计 Idea，无法把有效部分与无效部分分开。高分实际来自最近邻或精确尾部，却与宣称更复杂主决策的文字一起入档，形成不准确的算法解释。

这不是要求下一版必须加复杂的语义聚类，而是说明当前“跨分数层＋不同代码”没有兑现我们希望它提供的行为差异。广义主动取材仍可成立，当前代理指标不够。

### 3.3 算子目的被放松，材料对照不自动变成有效改进

旧 Pivot 明确要求相对当前算法换主要思路；新版提出 alternative main decision method，但不明确相对哪份材料。旧 Fuse 要求设计改进版本、争取超过双亲；新方案的指令主要要求形成连贯算法。

这些变化基本忠实于原始新方案，属于方法/提示设计。V10.6 本来就将所有有限有效 fitness 的候选入档，并没有“超双亲才准入档”的门槛；这里改变的是 donor 取样和生成目标措辞。不要求超双亲才入档，也不意味着需要弱化生成时争取改善的目标。无论保留哪种表述，都不能把算子被调用等同于实际完成了主要行为变更。

## 4. 确实存在的具体表达实现问题

### 4.1 历史 Algorithm 编号被放进新的编号空间

生成一个节点时，Idea 常写“结合 Algorithm 2 和 Algorithm 3”。实现将这段文字原样存为 `node.idea`，以后重新抽样、排序、编号时，又将它原样显示。相同序号这时已指向别的程序。

例：TSP rep2 的 node8 在评价9生成，其输入是 `[0,6,3]`，Idea 引用 Algorithm 3/2，原本对应 node3/node6。评价10将它展示在 `[4,5,8]` 中，Algorithm 3 变成 node8 自己，Algorithm 2 变成 node5。原文确实进入新 Prompt，没有被省略。

冻结 8,799 个候选的快照，以创建时与展示时的 `context_node_ids` 逐个解析编号，并排除不同节点但完全相同代码：

| 范围 | 展示块中编号对应了不同代码 |
| --- | ---: |
| 前250次评价 | 5,242 / 10,893（48.1%） |
| 全快照 | 12,566 / 26,004（48.3%） |
| TSP | 3,421 / 5,283（64.8%） |
| OP | 2,701 / 4,131（65.4%） |
| VRPTW | 2,445 / 4,893（50.0%） |

统计只包含明确的 `Algorithm N`，不含代码注释中的引用和其它写法。这是可复现的指代不一致，不能直接换算为模型误解率或性能损失率。OP 同样大量出现这一问题，却比 V10.6 同期更好，也提醒我们不能仅按出现频率判定唯一主因。

原方案没有明确规定 Idea 必须独立于生成上下文，这个接口条件在设计中也遗漏了。但把依赖旧编号的文本直接放进新编号空间，是可以具体修正的表达实现缺口。前次字段、索引和代码一致性检查没有覆盖“文本内部引用的意义”。

### 4.2 原始注释与额外长度约束，并非无影响的展示选择

V10.6 展示代码前移除 COMMENT token，保留可执行语句和 docstring；V10.7 直接展示原始 Code。原始方案要求完整代码，没有明确要求保留所有注释，当前实现因此额外展示了长自我讨论和旧 Algorithm 指代。

例如固定诊断的 OBP node61 有 2,636 字符注释和 6 处旧 Alg N 引用；TSP node83 注释也引用旧 Algorithm 3。只删除 Idea 仍会保留这些内容。它们可能干扰理解，但目前没有单独开关注释的完整搜索对照，不能认定其净影响。

100 words 输出要求和 256-token Idea 视图也是后加的工程选择。后者只省略了 97/26,004 个展示块，影响面较小；前者作用于所有生成，包括根，不能声称完全不影响表达。不过 V10.5 本来就要求约100词，且在 TSP 更强，所以“短 Idea 导致全面退化”不足以解释结果。

## 5. 反事实评价：只修生成代码，能否救回好 idea？

对 V10.7 TSP 三路最佳代码，各做三个版本，共 **9 次隔离评价**：原代码；只改一行、排除被置 inf 的对角后再求行均值；显式最近邻主体＋原尾部代码。其它权重、尾部条件、任务数据和20秒限时均保留。

| 候选 | 原代码 | 仅修 inf 均值 | 显式最近邻＋原尾部 |
| --- | ---: | ---: | ---: |
| rep1 n279 | −6.533894 | −7.635332 | −6.533894 |
| rep2 n67 | −6.823969 | −7.138143 | −6.823969 |
| rep3 n391 | −6.685091 | −7.056994 | −6.685091 |

全部完成，未超时。原代码精确复现历史 fitness；最近邻控制也逐一精确同分。原主分支全部选最近邻；修复后分别有 139/592、53/768、42/656 次主分支选择偏离最近邻。

**三份算法中，数值错误都掩盖了更弱的显式打分。** 修复实现没有恢复更强的算法 idea，反而暴露了打分组合本身的问题。不能据此说所有归档 idea 都弱，但足以推翻“这三条最佳路线只要修 NaN 就能恢复竞争力”的解释。

这个实验检验的是生成求解程序，不是对全档案采样机制做因果消融；不能将它直接当作搜索方法 idea 的否定证据。它也不证明该打分族所有参数都无效，只说明原有参数与条件下，纠正这一数值错误没有恢复竞争力。

## 6. 固定 Prompt 小对照

24次生成及24次隔离评价全部完成，全部 stop、通过严格解析、评价成功，无超时或补采样。实验方案在生成前固定：四个回顾性失败锚点、每个三种条件、两个共享采样 seed；同一 server3b 后端，最多三并发，16384 输出预算、严格原解析、原任务评价配置。

四个锚点为 TSP Pivot、OBP Pivot、TSP Fuse、VRPTW Fuse。A 原 Prompt 逐字重放；B 仅清空各程序 Idea；C 对 Pivot 恢复单调用祖先上下文组合，并保留100词输出约束，对 Fuse 仅换成当时最强可用跨血缘 donor，保持另一个辅助参考和父代不变，更新必要排序与序号。

独立复核确认 A 与原日志逐字一致、B 代码未改、Fuse C 没有采到未来程序。Pivot C 同时改变历史材料、旧算子指令和去注释视图，是组合对照；Fuse C 使用最强可用 donor，并非重现旧 top5 均匀抽样。每臂仅两个 seed，锚点又是回顾性选取，结果只能检验局部反应，不能据此宣称完整搜索或总体成功率。

下表每格依次为两个 seed 的 fitness，越高越好：

| 锚点与父代 fitness | A 原 Prompt | B 清空 Idea | C 对照 |
| --- | --- | --- | --- |
| TSP Pivot，−6.82397 | −7.69884 / −7.62590 | −6.82397 / −6.78870 | −8.61902 / −7.99895 |
| OBP Pivot，−744.5 | −744.5 / −744.5 | −744.5 / −2359.5 | −3000 / −3000 |
| VRPTW Fuse，−20.69657 | −20.91309 / −20.80548 | −21.03378 / −20.78929 | −21.13827 / −20.69657 |
| TSP Fuse，−6.71086 | −6.71086 / −6.71086 | −6.84976 / −6.71086 | −6.99930 / −6.71086 |

这组结果约束了可以下的结论：

- 去掉 Idea 仅在这个 TSP Pivot 锚点两次都优于原 Prompt；其它锚点混合。它说明某些 Idea 可能有负作用，不能支持普遍删除 Idea。B 同时删除设计信息、减少输入，还保留代码注释，既不是编号问题的纯消融，也没有清除全部旧指代。
- 恢复祖先上下文组合的四个 Pivot 候选全部更差，不能期待简单切回立即修复这些状态；但每锚点仅两个 seed，又使用了 V10.7 已形成的父代与历史，不能据此否定祖先机制在从头搜索中的作用。
- 更强 donor 没有稳定改善。VRPTW 一个 seed 好于A，另一个更差；TSP 一个持平、另一个更差。**上一轮“donor 变弱”的统计是成立的，但本轮没有支持把它认定为退化的充分原因或唯一主因。** 同一已陷入平台的档案里，“最强 donor”仍可能只是同类规则，分数更高并不保证互补。
- TSP Pivot B 略胜父代的一条仍保留 inf 主打分，只增加最后两个节点的精确比较；OBP C 明确生成 Worst-Fit，−3000 来自选择方向本身。有效返回与小幅提分依旧不能代替行为核查。

本组消耗119,975 tokens，累计生成时间923.5秒、累计评价时间24.6秒。加上前一组9次数值反事实，本次新增24次模型生成、33次独立评价，均在诊断目录记录，未混入正式预算。

## 7. 历史优秀路线究竟成功在哪里

TSP V10.6 rep1 提供了清楚的反例：n26/e36 也有 NaN 主打分，随后 n29/e42 的 Pivot 生成了真正执行的近邻补全＋2-opt，用候选首步之后完整尾路径的代价评价决策。n29 从 −6.47863 的父代提升到 −5.93337，随后 n63/e95、n64/e96 沿该结构继续改进到 −5.83911。前250内三者分别获得23/14/25次父代扩展。

相对地，V10.7 rep1 的 `169→196→201→203→205→215→220` 也持续得到开发，但主打分一直失效，主要提高精确尾部阈值。旧版的代表成功来自改变了真正起作用的主决策，再让这一结构得到开发；代码更长、调用更多或节点更多都不是这个成功机制本身。

OBP 也有相同区别：V10.6 三路在评价105/155/77跳出 Best-Fit，随后继续开发有效的剩余空间处理。V10.7 只有 rep1 在 e196 Pivot 首次小幅突破，e198 Refine 即达到 −728.5；它说明新方案有能力完成这条收益链，但另两路全程没有找到并开发有效偏离。

这些是真实路线证据，解释了分数为何不同；它们尚不能证明是哪一种上下文导致模型生成了首次突破。尤其不能反推“第二次摘要必然是成功原因”：V10.1–V10.5 没有同样的独立校准流程，也有更好的同期 TSP；V10.6 自己的摘要还漏掉过 NaN 等价退化。

## 8. 其它因素能否解释差距

| 解释 | 核查结果 | 仍然存在的限制 |
| --- | --- | --- |
| 评价任务或预算变了 | V10.5–V10.7 的任务配置和评价器源码哈希一致；按真实评价序号对齐 | 不能用有效率替代质量；失败评价与无效生成成本不同 |
| V10.7 只是还没跑完 | 前250已存在明显TSP差距；500采用相同已达预算rep子集仍有差距 | 完整终局和未见实例表现仍应等完成后比较 |
| local、坏初始化导致TSP退步 | TSP rep3 两版同server3b、最佳根分数和主要排序公式相同，250仍为6.23275对6.74618 | 其余7根和后续随机轨迹不同，不能当作完全配对实验 |
| 后端整体变差 | 同endpoint的CVRP rep3、OP rep3反而V10.7更好；没有统一方向服务退化证据 | 同模型ID不是历史权重、量化、负载完全一致的证明 |
| 100词导致思考/代码全面简化 | V10.5已有约100词；V10.7 TSP注释词268接近V10.6的278，OP代码结构几乎不变 | 字数和AST不是思考量；长度约束与新上下文的交互未隔离 |
| 格式解析筛选差异 | 确实存在：TSP前250的生成/拒绝为V10.6 917/167，V10.7 754/4；被拒可恢复代码更复杂 | 没有评价被拒样本，无法判定过滤有益还是有害 |
| 取消校准损失了可靠纠错 | 第二调用存在但准确性未获净价值证明，且有明确漏错反例 | 整套两阶段流程是否改善搜索，需要匹配的独立消融 |

格式筛选特别需要保留：V10.6 的 TSP 被拒但可提取、可编译且签名正确的代码，AST节点中位数为1088，成功入档为524。因而两版“有效子代超父代率”比较的是不同筛选后的分布。按评价预算比较也没有匹配生成次数，以及无效生成产生的额外父代计数更新。这个因素不能简单认作收益或损失，但不能忽略。

## 9. 归因结论与下一步

当前不应把 V10.7 描述为“核心想法已正确，只是主循环几行代码写错”。主循环基本忠实于原方案；弱 donor、同分层塌缩和缺少行为差异都是当前具体方案允许甚至预期的结果。它们暴露了方案设计本身的不足。

同时，“实现完全没问题”也应撤回。历史编号进入新编号空间、完整原始注释的额外曝光、未单独验证的长度约束，都属于具体表达实现或工程取舍。尤其编号错指是已经确认、应修正的信息一致性缺口；它的性能影响不能凭覆盖率直接定量。

对广义“从全档案组织有用程序材料”的 idea，当前证据还不足以判死。更合理的工作结论是：**V10.7 这一具体实例尚未稳定形成更有效的材料选择与行为改进，TSP/OBP 已有明确不足，并夹带表达实现缺陷；没有依据承诺修一个解析器或 NaN 就能恢复 SOTA。** OP 和 OBP rep1 的正面结果必须同时保留，具体长期主因仍未被独立识别。当前没有相同格式下均匀采样与分层采样的正式对照，不能判定质量分层本身有害。后续应把表达修正、算子材料分配、分层相对均匀抽样分别隔离，保留单调用作为共同基线，避免再把多个变化绑在一个版本里比较。

可立即明确的处置顺序是：先修正记录在新上下文中的语义一致性，明确自足 Idea 与注释视图；再比较相同表达实现下的材料策略。编号修正属于正确性要求，其搜索收益仍需测量。暂不根据本次两样本 pilot 直接宣布删除 Idea、恢复旧上下文或恢复独立校准。
