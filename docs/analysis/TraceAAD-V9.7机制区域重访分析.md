# TraceAAD V9.7 机制区域重访分析

对 V9.7 正式四任务三重复搜索按程序创建顺序重放，测量每次生成落在静态机制代理区域的新颖度，回答一个门槛问题：全局信息进入生成提示，有没有可测量的 proposal 杠杆。

## 1. 口径

- **区域**：`mechanism_tags` 在去除注释与字符串的词法 token 上打机制标签，`macro_family` 归并为任务内宏簇。静态代理可审计，非语义真值。
- **child**：形成新程序的一次响应。无效与未形成新程序的响应不进入 child 统计，仍计入预算份额的分母。
- **已访问**：同一 run 中创建时间严格早于本次的全体程序。
- **重访**分三层：child 的标签组合等于某个已出现组合（标签组合重访）；child 的宏簇已被访问（宏簇重访）；child 未引入任何新机制标签（无新标签）。
- **家族前沿**：该宏簇已创建程序的最大有向质量 $q$。

## 2. 现象

### 2.1 语义空间小且早期耗尽

每 run 访问宏簇 4–6 个、不同标签组合 10–48 个，对照每任务 2,400–2,900 个 code-novel child。进入初始根之外的新宏簇每 run 2–3 次，全部发生在前 125 次评价（四任务进入时点中位数为第 4–73 次）。此后约 85% 以上的预算在已访问宏簇内运动。

### 2.2 Explore 的换簇几乎全部落在已访问宏簇

| 任务 | Explore child | 换簇率 | 换簇后落回已访问宏簇 | 标签组合重访 | 宏簇重访（全部 child） |
| --- | ---: | ---: | ---: | ---: | ---: |
| TSP | 709 | 37.2% | 98.1% | 92.2% | 99.3% |
| CVRP | 786 | 48.9% | 97.9% | 92.2% | 99.0% |
| OP | 854 | 53.9% | 99.8% | 98.7% | 99.9% |
| OBP | 845 | 36.9% | 98.4% | 97.4% | 99.4% |

Refine 参照：换簇率 2.3%–12.1%，换簇后落回已访问宏簇 98.7%–100%。

### 2.3 重入来自下方，目的地集中于主导家族

| 任务 | Explore 出生即达家族前沿 | Explore 低于家族前沿 $1s$ 以上 | Refine 出生即达家族前沿 | Refine 低于前沿 $1s$ 以上 | 换簇首位目的地及份额 |
| --- | ---: | ---: | ---: | ---: | --- |
| TSP | 5.2% | 52.2% | 8.7% | 13.1% | local_score 68% |
| CVRP | 6.0% | 78.6% | 15.0% | 3.7% | angular_radial 57% |
| OP | 7.4% | 81.9% | 24.2% | 47.2% | feasibility_density 42% |
| OBP | 6.2% | 33.6% | 22.6% | 5.5% | best_fit 51% |

Explore child 只有 5.2%–7.4% 在出生时达到所在宏簇的当时前沿；三分之一到五分之四低于前沿超过一个 $s$。换簇目的地集中在程序数最多的主导家族。

### 2.4 亚前沿重入占用约四分之一预算

无新标签的 Explore child 占总搜索响应的比例：TSP 23.4%、CVRP 25.5%、OP 27.8%、OBP 27.7%。Explore 响应本身约占预算 29%。

### 2.5 被放弃路线几乎没有宏簇级独有知识

12 个 run 中，仅 3 个 run 存在只出现在非顶路线的宏簇，其最好质量距 run best 分别为 5.2、3.9、0.4 个 $s$。路线吸收态丢掉的是来源继续权，几乎没有丢掉宏簇知识。

### 2.6 新宏簇进入稀有但接近前沿

首次进入的宏簇，其最终最好质量距该 run 全局最好中位为 0.07–0.72 个 $s$；距 run best 不超过 2 个 $s$ 的占 78%–100%。首次进入来源：TSP 六例中五例、CVRP 九例中八例、OBP 八例中五例由 Explore 完成；OP 七例中仅一例（三例来自初始化、三例来自 Refine）。

### 2.7 最好家族与最大投入家族错位

TSP 中 completion_rollout 以中位 19 个程序达到宏簇最好 $q=-5.963$，local_score 用 295 个程序止于 $-6.052$；CVRP 中 sweep_partition 以 70 个程序达到 $-8.980$，angular_radial 用 151 个程序止于 $-9.509$。程序数是投入的粗代理，该错位描述预算分布与前沿分布的差距，不构成分配错误的因果证据。

## 3. 分析

1. **杠杆存在，对象是区域前沿认知。** 生成提示不含任何全局信息，而 Explore 在不知情时反复从下方重入已知区域：约四分之一预算用于这类 child，其中仅 5%–7% 推进所在宏簇前沿。若模型在生成前知道各已访问区域及其前沿质量，这部分预算存在被改写的空间。
2. **跨路线代码迁移的静态杠杆近零。** 吸收态没有造成宏簇知识损失，按路线组织全局记忆没有可利用的对象。
3. **全局信息的信息量很小。** 每 run 4–6 个宏簇、10–48 个标签组合即可完整描述已访问区域及其前沿，作为生成条件的成本可审计。
4. **发现事件前置且稀有。** 新宏簇进入集中在初始化后前 100 余次评价，awareness 机制的设计目标应是避免亚前沿重入，而非延长发现期。
5. **任务异质。** OP 的宏簇首次进入几乎全部来自初始化与 Refine，与其 improve 稀疏、早期耗尽较低前沿的画像一致；CVRP/OP 的亚前沿重入率（78.6%/81.9%）也明显高于 OBP（33.6%）。

## 4. 边界

宏簇粒度粗会机械抬高重访比例：2.2 的数字部分由"少量家族、早期全部访问过"的结构决定，决策相关量是 2.3 与 2.4 的亚前沿重入规模。重访分析只测量现状，不识别"若模型知道前沿会怎样改写提议"，后者属于固定锚点单步实验。静态标签不等于真实算法族，标签组合数是语义空间大小的下界代理。
