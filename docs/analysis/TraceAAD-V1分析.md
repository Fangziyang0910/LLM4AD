# TraceAAD V1 分析

> 版本规范:无(V1 未留下独立机制设计文档,事实来源见 [版本实验事实与机制诊断](TraceAAD-版本实验事实与机制诊断.md))
> 状态:2026-08-07 冻结;历史版本,不定义当前方法。结果不进入正式结果页。

## 1. 版本定位

V1 是 TraceAAD 的首个可运行版本(2026-W28 建立),"算法改进历史指导下一步"主张的第一次落地:在程序图与轨迹之上同时使用模式记忆、六算子、自适应 portfolio、Elo 成对比较、island、novelty gate 与 Pareto 生存。设计意图是让历史、差异、信用、多样性等多类信号共同决定程序的保存与展示。

## 2. 实验事实

无归档工件与批次/代码记录,事实仅来自已删除版本诊断文档的迁移条目。同跨规模口径 TSP200 12.306、CVRP100 15.955(数值越低越好)已具备竞争力,但控制层多、结果波动大。V1 的 OP 使用 `orienteering_construct`,与 V4 以后的 `op_aco` 不同,不能直接串联比较;V1/V2/V3 也没有当前四任务的完整同协议覆盖,以下结果只用于解释机制演化。

## 3. 机制检验

| 机制 | 检验状态 | 证据 | 证据级别 |
| --- | --- | --- | --- |

## 4. 结论

1. V1 证明历史结构(图、轨迹、记忆)与算子集合足以支撑有竞争力的搜索(TSP200 12.306、CVRP100 15.955),但控制层过多导致结果波动大。
2. 多种弱代理共同决定保存与展示时,机制标签和统计把模型声明当作稳定语义,没有任何一层被证实贡献独立价值——归因困难从此成为叠加设计必须回答的问题。
3. 该判断直接导向 V2 的完整机制叠加与 V3 的系统性删减;V1 的 OP 口径与后续不可比,结果不进入正式结果页。
