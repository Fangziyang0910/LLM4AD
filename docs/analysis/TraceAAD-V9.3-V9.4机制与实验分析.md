# TraceAAD V9.3 / V9.4 机制与实验分析

> 冻结对象：V9.3 批次 `20260809_134642`、V9.4 批次 `20260810_0024`，四任务 × 三重复 × 1000 方法样本及全部 held-out 测试。分析日期：2026-08-11。
>
> 运行行为分别以 [V9.3 完整机制设计](../methods/TraceAAD-v9.3完整机制设计.md)和 [V9.4 完整机制设计](../methods/TraceAAD-v9.4完整机制设计.md)为准。本文是联合版本审计，不把联合结果归因给未经消融的单个组件。

## 核心判断

V9.3 的联合结果比预期好：相对直接前版 V9.2，它在 15 个 held-out task × scale 单元中 10 个更好、1 个持平、4 个更差，主要收益来自 CVRP、OBP 和 OP，TSP 则退化。V9.3 的运行间波动也显著小于 V9.4。它不能因为结果较好就变成正确的决策定义，但数据表明“允许一段算法方向在退步后继续发展，再只让整段代表参与全局竞争”是有价值的搜索归纳偏置。

V9.4 做对了基本决策单位：一次选择、一次联合 `Idea + Code`、一次评价、一次更新；模型调用约减半，有效候选率由 V9.3 的 92.5% 提高到 95.4%。但 V9.4 没有形成稳定的质量增益：相对 V9.3，15 个 held-out 单元只有 5 个更好、10 个更差；相对 V9.2 也只有 6 个更好、1 个持平、8 个更差。它在 TSP 出现一个很强的 repeat，同时在 OBP 出现一个 1000 样本仍未超过第一个程序的 repeat，说明当前机制提高了结果上限，却明显降低了可靠性。

两版最关键的共同失败是预算仍然没有真正由轨迹价值决定。V9.3 的 rollout 价值从未让一个被选择锚点的 `Q` 高于自身质量；V9.4 的折扣信用虽真实更新，却只在 114 / 11,799 次正式选择中选到有正信用增益的锚点，而且全部依赖第五次的质量区覆盖，最高 `Q` 利用从未因信用选择一个原始 fitness 更低的锚点。两版正式预算平均都有约 98.5% 落在单一初始谱系，`8 -> 6` 路线初始化没有变成持续的多路线搜索。

因此当前最准确的结论是：

- V9.3 是结果上较强、机制职责上混杂的历史版本；有效信号主要来自连续发展和代表筛选，不来自 rollout 数值信用。
- V9.4 是决策语义和运行效率更正确的骨架，但折扣信用、所有子代入池和 `4:1` 覆盖的组合没有稳定提高最终质量。
- 轨迹窗口确实进入了生成过程，尚无无历史对照证明“历史本身”提高了生成质量；这项科学主张仍未被 V9.3 / V9.4 联合实验单独识别。

V9.2 只作为直接前版结果基线。V9.3 与 V9.4 的机制比较使用相同模型、四个任务、每个 run 1000 个方法样本和三个重复。搜索集 `score` 已统一为越大越好；held-out 表使用任务原生 objective，并在任务名后标明方向。

| `search_aborted=false` | 12 / 12 | 12 / 12 |

### 1.1 两个工件边界

V9.3 CVRP repeat 1 恢复运行后在 JSONL 末尾追加了 9 条重复 `sample_order=753..761`，所以该文件有 1009 行，`summary.json` 的 `candidate_count` 和测试结果中的 `num_valid_samples` 也多计了恢复前记录。checkpoint 仍是 1000 个方法样本、992 个评价事件；最终 best 位于 sample 930，未落入重复区。本文候选有效率按每个 `sample_order` 的最后一条记录去重，最终程序和 held-out 结果不受影响。

V9.3 TSP repeat 3 与 V9.4 TSP repeat 3 的训练重算分数分别相对搜索工件变化约 0.031 和 0.013。held-out 评价使用保存程序重新运行，结果完整；搜索表保留实验过程中实际用于选择的 artifact score。这两个差异提示训练 evaluator 仍有小幅重复评价误差，不影响下面关于预算流和谱系的计数结论。

### 3.1 按任务解释

**CVRP。** V9.3 是三版中唯一同时改善三个测试规模的版本，且 CVRP50 / 100 方差下降。V9.4 三个规模均低于 V9.3，CVRP100 / 200 也低于 V9.2。这里支持 V9.3 的持续短程发展和强筛选，不支持 V9.4 当前信用闭环。

**OBP。** V9.3 在 capacity 100 的 5k / 10k 上形成大而稳定的收益，在 capacity 500 也不差于 V9.2。V9.4 repeat 2 的搜索 best 始终是 sample 1，OBP10k / 100 测试为 4166.8；另外两个 repeat 分别为 4040.2 和 4051.2。均值仍优于 V9.2，但稳定性明显差于 V9.3。这个 task 最清楚地暴露了“质量区覆盖不等于脱离错误主谱系”。

**OP。** V9.4 搜索 best 均值最高，held-out OP100 / 200 却低于 V9.3，说明训练搜索增益没有稳定泛化。V9.3 的搜索均值几乎等于 V9.2，但 OP100 / 200 更高且方差显著更小；它更像获得了稳健的中大规模程序，而非只提高训练标量。

**TSP。** V9.3 三规模均低于 V9.2。V9.4 相对 V9.3 三规模都提高，但主要由 repeat 3 的强程序驱动：TSP100 三个结果为 `9.314 / 8.726 / 7.835`，TSP200 为 `13.295 / 12.393 / 11.137`。这证明 V9.4 可以形成很长的小步改进链和较高上限，却没有证明它能可靠找到这类链。

V9.4 相对 V9.3 只有 2 / 15 个 held-out 单元具有更小的重复间标准差，即 V9.3 在 13 / 15 个单元更稳定。这是当前两版最一致的结果差异。

## 4. V9.3 过程：有效的是连续发展，不是 rollout 信用

V9.3 共完成 3,876 个正式 rollout。只有 154 个（4.0%）代表程序严格优于起始锚点，3,722 个（96.0%）最终仍由起始锚点或等质量程序代表。三步协议因此大量消耗在“退步后恢复到原位”，并没有普遍产生三步净增益。

但这些少数净增益高度伴随多步连续发展：

- 154 个净改善 rollout 中，135 个曾在某一步相对直接父代退步；
- 62 个 rollout 真实跌到起点以下后又超过起点；
- 139 次严格全局突破中，第一、二、三步分别贡献 61、43、35 次，56.1% 来自第二或第三步；
- 其中 50 次突破发生在该 rollout 已经跌到起点以下之后。

这符合“算法修改常需先引入一个不完整中间状态，再校准或修正”的直觉。第一步相对父代的改善率只有 `80 / 3587 = 2.2%`，第二、三步分别为 30.6% 和 30.1%；后两者很大一部分是从较差中间节点恢复，但确实有 62 次最终越过起点。V9.3 最好程序的形成路径也普遍包含这类模式，例如 CVRP repeat 2 的 sample `531 -> 532`、OP repeat 2 的 `309 -> 310`、TSP repeat 1 的 `417 -> 418 -> 419` 都先退步，再在同一 rollout 后续步骤恢复并突破。

代表筛选进一步形成了强过滤：3,876 个 rollout 只有 208 次产生新的合格代表，run 结束时平均只有 23.3 个合格锚点。这与 V9.3 的稳定性一致，也揭示了其不足：大量有效中间程序被保留为事实，却没有独立获得全局预算资格。

rollout 数值信用本身基本无效。去重后的 3,876 次全局选择中，没有一次选择时 `Q(a) > q(a)`；一旦 rollout 得到更好的代表，新代表以更高原始 fitness 进入候选并直接压过获得均值更新的起始锚点。V9.3 的预算流仍由当前最好程序驱动，`Q` 只是记录，没有成为选择原因。

### V9.3 的机制判断

- **固定三步连续发展：部分有效。** 它真实产生了晚步突破和跨退步恢复，并与三个 task 的稳定收益同向；同时 96% rollout 无净改善，固定三步不是高效或概念正确的通用决策单位。
- **best-of-rollout 代表筛选：结果上有效、因果未分离。** 它抑制锚点爆炸并提高稳定性，但与连续发展、两阶段提示和更深初始化同时改变。
- **rollout `Q`：基本无效。** 数值没有成为实际利用决策的依据。
- **两阶段 Idea / Code：未证明有效。** 机制确实运行，却把模型调用翻倍；当前没有保持其他机制不变的联合生成对照。
- **三步初始化：有正结果信号。** 同为 sample 32 时四任务都优于 V9.4，但初始化形成的路线多样性没有延续到正式搜索。

## 5. V9.4 过程：覆盖有局部价值，信用没有主导预算

### 5.1 一步联合生成做对了什么

V9.4 的 11,799 个正式事件都遵守“一锚点、一窗口、一份联合 `Idea + Code`、一次评价、一次更新”。有效候选率比 V9.3 高 2.85 个百分点，模型调用量约减半。平均形成历史 / 下游事件数从 V9.3 的 `6.40 / 1.43` 变为 `3.89 / 3.92`；77.1% 的 V9.4 正式窗口同时含形成与下游证据，而 V9.3 只有 37.6%。V9.4 的轨迹上下文更加平衡，也更接近设计中的锚点化局部证据窗口。

这些事实证明机制运行和信息流闭合，不证明历史提高了候选质量。没有 `current_only` 或无下游窗口对照，不能从窗口非空推出历史有效。

### 5.2 折扣信用确实计算，但几乎没有改变利用

V9.4 的正式有效事件在距离 1、2、3 上分别产生 11,258、9,853、9,398 次信用观察，其中正信用为 242（2.1%）、671（6.8%）、1,066（11.3%）。距离越远正信用越常见，是因为较早祖先通常更弱、更容易被后代超过；`0.5^d` 只缩小信用幅度，没有消除“弱旧祖先更容易获得正信用”的发生率偏置。

信用对候选池不是完全无影响：11,819 次选择尝试中，`Q` 前十集合有 1,575 次不同于纯原始 fitness 前十。但它几乎没有改变实际预算落点：

- 只有 26 次选择落在纯原始 fitness 前十之外，占 0.22%；
- 只有 5 次所选锚点的原始 fitness 严格低于纯 fitness 第十名；
- 正信用使 `Q(a) > q(a)` 的锚点只被选择 114 次，占正式选择约 1%；
- 114 次全部来自 `quality_local_exploration`，最高 `Q` 利用从未因为信用改选一个原始 fitness 更低的锚点。

因此 V9.4 的折扣信用不是“没有运行”，而是“运行后很少改变分配”。它当前更像质量区覆盖的一个入池修正，尚未成为预算价值的主导证据。

114 次正信用覆盖选择中有 11 次直接改善、3 次严格突破，改善率 9.6%，高于全部覆盖事件的 3.0%。这是一个值得保留的探索性信号：收到延迟信用的旧锚点可能确实更值得重访。由于这些锚点不是随机进入覆盖，且跨 task 汇总，当前不能把差异解释为信用的因果收益。

### 5.3 `4:1` 质量区覆盖是局部有效机制

V9.4 三类选择的过程结果为：

| 分配模式 | 事件 | 直接改善 | 严格突破 |
| --- | ---: | ---: | ---: |
| 新锚点基本验证 | 1,046 | 112（10.7%） | 42（4.0%） |
| 质量区覆盖 | 2,352 | 70（3.0%） | 27（1.15%） |
| 最高 `Q` 利用 | 8,401 | 60（0.71%） | 60（0.71%） |

成熟最高分锚点已经接近平台，继续利用的改善率最低；基本验证新锚点的改善和突破率最高；覆盖处于两者之间，并以不足三分之一的预算获得了接近一半的利用突破数。固定覆盖不是装饰，它确实从纯利用在相同轮次不会选择的锚点中找到了突破。

它仍不足以证明 `4:1` 是合适比例，更没有改善独立路线覆盖。该规则只在 `Q` 前十内选择，而前十几乎都来自同一谱系。它增加的是主谱系内部的旧锚点重访，不是多个算法方向之间的预算分配。

### 5.4 退步节点保留了事实，却很少得到发展

V9.4 正式搜索产生 8,917 个相对父代退步的有效子代。只有 334 个（3.7%）后来被选中，325 个实际产生了子代。被扩展的退步节点中，107 个在三层内产生了优于自身的后代，47 个重新超过退步前父代，31 个最终通向严格突破。

这组数据同时支持两个判断：暂时退步路线确实存在延迟价值；“让所有退步节点获得资格”并不等于系统会给它们预算。质量前十门槛和新高分锚点竞争使 96% 以上退步节点从未被重访。V9.4 保留了正确事实，却没有形成稳定利用这些事实的分配机制。

### V9.4 的机制判断

- **一步联合生成：运行与效率上有效。** 决策语义正确、调用减半、有效率提高；最终质量没有稳定胜出。
- **三层折扣信用：数值运行，分配上基本无效。** 它改变过候选池，几乎不改变最高 `Q` 利用的实际选择。
- **`4:1` 质量区覆盖：局部有效。** 单位预算突破率高于纯利用，并让少量正信用锚点获得重访；它没有保护多谱系。
- **所有有效子代入池：副作用大于已证收益。** 合格锚点从平均 23 增到 944、被选锚点从平均 21 增到 107，最终却仍单谱系集中，并伴随更高结果方差。
- **真实失败记忆：有运行证据，质量作用未证明。** 它改善总体有效率，但没有可靠消除重复错误。
- **严格突破与信用日志：有效的可观测性。** 它们使上述判断可审计，本身不构成搜索质量机制。

## 6. 两版共同问题

### 6.1 多路线初始化没有转化为多路线搜索

按每个 run 先计算再平均，V9.3 和 V9.4 的正式事件落在第一初始谱系的比例分别为 98.55% 和 98.52%，谱系有效数都约为 1.03。V9.3 每个 run 平均选择 20.8 个不同锚点，V9.4 提高到 107.3 个；锚点数增加了五倍，谱系集中完全没有改善。

这说明锚点分散不能替代路线分散。`8 -> 6` 初始化目前主要用于提高找到一个好起点的概率，其余路线几乎没有形成持续历史。V9.4 的覆盖也只是主谱系内部覆盖。这个结果符合“fitness 前十会自然集中”的机制逻辑，却出乎多路线轨迹设计的原始期待。

### 6.2 数值信用被更好的后代自身遮蔽

V9.3 和 V9.4 都遇到同一个结构问题：如果成功后代本身立即成为合格锚点，它的原始 fitness 通常高于父代或祖先收到折扣后的 `Q`。于是后代继续得到利用预算，祖先信用只改变日志。V9.4 通过固定覆盖让少量祖先重访，缓解但没有解决这一问题。

这不是调大 discount、深度或前十数量就能解决的尺度问题。预算对象仍需回答：为什么重新从旧锚点及其更新后的知识状态出发，会比直接从已出现的优秀后代继续更有价值？当前信用定义没有提供足以改变该比较的证据。

### 6.3 失败记忆减少总失败，但重复模式仍存在

V9.4 在 98.6% 的候选生成 prompt 中实际展示了任务内已验证失败反馈。候选失败由 V9.3 的 897 次降到 555 次；前半程和后半程失败率由 V9.3 的 `7.05% -> 7.90%` 变为 V9.4 的 `4.83% -> 4.42%`。这是正向运行信号。

但 V9.4 的 555 次失败中有 342 次（61.6%）重复了该 run 先前完全相同的失败模式，高于 V9.3 的 54.3%。TSP timeout、通用 parse failure、矩阵维度和非有限矩阵错误仍会反复出现。总失败下降同时受到联合生成、候选分布和失败记忆影响；没有关闭失败记忆的 V9.4 对照，当前只能判断“机制运行且可能有帮助”，不能判断它已经有效消除重复失败。

## 7. 符合直觉与出乎意料的结果

### 符合直觉

1. 退步后继续生成有时必要。V9.3 的晚步突破和 V9.4 被扩展退步节点中的延迟恢复都支持这一点。
2. 两阶段生成会真实增加推理成本；当前没有证据表明这份额外成本换来独立收益。
3. 只在 fitness 前十内部覆盖不会保护初始路线多样性；两版都重新坍缩成单谱系。
4. 成熟最高分锚点容易平台，未验证锚点和适量覆盖比持续纯利用更容易产生下一次突破。
5. 允许所有有效子代参与竞争会增加选择空间和后程机会，也会放大早期随机路线差异。

### 出乎意料

1. 概念上有缺陷的 V9.3 在三个 task 上比修正后的 V9.4 更强、更稳。结果揭示的有效成分是“连续机会 + 代表过滤”，不是错误的三步决策语义本身。
2. 两版声称用于预算的数值信用都几乎没有成为实际选择原因。V9.4 设计中最核心的新量，在最高 `Q` 利用上对原始 fitness 排序产生了零次可观察反转。
3. V9.4 的正信用发生率随距离上升，而非下降。折扣控制了幅度，却没有控制弱祖先更容易得到正信用的机会偏置。
4. V9.4 的覆盖比纯利用更容易突破，却没有带来更好的平均最终结果。局部探索是必要的，但当前探索对象和路线边界仍然错误。
5. V9.4 同时产生 OBP 不动和 TSP 大幅突破的 repeat。当前方法具有较强上限，但可靠性主要取决于早期进入哪条主谱系。

## 8. 最终机制结论

| 机制 | 判断 | 主要依据 |
| --- | --- | --- |
| V9.3 三步连续发展 | 部分有效 | 62 次真实跨谷，56.1% 严格突破来自后两步；同时 96% rollout 无净改善 |
| V9.3 代表筛选 | 结果上有效，未独立识别 | 合格锚点平均仅 23.3，结果稳定；与其他组件耦合 |
| V9.3 rollout `Q` | 无效 | 0 / 3,876 次选择出现 `Q(a) > q(a)` |
| V9.3 两阶段生成 | 未证明有效 | 调用约翻倍，无同骨架联合生成消融 |
| V9.4 一步联合生成 | 工程与语义有效 | 决策单位正确、有效率 +2.85 个百分点、调用约减半 |
| V9.4 三层折扣信用 | 基本无效 | 仅 114 次正信用锚点被选，全部依赖覆盖；利用排序零反转 |
| V9.4 `4:1` 覆盖 | 局部有效 | 突破率 1.15%，高于纯利用 0.71%；不保护谱系 |
| V9.4 退步节点资格 | 事实有效、分配无效 | 8,917 个退步子代仅 334 个被重访 |
| V9.4 失败记忆 | 有希望但未证明 | 总失败降低，完全相同错误仍有 61.6% 为重复 |
| `8 -> 6` 多路线初始化 | 多样性目标无效 | 两版约 98.5% 正式预算集中到一个初始谱系 |
| 规范局部轨迹窗口 | 已运行，质量作用未识别 | 窗口真实非空且 V9.4 更平衡；缺少无历史对照 |

## 9. 后续验证优先级

下一轮不应继续调整 `0.5`、深度 3、前十或 `4:1` 常数。现有证据优先要求四个单变量对照：

1. 在 V9.4 一步联合生成骨架上比较纯 `q(a)` 与当前折扣 `Q(a)`，确认删除信用是否改变预算和最终质量；
2. 比较纯利用与当前质量区覆盖，保留相同初始化和所有子代资格，识别覆盖的净贡献；
3. 把“退步后额外继续一次或两次”定义成可审计的预算动作，与无承诺的一步重选比较，单独识别 V9.3 的连续发展收益；
4. 增加 `current_only` 与规范轨迹窗口对照，回答历史是否真正改变下一步生成质量。

路线覆盖应单独作为第五项：若要保留多个知识盆地，约束对象必须是初始谱系或行为方向，不能再用前十锚点数量代替。只有这些对照完成后，才有证据决定保留 V9.3 的持续性、V9.4 的覆盖，或重新定义轨迹预算价值。
