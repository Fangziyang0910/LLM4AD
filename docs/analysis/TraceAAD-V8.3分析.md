## 1. 版本定位

V8.3 正式版相对 V8.2 同时引入:完整单父树(永久保留全部评价有效节点)、局部上下文(最近 3 条形成边 + 最多 3 个代表性直接子分支)、五等概率算子(refine/tune/simplify/innovate/crossover)、两次 LLM 调用(Call 1 生成 design_idea + code,Call 2 读取实际代码生成 description)、扩展信用(new_child 质量含已有直接子代回报)与递归选择(虚拟根出发,S_new 与 S_down 竞争,预算 1000 evaluator)。设计意图是从改进树中提取与当前程序匹配的局部来时路,让 LLM 判断当前程序如何形成、已试过哪些方向,再按延续/修复/校准/简化/换向的意图修改。配置为 `n_init=10`、`max_depth=10`、`rho=0.25`、`kappa=0.1`、`beta=1`、exploration constant 0.1。

初始化以获得 10 个评价有效算法为目标,全部直接连接虚拟根;搜索期虚拟根只在既有根中按 `S_down` 选择,不生成新根方案。局部脉络默认提取最近 3 条形成边与最多 3 个代表性直接子分支,上下文不包含 UCT、访问次数、排名等调度数值。

## 2. 实验事实

正式批次 `v83_20260805_final`(实现真相源提交 `04aaef9`)完成 4 任务 × 3 重复 × 1000 evaluator。15 个测试设置为 TSP50/100/200、CVRP50/100/200、OP50/100/200 与 OBP 1k/5k/10k × C=100/500,各方法独立运行 3 次:

- **11 方法同场平均名次 7.667,第 9**(V8 4.067、V8.2 4.133、V4 4.600、V5 5.100);单版本上场平均名次 3.433、第 4,与 V7 并列。
- **TSP、CVRP、OP 上整体弱于 V8/V8.2**,三规模报告均值全部落后;OBP 相对有竞争力(capacity=100 三规模均值 414.9/2025.9/4039.7,接近 V4 但仍未列最佳;capacity=500 弱于 V8;整体效应量 −0.03 是四任务中唯一接近基线的)。
- **未在任一测试设置取得唯一最佳均值**;7 版本两两比较中相对 V4/V5/V8/V8.2 可分辨地更差(P(优于)≈1.00)。
- 15 规模整体效应量 −1.27,四任务全部落后(与 V7 的 −1.13 同属"四任务全落后"类,与 V4/V5/V6/V8/V8.2 的"任务分化"类成因不同);CVRP instance 胜率 ≤3%/0%/0% 全尺度地板,OP 12%/6%/3% 崩塌。
- 问题不是运行失败:四个任务 run 均正常完成 1000 次 evaluator,checkpoint 完整,失败发生在路线利用失衡。

搜索过程证据(根访问计数、sibling 数量)来自过程工件日志,测试结果来自 `eval_best_v83_20260806` 工件;两者分别反映搜索过程与最终泛化,不能相互替代。

| 树结构与完整历史保留 | 支持 | 节点、边、信用全部写入 checkpoint,局部轨迹按设计提取;完整单父树语义被 V9-Core 延续 | B |
| new_child 扩展信用(质量含已有直接子代回报) | 运行有害 | 成功 sibling 抬高 `Q_new`,同一中间节点长期垄断扩展(单个中间节点产生 243/558/629/681 个直接 sibling) | B |

## 4. 结论

1. **确认失败模式:根锁定与 sibling 爆炸。** 三个选择机制——带已获回报的 `new_child` 持续参与价值竞争、`descend` 用子树历史最大值、虚拟根无渐进拓宽——组合使搜索锁死单一根分支(990/990 次级访问)并向中间节点横向爆炸(243–681 个 sibling)。完整树、局部上下文与两次调用按设计执行,损害来自选择层信用,不在生成协议。整体效应量 −1.27、四任务全落后,与 V7 同类且可分辨地差于 V4/V5/V8/V8.2。
2. **否定过信用选择信号。** 一次幸运结果不应永久抬高整条祖先分支;未经验证的代理变量应当删除。同时 V8.3 为联合改动(树、上下文、五算子、两次调用、扩展信用、递归选择同时引入),总体分数不能归因到任一单一机制。
3. **两轮修正尝试均失败。** 平方根宽化(`v83_20260806_pw`)未完成即停止:10/12 run 最高根分支访问占比仍超 90%,`max_depth=10` 边界使选择器绕过宽度条件制造 sibling 绕行,修正后 `trajectory_progress`/`beta`/`rho`/`kappa` 不再参与实际选择、信用与选择无闭环,且调度后端与旧批次不一致不能作机制比较。信用重设计(轨迹先验 + 路线经验信用 + 概率 UCT)实现并通过冒烟,但正式 12 路实验未完成;已完成的三任务未见改善(12 尺度平均 Cohen's d −1.28,与 V8.3 的 −1.27 持平),仅作为机制故障修复记录,不作为正式版本发布。
4. **对下一版本的影响。** V9-Core 不采用趋势项、路线信用和概率控制器——更复杂的信用可改善过程形态,尚未证明提升最终质量,故选择简约调度;保留局部历史上下文的语义,不采用固定深度、V8.3 信用公式和五算子集合。
