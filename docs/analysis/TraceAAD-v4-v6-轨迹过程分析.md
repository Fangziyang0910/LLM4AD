# TraceAAD v4–v6 轨迹过程分析

## 一、研究问题

本报告量化 TraceAAD v4、v5 和历史过程批次 version6 的搜索轨迹，用于支撑 [算子、种群与多样性](../knowledge/研究认识.md)。研究问题是：

1. 三个版本在全局突破、局部精炼、代码变化幅度和突破时机上有何差异？
2. 新颖性与局部空间结构是否能够预测后续突破？
3. 这些过程差异能否解释版本表现，还是只构成需要消融验证的机制线索？

本文的 version6 是历史过程分析批次，不替代当前正式 V6 的结果排名；正式排名以[实验总汇](../experiments/实验总汇.md)为准。

## 二、证据与协议

### 2.1 数据来源与重建

分析脚本为 [experiments/analysis/analyze_traceaad_process.py](../../experiments/analysis/analyze_traceaad_process.py)。数据日期为 2026-08-02，共 36 个已完成 run（4 任务 × 3 版本 × 3 重复）。这 36 个 run 是已删除的[跨方法轨迹过程分析]的 `version4/version5/version6` 子集；run 级指标与图表可由上述脚本从原始实验日志重新生成。

36 个 run 覆盖 `tsp_construct`、`cvrp_aco`、`op_aco`、`online_bin_packing` × `version4/version5/version6` × 3 重复，全部完成 1000 次评估，状态为 `finished`。模型统一为 Qwen3.6-27B（NVFP4），temperature 1.0；同任务内评估配置一致（task_eval 字段相同），因此可作为受控的方法版本比较。

事件流 `method_events.jsonl` 提供 `program_evaluated`、`best_updated`、`child_accepted`、`operator_batch`、`trajectory_selection`、`population_management`；`samples/samples_*.json` 提供程序代码与分数。v5/v6 的节点与样本通过 `code_hash` 逐一映射；v4 使用已验证的 `profiler_sample_order` 对应 `sample_order`，init 节点按成功样本顺序对应。

现有日志支持离线重建轨迹、统计样本级全局 best-so-far 严格突破、计算算子级局部精炼率（LRR）和父子距离（PCD）、代码距离新颖性、窗口级语义几何（空间熵/适应度熵）、窗口级回归，以及版本×任务聚合与绘图。

现有记录不能支持零样本能力对照、温度敏感性实验、论文口径的行为/嵌入语义距离和真正的“代内种群分布”熵。前三项分别需要新的多温度采样、新 run、评估器或嵌入 API；最后一项缺少每迭代 active pool 快照，日志只保留被接受节点。

### 2.2 指标定义与代理假设

对照 [LLM优化器轨迹分析](../references/LLM优化器轨迹分析.md) 中的方法，逐项落地如下：

| 论文分析 | 本分析的落地方式 | 代理/差异 |
| --- | --- | --- |
| 突破率 | 按样本顺序重建全局 best-so-far，仅计分数严格超过历史最优的样本；首个有效样本不算突破 | 论文按代（10 offspring）计；本分析窗口=10 次评估，窗口突破率是“窗口内至少一次严格突破”的比例 |
| 局部精炼率 LRR | 被接受边中 `child.score > parent.score` 的比例 | 只覆盖被接受子代，失败的尝试未完整记录 |
| 父子距离 PCD | 子代与父代代码的 token Jaccard 距离（`1 - code_similarity`） | 代码距离是语义距离的代理，非行为/嵌入距离 |
| 新颖性 | 候选相对全部先前候选的最近代码距离，逐 run min-max 归一化 | 同上 |
| 空间熵/适应度熵 | 10 样本窗口内高斯核熵（均匀权重 / 适应度权重） | 窗口内节点数约 8–10，熵接近上界，区分度有限 |
| 代级混合效应 | 窗口级 OLS + 任务/版本固定效应 + run 聚类稳健标准误 | 论文用 GLMM（模型随机截距）；本分析用 LPM 近似，且“代”是窗口代理 |

所有过程指标均从现有日志事后计算，不改变任何运行。它们属于描述性或探索性分析。

## 三、结果

### 3.1 最终性能与突破统计

版本内任务均值（mean ± std，3 重复）：

| 任务 | version4 best | version5 best | version6 best | v4 BR | v5 BR | v6 BR |
| --- | --- | --- | --- | --- | --- | --- |
| cvrp_aco | -8.665 ± 0.064 | -8.717 ± 0.084 | -8.673 ± 0.096 | 0.183 | **0.200** | 0.197 |
| online_bin_packing | **-725.0 ± 1.7** | -733.3 ± 9.2 | -729.6 ± 7.8 | **0.113** | 0.067 | 0.073 |
| op_aco | 14.882 ± 0.066 | **14.896 ± 0.066** | 14.691 ± 0.204 | 0.147 | **0.153** | 0.113 |
| tsp_construct | **-5.976 ± 0.061** | -6.058 ± 0.059 | -5.980 ± 0.081 | **0.220** | 0.183 | 0.197 |

**观察。** 严格突破样本数（10 样本窗口突破率）分别为：v4 平均 19.3（0.166），v5 18.2（0.151），v6 16.7（0.145）。作为日志审计，`best_updated` 中的等分更短代码事件另行计数：v4 0，v5 12.1/run，v6 5.4/run。这些事件不是适应度突破。

最终分数按任务内归一化（z-score）后，版本均值为 **v4 +0.44σ，v5 -0.33σ，v6 -0.11σ**。在这 36 个 run 中，v4 同时具有最高的严格突破率和最好的平均最终性能。此前 v5 看似“突破更多”，原因是等分简化被计为突破。修正后的方向与论文的跨模型结论一致，但不能据此证明版本差异的原因。

突破平均出现在窗口 31.8、38.9 和 35.7；v4、v5、v6 分别有 82%、64% 和 73% 的突破位于前半程。v5/v6 的改进更多地延伸到后半程，但首次严格突破也更晚，三个版本平均位于窗口 2.9/10.5/9.6。

### 3.2 算子级：LRR / PCD / 结果构成

| 指标 | version4 | version5 | version6 |
| --- | --- | --- | --- |
| LRR（严格优于父代的被接受子代占比） | 0.116 ± 0.032 | **0.136** ± 0.048 | 0.104 ± 0.035 |
| PCD（父子代码距离均值） | 0.086 ± 0.018 | 0.085 ± 0.035 | **0.151** ± 0.044 |
| improve 占比 | 11.6% | 13.6% | 10.3% |
| plateau 占比 | 20.1% | 24.8% | 15.6% |
| regress 占比 | 68.4% | 61.6% | **74.0%** |
| 算子构成 | ideate 49.6% / refine 50.4% | 四算子约各 25% | ideate 42.6% / refine 43.6% / synthesize 6.5% / transfer 7.3% |

**观察。** v6 的 PCD 约为 v4/v5 的 1.8 倍，同时 LRR 最低、regress 占比最高。这一方向与论文关于较大语义修改和精炼可靠性的关系一致。v6 的双轨迹算子（synthesize/transfer）只占约 14%，因此不能把总体步长增大直接归因于双轨迹算子；按现有构成，它主要出现在 v6 的 ideate/refine 行为中。

### 3.3 新颖性与语义几何

| 指标 | version4 | version5 | version6 |
| --- | --- | --- | --- |
| 平均新颖性（归一化代码距离） | 0.081 ± 0.015 | 0.058 ± 0.027 | **0.107** ± 0.040 |
| 初始种群新颖性 | 0.284 ± 0.054 | 0.273 ± 0.054 | 0.278 ± 0.063 |
| 窗口空间熵 H_spatial | 2.229 ± 0.029 | **2.131** ± 0.149 | 2.210 ± 0.042 |
| 窗口适应度熵 H_fitness | 2.228 ± 0.029 | 2.129 ± 0.150 | 2.209 ± 0.042 |

**观察。** v6 的新颖性最高、局部精炼率最低；v5 的 H_spatial 最低，但最终性能仍低于 v4。H_fitness 与 H_spatial 几乎相同。该结果可能表示窗口内高质量候选与全体候选的分布接近，也可能来自窗口熵接近上界造成的低区分度。

对应的 best-so-far 曲线与局部化动态图可由 `analyze_traceaad_process.py` 重新生成（原输出目录 `cross_method_analysis/` 已删除）。

### 3.4 窗口级回归（并发 + 滞后）

因变量：窗口内是否发生突破；自变量：平均新颖性、H_spatial、H_fitness、窗口索引、新颖性×H_spatial 交互、任务与版本固定效应；标准误按 run 聚类（36 聚类）。并发 N=3600，滞后 N=3564。

| 变量 | 并发 coef | 并发 p | 滞后 coef | 滞后 p |
| --- | --- | --- | --- | --- |
| 窗口索引 | **-0.072** | <0.001 | **-0.067** | <0.001 |
| version5（相对 v4） | -0.000 | 0.986 | -0.013 | 0.474 |
| version6（相对 v4） | -0.027 | 0.067 | -0.028 | 0.055 |
| 平均新颖性 | **+0.020** | 0.033 | +0.016 | 0.138 |
| H_spatial | -0.230 | 0.208 | -0.012 | 0.949 |
| H_fitness | +0.246 | 0.179 | +0.007 | 0.972 |
| 新颖性 × H_spatial | +0.007 | 0.222 | +0.001 | 0.858 |

R²：并发 0.071，滞后 0.059。**观察。** 论文的“新颖性×空间熵”负交互在 TraceAAD 窗口口径下未复现；稳定出现的模式是突破集中在早期。新颖性在并发窗口中为弱正相关，滞后后不显著。修正口径后，v5/v6 相对 v4 都没有显著更高的突破概率。代理指标和窗口口径与论文不同，因此这一结果既不能支持该机制在 TraceAAD 中成立，也不能构成反证。

### 3.5 run 级相关（任务内归一化）

36 个 run 按任务内 z-score 后，最终分数与各描述子的相关系数为：突破率 +0.37、LRR +0.31、H_spatial +0.23、平均新颖性 +0.18、PCD +0.09。分任务方向不一致：OBP 中突破率/LRR/PCD/新颖性均与最终性能较强正相关（r 0.62–0.79），OP 中 PCD/新颖性负相关（r ≈ -0.4）。包含任务和版本固定效应的 run 级回归中，突破率系数为 +0.325（p=0.086）。样本量不足，不能由此作因果解释。

## 四、机制解释

### 4.1 由结果直接支持的判断

1. 在这个历史过程批次中，v4 的严格突破率和任务内归一化分数最高。该结果不等价于当前正式跨方法排名。v5 额外的 `best_updated` 主要来自等分简化，而非适应度突破。
2. v6 的步长最大、精炼可靠性最低、regress 最多，最终性能与 v4 持平或更差。现有结果没有显示步长增大带来收益。
3. 三个版本的突破均集中在搜索早期，后半程改进停滞是共同模式。
4. v5/v6 的首次严格突破明显晚于 v4，同时后半程突破占比更高。该模式表示启动较慢且后程仍有少量进展，不能直接解释为更高效的搜索。

### 4.2 待验证假设

**假设 B。** v6 更大的语义步长来自更激进的 ideate/refine，并降低父代精炼可靠性。双轨迹算子占比低，不能解释总体差异。可按算子分组重算 LRR/PCD；edge 表由分析脚本重新生成后即可直接分组。

**假设 C。** 论文提出的“局部化条件下新颖性才有生产力”需要真正的代内种群快照才能检验，当前窗口代理不足。需要在日志中加入 active pool 快照，再重算熵与交互。

## 五、局限与替代解释

- 语义距离是代码 token Jaccard 代理，未使用行为距离或嵌入距离。
- 窗口=10 次评估不等价于论文的“代”；窗口内节点少，熵接近上界。
- LRR 只统计被接受子代，未覆盖全部失败尝试。
- 每个版本只有 3 重复，回归功效有限。版本间比较同时改变多项机制，不能与论文的 15 模型横向比较直接对应。
- v4 的 `llm_calls` 在 cvrp/tsp 的部分 run 明显偏低，可能来自缓存或计数口径差异，因此未用于效率比较。
- version6 的更大 PCD 可能来自提示、状态分布或接受机制的共同变化；当前数据不能只归因于 ideate/refine。

## 六、决定与下一步实验

在新的行为距离和种群快照可用前，不用当前熵交互支持或否定论文机制。后续实验按成本从低到高进行：

1. 用当前的严格突破口径评估 2026-08-02 启动的 V6 局部精炼修订批次，对比突破率、LRR、PCD、回退率与强制精简触发频率；
2. 对 TSP/CVRP 实现论文口径的边集合/行为距离，替换代码距离代理，重跑新颖性与熵；
3. 为后续 run 增加 active pool 快照日志（每迭代的轨迹端点程序与分数），才能做真正的代级语义几何与混合效应；
4. 需要时补零样本基线与温度敏感性实验，补全论文对照。
