# TraceAAD V8.2 分析

> 版本规范:[docs/methods/TraceAAD-v8.2完整机制设计.md](../methods/TraceAAD-v8.2完整机制设计.md)
> 状态:2026-08-07 冻结;历史版本,不定义当前方法。

## 1. 版本定位

V8.2 在 V8 树骨架上调整调度与生成协议,使搜索更快集中到已显示潜力的子树:初始根 30→10、探索系数 0.5→0.1、平方根渐进拓宽→价值驱动的自适应 `new_child` 扩展(按子树结果分配信用)、两阶段 Action→Code→单阶段 Idea+Code、上下文上限 24576。设计意图:高质量 LLM 的主要作用是围绕有证据的程序做局部精炼,预算应更快集中,树应更深。

## 2. 实验事实

批次 `v82_20260804_203128`(协议 `traceaad-v8.2-adaptive-expand`),四任务 × 3 重复 + 完整测试(`eval_best_v82_20260805`)。十一方法同场 15 规模平均名次 4.133 第 3,紧随 V8;95% 区间 [3.533, 5.467];十方法同场与 V8 并列 3.867;单版本上场 2.167 与 V8 并列;P(V8 优于 V8.2)=0.47,两者不可分辨。对 MCTS-AHD 整体效应量 −0.10,胜出 4/15 规模;运行间变异系数 1.164%(高于 V8 的 0.809%)。

任务分化:TSP200 为唯一最佳均值;TSP/OP/OBP-C100 上 V8.2 更好,CVRP/OBP-C500 上 V8 更好;OP 任务平均效应量 −0.19(优于 V8 的 −1.23);CVRP50 instance 胜率 19%(低于 V8 的 53%)。

同期过程(2026-08-04 中期快照,重复数不足):前 10%–40% 预算内 V8.2 在 TSP/OP/CVRP 强 repeat 上 best-so-far 均值更高且更早锁定好解(TSP rep1 在 sample 94、OP rep1 在 sample 82,V8 同预算未达);OBP 前中期持续落后,约 350 sample 才追平;同预算树深明显更深(V8 约 4–6 层,V8.2 约 13–30 层);CVRP 强弱 repeat 分化明显。中期判断为支持跑完正式预算,不记为已证实优于 V8。

**轨迹深度对性能的影响:未单独检验,存在四种解释。** V8/V8.2 对照非单变量,至少差五项(n_init、探索系数、扩展策略、生成协议、checkpoint schema)。"轨迹深度无独立贡献"只是候选解释之一;深度收益也可能被初始起点减少抵消、被生成协议变化抵消,或小于当前结果协议分辨率。区分需固定其余参数、只操纵探索系数与扩展策略的单变量实验(见[版本迭代诊断](TraceAAD-版本迭代诊断与消融基座选择.md) 3.5、6.1)。

## 4. 结论

1. V8.2 确认自适应扩展协议可运行且与 V8 不可分辨(4.133 第 3、P(V8 优于 V8.2)=0.47);任务上呈现分化而非全面超越。
2. 确认的过程信号:深树(中位 34.50)、同期早期更快锁定好解(TSP/OP/CVRP 强 repeat)、OBP 前中期落后、CVRP repeat 分化——描述的是搜索行为,不构成性能结论。
3. 未确认深树对性能的独立贡献:V8/V8.2 对照是五项联合差异,四种解释都成立;这是目前最接近"操纵历史长度"的对照,方向为无差异(可用历史约 3 步增至约 35 步,无可测量变化)。
4. 对后续的影响:V8.2 的骨架与配置被 V9-Core 沿用为搜索基线;消融基座选 V8 系列树骨架(当前代码即 V8.2 形态),轨迹深度配置由 6.1 实验确定;V8.3 沿用 new_child 后出现根锁定与 sibling 爆炸,指向信用机制的弱点,但 V8.3 是联合修改,不能归因于 V8.2。
