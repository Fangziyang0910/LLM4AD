# 研究认识

本文记录 TraceAAD 研究中已经形成的、可以反复使用的判断。它不是实验日志，也不是机制参数表；新的稳定认识应主动融入相应主题，暂未确认的判断标记为 `[待验证]`。

## 核心出发点：算法改进是知识引导的渐进搜索

算法改进是逐步引入算法思想、逐步试错和逐步修正的过程。设计者从一个方案出发，引入一个想法，观察结果，再决定延续、细化、回退、重组或换方向。优秀算法通常不是一次独立生成出来的，它沿着一系列有因果关系的思想修改逐渐形成。**这是 TraceAAD 对自动算法设计 task 的最核心认识，也是后续所有机制的科学起点。**

当前程序只是这一过程的最终截面。它说明算法现在怎样运行，却没有直接说明某个机制为何出现、曾经替换了什么、哪些尝试有效、哪些方向失败，以及哪些思想仍值得发展。算法改进历史保存的正是这些额外知识。LLM 驱动的自动算法设计因此可以被理解为一种知识引导的搜索：搜索决定从哪里继续，历史知识帮助模型决定下一步怎样改。

TraceAAD 的核心对象由此自然成为算法改进轨迹。轨迹保存从起点到当前程序的祖先序列，包括每次引入的算法思想、修改动作和实际结果。它回答的是“当前算法怎样一步步走到这里”，并作为下一步推理最直接、最相关的知识上下文。给定任务、当前程序、祖先轨迹和预算约束构成当前决策状态，边上的修改是 action，生成与评估形成新的搜索转移。

这条“渐进搜索”认识也得到近期轨迹分析工作的直接支持。[Zhang 等人的研究](../../papers/traj_evo_search/README.md)在固定进化协议下分析了 15 个 LLM、8 个任务和 7.2 万余个候选解，发现优秀的 LLM 进化算子更像稳定的局部改进者：它们反复产生相对父代的小幅有效改进，而不是依赖少数大跨度跃迁后长期停滞。父代到子代的局部改进率比平均语义步长更能解释最终性能；较大的语义步长之所以通常不利，主要是因为它降低了改进的可靠性。

这里的“小步”是算法行为层面的受控改动，不等于限制代码行数或禁止引入新思想。它要求下一步尽量保留父代中已经验证有效的结构，针对一个明确弱点或尚未完成的方向进行可归因的修正，再由真实评价决定是否继续。对 TraceAAD 而言，轨迹历史的重要作用之一正是帮助 LLM 看清哪些结构已经有效、上一轮具体改变了什么以及当前问题在哪里，从而把四个语义算子都落到有锚点的连续改进上。`synthesize` 和 `transfer` 仍可重组或迁移跨轨迹知识，但新程序应以主轨迹的优秀局部解为落点，避免把跨轨迹参考误用成无约束的整体重写。`[待验证]` 这种局部改进倾向能否提高父子改善率、连续突破次数和重复实验下限，需要在 V5.3 完成后通过独立提示消融检验。

## 轨迹保存的内容与三类价值

轨迹是一段算法实验史，而不只是一串程序或一条 fitness 曲线。程序节点保存某一阶段可执行的算法状态，修改边保存从父程序到子程序的一次算法决策，整条路径保存这些决策的先后关系及其累积影响。下面定义的是轨迹作为科学信息对象应当承载的内容；v4 是否已经完整、准确地记录并利用了这些信息，需要通过实现和实验过程另行核对。

一条轨迹原则上包含四类相互关联的信息：

- **决策前状态**：任务与评估条件、当前程序、已有祖先历史、所处搜索阶段和可用预算。它说明一次修改是在什么条件下作出的。
- **修改的意图与实际行为**：模型想引入、细化、替换、删除、组合、回退或修复什么算法思想，为什么这样做，最终程序实际改变了什么，以及意图与生成代码是否一致。
- **直接结果**：子程序是否有效，fitness 怎样变化，是否改善父节点、路线历史最好或全局最好，以及运行时间、程序复杂度、跨实例或跨配置表现等可观察结果。成功、失败、停滞、报错和超时都属于真实实验事实。
- **跨步骤关系**：某个思想后来被延续、修复、重组或放弃；不同思想之间形成促进、冲突或约束；一次暂时退步是否为后续突破创造条件；一次立即改善是否限制了后续空间；路线是否出现波动、恢复、反复验证、条件性结论或尚未完成的方向。

其中，修改内容和评估结果是直接观察，思想为何有效、失败原因是什么、早期动作是否造成延迟影响则是根据多个步骤形成的解释。研究记录必须保留这一区别。单次改善只能证明“这次修改在当前条件下取得了这个结果”；重复结果、对照证据和后续发展才能逐步支持更强的机制认识。

这些内容共同解释了为什么成功、失败、停滞和波动都有价值。成功尝试指出可以延续或复用的方向；失败尝试划出已经探索过的边界，帮助后续避免重复踩坑或改换实现；停滞可能说明当前思想已经饱和、修改力度不足或评价信号缺少区分度；波动可能暴露思想之间的冲突，也可能是重构和跨越局部限制的过程。暂时退步可以具有延迟收益，立即改善也可能带来后续锁定。轨迹的形状描述发生了什么，不能单独裁定轨迹有无价值。

轨迹信息在搜索中形成三类彼此相关、不能互相替代的价值：

1. **成果价值**：轨迹当前或历史上是否已经产生优秀算法。它回答“这里有没有值得输出、保留或作为高质量锚点的程序”，主要由真实任务表现衡量。
2. **继续开发价值**：从轨迹当前状态继续投入搜索预算，未来产生优秀后代的可能性有多大。它回答“这条路线是否值得继续扩展”，服务于父代选择和预算分配。它依赖搜索策略、剩余空间和后续多步结果，无法由最近一步涨跌或是否单调上升直接确定。
3. **知识价值**：轨迹中的成功、失败、条件、思想关系和未完成方向，能够在多大程度上改善之后的算法决策。它回答“这段经验能教会搜索什么”，当前通过主轨迹的祖先上下文和双轨迹算子的直接参考发挥作用。一条路线即使不再值得扩展，其中的踩坑记录和条件性认识仍可以具有很高的知识价值。

三类价值共同服务于未来决策，却作用在不同位置。成果价值支持结果输出和高质量锚点保留，继续开发价值支持路线调度，知识价值支持下一步 action 生成与跨轨迹借鉴。同一条轨迹可以成果价值高而继续开发价值低，也可以当前质量较低却知识价值很高；把三者强行压成单一“轨迹总分”会丢失这种结构。

继续开发价值也不是成果价值与全部知识价值的简单加权和。它是在给定当前搜索策略和后续预算时，从该轨迹继续出发能够取得怎样结果的条件期望。当前程序的质量、尚未探索的空间和轨迹历史中可转化为下一步 action 的局部知识都会影响这个期望；能够迁移给其它路线的知识则可能很有价值，却不构成继续保留原路线的理由。因此，知识价值还需要区分“帮助本路线继续行动的局部可用知识”和“应被其它路线复用的可迁移知识”。路线可以停止繁衍，其事实历史仍存在于派生图和日志中；是否以及怎样重新利用，应由明确的参考选择或离线研究决定。

轨迹评分和轨迹选择也属于两个层次。评分提供关于成果、发展潜力、不确定性和经验内容的证据；选择根据具体决策使用这些证据。输出最好程序、分配下一次扩展、决定 active survivor 和保存搜索经验是四个不同决策，不要求共享一个标量排序。一个简洁系统可以让 fitness 决定结果输出，让继续开发代理与 UCB 决定父代扩展，让种群管理维持有限的高质量与探索路线，同时让主轨迹与直接参考承担在线知识利用。这样，淘汰一条低继续开发价值的路线不会删除派生图中的事实记录。

目前程序 fitness 是唯一直接、稳定的反馈，因此它主要测量成果价值。质量与局部趋势只能作为继续开发价值的手工代理，主轨迹与被选中的参考轨迹负责向生成阶段提供尚无直接标签的知识。UCB 为潜力未知的路线保留试验机会，后续真实后代可以用于回看一条路线的多步发展结果。固定统计量能够帮助当前调度，但不能替代轨迹内容本身，也不能充当三类价值的统一真值。

更长期的方向是学习依赖任务、搜索阶段和完整历史的轨迹价值模型。首先可以在相同后续评估预算下，观察从不同轨迹继续搜索所得到的后代结果，用等预算 continuation 或可比较的历史回报学习继续开发价值。知识价值还需要检验某段经验是否真实改善了后续 action 选择，因而比单纯预测后代 fitness 更难。价值模型的标签应来自真实搜索结果和受控比较，不能由 LLM 根据轨迹叙述主观打分；模型也不会自动替研究者定义“什么是有价值”。

## 两种在线搜索视野：局部来时路与直接参考

生成一个新算法时，最重要的参考信息是当前算法自身的来时路。当前程序中的机制正是由这些祖先修改形成的，祖先轨迹与当前决策具有最强的因果连续性和相关性。其他分叉记录了“同一搜索空间的别处发生过什么”，可以扩大视野，却不直接解释当前程序为何成为现在的样子。随着分叉数量增长，把原始旁支直接塞入轨迹还会引入新的选择问题：给哪些分叉、按什么标准选、信息之间是否冲突，以及额外上下文是否值得。

因此，轨迹应保持清晰定义：**一条轨迹是从起始程序到当前程序的严格祖先改进路径。** 这里的“改进”指以改进算法为目标的过程，路径中自然包含成功、停滞和退步。它承担算法形成过程的大部分直接指导作用，不混入不属于当前程序祖先关系的原始分叉。需要使用旁支知识时，搜索明确选择另一条参考轨迹。

当前在线决策写成：

$$
a_t\sim \pi\!\left(x,p_t,\tau_t,\rho_t\right),
$$

其中 $x$ 是任务，$p_t$ 是当前程序，$\tau_t$ 是当前程序的祖先轨迹，$\rho_t$ 是双轨迹算子使用的直接参考轨迹。$\tau_t$ 回答“这个算法怎样走到这里，下一步怎样承接”，$\rho_t$ 回答“另一条具体路线中有什么可以借鉴”。单轨迹算子令 $\rho_t=\varnothing$。

V5.1 和 V5.2 曾每 40 个已评价子程序生成一次所有路线共享的自然语言全局经验。V5.2 四任务过程审计发现，反思文本会把有限批次中的相关现象写成强结论，也出现 fitness 方向理解错误、把局部固定常数称为已确认原则、过早断言某些方向已经饱和等情况。这些文本虽然只进入 Action，却会被后续所有路线重复读取，因而可能把一次不可靠概括扩散成共享搜索偏置。

V5.3 因此先移除在线全局经验，保留主轨迹与直接参考两种可追溯的高分辨率视野。这是一个受控消融，不等于否认跨路线总结具有研究价值。更稳妥的全局认识可以继续由研究者基于完整工件离线形成；若未来重新引入在线机制，必须先解决证据范围、fitness 方向和不确定性表达，而不能让任意反思响应直接成为全体路线的共同前提。`[待验证]` 移除共享文本后能否恢复路线差异、减少错误方向的同步传播并改善重复实验下限。

这里必须区分**结构 ancestry**与**知识 provenance**。新程序的结构父代只有主轨迹上的锚点，因此新节点仍只接回主轨迹；参考轨迹只说明本次决策借鉴了哪里，不因提供知识而自动成为第二父代。由此，单条轨迹仍是严格祖先路径，搜索树仍保存清楚的程序来源，同时允许算法思想跨路线迁移和组合。

一条 active 轨迹直接限制为最多 8 个程序节点，评分、趋势、compact best 和分叉都只使用这段有界来时路。选择内部锚点时，锚点之后已经测试的旧尝试是非祖先决策证据，不应被写成新子程序的来时路。轨迹提示只保存每步 Action、简短实现说明、fitness、结果分类和机械变化，不重复每一步程序代码；当前程序和双轨迹算子的参考程序另行完整提供。

非祖先知识若真实影响下一步，必须先凝结成一个自包含 action。action 重述所采用的原则，系统另外记录本轮提供过的主轨迹、锚点、参考轨迹和参考程序。代码从唯一主锚点实现该 action，同时读取 Action 阶段实际展示的同一段主轨迹；双轨迹算子还读取本轮参考程序与参考历史。共享上下文本身已经表达两阶段关系，不在提示词中额外写入“历史只用于忠实实现”或“不得重新选题”等容易诱导模型的角色约束。

经验记录还必须区分程序运行结果与模型说明。程序代码、fitness、父子拓扑和机械代码差异来自搜索过程；Action 与生成的 Idea 是模型生成的文本，不能因进入轨迹就被当成已经验证的机制解释。

V5.1 四任务三重复提供了双轨迹知识算子的正向过程信号：在各算子评价数接近的条件下，`trace_synthesize` / `trace_transfer` 的父代改善率、路线最好推进率和全局最好更新率均高于 `trace_ideate` / `trace_refine`，11 个由派生边产生的最终最好程序中有 7 个来自双轨迹算子。这个结果说明直接参考能够产生有效修改，并支持继续保留迁移与组合；它仍是整体系内的观察证据，尚不能排除主轨迹质量、参考可用条件和其它机制的交互，独立贡献仍需算子消融确认。

四个算子应从种群进化的底层逻辑理解，但不能被非黑即白地改写成普通交叉或变异。`ideate/refine` 主要沿主轨迹产生不同幅度的定向变化，`synthesize/transfer` 主要让主轨迹与参考轨迹的知识发生重组或迁移；它们类似 EoH 的多个生成算子，都是针对算法设计与轨迹上下文适配后的语义操作。提示词应说明怎样利用轨迹证据，而不是要求模型输出“正在交叉”或“正在变异”。

## Action 是算法决策，不是审计表单

Action 阶段的职责是：在搜索系统已经选定算子、主程序、轨迹上下文和可选参考路线之后，让模型思考下一步算法应当怎样修改。它的最小充分输出是一段自包含的自然语言修改建议，其中自然包含“具体改什么”和“相对相关历史尝试有什么关键差异”；迁移或组合时，还要说明采用了参考路线中的什么原则以及怎样适配到主程序。代码生成阶段随后实现这段建议。

算子、主轨迹、锚点、参考轨迹和参考程序都是搜索系统已经掌握的事实，应由系统自动写入 provenance。要求模型再次填写 relation、evidence id，或者把修改意图拆成多个 JSON 字段，不会增加真实搜索知识，反而把“想出有价值的下一步”与“遵守审计格式”绑定在一起。系统 provenance 只能证明模型看到了什么上下文，action 只能记录模型提出了什么方案；模型为何采用某项知识仍属于待审计的解释，不能由一个自报字段变成事实。

V5 首轮运行提供了直接教训：action 请求本身几乎没有服务异常，但五字段 JSON 契约仍使约四成批次提取不到任何可执行 action，只有约三成批次获得预期的两条 action。格式服从度因此直接决定了一条被选轨迹是否得到候选和评估机会，把接口负担错误地注入了有效搜索空间与访问语义。对于开放式算法思考，高频 Action 应优先使用最小自然语言契约。V5.1 四任务 12 个正式运行中，约每次 Action 调用都稳定形成两次代码生成，平均 LLM 调用由 V5 的约 2.0--2.2 次/评价降至约 1.51 次/评价；自然语言契约已经恢复候选供给，这一接口收益可以确认。

Action 事故还揭示了一个更一般的接口原则：大模型可见的输出契约必须与程序真正执行的 parser/validator 契约一致。格式越简单并不自动意味着接口正确；如果 parser 把任意非空行当成 action、固定取第一个代码围栏，或者 validator 使用 prompt 未展示的字符上限和代码哈希条件，系统仍会发生静默误解析或不可解释拒绝。端到端测试要覆盖真实模型常见的前言、续行、多候选代码和冗长结构化输出，不能只用理想手写响应证明调用链可达。

V5.1 首批运行进一步表明，这项一致性必须覆盖代码的完整执行环境与任务真实类型。模型按 prompt 只返回使用 `np` 的目标函数时，parser 判定成功却未补回模板 import，造成的失败属于系统接口损耗；模型为整数容量数组生成浮点 tie-breaker 时，如果 prompt 没有说明真实 dtype，同一种 NumPy 原地转换错误会被反复放大。正确边界是由系统保留模板执行前言、接受合法的小型辅助函数，并把真实输入 dtype、输出 shape 与 finite 要求明确为任务契约；模型自行选择的算法复杂度仍交给原 evaluator 和 timeout 检验，不把过程诊断扩张成新的搜索控制器。评价日志同时需要保留准备、执行、运行时、无效返回和 timeout 的简短分类，否则失败无法成为可解释的过程证据。

轨迹中的 Action 和 `Idea` 都只是模型声明。为了让历史真正指导下一步，压缩历史不能只保存“计划改什么”而丢失“代码实际改成什么”；也不能把长篇推理直接继承为已经实现的算法事实。第一版仍无需增加 LLM judge，但应让 Action 受目标函数可见输入约束，让 `Idea` 保持为短实现声明，并用代码哈希、机械差异和必要的确定性摘要维持声明与事实的边界。V5.1 相对 V5 在 TSP、CVRP 和 OP 上明显降低完全重复程序，并提高全图与 active endpoint 的唯一代码比例；OBP 的改善很小且仍有一次运行长期停留在重复平台，说明接口修正能够减少上下文污染，但低区分度任务上的重复搜索不能只靠接口解决。

两阶段生成既需要自然语言 Action 记录修改意图，也需要上下文连续。当前 V5.3 让 Action 与 Code 共享同一段最多 8 节点轨迹的历史文本；双轨迹 Code 同时读取参考程序和参考历史。历史文本不重复逐步代码，因此主要上下文成本来自当前程序和参考程序本身。此前 TSP 最大 Action 输入达到 24573 tokens，实际组成中主/参考程序约占 12.6K 字符、两条历史约 7.6K、全局经验约 2.4K；OP 的极端输入中单个当前程序已达约 17.4K 字符。完整信息进入 Code 的作用是减少 Action 到实现的信息损失，现有证据不能把生成相同代码简单归因于上下文相同。当前默认不设置本地 prompt 上限，只在显式声明模型真实硬边界时预检。

父代选择分成两个连续决策：先从 active frontier 选择一条最长 8 节点的轨迹，再只在这条轨迹内从 endpoint 与 compact best 中选择锚点程序。锚点的完整代码是 Action 与 Code 的主程序，生成子节点也只写回该锚点；compact best 后已经测试的节点只作为历史结果展示，不会被误写成锚点已实现的机制。轨迹评分、趋势、compact best 和上下文都只读取当前保留轨迹，不沿程序树回溯到已被轨迹截去的根节点。

## 整体机制表现优先，消融用于解释贡献

TraceAAD 的首要研究目标是构建一个以轨迹为核心、整体达到领先性能的搜索机制。轨迹、评分、选择、算子、上下文和种群管理共同组成方法；当这个完整机制在严格、公平的实验协议下达到 SOTA，首先支持的是这套基于轨迹的知识引导搜索作为整体有效。组件消融的职责是随后解释哪些部分贡献最大、适用边界在哪里，以及下一版应怎样改进，不是整体方法成立之前必须跨越的前置门槛。

过程审计仍然重要，因为它帮助理解方法为什么有效、哪些部分正在浪费预算。评价一步修改时应区分三种结果：相对当前父节点的局部改善、相对路线历史最好的路线进展、相对全局最好的前沿推进。v4 中从退步 endpoint 出发的正向边大多只是部分回弹，这说明三种结果经常不一致，但不能据此认定局部回弹没有价值。父代价值也不能只看直接改进率：强路线更难改善，但成功后更可能推进全局前沿。

种群管理同样需要过程证据。池子按预期收缩只能说明数量受控；要理解质量精英、差异 reserve 和 softmax survivor 为什么有效，需要记录具体路线的保留/归档决定及其后续贡献。这里的目的不是把方法拆散后才允许评价整体，而是让 SOTA 机制拥有可信、可解释、可继续改进的科学叙事。

## 种群是路线资源，树是状态拓扑

把轨迹作为种群个体的理由是：搜索真正要分配的是“哪条改进路线继续发展”，而不是孤立地重复选择某个程序。单父代生成时，新程序只接在一个锚点程序之后，因此程序来源关系天然是树；多个初始程序形成森林，也可以视为共享虚拟根的树。轨迹是树上的一条有界状态历史，树结构保存父子关系，种群只保存当前可继续扩展的 frontier。

树结构并不意味着要把完整 MCTS 搬进来。UCB 的访问项只回答“哪条路线还没有被充分尝试”，适合用于父代扩展调度；种群生存管理回答“哪些路线继续占据有限席位”，适合用质量精英、路线差异 reserve 和 softmax 抽样完成。两者兼容但职责不同，不能把访问公平误写成质量，也不能让 UCB 直接决定生存。

父代调度可写成价值加访问公平的形式：

$$
A(\tau_i)=V_{search}(\tau_i)+c\sqrt{\frac{\log(1+N)}{1+n_i}},
$$

其中 $n_i$ 是该路线被选作父代的次数。$V_{search}$ 是对继续开发价值的轻量调度代理，只使用当前质量与路线走势，不能代表轨迹完整价值；UCB 项让长期未被尝试的路线仍有非零机会，随后对 $A$ 做 softmax。这个结构借鉴了 MCTS 的访问公平，也保留了种群方法的并行路线视角。

## 延迟管理与多样性

种群规模 $M$ 表示一个管理周期结束后保留的路线数。新轨迹进入扩张池后立即可被选作父代，但不在每次生成后淘汰；当池子达到 $2M$ 时才统一管理，再回到 $M$。这给新路线有限的试错窗口，避免一次没有立即提升的生成就抹掉其后续推理机会。它提供的是概率机会，不承诺每条路线都必然繁衍一次。

精英主义本身会提高利用效率，却会快速压缩算法思想的覆盖。v4 用最小的三段式管理保持平衡：保留少量质量精英，保留相对于精英集合仍有差异的路线代表，其余席位按搜索价值 softmax 抽样。路线差异只承担生存 reserve，不参与继续开发价值排序，也不设置硬 novelty 门槛。当前的代码、思想词项和行为指纹只是轻量代理，不能被表述为真正的语义相似度；只有消融显示同质化严重，才考虑 AST 或 embedding 等更复杂机制。

多样性的价值取决于它出现在哪里。上述轨迹分析发现，平均 novelty 本身不能预测最终性能；只有当种群已经集中在高质量语义区域时，局部的新变化才更容易转化为突破。搜索分散时继续扩大差异，往往只是语义漂移，不能形成可累积的改进。因而 TraceAAD 需要的是**优秀局部解附近的有效多样性**：质量与轨迹证据先确定值得发展的区域，差异机制再防止该区域内部过早收缩。差异 reserve 不应成为奖励全局远跳或长期保护低质量路线的独立目标；潜力未知路线的有限试验机会由 UCB 和延迟管理承担。`[待验证]` 后续应同时观察父子局部改进率、语义或功能步长、突破频率和种群分散程度，判断现有 reserve 是否确实把多样性配置在高质量局部区域。

全局最好程序独立于普通生存抽样，至少保留一条包含它的 active 路线作为 best-anchor。这样“当前输出的最好程序”和“下一步还能从最好程序继续推理”不会因为一次种群收缩而断开。

## 有效搜索空间取决于可执行状态覆盖

名义上的轨迹数量、算子数量和上下文来源数量都不等于有效搜索空间。对固定评估预算而言，真正重要的是搜索产生了多少有差异的可执行候选、active frontier 保留了多少不同的当前程序，以及一次评价是否带来了新的结果信息。轨迹身份可以衡量来时路，不能直接代替当前可执行状态的身份。

父子 fitness 在数值容差内不变的边记为 plateau。它是局部评价结果的分类，衡量一次修改是否改变了当前训练评价面，不衡量程序的绝对质量，也不能单独判定这一步是否有长期价值。Plateau 可能来自完全重复代码、行为等价实现、评估器分辨率不足或有意义的中性过渡。因而 plateau 比例应与规范化代码唯一率、父子完全重复率、active 唯一 endpoint、路线最好推进、全局最好推进和后续子代贡献共同解释。大量 plateau 只有在同时伴随重复代码、active 状态收缩和后期突破减少时，才构成有效探索不足的强信号。

同一当前程序可以由不同历史到达，这些历史可能具有不同知识价值；但知识差异不自动产生可执行状态差异。重复状态是否浪费搜索资源可以继续作为离线过程现象观察，不在 V5.3 中转化为在线候选拒绝规则。代码哈希和唯一率用于诊断，不决定候选能否评价、写入轨迹或获得 active 身份。

V5 首轮过程证据表明，增加参考轨迹并没有自动扩大有效视野。V5.1 修正 Action、全局反思和执行契约后，TSP/CVRP/OP 的全图唯一代码率由约 80%--88% 提高到约 93%--97%，最终 active endpoint 唯一率由约 61%--77% 提高到约 86%--99%，plateau 比例同步下降，并在这三个任务保留了更多后半程最好更新。OBP 只从约 70%/67% 提高到约 73%/69%，一次运行的 active endpoint 唯一率仍只有约 41%，且最终最好停在初始化。由此可以确认接口损耗曾显著压缩有效视野，也可以确认有效状态覆盖的改善具有任务依赖性；低区分度评价面上的同质化仍是未解决问题。

V5 首轮的有效搜索空间收缩应暂时记录为一个机制交互假设，而不是归因给单一组件：双轨迹算子改变候选的产生与跨路线传播，主轨迹和参考轨迹的质量偏向选择改变预算投向，trajectory-level 的 UCB、种群生存和重复状态保留则把局部重复放大成持续反馈。任一层单独存在都不足以解释当前收缩强度；三者共同作用时，相同或等价程序可以获得多个独立搜索身份，反复取得选择、探索和生存机会。`[待验证]` 后续应在机制问题汇总后统一设计修复顺序和受控消融，分别识别算子主效应、评分选择主效应及二者与 frontier 资源规则的交互效应；当前不据此提前删除双轨迹算子、恢复旧趋势分数或增加新的复杂控制器。

## 相关工作带来的边界

EoH 的质量排序、ReEvo 的随机父代与精英变异、ShinkaEvolve 的 offspring-count 修正、MEoH 的差异性选择和 MCTS-AHD 的访问次数，都说明质量、探索覆盖和访问公平可以由不同机制承担。它们没有提供把算法改进轨迹作为搜索个体与推理上下文的现成答案，因此 TraceAAD 的整体表现构成主要方法证据，过程指标和消融进一步解释各支撑机制的贡献与边界。

这些工作也提示一个反直觉事实：复杂的种群机制不必然带来更好的搜索。只要职责边界清晰，固定规模、延迟管理、轻量差异 reserve、global-best 保留和 UCB 调度已经足以表达当前科学主张。V5 只增加具有明确知识职责的跨轨迹迁移与组合，不同时引入独立 archive 检索、自适应算子调度或语义 novelty 判断。

## LLM 作为进化算子的底层认识

LLM 在自动算法设计中的主要能力不是一般数值优化，而是利用预训练得到的程序、算法和人类修改先验，对已有方案进行有语义的变化。[Evolution Through Large Models](https://arxiv.org/abs/2206.08896)把这种能力理解为从人类程序修改分布中学到的智能变异；[Evolving Code with a Large Language Model](https://arxiv.org/abs/2401.07102)进一步指出，传统遗传编程显式定义结构操作，而 LLM 将具体变化行为隐含在模型、提示词和上下文中。因而提示词、父代表示、历史内容和反馈形式都不是外围接口，它们共同定义了实际进化算子。LLM 的预训练先验使修改具有语义，也会偏置哪些变化更容易生成、哪些搜索区域更容易到达。

这类算子的质量首先表现为**可靠改进能力**：给定父代、历史和真实反馈后，能否持续生成比父代更好的后代。已有轨迹分析表明，频繁的小幅有效改进比少数大跨度跃迁更能解释最终表现；这里的小步指围绕已验证结构进行有锚点、可归因的算法修改，而不是机械限制代码变化量。[Behaviour Space Analysis of LLM-driven Meta-heuristic Discovery](https://arxiv.org/abs/2507.03605)也发现，提示词会显著改变探索、利用、收敛和停滞行为，代码简化与有限扰动可以形成很强的搜索策略。这进一步支持把提示词设计为实际算子参数，并同时观察父子改善率、停滞和运行行为，不能只看代码文本是否新颖。

LLM 产生的算法空间不是均匀平滑的。[Fitness Landscape of Large Language Model-Assisted Automated Algorithm Search](https://arxiv.org/abs/2504.19636)显示，不同算法设计任务会形成不同程度的多峰、崎岖和高质量聚集结构。因此，同一套轨迹深度、种群广度和选择压力不必在所有 task 上产生相同行为。多样性的价值也应结合父代质量、搜索地形和当前不确定性理解：优质局部区域内的变化更容易承接已有成果，未知路线仍需要有限探索机会，但全局远跳或单纯扩大种群分散度本身不构成进展。

轨迹搜索同时是一个有限预算分配问题。[Compute Allocation in Evolutionary Search: From Depth-Breadth to Multi-Armed Bandits](https://arxiv.org/abs/2605.29268)表明，在固定 LLM 调用预算下，过早押注一条弱路线和只扩展广度而不持续细化都可能浪费预算；深度与广度的有效比例具有任务和模型依赖性。[Code Repair with LLMs Gives an Exploration-Exploitation Tradeoff](https://arxiv.org/abs/2405.17503)则把迭代修改形成的候选树写成探索—利用和 bandit 问题。对 TraceAAD 而言，父代调度的核心不是寻找一个静态最优分数，而是根据当前质量、改进历史、访问不确定性和剩余预算，决定哪些路线继续深挖、哪些路线尝试修复、哪些路线用于跨轨迹借鉴。

LLM 的跨轨迹重组也不等同于字符串或代码片段拼接。[Language Model Crossover: Variation through Few-Shot Prompting](https://arxiv.org/abs/2302.12170)表明，多个父代可以通过上下文示例触发语义层面的关系归纳和后代生成。由此，TraceAAD 的 `synthesize` 和 `transfer` 可以从交叉与变异的底层逻辑理解，却仍应保留面向算法历史的适配形式：主轨迹提供当前算法的结构锚点，参考轨迹提供可迁移或可组合的思想，生成结果需要把参考原则适配到主程序，而不是机械合并代码或无约束重写。

历史的价值来自可追溯的“修改—结果”关系。[DeltaEvolve](https://arxiv.org/abs/2602.02919)提出用语义增量记录改了什么、为什么改以及产生了什么结果，说明完整代码快照之外的变化历史可以帮助后续搜索聚焦关键思想。这与 TraceAAD 保存算法来时路的主张直接呼应，但模型生成的修改说明仍只是声明，不能自动成为因果事实。代码、父子关系和 evaluator 结果是直接证据；修改动机、失败原因和可迁移规律需要经过机械差异、后续结果或受控实验验证。

模型自我反思尤其需要这样的证据边界。[When Can LLMs Actually Correct Their Own Mistakes?](https://aclanthology.org/2024.tacl-1.78/)的综述指出，可靠修正通常依赖可验证的外部反馈或专门训练，单靠提示触发的内在自我判断缺少稳定证据。这支持当前先移除自由文本全局经验的消融：fitness、错误、超时和后代结果可以指导修正，LLM 对这些现象的总结只能作为待检验假设，不能被强制写成所有路线共享的事实。

综合这些研究，当前形成以下可复用判断：

1. LLM 是带有程序与算法先验的语义变化算子，其行为由模型、提示词、父代、历史和反馈共同决定。
2. 算子首先应提高从父代到子代的可靠改善率，再讨论偶发的大跨度创新；局部连续性和探索能力需要共同测量。
3. 搜索地形具有任务依赖性，轨迹深度、种群广度、选择压力和多样性位置不能仅凭单个 task 固定成普遍规律。
4. 跨轨迹算子的本质是算法思想的语义重组与适配，参考轨迹是知识来源，不自动成为第二个结构父代。
5. 轨迹选择也是计算预算分配，应利用路线质量、历史进展和不确定性，避免过早承诺与无效铺开。
6. 轨迹应保留可验证的 action–result 对应；模型总结可以帮助压缩信息，但必须与程序事实和外部评价分开。
7. 多样性更可能在有质量基础或有明确探索理由时转化为进展，平均 novelty 和大范围漂移本身没有独立价值。

以上是外部研究对 TraceAAD 科学主张的支持与约束，不是对当前具体机制的直接证明。`[待验证]` 后续应在 V5.3 消融完成后，分别检验局部改进提示、跨轨迹语义适配、不同父代质量区域中的多样性收益，以及基于轨迹历史的预算分配；不把这些方向一次性叠加进同一版本。

## 自定义 task 协议的有效性不等于逐项复现论文

论文和原始代码为 task 设计提供经过验证的参照，但只有在研究问题明确是复现时，逐项参数一致才是首要判据。用于比较自动算法设计方法的自定义协议，首先需要在实验前固定训练域、保持训练集与测试集独立，并让所有方法共享同一数据、评价器、模型条件和结果选择规则。结论只能在这个预先声明的协议内成立，不能直接与采用另一协议的论文绝对数值比较。

公平性、难度和论文一致性是三个独立维度。当前正式比较采用各方法的原生搜索预算：PathWise 500，MCTS-AHD 1000，TraceAAD 1000；它回答的是各方法按自身设计运行时的整体表现，预算数值不同不构成协议缺陷，也不要求统一预算后重跑。共同预算截面可以作为额外的样本效率分析，但不是当前比较成立的前提。task 是否过度降难则应由实证判断：比较简单基线、较弱基线、可获得的精确最优或强参考解，观察搜索提升空间、方法间区分度、重复稳定性和跨规模泛化。参数偏离论文本身既不能证明 task 无效，也不能证明 task 有足够挑战。

## task 难度需要区分问题难度与可改进幅度

组合优化问题本身困难，不等于当前 AAD 接口仍为 heuristic 留有很大改进空间。当前主矩阵保留 TSP Construct、CVRP-ACO、OP-ACO 和多容量 Online Bin Packing，它们都仍有足够的构造、搜索或跨配置鲁棒性压力。Knapsack Construct 与 TSP-GLS 属于低改进幅度 task：前者的 ratio 基线距精确最优仅约 1.17%，后者强 GLS 后端把模板到最好方法的训练改善压缩到约 0.35%。二者既有实验结果与记录已从结果页和实验目录删除，后续也不再进入比较矩阵；主要预算集中到提升空间更充足的四个 task。

## 训练内最优与跨配置泛化必须分开

搜索只会优化评估器实际暴露的分布。一个候选程序可以在固定训练配置上获得稳定高分，同时依赖只在该尺度成立的评分项平衡；配置变化后，这种平衡可能完全反转。旧单容量协议下的一次 TraceAAD OBP 运行曾提供直接证据：候选 heuristic 用剩余容量构造 `age_bonus`，实际持续奖励更空的新箱。在训练容量 100 上，其他 penalty 和 look-ahead 项还能抵消该偏好；容量扩大到 500 后，这些项几乎失效，heuristic 遂退化为每件物品开启一个新箱。关闭 `age_bonus` 后，同一固定实例的箱数从 1000 恢复到 82。该案的实验工件已删除，但跨配置泛化失败的机制判断仍保留。

因此，训练 best、重复运行稳定性和跨配置泛化回答不同问题。训练分数只能证明程序适应了训练评估面；规模、容量或分布外推必须作为独立实验事实报告。训练域必须在实验前按目标 benchmark 固定，不能因为观察到某次外推失败而事后把失败配置加入训练：这会改变研究问题，而不是修复原实验。

OBP 文献中存在两套常用但不同的协议。EoH/HSEvo 在五个 5k、容量 100 的固定实例上设计 heuristic，再把不同规模和容量（包括容量 500）作为泛化测试；MCTS-AHD/CALM/PathWise 则预先把 1k/5k 与容量 100/500 的四个配置纳入训练域，只把 10k 视为尺度外推。因此，“容量 500 是否应在训练中”没有脱离 benchmark 的统一答案。旧单容量 TraceAAD OBP 的跨容量失败只作为已记录的机制认识保留；自 2026-07-24 起，当前仓库正式采用后一类多容量协议，后续对所有比较方法使用相同的四配置训练集重新搜索，只把 10k 测试记为 OOD。OBP 上不再保留或重跑 TraceAAD v2–v4 旧协议实验。

## 程序复杂度不是算法质量的代理

完整历史能帮助 LLM 理解算法怎样形成，但“保留历史”不等于“把历史中的每个机制永久保留在代码里”。只按任务分数选择、反复继承完整父程序，同时持续要求增加或深化思想，会让无收益逻辑在后代程序中持续积累。轨迹长度上限只约束保留的路线状态，不约束当前程序本身，因此不能充当复杂度控制。

TraceAAD v4 的五个任务都已观察到候选程序随搜索明显增长；直接父子比较中，变长子代的改进率均未超过变短子代。这个结果说明代码长度既不是质量信号，也不能自动解释为思想积累。合理目标不是追求最短程序，而是让新增复杂度与可验证收益相匹配，并让修改操作同时具备引入、替换、删除和压缩机制的能力。

轨迹搜索为这个问题提供了普通程序种群没有的条件：知识可以留在历史里，代码不必承担永久记忆。一次有价值但后来被替换的思想、一次无收益增加和一次简化失败，都可以继续保存在修改边及其结果中；从当前实现删除相关代码不会抹去这些经验。由此应把轨迹理解为知识载体，把当前程序理解为可执行载体。保留来时路与保留全部旧逻辑是两个不同目标。

面向 v5，采用的最小原则是“质量优先，完全同分择简”。程序只记录非空 LOC；轨迹在完全达到路线最好质量的节点中保留最短的紧凑锚点，所有质量排序也只在 fitness 完全相同时以更短程序打破平局。不同质量的候选仍只按任务表现排序，普通退步或变长候选仍可进入轨迹。V5.1 四任务中，global-best 因完全同分但更短而更新的次数与严格 fitness 更新处于同一量级，说明该规则虽然不惩罚任何严格更优程序，却经常改变后续锚点和质量分位，不能再视为几乎无作用的记录项。

固定长度惩罚会把不同 task 的分数尺度、合理复杂度和算法质量混在一起；硬 token 上限只能防止失控，不能判断增长是否值得；代码 novelty 也不等于简洁。V5.1 四任务中位有效代码长度均显著低于 V4，同时 OP 的 held-out 质量提高，但 TSP/CVRP 的重复稳定性和最大规模表现没有同步改善。因此现有结果只支持“整套 V5.1 机制缓解了 V4 的无节制膨胀”，不能把收益归因给 `refine` 明列 replace/delete/merge/simplify 或完全同分择简。当前 refine 已收回为围绕一个已验证机制或已暴露弱点的聚焦修正，不在提示中罗列增加、替换、删除或合并等操作；完全同分择简继续保留为独立选择规则。

## 泛化与鲁棒性来自搜索分布，而不是结果口号

跨规模泛化首先受训练信号边界约束。TSP、CVRP 和 OP 的搜索 fitness 只来自预先定义的训练分布，最终 100/200 规模不参与选择，因此历史再完整也只记录训练评价面上的成功和失败。若希望搜索到底层算法思想，Action 阶段可以用一句轻量归纳偏置要求修改由任务结构和尺度不变量支持，优先使用归一化或无量纲关系，避免依赖训练规模的固定常数；是否真实改善 OOD 仍必须由预声明 held-out 结果验证，不能以 Action 自述代替。

随机搜索的鲁棒性也并非不可控制。无法保证每次运行得到相同程序，但可以通过多训练实例或 seed 的评价分布、下分位表现、父代访问公平、路线差异 reserve 和停滞后的预算重分配压缩坏 run 的尾部风险。V5.1 的父代 softmax 没有整体坍缩：约 44 条 active 路线对应约 25 条有效候选；但被选路线平均质量分位达到约 0.68--0.74，最低质量四分位几乎不被选，而这些路线一旦被选往往具有更高的局部修复率。高质量路线则更容易推进 global best。由此应把“守住高质量前沿”和“为可修复路线保留发展预算”视为两个信号，而不是让同一个 Q 同时代理成果价值与继续开发价值。

V4 使用 $0.6Q+0.4P$，首轮 V5.1 只用 $Q$，两者再加相同 UCB。四任务过程数据中，高趋势路线更常推进全局最好，而 Q-only 在 TSP/CVRP 的重复稳定性弱于 V4；当前版本因此采用更保守的 $0.8Q+0.2P+\mathrm{UCB}$。这仍是待新实验验证的继续开发代理：局部趋势会奖励从差 endpoint 的部分回弹，必须同时检查路线最好推进、global-best 推进、三重复下限和 held-out 泛化；若只增加局部改善而不推进前沿，就应重新降低或定义趋势信用。

## 研究路线与待验证假设

第一阶段构建并验证整体达到领先性能的轨迹搜索机制，同时完整记录状态、action、结果和后代关系。第二阶段从树上的多步 action-result 序列构造不同时间尺度的 continuation return，研究哪些轨迹信息能够预测后续搜索收益。第三阶段再用等预算 continuation 数据训练轨迹价值模型，并把它用于上下文选择、路线调度或可迁移的算法设计策略。搜索策略决定观察到哪些状态和 action，信号设计决定这些记录能否支持信用分析，两者需要协同迭代。

当前主要假设均为 `[待验证]`：成果价值、继续开发价值和知识价值分工比单一综合分数更符合轨迹搜索；单父代树能在保留失败边界的同时维持路线多样性；UCB 父代调度能为未知潜力保留试验机会；退步、停滞和波动轨迹可以为后续决策提供可利用的信息；基于多步后代结果学习的价值模型能够比手工局部趋势更好地分配搜索预算。
