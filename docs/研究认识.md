# 研究认识

本文记录 TraceAAD 研究中已经形成的、可以反复使用的判断。它不是实验日志，也不是机制参数表；新的稳定认识应主动融入相应主题，暂未确认的判断标记为 `[待验证]`。

## 研究定位：让算法改进历史参与下一步决策

LLM 驱动的自动算法设计把代码生成能力交给模型，把有限评估预算的分配交给搜索。算法改进本身是连续过程：设计者从一个方案出发，引入一个思想，观察结果，再决定延续、修复、回退或换路。只看当前代码会丢失“为什么走到这里”和“哪些方向已经试过”的信息。

TraceAAD 的核心对象因此是算法改进轨迹。轨迹保存从根程序到当前程序的有序修改、每步结果和失败边界，并作为下一步 LLM 推理的知识上下文。轨迹不是一个静态标签，也不是把若干程序简单拼接；它是一个 MDP 状态的历史部分。给定任务、当前程序、来时路和预算约束构成状态，边上的一次算法修改构成 action，生成和评估形成 transition。

## 三种价值必须分开

“对搜索有价值”和“对 LLM 推理有价值”不是同一件事。终点分数高的路线适合继续利用，但一条暂时退步的路线仍可能记录了重要失败边界；一条分数一般但提出了不同思想的路线，可能为后续推理提供新的组合方式。质量、潜力和信息量回答不同问题，不能在没有验证的情况下压成一个标量，再声称这个标量代表轨迹的全部价值。

TraceAAD v4 因此保持三个职责的分离：终点质量与轨迹内历史最好节点组成搜索质量信号；近期提升、停滞和退步只描述路线走势；完整来时路直接提供推理信息。退步和失败不会自动等价于“没有信息”，也不会因为曾经达到高分就永久获得繁衍资格。它们是否有助于下一步生成，交由轨迹上下文和后续结果检验。

## 种群是路线资源，树是状态拓扑

把轨迹作为种群个体的理由是：搜索真正要分配的是“哪条改进路线继续发展”，而不是孤立地重复选择某个程序。单父代生成时，新程序只接在一个锚点程序之后，因此程序来源关系天然是树；多个初始程序形成森林，也可以视为共享虚拟根的树。轨迹是树上的一条有界状态历史，树结构保存父子关系，种群只保存当前可继续扩展的 frontier。

树结构并不意味着要把完整 MCTS 搬进来。UCB 的访问项只回答“哪条路线还没有被充分尝试”，适合用于父代扩展调度；种群生存管理回答“哪些路线继续占据有限席位”，适合用质量精英、路线差异 reserve 和 softmax 抽样完成。两者兼容但职责不同，不能把访问公平误写成质量，也不能让 UCB 直接决定生存。

父代调度可写成价值加访问公平的形式：

$$
A(\tau_i)=V_{search}(\tau_i)+c\sqrt{\frac{\log(1+N)}{1+n_i}},
$$

其中 $n_i$ 是该路线被选作父代的次数。$V_{search}$ 只承担搜索质量与路线走势，UCB 项让长期未被尝试的路线仍有非零机会；随后对 $A$ 做 softmax。这个结构借鉴了 MCTS 的访问公平，也保留了种群方法的并行路线视角。

## 延迟管理与多样性

种群规模 $M$ 表示一个管理周期结束后保留的路线数。新轨迹进入扩张池后立即可被选作父代，但不在每次生成后淘汰；当池子达到 $2M$ 时才统一管理，再回到 $M$。这给新路线有限的试错窗口，避免一次没有立即提升的生成就抹掉其后续推理机会。它提供的是概率机会，不承诺每条路线都必然繁衍一次。

精英主义本身会提高利用效率，却会快速压缩算法思想的覆盖。v4 用最小的三段式管理保持平衡：保留少量质量精英，保留相对于精英集合仍有差异的路线代表，其余席位按搜索价值 softmax 抽样。路线差异只承担生存 reserve，不参与主价值排序，也不设置硬 novelty 门槛。当前的代码、思想词项和行为指纹只是轻量代理，不能被表述为真正的语义相似度；只有消融显示同质化严重，才考虑 AST 或 embedding 等更复杂机制。

全局最好程序独立于普通生存抽样，至少保留一条包含它的 active 路线作为 best-anchor。这样“当前输出的最好程序”和“下一步还能从最好程序继续推理”不会因为一次种群收缩而断开。

## 相关工作带来的边界

EoH 的质量排序、ReEvo 的随机父代与精英变异、ShinkaEvolve 的 offspring-count 修正、MEoH 的差异性选择和 MCTS-AHD 的访问次数，都说明质量、探索覆盖和访问公平可以由不同机制承担。它们没有提供把完整算法改进历史作为单个 MDP 状态的现成答案，因此 TraceAAD 的主要假设仍需通过过程指标和消融验证。

这些工作也提示一个反直觉事实：复杂的种群机制不必然带来更好的搜索。只要职责边界清晰，固定规模、延迟管理、轻量差异 reserve、global-best 保留和 UCB 调度已经足以表达当前科学主张；额外的 archive 检索、跨轨迹组合和语义 novelty 判断会扩大机制表面积，暂不引入。

## 研究路线与待验证假设

第一阶段验证完整轨迹上下文是否改善下一步算法生成；第二阶段从树上的多步 action-result 序列构造即时与长期信用；第三阶段再训练能够迁移算法设计策略的模型。搜索策略决定观察到哪些状态和 action，信号设计决定这些记录能否支持信用分析，两者需要协同迭代。

当前主要假设均为 `[待验证]`：完整来时路比孤立当前程序提供更有效的下一步依据；质量、走势和访问公平分工比单一综合分数更稳健；单父代树能在保留失败边界的同时维持路线多样性；UCB 父代调度能减少高质量路线的预算垄断；退步和停滞历史在 LLM 推理中提供可利用的信息。
