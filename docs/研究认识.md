# 研究认识

本文记录研究过程中逐步形成的研究定位、问题认识与科学假设，并随着理论分析和实验结果持续修正。

## 研究定位：面向通用智能优化

研究主线是通用智能优化，涵盖优化问题建模、自动算法选择、自动参数设置和自动算法设计。当前工作聚焦大模型驱动的自动算法设计（LLM-AAD），希望利用大模型的生成能力与通用知识，提高算法设计与改进的自动化程度。

当前代表性 LLM-AAD 路线通常将 LLM 嵌入进化搜索过程，把算法代码视为个体，由 LLM 生成新的算法方案，再由搜索机制评估、筛选和持续改进。EoH、ReEvo、MCTS-AHD 等工作体现了这一基本范式：LLM 提供算法知识和生成能力，进化机制提供通过反馈不断改进个体的过程。

## 核心问题：算法设计与改进如何发生

本研究关注的核心科学问题是算法设计与改进的底层逻辑，以及如何据此构造能够学习通用算法设计模式的奖励信号。搜索得到更好的算法是检验这一认识的实验结果，搜索过程中呈现出的思想演化、成败原因和决策规律则是需要理解和学习的主要对象。

算法改进是一个连续过程。设计者从当前方案出发，逐步引入、修改或组合算法思想，再根据评估结果延续有效方向、修复失败尝试或切换路线。当前算法及其来时路共同描述决策状态，引入或修改算法思想构成 action，评估反馈形成状态转移的结果。一个 action 除了产生当前一步的效果，还可能改变后续可行的改进方向，因此具有跨步骤的延迟影响。

## 轨迹：连接搜索与学习

算法改进轨迹记录当前方案如何形成，包括每一步从什么算法出发、引入了什么思想、产生了什么结果，以及后续如何延续、回退、修复或重组。轨迹使搜索能够利用成功尝试、失败边界、停滞位置和仍可发展的方向来决定下一步行动。

轨迹同时是搜索与学习之间的桥梁。搜索机制利用已有轨迹选择下一条改进路线和 action，并在执行过程中产生带有逐步反馈和长期结果的新轨迹；学习机制从这些轨迹中进行多步信用分配，识别哪些 action 在什么状态下有效，以及早期思想怎样影响后续决策。

搜索机制与学习机制需要协同设计。搜索策略决定能够观察到哪些状态、action 和反馈，从而决定训练数据的分布与质量；学习得到的策略又会改变后续搜索的探索方向。两者共同构成持续生成经验、学习规律并改进搜索行为的闭环。

## 搜索中的探索与利用

探索与利用是有限评估预算的分配问题。在 TraceAAD 中，种群需要同时延续高质量算法改进路线，并让其它具有潜力的路线保留繁衍机会。算法思想多样性是希望得到的搜索结果；父代选择、随机性和种群更新共同控制预算覆盖。

TraceAAD 将轨迹作为种群个体。算法程序是实际评估对象，轨迹提供程序及其完整来时路。一次生成先选择父代轨迹，再从每条来源轨迹中选择锚点程序，最后由语义算子规定本轮算法设计任务。生成程序时使用的是完整轨迹上下文，锚点程序负责提供具体代码落点。

历史 v3 实验曾维护上限为 160 的活跃轨迹池，使用 $Q/P/D+\mathrm{UCB}$ 确定性选择轨迹、算子累计收益 UCB 和 0.92 相似过滤。这些组件共同影响搜索，后续分析需要通过拆分实验判断各自价值；当前默认实现已经切换到 v4。

TraceAAD v4 采用固定规模轨迹种群和完整轨迹档案。当前种群参与评分、父代选择和繁衍，完整档案保存全部有效历史并服务于经验分析。父代依据种群内质量和路径趋势评分，再通过 softmax 抽样；少量精英与 softmax 无放回抽样共同形成下一轮种群。该结构把当前搜索资源管理与完整历史保存分开。

v4 进一步采用扩张—收缩式种群管理：生存选择不在每个新节点产生后立即执行，而是在当前种群从 $M$ 条轨迹扩张到至少 $2M$ 条后统一收缩回 $M$ 条。扩张期间新轨迹立即进入父代候选池，因此暂时没有直接提升的路线仍有机会继续形成后续历史；统一管理时再根据百分位质量、近期路径趋势、质量精英、少量路线差异 reserve 和 softmax 生存抽样决定哪些路线继续繁衍。这个机制把“新轨迹需要发展时间”的假设显式写入搜索过程，同时让完整档案持续保存被淘汰路线。

### 种群个体的三个属性

把轨迹作为个体后，一个个体同时携带三种不同信息：当前末端程序的质量、路线曾经到达过的最好节点及其后续尝试所体现的潜力、以及它与其它路线的差异。三者回答的是不同问题，不能压成一个未经验证的“综合质量”：质量决定利用，历史潜力决定哪些暂时退步的路线仍值得保留，路线差异决定搜索是否只剩下一种算法思想。

因此种群不应要求每条轨迹同时达到最高质量和最大差异。一个可解释的最小构成是少量质量精英、少量路线差异代表和其余位置的 softmax 抽样。扩张到 $2M$ 后再管理给新轨迹一个有限的试错窗口，但不改变最终的固定规模约束；被淘汰的路线仍在完整档案中，因而搜索资源淘汰与经验丢失是两个不同问题。

路线差异 reserve 当前只使用代码 token、算法思想/动作词项和修改行为指纹，是防止同质化的弱保护，不等价于理解算法语义。它不设置硬 novelty 门槛，也不引入 embedding、island、迁移或额外 LLM 判断。只有消融实验显示同质化仍然严重，才有理由增加更复杂的机制。

MCTS 轨迹树会在程序来源关系和轨迹本身之外增加一层搜索拓扑。轨迹已经表达完整历史，从中间锚点分叉会改变路径前缀，双轨迹生成又会同时产生两条新轨迹；这些关系使树式唯一父节点和沿树回传信用难以对应实际生成语义。v4 因此沿用轨迹种群组织，不引入轨迹 MCTS 树、访问回传和渐进扩展。

`[待验证]` v4 第一版以种群内适应度百分位表示终点质量，并以轨迹上曾经达到的最好节点提供少量历史信用，再以提升、停滞和退步的近期加权结果表示路径趋势。质量和趋势形成轨迹主价值，路线差异只占少量生存 reserve，不进入父代评分，也不承担硬候选过滤。

单轨迹算子承担新思想生成和已有思想深化，多轨迹算子承担原则综合和思想迁移。两条轨迹共同作为上下文时，新程序只评估一次，然后分别连接到两条来源轨迹的锚点程序，形成两条具有不同来时路的新轨迹。程序节点共享代码、算法思想和适应度；锚点不同时分别记录两条修改边，锚点相同时两条轨迹共享同一条边。

轨迹选择和锚点选择承担不同职责。轨迹 softmax 决定繁衍哪条算法改进路线；锚点选择决定基于轨迹中的哪一份 code 修改。末节点保留最新思想积累，轨迹内最高分节点提供已知最佳代码基础；两者不同时第一版等概率选择。选择中间锚点后，其后的尝试作为失败边界和待修复方向进入 LLM 上下文。

`[待验证]` v3 过程观察显示，累计平均收益 UCB 使后期算子选择集中于终点精炼，但不同算子的单次 best 命中率接近，收益受到调用上下文影响。v4 语义算子首先采用均匀选择，算子统计只用于覆盖分析。只有受控实验显示搜索状态能够预测算子相对价值时，才重新引入自适应概率。

动量作为后续研究方向，可能同时描述程序变化、轨迹近期推进、种群质量分布和全局最好推进速度。v4 第一版先验证轨迹种群、softmax 和语义算子，不加入动量调度。

## 总体研究路线：从轨迹搜索到策略学习

总体思路是将算法设计理解为围绕算法思想展开的多步决策过程：先证明改进轨迹能够为下一步决策提供额外价值，再从轨迹中抽象长期信用信号，最后通过强化学习训练模型，使其学习具有迁移能力的算法设计策略。

### 第一阶段：构建基于轨迹的算法设计机制

TraceAAD 将算法改进轨迹作为路线选择和生成上下文，研究在当前算法相同的条件下，看到它的来时路能否帮助模型作出更好的下一步决策。轨迹提供已经引入的思想、有效修改、失败边界、停滞位置和可继续发展的方向；这一阶段需要通过受控消融检验轨迹信息能否提高下一步改进成功率、搜索样本效率和最终算法质量，并积累结构化的算法改进过程数据。

历史 v3 实验保留其相似过滤和活跃轨迹生存机制以保证复现。v4 移除模糊相似过滤，每个有效结果都进入完整轨迹档案和扩张中的可繁衍池，再由固定规模种群的质量精英、路线差异 reserve 和 softmax 生存决定是否参与下一轮父代选择。

第一阶段把轨迹历史设为主要实验变量，历史加工、复杂调度和额外优化目标按验证结果逐项加入。辅助机制逐项消融，便于定位性能变化的来源。

科研代码保持搜索机制简洁，同时提供长实验的基本可靠性。checkpoint 和断点恢复属于实验保障，保存搜索状态与评估预算，独立于科学机制运行。

### 第二阶段：构造可学习的多步决策信号

在搜索产生的轨迹上，把算法改进形式化为序列决策过程：任务、当前算法及其来时路构成状态，引入或修改算法思想构成 action，代码生成与评估形成状态转移。单步性能变化提供即时奖励，一个 action 对后续改进方向和最终结果的影响形成长期回报与信用；学习目标是估计某个算法设计 action 在给定状态下的长期价值。

搜索机制与信号设计需要协同迭代。搜索策略决定能够观察到哪些状态、action 和反馈，信号设计则要求搜索过程保留足以分析即时结果和延迟影响的轨迹结构。两者共同决定训练数据的覆盖范围、因果清晰度和学习价值。

### 第三阶段：强化学习算法设计策略

在轨迹结构和多步信用信号得到验证后，使用强化学习训练模型，使其根据任务、当前算法和改进历史选择下一步算法设计 action。目标是让模型减少重复和破坏性修改，更稳定地提出有效思想，并学习能够跨实例、跨任务迁移的算法设计模式。

三个阶段在研究叙事上依次推进为“轨迹搜索 → 轨迹信用 → 强化学习”，在实际研究中则表现为“轨迹搜索 ↔ 信号设计 → 强化学习”：前两个阶段反复协同修正，第三阶段建立在可靠轨迹数据和有效信用信号之上。

## 待验证的研究假设

**轨迹信息的搜索价值。** `[待验证]` 现有代表性 LLM-AAD 方法尚未系统地把完整算法改进轨迹同时作为生成上下文和学习对象。TraceAAD 需要通过过程分析与消融实验验证，完整来时路是否比当前程序、精英集合或局部父子关系提供更多有效决策信息。

**轨迹信号的学习价值。** `[待验证]` 相比 CALM 等基于正负样本对的 DPO 或组内优劣信号的 GRPO 路线，轨迹级强化学习有望同时利用 action 的即时结果、后续影响和跨步依赖，形成更贴近算法改进过程的奖励与信用分配信号。这一优势需要通过严格的学习基线、过程消融和跨任务泛化实验验证。

**算法设计策略的可学习性。** `[待验证]` 模型能够从跨轨迹的长期信用中学习具有迁移能力的算法设计模式，在相同数据、模型和训练预算下，比只利用局部或终局优劣信号的训练方法作出更有效的多步改进决策。
