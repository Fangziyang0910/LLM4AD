# TraceAAD V5.1 最终机制审查

> 状态：2026-07-25 完成实现审查、确定性修正与公开链路回归。本文判断
> V5.1 是否已具备正式测试条件；它不把尚未运行的正式重复实验写成机制收益。
> 本文原有的结构化全局反思结论已被后续修正；最终契约以
> [07-全局反思复杂门禁移除](07-全局反思复杂门禁移除.md) 为准。

## 1. 最终判断

四算子、\(Q+\mathrm{UCB}\)、双轨迹参考、active frontier 和最小
anti-bloat 确实构成耦合系统。首轮 V5 的搜索空间收缩不能归因于某一个
新机制：旧 Action 契约、空全局经验、重复代码评价、active clone 和偏紧的
输入预算共同改变了有效候选供给与资源分配。

本轮确认并修正三项仍存在的实现问题：

1. 完全相同程序仍被再次评价、写入树并获得新的 active 身份；
2. 32K 上下文固定预留 16K 常规输出，使长程序和双轨迹组合过早失去输入空间；
3. 批次契约要求两条 Action，四个算子约束却使用 “one”，输出数量职责冲突。

修正后，没有再发现评分公式、主/参考选择、单父代拓扑、种群收缩或
anti-bloat 比较器与权威设计不一致的实现。剩余不确定性属于待实验检验的
机制假设：均匀四算子是否优于较小组合、\(Q\) 是否足以代理继续开发价值、
高质量参考是否具有可迁移价值，以及精确同分择简是否压力过弱。

因此，当前代码可以作为最终 V5.1 进入正式过程测试；如果修复后仍稳定出现
后期停滞，应开始否定或收缩上述机制，而不能继续笼统归因于实现。

## 2. 审查不变量

本轮逐项检查：

- 四个算子在满足输入条件时都可达，并分别生成真实子边；
- 双轨迹算子只增加知识参考，不增加第二父边或参考路线 UCB credit；
- \(Q=0.7Q_{\mathrm{endpoint}}+0.3Q_{\mathrm{best}}\)，百分位并列感知；
- 父代选择使用 \(Q+\mathrm{UCB}\)，参考和 survivor 只使用 \(Q\)；
- endpoint 与 compact best 在不同时等概率成为锚点；
- active 达到 \(2M\) 后收缩到 \(M\)，保留质量精英、差异 reserve、
  softmax 样本和 global-best route；
- fitness 永远先于 LOC，程序长度只在 fitness 完全相同时打破平局；
- 不设置 LOC 上限、长度惩罚、近同分门槛或“变长即拒绝”规则；
- 上下文超限只表示模型接口不可执行，不成为低 fitness；
- 重复代码、解析失败和评价失败不会伪造成有效算法结果。

## 3. 确认正确的实现

### 3.1 四算子与知识写回

固定种子公开链路运行 60 次评价时，四算子分别产生：

```text
trace_ideate = 10
trace_refine = 17
trace_synthesize = 18
trace_transfer = 11
```

除 4 个初始化外的 56 次评价全部形成单父边。双轨迹参考只写入 provenance，
子程序仍从主锚点建立唯一入边。四算子不是名义存在但运行不可达。

### 3.2 评分、选择和 active frontier

实现中的 endpoint/best 权重、UCB 公式、softmax 温度、参考 \(Q\)-softmax
和 survivor \(Q\)-softmax 与机制文档一致。局部趋势仍写入分析字段，但不
进入父代或生存标量。

同一公开回路经历多次 \(2M\to M\) 收缩后，active 数为 \(M\)，global-best
仍处于 active 路线。没有发现 global best 被普通抽样意外归档、参考路线
获得父代访问次数或趋势字段重新混入评分。

### 3.3 最小 anti-bloat

当前规则只做两件事：

1. fitness 完全相同时选择更短的 compact/global-best/质量代表；
2. 完全相同的代码不重复评价和繁衍。

公开行为测试构造了一个超过 100 LOC、但 fitness 严格更高的子程序。它仍
成为 global best，并在收缩后保留于 active。由此可以确认，简约规则不能
用短低分程序覆盖长高分程序。

代码不同的退步、平台或变长候选仍正常评价并进入树；V5.1 没有语义近似
去重或硬规模限制。因此当前 anti-bloat 对高性能进化施加的是同质表示压力，
不是长度质量门槛。

## 4. 本轮修正

### 4.1 完全重复程序的评价前拦截

候选完成解析后先计算规范化代码哈希。若哈希已存在：

- 记录 `duplicate_program`、Action、主程序、算子和已有节点；
- 不调用 evaluator；
- 不创建节点、边或 active 轨迹；
- 不消耗程序评价预算。

初始化采用同一规则，重复根不会占 `n_init` 名额。该修正只处理确定性的
代码同一性；代码不同但行为近似的候选继续依赖真实评价。

### 4.2 输入与输出预算重新平衡

首轮 12 个 V5 run 共有 12,000 个成功初始化/代码回复。取字节长度最大的
100 个回复，用模型服务真实 tokenizer 重算：

```text
最大 = 5,733 token
中位 = 3,811 token
```

正式入口将常规生成上限与输出预留从 16,384 统一为 8,192。它仍覆盖历史
最大输出并保留约 43% 余量，同时让 32K 模型的 Action 输入预算从约 16K
增加到约 24K。该修正降低长程序和双轨迹组合的接口淘汰，不改变 LOC 质量
规则。

### 4.3 四算子的逐 Action 语义

四个约束统一写成 `For each action, ...`。两条 Action 分别承担同一算子
职责；`transfer` 的每条建议各迁移一个原则，`synthesize` 的每条建议各形成
一次功能交互。Action 与代码提示同时明确要求产生实质代码变化，系统仍以
哈希拦截模型未落实修改的结果。

## 5. 尚未证明的机制

以下项目实现正确，但不能由代码审查证明有效：

1. **均匀算子调度**：四算子各自可达，不代表 25% 尝试比例在所有任务和
   搜索阶段都最优。
2. **\(Q+\mathrm{UCB}\)**：\(Q\) 能识别已有成果，尚未证明足以预测路线的
   后续开发价值。
3. **参考 \(Q\)-softmax**：高质量程序可能是好供体，也可能已经饱和或与
   主程序思想重复。
4. **轻量差异 reserve**：它维持代码、Idea 和路径模式差异，不保证语义或
   active 当前程序覆盖。
5. **精确同分择简**：它不会牺牲严格更高 fitness，但可能不足以控制微小
   训练增益伴随的大幅复杂化。

这些项目应通过同模型、同预算和固定种子的过程实验判断。若 V5.1 已经实现
非空全局经验、接近零的完全重复评价和较高 active 唯一代码率，却仍在
CVRP/OP 稳定早停，下一步应优先比较四算子与 `ideate/refine`、以及
\(Q+\mathrm{UCB}\) 与候选继续开发代理，而不是继续增加接口补丁。

## 6. 正式测试的过程验收

正式 V5.1 首轮至少报告：

- Action 的 0/1/2 条提取率及四算子的有效评价数；
- `duplicate_program` 次数和因此节省的 evaluator budget；
- 图中唯一代码率、active 唯一 endpoint；
- 四算子的早/晚期 route-best 与 global-best yield；
- 非空全局经验是否进入下一轮 Action；
- proposal、有效节点、active survivor 和 global best 的 LOC；
- context overflow 的阶段、算子、主/参考程序长度和真实 token。

这些指标通过后，V5.1 的性能才主要检验机制组合；在此之前出现的失败仍需
先按接口、重复预算和状态覆盖分层解释。

## 7. 最终真实模型冒烟

使用 Qwen3.6-27B、TSP Construct 训练评估器和正式 8192 token 输出预留，
完成 8 个有效样本的小预算真实调用：

```text
有效节点 = 8 / 8
派生边 = 6
轨迹 = 8
最优节点仍在 active frontier = true
本次触发算子 = trace_synthesize, trace_transfer
全局反思尝试 = 1
全局经验更新 = 0
旧内容门禁拒绝了响应
```

初始化、Action、Code、评价、写图、frontier 管理、全局反思调用和 checkpoint
均实际执行。这个结果后来被重新判定为旧内容门禁造成的错误拒绝，不能解释成
合理 abstain。该门禁及其附带状态已经从 V5.1 删除；当前反思改为每 40 个
已评价子程序触发并直接保存自然语言响应。详细修正见
[07-全局反思复杂门禁移除](07-全局反思复杂门禁移除.md)。
